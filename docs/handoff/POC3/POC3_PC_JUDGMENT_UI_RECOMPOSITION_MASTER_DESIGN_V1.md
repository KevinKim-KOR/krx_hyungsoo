# 투자모델_v2 — PC 판단 UI 재조합 전체 설계 v1

- 작성일: 2026-07-26
- 문서 성격: UI 개편의 상위 설계와 개발 순서 확정
- 현재 상태: 설계 초안
- 상위 목표: `PC Judgment Dashboard UI v1`
- 전제: `First Real Decision Cycle v1` 사용자 운영 관찰은 병행

---

## 1. 현재 판정

현재 PC UI의 완성 상태는 `PARTIAL`이다.

개별 데이터와 기능은 상당 부분 완성되어 있다.

- 시장 국면과 위험 참고
- 상대상승 참고점수
- Market Discovery 후보
- Holdings 평가
- NAV·괴리율
- 구성종목과 중복률
- 판단 근거와 PENDING 초안
- OCI 적용
- Telegram·정보 PUSH 운영

그러나 기능별 화면과 버튼을 사용자가 직접 돌아다니며 조합해야 한다.

핵심 결함은 데이터 부족이 아니라 다음 세 가지다.

1. 첫 화면이 오늘의 상태보다 사용 절차를 보여준다.
2. 후보·보유·근거가 낮은 밀도로 반복되어 중요한 예외가 묻힌다.
3. 판단 초안·승인·OCI·PUSH 관련 실행 상태와 버튼이 흩어져 있다.

이는 단순한 UI polish가 아니라 실제 판단 흐름을 막는 구조 결함이다.

---

## 2. 전체 목표

기존 데이터·산식·운영 계약을 변경하지 않고 PC 화면을 다음 3계층으로 재조합한다.

```text
상태 Dashboard
→ 판정 Workbench
→ 실행 Operations Panel
```

사용자는 다음 질문에 순서대로 답할 수 있어야 한다.

1. 오늘 시장·보유 현황에 볼 것이 있는가?
2. 있다면 어떤 후보·보유 종목·위험을 확인해야 하는가?
3. 판단 결과나 운영 기준 중 무엇을 승인·OCI 적용·확인해야 하는가?

기존 Holdings·Market Discovery·ETF Exposure·AI Sessions·Data Status는 없애지 않는다.  
이들은 주 판단 흐름을 뒷받침하는 조회·관리·상세 화면으로 유지한다.

---

## 3. 화면 구조

### 3.1 계층 1 — 상태 Dashboard

**답할 질문:** 오늘 무엇을 봐야 하는가?

기본 노출:

- 데이터 기준일과 영역별 최신성
- 기존 시장 국면과 실제 제공 중인 전환 조건
- 보유자산 변화 요약
- 유력 후보와 보유 위험 요약
- NAV 이상·미연동·stale 등 예외
- 판단 대기·최근 OCI 적용·최근 발송 상태
- 판정 화면과 실행 패널로 가는 퀵 진입

변경 원칙:

- 현재 `STEP 1~5` 안내 카드는 첫 화면 기본 영역에서 제거한다.
- 절차 안내는 `도움말`로 접어 유지한다.
- 정상 상태를 길게 나열하지 않고 예외와 변화가 있는 항목을 우선한다.
- 실제 데이터가 없는 전환 거리·지수·위험값은 새로 만들지 않는다.

### 3.2 계층 2 — 판정 Workbench

**답할 질문:** 무엇을 비교하고 자세히 봐야 하는가?

기본 노출:

- 시장 후보 고밀도 표
- 보유 ETF 고밀도 표
- 후보와 보유의 직접 일치·중복 노출
- 기간 수익률·초과수익·참고점수·고점 대비·NAV 상태
- 선택 종목의 차트와 상세 evidence

변경 원칙:

- 종목 한 개를 기본적으로 한 행에 압축한다.
- 점수 근거·구성종목·중복률 상세·반복 설명은 기본 접힘으로 둔다.
- 비교 가능한 항목과 예외를 먼저 보여준다.
- 정상·TOP N 외·구성종목 확인 불가가 반복되면 건수로 묶고 필요할 때 펼친다.
- `unavailable`을 중복 없음·이상 없음으로 해석하지 않는다.
- 시스템이 자동 투자 판단을 추가하지 않는다.

### 3.3 계층 3 — 실행 Operations Panel

**답할 질문:** 무엇이 준비됐고, 무엇을 실행하거나 확인해야 하는가?

한곳에서 구분해 보여줄 항목:

1. 판단 초안
   - 초안 생성
   - `PENDING_APPROVAL`
   - 사용자 승인 상태
   - 승인 이후 전달 결과
2. OCI 운영 기준
   - 현재 적용 대상
   - 생성 시각·revision·최신 여부
   - 기존 OCI 적용 동작
   - 최근 적용·검증 결과
3. 정보 PUSH
   - Market·Holdings·Spike 현재 운영 상태
   - 최근 발송 결과
   - 기존에 존재하는 초안·미리보기 동작

변경 원칙:

- 정보 PUSH와 사용자 판단 초안 승인을 섞지 않는다.
- 자동 운영 중인 정보 PUSH에 매 발송 승인 절차를 다시 추가하지 않는다.
- 기존에 없는 수동 발송·자동 판단 기능을 만들지 않는다.
- 오래됐거나 불완전한 산출물은 최신처럼 보이지 않게 하고 기존 계약대로 Fail-Closed 처리한다.
- Workbench의 선택 맥락은 실행 패널 진입 시 유지하되, 동일 실행 버튼을 여러 화면에 중복 배치하지 않는다.

### 3.4 조회·관리·상세 화면

기존 화면은 다음 역할로 유지한다.

| 기존 화면 | 유지 역할 |
|---|---|
| Holdings | 보유 입력·관리와 상세 평가 |
| Market Discovery | 전체 후보 조회·필터·갱신·점수 계산 |
| ETF Exposure | 구성종목·중복률·NAV 상세 확인 |
| AI Sessions | 외부 AI 답변·사용자 판단·세션 이력 |
| Data Status | 수집 상태·기준일·데이터 품질 진단 |

Dashboard와 Workbench에서 상세가 필요할 때 이 화면들로 이동한다.  
같은 정보를 다시 계산하거나 별도 저장하지 않는다.

## 5. 공통 표현 원칙

### 5.1 정보 밀도

- 목록은 숫자와 상태를 한 행에 압축한다.
- 근거 문장과 원자료는 사용자가 선택했을 때만 펼친다.
- 첫 화면에 내부 artifact 경로·raw status·기술 식별자를 노출하지 않는다.

### 5.2 예외 우선

- 모든 정보를 같은 시각적 무게로 표시하지 않는다.
- stale·이상값·미연동·비교 불가·판단 대기를 우선 강조한다.
- 정상 항목은 요약하고 사용자가 원할 때 펼친다.
- 색상은 상승·하락·경고·정상처럼 의미가 있을 때만 사용한다.

### 5.3 데이터 정직성

- 서로 다른 기준일을 하나의 현재 시점처럼 합치지 않는다.
- 데이터 영역별 기준일과 최신성을 구분한다.
- 수집 성공과 판단 사용 가능 여부를 분리한다.
- 차트나 비교 데이터가 없으면 빈 시각화를 만들지 않고 사유를 표시한다.
- 이상값 경고가 있는 데이터는 정상값과 같은 무게로 사용하지 않는다.

### 5.4 기능 경계

- 기존 API·산식·DB·source를 우선 재사용한다.
- UI 조합을 위해 신규 source·proxy·factor·threshold를 만들지 않는다.
- 기존 응답만으로 설계 목표를 충족할 수 없으면 개발자가 임의 확장하지 않고 설계자에게 복귀한다.

## 6. 화면에서 확인된 데이터 문제의 처리

### 6.1 VIX 기준일 불일치

화면 실측:

- KODEX200 기준일: 2026-07-24
- VIX 기준일: 2026-07-03

UI에서는 다음을 적용한다.

- VIX 기준일을 KODEX200과 분리 표시한다.
- 현재 시장 위험 참고값으로 오해하지 않도록 stale 경고를 강하게 표시한다.
- 최신성 계약을 충족하지 못하면 현재 상태 요약의 정상 지표처럼 강조하지 않는다.

VIX 적재 정상화는 UI 재조합과 섞지 않고 별도 데이터 결함 Step으로 처리한다.
UI-1에서는 stale 경고를 우선 적용하되, UI-4 Closeout 전까지 적재 결함을 해소하거나
VIX를 현재 상태 판단 영역에서 제외해야 한다.

### 6.2 보유 ETF 구성종목 확인 불가

화면에서 다수 보유 ETF가 `constituents_unavailable` 상태다.

이번 UI 개편에서는:

- 비교 가능한 항목만 우선 표시한다.
- 확인 불가 항목은 건수와 사유로 한 줄 요약한다.
- 사용자가 펼쳤을 때 개별 항목을 확인할 수 있게 한다.

구성종목 source 확대는 이번 UI 범위에 넣지 않는다.

이 항목은 이번 Step에 넣으면 외부 source와 데이터 계약 변경으로 범위가 커지므로 BACKLOG로 넘기는 것이 맞다.  
보류 사유: UI 정보 구조 개편과 구성종목 수집 확장은 서로 다른 문제다.  
보류된 위험: 일부 보유 ETF는 후보와의 실제 중복 노출을 비교할 수 없다.  
재검토 트리거: 비교 불가 비율이 실제 판단을 계속 차단하거나 기존 BACKLOG의 fetcher 다변화 조건이 충족될 때.

## 7. 개발 Step 분리

기존 `PC Judgment Dashboard UI v1` 상위 목표는 유지하되, 한 번에 구현하지 않는다.

| 순서 | 개발 Step | 단일 목표 |
|---|---|---|
| UI-1 | PC Status Dashboard v1 | 첫 화면을 절차 안내에서 오늘의 상태·예외·대기 작업 중심으로 전환 |
| UI-2 | Judgment Workbench Density & Exception v1 | 후보·보유·근거를 고밀도 표와 예외 우선 구조로 재조합 |
| UI-3 | Operations Panel Consolidation v1 | 기존 판단 초안·승인·OCI·정보 PUSH 상태와 동작을 한곳에서 역할별로 구분 |
| UI-4 | PC Judgment Flow Closeout v1 | 실제 데이터로 상태→판정→실행 동선과 기존 상세 화면 연결을 최종 검증·정리 |

운영 원칙:

- 한 번에 한 Step만 설계한다.
- 각 Step이 PASS가 아니면 다음 Step으로 가지 않는다.
- 다음 Step의 세부 레이아웃·구현 파일·AC는 해당 Step 설계에서 확정한다.
- `First Real Decision Cycle v1` 관찰은 개발과 병행하되 별도 기능을 추가하지 않는다.

## 8. 이번 전체 UI 개편에서 하지 않는 것

- 신규 투자 알고리즘
- 신규 factor·label·threshold
- 신규 데이터 source·proxy
- 신규 DB 또는 대규모 데이터 계약 변경
- OCI·Telegram 운영 주기와 발송 계약 변경
- 자동 BUY·SELL·리밸런싱·주문
- 친구 화면의 공격·방어 비중·손절·다계좌 구조 복제
- 모바일 UI
- 업종 Treemap
- ML 학습·백테스트·튜닝
- 전체 디자인 시스템 교체

## 9. 전체 완료 기준

1. 첫 화면에서 30초 안에 시장 변화·유력 후보·보유 위험·데이터 예외를 판단할 수 있다.
2. 후보와 보유 종목을 여러 화면 이동 없이 고밀도로 비교할 수 있다.
3. 세부 evidence는 필요할 때만 펼쳐지고 기본 목록을 밀어내지 않는다.
4. 반복되는 정상·확인 불가 항목은 요약되고 예외가 먼저 보인다.
5. 판단 초안·승인·OCI 적용·정보 PUSH가 역할별로 구분된 한 실행 공간에서 확인된다.
6. 정보 PUSH와 판단 승인이 혼동되지 않는다.
7. 기준일·stale·unavailable·이상값이 최신 정상 데이터처럼 표현되지 않는다.
8. 기존 조회·관리·상세 기능과 운영 계약이 유지된다.
9. 실제 데이터 화면에서 사용자가 `상태 → 판정 → 실행` 흐름을 완료할 수 있다.
10. 이를 위해 여러 기존 메뉴를 다시 순회하며 머릿속으로 정보를 조립해야 한다면 전체 UI 개편은 PASS가 아니다.
