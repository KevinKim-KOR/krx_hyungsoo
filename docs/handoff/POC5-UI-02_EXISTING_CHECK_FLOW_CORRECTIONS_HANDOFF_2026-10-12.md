## 1. 바뀐 것 (지금 화면)

- **「확인 근거」 정렬 네 가지**: 평가 비중(큰 값부터) · 손익률 · 5일 변화(기본) · 20일 변화(작은 값부터).
  - 화면 숫자 그대로 · 값 없는 종목 맨 뒤 · 같은 값끼리와 값 없는 행끼리는 원래 순서 · 행을 빼지 않음 · 재조회 0
  - 코드: `frontend/app/components/holdings_risk_evidence/helpers.ts :: sortEvidenceRows` · `EVIDENCE_SORT_OPTIONS`
  - 'KODEX200 대비' 정렬은 1차에 있었으나 뺐다. KODEX200 대비 20일 = 종목 20일 − KODEX200 20일이고 빼는 값이 모든 종목에 같아 20일 변화와 순서가 같다(2026-10-12 실데이터 29종목 확인). 카드의 'KODEX200 대비 20일' 값은 그대로 보인다.
- **선택 종목 상세 맨 위 '자료 확인 안내'**(`helpers.ts :: evidenceGuidance`)
  - 사유: 보유 시세 미확인(`price_missing`) · 평가 계산값 미확인(`calc_missing`) · 계좌 간 단기 흐름 값 불일치(`evidence_conflict`) · 단기 흐름 `unavailable`(백엔드 문구)
  - 그 종목 `evidence_notes`(여러 계좌면 같은 문구 한 번 · 일반 문구도 그대로)
  - 자료 확인 필요인데 위 사유가 없으면 '자료 확인이 필요하지만 상세 사유 정보가 제공되지 않습니다.'를 맨 위에
  - 안내가 없으면 영역 없음 · 정렬을 바꿔도 유지 · 재조회 0
- **상세 아래 버튼 '전체 ETF NAV·괴리율 보기 →'** → 「데이터 상태」(`data_status`). 종목 전달 · 검색 자동 입력 없음(설계 §11-4).
- **「오늘의 투자 점검」**: '내가 가진 ETF' 목록 위 '최근 5거래일 변화가 낮은 보유 ETF부터 최대 3개'(선정 함수 · 숫자 변경 0).
- **기록 정리**: 대조표에서 근거가 확인된 행만 BACKLOG · STATE · PROGRAM_TRUTH · 통합지도 · README 에 정정으로 남김(옛 판정 원문 불변).

## 2. 보류 · 후속 (이번 종료 범위 밖)

1. **「오늘의 투자 점검」 두 안내 카드**('개발 중인 판단 기능' · '코스피 상세 지표') — 제거 · 파일 삭제 보류(설계자 판정). 사실과 다른 문구('거래량 자료 미저장' 등)를 그대로 담고 있다. 다음 설계 결정 때 다룬다.
2. **거래량 흐름 · 종합 위험 감지** = 미구현 요구 · 보완 후보. **공격·방어 · SuperTrend** = 미구현 · 기존 제외 기록(불필요 입증 아님).
3. **seed 정합** = 사용자 결정 대기 — PC seed(기본 후보 3개)를 OCI 승인본 20개에 맞출지. 차이표 = PLAN 부록. 결정 전에는 두 파일을 덮어쓰지 않는다.
4. **PC FDR 수동 갱신 보호** = 조건부 후속(멈춤 관측 0 · 설계 §6-1 · 구현 0).

## 3. 운영 · 사용 메모

1. 지금 실데이터에는 '자료 확인 필요' 종목이 0개다(2026-10-12 응답 · 단기 흐름 32항목 모두 ok · 시세 · 계산 미확인 0). 그래서 '자료 확인 안내'에는 일반 문구(Market Discovery 후보 여부 · 20거래일 KODEX200 대비 · 구성종목 · 일부 NAV)만 보인다. 사유 분기는 시험 자료로만 확인했다.
2. 선택 상세의 'NAV · 괴리율' 줄과 「데이터 상태」 표는 같은 NAV 저장소(`app/etf_nav_store`)를 읽는다. 표에 더 있는 것은 source · status 두 칸이다. 사용자가 '종목으로 바로 가기'를 물었으나 요청하지 않았다(설계자에게 넘길 것 없음).
3. 계좌 불일치 종목의 목록 값은 기존 코드대로 첫 계좌 항목 값이다(`aggregateEvidenceByTicker` · 변경 0). 안내 문구는 '서로 다릅니다'까지만 말한다.
4. 「확인 근거」 맨 위와 「오늘의 투자 점검」 최대 3개의 맨 위 종목은 다를 수 있다. 앞은 자료 확인 필요 행도 값이 있으면 넣고, 뒤는 backend `select_top_holdings` 가 정상 행만 고른다.

## 4. 다음 개발자 주의 (이번 단계 교훈)

1. **사용자 의견은 먼저 확인 · 판단한 뒤 넘긴다.** 실화면 의견 2건을 사용자에게 되묻지 말고 코드 · 산식으로 오류 여부를 판단해 설계자에게 넘기라는 사용자 지적이 있었다(2026-10-12 · 판단 기록 = 결과서 §11).
2. **설계 표의 '사유 문구'는 실데이터로 대조한다.** `evidence_notes` 는 사유가 아니라 일반 문구가 늘 섞여 있었다(29종목 모두 3~4개). 첫 규칙('안내가 없을 때만 사유 미제공 문구')은 실데이터에서 거의 동작하지 않아 구조 칸 기준으로 고쳤다.
3. **안내 문구는 실제 동작보다 넓게 말하지 않는다.** 계좌 불일치 문구를 '한 값을 고르지 않았다'로 썼다가, 목록이 첫 계좌 값을 보이므로 '서로 다릅니다'로 줄였다.
4. **화면 서버는 파일 변경을 자동으로 다시 읽는다.** 화면 전용 변경은 재기동 없이 새로고침으로 확인한다(사용자 결정 2026-10-12).
5. `git add -A docs/` 금지 — 사용자 소유 untracked `docs/handoff/INVESTMENT_MODEL_V2_MASTER_HANDOFF_2026-07-26.md`.
