## 1. Q1 — 수급은 본인 계정으로 조회하는 경로 우선

이번 핵심은 사용자가 일별·수개월 수급을 반복해서 읽는 것이다. 매번 KRX CSV를 내려받아 올리는 작업을 기본 운영으로 정하지 않는다. (b)는 기본안으로 채택하지 않으며, (c)·(d)도 지금 병행 구현하지 않는다.

설계 §5의 '자동 로그인은 넣지 않는다'는 설계자가 정한 원래 경계다. **사용자 명시 승인 뒤, 사용자의 KRX 회원 계정으로 PC 갱신 작업에서 정상 로그인해 코스피 현물 투자자 통계만 읽는 예외**로 개정한다. 이는 KRX Open API 서비스를 새로 승인받았다는 뜻이 아니다. 출처는 'KRX 웹 통계'로 구분한다.

- 계정은 사용자가 PC의 git 제외 .env에 직접 설정한다. 채팅·Git·응답·연구 산출물·로그·OCI에 ID/비밀번호/세션을 넣지 않는다. 새 계정 관리 화면·서비스는 만들지 않는다.
- 설치된 pykrx의 인증 세션·조회 함수를 우선 재사용한다. 원문 응답의 빈칸·조회 실패를 0으로 바꾸는 경로는 이 자료에 쓰지 않는다. 필요한 얇은 읽기 adapter에서 원문 상태와 숫자를 검사한다. 라이브러리 전체 수정·업그레이드는 하지 않는다.
- 로그인·조회 요청 모두 기존 방식의 timeout을 적용한다. 조회 실패·인증 실패는 해당 단계 실패로 끝내고 이전 자료를 유지한다. 무한 재로그인·차단 회피·CAPTCHA 우회·브라우저 쿠키 추출은 넣지 않는다.
- 정상 회원이 볼 수 있는 통계와 해당 웹 서비스의 이용 조건을 한 번 확인한다. Open API 약관을 회원 웹 조회의 허가 근거로 대신 쓰지 않는다. 이용 조건상 불가하거나 추가 인증이 막으면 그 사실을 보고한다. 별도 법무 점검 단계나 우회 경로 탐색으로 확대하지 않는다.
- 순매수만이 아니라 필요한 매수·매도·전체 거래대금을 같은 시장·분류·단위로 확보할 수 있는지 확인한다. 기관 합계와 세부 중복 없음, 매수−매도=순매수, 날짜·단위 보존을 작은 표본으로 대조한다. 정해진 제공 시각 이전의 당일 잠정값은 확정 수급으로 넣지 않는다.

**근거 표현 정정:** PLAN의 '공식 경로 없음'은 현재 증거보다 넓다. '현재 사용 중인 승인 API 3개에는 수급 경로가 없고, Open API 전체 목록의 직접 확인은 미완료이며, 회원 웹 조회 경로는 인증 전'으로 적는다. 설계자의 공식 목록 조회도 동적 목록의 전체 항목을 확보하지 못했다. 제3자 요약만으로 전체 서비스 부재를 확정하지 않는다. 공식 목록은 접근 가능한 화면에서 한 번 확인하면 충분하며, 없는 API를 끝없이 찾는 선행 단계를 만들지 않는다.

**자동 권한 검사 차단:** 이번 KRX 재조회 명령은 개발 환경의 자동 권한 검사에서 차단되어 실행되지 않았다고 보고됐다. 거절 이유 원문은 PLAN에 없다. 대상 작업과 이유를 기록하고 허용되는 정상 절차를 확인한다. 이를 KRX 서버의 응답이나 조회 불가능 실측으로 쓰지 않는다. 사용자 계정 사용 승인도 그 실행 차단을 자동 해제하거나 우회를 허용하지 않는다. 허용받지 못하면 해당 확인을 멈추고 정확한 차단 사유를 알린다.

## 2. Q2 — 환율은 (c) Yahoo 원시 시각·시간대 보존

**FRED DEXKOUS를 이번 일별 단기 관측의 주 자료로 채택하지 않는다.** 연준 H.10은 직전 영업 주의 일별 환율을 월요일 오후에 묶어 발표한다(월요일 연방 공휴일이면 다음 영업일). 관측 빈도 Daily와 발표 빈도는 다르다. PLAN의 '약 2영업일 늦음'은 확인 당시 최신 행과의 간격일 뿐 고정 지연 계약이 아니다. 소급 발표되는 값을 단기 변화 확인의 주 자료로 쓰면 사용자의 목적과 어긋난다.

- 이미 FDR이 사용하는 Yahoo 차트 계열을 좁은 adapter로 읽어 **원시 timestamp와 공급자 시간대**를 보존한다. 같은 원천이며 새로운 환율 계열로 몰래 대체하지 않는다. 해당 외부 호출 방식은 사용자 승인 범위에 명시한다.
- 시간대 이름을 이용해 과거 각 시점의 서머타임을 적용한다. 현재 UTC offset을 전체 이력에 적용하거나 날짜에 일괄 +1을 하지 않는다. 요일 개수를 맞추기 위한 날짜 보정도 하지 않는다.
- 세션/봉 기준과 최신 행의 완료 여부를 확인해 진행 중 행을 제외한다. 같은 날짜의 빈 행·진행 중 행을 정상 종가로 중복 저장하지 않는다. 이번 단계에서 한국 15:30 환율로 명명하지 않는다.
- 최소 확인은 서머타임 적용/해제 양쪽의 날짜 예와 최신 진행 중 행 제외다. 현재 받은 응답·설치 소스로 확인 가능한 것은 재사용한다. 시간대·완료 여부를 신뢰할 근거가 없으면 그 지점만 보고하고 FRED로 자동 대체하지 않는다. ECOS 등 다른 자료원 탐색을 동시에 진행하지 않는다.

FRED는 이번 구현의 대체·보정·혼합 계열로 추가하지 않는다. 별도 자료원 지원이나 새 키 발급을 기본 요구로 늘리지 않는다.

## 3. Q3 — WTI는 (a), 완료 시각은 선물 계열 기준

Yahoo CL=F 근월물 선물 계열을 유지한다. PLAN의 '뉴욕 마감'은 **NYSE/VIX의 오후 4시 마감 규칙을 복사한다는 뜻으로 쓰지 않는다.** WTI는 해당 선물·공급자 일봉 기준으로 확인한다.

최신 진행 중 행은 원천 timestamp·시간대·세션 근거로 제외한다. 정확한 당일 완료 여부를 확인할 수 없으면 설계 개정 3에서 허용한 보수적 이전 일자 채택을 쓰고 실제 기준일과 지연을 표시한다. 별도 휴장일 달력 시스템을 새로 만드는 조건은 아니다. 같은 Yahoo adapter의 시각 해석을 재사용할 수 있다.

만기 교체 영향 가능성·선물 계열·USD/배럴 표기는 유지한다. 공급자 일별 값은 공식 정산가라고 부르지 않는다.

## 4. 질문 외 PLAN 수정 — 현재 자료를 정확하게 유지

1. **정정 수치 동결은 채택하지 않는다.** '최신일 다음 날부터만 조회 / 기존 값과 다르면 저장 거절'을 수정한다. 이후 환율·WTI는 최근 90일, 수급은 최근 20 한국 거래일을 겹쳐 받아 동일 계열의 유효한 원천 정정을 반영한다. 첫 수집은 기존 설계의 연초+준비 구간이다. 기간 요청을 우선하며 날짜마다 전 종목 조회하는 방식은 쓰지 않는다. 원천 API가 이 방식을 지원하지 않으면 실제 최소 호출 대안을 적는다.
   - 성공한 응답의 계열·날짜·단위·분류·값을 확인한 뒤 upsert하고 현재 수집 시각을 남긴다. 실패·결측을 0으로 덮거나 기존 유효 행을 지우지 않는다. 제공자가 다른 값·날짜·단위가 섞이는 오류는 여전히 실패다.
   - 과거 정정분을 최신 통계로 반영하는 것과 과거 시점에 알았던 값으로 주장하는 것은 별개다. 이번 표는 최신 확보 자료이며 PIT 데이터셋으로 선언하지 않는다. 별도 버전 원장은 만들지 않는다. 자료를 고정하는 것으로 PIT 문제를 해결했다고 적지 않는다.
2. **누적 첫날을 빠뜨리지 않는다.** 설계의 '시작일에 0'은 **선택 기간 시작 직전 기준점이 0**이라는 의미로 정정한다. 첫 거래일 표시값에는 그날 순매수가 들어간다. 마지막 누적값은 기간 내 전 일자의 합과 같아야 한다. 부분 기간·결측은 기존 설계대로 표시한다.
3. **기준일을 서로 바꿔 쓰지 않는다.** 장기 D와 각 자료의 최신 완료 E를 유지한다. 새 출처를 기존 latest_refresh에서 제외하는 변경은 수용한다. 다만 갱신 기준일을 억지로 KOSPI로 하드코딩하거나 원래의 갱신 상태 의미를 바꾸지는 않는다.
4. **저장 구조·응답 구조는 수용한다.** 같은 시장 DB의 두 표, 새 GET /market/flow-context 1개, 서버 공통 빌더의 문장 재사용을 허용한다. 투자자 거래대금은 원천 단위를 정확히 변환한 정수 원으로 저장한다. series_id는 공급자·가격 의미·단위가 고정되도록 해 다른 계열이 같은 키로 섞이지 않게 한다. 새 API·표는 승인 목록에 명시한다.

관련 시험의 '기존 값과 다르면 무조건 거절' 기대값은 위 정상 정정 반영·잘못된 계열 거절로 바꾼다. 추가로 누적 첫날 포함, 과거 정정 반영, DST 전후 날짜, 진행 중 봉, 실제 0과 빈칸 구분을 확인한다. 전체 회귀 반복 실행이나 더 많은 변이 수를 목표로 만들지 않는다.

## 7. PLAN §9 뒤 추가 판정 — 수급 자료원 변경

### 7-1. 중단·기존 승인 처리

KRX Data Marketplace 웹 이용약관의 자동 수집·복제 관련 조항을 설계자도 공식 페이지에서 확인했다. 이용 허락이 확보되지 않은 회원 웹 자동조회 경로는 여기서 중단한다. 사용자 본인 계정 사용 승인이 거래소의 정보 이용 허락을 대신하지는 않는다. KRX 계정 설정·로그인·우회 수집을 계속하지 않는다. 이를 '수급 개발 전체 불가'로 확대하지 않는다.

갱신된 PLAN 머리의 사용자 승인 기록('세 가지 모두 승인')을 수용한다. **Yahoo 환율·WTI 조회, 같은 시장 DB 두 표, GET /market/flow-context에 대한 기존 승인은 유효하며 다시 묻지 않는다.** KRX 계정을 새로 넣을 필요는 없다. 한국투자증권의 API·앱키 사용은 기존 KRX 승인과 다른 범위다.

### 7-2. 우선 대안 — 한국투자증권 KIS 공식 API

설계자가 공식 API 목록과 공식 저장소에서 다음을 확인했다. 제3자 MCP 소개에만 의존한 제안이 아니다.

- 서비스: **시장별 투자자매매동향(일별), 국내주식-075**.
- 경로: /uapi/domestic-stock/v1/quotations/inquire-investor-daily-by-market · TR: FHPTJ04040000.
- 공식 예제는 코스피(KSP), 업종 코드 0001을 사용하며 두 날짜 인자를 같은 기준일로 넣는다. 두 인자를 시작일·종료일 범위로 임의 해석하지 않는다.
- 공식 출력 예제에 외국인·개인·기관계 등의 **일별 순매수 거래대금** 필드가 있다. 수량과 대금을 구분해야 한다.
- 공식 안내에 계좌·ID 연결, Open API 신청과 앱키 발급 절차가 있다. 사용자가 이 계좌를 이미 보유하는지, 추가 신청을 원하는지는 아직 모른다. 사용자 선택 없이 새 증권계좌 개설·신청·연결을 요구하거나 진행하지 않는다.

**아직 확인하지 않은 것:** 사용자 계정의 실제 조회 성공, 이용 가능 환경, 연초+준비 구간 전체의 조회 가능성, 호출/페이지 제한, 금액 단위·분류·확정 시각, 개인 분석·저장·AI 검토 전달에 적용되는 이용 범위. API가 있다는 사실만으로 이 모두를 통과했다고 쓰지 않는다.

사용자가 KIS 사용을 선택하면 개발자는 위 항목을 해당 공식 명세와 소규모 읽기 전용 표본으로 한 번 확인한다. 필요한 인증·시장 조회만 기존 requests로 연결하며, 주문·잔고 조회·자동매매·MCP·공식 예제 저장소 전체 설치·별도 SDK는 추가하지 않는다. 정상 토큰 재사용·만료 처리는 이 조회 경계에만 둔다. 비밀 설정은 PC에서 사용자가 직접 하고 Git·로그·응답·OCI에 넣지 않는다.

### 7-3. 순매수만 제공돼도 핵심 흐름을 구현할 수 있다

이전 판정의 매수·매도·전체 거래대금 필수 확보는 KRX 웹 통계의 구조를 전제로 했다. **투자자별 순매수 대금의 진본·단위·분류·기간을 확인할 수 있으면 누적 흐름, 20/60일 강도, 하루 규모 확대를 구현할 수 있다.** 매수·매도 총액이 없다는 이유만으로 이 핵심을 막지 않는다.

- 외국인·개인·기관계와 제공되는 나머지 분류를 정확히 매핑한다. 합계와 세부를 중복 합산하지 않고 미제공 분류는 없다고 표시한다. 개인과 외국인의 차이를 '부족액'으로 만들지 않는다.
- 순매수만 제공되면 buy_value/sell_value는 NULL로 허용한다. 0 또는 순매수의 양·음 부분으로 가짜 매수·매도 총액을 만들지 않는다. 같은 승인된 수급 표 안의 처리이며 별도 표를 늘리지 않는다.
- 시장 거래대금의 동일 범위·기간을 확인할 수 없다면 **거래대금 대비 비율만 생략하고 사유를 표시**한다. 이를 위해 다른 시장·다른 API의 숫자를 임의로 합치지 않는다. 순매수 금액·추세·단기 확대는 유지한다.
- 올해 이력이 실제로 제공되는지 확인한다. 최근 자료만 받고 연초 누적으로 표시하지 않는다. 과거 조회가 불가능하면 그 제한만 보고한다. 수백 API·타 증권사를 연속 조사하거나 KRX 수집으로 돌아가지 않는다.

### 7-4. 다음 동작

1. 사용자에게 KIS 계좌 보유·API 이용 의향을 확인한다. 새 계좌·키 사용이 부담이면 기존 이용 증권사 정보부터 받아 그 경로의 확인 범위를 좁힌다. 지금 KIS가 무조건 가능한 것으로 구현을 확정하지 않는다.
2. 사용자가 선택·승인한 경로만 공식 명세·소규모 조회로 확인한다. 핵심 자료를 확보하면 PLAN §9에 원천·필드·단위·기간 사실을 덧붙이고 전체 화면 목업으로 진행한다. 별도 조사 Step·전체 PLAN 재제출은 필요 없다. 핵심 제한이 발견될 때만 알린다.
3. 계좌 답을 기다리는 동안 이미 확인한 Yahoo 시각 처리·기승인 저장/응답 계획·계산 fixture·화면 배치 준비는 진행할 수 있다. 앱 구현은 기존 사용자 목업 확인 절차를 따른다. 수급이 비어 있는 상태로 28 종료를 선언하지 않는다.

CSV 업로드·KRX 유료 상품·네이버 수집은 이번에 병행 구현하지 않는다. CSV는 사용자가 그 운영 부담을 받아들이는 경우의 선택지로 남긴다. 이 판정은 사용자의 새 증권사 계정·API 사용 승인이나 실제 조회 성공을 의미하지 않는다.
