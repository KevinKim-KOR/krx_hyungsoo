# POC5-21 — PC 후보 수익률의 실제 계산 기간 표시

작성: 설계자 · 2026-10-17 · 독자: 개발자 / 사용자 / 검증자
상태: 다음 범위 지정 · 개발자 전체 화면 목업과 짧은 PLAN 대기

## 1. 종료 수용과 목적

- 사용자 전달의 커밋 `704d84a1`·push 보고를 근거로 POC5-20 종료를 수용한다. 실제 저장소를 직접 조회한 확인은 아니다.
- 이번 목표는 「요즘 잘 오르는 ETF」 후보의 수익률이 **어느 가격 날짜부터 어느 날짜까지의 값인지** 화면과 AI 해석용 복사문에서 확인하게 하는 것이다.
- 근거는 BACKLOG의 POC5-11 관찰이다: `basis_end_date`·`selected_basis_end_date`는 전체 저장 최신일을 쓰지만, `_compute_period`의 끝 가격은 종목마다 자기 마지막 저장 행이다. 이 관찰은 PC 시장 판정 날짜를 고친 것과 별개로 남아 있다. 현재도 같은 구조인지 PLAN에서 해당 경로만 확인한다.
- 예를 들어 시장 저장 최신일이 10-14인데 한 후보의 마지막 가격이 10-13이면, 그 후보 수익률을 '10-14까지 계산한 값'으로 보이지 않게 한다. 이 예는 확인용 fixture이며 새 실측 사례를 주장하는 것이 아니다.

## 2. 계산 기간 계약

- 기존 수익률 계산이 **실제로 선택한 시작 가격·끝 가격의 날짜**를 그 값의 근거로 전달한다. 전체 시장 최신일이나 요청 종료일을 종목의 실제 끝 날짜로 대체하지 않는다.
- 대상은 현재 화면과 AI 해석용 복사문에 이미 표시하는 후보 수익률이다. 지원 기간·기간 선택·정렬의 기존 뜻은 유지한다. '1개월'을 달력 개월이나 고정 저장일 수로 새로 정의하지 않는다.
- 종목별 실제 날짜는 수익률을 계산한 행에서 가져온다. 월말·휴장일을 추정해 날짜를 새로 만들거나 화면에서 가격 시계열을 다시 조회해 역산하지 않는다.
- 저장된 일간 변화처럼 시작 가격을 직접 선택하지 않는 값은 그 계산·자료원 정의와 실제 기준일을 표시한다. 임의 전날을 시작일로 붙이지 않는다. 실제 경로 차이는 PLAN에 적는다.
- 시장 전체 저장 최신일, 해당 종목 마지막 가격일, 각 수익률에 사용한 날짜를 구분한다. 현재 화면의 공통 기준일 필드가 무엇을 뜻하는지도 PLAN에서 확인한다. 이미 정정한 KODEX200 시장 판정 날짜는 유지한다.
- 수익률 숫자·단위·기간 선택·정렬·선정·필터는 그대로다. 이번에 기준일이 다른 후보를 임의 탈락시키거나 같은 날짜 가격으로 다시 계산하지 않는다.
- 기존 자료 부족 값·사유를 보존한다. 날짜를 확인하지 못하는 값에는 '계산 기간 확인 불가'를 명시하고 공통 최신일로 채우지 않는다. 기존에 계산 불가인 수익률을 새로 만들어 내지 않는다.

## 3. 화면과 복사문

- 기존 후보 목록·카드의 기간 안내 자리를 사용한다. 새 메뉴·별도 카드·독립 펼침 기능을 만들지 않는다. 개발자가 현재 배치와 함께 목업으로 구체화한다.
- 기본 선택 기간의 실제 시작~끝을 확인할 수 있게 한다. 모든 표시 후보가 같은 날짜를 쓰는 정상 상태는 공통 안내 한 번으로 묶어 날짜를 줄마다 반복하지 않는다. 이 공통 안내는 실제 표시한 후보 자료로 확인된 경우에만 쓴다.
- 끝 날짜가 공통 기준과 다른 후보는 그 후보 가까이에 **'수익률 끝일 YYYY-MM-DD'**를 짧게 보인다. 공통 기준과의 차이를 기본 화면에서 알 수 있어야 한다. 자세한 계산 정의를 읽기 위해서만 기존 클릭형 ?를 사용한다.
- 끝 날짜는 같아도 실제 시작일이 다르면 각 값의 실제 기간을 확인할 수 있어야 한다. 차이 자체를 새로운 오류·위험 등급으로 만들거나, 기간이 충분하다고 임의 판정하지 않는다.
- 여러 기간 수익률을 함께 보여 주는 경우 선택 기간의 핵심 안내는 기본 화면에 두고, 나머지 값의 실제 기간은 기존 기간 설명 자리 또는 공통 ?에서 구분해 확인하게 한다. 새 날짜 설명을 값마다 긴 문단으로 붙이지 않는다.
- AI 해석용 복사문은 **각 수익률과 그 실제 기간을 함께** 담는다. 예: `1개월 +3.20% (사용 종가 2026-09-11 → 2026-10-13)`. 일간 변화는 실제 기준일과 기존 자료원 의미를 쓴다. 화면에서 보인 날짜와 복사문의 날짜가 달라지면 안 된다.
- 복사문 머리말의 시장 저장 최신일은 후보 모두의 수익률 끝일을 보증하는 날짜처럼 표현하지 않는다. 수동 복사·기존 AI 세션 전달이 같은 텍스트 생성기를 쓰면 해당 공통 생성기를 정정한다. 새 외부 전송은 추가하지 않는다.
- 기존 ETF 필터·시장 국면·구성종목·중복률·해석 주의 문구는 유지한다. 수익률 기간 정정에 새 매매 의견을 붙이지 않는다.

## 4. 구현 범위

- 기존 PC 시장 조회 응답에 실제 기간의 선택 메타데이터를 연결할 수 있다. 이미 읽어 계산에 쓴 행을 재사용하고 종목별 날짜 확인용 SELECT·외부 조회를 추가하지 않는다. 새 API 경로·DB 표·의존성은 필요 없다.
- 날짜가 계산 함수 안에서만 확인되면 필요한 전달 경로를 최소한으로 확장한다. 공유 코드를 한 글자도 바꾸지 말라는 지시는 아니다. 기존 수익률 결과와 운영 호출의 동작을 보존하면서 **PC 응답과 복사문에만** 새 기간 계약을 적용한다. 정확한 방식과 기존 호출처는 PLAN에서 제시한다.
- OCI 근거 문장의 별도 날짜 관찰·운영 PUSH·원장·PARAM은 이번에 변경하지 않는다. 과거 저장 스냅샷의 날짜를 최신 자료로 다시 채우지도 않는다.
- `MarketDiscoveryView.tsx`는 POC5-12 당시 861줄로 근접 상태였다. 현재 줄 수를 확인하고, 필요하면 이번 기간 표시 부분만 작은 컴포넌트로 분리한다. 별도 선행 리팩터 단계나 화면 전체 재작성을 만들지 않는다.
- 종료 기록은 이 PC 기간 표시 관찰의 해소 범위를 적는다. OCI 문장까지 정정됐다고 기록하지 않는다. POC5-20 연구 결론과 Q6 운영 계약은 그대로다.

## 5. PLAN·목업·검사

1. 개발자는 짧은 PLAN에 값별 실제 계산 행·날짜의 생성 위치, 화면·복사문 이용처, 최소 전달 방식, 변경 파일과 검사를 적는다. 전수 감사는 반복하지 않는다. 사실이 이미 달라졌다면 그 차이와 권장안만 보고한다.
2. 개발자가 1440px·1000px 전체 화면에서 정상·한 후보의 끝 날짜 다름·실제 시작일 다름·기간 확인 불가를 목업으로 보여 준다. 실제 없는 상태는 격리 fixture로 표시한다. 라이브 DB는 바꾸지 않는다. 사용자가 목업을 확인한 뒤 PLAN을 설계자에게 제출한다.
3. 시험은 실제 선택 행의 날짜와 수익률 연결, 다른 종목 최신일 변화에도 해당 종목 실제 날짜 불변, 같은 끝일·다른 시작일, 결측, 화면·복사문 일치, 추가 조회 없음, 기존 수익률·정렬·운영 호출 결과 불변을 확인한다. 관련 검사와 백엔드 회귀·프론트 회귀·타입·린트를 수행한다.
4. 사용자 실화면·검증자 확인을 거쳐 결과서를 제출한다. 날짜가 원래부터 일치하는 정상 자료에서도 불필요한 줄이 늘지 않았는지 확인한다. OCI pull·거래일 운영 대기는 이 단계의 완료 조건이 아니다.
