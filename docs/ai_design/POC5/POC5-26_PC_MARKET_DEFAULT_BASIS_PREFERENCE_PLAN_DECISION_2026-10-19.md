# POC5-26 PLAN 판정 — 기본 조회 기준 설정

작성: 2026-10-19 · 설계자 → 개발자 / 사용자
근거: 제출 PLAN V1 · 사용자 목업 확인(2026-10-19 · Q1 (a) 그대로).

**판정: PASS. Q1 (a)를 수용한다. 아래 안내 문구만 반영하고 바로 구현한다. PLAN 재제출·목업 재확인은 필요 없다.**

## 1. Q1 판정

카드·표 보기 모두 목록 카드 맨 위에 기본 조회 기준과 저장 버튼을 둔다. 기준 변경은 기존 표 머리를 이용하며 카드 보기에 별도 선택 버튼을 추가하지 않는다. 설계의 '선택 옆' 배치를 현재 화면 구조와 사용자 확인 목업에 맞춘 것으로 수용한다.

## 2. 구현안 수용

- daily · one_month · three_month 중 하나만 이 브라우저에 저장한다. 기준을 임시 변경하거나 정렬 방향을 바꾸는 동작은 기본 저장이 아니다. 정렬 방향·필터·보기 방식은 함께 저장하지 않는다.
- 브라우저에서 화면 상태를 만들 때 설정을 읽어 첫 시장 조회 기준을 정하는 안을 수용한다. 메뉴 재진입 때 화면이 새로 올라오는 현행 방식도 유지한다. 다른 화면의 별도 1개월 요청을 이 화면의 중복 요청으로 세지 않는다.
- helper·작은 표시 컴포넌트·기존 표의 선택 top 영역으로 분리하는 안을 수용한다. 화면 전체 리팩터·새 설정 메뉴·백엔드 변경은 없다.
- 없음·허용 밖 값·읽기 실패는 기존 1개월로 시작한다. 허용 밖 값의 짧은 안내를 같은 자리에 보이는 판단도 수용한다. 읽는 과정에서 저장값을 자동 수정하지 않는다.
- 실제 표시·보유와 비교 조건·전달 자료는 현재 조회 응답을 따른다. 기존 복사/전달에 없던 기준 이름이나 필드를 이 작업 때문에 새로 추가하지 않는다.
- 저장 클릭은 설정만 쓰며 시장 GET을 만들지 않는다. 기존 조회 갱신·응답 순서·실패 시 받은 화면 유지 규칙을 보존한다.

## 3. 실패 안내 문구 정정

PLAN의 쓰기는 setItem 뒤 재읽기 결과까지 확인한다. 이때 예외·불일치만으로 '저장소를 쓸 수 없음'이나 '영구 저장된 기본은 이전 값 그대로'를 확정할 수 없다. **저장 실패 안내는 '기본값 저장을 확인하지 못했습니다. 현재 조회는 유지됩니다.'로 한다.** 화면의 기본 표시와 현재 조회를 임의로 바꾸지 않는 계약은 유지한다. 이 문구 정정은 같은 위치의 안내 정확성을 위한 것으로 별도 목업을 다시 만들지 않는다.

## 4. 검증과 진행

PLAN §3의 초기 조회·명시 저장·임시 변경·실패·메뉴 재진입·현재 조건 전달 및 기존 POC5-12 보존 검증을 수행한다. 필요한 프론트 검사와 프로젝트 필수 절차를 따르되 변경 없는 백엔드 전체 회귀를 추가하지 않는다. 사용자 실화면·검증자 확인 뒤 RESULT를 제출한다.

**OCI 운영점검은 이 PC 설정 기능의 선행조건이 아니다.** 기존에 정한 범위·일정의 운영점검은 별도로 유지한다. 이 판정 때문에 새 OCI 점검이나 대기 작업을 추가하지 말고 26 구현을 진행한다. 이 단계에는 OCI pull·거래일 대기·별도 인계 문서가 없다. 커밋·push는 기존 사용자 승인 범위를 따른다.
