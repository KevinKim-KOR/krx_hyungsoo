# POC5-19 실화면 의견 반영 — 차트 읽기와 세부 접근 개정

작성일: 2026-10-17 · 작성자: 설계자 · 독자: 개발자

**판정: 구현·시험 결과는 확인했다. 현재는 ‘사용자 실화면 확인 완료·사용성 보완 요청’ 상태이며 종료 판정이 아니다. 아래 보완을 같은 POC5-19 안에서 진행한다.**

## 1. 근거와 변경 목적

- 첨부 RESULT와 사용자 화면 두 장을 확인했다. 검증자 정식 판정 전이며, 설계자가 코드·서버를 직접 재검증한 것은 아니다.
- 가격 차트 영역에는 날짜·값 눈금이 보이지 않는다. 거래량 차트는 0·최대값·양끝 날짜는 있지만 중간 날짜·규모를 읽기 어렵다. 이를 데이터 부족이 아닌 표시 설계의 부족으로 본다.
- 목표는 사용자가 **언제, 얼마였고, 가격과 거래량이 같은 날짜에 어떻게 움직였는지** 직접 읽을 수 있게 하는 것이다. 상세를 열기 위해 페이지 아래로 내려가야 하는 배치도 고친다.
- 사용자 요청에 따라 이번 프론트 범위를 KOSPI·종목 가격·POC5-19 거래량 차트까지 보충한다. 기존 ‘오늘의 투자 점검 변경 없음’은 해당 KOSPI 차트의 읽기 개선에 한해 개정한다. 수치 계산·API·수집·OCI·PUSH는 바꾸지 않는다.

## 2. 상단에서 여는 공통 상세창

- 「확인 근거」의 선택 종목 제목 또는 세 근거 묶음 바로 위에 **[세부 흐름 보기] 하나**를 둔다. 기존 하단 버튼과 펼침 영역은 중복으로 남기지 않는다.
- 누르면 기존 UI 스타일의 공통 상세창을 연다. 창 제목에는 종목명을, 첫 부분에는 실제 자료 기준일과 기존 핵심 근거를 짧게 표시한다.
- 창 안에서 가격과 거래량을 함께 본다. 그래프와 선택 날짜의 값이 먼저 보이고, 계산 기간·출처·긴 설명은 아래나 ?에 둔다.
- 기본 화면의 세 근거 묶음과 가격 차트는 유지한다. 상세창에서 같은 자료를 크게 비교할 수 있도록 기존 조회 결과를 재사용한다. 상세창을 열고 닫을 때마다 가격 GET을 반복하지 않는다.
- 기존 가격 조회 상태를 상위에서 공유하는 등 필요한 작은 프론트 조정은 허용한다. 새 캐시 체계나 조회 API는 만들지 않는다. 이미 요청 중이면 준비 중 상태를 표시한다.
- 상세창은 화면 안에 맞추고 제목·닫기를 찾기 쉽게 한다. 1000px에서도 가로 스크롤 없이 읽을 수 있게 한다. 종목이 바뀌면 상세창과 선택 상태를 이전 종목에서 이어받지 않는다. 기존 대화창의 Esc·초점 복귀 방식을 재사용한다.

## 3. 차트 세 곳의 공통 읽기 기준

대상: KOSPI 차트, 「확인 근거」의 기존 종목 가격 차트, 새 거래량 차트. 공유 가격 차트의 기존 호출자에는 제목·단위가 맞게 적용되는지 확인한다. 나머지 화면 전수 개편은 요구하지 않는다.

- **가로축:** 날짜임을 기본으로 알 수 있어야 한다. 양끝과 중간 날짜를 읽을 수 있도록 폭에 맞춰 약 3~5개 눈금을 표시한다. 다른 연도를 가로지르면 연도도 구분한다.
- **세로축:** 실제 입력값의 단위와 약 3~5개 값 눈금을 표시한다. 지수는 pt, 가격은 원, 거래량은 주다. 기존 값이 정규화 값이면 그 기준을 명시하며, 이번에 새 정규화로 바꾸지 않는다.
- **가이드라인:** 값 눈금과 맞는 옅은 가로선을 둔다. 선이나 막대만 떠 있는 그림으로 만들지 않는다. 눈금은 데이터와 같은 좌표 변환을 사용한다.
- **정확한 값:** 차트 바로 위의 고정된 짧은 줄에서 선택 날짜·실제 값을 읽을 수 있게 한다. 마우스 또는 터치로 날짜를 고르고, 키보드 좌우 이동도 지원한다. 현재 선택을 선의 점/세로 안내선 또는 막대 강조로 구분한다.
- 처음에는 해당 차트의 가장 최근 저장 날짜를 선택한다. 툴팁만으로 수치를 제공하지 않으며, 화면 밖으로 잘리는 설명창에 의존하지 않는다.
- 작은 단위로 줄인 축 눈금과 별도로 선택값은 충분한 정밀도로 표시한다. 단위 생략 때문에 %·원·주를 혼동하게 하지 않는다.
- 거래량은 0 기준선에서 막대를 시작한다. 가격·지수의 축은 표시 범위에 맞춰 잡되 최솟값·최댓값이 눈금으로 드러나야 한다. 일정한 값·전부 0인 경우에도 좌표 계산이 깨지지 않아야 한다.
- 결측을 0이나 직전 값으로 채우지 않는다. 날짜 자리와 ‘자료 없음’을 유지하고, 가격 결측을 선으로 이어 정상 관측처럼 보이지 않게 한다. 기존 저장일 축을 달력의 연속 관측으로 설명하지 않는다.

## 4. 상세창에서 두 흐름 함께 읽기

- 상세창에서는 거래량의 최근 최대 20개 날짜를 공통 축으로 사용한다. 이미 받은 가격 시계열을 **날짜로 대응**시켜 같은 기간의 가격과 거래량을 위아래로 보여 준다. 배열 위치끼리 짝짓지 않는다.
- 한 날짜를 고르면 두 그래프가 그 날짜를 함께 가리키고, 가격·거래량의 실제 값을 같이 보여 준다. 해당 날짜 가격이 기존 응답에 없으면 자료 없음으로 둔다. 더 오래된 다른 날짜의 값으로 대체하지 않는다.
- 기본 화면 가격 차트의 기존 기간·기준은 그대로다. 상세창의 공통 기간은 제목/기간 줄에서 구분한다. 기존 응답 자료로 대응이 불가능한 사실이 확인될 때만 그 원인을 보고한다. 새 수집을 먼저 추가하지 않는다.
- 기존 거래량 평균·배수·변동성 계산은 그대로다. 과거 선택 날짜에 현재 기준일 평균을 ‘그날의 평균’으로 붙이지 않는다. 이번에 과거 배수 시계열이나 매매 신호를 만들지 않는다.
- 기준일이 다르거나 과거 자료인 경우 기존 안내를 보존한다. 날짜별 값 확인과 두 흐름의 비교를 제공하며, 미래 위험·가격 방향의 결론을 새로 만들지 않는다.

## 5. 진행과 완료 기준

1. 실제 세 차트의 입력값·단위와 기존 가격 응답 재사용 위치만 코드로 확인한다. 새 조사 보고서는 필요 없다. 실제 충돌이 없으면 프론트 배치·좌표·선택 표시 범위에서 진행한다.
2. 개발자가 1440px·1000px 전체 화면 수정 목업을 만든다. KOSPI 축/선택값, 종목 상세의 상단 진입, 열린 상세창과 날짜 선택 모습을 보여 준다. 결측 한 사례도 포함한다. 개인 보유 화면은 외부에 게시하지 않는다.
3. 사용자 목업 확인 후 PLAN의 프론트 범위와 수용 기준을 맞추고 구현한다. 이 판정 범위라면 PLAN을 다시 제출하지 않는다.
4. 축 눈금·단위·선택 날짜/값·두 차트 날짜 대응·결측/0·반복 열기 추가 GET 없음·기존 기간 선택 보존을 관련 화면 시험으로 확인한다. 타입·eslint·프론트 회귀를 실행한다. 백엔드가 그대로면 기존 백엔드 검사 근거를 재사용하고, UI 수정 때문에 전체 백엔드를 반복 실행하지 않는다.
5. 사용자 실화면 확인 뒤 정식 검증자에게 갱신한 RESULT를 제출한다. 현재 ‘사용자가 아직 화면을 보지 않음’ 표현은 실제 의견 수신 사실로 바꾸고, 보완 확인 완료와 구분해 기록한다.

- 사용하지 않는 POC5-16 파일 삭제는 이번 사용자 의견으로 자동 승인된 것이 아니다. 아직 별도 승인이 없으면 유지하며, 이 정리를 사용성 보완의 선행 조건으로 만들지 않는다.
- 별도 차트 고도화 단계·외부 조회·새 의존성·종합 위험 산식·운영 대기는 요구하지 않는다. 이번 단계의 완료 기준은 숫자와 날짜를 읽고, 상단에서 세부 비교를 할 수 있는 실제 화면이다.
