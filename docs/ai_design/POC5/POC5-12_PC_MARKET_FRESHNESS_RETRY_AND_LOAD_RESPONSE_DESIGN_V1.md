# POC5-12 — PC 시장 화면 응답·VIX 경고·실패 재시도 보완 설계 V1
작성: 설계자 · 2026-10-14 · 독자: 개발자 / 검증자
상태: 다음 범위 확정 · 짧은 개발 PLAN 제출 대기
근거: POC5-11 RESULT §4·§5·§7-1·§10, 사용자 첨부 화면

## 1. 종료 수용과 이번 판단
POC5-11(f950ebfa)의 종료 보고를 수용한다. 수집 연결과 PC 판정 날짜 정정은 해소된 범위다.
소스 재검증이나 종료 재판정은 요청하지 않는다. 아래 세 미해결 항목을 POC5-12에서 보완한다.

| 항목 | 결정 |
|---|---|
| 정상 수집 뒤 VIX 오래됨 경고 | KODEX200 날짜와 비교하는 규칙을 변경 |
| VIX만 실패한 뒤 6시간 대기 | 기존 버튼으로 VIX만 즉시 재시도 가능하게 변경 |
| 첫 조회 10초 초과 | 보고된 중복 요청·파일 감시 부하부터 줄이고 실제 화면 확인 |

현재 화면은 VIX 10-13·KODEX200 10-14를 각각 표시한다. 날짜가 다르다는 사실을 수집 실패로 취급하지 않는다.
이번 목적은 실제 사용상의 오류·대기를 줄이는 것이다. 새 투자 신호나 종합 위험 점수를 만들지 않는다.

## 2. VIX 최신성 경고
VIX의 기준은 POC5-11의 미국 동부 마감 비교일 계산을 재사용한다.
화면 조회 시각을 그 함수에 적용하고, 토·일은 직전 평일로 돌린 비교일 E를 얻는다.
실제 저장일 D 이후 E까지의 평일 수 L을 센다. KODEX200 날짜는 이 판정에 쓰지 않는다.

| 상태 | 표시 |
|---|---|
| D = E | 오래됨 경고 없음 · 실제 VIX 기준일 유지 |
| L = 1 | 오래됨 경고 없음 · 실제 기준일 유지, 상세에서 차이 확인 가능 |
| L ≥ 2 | 'VIX 자료 업데이트 확인 필요(기준일 D)' · 기존 갱신 이동 동작 |
| 날짜 없음·해석 불가 또는 D > E | 'VIX 기준일 확인 필요' · 실제 자료 상태 표시 |

L=1은 공개 지연·평일 휴장에 대한 간단한 운영 여유다. 최신 자료임을 보증하거나 투자 위험을 판정하는 기준이 아니다.
새 미국 거래일 달력은 만들지 않는다. L≥2도 확정 장애라고 단정하지 않고 업데이트 확인 대상으로 표시한다.
주말은 지연을 늘리지 않는다. 기준일을 오늘로 고쳐 쓰거나 자료 결측을 0·정상으로 대신하지 않는다.
계산값·종가·기존 위험 참고 산식은 유지한다. 바꾸는 것은 정비 큐의 최신성 안내다.

시간 계산은 기존 Python 마감 함수와 같은 곳에서 한다. 프론트에 미국 마감·서머타임 계산을 별도로 복제하지 않는다.
필요하면 기존 PC GET 응답에 작은 선택 필드를 붙여 판정과 비교일을 전달한다. 새 API 경로·DB 표는 만들지 않는다.
판정이 없는 응답을 다시 'VIX < KODEX200' 규칙으로 추측하지 않는다. 실제 날짜를 보이며 최신성 확인 불가로 둔다.

## 3. VIX만 실패하면 바로 재시도
전체 갱신의 다른 단계가 성공하고 VIX만 실패한 경우를 기존 작업 상태에 작은 명시적 표식으로 남긴다.
화면 문구의 부분 문자열이나 현재 VIX 날짜만으로 '직전 수집 실패'를 추정하지 않는다.
기존 상태 저장·조회 경계를 사용한다. 별도 원장·작업 큐·새 저장소는 필요 없다.

- 기존 전체 갱신의 6시간 대기 중이며 VIX 재시도가 필요하면, 같은 버튼을 'VIX 다시 받기'로 표시한다.
- 이 경우 사용자 클릭은 VIX 단계만 실행한다. ETF 전체·보유 개별주·KOSPI·NAV를 다시 받지 않는다.
- 같은 프로세스의 실행 중 작업 중복 방지는 유지한다. running이 끝나면 추가 대기·횟수 제한 없이 다시 누를 수 있다.
- 성공하면 재시도 표식을 해제한다. 실패하면 한국어 사유와 표식을 유지한다. 자동 반복은 하지 않는다.
- VIX만 받은 일을 '전체 시장 자료 갱신 완료'로 보고하지 않는다. 전체 갱신의 마지막 성공 시각·건수도 갱신하지 않는다.
- 기존 전체 갱신이 가능한 시점에는 원래 버튼·원래 전체 동작을 유지한다.
- 다른 단계도 실패한 경우의 처리나 전체 갱신 쿨다운 일반 규칙은 이번에 바꾸지 않는다.

PC를 다시 켜도 직전 VIX 단독 실패를 알 수 있도록 기존 상태 파일에서 표식을 보존한다.
VIX 재시도에도 11의 20초 요청 대기·미확정 날짜 제외·실패 격리를 재사용한다.
정상 수집 뒤 최신성 안내가 남는 것만으로 재시도 실패 표식을 세우지 않는다.

## 4. 첫 화면 조회 지연
RESULT §5-8의 측정을 출발점으로 쓴다. 동일 동시 요청 8개·3회 재현을 다시 반복 조사하지 않는다.
같은 시장 요청 2개, 확인 근거 계산 1개가 차례로 4.8~5.1초씩 걸리고 서버는 200으로 끝났다는 보고다.
원인과 개선 전후 수치는 개발자 보고와 실제 확인을 구분해 결과서에 남긴다.

최소 변경 순서는 다음과 같다.
1. 같은 화면에서 같은 입력의 GET이 진행 중이면 그 요청을 공유한다. StrictMode의 중복 요청을 먼저 줄인다.
   완료 응답을 오래 보관하는 캐시·새 버전 관리·자동 재조회는 만들지 않는다.
2. PC backend의 파일 감시 범위를 실제 코드 경로로 좁힌다.
   코드 수정 시 자동 다시 읽기는 유지하고 state·node_modules·가상환경 등 불필요한 감시를 줄인다.
3. 먼저 완료된 영역은 표시한다. 시장 요청 하나의 지연 때문에 이미 받은 전체 화면을 오류로 덮지 않는다.
4. 위 보완 뒤에도 지연이 남으면 해당 GET의 대기·계산·DB 읽기 중 어디가 차지하는지 한 번 좁혀 측정한다.
   동기 계산이 다른 GET을 막는 것이 원인이면 기존 실행 경계로 보완한다. 새 작업 서버·큐·DB는 만들지 않는다.

기존 10초보다 긴 실제 정상 응답이 남으면 해당 시장 GET의 제한을 20초로 조정할 수 있다.
이를 '계산이 빨라졌다'고 보고하지 않는다. 공통 API timeout이나 VIX 수집 timeout과 혼동하지 않는다.
목표는 일상적인 화면 열기에서 시간 초과 오류가 반복되지 않고, 한 번의 실제 요청 결과를 읽을 수 있는 것이다.
새 초단위 SLA나 모든 계산의 성능 재설계는 이번 완료 조건이 아니다.

## 5. 짧은 PLAN에서 확인할 것
- 기존 미국 마감 함수와 PC 응답 조립 위치, 정비 큐 표시 변경 위치.
- VIX 단독 실패 표식을 보존할 기존 상태 필드와 같은 버튼·기존 갱신 경로의 연결.
- 현재 화면의 중복 GET 위치와 파일 감시 설정, 보고된 측정으로 설명되지 않는 지점이 있는지.
- 바뀌는 파일·격리 시험·실제 확인 방법. 전체 백로그·자료원을 다시 조사하지 않는다.

문구만 기존 위치에서 바꾸는 것은 새 전체 목업 확인 회차가 필요 없다.
새 배치·동선을 제안해야 하면 개발자가 실제 전체 화면 목업을 PLAN과 함께 준비한다. 설계자는 목업을 그리지 않는다.
PLAN 판정 뒤 구현한다. 이 문서는 즉시 구현 승인이나 실제 코드 VERIFIED 판정이 아니다.

## 6. 검증·종료·남은 범위
검증은 바뀌는 동작에 집중한다.
- 첨부 사례(10-14 국내·10-13 VIX)에서 잘못된 오래됨 경고가 사라짐.
- 마감 전후·서머타임·주말, 1평일 여유·2평일 이상·날짜 없음의 표시와 원래 값 보존.
- VIX만 실패 → 대기 중 기존 버튼 → VIX만 호출, 성공·재실패·PC 재기동·중복 클릭.
- VIX 재시도 뒤 전체 갱신 시각·건수 보존, 정상 수집을 실패 표식으로 바꾸지 않음.
- 같은 입력 중복 GET·입력 변경·화면 이동 시 늦은 응답이 다른 화면 상태를 덮지 않음.
- 보완 전후 요청 수·화면 표시 시간·실제 timeout 여부, 코드 자동 다시 읽기 유지.

실제 확인은 사용자의 일반 화면 열기와 기존 갱신 동작으로 한다. 실패 사례는 격리 fixture로 검증한다.
OCI·PUSH·보유·원장·시세 산식은 유지한다. 불가피한 공유 경로 충돌은 그 지점만 PLAN에 보고한다.
새 외부 조회·정기 갱신·첫 거래일 대기·라이브 파일 전수 해시를 추가하지 않는다.
종합 위험 분류·KOSPI 지수 거래량 등의 미완료 요구는 그대로 남는다. 이번 사용성 보완이 전체 개발 완료는 아니다.
