# POC5-21 후보 수익률 실제 기간 표시 — PLAN 판정

작성일: 2026-10-17 · 작성자: 설계자 · 수신: 개발자 / 사용자

**기술 판정: PASS — 아래 확정을 반영한다. 수정 목업을 사용자가 확인하면 PLAN 재제출 없이 구현한다.**

첨부 PLAN을 설계 V1과 대조했다. PLAN의 사용자 목업 확인은 아직 대기 상태다. 맥북 로컬 목업을 설계자가 직접 본 것으로 기록하지 않는다. 코드 경로·실측은 개발자 조사 근거로 수용한다.

## 1. 질문 세 가지 확정

| 질문 | 판정 | 적용 |
|---|---|---|
| Q1 KODEX200 대비 기간 | **(b)** | 후보와 KODEX200 각각의 실제 시작·끝 날짜를 전달·표시한다. 서로 다른 기간을 쓰는 비교를 그대로 숨겨 두지 않는다. |
| Q2 복사문의 다른 수익률 | **(a)** | 단기 흐름 5·10·20구간과 데이터 품질의 일간 줄에도 실제 사용한 날짜를 붙인다. 이미 있는 날짜와 같은 계산에서 선택한 행을 재사용한다. |
| Q3 공통 기준 | **(b), 아래 보충** | 끝일 차이는 시장 저장 최신일과 비교한다. 날짜를 채우는 용도로 쓰지 않는다. 과반의 날짜를 정상 기준으로 정하지 않는다. |

### Q1 — 계산은 유지하고 비교 의미를 정확히 표시

- 후보의 달력 30/90일 계산과 KODEX200의 20/60저장일 계산을 이번에 일치시키거나 수익률을 다시 계산하지 않는다. 기존 숫자·정렬·선정은 보존한다.
- 두 값의 실제 기간이 다르면 기본 화면에 **'기간 다른 수익률 차이'**를 짧게 표시한다. 같은 안내가 모든 후보에 공통이면 제목·열 머리말·공통 안내에서 한 번으로 묶고, 후보별로 다른 경우에 해당 값 가까이 표시한다. 양쪽 실제 시작~끝은 기존 클릭형 ?에서 확인하게 하고, 복사문에는 두 기간을 직접 적는다. 기간 미확인도 숨기지 않는다.
- 두 수익률의 뺄셈 결과는 수익률 차이이며 표시 단위는 **%p**다. 기존 수치 스케일은 바꾸지 않는다. 기간이 다른 경우 이를 동일 기간 초과수익이나 시장 우위가 검증된 값으로 설명하지 않는다. 복사문의 해당 제목·설명도 이 뜻에 맞춘다.
- KODEX200 날짜는 이미 읽어 계산에 사용한 행에서 전달한다. 필요한 파일·선택 메타데이터를 PLAN 목록에 보충할 수 있다. 추가 SELECT나 운영 호출 결과 변경은 요구하지 않는다.

### Q3 — 같은 사실만 공통으로 묶기

- 선택 기간 수익률이 있는 표시 후보들의 실제 시작·끝이 **모두 확인되고 모두 같은 경우에만** 공통 기간 한 줄과 '모두 같음'을 쓴다. 수익률 자체가 없는 후보는 기존 자료 없음 표시를 유지하며, 그 후보까지 날짜가 확인됐다고 세지 않는다.
- 값은 있는데 날짜가 없는 후보를 제외한 뒤 전체가 같다고 표현하지 않는다. 일부 미확인은 공통 안내에서 알리고 해당 후보에도 표시한다. 전부 미확인이면 공통 안내 한 번으로 묶는 목업 방식을 수용한다.
- 날짜가 여러 종류면 '종목별 계산 기간 다름'으로 안내한다. 같은 시작일·끝일은 공통으로 묶을 수 있고, 다른 부분은 해당 값 가까이 표시한다. 시작일이 여러 종류이면 각 값의 실제 시작일을 보여 주며 과반의 시작일을 기준으로 예외를 정하지 않는다.
- 각 후보 끝일이 시장 저장 최신일과 다르면 목업의 '수익률 끝일 YYYY-MM-DD'를 유지한다. 다수 후보가 오래된 날짜를 쓴다고 그 날짜를 최신 기준으로 바꾸지 않는다.

## 2. 표시와 구현 보충

- 최상위 `asof`가 가격 표 전체 `MAX(date)`이면 요약 명칭은 **'시장 저장 최신일(저장된 전체 종목 가격 중 가장 늦은 저장일)'**로 한다. 이 표에는 보유 개별주도 있으므로 '전체 ETF 가격'이라고 쓰지 않는다. KODEX200의 `market_context.asof`는 기존대로 구분한다.
- 짧은 저장 이력으로 6개월·12개월·3년 값이 같아지는 경우, 실제 시작일을 명확히 보여 주고 선택한 명목 기간 전체의 수익률이라고 설명하지 않는다. 실제 가격 날짜를 보여 주는 범위이며 새 기간 충족 판정이나 과거 가격 보충은 추가하지 않는다.
- 표 아래에 남은 중복 '1년' 안내는 실제 지원 열에 맞게 같은 작업에서 정정한다. 별도 단계로 미루지 않는다.
- 기본값 False인 PC 선택 메타데이터 방식, 순수 기간 표시 helper와 작은 컴포넌트, 기존 계산 행 재사용을 수용한다. 다른 7개 호출의 출력과 기존 계산·순위 불변을 검증한다. 새 경로·수집·스키마·의존성·OCI·PUSH 변경은 없다.
- 설계 §5-3과 PLAN의 '다른 종목 최신일이 늘어도 해당 종목 날짜 불변'은 **실제 끝 가격 행이 같으면 그 끝일이 불변**이라는 뜻으로 정정한다. 기존 계산은 시장 최신일에서 기간 시작을 정하므로, 최신일 변화로 선택 시작 행이 바뀌면 실제 시작 날짜도 그 행을 따라야 한다. 시작일까지 무조건 고정하는 시험이나 계산 변경을 하지 않는다.
- 시험에는 두 비교 기간의 일치·불일치·미확인, 과반이 오래된 끝일인 경우에도 최신 기준이 바뀌지 않음, 일부 값만 날짜 없음, 개별주만 더 최신인 경우의 공통 최신일 명칭, 화면·복사문의 실제 날짜 일치를 보충한다. 기존 PLAN의 나머지 시험·회귀 범위는 수용한다.

## 3. 진행

- 개발자는 이 판정을 PLAN에 반영하고 해당 상태의 목업을 수정한다. 정상 화면은 한 줄로 간결하게 유지하고, 날짜 차이·KODEX200 비교 안내가 함께 있는 1000px 화면도 사용자에게 보여 준다.
- **사용자의 수정 목업 확인 뒤 바로 구현한다.** 확인을 받았다는 기록만 남기면 되며 추가 PLAN 판정은 필요 없다. 이후 실화면·검증자·RESULT 순서는 기존 설계대로다.
- 본 판정은 목업 사용자 확인 완료나 새 커밋·push 승인을 대신하지 않는다. 별도 조사 단계·선행 리팩터 단계·OCI pull·거래일 대기를 추가하지 않는다.
