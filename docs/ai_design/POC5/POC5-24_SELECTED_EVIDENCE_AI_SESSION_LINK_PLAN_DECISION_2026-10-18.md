# POC5-24 선택 근거의 AI 투자세션 연결 — PLAN 판정

작성일: 2026-10-18 · 작성자: 설계자 · 수신: 개발자 / 사용자

**판정: 기술 PLAN PASS. Q1·Q2·Q3 모두 (a). 아래 보충을 PLAN·목업에 반영하고 재제출 없이 진행한다.**

제출 PLAN을 설계 V1과 대조했다. 현재 코드의 동선·저장 구조는 개발자 조사 보고를 근거로 수용한다. 이번 첨부에는 목업 원본이 없고 사용자 확인 기록도 아직 없으므로, 실제 배치 검토나 사용자 목업 승인 완료로 기록하지 않는다.

## 1. 질문 확정

| 질문 | 판정 | 적용 |
|---|---|---|
| Q1 목록의 대상 표시 | **(a)** | 목록 응답의 선택 필드 `target_label`을 허용한다. 선택 근거 모드이며 저장된 선택 종목이 한 개인 기록에서 이름·티커를 읽어 만든다. 기존 요약 앞에 표시하고 새 제목 열·DB 변경은 만들지 않는다. 일반 후보가 우연히 한 개인 옛 기록까지 선택 근거 모드로 해석하지 않는다. |
| Q2 기존 초안 확인 | **(a)** | 새 전달 버튼에서만 확인 줄을 제공한다. [취소]는 기존 초안·현재 미리보기를 보존하고, [바꾸고 이동]에서만 교체한다. 기존 두 전달 경로의 동작과 답변의 메뉴 이탈 시 소실 동작은 이번에 확대 수정하지 않는다. |
| Q3 필수 필터 | **(a)** | 두 대상 종류 모두 당시 「보유와 비교」 화면의 네 필터를 저장한다. 선택 근거 기록에서는 '당시 화면의 후보 목록 필터'로 표시한다. 보유 종목 자체를 이 필터로 골랐다는 뜻으로 설명하지 않는다. 기존 API 필수 계약은 유지한다. |

## 2. 저장·표시 보충

- 기존 `candidate_snapshot_json` 한 건 안의 선택 모델 `selected_preview`를 수용한다. 요청·저장·상세 재조회에서 원문·대상 종류·생성 시각·각 근거 날짜가 보존돼야 한다. 질문 편집과 처음 넘긴 원문을 구분하고, 같을 때 원문을 두 번 표시하지 않는 안도 수용한다.
- 선택 근거 모드에서 `source_screen=holdings_compare_preview`, 후보 한 건, 원문 질문, 관련 없는 스냅샷 null, 최신 ML 근거 자동 보충 생략을 수용한다. 이동은 초안 준비이며 DB 자동 저장이 아니다. 기존 전체 후보 전달·과거 기록은 기존 동작을 유지한다.
- **가격 기준일이 없는 경우:** 필수 `asof`에 생성 날짜를 쓰는 안은 선택 근거 모드의 '기록 기준일'로만 허용한다. 이때 '기록 기준일 — 미리보기 생성일 사용'으로 표시하고 실제 가격 기준일은 '미확인'으로 둔다. `selected_preview.evidence_as_of.target_as_of_date`를 생성일로 채우지 않는다. 가격 기준일이 있으면 그 날짜를 사용한다. 생성 날짜는 전달받은 생성 시각의 KST 날짜로 정한다.
- 확인 줄의 UTC 초안 시각은 **Asia/Seoul(KST)**로 표시한다. 브라우저가 설정된 다른 시간대에 따라 바꾸지 않는다. 기존 저장 문자열은 유지하고 해석 실패 시 원문을 표시한다. 새 날짜 표시 체계는 만들지 않는다.
- 작성 화면의 출처 설명, 상세의 '선택 종목' 명칭, 순위 없는 보유의 '1.' 제거를 함께 수용한다. 후보의 순위는 전달 당시 목록 순위이며 새 투자 추천 순위가 아니다.
- 초안 교체 확인 중 종목·종류·목록 조건이 바뀌어 기존 미리보기가 비워지면 확인 줄도 닫고 이전 전달을 취소한다. 확인 버튼으로 예전 종목 원문을 새 종목 이름에 붙이지 않는다.
- Q2 확인 줄이 보호하는 범위는 sessionStorage에 남아 있는 전달 초안이다. 메뉴를 떠날 때 이미 사라지는 입력 중 답변까지 복구·보호하는 기능으로 설명하지 않는다. 별도 답변 자동 저장·전역 초안 관리 과제는 만들지 않는다.

## 3. 검사와 진행

- 예정 파일·시험 범위를 수용한다. 실제 생성 API → 저장 → 목록·상세 재조회로 `selected_preview`가 유실되지 않는지, 질문 편집 뒤 원문 보존, 일반 한 종목 기록과 선택 모드 구분, 가격 날짜 미확인, KST 표시, 교체 확인 중 선택 변경을 필요한 연결 시험에 포함한다.
- POC5-23의 `preview_text`는 그대로 전달·저장한다. 새 숫자 포맷·근거 재조회·최신값 자동 대체는 추가하지 않는다.
- PLAN에 본 판정을 반영한다. 백엔드 모델·목록 응답·저장 왕복 시험은 진행할 수 있다. 화면은 보충 표기를 반영한 목업을 사용자에게 확인받은 뒤 구현한다. 판정대로 반영하면 추가 PLAN 판정은 필요 없다.
- 이후 사용자 실화면 → 검증자 → RESULT로 진행한다. 실제 AI 답변 입력·판단의 정답·실제 매매·라이브 시험 기록 생성을 별도 완료 조건으로 요구하지 않는다. 기존 저장 조건인 답변 한 개 이상은 유지한다.
- OCI pull·거래일 대기·별도 인계 문서·미사용 파일 삭제 승인·다른 전달 경로의 초안 보호 보완은 이번 진행 조건이 아니다. 커밋·push는 사용자 승인 범위를 따른다.
