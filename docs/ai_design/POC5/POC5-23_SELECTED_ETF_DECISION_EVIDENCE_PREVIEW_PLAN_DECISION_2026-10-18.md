## 2. 중복 근거의 범위

- 후보는 **직접 보유 여부**와 **후보 ETF ↔ 현재 보유 ETF의 구성종목 중복**을 나눠 제공한다. 기존 분석의 매칭·중복률 정의·저장 구성종목 범위를 그대로 사용한다. 전체 포트폴리오 중복 비중이나 새 경고 등급을 만들지 않는다.
- 저장된 구성종목으로 계산 가능한 쌍만 계산하고 비교 가능 a/b개와 누락 사유를 함께 남긴다. 자료가 없는 쌍을 0%로 넣거나, 일부 쌍의 일치 0건을 전체 보유와 '중복 없음'으로 표현하지 않는다.
- 실제 겹침 대상·기존 중복률·양쪽 자료 기준일을 제공한다. 표본 구성종목만 사용한 중복률을 ETF 전체를 완전히 조사한 값으로 설명하지 않는다. 기존 분석의 한계 문구를 재사용한다.
- 보유 분기의 `constituents_overlap`이 '현재 후보들에 반복되는 구성종목'을 뜻한다면 그 비교 대상을 그대로 적는다. 이를 '내 보유 ETF 사이 중복'이라고 바꾸지 않는다.
- 새로운 구성종목 수집·자동 갱신·fetcher·외부 호출은 없다. 자료 부족은 해당 묶음의 사유이며 나머지 미리보기는 제공한다. 기존 분석 연결에 필요한 작은 로컬 읽기와 조립 변경을 허용한다.

## 3. 같은 화면에서 함께 정정할 사항

- **단기 비교 문구:** PLAN과 시안의 'KODEX200 대비(같은 저장일 구간)'은 사용하지 않는다. **'단기 KODEX200 차이(저장일 수 기준)'·%p**로 쓴다. 기존 5/10/20구간 계산은 양쪽 시작·끝 날짜의 일치를 검사하지 않는다. 도움말·복사문에 이를 한 번 설명하고 POC5-22의 1/3개월 실제 동일 날짜 비교와 구분한다. 단기 산식을 다시 만드는 작업은 하지 않는다.
- **후보 화면의 중복 표시:** 잘못된 식별자 비교에서 나온 '보유 ETF 0개'·'중복 없음'은 확정 근거로 표시하지 않는다. 직접 보유 사실은 유지하고 실제 비교 전에는 구성종목 중복 미확인으로 둔다. 새 계산 결과를 화면에 연결하는 데 별도 자동 조회는 추가하지 않는다. 현재 「보유와 비교」 동선의 최소 표시 정정을 이번에 함께 한다.
- **화면의 오래된 고점 대비:** 실제 스냅샷 가격 기준일을 이미 전달받는다면 그 날짜와 '과거 스냅샷'을 값·정렬 기준에서 분명히 표시한다. 날짜를 화면에서 확인할 수 없다면 이 화면에서 해당 값과 그 값을 쓰는 정렬을 사용하지 않는다. 시장 최신일·생성일로 날짜를 대신 붙이지 않는다. 새 현재값 계산이나 스냅샷 갱신은 만들지 않는다. 적용은 관련 데이터 구조에 맞는 최소 변경으로 하고 결과서에 기록한다.
- **빈 상자처럼 보이는 버튼:** [세부 근거 펼치기]의 글자색을 해당 버튼 범위에서 함께 고친다. 기존 크기·모양·동작은 유지하며 이 CSS 정정을 별도 단계로 나누지 않는다.

## 4. 조립·검사 보충

- PC 화면과 같은 응답 조립 경로, 생성 시각 선택 필드, 대상 가격 기준일 연결, 상자 표시와 복사 원문의 일치를 수용한다. 동일한 계산 함수를 사용해도 클릭 시 재조회로 날짜·입력이 달라졌으면 이전 화면과 같은 시점 자료라고 설명하지 않는다.
- 선택 종목 **또는 후보 목록 조건**이 바뀌면 이전 미리보기를 비우고 늦은 응답을 버린다. 현재 조건으로 다시 계산했을 때 종목이 없으면 그 사유를 알리며 다른 조건의 종목 값으로 채우지 않는다.
- REJECT된 참고점수 문구 제거, NAV·자료 상태의 실제 키 연결, 기존 보유 비중·손익 정책 유지, 소비처 한 곳의 수동 복사를 수용한다. 별개인 AI 세션 저장 경로·LEGACY 초안·PUSH를 이번에 고치지 않는다.
- 예정 검사를 수용한다. Q3에는 실제 ETF 구성종목끼리 비교되는 사례·부분 자료 누락·직접 보유와 중복의 구분을, Q1에는 목록 조건 변경을, 단기 문구에는 실제 동일 날짜를 보장하지 않는 계약을 반영한다. 전체 백로그 소스 감사나 별도 검증 프레임워크를 추가하지 않는다.
