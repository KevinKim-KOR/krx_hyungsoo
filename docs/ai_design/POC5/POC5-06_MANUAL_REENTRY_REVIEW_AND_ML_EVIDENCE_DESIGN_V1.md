## 2. 완료 모습과 화면

기존 「종목 관리」의 History 창에 **[재진입 검토]**를 추가한다. 과거 보유와 현재 보유 모두 선택할 수 있다. 버튼을 누르면 선택 종목·계좌·보유 기간을 고정한 검토 창을 연다. 창을 연 것만으로 학습·외부 조회를 실행하지 않는다.

검토 창은 세 부분으로 구성한다.

| 부분 | 표시 내용 |
|---|---|
| 내 거래 | 선택 기간과 이전 기간의 거래·실현손익, 마지막 실제 매도, 매수일 미상·입력 정정 안내 |
| 저장된 근거 | 매도 기준일 이후 가격 변화, 최근 가격 상태, 같은 종목의 알림·객관적 가격 결과·선택 평가 |
| ML 검토 | [ML 검토 실행], 추정 기준일, 실험 추정값, 단순 기준과 과거 검증 오차 비교, 한계 |

계좌·기간별 손익은 합치지 않는다. ML은 종목 가격만 사용하므로 같은 종목·다른 계좌라고 모델을 따로 학습하지 않는다. 입력 정정으로 종료한 기간에는 실제 매도일·매도 손익을 만들어 넣지 않는다.

가격은 ‘저장 종가 YYYY-MM-DD 기준’으로 표시한다. 현재 체결 가능 가격으로 부르지 않는다. 자료가 낡으면 ‘이 날짜 기준 검토’임을 추정값 옆에 표시한다. 일반 문구의 ‘지금’, ‘현재 재진입 적기’로 바꾸지 않는다.

기존 PC 가격 갱신 화면과 ‘받은 알림 기록’의 수동 새로고침으로 이동할 수 있게 한다. 검토 버튼이 이를 자동 실행하지 않는다. 기존 갱신이 전체 ETF를 받는다면 그 사실을 그대로 안내하고, 이번 기능 때문에 새 단일 종목 수집기를 만들지 않는다.

[재매수]는 기존 05 매매 창을 여는 동작이다. ML 결과를 누르면 거래가 저장되는 연결은 만들지 않는다. 신규 메뉴는 없다. 창과 버튼을 보여 주는 작은 목업 한 번을 backend 구현 중 확인하며, 기존 05 전체 목업 확인을 반복하지 않는다.

사용자 평가가 있으면 사용자의 판단 근거로 먼저 보여 준다. 객관적 가격 결과와 ML 추정값을 그 평가로 덮어쓰지는 않는다. 평가가 없는 알림도 그대로 조회·후속 ML 자료로 사용할 수 있다. 이번 모델은 가격 기반이므로 평가 유무가 학습 표본이나 추정값을 바꾸지 않는다.

## 4. 가격·날짜 계약

06 ML은 **PC etf_daily_price의 네이버 계열 저장 종가**만 쓴다. 가격 의미 표기는 **‘저장 종가(네이버 계열·분배락 조정 흔적·총수익 여부 미확정)’**로 통일한다. ‘분배금 미반영’, ‘공식 무조정 종가’, ‘확인된 총수익’으로 바꾸지 않는다. 05의 reader는 두 날짜 지점용이므로 ML에는 mode=ro SELECT로 전체 계열을 읽는 별도 reader를 둔다. OCI KRX 무조정 가격·봉인 KRX DB·원장 price_outcome을 학습 계열에 붙이지 않는다.

개별주는 개인 History와 기존 알림을 조회할 수 있다. 05 조사에서 PC 개별주 가격이 오래됐고, 장기 공식 가격 계열이 확인되지 않았으므로 이번 ML 학습 대상은 ETF로 한정한다. 개별주를 ETF로 분류하거나 오래된 FDR 값으로 오늘의 모델을 만들지 않는다.

기준일 t는 마지막 저장 완료 종가일이다. **06만의 연구 축**은 해당 연도 거래일 파일이 있으면 파일, 없으면 기존 평일 기본 규칙과 KOSPI 저장일의 교집합이다. 기존 `trading_days_ending(..., stored=KOSPI 저장일)`의 뜻을 재사용한다. +20은 선택 ETF 가격 행 20개 뒤가 아닌 이 축의 다음 20번째 날짜다. ‘공식 휴장 목록이 아닌 KOSPI 저장일 보정 연구 축’을 결과·입력 snapshot에 표시한다. 누락된 KOSPI 저장일이 실제 거래일이어도 축에서 빠질 수 있다는 한계가 있다. 공식 파일 생성·운영 Calendar·02 outcome 규칙은 바꾸지 않는다.

축 날짜·연도별 적용 방식·파일/저장일 근거·KOSPI 최신일·기본 평일 중 제외된 날짜/건수를 보존하고 hash에 넣는다. 기준 ETF의 t가 축에 없거나 파일 없는 해의 KOSPI 최신일이 t보다 이르면 `AXIS_UNCERTAIN`이다. 최신성 비교는 기존 완료 거래일 규칙을 재사용하고 저장 최신일·기대일을 함께 표시한다. 축이 불확실해도 개인 History·기존 원장 근거는 조회할 수 있다.

- 연구 축의 날짜 공백·감지된 기준 변화 경계를 넘는 feature/target 창은 제외한다. 다른 날짜·다른 소스로 채우지 않는다. 같은 네이버 reader의 NAVER_FDR → FinanceDataReader 라벨 변경 자체는 경계가 아니다.
- 종가가 유한한 양수가 아니면 그 창은 제외한다. 빠진 거래일을 제거한 뒤 남은 행을 연속 거래일로 취급하지 않는다.
- FinanceDataReader 행의 저장 change와 직전 저장 종가로 계산한 변화의 차이가 절대 비율 1e-6을 넘으면 경계다. FDR → NAVER_FDR 재전환도 보수적으로 경계로 둔다. 첫 가격 행이 아닌 FDR 행의 change 누락 등 연속성을 확인할 수 없는 지점은 해당 창을 제외한다. 연속성을 확인할 change가 없는 NAVER_FDR 구간은 제한된 연구용 저장 계열로 사용하되 경계 검사가 부분적임을 표시한다(§10-3).
- 미허용 출처·가격 의미 미확인 창을 학습에서 제외하고 사유를 센다. t의 feature 창을 확정할 수 없으면 `PRICE_BASIS_UNCONFIRMED`로 현재 추정값을 만들지 않는다. 옛 구간 내부의 미감지 계단이 남을 수 있다는 한계는 숫자 옆의 자료 한계와 상세 결과에 보존한다. 경계를 감지했다는 사실이 전체 가격 계열의 일관성을 입증한 것은 아니다.
- 정확한 가격 계열·source·제외 사유를 결과에 남긴다. 과거 수정값을 사용한 연구는 현재 저장 자료 기준 재구성이지, 당시 공개 시각까지 확인한 PIT 검증이라고 부르지 않는다.
- 매도 기준일 가격과 마지막 저장일 가격이 같은 계열로 존재할 때만 매도 후 변화율을 만든다. 기준일이 더 늦거나 가격이 없으면 값을 만들지 않는다.

## 5. ML 실험 한 가지

### 5-1. 목표와 입력

모델은 미래 수익률 순위나 ‘재매수 확률’을 출력하지 않는다. 다음 수치 하나를 추정한다.

```text
D20(t) = min(0, min(C(t+h) / C(t) - 1, h=1..20))
```

이름은 **‘이후 20거래일 최저 종가 변화(연구 추정)’**다. 화면·문서에서 ‘하락 위험 예측’으로 줄이지 않는다. 연구 축과 저장 가격으로 계산한 기준일 대비 가장 낮은 종가 변화이며 고점에서 저점까지의 최대낙폭(MDD), 장중 최대손실, 손실 확률이 아니다. 전 구간 종가가 기준일보다 높으면 0이다. 총수익 여부 미확정인 저장 가격 변화이고, 비용을 포함한 매매 성과가 아니다.

입력은 t까지의 가격으로 계산한 다섯 값으로 고정한다.

1. 5거래일 종가 변화 `C(t)/C(t-5)-1`
2. 20거래일 종가 변화 `C(t)/C(t-20)-1`
3. 60거래일 종가 변화 `C(t)/C(t-60)-1`
4. 최근 20개 일별 로그수익률의 표준편차(모집단 표준편차, ddof=0)
5. 최근 60거래일 최고 종가 대비 현재 종가 변화 `C(t)/max(C(t-59)..C(t))-1`

모델은 **StandardScaler → Ridge(alpha=1.0, solver='svd', fit_intercept=True)** 하나다. 기존 설치된 scikit-learn을 사용하며 설치·버전 변경·RF/XGB/LGBM·설정 탐색은 없다. 가격 변화는 내부에서 소수 비율로 계산한다. 예측은 D20의 범위 [-1, 0]로 제한하며 검증과 최종 추정에 같은 제한을 적용한다.

비교 기준은 해당 학습 구간 D20의 중앙값을 모든 검증 날짜에 적용하는 고정 예측이다. 과거에 보지 못한 날짜에서 이 단순 기준보다 나은지 확인한다. 모델·목표·기간을 결과에 맞춰 바꿔 같은 실험의 성과를 다시 주장하지 않는다.

### 5-2. 과거 검증과 실행

선택 ETF 하나에 대해 사용자가 누를 때 표본 생성·과거 검증·최종 학습을 한 번 실행한다. 전 종목 순위 계산·야간 재학습·매도 종목 자동 추적은 없다.

검증 종료 기준일은 §4 연구 축에서 t보다 20일 전으로 고정한다. 이 날까지의 **마지막 189개 기준 날짜**를 오래된 순서로 63일씩 세 구간으로 나눈다. 누락 날짜도 축의 구간 안에 남기고 해당 표본만 제외한다. 학습은 각 구간 시작일보다 앞에 D20 평가 종료일까지 완료된 표본만 사용한다. 해당 날짜에 학습 가능한 표본이 252개 미만이면 그 구간은 `DATA_SHORT`다. 이 값들은 1년 학습·분기 단위 검증에 해당하는 연구 길이이며 투자 유효성 통과선이 아니다.

표준화는 각 학습 구간에서만 fit한다. 검증 구간의 값·정답을 표준화·학습·설정 선택에 쓰지 않는다. 마지막 과거 학습일의 정답이 검증 기간에 걸치면 제외한다. 날짜를 무작위로 섞거나, 유효 행 20개를 제외한 것만으로 날짜 경계가 지켜졌다고 간주하지 않는다.

세 구간에 학습 요건과 유효 검증 표본이 모두 있으면 구간별·전체 MAE를 단순 기준과 비교한다. 어느 구간이 비면 불완전 검증을 성공으로 처리하지 않고 `DATA_SHORT`로 남긴다. 구간의 63개 날짜와 실제 유효 검증 날짜/제외 수를 함께 보여 준다. 적은 유효 검증 수를 숨기지 않고, 이번 판정에서 새 최소 검증 수를 추가하지 않는다. 모델과 기준은 같은 유효 날짜·목표로 비교한다. 전체는 유효 검증 표본별 절대오차의 평균이다. 단위는 %p다.

그 뒤 t까지 D20이 성숙한 표본으로 최종 모델을 fit하고 t의 feature로 추정한다. 아직 +20 결과가 없는 최근 날짜는 최종 학습 정답에 넣지 않지만, t의 예측 입력은 사용할 수 있다. 같은 snapshot·recipe의 결과는 동일해야 한다.

MAE의 개선·차이 없음·악화를 보고한다. 개선이 있어도 **‘연구 추정·투자 유효성 미확정’**으로 표시한다. 열위면 ‘단순 기준보다 검증 오차 큼’을 추정값 옆에 표시하고 개선 결과처럼 요약하지 않는다. 겹치는 20일 창을 독립 표본으로 간주한 신뢰구간·성공률·확률 배지는 만들지 않는다. 기존 연구에서 이미 살펴본 역사 자료이므로 새로운 확증 시험이라고 부르지 않는다.

### 5-3. 사후평가와 현재 검토 구분

06의 과거 검증은 가격 기반 D20 추정의 오차 평가다. 알림의 도움이 됐는지, 특정 거래가 적절했는지 자동 판정하는 모델은 아니다. 해당 질문은 사용자 평가와 원시 결과를 함께 보며, 별도 후속 목표·기준을 정할 때 다룬다. 이번 D20을 알림 성공 라벨로 재사용하지 않는다.

현재 새로 학습한 모델을 과거 알림일에 적용해 ‘당시에도 이렇게 예측했다’고 기록하지 않는다. 이후 가격·나중에 입력한 피드백·실현손익은 당시 입력 feature가 아니다. 사용자 평가 없는 알림을 향후 사후평가에서 제외하지 않는 계약은 그대로 유지한다.

## 6. 구현과 결과 보존

기존 History 계산과 화면을 재사용하고, 가격 표본·ML 계산은 별도 작은 모듈로 둔다. 새 PC DB·원장 테이블·모델 등록 서비스·작업 큐를 만들지 않는다. 기존 설치·실행 방식으로 선택 ETF 한 개를 계산하는 시간을 PLAN에서 측정하며, 장시간 작업 구조를 미리 설계하지 않는다.

로컬 API는 기존 holdings-history router 아래 조회와 ML 실행 경계로 두고, 정확한 URL·응답 모델·파일 분리는 PLAN에 적는다. ML 실행은 POST이며 보유 저장 API와 분리한다. 공개 API가 아니다. 파라미터는 position/cycle 선택값으로 받고 서버가 검증한 ticker를 사용한다. 임의 파일 경로·모델 경로를 입력받지 않는다.

개인 문서는 한 번 읽은 유효 revision, 원장 사본은 읽기 트랜잭션, 가격은 확정한 읽기 snapshot을 사용한다. 중간 동기화·보유 정정이 있으면 결과는 읽은 기준을 표시한다. 여러 저장소의 분산 트랜잭션을 만들지 않는다.

명시적 ML 실행 결과는 PC 연구 경로 `state/ml/research/poc5_06/<생성시각>_<id>/`에 새 산출물로 저장한다. 기존 연구 산출물 관례를 따른다. 필요한 파일은 `review.json`과 `input_snapshot.json` 정도로 제한한다.

- review: 선택값·생성 시각·자료 기준일·읽은 revision·사실 요약·recipe·모델 상태·검증 기간/오차·추정값·제외 사유·실행 시간·라이브러리 버전·연구 축/부분적 가격 경계 검사 안내.
- input snapshot: 실제 사용한 가격 날짜·값·출처, 계산에 사용한 선택 기간의 사실, 표시한 알림/피드백 식별 근거. 개인값은 PC 연구 파일에만 둔다.
- 동일 입력과 recipe를 식별할 canonical hash를 남긴다. live DB 파일 hash만으로 가격 입력이 고정됐다고 주장하지 않는다.
- 모델 pickle·영구 가중치 배포는 하지 않는다. 다시 실행하면 같은 입력으로 재학습할 수 있다.
- 저장 실패나 모델 오류를 정상 완료로 표시하거나 직전 결과로 바꾸지 않는다. History·가격 근거는 별도로 열 수 있다.

### 10-1. Q-A — 기반 문서 충돌: 한정 예외를 명시하고 진행

추천의 문구 통일·운영 미승인·날짜 붙은 문서 기록을 수용한다. 다만 **미래 D20을 추정하는 모델을 표현 변경만으로 기존 금지 밖이라고 해석하는 부분은 수용하지 않는다.** 미래값 추정이라는 사실을 인정하고 적용 범위를 명시적으로 변경한다.

**기반 문서에 덧붙일 확정문:**

### 10-3. Q-C — 출처 라벨 대신 감지된 불연속 기준 수용

두 라벨의 같은 reader 사용·주 전환 연속성은 보고를 수용한다. **라벨만 바뀐 연속 창은 사용**하고, FDR change 불일치(절대 비율 > 1e-6), FDR→NAVER_FDR 재전환, 연구 축 공백을 경계로 처리한다. 1e-6은 0.0001%p이며 가격 비율 단위와 퍼센트 단위를 섞지 않는다. 경계/연속성 미확인 지점을 넘는 창만 제외하고 사유를 센다.

미허용 출처나 FDR change 누락은 해당 창을 제외한다. 유효한 과거 표본이 있어도 최신 t의 60일 feature 창이 이 조건을 만족하지 못하면 **현재 추정은 PRICE_BASIS_UNCONFIRMED**다. 과거 일부 창의 결함만으로 정상적인 History·원장 조회까지 막지 않는다.

NAVER_FDR 내부의 change 없는 구간은 이번 **제한된 저장 계열 연구**에 사용하지만 검사하지 못한 계단이 있을 수 있음을 화면·review에 명시한다. 따라서 ‘가격 기준 일관성 확인 완료’나 ‘711종목 ML 유효’라는 결론은 내리지 않는다. 711은 제안한 규칙의 자료 통과 건수일 뿐이다. 총수익 미확정·부분적 경계 감지의 한계가 남는 것을 수용한다.

기존 DEF-ETF-DAILY-PRICE-BASIS-CONSISTENCY는 미해결로 남긴다. 시세표 수정·과거 가격 재적재·공식 계열로 교체·장기 수집기 정비는 이번 범위에 넣지 않는다. 기존 missing_confirm 표식을 무결성 통과 근거로 사용하지 않는 계획을 수용한다.

069500의 **−1.75%·MAE 6.11/6.65는 경계 없는 시제품** 수치다. 최종 규칙의 기준값으로 고정하거나 검증 통과 수치로 복사하지 않는다. 확정 경계·축·snapshot으로 실제 계산한 표본/오차를 RESULT에 기록한다.

### 10-4. Q-D — 세 연결 종류를 구분하여 수용

`subject_kind=ticker`의 subject_id 정확 일치, sector의 기록된 `values_json.ticker` 정확 일치, index_group의 기록된 `values_json.tickers` 구성원 일치만 허용한다.

주체 항목은 기본 표시한다. 사업군 대표와 지수 묶음 구성은 ‘연관 근거’로 따로 표시하고 직접 종목 신호처럼 제목을 바꾸지 않는다. 현재 설정·마스터·이름·시장 태그로 과거 대표/구성을 복원하지 않는다.

### 10-5. PLAN §2-3·구현 계획 기본값

- `AXIS_UNCERTAIN` 문구의 ‘KOSPI 최신일이 t보다 이름’은 **‘t보다 이른 경우’**로 정정한다. 자료 부족/비ETF/가격 불명/읽기 오류/저장 실패 상태 구분을 유지한다.

첫 정상 저장에서 V1 줄 ID를 그대로 확정하는 시험 보고를 수용한다. §10-5의 ‘ID가 달라지면 다시 열기’는 실제 선택 ID가 무효가 됐을 때의 처리이며 첫 저장 때 반드시 바뀐다는 의미가 아니다. 이 정정은 문서의 의미 설명이다. 코드 수정·새 시험·검증자 재제출을 요구하지 않는다.

### 11-2. 추가 변경과 한계 수용

결과서 §4 다섯 항목을 수용한다. 05의 읽은 문서 adapter와 제공된 DB 연결 재사용은 같은 snapshot 계약을 지키는 변경이다. 기존 호출 동작을 유지한 회귀 보고를 근거로 한다. 03 outcome 표시 함수의 입력 타입 조정·05 표시부 export·ML 위치 안내 문구·새 창 CSS는 이번 창을 연결하는 범위다. ‘기존 코드 수정 0’이라는 초안 표현을 결과서의 실제 파일 목록으로 대체하며 외부 범위 확대라고 기록하지 않는다.

부분적인 가격 경계 검사·보정 연구 축·1일치 원장·현재 결과 행 없음·시세 DB 오류 시 창 전체 실패·실화면 미확인은 현재 범위의 한계로 수용한다. ‘원장 결과가 아직 없음’과 ‘원장 손상’은 이번 r1 정정대로 구분해야 한다. ML 입력·표본은 평가 유무와 무관하고 사용자 피드백/기존 outcome은 불변이다.

PC 최신 종가 2026-10-08, 069500 모델 MAE 4.37%p/기준 4.36%p와 추정 −3.48%는 10-10 갱신 뒤 개발자 실측 보고다. 이 사례는 단순 기준보다 오차가 큰 **WORSE**로 표시하는 정상 연구 결과다. 29종목 중 OK 10·DATA_SHORT 16·NOT_ETF 3을 전체 모델 성능이나 투자 유효성 판정으로 해석하지 않는다. 이번 PASS는 계산·조회·표시 기능의 배포 판정이며 운영·추천 모델 채택은 미승인으로 유지한다.

### 11-3. 최종 실화면 확인 — 한 번에 완료

기존 목업 확인은 유지한다. 결과서 §7-1 다섯 변경은 재목업 게이트를 만들지 않고 예정된 최종 실화면 확인에 포함한다.

1. ‘내 평가(알림 전체)’ 열 위치·메모·계약 버전.
2. 관측만 된 알림의 건수와 펼치기.
3. 늦은 기준일일 때 추정값 옆의 ‘이 날짜 기준 검토’ 태그.
4. 읽은 revision·문서 내용 hash 표시.
5. 알림(event) 수와 item이 여러 개인 경우 ‘항목 N개’ 표시.

현재 보유 ETF 하나의 History → 재진입 검토 → 수동 ML 실행 → History 복귀를 확인한다. 정상 실행이면 PC 연구 폴더의 review.json·input_snapshot.json을 확인하고 보유·OCI 적용 hash·원장에 변경이 없음을 확인한다. 069500처럼 실제 결과와 열위 경고가 있는 ETF를 사용할 수 있다. 화면 배치·가독성·버튼 동작은 사용자가, 산출물·읽기 기준·부수효과는 개발자가 확인한다.

실자료에 없는 사용자 메모·다중 item·지연 상태를 만들기 위해 실제 평가·거래·시세를 바꾸지 않는다. 이런 조건은 이미 수행한 fixture/화면 시험을 근거로 하고, 실제 보이는 부분을 사용자와 확인한다. 새 거래·원장 동기화·+20 성숙·최신 시세 갱신을 완료 조건으로 추가하지 않는다. 02/03의 10-12 확인과 공식 R0는 기존 별도 일정이다.

### 11-4. 배포와 종료 지시
