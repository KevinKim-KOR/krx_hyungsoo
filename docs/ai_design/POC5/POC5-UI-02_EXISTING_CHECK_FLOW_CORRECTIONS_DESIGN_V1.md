## 1. 이번 결정

개발자의 읽기 전용 대조 결과를 범위 결정의 근거로 수용한다. 설계자가 소스나 OCI를 직접 실행한 확인은 아니다. §5 대조는 완료했으므로 같은 조사를 다시 요청하지 않는다.

첫 변경의 목적은 **이미 제공하는 보유 점검 기능을 정확하게 안내하고, 빠진 정렬과 잘못된 이동을 연결하는 것**이다. 수동 갱신의 횟수·사용 시간을 제한하는 개발은 포함하지 않는다. PC FDR 보호는 조건부 후속으로 둔다. 공식 R0가 예정된 10-23까지 기다리는 조건은 없다.

| 대조표 §2 요청 | 설계자 결정 |
|---|---|
| 1. 첫 변경 범위 | POC5-UI-02: 낡은 미완성 기능 목록 제거 + 「확인 근거」 정렬 + 원인 확인 이동 정정 + §5의 관련 기록 정리 |

## 2. 낡은 기능 안내 제거

「오늘의 투자 점검」의 미완성 기능 목록에서 아래 다섯 항목을 모두 제거한다. 완료 기능과 조건부 보류·폐기 기능을 매일 보는 화면의 개발 예정 목록으로 섞어 두지 않는다.

| 항목 | 기록에 남길 상태 | 화면 처리 |
|---|---|---|
| P-06 내가 가진 ETF의 위험 신호 | 부분 구현. 종합 위험 구간 분류는 보류 | 이미 있는 점검 기능을 “개발 중”으로 안내하는 항목 제거 |
| P-11 시장 흐름 전환까지의 거리 | 현재 기준선 대비 위치는 구현. 미래 전환 예측과 구분 | 예정 항목 제거. 현재 MA20/MA60 값과 한계 안내 유지 |
| P-10 거래량 흐름 | 조건부 보류. ETF·KODEX200 거래량 저장, KOSPI 지수 거래량 미저장 | 주 화면 예정 항목 제거. 저장 범위는 기록에 정확히 정정 |
| P-12 공격·방어 비중 | 제외·폐기 | 두 안내 목록에서 제거 |
| P-13 SuperTrend | 제외·폐기 | 두 안내 목록에서 제거 |

대상은 조사에서 확인한 InDevelopmentSection과 KospiDetailSection의 미도입 안내다. 목록이 비면 제목·빈 카드도 제거한다. 실제 시장 관찰값이 함께 있는 영역에서는 안내 부분만 제거하고 관찰값은 유지한다. “코스피 상세 (개발 중)” 접근성 이름도 실제 내용에 맞게 고친다.

이 제거 때문에 사용처가 없어지는 선언만 함께 정리한다. 다른 화면의 정상적인 “이번 ML 범위 밖”, “적용 예정 사업군” 등 자료 상태 문구까지 일괄 삭제하지 않는다.

PC 최대 3건 선정 함수·숫자·대상은 바꾸지 않는다. 필요한 설명은 “최근 5거래일 변화가 낮은 보유 ETF부터 최대 3개”로 한정한다. 종합 위험 등급이나 매도 권고로 표현하지 않는다. OCI 보유 브리핑과 같다는 오래된 주석은 삭제하거나 각 기준을 명시한다.

## 3. 「확인 근거」 정렬과 이동

### 3-1. 사용자 선택 정렬

POC3-05에서 요구했으나 연결되지 않은 다섯 선택을 제공한다. 현재 화면이 받은 수치로 순서만 바꾼다.

| 선택 | 순서 |
|---|---|
| 평가 비중 | 큰 값부터 |
| 평가손익 | 작은 값부터 |
| 5일 변화 | 작은 값부터 · 기본 선택 |
| 20일 변화 | 작은 값부터 |
| KODEX200 대비 | 작은 값부터 |

- 화면에 표시하는 기존 지표의 원래 숫자로 정렬한다. 반올림된 표시 문자열은 쓰지 않는다.
- 지표별 기존 응답 키·단위를 PLAN에 한 번 명시한다. 평가손익을 수익률 등 다른 지표로 임의 대체하지 않는다.
- 값이 없는 행은 어느 선택에서나 맨 뒤에 둔다. 같은 값과 결측끼리는 기존 응답 순서를 유지한다. 행을 제외하지 않는다.
- 정렬 때문에 다시 조회하거나 저장하지 않는다. 선택은 해당 화면의 메모리 상태로 충분하다.
- 기존 helper가 이 규칙과 맞으면 재사용하고, 맞지 않는 부분만 보완한다. 종목 묶음·계좌 집계·수치 산식은 바꾸지 않는다.
- 제목·부제는 선택한 정렬과 일치시킨다. 모든 정렬을 위험 순위로 부르지 않는다. 기본 부제는 “보유 ETF의 수치와 확인 근거”면 충분하다.
- 기존 선택 컨트롤 양식을 사용한다. UI-01의 큰/중간 버튼 규칙과 선택 묶음 예외를 유지한다.

### 3-2. 원인 확인 이동

기존 “원인 확인” 동작을 onNavigate("data_status")에 연결한다. 사용자 문구는 “데이터 상태에서 원인 확인 →”로 맞춘다. 새 메뉴·경로·조회 기능은 만들지 않는다.

차트·NAV·구성종목·20일 변화 등 이미 있는 확인 근거는 유지한다. 매일 보는 화면에 원장을 자동 동기화하거나 PUSH 사유를 복제하는 작업은 이번 범위에 넣지 않는다.

## 4. 구현 경계

PC 화면과 관련 테스트·기록을 고친다. 새 API·DB·수집·의존성·cron·OCI 변경은 필요하지 않다. 실제 보유·거래 이력·seed·PARAM·알림 원장·시세를 수정하는 기능도 추가하지 않는다.

다섯 정렬 값 중 대응하는 기존 값이 없다는 사실이 드러나면 그 항목의 키·단위 차이만 PLAN에서 보고한다. 이를 이유로 새 시세나 산식을 끼워 넣지 않는다. 나머지 조사 결과를 다시 전수 점검할 필요는 없다.

## 5. 함께 정리할 문서

대조표에서 이미 근거가 확인된 행만 정리한다. 옛 설계·결과서의 판정 원문은 바꾸지 않고, 현행 관리 문서에 정정 근거와 날짜를 남긴다.

통합지도의 P-19/P-20·B-004/007/078/082/083도 기존 종료 근거로 설명할 수 있는 부분만 정정한다. 도구 구현을 최적 기간·MDD/Sharpe·생존 편향 해결·운영 ML 승인으로 바꾸지 않는다. 근거가 모호한 상태는 이번에 완료로 처리하지 않는다.

61건은 정리 전 등록 항목 수다. 정리 후에는 기존 세는 방식으로 한 번 계산해 기록한다. 종료 항목을 보존할 수 있으며, 등록 건수를 남은 개발 건수로 안내하지 않는다. STATE에만 있는 연구·운영 관찰 항목을 이번에 전부 BACKLOG로 옮기지는 않는다.

## 6. 조건부 후속과 seed 검토

1. **PC FDR 수동 갱신 보호**: 조건부 후속. 다음 필수 개발로 지정하지 않는다. OCI 보호와 PC 미보호라는 조사 사실은 유지하되, 실제 멈춤 관측 이력은 없다.
   - timeout은 외부 가격 조회의 응답 대기시간을 뜻한다. 사용자의 갱신 횟수·버튼 사용 시간·하루 한도를 뜻하지 않는다.
   - 정상 갱신은 362.6초가 걸렸다. 전체 작업의 강제 종료 상한을 이번 결정으로 추가하지 않는다.
   - 실제 멈춤·반복 지연이 생기거나 해당 조회 경로를 수정할 필요가 있을 때 최소 보완을 검토한다. 그때 목표는 기다림에서 벗어나고 다시 실행할 수 있게 하는 것이다.
   - 별도 상시 감시·자동 재기동·작업 관리 체계를 만들지 않는다. UI-02를 마친 뒤 이 항목의 별도 PLAN을 자동으로 시작하지 않는다.
2. **seed 재승인 검토**: 88일 경과와 PC/OCI 구성 차이를 근거로 지금 검토 가능하다. stale 표시 경로가 없다는 이유로 실제 검토를 무기한 미루지 않는다.
   - 기존 승인본 20개와 PC 3개의 종목·이름·보유 여부·출처·기준일 차이표 한 번이면 충분하다. 새 외부 수집이나 점수 모델은 필요 없다.
   - OCI 승인본에 PC를 맞추는 안을 기본 제안으로 제시한다. 사용자가 현재 관심 종목과 함께 확인한 뒤 적용 여부를 결정한다.
   - 사용자 결정 전에는 두 seed 파일을 덮어쓰지 않는다. 나이가 오래됐다는 이유만으로 후보를 자동 탈락시키지 않는다. 편집 UI·품질 점수·자동 재승인은 이번 결정으로 승인하지 않는다.

seed 차이 확인은 10-23 R0 결과를 기다리는 일이 아니다. FDR 보호는 필요가 확인될 때 선택한다. 백로그 등록을 개발 의무로 취급하지 않는다. R0와 알림·ML 표본 성숙은 별도 일정대로 진행한다.

## 7. 검증과 종료

필요한 검증은 정렬 선택·숫자 순서·결측/동점 보존, 원인 확인 이동, 낡은 목록 제거와 기존 시장 관찰값 유지다. 과거 AC-13의 뜻과 반대로 문구를 고정한 시험은 원 설계의 “폐기 항목 제거”에 맞춘다.

변경한 화면의 테스트와 기존 frontend 정적 검사를 수행한다. backend 코드를 바꾸지 않으면 이 작업만을 이유로 backend 전체 회귀나 라이브 파일 전수 해시를 새로 요구하지 않는다. 저장소의 필수 절차는 따른다.

완료 순서는 PLAN 판정 → 구현·검증 → RESULT 판정 → 승인된 커밋·push → PC 실화면 확인 → 종료 기록이다. 실화면은 다섯 정렬과 “데이터 상태” 이동을 확인하면 된다. 새로운 폼·창이 없으므로 별도 목업 승인 단계를 추가하지 않는다.

RESULT에서 이 범위가 통과한 뒤 실화면까지 통과하면 재판정 없이 종료 기록을 작성할 수 있다. OCI pull·다음 거래일 확인은 필요 없다.

- **거래량**: 붙일 수 있는 후속 후보다. 이미 저장된 ETF·대표 ETF 거래량을 기존 확인 근거에 보완하는 방향부터 검토할 수 있다. 대표 ETF 자료를 KOSPI 전체 거래량으로 표기하지 않으며, 이번 문서 정정과 함께 새 판정 산식을 몰래 확정하지 않는다.
- **종합 위험 구간**: 현재의 개별 하락 알림보다 넓은 요구다. 사용할 근거와 각 상태의 의미를 정해야 한다. 기존 하락 사유를 화면에서 명확히 보여주는 일과 새 종합 등급을 계산하는 일을 나눠서 설계할 수 있다. 모든 외부 자료를 모을 때까지 기다려야 하는 일괄 조건은 이번에 추가하지 않는다.
- **공격·방어 비중**: 현재 포트폴리오의 분류별 구성 표시와 권장 비중 산출은 서로 다른 기능이다. 전자는 사용자 판단을 돕는 화면으로 설계 가능하다. 후자는 비중 결정 기준이 필요하다. 두 가지를 모두 자동매매로 묶어 제외하면 안 된다.
- **SuperTrend**: 새로운 보조 지표 후보로 재검토는 가능하다. 입력 자료·산식·표시 의미와 기존 지표와의 차이를 정하는 별도 범위가 필요하다. 단지 예전에 보류·제외됐다는 이유로 사용자 목적까지 폐기하지 않는다.

위 항목은 보완 가능성과 남은 요구를 설명한 것이다. 네 기능을 한꺼번에 구현하거나 종합 신호·운영 ML을 승인하는 지시가 아니다. 기술적으로 추가할 수 없다는 근거는 이번 자료에 없다. 추가 범위와 우선순위를 정하지 않은 상태를 “필요 없다”로 바꾸지 않는다.

### 2. 중복 정렬 제거

- 「확인 근거」에서 **KODEX200 대비 정렬 선택만 제거**한다. 행·상세의 “KODEX200 대비 20일” 값과 기준·단위 표시는 유지한다.
- 최종 선택은 **평가 비중 / 손익률 / 5일 변화 / 20일 변화** 네 가지다. 기본값은 5일, 방향·결측·동점·행 보존·선택 상세 유지·추가 조회 없음은 기존 계약 그대로다.

- 다른 기간의 초과수익 정렬로 바꾸거나 다섯 개를 유지하기 위한 새 지표를 넣지 않는다.
- 이 선택에만 쓰이던 신규 정렬 키·선언·시험은 함께 정리할 수 있다. 공유 가격 계산이나 다른 화면의 정렬·표시까지 바꾸지 않는다.

### 3. 선택 종목의 사유를 상세에서 바로 표시

「확인 근거」의 현재 선택 종목 상세에 **“자료 확인 안내”** 영역을 둔다. 이미 받은 두 응답과 화면의 기존 판정 정보만 사용한다.

| 기존 정보 | 표시 |
|---|---|
| market-evidence의 evidence_notes | 해당 종목의 기존 사유 문구. 제공되지 않은 날짜·누락 건수·상세 원인을 추측해 덧붙이지 않음 |
| enriched의 price_missing | true이면 “보유 시세를 확인할 수 없습니다.” |
| enriched의 calc_missing | true이면 “보유 평가 계산값을 확인할 수 없습니다.” |
| 기존 화면이 확인한 계좌 간 값 불일치 | 해당 불일치의 기존 판정 사유. 어떤 값·계좌인지 이미 있는 정보만 사용 |

- 선택 종목에 속한 사유만 보여준다. 여러 계좌의 기존 사유가 있다면 필요한 내용을 보존하고 동일 문구는 한 번만 표시한다.
- 상세 조립에 필요한 frontend 내부 필드는 보완할 수 있다. 종목 묶음·수치 산식·행 상태·선정 규칙은 변경하지 않는다.
- 안내를 위해 다시 조회하거나 저장하지 않는다. 새로운 정상/위험 등급이나 자동 조치를 만들지 않는다.
- “자료 확인 필요”인데 구체 사유가 없으면 “자료 확인이 필요하지만 상세 사유 정보가 제공되지 않습니다.”로 표시한다. 사유가 없다는 이유로 정상이라고 단정하지 않는다.
- 기존 NAV 안내는 유지하고 새 사유와 함께 읽을 수 있게 한다. 표시할 안내가 전혀 없는 정상 행에 빈 영역을 만들 필요는 없다.
- 정렬을 바꿔도 선택한 종목과 그 종목의 사유가 함께 유지된다.

### 4. 데이터 상태 이동의 용도 정정

기존 버튼 문구를 **“전체 ETF NAV·괴리율 보기 →”**로 바꾼다. 이동 대상은 data_status 그대로다.

이번에는 메뉴 이동에 종목을 넘기거나 검색창을 자동으로 채우는 연결을 추가하지 않는다. 전체 ETF 표가 가격 이력 부족·보유 시세 미확인의 원인까지 설명한다고 안내하지 않는다.
