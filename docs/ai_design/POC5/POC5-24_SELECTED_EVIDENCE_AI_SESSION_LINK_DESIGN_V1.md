# POC5-24 선택 근거의 AI 투자세션 연결 — 설계 V1

작성일: 2026-10-18 · 작성자: 설계자 · 수신: 개발자 / 사용자

**목표: 선택 종목의 미리보기에서 기존 AI 세션 작성 화면으로 이동해, 그때의 근거를 질문에 담고 AI 답변·사용자 판단을 같은 기록에서 다시 본다.**

## 1. 기준과 범위

- POC5-23 종료 보고(`089310e3` · 2026-10-18 · `IMPLEMENTED_VERIFIED_CLOSED`)를 수용한다. 설계자가 원격 저장소를 직접 확인한 기록은 아니다.
- POC5-23 PLAN·RESULT에서 현재 미리보기의 소비처는 상세 카드 하나이고, 기존 AI 세션 전달 경로는 이를 소비하지 않는 것으로 확인됐다. 기존 세션 생성·답변·판단·목록·상세 기능을 재사용해 이 연결만 보완한다.
- 기존 미리보기 생성·복사는 유지한다. 새 분석·수집·숫자 표시 함수·위험 점수·ML·별도 판단 원장은 만들지 않는다.
- STATE의 다음 줄은 이번 PLAN을 기록하는 자연스러운 변경에서 '23 종료 · 다음 24 PLAN/목업'으로 맞춘다. 다음 단계 표시는 자기 커밋 번호를 몰라도 맞출 수 있다. 이를 위한 별도 문서 커밋은 필요 없다.

## 2. 사용자 흐름

1. 기존 「보유와 비교」에서 보유 또는 후보 한 종목을 선택하고 미리보기를 생성한다.
2. 같은 미리보기 버튼 줄의 **[AI 세션에서 검토]**를 누르면 기존 AI 세션 작성 화면으로 이동한다. 선택 종목과 생성된 근거·질문이 미리 채워져 있어 다시 종목을 고르거나 글을 옮겨 적지 않는다.
3. 사용자는 기존 방식으로 질문을 복사해 외부 AI와 대화하고, 답변·자신의 판단을 입력할 수 있다. 앱이 외부 AI를 호출하거나 메시지를 보내지는 않는다.
4. 기존 저장 동작으로 저장하면 기존 세션 목록·상세에서 그 기록을 다시 연다. 답변·판단 입력은 기존 선택 정책을 따르며 새 필수 평가 항목이나 실제 매매 조건을 추가하지 않는다.

버튼은 미리보기가 정상 생성된 경우에 사용한다. 종목·목록 조건 변경으로 이전 미리보기가 비워졌으면 새로 생성한 뒤 전달한다. 기존 작성 중인 질문·답변이 있으면 조용히 덮어쓰지 않고 기존 초안 보호 방식을 사용한다.

## 3. 전달과 저장 계약

- **입력은 사용자가 보고 있는 POC5-23 응답이다.** 대상 종류·티커·이름, `generated_at`, 실제 근거 기준일, `preview_text`를 그 시점 값으로 전달한다. 전달 버튼에서 미리보기를 재생성하거나 시장·보유 자료를 다시 계산하지 않는다.
- 원문을 기존 세션 질문 본문에 포함하는 방식을 기본으로 한다. 기존 질문·스냅샷 JSON 안의 적절한 자리가 있으면 재사용할 수 있다. 선택 근거 보관을 위해 새 테이블·DB 컬럼·별도 파일 저장소를 만들지 않는다.
- 제목은 선택 종목을 알아볼 수 있게 한다. 동일 종목의 다른 시점 검토는 기존 세션 방식으로 구분한다. 종목별 새 이력 시스템은 만들지 않는다.
- 질문·AI 답변 편집과 저장은 기존 사용자 동작을 따른다. 저장된 질문·근거를 열 때 최신 시세로 자동 교체하지 않는다. 처음 넘긴 근거와 이후 사용자가 편집한 질문을 같은 뜻으로 설명하지 않는다.
- 기존 작성·저장 경로가 시장 후보 전체·최신 ML 근거를 자동 보충한다면, 이번 선택 근거를 다른 자료로 바꿔 넣지 않도록 해당 전달 모드에서만 보완한다. 선택 한 종목을 다른 상위 후보 전체의 근거로 저장하지 않는다. 기존 시장 후보 전체 전달 기능은 보존한다.
- 이동만으로 세션을 자동 저장하지 않는다. 실제 저장은 기존 저장 버튼에서 수행한다. 새 감사 로그·해시·버전 원장·중복 방지 프레임워크는 요구하지 않는다.
- 기존 보유 비중·손익의 미리보기 정책과 PC 세션 저장 정책을 유지한다. 수량·평단·계좌·거래 금액·메모를 새로 수집하거나 원장·OCI로 보내지 않는다.

## 4. 짧은 PLAN과 목업

개발자는 아래 세 사실만 현재 소스로 확인해 짧은 PLAN에 적는다.

1. 기존 AI 세션 전달 초안·작성 화면·생성 API·질문/답변/판단 저장 구조와 자동 보충 동작.
2. 선택 미리보기 원문을 전달·저장·재조회할 최소 연결안, 기존 미저장 초안 처리, 기존 전체 후보 전달 보존 방법.
3. 변경 파일·시험 범위와 추가 필드가 필요하면 기존 JSON/선택 필드 안에 둘 위치.

전체 화면 목업은 개발자가 1440/1000px에서 작성한다. 미리보기 버튼 줄 → 선택 종목으로 채워진 기존 세션 작성 화면 → 저장 후 상세를 보여 준다. 새 메뉴·장문의 고정 안내는 추가하지 않고, 버튼 크기는 기존 큰/중간 규격을 따른다.

이미 같은 연결이 구현돼 있으면 재구현하지 말고 실제 동선과 남은 차이만 PLAN에 보고한다. 다른 백로그 전수 조사·리팩터를 선행하지 않는다. 사용자 목업 확인과 PLAN 판정 후 구현한다.

## 5. 수용 기준과 종료

- 보유·후보에서 선택한 한 종목의 원문·대상·생성 시각·가격 기준일이 작성 화면으로 정확히 전달된다. POC5-23 숫자 문자열을 다시 포맷하지 않는다.
- 기존 저장 API로 저장한 뒤 실제 조회 경로로 다시 읽었을 때 확인한 질문·근거·답변·사용자 판단을 볼 수 있다. 시험은 임시 DB를 사용하며 실제 매매나 라이브 시험 기록 생성을 요구하지 않는다.
- 전달 중 선택이 바뀌거나 기존 작성 중인 초안이 있어도 다른 종목 자료나 기존 입력이 조용히 덮이지 않는다. 이전 세션과 기존 전체 후보 전달도 정상 동작한다.
- 새 외부 호출·계산·자동 저장·보유 변경·운영 원장 변경·OCI/PUSH 변경이 없다. 선택 평가가 없는 알림을 ML 자료에서 제외하는 규칙도 만들지 않는다.
- 필요한 연결 시험·기존 필수 검사 → 사용자 실화면 → 검증자 → RESULT 판정 후 승인 범위에 따라 커밋·push해 종료한다. 판단의 정답·실제 거래·ML 성과를 이 연결 기능의 완료 조건으로 삼지 않는다.

미사용 POC5-16 파일 삭제는 사용자 결정 대기로 유지하며 본 단계와 분리한다. OCI pull·거래일 대기·별도 인계 문서는 종료 조건이 아니다.
