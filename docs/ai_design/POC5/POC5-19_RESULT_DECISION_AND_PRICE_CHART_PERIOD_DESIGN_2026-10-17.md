# POC5-19 RESULT 판정과 가격 차트 기간 선택 설계

작성일: 2026-10-17 · 작성자: 설계자 · 독자: 개발자

## 1. POC5-19 RESULT 판정

**PASS. 현재 검증된 구현은 종료 기록 정리와 사용자 승인 범위의 커밋·push로 마무리한다. 아래 추가 기간 선택을 이번 PASS의 조건으로 붙이지 않는다.**

- 첨부 RESULT §0~§12를 기존 설계·두 개정 판정과 대조했다. 설계자의 문서 기반 판정이며 저장소·서버·화면을 직접 재검증한 것은 아니다.
- 사용자 개정 실화면 확인과 검증자 r2 VERIFIED를 수용한다. 저장 거래량 흐름, 세 근거 기본 표시, 상단 상세창, 축·눈금·단위·선택값, 날짜로 대응한 가격/거래량 비교와 기존 자료 재사용이 승인 범위를 충족했다.
- r1의 작은 비영 값을 0으로 표시한 결함은 정정됐다. 검증자의 같은 화면 재현 통과와 24조건 표시 대조를 수용한다. 일반 값 최대 소수 6자리·1 미만 비영 값 유효 숫자 6개라는 표시 정밀도도 수용한다. 모든 소수의 무손실 출력으로 설명하지 않는다.
- 전체 backend 3,678건과 변이는 개발자 근거다. 검증자 r1의 관련 backend 156건·API 재현 1건·정적 검사, r2의 frontend 654건·독립 화면 재현 1건·표시 대조가 각각 직접 근거다. 검사 범위를 합치거나 확대해 기록하지 않는다.
- RESULT §4의 공유 창 선택 prop·초점 복귀·Esc·날짜/단위 문구와 숫자 표시 정정을 수용한다. 미사용 POC5-16 파일은 기존대로 별도 승인 전까지 보존한다. 삭제는 종료 조건이 아니다.
- 기존 RESULT에 본 판정과 종료 기록을 붙이고 `IMPLEMENTED_VERIFIED_CLOSED`로 정리한다. STATE·PROGRAM_TRUTH·BACKLOG·통합지도의 해당 상태도 맞춘다. P-10 부분 완료와 미구현 해석/종합 위험 분류의 구분을 유지한다.
- 이번 단계 사용자 커밋·push 승인이 있으면 구현·시험·종료 기록을 함께 반영하고 커밋 ID와 저장소 상태를 보고한다. 이미 받은 동일 범위 승인은 재요청하지 않는다. 본 설계 판정 자체를 사용자 승인으로 해석하지 않는다.
- 문서 정리만으로 재검증·재판정·추가 실화면·OCI pull·영업일 대기는 필요 없다. 별도 인계 문서도 필요 없다.

## 2. 실화면 의견 두 건 판정

| 의견 | 판정 |
|---|---|
| 종목 가격의 전체 저장 기간이 너무 길어 기간 선택 필요 | **채택.** 아래 작은 프론트 작업 `POC5-UI-04`로 바로 이어간다. 기존 시계열의 표시 범위 선택이다. |
| 선택 종목 바로 아래 상세를 표시할 수 있는가 | **가능하다.** 다만 이번 전달에는 '확인만·수정 요청 아님'으로 명시됐다. 가능 여부에 답하고 현 배치는 유지한다. 자동 스크롤도 이번에 임의로 추가하지 않는다. 실제 배치 변경 요구가 확정되면 그때 반영한다. |

이번 두 의견은 현재 설계 위반에 따른 반려 사유가 아니다. 완료된 구현을 닫고, 명확한 추가 요청 한 가지만 이어간다.

## 3. POC5-UI-04 — 종목 가격 차트 기간 선택

목적: 수년치 전체 그림 대신 최근 흐름을 기본으로 보고, 필요할 때 긴 기간으로 넓힐 수 있게 한다.

- **대상:** 공유 `workbench/PriceChart.tsx`를 쓰는 「확인 근거」·「ETF 비교하기」의 기본 종목 가격 차트 두 곳. 기본은 **3개월**, 선택지는 **3개월 / 6개월 / 1년 / 전체**다.
- KOSPI의 기존 최근 120개 저장일과 세부 흐름 창의 최근 최대 20개 날짜 대응은 유지한다. 이번에 다른 차트까지 기간 선택 범위를 늘리지 않는다.
- 기간 선택은 차트 위쪽에 기존 UI 스타일의 작은 선택 묶음으로 둔다. 1000px에서도 값·제목과 겹치거나 가로 스크롤을 만들지 않게 줄을 나눈다. 선택된 기간을 분명히 표시한다.
- 기준 D는 해당 차트가 이미 받은 **종목 가격 시계열의 마지막 저장 날짜**다. 오늘 날짜나 전체 시장의 최신일로 바꾸지 않는다.
- 3/6개월은 D에서 각각 달력 3/6개월을 뺀 날부터 D까지, 1년은 달력 1년 전부터 D까지다. 월말에 해당 날짜가 없으면 그 달 말일로 맞춘다. 경계 날짜는 포함한다. 날짜를 시각대 변환 때문에 전날/다음 날로 바꾸지 않는다.
- 전체는 받은 전체 시계열이다. 선택 기간보다 상장/저장 기간이 짧으면 있는 만큼만 보인다. 차트 아래 실제 시작~끝·N개 저장일을 표시하고 임의 과거 값을 채우지 않는다.
- 선택 날짜는 처음과 기간 변경 때 표시 창의 가장 최근 날짜로 둔다. 단위·축 눈금·결측·키보드 등 기존 차트 읽기 계약은 유지한다.
- 기간 선택은 프론트의 표시 상태다. 새 종목을 선택하면 기본 3개월로 시작한다. 영구 저장·URL 계약·전역 설정은 추가하지 않는다.
- **원본 조회 결과와 공유 조회 키는 그대로 보존한다.** 차트에 넘겨 그릴 배열만 잘라야 한다. 공유 결과를 잘라 저장해 세부 흐름 창의 날짜 대응 자료가 사라지게 하지 않는다. 기간 버튼 때문에 추가 GET·DB 읽기·외부 조회를 시작하지 않는다.
- 가격/수익률 계산·원장·보유 자료·API·DB·의존성·PUSH·OCI는 변경하지 않는다.

## 4. 작은 후속 작업의 진행

- POC5-19 종료 정리와 별도로 위 기간 선택을 준비한다. 현재 설계와 개발자가 이미 확인한 '전체 시계열 수신' 사실로 충분하므로 별도 PLAN 제출·판정 왕복은 요구하지 않는다. 실제 코드와 다른 사실이 확인될 때만 그 차이를 보고한다.
- 개발자가 두 대상 화면의 기간 선택 위치와 짧은 실제 표시 기간을 1440px·1000px 전체 화면 목업으로 보여 준다. 사용자 확인 뒤 구현한다. 새 기능 전체를 다시 그릴 필요는 없다.
- 검사: 기간 경계·월말·짧은 시계열·전체 복구, 기간 변경 시 가장 최근 값 선택, 실제 기간/저장일 수, 기간 선택의 새 GET 없음, 세부 흐름 창의 전체 원본 재사용을 관련 화면 시험으로 확인한다. 타입·eslint·프론트 회귀를 실행한다. backend 변경이 없으므로 backend 전체 회귀를 반복하지 않는다.
- 사용자 실화면과 검증자 확인을 거쳐 짧은 결과를 제출한다. 별도 조사·구조 개편·차트 기능 추가를 붙이지 않는다. 이 문서 하단이 후속 설계 원문이므로 별도 설계 파일 작성은 의무가 아니다.
