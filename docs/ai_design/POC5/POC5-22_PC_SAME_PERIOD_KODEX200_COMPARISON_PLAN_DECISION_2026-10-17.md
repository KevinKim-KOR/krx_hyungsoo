# POC5-22 동일 기간 KODEX200 비교 — PLAN 판정

작성일: 2026-10-17 · 작성자: 설계자 · 수신: 개발자 / 사용자

**판정: PASS — Q1·Q2·Q3 모두 (a). 아래 확정을 PLAN에 반영하고 재제출 없이 구현한다.**

첨부 PLAN을 설계 V1과 대조했다. 사용자 목업 확인은 PLAN의 2026-10-17 '좋습니다. 진행해주세요.' 기록을 수용한다. 설계자가 맥북 목업·DB·코드를 직접 실행한 확인은 아니다.

## 1. 질문 확정과 설계 보충

| 질문 | 판정 | 적용 |
|---|---|---|
| Q1 가격 기준 연결 검사 | **(a)** | 현재 후보 계산과 같은 저장 날짜·종가를 사용하고, 이번에는 자료원·change 열 확장과 연결 검사를 추가하지 않는다. |
| Q2 「ETF 비교하기」 보유 탭 | **(a)** | 보유 근거 API의 PC 응답 사본에도 새 동일 기간 객체를 연결하고, 보유 탭·상세에서 같은 helper로 표시한다. 공유 builder는 유지한다. |
| Q3 「보유와 비교」 후보 카드 | **(a)** | 기존 단기 20구간 값으로 숫자를 바로잡아 해당 화면의 정렬·보유 카드와 맞춘다. 이 자리에 1개월 값을 새로 넣지 않는다. |

- **Q1의 한계는 숨기지 않는다.** 도움말과 복사문의 공통 설명에 '저장 종가로 계산하며 가격 조정 기준의 연속성은 검사하지 않습니다'라는 뜻을 한 번 적는다. 칸마다 경고를 반복하거나 새 경보 배지를 만들 필요는 없다.
- 새 객체의 `status=ok`는 필요한 날짜·유효 가격으로 산술 비교가 가능하다는 뜻이다. 가격 기준 연결을 확인했다는 뜻으로 기록하지 않는다. 상위 30개 창의 끊김 0은 개발자 조사 범위의 참고 관측이며 전체 이력 검증으로 확대하지 않는다. BACKLOG에는 이 한계를 관찰로 보존하고 자동 후속 검증 단계를 열지 않는다.
- 이에 따라 설계 §3의 가격 기준 연결 처리 요구는 이번에 검사하지 않는 범위로 확정한다. 정확한 A·B, 양수·유한 종가, 결측을 다른 날짜로 대체하지 않는 요구는 유지한다.
- **Q2는 기존 자료 제공 범위를 보존한다.** 현재 경로는 상위 10 후보와 연결되는 보유 종목에만 값을 제공한다. 해당 종목이 없으면 '동일 기간 값 없음'으로 두고, 다른 기간 값이나 단기 20구간 값으로 채우지 않는다. 상위 10 밖 보유 종목의 새 계산 경로를 이번에 만들지 않는다. 이 가용 범위는 결과서에 명시한다.
- **Q3는 설계의 대상 가정을 정정한다.** 조사 결과 「보유와 비교」의 의도·정렬·보유 쪽은 20구간이고 후보 카드만 1개월 값이었다. 이 화면은 1/3개월 동일 기간 비교로 전환하지 않고 잘못 연결된 값을 정정한다. 별도 단계로 나누지 않는다.
- Q3 칸은 **'20구간 KODEX200 차이'·%p**로 의미를 분명히 한다. 기존 저장행 기반 단기 계산이며, 새 1/3개월 동일 기간 지표와 구분한다. 이 기존 단기 값의 비교 날짜까지 이번에 다시 맞췄다고 기록하지 않는다.

## 2. 나머지 구현 계획 수용

- 후보의 반올림 전 수익률과 같은 A·B의 KODEX200 수익률을 빼고 마지막에 소수 4자리로 전달하는 계산·선택 객체·기본 False 경계를 수용한다. 추가 SELECT·외부 조회·연구 모듈 import 없이 기존 이력을 한 번 정리해 재사용한다.
- PC 시장 API와 보유 근거 API의 해당 PC 사본 연결을 허용한다. 그 외 호출·공유 builder·기존 `excess_return.*`·`basis_*`·시장 판정·PUSH 계약은 유지한다. 새 필드가 없을 때 기존 차이를 대체값으로 사용하지 않는다.
- 「ETF 비교하기」의 **기존 사용자 선택 KODEX 정렬은 새 표시값과 같은 값으로 정렬**하도록 수용한다. 기존 정렬 선택지의 의미를 맞추는 변경이며, 시장 후보의 자동 선정·기본 수익률 정렬이나 새 순위 정책을 바꾸는 것은 아니다. 「보유와 비교」의 기존 단기 20구간 정렬은 그대로다.
- 공통 복사문·화면·새 `candidate_snapshot.same_period_kodex200`가 같은 객체의 날짜·수치를 사용하도록 한다. 저장 모델의 선택 필드 추가와 기존 JSON 안 보관을 수용한다. 과거 기록을 다시 쓰지 않는다.
- 기존 `market_context_snapshot.candidate_excess_returns`를 보존할 경우 기존 다른 기간 차이의 정의도 보존한다. 새 동일 기간 값의 생성 입력·대체값으로 사용하지 않는다. 새 비교의 기준은 새 객체이며 질문 본문과 일치해야 한다.
- 1/3개월 비교와 단기 20구간 비교는 서로 다른 계약이다. 단위·기본 표시를 위한 작은 helper는 공유할 수 있지만, 자료가 없다고 서로 바꿔 끼우지 않는다.
- PLAN의 변경 파일·시험·회귀 범위를 수용한다. Q1 미검사의 설명, Q2 자료 없음, Q3 표시 숫자와 기존 20구간 정렬의 연결, 기존 KODEX 사용자 정렬과 새 표시값의 일치를 시험에 반영한다.
