## 1. 완료 모습과 평가의 뜻

「받은 알림 기록」에서 **[사후평가 실행]**을 누르면 PC 사본의 당시 신호와 저장된 가격 결과를 읽어 평가 산출물을 만든다. 매일 방문하거나 모든 알림을 평가할 필요가 없다.

| 근거 | 이번 결과 | 의미 |
|---|---|---|
| 실제 가격 결과 | +1/+5/+20 종가 변화·관측 경로 최고/최저 변화·성숙 상태 | 알림 뒤 가격이 어떻게 움직였는가 |
| ML 과거 검증 | +5 추정·실제값·오차, 단순 기준과 같은 표본의 MAE 비교 | 당시 정보가 이후 가격 결과 추정에 도움이 됐는가 |
| 사용자 평가 | 최신 ‘도움됨/보통/불필요·혼란’과 평가 시점 | 사용자에게 도움이 됐는가 |

**기본 사후평가는 가격 결과에 따른 평가다.** 사용자 평가가 있으면 알림 요약에서 별도 근거로 우선 표시한다. 없으면 ‘사용자 평가 없음’과 자동 평가를 제공한다. 사용자 평가를 모델 점수로 대체하거나 자동 평가를 user_feedback에 넣지 않는다. 세 근거를 한 성공률로 합치지 않는다.

가격 추정이 맞았다는 사실만으로 매수·매도 판단이나 알림의 전체 적절성이 입증되지는 않는다. 이번 대리 목표는 ‘신호 당시 정보와 이후 +5 가격 변화의 관계’다. 모델이 사용자 도움 여부를 알아냈다고 표시하지 않는다.

## 3. 입력·대상·분모

원장 사본을 mode=ro·읽기 트랜잭션 하나로 읽어 메모리 snapshot을 확정한 뒤 연결을 닫는다. 학습·파일 저장 중 DB 읽기 트랜잭션을 유지하지 않는다. 날짜 축·예상 결과 슬롯·series 연결은 02/04의 확정 helper를 재사용한다. 과거 가격 DB·현재 종목 마스터로 신호를 재구성하지 않는다.

- 가격 관측 모집단: FINALIZED·PRIMARY_LIVE·off_schedule=0의 evaluable=1 가격 결과 대상. 02 대상 규칙을 재사용한다.
- sent·suppressed·상한 제외·not_selected를 모두 관측에 포함한다. **feedback 유무는 어떤 대상 필터에도 넣지 않는다.**
- 전달된 본문 항목: disposition=sent AND delivery_status=sent를 별도 표시한다. partial은 item별 실제 전달을 확정할 수 없으므로 별도 건수로 둔다. 전달 실패·skip을 가격 실패나 비유익 라벨로 만들지 않는다.
- exposure의 PRIMARY·SECONDARY·NONE을 보존한다. PRIMARY_LIVE는 수집 cohort이고 PRIMARY는 노출 구분이다. 둘을 혼동하지 않는다. NULL state도 평가 가능한 비선정 상태로 기록돼 있다면 유지한다.
- 사건·항목·가격 관측·서로 다른 신호 날짜·series 수를 따로 센다. 반복 틱과 대표 ETF 중복을 독립 알림 수로 부풀리지 않는다.
- LEGACY·예정 외·evaluable=0·결과 대상 아님은 사유/건수를 표시한다. legacy 신호·outcome backfill은 하지 않는다.

가격 사후평가는 시장·기초지수도 기존 series별로 제공한다. **V1 ML 대상은 보유 브리핑/장중의 ticker·sector 중 지원되는 KRX_UNADJUSTED 결과뿐**이다. 시장 SP500→KOSPI와 기초지수 그룹은 ‘이번 ML 범위 밖’으로 표시하고 원시 결과는 유지한다. 시장 방향을 한국 시장 예측으로 채점하거나 여러 ticker 결과를 그룹 평균 라벨로 만들지 않는다.

## 4. 자동 가격 사후평가

각 (event_id, item_seq, series_id, horizon)에 저장된 결과를 그대로 읽는다. 새 가격 결과를 계산·수정하거나 FDR/현재가로 결측을 메우지 않는다.

- MATURED이면 평가일·t0·종가 변화·max_up_raw/max_down_raw·price_basis를 표시한다. 무조정 가격 비교이며 배당·세금·수수료를 포함한 개인 손익이 아니다.
- 대표/대체 ETF와 기초지수 구성원은 저장된 series 연결을 사용한다. 현재 대표 설정으로 과거 연결을 바꾸지 않는다.
- +5가 성숙하면 ‘기준가격 대비 +5 종가 상승/하락/변화 없음’을 자동 표시한다. 부호는 저장 원시값으로 판단한다. D/U 상태 뒤의 결과를 함께 보되 이 문구를 신호 성공/실패로 이름 붙이지 않는다. 끝점 변화가 경로 전체의 계속 상승/하락을 증명하지 않는다.
- 경로 최고/최저에는 path_points를 함께 보존한다. 경로 수가 horizon보다 작으면 ‘일부 종가 경로’로 표시한다. 끝점 결과가 유효하면 경로 일부 누락만으로 +5 끝점 라벨을 지우지 않는다.
- PENDING은 미도래/도래 후 미기록을 04 규칙으로 구분한다. T0_MISSING·PRICE_MISSING·UNTRACKED_AFTER_EXIT·UNSUPPORTED_PRICE_SOURCE는 각각 표시한다. 결측을 0%·나쁜 알림으로 바꾸지 않는다.
- 사용자 평가 있음/없음에 따라 같은 가격 결과의 수치·문구가 바뀌지 않는다.

## 5. ML V1 — 목표와 입력

```text
라벨 y = price_outcome.return_raw (horizon=5, status=MATURED)
관측 키 = event_id + item_seq + series_id
모델 = Ridge(alpha=1.0, solver="svd", fit_intercept=True)
비교 기준 = 해당 학습 표본의 날짜 균형 가중 중앙값 y 하나
```

02의 +5는 15:30 이전/이후에 첫 종가가 다른 **+5번째 종가**다. 이를 무조건 사건 다음 5거래일로 다시 계산하지 않는다. +1/+20은 이번 모델의 다른 라벨·선택 후보가 아니며 원시 검토 자료다. 06 D20과 같은 모델·목표로 취급하지 않는다.

입력은 당시 저장 스냅샷에서 아래 허용 목록만 사용한다.

| 입력 | 처리 |
|---|---|
| push_kind·subject_kind·state·event_type·exposure·held | 범주값. NULL은 명시적 NONE. 학습 구간에서 범주 사전을 fit하고 처음 보는 범주는 별도 미관측 처리 |
| 판정에 실제 사용한 20거래일 가격 변화 | values_json에 저장된 가격 기반 값만. 비율로 정규화 |
| 판정에 실제 사용한 당일 가격 변화 | 같은 원칙. 매입가 대비 수익률과 혼동하지 않음 |

숫자 두 필드의 실제 키·부호·%/비율 단위·적용 kind를 PLAN에서 고정한다. 저장되지 않은 값은 새로 계산하지 않는다. 없는 숫자는 결측 표시와 함께 학습 구간 유효값의 가중 중앙값으로 대입하고, 그 구간에 유효값이 전혀 없으면 0+결측 표시를 사용한다. 숫자가 없는 정상 item을 사용자 무평가와 함께 제외하지 않는다.

숫자는 학습 구간에서만 대입값·가중 평균·가중 모집단 표준편차를 계산해 표준화한다(상수 열은 변환값 0). 범주는 학습 구간에서 사전을 확정한 dense float64 one-hot이며 별도로 표준화하지 않는다. 시험의 미관측 범주는 해당 범주 묶음의 0 벡터로 처리하고 건수를 남긴다. 식별자·종목 이름·본문·메모·사후 피드백·이후 가격·computed_at·전달 성공/실패·개인 매입가 대비 값은 feature가 아니다. 서로 다른 계약 버전의 필드 의미가 다르면 명시된 매핑으로만 정규화하고 지원되지 않는 버전은 사유를 남긴다.

학습은 날짜와 series의 반복을 다음 가중치로 균형화한다: 한 신호 날짜의 서로 다른 series 수 S, 그 날짜 같은 series의 유효 행 수 N일 때 각 행 w=1/(S×N). 날짜별 합은 1이다. 모든 유효 관측을 보존하며 임의 대표 행만 뽑지 않는다. 중앙값은 y 오름차순에서 누적 가중치가 총량의 절반 이상인 첫 값으로 고정한다. 모델 fit에는 같은 w를 사용한다.

기존 설치 버전을 PLAN에 기록한다. 공식 API 참고는 [Ridge](https://scikit-learn.org/stable/modules/generated/sklearn.linear_model.Ridge.html)와 [학습/시험 전처리 분리](https://scikit-learn.org/stable/common_pitfalls.html#data-leakage)다. 모델·기간·가중치·최소 날짜 수는 이 프로젝트의 설계 선택이며 문서가 투자 유효성을 보장하는 기준은 아니다.

## 6. 시간 분리 검증과 결과

보고 종료일은 KST 오늘 이전의 마지막 완료 거래일을 기본으로 하고 명시적 선택도 같은 범위로 받는다. 종료일은 신호 포함 기간의 끝이며 당시 PC 사본을 복원하는 기능은 아니다. 자동 가격 평가에는 실행 snapshot에 저장된 이후 결과를 쓰고 각 평가일·계산 시각을 표시한다. 운영 캘린더로 종료일의 5거래일 전을 검증 anchor로 정한다. anchor로 끝나는 마지막 15거래일을 오래된 순서로 5일씩 세 구간으로 나눈다. 사건 없는 날을 삭제해 날짜를 붙이지 않는다. 사본·결과가 늦으면 해당 표본은 미성숙으로 남는다.

각 구간에서 다음을 지킨다.

1. 구간 시작보다 앞선 사건만 학습 후보이며, **+5 eval_date의 종가 시점과 outcome.computed_at 모두 구간 첫 시험 사건 시작 시각보다 앞선 행**만 학습한다. 저장 시각은 시간대 변환으로 비교한다. 학습 정답이 그때 아직 없었다면 제외한다.
2. 같은 사건 날짜의 모든 item/series는 같은 구간이다. 행 무작위 분할이나 ‘마지막 5행 제거’로 대체하지 않는다. 구간 안에서 모델을 다시 fit하지 않는다.
3. 각 학습 구간에 서로 다른 유효 신호 날짜 20일 이상과 유효 시험 행이 필요하다. 부족한 구간은 DATA_SHORT다. 이 수치는 V1의 출력 보류 기준이며 성능의 충분성 증명이 아니다.
4. 모델·단순 기준은 동일 시험 행·동일 라벨로 비교하고 시험 +5의 eval_date는 보고 종료일 이하다. 가중치는 실제 사용하는 학습/시험 집합에서 각각 확정한다. MAE는 날짜별 가중 절대오차의 합을 날짜 수로 평균하고 %p로 표시한다. 그룹별 건수도 함께 출력한다.
5. 모델 추정은 수익률의 하한 -1로만 제한하고 상한은 자르지 않는다. 제한은 모든 시험에서 동일하다. 단순 기준과 오차를 계산할 때 실제 라벨을 자르지 않는다.

세 구간이 모두 유효하면 전체와 구간별 MAE를 제공한다. 전체는 시험 날짜를 합친 날짜 균형 MAE다. 비교 문구 ‘개선/차이 없음/악화’는 표시하는 소수 2자리 %p 기준으로 정하고 원시 오차·차이도 보존한다. 불완전 검증은 구간별 진단만 남기며 전체 비교 판정을 만들지 않는다. 어떤 결과도 승인·확률·추천 배지로 바꾸지 않는다.

item별 ML 칸에는 **자신을 학습에 넣지 않은 해당 시간 구간 모델의 과거 검증 추정**만 붙인다. 시험 구간 밖·미성숙·자료 부족은 ML 값 없음과 사유를 표시하되 자동 가격 평가·사용자 평가는 계속 제공한다. 전체 자료로 fit한 값을 과거 알림에 붙여 ‘당시 예측’이라고 표시하지 않는다. computed_at은 OCI 결과의 기록 시각이며 그때 PC에서 읽었다는 증거는 아니다. 이 경계는 연구 재구성에 사용한다. V1은 새 현재 알림 예측이나 운영 모델 저장/채택을 하지 않는다.

표시 예: ‘+5 실제 -3.00% / 과거 검증 추정 -1.00% / 단순 기준 -0.50% / 절대오차 2.00%p’. 이는 당시 운영에서 발행한 예측이 아니라 보존된 스냅샷으로 재구성한 연구 검증이다. 반복된 종목·겹치는 결과 창을 독립 표본으로 가정한 신뢰구간·적중률은 제공하지 않는다.

## 7. 사용자 평가 사용과 산출물

사용자 평가는 알림 전체 event의 최신 1건을 사용하고 feedback_seq·helpfulness·feedback_at을 보존한다. 여러 item에 붙여도 여러 사용자 평가로 세지 않는다. 도움 여부와 가격 평가가 다르면 두 근거를 그대로 표시한다. action·메모는 기존 화면에서 볼 수 있으나 학습·연구 파일에는 복사하지 않는다.

- 연구 산출물: 기존 관례의 `state/ml/research/poc5_08/<생성시각>_<id>/`에 report.json·input_snapshot.json. 운영 DB에는 쓰지 않는다. 모델 pickle·학습 서비스·별도 latest 상태 파일을 추가하지 않는다.
- snapshot은 실제 사용한 허용 feature·결과·연결 키·시간·계약 버전·평가 식별값·recipe를 담는다. values_json 전체·본문·개인값을 복사하지 않는다. 행/키를 안정적으로 정렬하고 하나의 입력 digest를 계산한다. 생성/동기화 시각은 별도 메타데이터로 표시한다.
- 같은 입력과 recipe면 자동 가격 평가·모델·단순 기준·오차가 같다. feedback만 바뀌면 digest·사용자 평가 표시는 바뀌되 표본·가중치·모델 수치가 같다.
- 필수 입력표 누락·읽기 오류·중복 키·참조 손상은 빈 모집단으로 성공 처리하지 않는다. CHECK_REQUIRED와 원인을 표시한다. 정상적인 사본 없음·미성숙·미지원·DATA_SHORT와 구분한다.
- 쓰기 실패는 실행 실패로 돌려주고 기존 산출물을 보존한다. report와 snapshot이 완성된 산출물만 latest로 제공한다. DB 수리·원장 변경·성숙 재실행은 하지 않는다.

## 8. 화면·로컬 API

기존 「받은 알림 기록」 머리에 큰 48px **[사후평가 실행]**을 붙인다. [원장 새로고침]과 별도 동작이다. 실행은 사본 전체의 보고 기간을 대상으로 하며 현재 목록 하루만 학습하지 않는다.

### 1. 판정과 근거

첨부 DESIGN V1과 PLAN V1을 모두 대조했다. PC 원장 사본의 읽기 전용 snapshot, 무평가 데이터 사용, +5 고정 Ridge와 같은 표본의 중앙값 기준, 학습 구간만의 전처리, 시간 분리, 기존 메뉴의 수동 실행 방향을 승인한다.

이 판정은 첨부 문서와 개발자의 조사 보고에 근거한다. 설계자가 실제 코드·PC DB·OCI·설치된 라이브러리를 재검증했다는 뜻은 아니다.

### 2. 수용하는 구현 세부

- `return_20d_pct` / `day_return_pct` 저장값을 %에서 비율로 변환한다. 개인 `profit_loss_pct`를 쓰지 않고 구조적 결측 때문에 행을 버리지 않는다.
- 학습 구간의 가중치·가중 중앙값·전처리·Ridge와 시험 구간의 가중치·MAE를 분리한다. 사용자 평가는 feature·label·표본 필터로 쓰지 않는다.
- PLAN §2-6-1의 시험 시작 시각(구간 ML 시험 행 중 가장 이른 `runtime_kst`)을 수용한다. 학습 신호일은 고정된 구간 시작일보다 앞서야 하고, 평가일 종가 시각과 `computed_at` 모두 이 시작 시각보다 앞서야 한다. 빈 날짜를 지워 구간을 붙이지 않는다.
- `price_basis`는 `|` 앞 기본 이름을 `KRX_ETF_UNADJUSTED` / `KRX_STOCK_UNADJUSTED`와 정확히 비교한다. 실제 분류 접미는 보존하고 feature로 쓰지 않는다.
- 04/02 helper 재사용, 로컬 API 2경로, 연구 파일 2개, 선택 사용자 평가, NO_COPY / CHECK_REQUIRED 구분을 수용한다.

### 3. 확정 보충 — 재제출 없이 반영

#### A. 12월 9일은 전체 구간 비교의 조건부 기준일

PLAN의 전제에서 날짜 계산은 맞는다. 학습 20신호일: 10-08~11-05, 첫 시험일: 11-12, 15번째 시험일: 12-02, 보고 종료일: 12-09다. 이는 매 거래일 유효 대상과 정상 성숙이 있는 경우 세 구간 전체 비교가 가능한 조건부 하한이다. 실제 실행은 12-10 해당 배치 완료·PC 동기화 뒤다.

`FIRST_ML_DATE`와 ‘그 전에는 ML이 돌지 않는다’로 읽힐 문구를 **‘전체 3구간 비교의 가장 이른 보고 종료일(조건부)’**로 맞춘다. 충분한 구간의 진단은 그 전에도 제공할 수 있다. 모든 구간이 유효하지 않으면 전체 비교를 만들지 않고 DATA_SHORT와 구간 진단을 표시한다. 날짜를 고정 실행 금지 조건으로 쓰지 않고 실행마다 실제 유효 표본으로 판단한다.

#### B. 신호 기간 종료일과 가격 관측 기준일을 구분

DESIGN §4의 ‘04 규칙 재사용’과 §6의 ‘실행 snapshot의 이후 결과’ 사이에 모호한 부분이 있어 설계자가 보충한다. **PLAN §2-1.4의 PENDING을 보고 종료일만으로 판정하는 안은 변경한다.**

- `end_date`는 대상 신호 기간과 ML 구간의 상한이다. 결과를 그날 상태로 되돌리지 않는다.
- snapshot 획득 시각을 한 번 고정하고, 기존 calendar와 15:30 경계에 따른 마지막 종가 종료 거래일을 `price_asof_date`로 둔다. 이는 연구 입력 기준일이며 DB에는 쓰지 않는다.
- 저장 결과가 없는 슬롯은 평가일이 `price_asof_date`보다 뒤면 미도래, 같거나 앞이면 도래 후 미기록으로 표시한다. 도래 후 미기록도 공개·보강 대기를 포함하므로 그 사실만으로 오류나 PRICE_MISSING으로 바꾸지 않는다. 저장된 결과 상태는 그대로 쓴다.
