# POC5-18 PC 시장 갱신의 예상 밖 오류 상태 정정 — 설계 V1

작성일: 2026-10-16 · 작성자: 설계자 · 독자: 개발자
대상 결함: `DEF-PC-REFRESH-UNEXPECTED-COMPLETED`
기준: 개발자 POC5-17 종료 보고의 커밋 `64749ad4` · 원격 반영은 개발자 보고 근거
저장 권장 경로: `docs/ai_design/POC5/POC5-18_PC_MARKET_REFRESH_UNEXPECTED_FAILURE_STATUS_DESIGN_V1.md`

## 1. 해결할 문제와 완료 모습

POC5-17 RESULT §5·§11·§12에서 다음 기존 동작이 확인됐다.

- ETF 목록 수집 뒤 종목 목록 읽기가 예상 밖 예외로 실패하면, 가격 시도 수가 0인 채 `completed`와 6시간 대기가 기록될 수 있다.
- 가격 자료를 받은 뒤 가격 기록 행 쓰기가 실패한 경우도, 연속 timeout 조기 중단이 없으면 같은 완료 판정을 받을 수 있다.
- 연속 timeout 중단이 실제로 있었던 경우는 POC5-17에서 이미 고쳤다. 이번에는 중단 없는 예상 밖 오류를 다룬다.

완료 모습: **해당 실행에서 예상 밖 오류가 발생했으면 최종 상태를 failed로 기록하고, 그 실행으로 성공 갱신 시각이나 6시간 대기를 새로 만들지 않는다. 작업이 끝나면 같은 버튼으로 다시 실행할 수 있다.** 이미 받은 자료는 보존한다.

## 2. 범위

- 대상은 PC `POST /market/refresh`의 기존 `refresh_unexpected` 예외 처리 경계와 최종 성공 판정이다. 기준 파일은 `app/market_refresh_service.py`다.
- 구현 전 이 경계의 실제 위치와 도달 경로를 확인한다. 오류 문구 검색 결과만으로 동작을 추정하지 않는다.
- 기존 상태값 `failed`, 오류 요약, 실행 잠금, 재실행 경로를 재사용한다. 이 실행에서 예외가 있었음을 최종 판정까지 보존하는 작은 내부 표식으로 충분하다.
- 새 메뉴·목업·API 경로/응답 필드·DB 표·의존성·외부 조회·자동 재시도·새 대기/횟수 제한은 없다. OCI·PUSH·터미널 수동 스크립트·POC5-17 요청 timeout은 그대로다.

## 3. 상태 판정 계약

| 경우 | 이번 판정 |
|---|---|
| 해당 예외 경계에서 예상 밖 오류 발생 | 최종 failed. 오류가 생겼다는 사실을 뒤 단계 성공이 지우지 않는다. |
| 연속 timeout 조기 중단 + 예상 밖 오류 | POC5-17의 failed를 유지하고, 중단 이유와 오류를 모두 남긴다. |
| 종목별로 기존 처리되는 일부 가격 조회 실패 | 기존 completed/failed 기준과 기존 대기 정책을 유지한다. |
| 마지막 5종목 timeout, 미조회 0, 예상 밖 오류 없음 | POC5-17 RESULT 판정대로 기존 결과 판정을 유지한다. |
| 정상 갱신 | 기존 완료·성공 시각·6시간 대기와 같다. |
| 기존 ETF 목록 실패·보유 개별주 일부 실패·KOSPI/VIX/NAV 결과 | 기존 정책을 유지한다. 모든 사유를 새 실패 정책으로 묶지 않는다. |

- 오류 문구에 특정 문자열이 들어 있는지로 성공 여부를 결정하지 않는다. 예외를 처리하는 실제 경계에서 발생 사실을 남긴다.
- 해당 실행 안에서 예상 밖 오류 표식은 한 번 생기면 최종 판정까지 유지한다. 다음 실행은 새 실행으로 시작하며 이전 오류를 물려받지 않는다.
- 뒤 단계의 실행 여부·순서는 기존 흐름을 유지한다. 추가 조회로 자동 복구하거나 같은 작업 안에서 재시도하지 않는다.
- 예상 밖 오류가 있으면 VIX만 실패한 회차로 판정하지 않는다. 기존 VIX 전용 재시도 표식과 전체 갱신 잠금 관계를 유지한다.
- 작업이 실제로 끝난 뒤 메모리와 기존 영속 상태가 failed로 정리돼야 한다. 작업은 계속 실행 중인데 running만 풀어 중복 실행을 허용하는 방식은 쓰지 않는다.
- 이번 failed 실행은 새로운 성공 시각을 만들지 않는다. 이전 정상 성공 이력을 오류 시각으로 덮거나 지우지 않는다. 재실행은 기존 failed 경로를 따라 허용한다.

## 4. 자료와 사용자 표시

- 앞서 저장한 정상 가격은 보존한다. 실패한 회차라는 이유로 자료를 롤백·삭제하거나 실패 종목의 예전 값을 빈 값으로 덮지 않는다.
- 현재 화면의 failed 표시와 기존 오류 요약을 사용한다. 예외 사유를 숨기거나 가격 시도 수 0을 근거로 성공 처리하지 않는다.
- 반환 전 오류 때문에 건수를 확보하지 못한 경우 성공 건수를 추정해 만들지 않는다. 기존 건수 필드의 의미는 보존하고, 오류 요약으로 해당 단계가 정상 종료하지 못했음을 드러낸다.
- 과거 completed 이력을 소급 변경하거나 과거 로그를 고치는 작업은 포함하지 않는다.

## 5. 구현 전 짧은 PLAN

다음 세 가지만 실제 코드와 대조해 제출한다. 확인된 근거가 같으면 설계자 질문을 만들 필요는 없다.

1. `refresh_unexpected`의 예외 경계와 위 두 재현 경로, 현재 최종 상태·성공 시각 결정 위치.
2. 예상 밖 오류 사실을 보존하고 최종 failed로 연결할 최소 변경. 기존 POC5-17 중단 정보와 VIX 전용 재시도 판정의 관계.
3. 아래 시험을 기존 fixture로 재사용할 방법과 변경 파일. 공통 함수나 다른 실행 경로를 바꿔야 한다면 이유를 적는다.

이번 수정의 목적은 완료 판정 정정이다. 일반적인 갱신 엔진 재설계나 별도 구조 분리 단계를 선행 요구하지 않는다.

## 6. 검증과 종료

라이브 DB와 외부 서버 장애를 만들지 않고 tmp DB·기존 시험 주입 지점으로 확인한다.

- **종목 목록 읽기 오류:** ETF 목록 단계는 성공한 뒤 목록 읽기를 실패시킨다. 최종/영속 상태 failed·성공 시각 미갱신·대기 0·다음 실행 accepted를 확인한다.
- **중단 없는 가격 기록 오류:** 정상 자료가 저장된 뒤 가격 기록 INSERT만 실패시킨다. 저장 자료 보존, failed·오류 요약·다음 실행 가능을 확인한다. POC5-17의 SQLite 재현 방식을 재사용할 수 있다.
- **기존 중단과의 결합:** timeout 중단 뒤 기록 오류에서도 POC5-17의 failed와 두 사유가 유지된다.
- **정상/부분 실패 대조:** 정상 완료와 기존 일부 종목 실패 완료의 대기 규칙, 마지막 5종목 timeout·미조회 0의 기존 판정이 변하지 않는다.
- **실행 간 분리:** 오류 회차 뒤 재실행이 정상 종료할 수 있다. 정상 종료 뒤에는 기존 대기가 작동한다. VIX만 실패한 경우의 기존 전용 재시도도 유지된다.
- 관련 시험과 정적 검사 후 백엔드 전체 회귀를 한 번 실행한다. 기존 갱신·POC5-17·VIX 재시도 시험을 활용한다. 화면 변경이 없으면 프론트 시험이나 목업을 추가하지 않는다.

순서: 짧은 PLAN → 판정 → 구현 → 검증자 → RESULT 판정 → 종료 기록·사용자 승인 범위의 커밋/push. 외부 장애 실재현·거래일 대기·OCI pull은 종료 조건이 아니다. 별도 인계 문서는 필요 없다.

종료 시 해당 결함 항목만 해소로 정리한다. POC5-17의 DNS·느린 연속 응답 등 전체 종료 보장 부재는 그대로 남긴다.
