# POC5-15 현재 시장·보유 상태 조합 — PLAN 판정 및 화면 설명 개정
작성일: 2026-10-15 · 독자: 개발자 · 사용자 · 검증자
판정: **CONDITIONAL_PASS — 본 보충 반영과 수정 목업 사용자 확인 뒤 구현**
근거: PLAN V1·compare.html·사용자 목업 의견. 조합 로직은 수용하고 설명·줄바꿈을 개정한다.

## 1. 사용자 의견의 적용
- 사용자 의견은 “목업의 기본 방향은 좋으나 긴 상시 설명은 읽지 않게 된다. 현재 해당하는 것만 보여 주고 설명은 ? 등으로 열며, 의미 단위 줄바꿈이 필요하다”이다.
- 정보와 설명의 구분을 화면에 적용한다. 긴 문단에 줄바꿈만 늘려 요약 높이를 키우지 않는다.
- 첨부 compare.html은 shots/ 상대 이미지 경로를 가리키는 비교 목차이다. 이 첨부만으로 실제 캡처를 직접 확인했다고 기록하지 않는다. 화면 의견은 사용자의 확인을 근거로 한다.
- 목업 수정은 개발자가 한다. 설계자가 별도 목업을 다시 만들지 않는다.

### Q1. 실제 실패와 근거 없는 건수
- 받은 자료가 없는데 띠를 없애지 않는다. “자료 확인 필요” 또는 표에 따른 상태를 보여 준다.
- 실제 실패한 조회를 구분해 “보유 자료를 불러오지 못했습니다” 또는 “확인 근거를 불러오지 못했습니다”처럼 한 문장으로 쓴다.
- 실패하지 않은 자료까지 함께 실패했다고 쓰지 않는다. 확인되지 않은 건수를 0건으로 만들지 않는다.
- 이전 §6.4의 취지는 “근거 없이 자료 확인 필요 건수를 만들지 않는다”로 유지한다. 실제 조회 실패의 상태·사유 표시는 허용하도록 해당 시험을 개정한다.
- 최초 불러오는 중은 기존대로 판정하지 않는다. 성공한 빈 보유는 실패보다 먼저 구분해 “보유 판정 대상 없음”만 보인다.
- 재조회 실패 뒤 유효한 기존 응답을 유지하는 정책과 정상·오류 구분은 그대로 사용한다. 새 조회·재시도 제한을 만들지 않는다.

### Q2. Q6에 넣을 문장
구현 커밋 때 기존 상태 블록 아래 다음 내용을 기록한다. OPERATIONAL_CONTRACT = OPEN과 질문 상태는 유지한다.

> POC5-15 PC 현재 상태 조합 룰 — 운영 표시 후보. 기존 시장 국면(bear / bull / neutral)과 PC 하락 구간 존재를 조합하며 새 수치 임계는 없다. 시장·보유 상태의 조합을 보여 주는 표시이고, 연구 계약의 위험/정상 분류 또는 이후 손실과 대조한 타당성 검증을 완료한 것이 아니다. Q6 운영 계약 확정·ANSWERED로 승격하지 않는다.

### Q4. 표현 변경
- 기존 “현재 기준 하락 신호 미해당”은 두 화면 모두 **“시장·보유 하락 구간 미해당”**으로 바꾼다.
- '하락 신호' 금지 검사에 새 예외 문구를 뚫지 않는다. 나머지 조합 표와 의미는 유지한다.
- “미해당” 설명은 이 상태의 도움말에서 현재 기준에 해당하지 않았다는 뜻으로 풀어 준다.

## 3. 기본 화면에 남길 것
| 정보 종류 | 기본 표시 |
|---|---|
| 현재 상태 | 굵은 상태 문구와 ? 도움말 |
| 구간 수·평가 비중 | 기존 값·PC 구간 이름 유지 |
| 시장 국면·지속일 | 짧은 보조 정보 |
| 판정 가능 a/b·PC 가격 흐름 기준일 | 간결한 보조 정보. 날짜는 가격 흐름 기준임을 구분 |
| 판정 불가·평가 미확인·조회 실패 | 해당할 때만 짧은 상태·사유 표시 |
| 정의·산식·반올림·PC와 OCI 차이 | ? 도움말로 이동 |

- “확인 불가”, 일부 종목 판정 불가, 일부 평가 미확인은 중요한 현재 정보이므로 도움말 속에만 숨기지 않는다.
- 정상인 항목에 해당하지 않는 오류 설명을 늘어놓지 않는다. 정상이라는 별도 장문도 추가하지 않는다.
- 「확인 근거」의 출처 구분은 **“PC 저장 종가 기준”**이라는 짧은 표시로 남긴다.
- 기존 13 판정의 PC·OCI 차이 상시 문장 요구를 이 범위에서 개정한다. 전체 설명은 도움말로 옮기되 PC 출처와 실제 기준일은 기본 화면에서 확인 가능하게 한다.
- 오늘 띠에 그 긴 안내를 생략한 사용자 결정은 유지한다. 종목 상세의 실제 계산 기간·개별 자료 사유는 기존 자리에 둔다.

## 4. 줄바꿈과 배치
### 오늘 보유 띠 — 세 정보 묶음
1. **현재 상태 문구 + ?**: 독립된 제목 줄. 시장 국면을 같은 긴 문장에 이어 붙이지 않는다.
2. **PC 하락 구간 종목 수·평가 비중**: 핵심 숫자를 함께 읽는 줄.
3. **시장 국면·지속일 / 구간 판정 a/b**: 작은 보조 정보 묶음. 해당하는 짧은 부분 확인 표시를 함께 둔다.

- 시장 정보를 첫 줄에서 보조 묶음으로 옮기는 것을 승인한다. 새 상시 설명 줄을 늘리지 않는다.
- 실패이면 상태와 짧은 사유만, 빈 보유이면 대상 없음만 보여 준다. 없는 수치의 자리를 채우지 않는다.
- 세 묶음은 정보 구조이지 무조건 세 줄에 가두라는 뜻이 아니다. 좁을 때는 묶음 단위로 자연스럽게 내려가게 한다.

### 「확인 근거」 요약
- “현재 상태 + ?”를 제목처럼 분리하고 기존 시장 국면은 보조 정보로 배치한다.
- 구간 수·비중, 구간별 분포, 판정 범위·기준일을 각각 의미가 맞는 묶음으로 정렬한다.
- 판정 가능 수·기준일·출처는 한 보조 영역에서 간결하게 묶는다. 항목마다 강제로 한 줄씩 만들지 않는다.
- 긴 공통 안내 문단은 제거한다. 중요한 상태와 숫자를 말줄임표로 자르거나 글자를 과하게 줄여 한 줄로 맞추지 않는다.

## 5. ? 도움말
- 요약마다 진입점은 하나로 둔다. 항목마다 아이콘을 늘리지 않는다. 두 화면은 같은 설명 데이터를 재사용한다.
- 클릭해 여닫는 작은 팝오버를 기본으로 한다. 기존 컴포넌트·아이콘 버튼 규격을 재사용하고 새 의존성은 추가하지 않는다.
- 호버만으로 열리게 하지 않는다. 키보드로 열기·닫기가 되고 Escape·바깥 클릭으로 닫히며 화면 밖으로 잘리지 않게 한다.
- 내용은 **현재 조합의 뜻 → 현재 표시값의 기준 → 해당하는 제한** 순서로 짧은 문단을 나눈다.
- 현재와 무관한 모든 조합·모든 오류의 설명 표를 넣지 않는다.
- PC 저장 종가여서 OCI 알림과 값이 다를 수 있음, 소수 1자리 반올림 뒤 구간 판정, 비중의 평가금액 합산 기준은 필요한 짧은 설명으로 옮긴다.
- “미해당” 정의는 해당 상태일 때, 일부 판정·평가 부족의 자세한 뜻은 그 경우에만 보여 준다.
- 도움말을 여는 동작은 받은 자료만 쓰며 추가 조회·저장·발송을 만들지 않는다.

## 6. 나머지 PLAN과 진행
- M의 bear / bull·neutral / 미확인 매핑, 빈 보유 우선 처리, 기존 요약 재사용, 평가 부족과 가격 분류 분리, 두 화면 공통 함수는 수용한다.
- 실패·빈 보유에서도 같은 입력은 같은 상태 문구를 사용한다. 사용자 데이터의 의미·구간 계산·선정·비중·API는 바꾸지 않는다.
- 개발자는 본 판정을 PLAN 보충에 기록하고 기존 목업을 수정한다.
- 확인용은 실제 자료의 두 화면 1440·1000px, 대표 부분 확인 상태, 도움말 열린 모습으로 충분하다. 기존 10개 상태 자료와 시험 계획을 재사용하고 목업을 처음부터 다시 만들지 않는다.
- 사용자 수정 목업 확인을 기록하면 별도 PLAN 재제출 없이 구현한다. 이번 표현·배치 변경이 기술 판정 대기 라운드를 추가하지 않는다.
- 시험은 조합 전체, Q1 실제 실패와 허위 건수 없음, Q4 문구, 조건부 사유, 도움말 개폐·추가 조회 없음, 기존 구간·선정·비중 보존을 확인한다.
- 숨긴 설명이 도움말에서 실제로 읽히는지, 실패·일부 자료 상태가 기본 화면에 남는지를 확인한다. 단순히 문구가 없어졌다는 시험으로 끝내지 않는다.
- 기존 변경 범위 검사·검증자·RESULT 절차로 마친다. OCI pull·영업일 대기는 필요 없다.
