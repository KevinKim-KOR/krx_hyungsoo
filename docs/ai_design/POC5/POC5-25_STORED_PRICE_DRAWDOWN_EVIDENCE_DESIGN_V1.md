# POC5-25 현재 저장 종가의 고점 대비 근거 정정 — 설계 V1

작성일: 2026-10-19 · 작성자: 설계자 · 수신: 개발자 / 사용자

**목표: PC의 고점 대비 표시·사용자 선택 정렬·직접 연결된 전달값이 현재 저장 종가와 실제 계산 기간을 사용하게 한다.**

## 1. 착수 근거와 범위

- POC5-24 종료 보고(`87a29bf2` · 2026-10-19)를 수용한다. POC5-23~24의 선택 근거 생성·세션 연결은 종료 상태로 유지한다. 설계자가 원격 저장소를 직접 확인한 것은 아니다.
- POC5-23 결과서 §4·§5에는 「요즘 잘 오르는 ETF」 카드 펼침·표, 「ETF 비교하기」 상세·정렬의 고점 대비가 폐기된 점수 스냅샷을 날짜 없이 사용하는 문제가 남아 있다. 당시 보고의 스냅샷 전체 가격 기준일은 2026-08-27이며 종목별로 더 이른 행도 있다. 이번에 이 관찰을 다음 실제 정정 대상으로 선정한다.
- 두 화면의 표시·수동 정렬·그 값을 이미 포함하는 복사문/새 AI 전달을 한 범위로 처리한다. 새 위험 지표 연구나 단순 문구 정리 단계로 나누지 않는다.
- POC5-23에서 제거한 「보유와 비교」의 고점 대비와 미리보기 항목은 다시 넣지 않는다. 이번에 해당 값을 제공하지 않던 보유·개별주까지 지원 범위를 넓히지 않는다.

## 2. 현재 관측값의 정의

이 값은 **'최근 20저장일 종가 고점 대비'**다. 고점·현재가 모두 같은 종목의 PC 저장 종가에서 읽는다.

| 항목 | 계약 |
|---|---|
| 기준일 D | 해당 종목의 실제 PC 저장 가격 기준일. 기존 PC 가격일 정의를 재사용하고 시장 전체 최신일·스냅샷 생성일로 대신하지 않는다. |
| 창 | D를 포함해 D 이하의 최근 원본 저장 가격 행 20개. '20개 종가'이며 20개 변화 구간을 만들기 위한 21행이 아니다. 달력 20일·공식 거래일 20일로 설명하지 않는다. |
| 고점 H | 그 20개 종가 중 최대값. 장중 고가가 아니다. |
| 값 | `(D의 종가 / H - 1) × 100`, 단위 %. 예: 고점 120·현재 종가 90이면 −25%. 고점과 같으면 0%. |
| 계산 불가 | 20행 미만·창 안 비정상 종가(양수·유한 조건 미충족)·기존 PC 가격 기준 연결 검사에서 확인된 경계는 값 없음과 사유로 둔다. 비정상 행을 빼고 더 오래된 행으로 창을 채우지 않는다. |

- 동일 고점 날짜가 여러 개면 가장 최근 날짜를 표시한다. 전달 정보에는 실제 기준일·창 시작/끝·고점 종가와 날짜·값/사유가 있어야 한다.
- 기존 가격 기준 연결 판정을 재사용한다. 단순한 source 라벨 변경만으로 새 경계를 발명하거나 전체 이력 조사를 하지 않는다. 현재 PC 비교 기준일과의 불일치는 기존 PC 날짜 안내를 따른다.
- 기간 중 최대 낙폭(MDD)·보유 손익률·미래 하락 확률·위험 등급과 구분한다. 설명은 기존 `?`에서 짧게 제공한다.
- 옛 ML `drawdown_20d`와 창 정의가 같다는 가정으로 값을 섞지 않는다. 새 PC 관측값은 선택 객체 하나로 구분하고, 과거 학습·연구 필드의 의미는 그대로 둔다.

## 3. 계산·표시·전달 연결

- PC 응답 조립 경로에서만 현재 관측값을 연결한다. 기존에 읽는 가격 이력을 우선 재사용하고 필요하면 제한된 저장 창 읽기를 허용한다. 새 수집·외부 조회·모델 실행·feature 적재·DB 표는 없다.
- 두 화면은 같은 관측 객체와 표시 helper를 사용한다. 종목별 계산 기간이 다르면 그 실제 기간을 보여 주며, 필요한 종목의 값이 없으면 과거 스냅샷 값으로 채우지 않는다.
- 기존 고점 대비 칸을 현재 관측값으로 교체한다. 이름은 '20저장일 종가 고점 대비'로 분명히 하고 기준일을 확인할 수 있게 한다. 같은 날짜가 반복되는 경우 기존 공통 기준일 표시를 재사용할 수 있다. 새 카드·별도 펼치기 버튼은 추가하지 않는다.
- 기존 고점 대비 사용자 정렬은 새 값으로 정렬한다. 정렬 방향은 기존 선택의 뜻을 보존하고 값 없음은 맨 뒤·동률은 기존 순서다. 기본 수익률 기준 후보 선정과 기본 정렬은 바꾸지 않는다. 수동 고점 정렬이 서버 조회 조건에 있다면 그 선택 경로만 이번 정의로 정정한다.
- 현재 복사문·AI 전달에서 이미 고점 대비를 싣는 곳은 같은 값·단위·기간을 사용한다. 새 선택 객체를 기존 JSON/선택 모델 안에 담을 수 있다. 현재값의 근거로 옛 ML 고점 필드를 끼워 넣지 않는다.
- 과거 AI 기록·스냅샷·연구 결과를 다시 쓰지 않는다. POC5-23~24의 원문은 재생성하거나 바꾸지 않는다. 고점 대비를 쓰지 않는 전달 경로에 새 항목을 추가할 필요도 없다.
- 숫자 표시는 기존 공통 % 표시 규칙을 재사용한다. 이번을 이유로 새 숫자 표시 체계·전역 리팩터를 만들지 않는다.

## 4. 개발자 PLAN과 목업

아래 사실만 현재 소스로 확인해 짧은 PLAN에 적는다.

1. 남은 두 화면의 고점 대비 원천·표시·수동 정렬·복사/AI 전달 소비처. 기존 ML 값의 창 정의와 이번 PC 관측값의 차이도 명시한다.
2. 계산·날짜·가격 기준 연결 helper 재사용 위치, 기존 읽기 재사용과 추가 읽기, 기존 호출 보존 방법 및 변경 파일.
3. 실제 ETF 한 개의 옛 스냅샷 값/날짜와 새 값/기간 대조, 자료 부족·기준일 불일치의 표시.

개발자가 두 화면 전체를 1440/1000px 목업으로 보여 준다. 기존 칸의 값·이름·날짜·도움말과 정렬이 보이면 충분하다. 사용자 목업 확인과 PLAN 판정 뒤 구현한다. 다른 백로그 전수 감사나 별도 리팩터 단계를 선행하지 않는다.

## 5. 수용 기준과 종료

- 실제 저장 종가로 고점·날짜·기간·비율이 재현되고, 두 화면·수동 정렬·해당 복사문/새 AI 전달에서 같은 뜻과 값을 사용한다.
- D를 포함한 20행, 고점 중복 날짜, 자료 부족·비정상 행·기존 가격 기준 경계·스냅샷 잔존의 대체 금지를 필요한 시험으로 확인한다. 기본 후보 선정과 관련 없는 기존 호출은 보존한다.
- 사용자 실화면·검증자 확인과 RESULT 판정 후 승인 범위에 따라 커밋·push한다. 이번에 확인한 같은 고점 원천의 소비처 정정은 이 단계 안에서 마무리한다.

OCI·PUSH·cron·운영 PARAM·ML·위험 분류는 변경하지 않는다. 거래일 대기·별도 인계 문서·미사용 POC5-16 파일 삭제 승인은 종료 조건이 아니다. STATE의 다음 줄은 이번 PLAN 기록과 함께 갱신한다.
