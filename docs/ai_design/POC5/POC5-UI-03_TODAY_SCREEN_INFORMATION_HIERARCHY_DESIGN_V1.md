## 3. 숨기면 안 되는 것
자료 부족·기준일 불일치·가격 비교에서 제외된 보유·갱신 실패는 일반 상세로 접어 숨기지 않는다.
기존 경고와 조치를 사용해 시장 또는 보유 영역 가까이에 항상 표시한다. 정상일 때 새 경고 카드를 만들지 않는다.
문제 건수와 이유는 펼침 전에도 보이고, 종목이 많으면 전체 목록만 펼쳐 본다.
자료가 서로 다른 기준일이면 각각 실제 날짜를 표시한다. 모든 값을 하나의 '최신 기준일'로 묶지 않는다.

기존 KOSPI 차트의 상태·자료 기준 표시를 유지한다. KODEX200 참고값을 KOSPI 지수 값이나 종합 위험 등급으로 바꾸지 않는다.
자료가 없을 때 0·정상값으로 대체하지 않는다. 접힌 영역에도 값 없음·과거 자료 규칙이 그대로 적용된다.

## 4. 상세의 위치와 기능 보존
- 시장 수치와 KODEX200 거래량은 같은 카드 아래에서 펼쳐 본다. 거래량을 보기 위해 다른 메뉴를 찾아야 하는 구조로 바꾸지 않는다.
- 종목의 전체 가격·거래량 근거는 기존 「확인 근거」 상세에서도 그대로 제공한다.
- 최대 3개의 선정·순서·기간·날짜 판정은 유지한다. 기본 화면에서 숨긴 손익률도 09의 정확한 종목 합산값이다.
- 기존 버튼의 목적지·동작을 유지한다. 종목을 전달하는 새 메뉴 연결은 만들지 않는다.
- 두 안내 카드는 화면 아래의 접힌 묶음 안에서 보존한다. 요구사항을 폐기하거나 기능을 삭제하는 결정이 아니다.
- 기존 정상 메시지·경고가 여러 위치에 있다면 같은 문제의 반복 표시만 정리한다. 서로 다른 사유는 합치거나 누락하지 않는다.
- 펼침 상태는 화면 안에서만 관리한다. 새 저장소·설정·DB를 만들지 않는다.

## 5. 전체 화면 목업을 먼저
개발자는 구현 전에 현재와 변경안을 같은 실제 폭으로 나란히 비교할 수 있게 준비한다.
1440px·1000px에서 사이드바부터 화면 아래까지 전체 구성을 보인다. 부분 카드만으로 확인을 대신하지 않는다.
자료는 같은 PC 응답을 사용하고 기준 시각을 적는다. 설계자의 개념 배치안은 이 실제 목업을 대신하지 않는다.

필수 화면은 정상 기본 상태와 상세 펼침 상태다.
자료 문제는 한 가지 대표 상태를 격리 fixture로 추가해 경고가 접히지 않음을 보여 준다. 라이브 자료를 바꾸지 않는다.
'위험 감지'처럼 새로 완성된 것처럼 보이는 상태·문구를 추가하지 않는다.
버튼은 기존 큰 48px / 중간 40px 규칙을 따른다. 긴 이름·필드 정렬·화면 전체 높이를 함께 확인한다.

순서: 개발자의 전체 화면 목업 + 짧은 PLAN → 사용자 화면 확인 → 설계자 PLAN 판정 → 구현.
사용자가 이미 동의한 절차이며, 이번에도 글만으로 화면 배치를 확정하지 않는다.
PLAN은 바뀌는 화면 파일·접기 구현·경고 보존·검사만 적는다. 백로그 전수 조사·수집 재검증은 반복하지 않는다.

## 6. 범위·검증·종료
이번 범위는 PC 화면 표시다. 기존 응답과 계산을 그대로 사용한다.
새 메뉴·API·백엔드 계산·DB·외부 조회·PUSH·OCI 변경은 필요하지 않다.
공용 표시 컴포넌트를 변경하면 기존 「확인 근거」 거래량 표시가 유지되는지만 함께 확인한다.

검증은 펼침 동작·경고 상시 노출·같은 실제 값 유지·기존 버튼 연결·두 실제 폭 정렬에 집중한다.
값 숨김을 값 삭제나 계산 제외로 구현하지 않는다. 변경에 맞는 화면 시험과 저장소 필수 검사를 진행한다.
화면 변경과 무관한 라이브 파일 전수 해시·OCI 거래일 확인은 새 종료 조건으로 추가하지 않는다.
검증 통과·사용자 실화면 확인 뒤 기존 승인에 따라 커밋·push하고 종료한다. OCI pull은 필요 없다.

### Q1 — 날짜 출처와 이름
선택한 응답은 069500의 유효 가격 행을 특정하며, PLAN 조사상 기준선 계산의 종목·행 조건과 같다.
기준선 값이 있을 때 그 날짜를 함께 표시한다. 0인 정상 값도 '값 있음'이다.
날짜가 없으면 '기준일 확인 불가'로 표시한다. `market_context.asof`나 KOSPI 날짜로 대신 채우지 않는다.
OPS-03의 '날짜는 판정 줄에만' 시험은 새 표시 계약에 맞춰 수정한다.

**추가 표시 정정:** 펼친 기존 시장 판정의 `market_context.asof`는 전체 가격 표 최신일이다.
현재의 'KODEX200 기준일' 이름은 유지하지 않는다.
UI-03에서는 해당 날짜 이름을 **'저장 가격 최신일'**, 짧은 설명을 **'저장된 전체 종목 기준'**으로 고친다.
이를 KODEX200 가격 날짜나 시장 판정의 실제 계산일로 설명하지 않는다. 응답 값과 backend 계산은 이번에 바꾸지 않는다.
이 문구 정정은 이번 판정으로 승인한다. 목업 전체 재제작·재확인 회차를 추가하지 않는다.

### Q2 — 기존 갱신 동작 유지
문제 0건일 때 기존 카드가 남는 것은 수용한다. 설계 표의 '문제가 있을 때'를 기존 카드 제거 지시로 적용하지 않는다.
'최신' 한 줄과 버튼의 기존 뜻을 유지하고 정상 메시지·상태 카드를 더 만들지 않는다.
이 표시가 모든 시장 자료의 최신성을 보증하는 문구로 확대되지 않게 한다.

### Q3 — 사유를 펼침 전에 표시
기존 자료 없음·부족·계산 불가 문구를 재사용한다. 서로 다른 사유를 하나로 뭉개지 않는다.
응답에 비교 기간 불일치 같은 구체적 사유가 있으면 기존 날짜 사유 표시를 재사용해 그 이유를 알린다.
'값이 비어 있음'만으로 위험 등급이나 하락 신호를 만들지 않는다.
펼친 뒤에도 같은 사유·기준일·값 상태가 유지돼야 한다.

### Q4 — 건수와 날짜는 계속 보임
접힌 상태에도 제외 이유·전체 종목 수·기준일별 종목 수를 보인다. 긴 줄은 줄바꿈한다.
건수는 종목 기준이며 같은 종목의 여러 계좌를 여러 종목으로 세지 않는다.
'모두 보기'로 전체 이름을 확인하고 다시 접을 수 있게 한다. 새로운 조회는 하지 않는다.
4종목 이상 fixture의 동작과 두 실제 폭 표시를 구현 검사에서 확인한다. 새 목업 승인 회차는 필요 없다.

## 4. 다음 작업 확정 — POC5-11
**PC 시장 자료 갱신 연결·기준일 정정**을 다음 기능 보완 단계로 확정한다.

3. 성공 시 기존 VIX 저장 자리·실제 자료 기준일을 확인하고, 실패 시 기존 갱신 결과에 한국어 사유를 남긴다.
4. PC 시장 판정의 날짜는 실제 사용한 KODEX200 자료에서 얻도록 정정한다.
   전체 표 최신일을 쓰는 공용 함수의 뜻을 무작정 바꾸지 않는다. 그 날짜가 계산 입력인지 표시 메타인지 먼저 특정한다.
5. 기존 자료원·기존 VIX 날짜 판정을 재사용한다. KODEX200과 날짜가 같아야 한다는 새 조건을 만들지 않는다.

PLAN은 함수 연결 위치·PC DB 경로·기록 부수 효과·시장 날짜 호출자·격리 시험만 조사한다.

개발 검증은 가짜 수집기와 격리 DB로 하고, 실제 수집은 사용자의 기존 갱신 버튼으로 확인한다.
