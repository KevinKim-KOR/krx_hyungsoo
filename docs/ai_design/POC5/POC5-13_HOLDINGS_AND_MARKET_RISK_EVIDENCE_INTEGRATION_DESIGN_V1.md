## 2. 목적과 완료 모습
사용자가 '시장이 약한데 내 보유에서는 어디를 먼저 살펴볼까'를 한 화면의 근거로 파악하게 한다.
현재 시장 국면과 보유의 기존 20일 하락 구간을 함께 보여 주고, 해당 종목의 합산 평가 비중을 보여 준다.
새 종합 위험 점수·등급·ML·매매 규칙은 만들지 않는다. P-06 전체 완료가 아닌 근거 통합 1차다.

완료 모습:
- 「오늘의 투자 점검」의 기존 보유 확인 영역에 짧은 요약 한 줄이 보인다.
- 「확인 근거」에서 시장 국면, 하락 구간별 종목 수·합산 비중, 자료 확인 필요를 함께 읽는다.
- 기존 보유 목록에서 하락 구간 해당 종목을 골라 상세 가격·거래량·계좌 근거를 확인한다.

요약 예시는 '시장: 기존 국면 / 20일 하락 구간 해당 N종목·보유 평가 비중 P% / 자료 확인 M종목'이다.
N·P·M은 실제 응답에서 계산한다. 시장이 그 종목의 하락 원인이라고 단정하지 않는다.

## 3. 기존 규칙과 관측 자료
보유 구간은 현재 확정된 보유 브리핑의 20일 하락 구간 정의·임계·이름을 재사용한다.
순수 구간 판정 함수·활성값을 확인해 PC의 유효한 20일 변화에 적용한다. 새 임계나 점수를 정하지 않는다.
PUSH 러너 전체를 호출하거나 운영 저장·발송 경로를 PC 조회에서 실행하지 않는다.

PC 가격 출처·실제 계산 기간·기준일을 표시한다. OCI 알림과의 출처·시점 차이를 숨기지 않는다.
PC 자료에 기존 구간 규칙을 적용할 수 없는 계약 차이가 있으면 PLAN에 그 차이만 질문한다.
기존 PC 5일·20일 변화·KODEX200 대비·보유 평가·시장 국면 계산은 바꾸지 않는다.
VIX·거래량은 현재의 상세 참고 역할을 유지한다. 새 위험 가중치나 분류 임계로 승격하지 않는다.
매입 손익률과 최근 가격 하락은 다른 값이다. 손익률을 하락 구간 입력으로 쓰지 않는다.

구간 판정은 자기 20일 값과 PC 가격 기준일이 유효할 때 한다.
기준일이 다른 종목·이력 부족은 '자료 확인 필요'로 분리한다.
자기 20일 값은 유효하고 비교 기간만 달라 KODEX200 대비가 비어 있는 경우에는 자기 하락 구간을 표시할 수 있다.
'하락 구간 미해당'을 '안전'으로 부르거나, 자료 없는 종목을 정상 구간에 넣지 않는다.

## 4. 종목 수와 평가 비중
동일 종목의 여러 계좌는 기존 종목 합산 규칙을 사용한다. 종목 수는 ticker 기준이다.
각 하락 구간의 비중은 해당 종목들의 합산 평가금액 / 전체 보유 평가금액이다.
최대 3개만 분모로 삼거나 계좌별 비중·손익률을 단순 평균하지 않는다.

평가 자료가 부분이면 전체 보유 비중으로 단정하지 않는다. 기존 결측 표시와 함께 '평가 확인 필요'를 알린다.
하락 관측 자료의 부족과 평가금액 부족은 구분한다. 둘 중 한쪽의 유효값까지 모두 숨기지 않는다.
'판정 가능 N / 전체 M'도 보여 자료 부족 상태의 0건이 '보유 위험 없음'처럼 읽히지 않게 한다.
가격 흐름의 기준일과 보유 평가의 기준이 다르면 각각 기존 기준 표시를 유지한다.

## 5. 화면 배치
「오늘의 투자 점검」:
- 기존 '오늘 내가 확인할 것' 안에 요약 한 줄만 둔다. 새 숫자 카드·차트를 늘리지 않는다.
- 기존 「확인 근거」 이동 버튼을 사용한다. 최대 3개의 선정·5일 정렬·표시값은 그대로다.

「확인 근거」:
- 목록 위에 기존 시장 국면과 구간별 종목 수·평가 비중, 관측 가능 범위를 간결하게 둔다.
- 기존 목록에 '전체 / 하락 구간 / 자료 확인' 보기 선택을 둔다. 목록·상세를 새 화면에 복제하지 않는다.
- 기본은 전체이며, 기존 사용자 선택 정렬을 유지한다. 선택·정렬은 받은 자료로 처리한다.
- 하락 구간과 기존 날짜 사유를 종목 이름 주변 또는 상세에서 보여 준다. 기존 표에 여러 숫자 열을 더하지 않는다.
- 거래량·VIX 등의 긴 참고값은 기존 상세·펼침을 사용한다.

ETF와 지원되는 보유 개별주를 함께 다루므로 이 기능의 용어는 '보유 종목'이다.
보유 중인 레버리지 ETF를 발견 화면의 필터 규칙으로 임의 제외하지 않는다.

## 6. 구현 경계
기존 PC 시장·보유·가격 흐름 응답을 조립한다. 필요한 작은 구간·집계 필드는 기존 GET에 선택 필드로 보완할 수 있다.
전체 ETF 재계산·재수집을 보유 요약 때문에 반복하지 않는다. 동일 응답의 값·날짜를 사용한다.
기존 시장 GET이 필요하면 현재 공유 읽기를 재사용하며, 펼침·보기 선택·정렬 때 새 조회를 하지 않는다.
새 API 경로·DB·원장 쓰기·외부 수집·OCI·PUSH·PARAM 변경은 없다. 개인 평가금액은 PC 표시 안에서만 사용한다.
새 책임은 별도 작은 조립·표시 함수로 두고, MarketDiscoveryView.tsx에는 추가하지 않는다.

## 7. PLAN과 목업
개발자는 다음 네 가지만 현재 코드에서 확인한다.
1. 기존 하락 구간 함수·임계의 실제 출처, PC 20일 값과의 단위·가격 의미 일치.
2. 종목 합산·전체 평가 분모·결측 규칙, 같은 응답의 날짜·값 전달 경계.
3. 두 화면의 기존 조회·조립·컴포넌트 연결. 전체 ETF 계산을 추가하지 않는 위치.
4. 정상·자료 부족·다중 계좌의 시험과 사용자 확인 방법.

실제 PC 자료로 현재와 변경 전체 화면을 1440·1000px에서 보여 준다. 자료 부족은 격리 fixture로 확인한다.
글만으로 배치를 확정하지 않는다. 목업은 개발자가 만들고, 사용자 확인 뒤 PLAN을 판정한다.
기존 백로그 전수 대조·완료 단계 재검증·별도 선제 Cleanup을 PLAN의 준비 조건으로 추가하지 않는다.
