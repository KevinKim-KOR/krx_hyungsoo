# POC5-22 — PC 후보와 KODEX200의 동일 기간 수익률 비교

작성: 설계자 · 2026-10-17 · 독자: 개발자 / 사용자 / 검증자
상태: 다음 범위 지정 · 개발자 짧은 PLAN과 전체 화면 목업 대기

## 1. 현재 위치와 목적

- 사용자 전달의 커밋 `05093286`·push 보고를 근거로 POC5-21 종료를 수용한다. 실제 저장소를 직접 조회한 확인은 아니다.
- 21에서 후보의 달력 30/90일 계산과 KODEX200의 20/60저장일 계산이 다르다는 사실과 실제 날짜가 드러났다. 이번에는 **후보가 사용한 바로 그 시작일·끝일의 KODEX200 가격**으로 비교한다.
- 사용자는 후보가 오른 정도와 같은 기간 시장 대표 ETF가 오른 정도의 차이를 확인할 수 있어야 한다. 서로 다른 기간의 차이에 이름만 붙이는 수준에서 실제 동일 기간 비교로 이어간다.
- 모델·위험 등급·자동 추천은 이번 목표가 아니다. POC5-20 연구 결론과 Q6 운영 계약은 유지한다.

## 2. 대상 — 같은 지표를 쓰는 PC 화면을 함께 처리

- 기존 후보의 **1개월·3개월 KODEX200 대비 칸**을 대상으로 한다. 「요즘 잘 오르는 ETF」 카드·표와 공통 AI 복사문을 정정한다.
- 「ETF 비교하기」와 「보유와 비교」에서 같은 후보 응답의 해당 지표를 재사용하는 표시도 함께 연결한다. PLAN에서 실제 이용 필드를 확인한다. 이름만 같은 별도 보유 계산까지 일괄 교체하지 않는다.
- 화면마다 독립 비교 공식을 두거나, 나머지 화면의 같은 지표를 작은 후속 단계로 나누지 않는다. 실제 다른 계산 계약이 발견되면 그 차이만 PLAN에 보고한다.
- 6개월·12개월·3년의 새로운 비교 항목, 새 메뉴·카드·순위·필터는 추가하지 않는다. 후보 수익률과 현행 선정·정렬은 유지한다. 단기 흐름 5/10/20구간의 별도 비교는 21의 날짜 표시 계약을 유지한다.

## 3. 계산 계약

각 후보·대상 기간에서 A·B는 기존 후보 수익률이 실제 사용한 두 가격 날짜다. 짧은 저장 이력도 그 실제 기간을 사용한다.

```text
후보 수익률(%) = 100 × (후보 종가 B / 후보 종가 A − 1)
KODEX200 수익률(%) = 100 × (069500 종가 B / 069500 종가 A − 1)
동일 기간 차이(%p) = 후보 수익률(%) − KODEX200 수익률(%)
```

- 후보 수익률은 기존 계산값과 단위를 확인해 재사용한다. 이미 반올림한 화면 문자열끼리 빼지 않는다. 예: 후보 +10%, KODEX200 +5%면 차이는 +5%p다. 수익률 비율을 다시 나누는 산식으로 바꾸지 않는다.
- KODEX200은 **A·B와 정확히 같은 날짜의 유효한 양수 종가**를 사용한다. 전후 날짜·최근 날짜·보간 가격으로 대신하지 않는다. 후보마다 실제 A·B가 다르면 비교할 KODEX200 기간도 달라진다.
- 후보 실제 기간 없음, 필요한 KODEX200 날짜·가격 없음은 계산 불가 사유로 구분한다. 결측을 0이나 기존 다른 기간 차이로 채우지 않는다. 후보 자체 수익률까지 숨길 필요는 없다.
- 기존 정보로 가격 기준 연결을 확인할 수 없는 경우의 처리는 기존 PC 가격 기준 규칙을 재사용해 PLAN에 명시한다. 새 단절 임계·자료원 전환 규칙·가격 이력 복구 연구는 만들지 않는다.
- 이 값은 PC 저장 종가의 같은 기간 비교다. 배당 포함 총수익률·개인 손익·성과 우위의 지속 가능성을 보증하는 지표로 설명하지 않는다.

## 4. 전달·저장 경계

- PC 시장 응답의 후보별 선택 필드에 1개월·3개월 각각 실제 A·B, 후보 수익률, KODEX200 수익률, 차이(%p), 계산 상태·사유를 함께 전달한다. 필드명·단위는 PLAN에서 고정한다.
- **기존 다른 기간 차이 필드와 `basis_*` 의미·값은 보존**한다. 이번 PC 표시·복사문은 새 동일 기간 필드를 명시적으로 사용한다. 새 필드가 없는 과거 응답을 기존 차이 값으로 조용히 대체하지 않는다.
- PC 화면 API의 선택 경계에서만 새 값을 만든다. 이미 읽은 KODEX200 시계열을 한 번 정리해 재사용하고, 후보마다 KODEX200을 다시 조회하지 않는다. 추가 SELECT·외부 조회·API 경로·DB 표·의존성은 필요 없다.
- 기본 운영 호출은 기존 출력·계산·조회 횟수를 유지한다. PC 전용 helper가 연구 모듈에 의존한다면 비활성 운영 경로에서 그 모듈을 새 필수 import로 만들지 않는다. 별도 운영 리팩터 단계는 열지 않는다.
- 새로 만드는 AI 전달 자료에는 화면에서 사용한 동일 기간 비교 객체를 기존 `candidate_snapshot`의 선택 필드로 함께 저장한다. 질문 본문과 구조화 자료의 날짜·수치가 일치해야 한다. 기존 키·값·과거 기록은 그대로 두며 새 표·마이그레이션·원장 기록은 만들지 않는다.
- 과거 AI 기록에 새 객체가 없으면 당시 자료에 없었다고 처리한다. 현재 시세로 과거 기록의 비교값을 다시 계산하지 않는다. 보유 수량·평단·개인 손익은 새 비교 객체에 넣지 않는다.

## 5. 화면·복사문

- 기존 KODEX200 대비 두 칸을 **'동일 기간 KODEX200 대비'** 값으로 교체한다. 기존 다른 기간 차이와 새 값을 나란히 늘어놓지 않는다. 요청 기간과 실제 사용 기간의 구분은 21의 표시를 재사용한다.
- 차이(%p)를 기본으로 보이고, 기존 클릭형 ?에서 실제 기간·후보 수익률·KODEX200 수익률·뺄셈 의미를 확인하게 한다. 기본 화면의 숫자·긴 안내가 늘지 않도록 기존 자리를 활용한다.
- 계산 불가이면 해당 칸에 짧은 사유를 보인다. 자료 부족을 시장 대비 열위나 위험 경고로 표현하지 않는다. 기존 상승·하락 색상 계약을 사용한다.
- 공통 복사문은 동일 기간, 양쪽 수익률과 차이(%p)를 함께 적는다. 세 화면의 같은 후보·같은 기간은 같은 객체와 표시 helper를 사용한다. 이전 '기간 다른 수익률 차이' 설명을 새 동일 기간 값에 남기지 않는다.
- 값의 의미는 '그 저장 가격 기간에 KODEX200보다 몇 %p 높거나 낮았는가'다. 이를 매수·매도 의견·새 위험 순위로 변환하지 않는다.

## 6. PLAN·목업·검사와 완료

1. 짧은 PLAN에 세 화면의 실제 데이터 이용처, 후보 A·B·수익률 단위, 이미 읽는 KODEX200 시계열의 범위, 가격 기준 확인 재사용, 선택 필드·AI JSON 전달 방식을 적는다. 실제 코드 차이와 권장안만 질문한다. 별도 전수 감사는 필요 없다.
2. 개발자가 영향받는 기존 화면의 1440px·1000px 전체 목업을 만든다. 정상, 짧은 후보 이력, 후보와 KODEX200의 최신일 차이·필요 날짜 없음 사례를 포함한다. 실제 없는 상태는 격리 fixture로 표시한다. 사용자 목업 확인 뒤 PLAN 판정을 거쳐 구현한다.
3. 알려진 두 가격의 계산 예, 실제 A·B 선택, 짧은 이력, 정확한 날짜 결측·유효하지 않은 가격, 과거 응답에 새 필드 없음, 가격 기준 확인 불가를 시험한다. 화면·복사문·새 AI 스냅샷의 일치와 기존 호출·수익률·순위·조회 횟수 불변도 확인한다. 변경 범위 검사와 backend·frontend 회귀·타입·린트를 수행한다.
4. 사용자 실화면·검증자 확인 뒤 RESULT 판정을 요청한다. 이번에는 실제 동일 기간 비교가 제공된 범위와 여전히 남는 운영·자료원 한계를 구분해 종료 기록한다. OCI·PUSH·PARAM·cron 변경이나 거래일 대기는 필요 없다.
