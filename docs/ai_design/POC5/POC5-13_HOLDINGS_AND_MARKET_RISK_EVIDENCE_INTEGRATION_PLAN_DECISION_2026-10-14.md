# POC5-13 보유·시장 위험 근거 통합 — PLAN 판정
작성일: 2026-10-14
독자: 개발자 · 사용자
판정: CONDITIONAL_PASS — 아래 보충 반영과 사용자 수정 목업 확인 뒤 구현

## 1. 판정 범위
- 제출된 POC5-13 DESIGN V1과 PLAN V1을 대조한 문서 판정이다. 저장소 코드·OCI를 직접 검증한 판정은 아니다.
- 맥북의 `file:///private/tmp/...` 목업은 이 환경에서 직접 열어보지 못했다. 화면 확인 완료로 기록하지 않는다.
- 기존 시장 국면과 보유 하락 구간을 PC 화면에 모아 보여 주는 범위를 승인한다.
- 종합 위험 감지의 새 등급·가중치·매매 지시를 만드는 단계가 아니다. 해당 미구현 요구는 계속 열린 항목이다.

## 2. 질문 판정
| 질문 | 결정 | 반영할 내용 |
|---|---|---|
| Q1 가격 계열과 구간 이름 | (b) PC용 표시 이름 | 저장 가격·저장일 계산이라는 뜻을 이름에 반영 |
| Q2 KODEX200과 다른 20일 시작일 | (b) 자기 값으로 판정 | 자기 하락 구간과 상대 비교 가능 여부를 분리 |

### Q1. 이름과 가격 의미
- 요약 이름은 **“PC 최근 20저장일 하락 구간”**으로 한다.
- 종목 배지는 “PC 20저장일 하락 10% 이상 / 8~10% / 5~8%”로 통일한다.
- “저장일”은 기존 PC 계산의 유효 종가 21개로 얻은 20구간을 뜻한다. 거래일 캘린더로 다시 계산하지 않는다.
- 기존 `normalize_pct`와 `classify_decline`, 수치 경계와 상태 코드는 재사용한다.
- PC 표시 이름은 PC 응답·화면에서 따로 정한다. 공유 `DECLINE_STATE_LABEL`과 OCI 알림 이름은 바꾸지 않는다.
- 요약 근처에 “PC 저장 종가 기준 · OCI 알림과 값이 다를 수 있음”을 늘 표시한다.
- 상세에는 실제 시작일·종료일과 판정에 사용한 소수 1자리 변화를 보여 준다.
- 도움말에 기존 판정이 소수 1자리 반올림 후 적용됨을 설명한다. 기존 5일·20일 수치 표시 자릿수는 그대로 둔다.
- 이 판정은 설계서의 PC 구간 표시 이름을 보충하는 개정이다. 가격 수집·보정 계열 변경은 포함하지 않는다.

### Q2. 자기 구간과 상대 비교
- PLAN의 추가 조건 `start_date_20d == KODEX200 start_date_20d`는 제거한다.
- 자기 20저장일 변화가 유효하고 종료일 등 기존 PC 가격 기준 검사를 통과하면 하락 구간을 판정한다.
- 시작일이 KODEX200과 다르면 상대 비교 값은 기존 규칙대로 비우고, 실제 날짜 사유를 유지한다.
- 자기 구간은 유효하지만 상대 비교는 불가능한 종목은 “하락 구간”과 “자료 확인 필요” 보기에 함께 들어갈 수 있다.
- 종료일 불일치·자기 이력 부족·유효하지 않은 숫자는 판정 불가이다. 이를 하락 구간 아님으로 바꾸지 않는다.
- 계좌별 평단·손익 차이는 정상이다. 구간 판정을 막을 충돌은 가격 흐름·계산 날짜에 관한 충돌이다.
- 서로 다른 시작일을 모두 동일한 달력 기간처럼 설명하지 않는다. 상세의 실제 기간으로 확인하게 한다.
- 실제 자료에 시작일 불일치가 없다는 제출 보고에 따르면 이 변경만으로 실제 18/29종목 수는 바뀌지 않는다.
- 불일치 fixture의 판정 가능 수·구간 수·비중은 새 규칙으로 다시 계산한다. 기존 목업 수치를 그대로 옮기지 않는다.

### Q3. 오늘 화면과 판정 가능 수
- 오늘 화면은 기존 시장 국면 · PC 하락 구간 종목 수와 평가 비중 · “구간 판정 가능 a/b종목” 순서로 둔다.
- a와 b는 종목 기준이며 여러 계좌의 같은 종목을 중복 세지 않는다.
- a/b는 하락 구간 계산 가능 여부만 뜻한다. 현재가·평가금액·상대 비교가 모두 정상이라는 뜻으로 쓰지 않는다.
- 기존 “자료 확인 필요” 건수와 사유는 유지한다. 새 판정 불가 사유도 상세에서 확인할 수 있게 한다.
- 하락 구간에 들지 않은 종목에 “안전” 배지를 붙이지 않는다.

## 3. 평가 비중과 날짜의 보충
- 분자·분모는 모두 정상 `GET /holdings/enriched` 응답과 기존 종목 합산 함수로 계산한다.
- `market-evidence` 응답의 잘못된 평가금액·평가손익은 이번 비중 계산에 사용하지 않는다.
- 같은 종목의 일부 계좌만 평가금액이 확인되면 종목 합산값이 있어도 부분 자료 상태이다.
- 확인된 금액으로 비중을 내는 경우 “확인된 평가금액 기준 · 일부 평가 자료 미확인”을 표시한다.
- 평가금액이 전부 없거나 분모가 0이면 비중을 “확인 불가”로 둔다. 0%·100%로 채우지 않는다.
- 구간별 비중과 전체 하락 비중은 각각 원금액으로 계산한 뒤 표시 반올림한다. 표시값 합의 반올림 차이를 억지로 맞추지 않는다.
- `price_basis.reference_date`는 **“PC 가격 흐름 기준일”**이다. 이를 시장 국면 계산에 실제 사용한 날짜라고 단정하지 않는다.
- 시장 국면 입력 날짜가 기존 응답에 있으면 그 날짜를 따로 쓴다. 전체 시세 표 최신일로 대체하지 않는다.
- 이 표시를 위해 시장 전체 요청·계산을 추가하지 않는다.

## 4. Q4 후속 수정 — 지금 착수할 일
- 동일 종목 마지막 줄 평가값이 여러 계좌 줄에 복사되는 문제는 별도 결함으로 등록한다.
- 결함 식별자는 기존 번호가 있으면 재사용하고, 없으면 `DEF-HOLDINGS-EVIDENCE-MULTIROW-VALUATION`으로 둔다.
- 다음 수정은 **POC5-14 동일 종목·여러 계좌 평가값 정정**의 짧은 PLAN으로 준비한다. 이번 13과 별도로 조사할 수 있다.
- 조사 범위는 덮어쓰는 매핑 위치, 기존 행 구분 방법, 해당 값이 쓰이는 출력·선정·합산 지점이다.
- 공유 호출 경로가 있다는 사실과 Telegram 본문·초안에 잘못된 값이 실제 실리는지는 구분해서 보고한다.
- 수량·평단이 다른 두 계좌 fixture로 잘못된 행별 값과 의도한 행별·종목 합산 값을 재현한다.
- 기존 행 식별 정보와 순서 계약부터 확인한다. 이 정정만을 위해 새 ID·DB 구조를 만들지 않는다.
- 이 단계에서는 조사·PLAN까지만 진행한다. 공유 계산 수정과 필요한 배포 범위는 그 PLAN에서 판정한다.
- POC5-13의 공유 builder·PUSH 변경 금지는 유지한다. 추정만으로 운영 발송을 중단하지 않는다.
- POC5-13 시험은 두 응답의 평가금액이 일부러 다르게 주어진 경우에도 새 비중이 정상 enriched 응답과 일치함을 확인한다.

## 5. 구현·검증 순서
1. 개발자가 본 판정을 PLAN 보충에 기록하고 목업의 이름·기간 불일치 사례·판정 가능 수를 고친다.
2. 사용자가 두 화면의 수정 목업을 확인한다. 기존 1440px·1000px 전체 화면 방식은 유지한다.
3. 확인 기록 뒤 POC5-13 구현을 시작한다. 지정된 보충만 반영했다면 설계자에게 PLAN을 다시 제출하지 않는다.
4. 기존 시험에 반올림 경계·기간 불일치·판정 불가·복수 계좌 부분 평가·잘못된 응답과의 독립성을 포함한다.
5. 공유 builder 결과·PUSH·보유 저장 불변을 확인하고 검증자 검증 및 RESULT 판정을 받는다.

새 DB·메뉴·외부 조회·cron·의존성·OCI 배포를 추가하지 않는다.
기존 두 조회와 PC 응답 조립·화면 통합 범위로 진행한다.
