### Q1 — 같은 계산 이력에서 날짜를 얻는다
이미 읽은 유효한 069500 이력의 마지막 날짜를 PC 시장 판정에 전달한다.
국면·지속일·기준선에 사용한 이력과 같은 읽기여야 한다. 새 날짜 조회를 추가하지 않는다.
이력이 없으면 날짜는 None이다. 전체 가격 최신일이나 다른 종목 날짜로 대신 채우지 않는다.

제안한 기본 False의 키워드 인자와 PC GET /market/topn/latest에서만 True를 넘기는 경계를 승인한다.
최상위 asof·후보 기간 계산·공용 _latest_date_in_db의 뜻·다른 호출자의 출력은 유지한다.
오늘 화면의 '저장 가격 최신일(저장된 전체 종목 기준)'은 이 단계에서 'KODEX200 기준일 D'로 고친다.
이 문구 변경에 새 전체 화면 목업 승인 회차는 필요 없다.

### Q2 — VIX 조회 대기만 제한한다
기존 fdr_request_timeout()을 VIX 호출 경계에서 재사용한다.
20초는 기존 도구가 제한하는 조회 대기 범위다. 전체 갱신이 20초 안에 끝난다고 표시하지 않는다.
결과서에는 실제로 어느 요청 대기를 제한하는지 명시한다.
사용자의 갱신 횟수·실행 시간대·재시도 가능 여부에 제한을 추가하지 않는다.

PC 갱신 worker에서 해당 도구가 작동하는지, 정상·예외·timeout 뒤 설정이 복원되는지 확인한다.
다른 수집 단계의 timeout 설정을 함께 바꾸거나 새 watchdog·작업 관리 체계를 만들지 않는다.
VIX 예외·timeout은 한국어 사유로 남기고 NAV 단계와 작업 종료 처리를 계속한다.
실패 뒤 running에 남아 다음 수동 갱신이 막히지 않아야 한다. 이미 성공한 단계의 저장 결과도 유지한다.

### Q3 — 기존 기록으로 충분하다
화면에는 '시장 불안 지표(VIX)를 갱신하지 못했습니다'를 기존 완료 사유 뒤에 붙인다.
서버 로그에는 반환 status·exit_code·error·실제 as_of_date 중 있는 값을 기록한다.
error가 없다고 실패가 사라진 것으로 처리하지 않는다.
새 market_refresh_log 행·상태 파일은 만들지 않는다. 마지막 전체 갱신 조회의 뜻을 유지한다.

### Q4 — 수집 결과와 최신성 판정을 구분한다
조회가 성공했는데 기존 날짜 비교에서 경고가 남는 경우를 수집 실패로 다시 분류하지 않는다.
실제 VIX 저장 날짜·KODEX200 날짜·수집 status·경고 잔류 여부를 함께 기록한다.
날짜를 맞추려고 VIX 기준일을 앞당기거나 자동 재시도를 반복하지 않는다.
이번에 새 해외 거래일 달력이나 '두 지표 날짜가 같아야 정상'이라는 추가 규칙을 만들지 않는다.

정상 수집 뒤에도 경고가 남으면 기존 최신성 판정의 한계로 명시한다.
PC 수집 연결 누락의 해소와 경고 판정의 해소는 나눠 기록한다. PC 시장 자료 전체가 최신이라고 보고하지 않는다.

## 3. PLAN의 추정 두 가지 처리
- 진행 중인 세션 자료가 영구 고정될 수 있다는 §5의 추정은 확인 없이 수용한 한계가 아니다.
  조회 끝 날짜와 증분·추가 전용 저장 경로를 한 번 대조하고 관련 fixture로 실제 가능성을 확인한다.
  실제 가능하면 PC 호출의 조회 범위에서 미확정 자료를 제외하는 최소 보완을 한다. 수동 갱신 시간대를 막지 않는다.
  공유 기본 동작 변경이나 새 달력이 필요하면 그 충돌만 보고하고 나머지 구현은 계속한다.
- 후보 basis_end_date·OCI 근거 날짜 문제는 별도 관찰 항목으로 기록한다.
  이번에 바꾸지 않은 경로를 검증 완료·해소로 처리하지 않는다. 같은 내용을 백로그에 중복 등록하지 않는다.

## 4. 검증과 종료
제출 PLAN의 격리 시험을 진행한다. 서비스 기본 stub이 새 VIX 경계 시험까지 가리지 않도록 한다.
- 성공·이미 최신·기존 날짜 충돌·조회 예외·timeout에서 저장·사유·작업 종료를 확인한다.
- PC DB 경로 전달과 기존 갱신 기록 보존, 실패 뒤 다음 실행 가능 여부를 확인한다.
- KODEX200 유효 끝 D1, 전체 최신 D2인 경우 PC 판정은 D1, 최상위·후보 계산과 기존 호출자는 D2임을 확인한다.
- 069500 이력이 없을 때 날짜 대체 없음, 국면·지속일·기준선 값 보존, 화면 이름 변경을 확인한다.

외부 조회 없는 fixture와 가짜 수집기로 검사한다. timeout 시험 때문에 실제 20초를 기다릴 필요는 없다.
변경 범위·저장소 필수 검사를 한 차례 완료하고, 통과 뒤 근거 없이 반복하지 않는다.
실제 확인은 사용자의 기존 갱신 버튼 1회다. VIX 행·실제 기준일·완료 사유·시장 판정 날짜를 읽기 전용으로 확인한다.
결함 두 건은 이 확인 뒤 닫되, 남은 최신성 한계는 별도로 남긴다. OCI pull·첫 거래일 대기를 새 조건으로 추가하지 않는다.
