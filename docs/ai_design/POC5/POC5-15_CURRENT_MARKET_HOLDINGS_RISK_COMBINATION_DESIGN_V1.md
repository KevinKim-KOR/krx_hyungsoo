## 1. 현재 위치와 다음 목적
- 사용자 보고의 종료 커밋 `e1bb9839`를 근거로 POC5-13·14 종료를 수용한다. git·PC를 설계자가 직접 조회한 것은 아니다.
- 13이 시장 국면·하락 구간 수·비중을 연결했다면, 이번에는 그 조합을 현재 상태 문장으로 분류한다.
- 목적은 사용자가 시장과 보유의 약세가 함께 나타나는지, 어느 쪽에서만 확인되는지 바로 읽는 것이다.
- 현재 구현된 숫자를 다시 조립할 책임을 사용자에게 남기지 않되, 미래 손실 예측이나 검증되지 않은 위험 강도를 만들어 붙이지 않는다.
- 「오늘의 투자 점검」 기존 보유 요약 띠와 「확인 근거」 기존 요약에 반영한다.
- 확인 가능한 기준 문서는 ASSUMPTIONS Q6·PROJECT_ORIGIN_INTENT §9.5(전달본 2026-10-02), 13·14 RESULT 및 기존 판정이다. 이후 사용자 결정은 현재 기록을 우선한다.
- 개발자는 저장소의 현행 기반 문서와 아래 계약을 좁게 대조한다. 최신 코드를 직접 보지 않은 설계자의 함수·코드 이름 추정을 구현 근거로 삼지 않는다.

## 2. 이 단계의 분류 계약
- factor 1 = 기존 시장 국면이 하락 국면인가.
- factor 2 = 기존 PC 하락 구간에 해당하는 보유 종목이 하나 이상 확인되는가.
- 시장 계산식과 하락 구간의 −5·−8·−10 경계·반올림·기간은 기존 계약 그대로다.
- “하나 이상”은 기존 하락 구간의 존재를 요약하는 조건이다. 종목 수·비중으로 새 위험 임계를 만들지 않는다.
- 거래량·VIX·매입 손익률을 새 가중치나 분류 입력으로 넣지 않는다.
- 분류는 PC 저장 자료의 현재 조합이다. 시장 국면이 종목 하락의 원인이라는 뜻도, 이후 손실 확률도 아니다.

## 3. 입력 상태 정의
| 입력 | 상태 | 조건 |
|---|---|---|
| 시장 M | 하락 | 기존 판정의 유효한 하락 국면 코드 |
| 시장 M | 하락 아님 | 기존 판정의 유효한 다른 국면 코드 |
| 시장 M | 미확인 | 사용 가능한 판정 입력 없음·해석할 수 없는 코드 |
| 보유 H | 하락 있음 | 기존 decline_band에서 구간 해당 종목 N > 0 |
| 보유 H | 하락 없음 | 보유 B > 0 · 판정 가능 A = B · N = 0 |
| 보유 H | 미확인 | 사용 가능한 보유 입력 없음 또는 N = 0인 상태에서 A < B |
| 보유 H | 대상 없음 | 정상 보유 응답으로 빈 보유임이 확인된 경우 |

- M의 유효 코드 목록은 현재 시장 판정 함수의 계약을 재사용한다. 화면의 한국어 문구를 역으로 해석하지 않는다.
- 알 수 없는 코드는 “하락 아님”으로 처리하지 않는다. 자료 최신성 안내는 기존 기준을 유지한다.
- N > 0이면 일부 종목 판정 불가가 있어도 확인된 하락 존재를 유지한다. “일부 종목 판정 불가”와 a/b를 함께 보여 준다.
- 응답 실패와 실제 빈 보유를 구분한다. 실패를 빈 목록으로 바꾸어 정상 상태를 만들지 않는다.
- 재조회 실패 시 기존 유효 응답과 화면을 유지하는 12의 정책은 유지한다. 남아 있는 유효 자료로 분류하되 기존 실패 안내·기준 표시를 유지하고, 사용할 자료 자체가 없을 때 미확인으로 둔다.
- 평가금액 부족은 비중 계산의 문제이다. 유효한 가격 하락 분류까지 없애지 않는다.
- 같은 종목의 여러 계좌는 기존 종목 합산·흐름 충돌 처리대로 센다.

## 4. 출력 문구 — 운영 표시 후보
| 시장 M | 보유 H | 현재 조합 문구 |
|---|---|---|
| 하락 | 하락 있음 | **시장·보유 동반 약세** |
| 하락 아님 | 하락 있음 | **보유 하락 구간 확인** |
| 하락 | 하락 없음 | **시장 하락 · 보유 하락 구간 미해당** |
| 하락 아님 | 하락 없음 | **현재 기준 하락 신호 미해당** |
| 미확인 | 하락 있음 | **보유 하락 구간 확인 · 시장 판정 불가** |
| 하락 | 미확인 | **시장 하락 · 보유 판정 불완전** |
| 하락 아님 / 미확인 | 미확인 | **자료 확인 필요** |
| 미확인 | 하락 없음 | **보유 하락 구간 미해당 · 시장 판정 불가** |
| 모든 시장 상태 | 대상 없음 | **보유 판정 대상 없음** |

- 시장 하락 아님을 상승장·정상 시장·안전이라고 바꾸지 않는다.
- “미해당”은 현재 기존 기준에 걸리지 않았다는 뜻이다. 위험이 없다는 뜻으로 쓰지 않는다.
- 각 문구의 근거는 이미 있는 시장 국면, N종목, 비중, A/B와 실제 기간이다.
- 일부 종목 판정 불가가 있는 “하락 있음” 조합은 부분 확인임을 알린다. 관측된 사실을 숨기거나 완전 판정처럼 쓰지 않는다.
- 문구와 의미는 전체 화면 목업에서 사용자에게 함께 확인받는다. 위험도 높음·중간·낮음 또는 매수·매도 의견을 덧붙이지 않는다.

## 5. 화면 적용
- 오늘 보유 띠의 **기존 첫 줄**에 현재 조합 문구와 기존 시장 국면을 넣는다. 하락 종목·비중 및 판정 가능 수의 두 줄은 유지한다.
- 새 카드·네 번째 상시 요약 줄·새 숫자 열을 늘리지 않는다. 긴 문구의 실제 폭 줄바꿈은 목업으로 확인한다.
- 「확인 근거」 기존 요약의 시장 줄에도 같은 조합 문구를 사용한다. 기존 구간별 수·비중·가격 기준일·상시 안내를 유지한다.
- 두 화면은 같은 조합 함수를 사용한다. 판정·근거 설명이 화면마다 다르게 나오지 않는다.
- 파란 배지와 기존 색상 관례를 유지한다. “안전”을 뜻하는 초록 상태 배지를 새로 만들지 않는다.
- 보기·정렬·최대 3개 선정·상세·목적지는 유지한다. 상태 문구를 보고 사용자가 기존 하락 구간 보기를 선택한다.
- 「현재 제공 범위와 남은 기능」은 기존 “부분 제공”을 유지한다. 완료 범위는 RESULT에서 정확히 갱신한다.

## 6. 구현 경계와 기반 문서
- 기존 시장·보유·decline_band·평가 합산 응답과 요청 성공 여부로 PC에서 순수 조합한다.
- 기존 summary 조립 책임에 작은 함수를 추가하거나 필요한 작은 보조 파일로 나눈다. 대형 시장 발굴 화면에 책임을 추가하지 않는다.
- 새 조회·API 경로·DB·원장 기록·외부 수집·의존성·PUSH·PARAM·OCI 변경은 없다.
- 기존 데이터 문제를 분류를 위해 자동 갱신·보정하지 않는다. 부족 상태는 위 표로 전달한다.
- ASSUMPTIONS Q6에는 **PC 현재 상태 조합 룰의 운영 표시 후보**로 기록한다. PLAN·목업 확인 전 운영 확정 또는 Q6 ANSWERED로 바꾸지 않는다.
- 사용자 목업 확인과 PLAN 판정 때 이 한정 표시 계약의 확정 범위를 기록한다.
- 새 factor나 위험 강도의 타당성 검증·ML 분류는 별도 판단이다. 이번 조합 표시로 전체 종합 위험 요구를 모두 충족했다고 기록하지 않는다.

## 7. PLAN에서 확인할 것 — 한 번만
1. 시장 국면 실제 유효 코드와 하락 코드, 기존 자료 상태가 전달되는 위치.
2. 두 화면의 요청 성공·실패와 실제 빈 보유를 구분할 수 있는 기존 상태.
3. 13의 N·A/B·비중·부분 판정 근거를 중복 계산 없이 재사용하는 위치.
4. 기존 띠·요약 조립과 관련 파일 크기, 변경 위치와 필요한 시험.
5. 저장소 현행 Q6·운영 경계와 차이가 있으면 정확한 차이와 권장안을 PLAN에 적는다.

- 실제 PC 자료의 현재·변경 전체 화면을 1440px·1000px에서 보여 준다. 목업은 개발자가 만든다.
- 시장만 약세·보유만 약세·미해당·자료 일부/전부 부족·빈 보유는 격리 fixture로 확인한다.
- PLAN은 짧게 작성한다. 기존 백로그 전수 조사나 종료된 단계 전체 재검증을 준비 조건으로 추가하지 않는다.
- 사용자 목업 확인 → 설계자 PLAN 판정 → 구현 순서로 진행한다. 이 파일을 받았다고 곧바로 코딩하지 않는다.

## 8. 검증·종료
- 표의 모든 조합, 부분 판정, 빈 보유와 요청 실패, 알 수 없는 시장 코드, 평가 부족을 시험한다.
- 미해당·자료 부족을 안전으로 오인하지 않는 문구와 기존 구간 함수·선정·비중 불변을 확인한다.
- 두 화면에서 동일 입력의 문구가 같고 추가 조회·쓰기·발송이 없는지 확인한다.

- PC 반영으로 종료하며 OCI pull·첫 영업일 대기를 조건으로 추가하지 않는다.
- 종료 기록은 기존 RESULT·STATE·PROGRAM_TRUTH·BACKLOG·통합지도에 남긴다. 별도 인계 문서는 이번 단계의 필수 산출물이 아니다.
