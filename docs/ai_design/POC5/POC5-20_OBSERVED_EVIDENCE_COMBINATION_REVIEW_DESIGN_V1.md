# POC5-20 — 가격·거래량·변동성 근거 조합의 과거 사례 대조

작성: 설계자 · 2026-10-17 · 독자: 개발자 / 사용자 / 검증자
상태: 다음 범위 지정 · 짧은 PLAN 제출 뒤 구현

## 1. 종료 수용과 다음 목표

- 사용자 전달의 커밋 `c5dd13e8`·push 보고를 근거로 POC5-UI-04 종료를 수용한다. 저장소를 직접 조회한 확인은 아니다.
- POC5-19에서 가격 흐름·거래량·가격 흔들림을 함께 보여 주는 배치는 구현됐다. 남은 질문은 **같은 가격 하락 구간 안에서 거래량과 변동성의 차이가 이후 가격 경로의 차이와 함께 나타났는가**이다.
- 통합지도 P-06·ASSUMPTIONS Q6의 factor 타당성 검토와 P-10의 거래량 해석에 필요한 근거를 한 번 대조한다. 기능 수를 늘리는 대신 기존 관측값의 쓸모를 확인한다.
- 결과물은 PC 저장 자료로 만든 짧은 대조 리포트다. 예를 들어 같은 5~8% 하락 구간에서 네 조합의 이후 20일 경로가 어떻게 달랐는지 숫자로 확인한다. 어느 조합이 더 위험하다는 결론을 미리 정하지 않는다.

## 2. 이번 범위

- PC에서 개발자가 수동 실행하는 분석 명령 하나와 필요한 작은 계산 모듈을 만든다. 새 메뉴·화면·API·DB 표·자동 실행은 필요 없다. 사용자 매일 평가나 추가 입력도 없다.
- 입력은 현재 보유 ETF 목록, 기존 PC 저장 종가·거래량, 기존 2026년 거래일 캘린더다. 계좌가 여러 개여도 같은 종목은 한 번만 쓴다. 보유 중인 레버리지·인버스를 임의로 빼지 않는다. 개별주는 이번 분석 대상 밖의 건수로 남긴다.
- 분석 기준일 범위는 2026-02-19부터 명시한 `--end YYYY-MM-DD`까지다. 실제 거래량 저장 시작과 계산 가능한 범위는 PLAN에서 확인한다. 과거 계산 창은 시작일 이전의 기존 자료를 읽을 수 있다. 입력·이후 결과 모두 `--end` 뒤의 가격은 쓰지 않고, 아직 끝나지 않은 20일 경로는 미도래로 둔다.
- 운영 원장과 다른 **현재 보유 ETF의 저장 가격 재계산 표본**이다. 과거 실제 보유·과거 알림·당시 전체 ETF 시장을 복원했다고 설명하지 않는다. 현재 보유 선택의 편향과 저장 자료의 사후 수정 가능성을 리포트에 적는다. 상품 구조·종목 구성이 다른 영향을 조합의 효과로 단정하지 않는다.
- POC4-02B의 종료된 사건 정의·조기경보 실험과 POC4-03 모델 비교는 재실행하지 않는다. 이번에는 학습·예측·최적화·매매 전략 수익률을 계산하지 않는다. 운영 모델 없음과 Q6 운영 계약 OPEN은 유지한다.

## 3. 기준일 당시 관측값

각 종목·기준일마다 **그날 이하 자료만** 사용한다. 미래 가격은 아래 결과 계산에만 쓴다.

| 관측 | 고정 정의 |
|---|---|
| 가격 하락 구간 | PC 최근 20저장일 변화와 기존 `classify_decline(normalize_pct(...))` 경계 재사용. 5~8%·8~10%·10% 이상 하락 및 구간 미해당을 구분 |
| 거래량 | 그날 거래량 ÷ 그날을 제외한 직전 20개 저장일 평균. POC5-09의 0·결측·평균 분모 규칙 그대로 |
| 가격 흔들림 | POC5-16의 최근·직전 20구간 모집단 표준편차. 41개 종가·공유 경계 종가·비정상 행·가격 기준 경계 규칙 그대로 |

- 기존 계산과 같은 정의의 순수 함수를 재사용한다. 역사적 기준일 계산을 위해 PC 전체 최신일과 비교해 과거 전부를 제외하지 않는다. 각 계산 창의 끝을 그 기준일로 고정한다.
- 서로 다른 산식의 기존 ML feature 표를 이름만 같다는 이유로 대체하지 않는다. 추가 외부 수집은 하지 않는다.
- 종가·거래량 결측이나 기준 경계를 0 또는 정상으로 바꾸지 않는다. 계산 불가 사유와 종목·날짜 건수를 남긴다. 조합 분류 불가를 '구간 미해당'에 넣지 않는다.

## 4. 이후 경로와 비교표

기준일 t 다음의 **2026년 캘린더상 20거래일** 종가로 아래 두 관측만 계산한다. 휴장일이 아닌 저장 결측을 건너뛰어 더 먼 날로 채우지 않는다.

```text
끝점 변화 = C(t+20) / C(t) - 1
기간 중 최저 종가 변화 = min(0, min(C(t+h) / C(t) - 1, h=1..20))
```

- 20개 종가가 모두 확인되고 연결 가능한 경우만 결과 완결이다. 미도래·저장 결측·가격 기준 확인 필요를 나눠 센다. 장중 저가·개인 손익·배당 포함 총수익률로 이름 붙이지 않는다.
- 가격 하락 구간별로 **거래량 평균 초과 / 평균 이하 × 흔들림 커짐 / 커지지 않음**의 네 조합을 고정한다. 거래량 1배는 평균 이하, 흔들림 비교는 POC5-16과 같은 소수 둘째 자리 기준이다. '커지지 않음'에는 작아짐·같음이 포함된다. 이 경계들은 관측 비교 기준이며 매매 임계가 아니다.
- 가격 구간만 본 표와 네 조합 표는 **관측 세 가지와 이후 결과가 모두 있는 같은 표본**을 쓴다. 결측 때문에 모집단이 달라진 차이를 조합 효과로 설명하지 않는다. 전체 대상에서 공통 표본까지의 제외 사유·건수도 보인다.
- 각 행에 종목×기준일 수, 서로 다른 종목 수·기준일 수, 두 결과의 중앙값·25/75 분위수를 보인다. 기존 분위 함수 정의를 재사용한다. 수익률은 %로 표시한다.
- 추가로 기준일마다 먼저 결과 중앙값을 구하고, 그 날짜별 중앙값의 중앙값을 나란히 보인다. 특정 날짜에 종목이 많이 모인 영향을 확인하는 보조값이며 일반 중앙값과 구분한다.
- 같은 종목의 겹친 20일 경로를 독립 시행으로 세어 성공률·유의확률을 만들지 않는다. 빈 조합은 0%가 아니라 '표본 없음'이다. 작은 표본도 숨기지 않고 실제 건수를 보인다.
- 기간별 차이를 확인할 수 있도록 입력 범위의 거래일을 순서대로 반으로 나눈 앞·뒤 기간에도 같은 표를 부록으로 낸다. 홀수이면 앞 기간이 하루 길다. 유리한 시작일·종목·조합만 다시 고르지 않는다.
- 결과에 맞춘 새로운 점수·위험 등급·최적 기준·자동 채택 판정은 만들지 않는다. 최종 해석은 표본 범위를 확인한 뒤 설계자가 한다.

## 5. 실행·산출물

- PC 입력은 읽기 전용으로 일관된 자료를 읽어 계산한다. 기존 보유·시세 DB·원장·적용 기록은 쓰지 않는다. OCI 접속·PUSH·cron·PARAM 변경도 필요 없다.
- 산출물은 기존 PC 연구 관례의 `state/ml/research/poc5_20/<종료일>_<생성시각>/` 새 폴더에 둔다. `report.md`·`report.json`과 재현에 필요한 입력 식별 정보를 남긴다. 별도 실행 관리 서비스는 만들지 않는다.
- 리포트 앞부분에는 질문, 실제 자료 기간·대상 수, 제외 요약, 가격 구간별 네 조합의 대조표를 둔다. 계좌·수량·평단·개인 손익·메모는 입력이나 출력에 넣지 않는다.
- 입력 식별 정보는 사용한 종목·기간·종가·거래량·캘린더·계산 정의를 구분할 수 있게 한다. 산출물 생성 시각을 제외하면 같은 입력과 정의는 같은 수치가 나와야 한다.

## 6. PLAN과 완료 기준

1. 개발자는 짧은 PLAN에 실제 자료 범위·결측, 재사용할 계산 함수와 역사적 기준일 적용 방법, 기존 연구와의 차이, 변경 파일·필요한 시험만 적는다. 이후 결과의 유불리는 PLAN 단계에서 분석하지 않는다. 별도 전수 감사나 목업은 필요 없다.
2. 정의가 같은 기존 계산과의 대조, 기준일 뒤 입력값 차단, 20거래일 경계·휴장·누락, 같은 종목 다계좌 중복, 0과 결측, 공통 표본 분모, 알려진 작은 표의 통계를 시험한다. 변경 범위의 검사와 백엔드 회귀를 수행한다. 화면 검사는 변경이 없어 반복하지 않는다.
3. PLAN 판정과 구현 시험 뒤 실제 PC 자료로 공식 대조를 한 번 실행한다. 결과서·리포트를 함께 검증자 확인에 넘긴 뒤 설계자 RESULT 판정을 요청한다. 동일 입력 재실행은 수치 결정성 확인에 쓰며, 결함 정정에 따른 재실행은 사유를 남긴다. 결과가 약하다는 이유로 창·종목·산식을 바꾸어 반복하지 않는다.
4. 표와 제외 사유가 계약대로 만들어지면 구현은 완료다. '차이가 뚜렷하지 않음'이나 '비교 자료 부족'도 정상 결과이며, 수익성·예측력 입증을 개발 종료 조건으로 두지 않는다. 실제 입력 부족이 확인되면 보고하고 이미 있는 자료로 가능한 범위에서 닫는다.
5. 본 단계는 Q6 운영 위험 등급을 확정하지 않는다. 리포트 확인 후 관측 근거로 계속 둘지, 추가 검증할 가설이 있는지 한 번 판정한다. 기준을 찾을 때까지 이어지는 자동 후속 연구를 예정하지 않는다.
