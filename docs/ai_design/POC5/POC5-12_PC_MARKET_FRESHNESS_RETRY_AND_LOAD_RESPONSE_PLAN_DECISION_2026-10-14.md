### Q1 — 조건과 문구를 함께 고친다
세 화면에서 fresh·one_weekday_behind는 오래됨 경고를 내지 않는다.
update_check는 'VIX 자료 업데이트 확인 필요', date_check는 'VIX 기준일 확인 필요'로 표시한다.
PLAN의 '문구는 그대로, 조건만 변경'은 다음처럼 보충한다.
기존 '시장 …보다 이전' 문장은 새 판정의 이유가 아니므로 제거한다. 국내 날짜와 비교한다는 옛 설명을 남기지 않는다.
실제 VIX 기준일·값은 보존하며, 자료 없음과 freshness 필드 없음도 설계서대로 구분한다.
같은 현재 PC 참고자료를 표시하는 연결만 수정한다. 저장된 초안·원장·과거 재현 내용은 바꾸지 않는다.

### Q2 — 요청과 동작이 일치한다
scope를 생략한 기존 POST는 원래 전체 갱신 동작을 유지한다.
scope=vix는 서버가 재시도 표식과 실행 중 상태를 확인한 뒤 VIX만 실행한다.
알 수 없는 scope나 재시도 대상이 없는 요청을 전체 갱신으로 바꿔 실행하지 않는다.
전체 갱신과 VIX 재시도의 확인·시작은 같은 기존 잠금 경계에서 한다. 다른 프로세스용 잠금 체계는 추가하지 않는다.

### Q3 — NAV도 다른 단계에 포함한다
설계서의 '다른 단계가 성공하고 VIX만 실패'에는 NAV도 포함된다.
ETF 목록·가격·보유 개별주·KOSPI뿐 아니라 NAV의 실제 호출 결과도 확인한 뒤 표식을 확정한다.
NAV가 기존 error_summary에 사유를 남기지 않는다는 이유만으로 성공으로 보지 않는다.
각 단계의 결과·예외를 사용한다. 정상적인 대상 없음·생략은 실패가 아니다.
이를 위해 NAV 수집 방식이나 전체 갱신의 기존 completed/failed 판정을 바꿀 필요는 없다.

표식은 가장 최근 전체 갱신 결과와 맞춘다.
새 전체 갱신에서 다른 단계도 실패했다면 과거의 VIX 단독 실패 표식으로 재시도를 열지 않는다.
VIX 성공이면 해제하고, 최신 전체 결과가 VIX 단독 실패일 때만 다시 필요 상태로 둔다.

### Q4 — 적용은 실제 확인 때 한 번
start.sh·start.bat의 app/scripts 감시 범위 변경을 승인한다.
구현·검증을 끝낸 뒤 사용자에게 기존 시작 방식과 재기동 적용 여부를 간단히 안내한다. 지금 재기동할 필요는 없다.
진행 중 갱신이 끝난 상태에서 적용한다. 코드 수정의 자동 다시 읽기가 계속 작동하는지 확인한다.
새 실행 도구나 watchfiles 설치는 요구하지 않는다.

## 3. 재시도 결과 표시 보충
기존 market_refresh_state의 vix_retry 행을 사용하며 새 표·스키마를 만들지 않는다.
성공 뒤 '필요' 표식 해제와 '성공 결과' 확인을 구분한다.
행이 없어졌다는 사실만으로 성공·기준일을 추측하지 않는다.

성공 결과를 기존 응답이나 같은 행에 명시해 화면이 읽을 수 있도록 한다.
예를 들어 같은 행에 completed 결과를 남기고 needed=false로 두는 것은 승인한다. 해제에 반드시 행 삭제가 필요한 것은 아니다.
처리가 빨리 끝나 첫 상태 조회 전에 완료돼도 'VIX 다시 받기 완료(기준일 D)'를 확인할 수 있어야 한다.
재실패·재기동 시 실패 복구도 기존 scope 행에서 처리한다.
VIX 결과가 전체 갱신의 상태·마지막 성공 시각·건수·기록으로 섞이지 않도록 한다.

## 4. 조회 지연 보완 승인
같은 URL의 시장 GET을 진행 중에만 공유하고 성공·실패·timeout 뒤 제거한다.
입력 변경·화면 이동 시 늦은 응답을 무시하며, 같은 실패 Promise를 다음 시도까지 계속 재사용하지 않는다.
현재 두 무거운 GET이 이미 동기 def라는 조사 결과를 수용한다. 이벤트 루프 차단이라고 단정해 실행 방식을 다시 바꾸지 않는다.

기존 화면 유지의 조건은 명확히 한다.
같은 입력의 재조회 실패면 받은 자료와 실제 기준일을 남기고 오류 한 줄을 표시한다.
입력을 바꾼 뒤 실패하면 이전 조건 자료임을 분명히 알리거나 해당 결과 영역을 숨긴다. 새 조건의 결과처럼 보이면 안 된다.
먼저 완료된 영역은 유지하고, 한 요청의 실패로 성공한 다른 영역까지 오류로 덮지 않는다.

기존 파일 감시 측정을 반복 감사하지 않는다. 실제 시작 스크립트 적용 전후 요청 수·CPU·화면 응답을 비교한다.
보완 뒤에도 정상 응답이 10초를 넘으면 해당 시장 GET만 20초로 조정할 수 있다.
timeout 조정과 실제 계산·대기시간 개선을 따로 보고한다. 새 캐시·SLA·계산 전면 최적화는 추가하지 않는다.

## 5. 검증·종료와 개발자 전달문
제출 PLAN의 격리 시험에 NAV 실패, 이전 표식 후 다른 단계 실패, 빠른 재시도 완료를 보충한다.
GET 실패·timeout 뒤 재요청과 조건 변경 뒤 이전 자료 오인 방지도 확인한다.
새로운 반복 검토·변이 건수 목표는 만들지 않는다. 변경에 맞는 시험과 저장소 필수 검사를 완료한다.
실패 사례는 격리 fixture로 확인한다. 라이브 실패를 만들거나 전체 갱신을 불필요하게 반복하지 않는다.
사용자 재기동 뒤 일반 화면 열기와 VIX 경고 표시를 확인하고 기존 RESULT 절차로 종료한다. OCI pull·거래일 대기는 필요 없다.
