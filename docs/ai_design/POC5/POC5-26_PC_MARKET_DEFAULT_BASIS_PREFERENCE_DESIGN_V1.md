# POC5-26 기본 조회 기준 설정 — 설계 V1

작성: 2026-10-19 · 설계자 → 개발자 / 사용자
근거: 사용자 백로그 #19 개발 요청(POC5-25 RESULT §11). #19는 백로그 출현 순서이며 POC5-19 거래량 작업과 다른 항목이다.

**목표: 「요즘 잘 오르는 ETF」를 새로 열 때 쓰는 조회 기준을 사용자가 한 번 정하고 유지한다.**

## 1. 착수와 범위

- 다음 실제 개발은 이 항목 하나다. POC5-25는 종료 정리를 진행하며, 이 설계를 기다리느라 종료를 미루지 않는다.
- 새 설정 메뉴·페이지·API·DB·의존성·수집·ML·OCI·PUSH·운영 PARAM을 추가하지 않는다.
- 설정 대상은 현재 화면의 조회 기준 하나다. 일간·1개월·3개월 등 **현재 화면이 실제 지원하는 선택지와 기존 API 값**을 그대로 사용한다. 필터·상위 개수·카드/표 보기·다른 화면의 기준까지 함께 저장하지 않는다.

## 2. 사용자 동작

1. 기존 조회 기준 선택으로 원하는 결과를 본다. 임시로 다른 기간을 보는 동작은 지금과 같다.
2. 그 선택 옆의 중간 크기 **[이 기준을 기본으로]**를 누르면 현재 선택만 저장한다.
3. 같은 자리에서 '기본: 1개월'처럼 저장된 기준을 알 수 있다. 현재 선택이 이미 기본이면 버튼은 저장할 것이 없음을 보인다.
4. 앱을 새로 열거나 브라우저 화면을 새로 불러오면 저장한 기준으로 첫 시장 조회를 시작한다. 저장된 값이 없으면 현재 기본값인 1개월로 시작한다.
5. 기본을 바꾸지 않고 일시적으로 다른 기준을 선택할 수 있다. 조회 기준을 바꿀 때마다 기본 설정이 자동으로 바뀌지 않는다.

새 카드·대화창 없이 기존 기준 선택 근처에 배치한다. 기본과 현재 조회가 다르다는 것을 구분할 수 있어야 한다. 한 문장의 범위 설명('이 브라우저에 저장됩니다')이 필요하면 기존 도움말 안에 둔다. 큰 설명 문단을 추가하지 않는다. 버튼은 기존 UI-01 중간 규격을 따른다.

## 3. 저장과 조회 계약

| 항목 | 계약 |
|---|---|
| 저장 위치 | 브라우저 localStorage의 전용 설정 한 값. 이 브라우저·같은 앱 주소에서 유지한다. 기기·브라우저·접속 주소 간 동기화는 이번 범위가 아니다. |
| 저장 시점 | 사용자가 [이 기준을 기본으로]를 명시적으로 눌렀을 때만 쓴다. 조회·필터 변경·메뉴 이동·기동 때 자동으로 저장하지 않는다. |
| 허용값 | 현행 조회 기준 선택지에 대응하는 값만 허용한다. 이름을 새 기간 계산으로 해석하지 않는다. |
| 첫 조회 | 설정 읽기가 끝난 뒤 확정한 기준으로 시작한다. 기본 1개월을 먼저 조회하고 저장값으로 다시 조회하는 두 번 호출은 만들지 않는다. |
| 일반 재조회 | 현재 화면에서 선택한 기준과 필터를 유지한다. 데이터 갱신·조회 재시도 때문에 저장 기본값으로 되돌리지 않는다. 메뉴 이동 중 살아 있는 화면 상태의 유지 정책도 임의로 바꾸지 않는다. |
| 저장 클릭 | 기본 설정만 저장하며 시장 GET·외부 수집·다른 자료 재계산을 일으키지 않는다. 저장 성공 뒤에만 기본 표시를 바꾼다. |
| 설정 없음·허용 밖 값·읽기 실패 | 기존 1개월 기본으로 첫 조회한다. 설정 문제 때문에 시장 화면을 막지 않는다. 읽기 실패는 필요한 경우 설정 자리의 짧은 안내로 구분한다. 시세·계산값을 대체하는 규칙이 아니다. |
| 저장 실패 | 저장 실패를 짧게 알리고 기존 저장 기본 표시·현재 조회를 유지한다. 성공한 것처럼 표시하지 않는다. |

## 4. 기존 연결 보존

- 기존 조회 기준은 현재 화면의 후보 계산·기간 표시·동일 기간 비교·복사문·AI 세션 전달의 조건으로 계속 쓰인다. **전달할 조건은 저장 기본값이 아니라 실제로 조회 중인 선택값**이다.
- 최근 20저장일 고점 대비 등 고정 관측 창의 정의를 조회 기본 설정 때문에 바꾸지 않는다.
- POC5-12의 같은 GET 진행 중 공유·늦은 응답 무시·재조회 실패 시 받은 화면 유지 규칙을 보존한다.
- 「ETF 비교하기」의 기본값, 관찰 후보군(seed), OCI 활성 PARAM과 관계없는 설정이다. 해당 값이나 파일에 쓰지 않는다.

## 5. 짧은 PLAN과 전체 화면 목업

개발자가 다음 사실만 조사해 짧게 적는다.

1. 현재 기준 선택지·초기값·상태 생성과 첫 시장 GET의 연결 위치.
2. 기존 브라우저 설정 helper가 있다면 재사용 위치, 없으면 최소 저장/읽기 helper와 변경 파일.
3. 저장 실패·초기 설정 읽기·기존 조회/복사/전달 보존을 확인할 방법.

개발자가 실제 전체 화면 1440/1000px 목업을 만든다. 초기 1개월, 기본 3개월 저장 상태, 임시로 다른 기준을 조회하는 상태가 구분되면 충분하다. 저장 실패는 격리 자료로 보여 줄 수 있다. 라이브 자료를 바꾸지 않는다.

사용자 목업 확인과 PLAN 판정 뒤 구현한다. 현행 코드와 실제로 맞지 않는 계약만 질문한다. 파일 크기 때문에 필요하면 저장·표시 부분만 작은 helper/컴포넌트로 두며 전체 화면 리팩터를 별도 선행 Step으로 만들지 않는다.

## 6. 수용 기준과 종료

- 저장한 기본값이 화면 새로 불러오기 뒤 유지되고, 첫 시장 요청부터 그 기준을 사용한다.
- 임시 조회 기준 변경은 기본값을 덮어쓰지 않는다. 기본 저장만으로 시장 요청이 새로 생기지 않는다.
- 현재 선택과 저장된 기본이 다를 때 표시·복사·전달이 실제 조회 선택과 일치한다.
- 설정 없음·잘못된 값·읽기/쓰기 실패에서 위 계약을 지킨다. 기존 자료 갱신·응답 처리·기간 계산은 보존한다.
- 필요한 프론트 시험·타입·lint 및 프로젝트 필수 검사를 수행하고 사용자 실화면·검증자 확인 뒤 RESULT를 제출한다. 변경 없는 백엔드 전체 회귀를 이 단계의 새 완료 조건으로 추가하지 않는다.
- RESULT 판정 후 승인 범위에 따라 커밋·push하고 종료한다. OCI pull·거래일 대기·별도 인계 문서는 없다.
