# POC5-23 선택 ETF 판단 근거 미리보기 통합 — 설계 V1

작성일: 2026-10-18 · 작성자: 설계자 · 수신: 개발자 / 사용자

**목표: 선택한 ETF의 가격 흐름·거래량·가격 흔들림·시장 맥락·중복 근거를 기존 미리보기에서 함께 읽고, 같은 문장을 복사해 AI와 토론한다.**

## 1. 최신 문서 검토와 다음 작업 결정

근거는 사용자 첨부 `STATE_LATEST(20261018-024921).md`, `BACKLOG(5).md`와 앞서 확정한 POC5-20~22 판정이다. 개발자의 `6cab3a18` 문서 정정·push 보고를 수용한다. 설계자가 저장소 전체 소스를 직접 대조한 감사는 아니다.

| 남은 항목 | 이번 결정 |
|---|---|
| `compute_topn(asof=과거일)` | 과거 재현·백테스트에서 이 인자를 사용하기 전 재검토. 현재 호출을 바꾸는 작업으로 승격하지 않는다. |
| FDR timeout 잔여 | POC5-17~18의 PC 버튼 보호는 완료로 유지. 수동 스크립트·DNS·느린 연속 응답 한계는 현재 설계의 선행 작업이 아니다. |
| 종합 위험 분류·ML 고도화 | 미완료 요구로 유지. POC5-20에서 보편적 위험 순서를 확인하지 못했으므로 새 점수·등급을 임의로 만들지 않는다. |
| 인증·SLA·캐시·다중 사용자·모바일 등 조건부 과제 | 해당 사용 필요·장애가 보고된 범위에서만 재검토한다. 등록돼 있다는 이유로 모두 개발하지 않는다. |
| PC seed 3개 / OCI 승인본 20개 | 사용자 결정 대기로 유지. 승인본 교체·재승인·편집 화면은 이번에 추가하지 않는다. |
| 미사용 POC5-16 컴포넌트·시험·CSS | 사용자 삭제 승인 대기인 선택적 정리. 별도 POC나 이번 착수·종료 조건으로 삼지 않는다. |

**다음 실제 작업은 POC5-23으로 지정한다.** 원래 목적의 'AI와 함께 투자 방향 찾기'에 현재 관측 근거를 연결한다. 완료된 POC5-21~22 비교 정정, 위험 분류 연구, 운영 보호를 다시 여는 작업은 아니다.

백로그의 `DEF-HOLDINGS-EVIDENCE-MULTIROW-VALUATION` 부록에는 미리보기가 `data_quality`·`overlap`을 읽지만 builder의 실제 키는 `constituents_overlap`이라는 연결 누락이 기록돼 있다. STATE의 기존 `Decision Draft Preview v1`은 선택 ETF 한 개의 수동 미리보기이며 PENDING 초안·발송과 분리돼 있다. 개발자는 이 동선의 현재 존속과 키를 PLAN에서 확인한다. 이미 고쳐진 부분은 재구현하지 않는다.

## 2. 사용 흐름과 화면

- 기존 「보유와 비교」의 선택 ETF 상세와 `판단 근거 미리보기`·복사 동선을 사용한다. 현재 저장소에서 동선이 달라졌으면 PLAN에 실제 위치와 최소 연결안을 적는다. 폐지된 발송·승인 경로를 복구하지 않는다.
- 선택은 ETF 한 개다. 보유·후보 양쪽을 지원하고, 같은 종목의 여러 계좌는 기존 종목 단위 표시를 따른다. 개별주로 범위를 넓히지 않는다.
- 현재 상세의 핵심 수치와 미리보기는 같은 계산 정의를 사용한다. 버튼 한 번으로 필요한 근거가 모이고, 근거마다 새 버튼을 누르게 만들지 않는다.
- 기본 화면에는 선택 종목·각 근거의 값/기준일·실제 제한만 짧게 보인다. 긴 산식과 일반 설명은 기존 `?`를 사용한다. 구역 제목과 줄바꿈으로 읽는 순서를 만든다.
- 새 메뉴·새 차트·새 점수는 만들지 않는다. 개발자가 실제 폭 1440/1000px의 전체 화면 목업을 만들고, 사용자 확인 뒤 화면을 구현한다.

## 3. 한 번에 전달할 근거

| 묶음 | 내용과 재사용 계약 |
|---|---|
| 대상·시장 | 종목명·티커, 현재 제공되는 시장 국면과 기준일, 기존 KODEX200·VIX 맥락. 날짜가 다른 자료는 각각의 날짜를 남긴다. |
| 가격 흐름 | 현재 PC 화면의 5/20저장일 변화·하락 구간 등 해당 종목에 이미 제공하는 관측값. 기존 계산·범위·자료 부족 판정을 재사용한다. |
| KODEX200 비교 | POC5-22의 1/3개월 동일 기간 객체가 제공되는 경우 실제 A·B·양쪽 수익률·차이(%p)를 함께 전달한다. 값이 없는 보유를 위해 상위 10 밖 계산을 확장하지 않는다. 기존 단기 20구간 값은 별개 정의임을 구분한다. |
| 거래량 | POC5-09의 기준일·거래량(주)·직전 20개 저장일 평균·배수. 원래 계산값과 표시 정밀도를 재사용한다. |
| 가격 흔들림 | POC5-16의 최근/직전 20구간 표준편차(%)·비교·대상 기간과 계산 불가 사유. 새 변동성 산식을 만들지 않는다. |
| 중복·자료 상태 | 실제 구성종목 중복 근거와 비교 범위·기준일, 현재 존재하는 NAV/괴리율 및 자료 확인 사유. 실제 payload의 뜻을 확인해 연결하고, 없는 `data_quality` 키를 임의 값으로 채우지 않는다. |

- 수치가 함께 관측됐다는 사실과 미래 결과의 해석을 구분한다. '거래량 증가 → 위험', '흔들림 증가 → 매도' 같은 결론이나 새 종합 위험 순서를 생성하지 않는다.
- 미확인·미조회·가격 기준 문제는 해당 묶음에 이유를 남긴다. 미리보기에서 줄을 조용히 빼거나 0·다른 기간·다른 종목 값으로 채우지 않는다. 일부 근거가 없다는 이유로 나머지 정상 관측까지 버리지 않는다.
- 끝에는 AI에게 함께 해석할 사실, 가능한 다른 해석, 추가 확인할 사항을 구분해 달라는 짧은 질문을 둔다. 시스템이 LLM을 호출하거나 답변을 생성하지 않는다.

## 4. 조립·연결 범위

- 기존 `POST /decision-draft/preview`와 미리보기 조립을 우선 재사용한다. 현재 화면이 사용하는 PC 응답 조립·계산 helper를 연결하고, 공유 builder·PUSH용 기본 계산의 뜻을 바꾸지 않는다.
- 화면과 미리보기가 각각 별도 산식으로 값을 만들지 않는다. 기준일·입력이 다르면 같은 시점 값처럼 표시하지 않는다. 생성 시각과 실제 가격 기준일도 구분한다.
- 외부 수집은 하지 않는다. 이미 받은 응답·읽은 저장 자료를 우선 재사용한다. 필요하면 선택 ETF의 저장 창을 추가로 읽는 작은 쿼리는 허용하며 PLAN에 적는다. 추가 읽기 0을 맞추기 위해 우회 구조를 만들지 않는다.
- 기존 미리보기의 보유 비중·손익 표시 정책은 유지한다. 새로 더하는 관측 블록에 수량·평단·계좌·거래 금액·이력 메모를 추가하지 않는다. 개인 원장·OCI로 새 자료를 보내지 않는다.
- 화면의 미리보기와 복사 결과는 같은 문자열을 사용한다. 기존 AI 전달 경로가 이 미리보기를 직접 소비한다면 그 경로도 같은 결과를 사용한다. 별도 새 영구 스냅샷·테이블·마이그레이션은 만들지 않는다.
- 이전 미리보기 응답은 종목 변경 시 현재 선택에 표시되지 않게 한다. 기존 오류·요청 취소 처리와 개인정보 정책을 유지한다.

## 5. 짧은 PLAN에서 확인할 사실

1. 현재 미리보기의 진입 화면·요청·응답과 실제 소비처. 활성 PC 미리보기와 LEGACY 발송 초안을 구분한다.
2. 표의 각 묶음이 지금 전달되는지, 빠졌다면 현재 PC 화면의 어느 응답·helper를 재사용하는지. 중복·자료 상태 키 누락도 이 안에서 확인한다.
3. 종목 하나의 화면/미리보기 값·기간 대응, 추가 저장 읽기와 변경 파일, 기존 필드 보존 방법.
4. 실제 ETF 한 개의 전후 전체 화면 목업과 자료 일부 없음 사례. 라이브 자료를 수정하지 않는다.

이미 전달되는 근거는 그대로 쓴다. 새 전수 감사·리팩터 선행 단계·별도 연구 보고서를 요구하지 않는다. 설계와 실제 코드가 충돌하는 질문만 PLAN에 올리고, 목업 확인과 PLAN 판정 뒤 구현한다.

## 6. 수용 기준과 종료

1. 보유 ETF·후보 ETF에서 기존 버튼으로 선택 종목 한 개의 근거가 조립되고, 화면·미리보기·복사문의 대상·숫자·단위·날짜가 맞는다.
2. 중복 자료가 존재하는 실제 payload에서 연결 누락으로 사라지지 않는다. 조회 전/비교 불가를 '중복 없음'으로 바꾸지 않는다.
3. 가격·거래량·흔들림은 기존 정의를 보존한다. 한 묶음의 자료 부족과 종목 변경 뒤 늦은 응답을 구분해 처리한다.
4. 수집·ML 실행·보유 쓰기·원장 쓰기·OCI·PUSH 동작은 추가하지 않는다. 현재 동일 기간 비교의 승인된 범위와 한계를 유지한다.
5. 해당 조립·API·화면 연결에 필요한 시험과 기존 필수 검사를 통과하고, 사용자 실화면과 검증자 확인을 받는다. 수치 표시만 검사하는 시험으로 실제 연결 검사를 대신하지 않는다.
6. RESULT 판정 후 기존 문서의 관련 상태를 정리하고, 사용자 승인에 따라 커밋·push해 종료한다. 새 기능 완료분만 기록하며 종합 위험 분류·운영 ML 완료로 기록하지 않는다.

OCI pull·거래일 운영 확인·R0 실행을 이번 종료 조건으로 두지 않는다. 별도 인계 문서도 필수로 요구하지 않는다.
