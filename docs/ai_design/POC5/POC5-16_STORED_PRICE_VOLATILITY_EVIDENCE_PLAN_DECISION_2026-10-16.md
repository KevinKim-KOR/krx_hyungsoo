## 3. Q1 — 기준일과 원본 창의 구분
- D = PC 가격 흐름 기준일, E = 기존 거른 읽기의 마지막 유효 가격일로 구분한다.
- PLAN의 선행 검사를 유지한다. E 없음 → 자료 부족, D 없음 → 기준일 확인 불가, E ≠ D → 날짜 불일치로 값을 숨긴다.
- 위 검사를 통과하면 E = D이다. 이때 **D 이하의 원본 최근 41행**을 날짜순으로 읽는다.
- PLAN의 “E 이하 읽기”는 위 검사를 통과한 뒤에만 적용한다. E로 임의 후퇴한 뒤 기준일 불일치를 무시하고 수치를 내지 않는다.
- 원본 읽기에서는 null·0·음수·비정상 종가를 제거하지 않는다. 읽은 창에서 각 기간의 유효성을 검사한다.
- D 이후 행은 관측 기준일 밖이므로 제외한다. D 이하의 비정상 행을 제외하는 것과 구분한다.
- D 당일 종가가 비정상이어서 E가 이전 날짜가 되면 날짜 불일치로 숨긴다. 오래된 창을 최신 창처럼 보여 주지 않는다.
- E를 표시하는 새 사유 문구는 **“마지막 유효 가격일”**처럼 정확히 표현한다. 거른 날짜를 원본 표의 “최근 저장일”이라고 단정하지 않는다.
- 추가 SELECT는 같은 SQLite에서 종목별 최대 한 번·최대 41행으로 허용한다. 여러 계좌의 같은 종목은 결과를 공유한다.
- 기존 가격 읽기와 5일·20일·구간 값·날짜는 수정하지 않는다.

## 4. Q2 — 경계는 가격 사이의 연결에 적용
- 기존 POC5-06 판정의 산식·허용 출처·전환 규칙을 재사용한다. 새 수치 임계나 출처 추정을 추가하지 않는다.
- 필요한 작은 공개 접점만 허용한다. 기존 06 동작을 바꾸거나 재진입 모델·전체 흐름·저장기를 PC 조회에서 실행하지 않는다.
- 화면의 **“가격 기준 변화”는 “가격 기준 확인 필요”로 정정**한다.
- change 누락·출처 전환 등은 연속성을 확인할 수 없는 사유도 포함한다. 분배락·액면 변경이 실제 발생했다고 단정하지 않는다.
- NAVER_FDR 구간의 부분 검사 한계는 기존대로 수용하고 RESULT에 적는다. 경계를 못 찾았다는 것을 모든 가격 기준이 검증됐다는 뜻으로 기록하지 않는다.

가격을 오래된 순서 P0…P40으로 두면:
- 직전 기간의 20개 연결: P0→P1부터 P19→P20까지.
- 최근 기간의 20개 연결: P20→P21부터 P39→P40까지.
- **P19→P20의 경계는 직전 기간만**, **P20→P21의 경계는 최근 기간만** 막는다.
- 경계 종가 P20 자체가 비정상이면 두 기간 모두 해당 가격을 사용하므로 둘 다 계산 불가이다.
- P0로 들어오는 창 밖 연결을 검사하려고 42번째 종가를 요구하지 않는다. P0 자체의 가격·출처 유효성은 확인한다.
- 경계 검사와 계산은 이처럼 기간별로 적용한다. 한 기간의 문제로 다른 유효 기간까지 숨기지 않는다.

## 5. Q3·Q4와 표시 보충
- D가 없을 때는 별도 상태와 “PC 가격 흐름 기준일을 확인할 수 없어 값을 보이지 않습니다”를 사용한다.
- KODEX200 과거 41행·20일 시작일 일치까지 추가 조건으로 요구하지 않는다.
- 접힌 상태에서도 현재 해당하는 계산 불가·기준일 사유와 ?를 확인할 수 있게 한다.
- 값·비교·기간은 펼침 안에 두고, 정상 상태에 장문 설명을 더하지 않는다.
- 최근만·직전만·둘 다 없음 상태와 기간별 독립 사유를 수용한다. 최근·직전 중 한 값이 없으면 비교 문구를 만들지 않는다.
- 모집단 분모 20·단순 수익률·% 단위·연율화 없음·소수 둘째 자리 표시값 비교는 설계 그대로다.
- 위 날짜 명칭과 경계 사유의 문구 정정은 사실을 정확히 하는 보충이다. 확정 목업의 구조·색·위치를 다시 정하지 않는다.

## 6. 검증과 다음 순서
- PLAN의 계산·응답·화면 시험을 수행하고 다음 구분을 포함한다.
  1. D 이후 비정상 행은 창 밖, D 이하 창 안 비정상 행은 건너뛰지 않음.
  2. D 당일 비정상으로 E가 후퇴하면 값 숨김. 기준일 없는 경우와 구분.
  3. 공유 경계 종가의 두 연결에 각각 경계가 생기는 경우와, 종가 자체가 비정상인 경우.
  4. change 누락을 실제 가격 변화로 단정하지 않는 사유 문구, 라벨 변경만인 경우의 기존 규칙.
  5. 같은 종목 여러 계좌의 추가 읽기 한 번, 기존 값·날짜 불변, DB 쓰기·새 외부 조회 없음.
- 표본 분모 함수·로그 수익률 함수의 동작 불변과 06 경계 공개 접점의 기존 동작을 관련 시험으로 확인한다.
- 개발자는 본 판정을 PLAN에 보충한 뒤 구현을 시작한다. **PLAN 재제출·목업 재확인은 필요 없다.**
- 검증자 검증 후 RESULT에 수행 근거와 수용한 검사 한계를 제출한다.
- 사용자 실제 종목 상세 확인·커밋·push·종료는 기존 절차를 따른다. OCI pull·첫 영업일을 기다리지 않는다.
- Q6에는 PC 변동성 관측 후보의 계산 범위만 기록한다. 운영 위험 계약·임계·라벨 또는 ML 검증 완료로 승격하지 않는다.
