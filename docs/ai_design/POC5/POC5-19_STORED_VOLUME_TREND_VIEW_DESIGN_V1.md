## 1. 다음 작업 선정

- 이번 대상은 통합지도 **P-10 거래량 흐름** 중 저장 자료의 추이 표시다. BACKLOG §14에도 POC5-09가 단독 관찰값만 제공하고 복합 지표·흐름 해석은 미구현이라고 적혀 있다.
- POC5-09의 현재 거래량·직전 20개 저장일 평균·평균 대비 배수는 하루의 단면이다. 사용자가 최근 여러 날의 거래량을 직접 볼 수 있도록 같은 상세에 작은 막대 차트를 제공한다.
- 종합 위험 분류(P-06)는 살아 있는 요구로 유지하되, 이번에 점수·임계·가중치·검증되지 않은 위험 등급을 붙이지 않는다. 조건이 오지 않은 인프라·모바일·운영 고도화 항목도 이번 대상이 아니다.
- POC5-17~18의 갱신 보완은 종료됐다. 다음 작업을 위한 새 결함 발굴·갱신 재설계는 요구하지 않는다. 이번 기능은 기존에 저장한 자료로 바로 만들 수 있는 사용자 기능이다.

## 2. 사용 모습

- 위치는 **「확인 근거」 → 선택 종목 상세 → 기존 저장 거래량 영역**이다. 기존 네 칸은 그대로 두고 그 아래 **[최근 거래량 흐름 보기]**를 붙인다.
- 기본은 접힘이다. 펼치면 **최근 최대 20개 저장일의 일별 거래량 막대 차트** 하나를 본다. 종목을 바꾸면 기본 접힘으로 시작한다.
- 날짜는 가로축, 거래량(주)은 세로축이다. 날짜별 실제 거래량은 기존 차트의 상세값 표시 방식으로 확인한다. 크기 단위를 줄여 표시할 때도 주 단위를 명확히 한다.
- 차트 위에는 종목명과 `기준일 D · 최근 N개 저장일` 정도만 짧게 보인다. 조회 시각과 가격 자료 기준일을 혼동하지 않는다.
- 설명은 기존 클릭형 **?** 안에 둔다. 뜻 → 기간·단위 → 지금 해당하는 제한 순서로 짧게 나눈다. 긴 안내 문단을 상시 노출하지 않는다.
- 거래량이 늘었다는 사실을 상승·안전·매수 신호로 이름 붙이지 않는다. 막대는 기존 중립 계열 색을 쓴다. 기존 가격 흐름·하락 구간·변동성 표시와 계산은 유지한다.
- 「오늘의 투자 점검」에는 새 차트·카드·요약 수치를 추가하지 않는다. 새 메뉴도 없다.

## 3. 자료 계약

- 대상은 현재 「확인 근거」가 거래량 근거를 제공하는 보유 종목이다. 같은 종목 여러 계좌는 같은 시장 자료를 공유한다. 전체 ETF를 추가 수집하거나 계산하지 않는다.
- POC5-09의 저장 거래량 자료원·주 단위·기준일 판정을 재사용한다. 실제 필드·읽기 위치·기존 반환 자료의 재사용 가능성은 PLAN에서 코드로 확인한다.
- 창은 해당 종목의 승인된 거래량 기준일 D 이하에서 **원본 저장 행을 날짜순으로 최근 최대 20개**다. 현재 기준일 행을 포함한다. 이 차트는 '20거래일이 연속 검증됐다'는 의미가 아니므로 이름을 저장일로 쓴다.
- 20개보다 적으면 확보된 N개만 그대로 보여 준다. 자료를 더 모을 때까지 차트를 막지 않는다. 0개면 기존 자료 없음 문구를 사용한다.
- 창을 고르기 전에 결측 거래량 행을 지워 과거 행으로 채우지 않는다. 창 안에서 거래량이 null·숫자 아님·음수·비유한 값이면 그 날짜는 값 없음으로 구분한다. 0으로 대체하지 않는다. **저장된 정상 거래량 0은 유효값**이다.
- 값 없는 날짜도 날짜 위치는 유지하고 빈 값임을 알 수 있게 한다. 누락·비정상 값이 있으면 펼친 영역에만 짧은 자료 확인 문구를 두고, 기존 네 칸의 확인 필요 안내는 유지한다.
- 기존 기준일 규칙상 표시할 수 없는 경우 기존 사유를 사용한다. 다른 기준일 자료를 정상 최신 추이로 조용히 대체하지 않는다. 없는 날짜·거래량·휴장일을 새로 만들지 않는다.
- 기존 평균·배수는 기존 정의 그대로다. 차트용 이동평균·배수 시계열·순위·추세 등급·상승/하락과의 결합 판정은 만들지 않는다.

## 4. 구현 경계

- PC의 기존 근거 GET 응답 사본에 날짜·거래량 목록을 선택 정보로 붙인다. 공개 API 경로·새 DB 표·DB 쓰기·외부 조회·자동 갱신·의존성·OCI·PUSH·원장 변경은 없다.
- 가능하면 POC5-09에서 이미 읽은 창을 재사용한다. 부족하면 같은 읽기 모듈 안에서 종목별 한 번의 제한된 조회로 현재 네 칸과 차트 자료를 함께 얻는 안을 PLAN에 적는다. 기존 평균에 필요한 행을 차트 20개 제한 때문에 버리지 않는다.
- 같은 종목의 다중 계좌 때문에 중복 조회하지 않는다. 20개보다 더 긴 차트 자료를 전송하지 않는다.
- 펼치기 자체가 외부 수집이나 별도 시세 요청을 시작하지 않는다. 이미 받은 응답으로 표시한다. 기존 차트 도구를 우선 재사용하고 라이브러리를 새로 설치하지 않는다.
- 기존 거래량 계산·공유 builder·알림·초안의 의미를 바꾸지 않는다. 구현 위치와 필드 이름은 실제 코드의 책임 경계에 맞춰 개발자가 제안한다.

## 5. 개발자가 먼저 할 일

1. 현재 거래량 응답·조회 창·차트 도구를 확인한다. 별도 조사 보고서는 만들지 않는다.
2. **개발자가 전체 화면 목업을 만든다.** 1440px·1000px에서 현재와 변경안을 같은 입력으로 비교한다. 정상 접힘/펼침과 일부 거래량 없음 사례를 포함한다. 실제 개인 보유 자료는 로컬에서만 사용한다.
3. 사용자 목업 확인 뒤 짧은 PLAN을 제출한다. 재사용할 읽기·선택 응답 필드·정상/결측 처리·화면 위치·필요한 시험만 적는다. 조사에서 설계와 충돌한 사실만 질문한다.

설계자는 목업을 대신 제작하지 않는다. 사용자 확인 전의 목업 작업은 저장소 운영 코드 구현과 구분한다.

## 6. 수용 기준과 검증

- 최신 기준일을 포함한 최대 20개 원본 저장 행을 날짜순으로 표시한다. 21개 이상 입력, 20개 미만 입력, 0개 입력을 구분한다.
- 0 거래량과 결측을 구분하고, 결측을 제거해 창을 바꾸거나 0으로 채우지 않는다. 실제 날짜·단위·값을 표시한다.
- 다중 계좌의 동일 종목은 같은 자료이며 중복 읽기가 없다. 기존 평균·배수·기준일 판정과 나머지 응답 값은 보존된다.
- 접힘·펼침·종목 변경·? 설명을 확인한다. 펼치기로 추가 조회가 발생하지 않는다.
- 관련 백엔드·프론트 시험과 정적 검사로 확인하고, 저장소에서 요구하는 회귀 검사를 따른다. 라이브 자료를 일부러 손상시키거나 외부 장애를 만들지 않는다.
- 사용자 실화면과 검증자 확인 뒤 RESULT로 제출한다. 자료가 이미 있으므로 R0 일정·원장 학습 표본·다음 거래일·OCI 배포를 기다리는 조건은 없다.
- 종료 시 P-10은 **ETF·보유 종목의 저장 거래량 관찰값 및 추이 표시 제공**까지 반영한다. KOSPI 지수 전체 거래량·검증된 거래량 해석·종합 위험 분류를 완료로 표시하지 않는다. 별도 인계 문서는 필수로 만들지 않는다.

이 단계는 저장된 흐름을 실제로 보게 하는 기능으로 끝낸다. 후속 위험 산식이나 복합 지표 개발이 자동으로 따라붙는 단계가 아니다.
