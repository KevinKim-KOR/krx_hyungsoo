# POC5-16 — 저장 종가의 가격 변동성 근거 설계 V1
작성: 설계자 · 2026-10-15 · 독자: 개발자 / 사용자 / 검증자
상태: 다음 범위 지정 · 짧은 PLAN과 개발자 전체 화면 목업 대기

## 1. 현재 위치와 목적
- 사용자 보고의 종료 커밋 `48cb3b8a`를 근거로 POC5-15 종료를 수용한다. 원격·PC를 직접 조회한 확인은 아니다.
- 13·15가 보유 하락 정도와 시장 상태의 조합을 보여 주었다면, 이번에는 **최근 가격 흔들림이 직전 기간보다 커졌는지** 확인하게 한다.
- Q6에 남아 있는 변동성 후보를 저장 가격으로 구체화하는 단계이다. 이미 계산 함수가 있는지는 개발자 PLAN에서 확인한다.
- 완료 모습은 「확인 근거」의 선택 종목 상세에서 **“가격 흔들림(변동성) 보기”**를 펼쳐 최근·직전 값을 비교하는 것이다.
- 대문 요약·종목 목록·하락 구간·현재 상태 문구는 그대로 둔다. 상세에서 필요할 때 보는 근거 하나를 추가한다.
- 이 값은 가격 방향이나 위험 강도 판정이 아니다. 기존 시장 국면·하락 구간과 별개의 관측값이다.

## 2. 계산 계약
- 가격은 기존 PC 가격 흐름과 같은 저장 종가 계열을 쓴다. ETF·지원 보유 개별주를 모두 대상으로 한다.
- OCI 실시간 시세·KRX 무조정 계열·개인 평균매입단가·평가손익률을 섞지 않는다.
- 저장된 날짜의 오름차순 종가 사이 단순 수익률 = 다음 종가 ÷ 직전 종가 − 1.
- **최근 값**은 가장 최근 21개 저장 종가가 만드는 20개 수익률의 모집단 표준편차이다.
- **직전 값**은 그 바로 앞 20개 수익률의 같은 표준편차이다. 둘 다 얻으려면 총 41개 종가가 필요하다.
- 두 기간은 경계 종가 하나를 공유하고 수익률 구간은 겹치지 않는다. 42개 종가나 중첩 rolling 기간으로 바꾸지 않는다.
- 표준편차는 각 수익률에서 해당 20개 평균을 뺀 값의 제곱 평균에 제곱근을 취한다. 분모는 20이다.
- 계산 결과에 100을 곱해 % 단위로 표시한다. 연율화·로그 수익률·위험 점수로 변환하지 않는다.
- 날짜는 **실제 저장 구간**이다. 거래일 캘린더를 새로 구성하지 않고 “20거래일”이라고 단정하지 않는다.
- 화면 이름은 “최근 20구간 / 직전 20구간”으로 하고 각각 실제 시작일·종료일을 함께 확인할 수 있게 한다.
- 기존 함수가 위 정의와 같으면 재사용한다. 연율화·표본 분모·로그 수익률 등 의미가 다르면 조용히 이름만 재사용하지 않는다.
- 다른 산식의 기존 ML feature·운영 계산을 이번 정의에 맞춰 변경하지 않는다.

## 3. 자료와 결측
- 최근 21개 가격이 유효하면 최근 값은 제공한다. 41개가 없어 직전 값을 못 구하더라도 최근 값까지 숨기지 않는다.
- 필요한 창 안의 가격은 날짜 순서가 명확하고 유한한 양수여야 한다. 0·음수·결측·비정상 값은 해당 기간을 계산 불가로 둔다.
- 잘못된 행을 빼고 더 오래된 가격을 끌어와 20구간을 채우지 않는다. 없는 날짜·가격을 보간하지 않는다.
- 이전 기간만 계산 불가이면 “직전 기간 자료 부족/확인 필요”를 해당 값 자리에 짧게 표시한다.
- 기존 PC 가격 기준일 검사를 함께 사용한다. 기준일이 다른 오래된 종목 값을 최신 자료의 비교값처럼 보여 주지 않는다.
- 자기 종목의 변동성끼리 비교한다. KODEX200과 20일 시작일이 다르다는 이유로 자기 유효값을 제외하지 않는다.
- 새 계산을 위해 KODEX200의 과거 41개 가격까지 요구하지 않는다.
- 출처 문자열의 단순 전환을 새 단절 기준으로 만들지 않는다. 기존에 확인된 실제 가격 기준 경계는 재사용하고 서로 다른 가격 의미를 임의 연결하지 않는다.
- 가격 출처·날짜·기간 판정에 기존 계약으로 처리할 수 없는 차이가 있으면 그 차이와 권장안만 PLAN에 올린다.
- 같은 종목 여러 계좌는 같은 가격 근거를 쓴다. 수량·평단·계좌에 따라 변동성이 달라지지 않는다.
- 보유 평가금액이 없더라도 가격 창이 유효하면 계산한다. 평가금액 부족을 가격 부족으로 바꾸지 않는다.

## 4. 비교 표현
| 조건 | 표시 |
|---|---|
| 최근·직전 모두 있음 | 두 값과 “직전보다 커짐 / 작아짐 / 같음” |
| 최근만 있음 | 최근 값 + 직전 기간 확인 불가 |
| 직전만 있음 | 실제 직전 기간 값 + 최근 기간 확인 불가 · 비교 문구 없음 |
| 둘 다 없음 또는 기존 가격 기준일 검사 불통과 | 짧은 사유와 실제 확인 가능한 날짜 · 비교 문구 없음 |

- %는 소수 둘째 자리로 표시한다. 비교 문구도 표시된 두 값으로 결정해 같은 숫자인데 커졌다고 보이지 않게 한다.
- “같음”은 표시 자릿수 기준이며 도움말에 그 뜻을 적는다.
- 임계값으로 고위험·안전·매수·매도를 분류하거나 현재 하락 구간에 가중하지 않는다.
- 기본값 0%로 결측을 채우지 않는다. 실제 변화가 일정해 계산된 0%는 유효한 관측값이다.
- 종목 간 순위나 평균을 이번 화면에서 만들지 않는다. 레버리지 여부로 현재 보유를 임의 제외하지 않는다.

## 5. 화면 — 선택 종목 상세에서만
- 기존 가격 흐름·저장 거래량 근거와 가까운 곳에 접힌 구역 하나를 둔다. 기본은 접힘이다.
- 펼치면 최근·직전 값을 같은 폭으로 정렬하고 비교 문구를 보여 준다. 날짜는 보조 정보로 묶는다.
- 모든 항목을 한 줄에 이어 붙이거나, 날짜마다 별도 큰 줄을 늘리지 않는다. 실제 폭에서 의미 단위로 줄바꿈한다.
- 구역의 ? 하나로 설명을 연다. 15의 클릭형 도움말과 UI-01 버튼 규격을 재사용한다.
- 설명은 “현재 값의 뜻 → 계산 기준 → 지금 해당하는 자료 제한” 순서로 짧게 나눈다.
- “위아래 가격 변화가 얼마나 들쑥날쑥했는지 보여 줍니다. 하락 폭을 뜻하는 값은 아닙니다.”라는 의미를 설명한다.
- 최근·직전 20개 가격 변화의 표준편차이며 연율화하지 않았다는 상세 정의는 도움말에서 확인하게 한다.
- 현재 해당하는 자료 부족·기준일 문제는 기본 표시 영역에 짧게 남긴다. 도움말 속에만 숨기지 않는다.
- 색은 기존 중립 스타일을 사용한다. 커짐·작아짐을 상승·하락 수익 색상이나 위험 경보로 표현하지 않는다.
- 새로운 메뉴·표 열·대문 카드·알림을 만들지 않는다. 기존 ?의 공통 설명을 반복해서 늘리지 않는다.

## 6. 구현 경계
- 기존 PC 근거 GET 응답의 사본에 작은 선택 근거 필드로 연결하는 것을 허용한다. 새 API 경로·DB 표는 필요 없다.
- PC용 읽기·계산 helper에서 처리한다. 공유 builder·PUSH·초안·원장·PARAM은 바꾸지 않는다.
- 필요한 작은 가격 창을 기존 SQLite에서 읽을 수 있다. 새 HTTP 조회·외부 수집·자동 갱신을 추가하지 않는다.
- 새 계산 안에서는 한 요청의 같은 종목 가격 창을 한 번 읽어 재사용한다. 영구 캐시나 새 동기화 체계를 만들지 않는다.
- 기존 5일·20일·KODEX200 대비·구간 판정·선정·비중의 값과 날짜를 보존한다.
- 이미 있는 변동성 함수·가격 읽기를 조사하고 재사용 범위를 결정한다. 단일 대형 파일에 계산을 계속 쌓지 않는다.
- 외부 패키지 설치·운영 DB 쓰기·보유 변경·OCI 배포·cron 변경은 없다.

## 7. 개발자 PLAN과 목업
한 번의 좁은 조사로 아래를 확인한다.
1. 기존 변동성 함수 유무와 정확한 산식·단위·가격 의미. 재사용 가능 여부.
2. 같은 PC 종가 계열의 실제 21·41행 읽기와 날짜·결측·가격 기준 경계 처리 위치.
3. PC 응답 사본과 종목 상세 연결 위치·관련 파일 크기.
4. 실제 보유에서 두 기간 가능/최근만 가능/기준일 불일치 사례의 유무. 없는 상태는 격리 fixture로 보여 준다.
5. 기존 계산·응답을 보존할 시험과 필요한 검사.

- 목업은 개발자가 만든다. 「확인 근거」 전체 화면 1440·1000px에서 구역 접힘·펼침과 도움말 열린 모습을 확인한다.
- 실제 값이면 출처·기록 시점을 적는다. 꾸민 숫자를 실제 PC 측정값으로 쓰지 않는다.
- 사용자가 목업을 확인한 뒤 짧은 PLAN을 설계자에게 제출한다. 판정 전 구현하지 않는다.
- 기존 백로그 전수 조사·완료 단계 전체 재검증·선제 Cleanup을 준비 단계로 추가하지 않는다.

## 8. 검증·종료·기록
- 고정 예: 20개 수익률이 모두 같으면 표준편차 0, +10%와 −10%가 각각 10개이면 모집단 표준편차 10%이다.
- 최근·직전 기간이 구간을 공유하지 않는지, 단위·분모·연율화 없음·표시값 비교를 확인한다.
- 최근만 가능, 일부 가격 비정상, 날짜 불일치, 복수 계좌, 평가금액 결측을 검증한다.
- 기존 구간·시장 조합·선정·비중·보기·조회 수·쓰기·발송 경계 보존을 확인한다.
- 코드 변경에 필요한 관련 시험·정적 검사와 저장소 필수 검증을 수행하고 검증자·RESULT 절차로 종료한다.
- PC 반영과 해당 종목 상세 사용자 확인으로 마친다. OCI pull·첫 영업일을 기다리지 않는다.
- Q6에는 PC의 변동성 관측 후보가 계산 가능해진 범위만 기록한다. factor 타당성·운영 위험 임계·라벨 확정 또는 ML 검증 완료로 승격하지 않는다.
- 기존 RESULT·STATE·PROGRAM_TRUTH·BACKLOG·통합지도를 갱신한다. 별도 인계 파일은 이번 단계의 필수 산출물이 아니다.
