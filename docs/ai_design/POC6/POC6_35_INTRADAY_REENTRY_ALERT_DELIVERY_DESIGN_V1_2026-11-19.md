# POC6-35 장중 재진입 알림 누락 정정 · 설계 V1

2026-11-19 · **개발 PLAN 작성 대기**

선행 단계는 POC6-34(PASS · CLOSED)다. 종료 뒤 형수님이 지시한 메뉴 조정을 수용한다. 개발 보고 기준 main은 `631b14a9`이고, 메뉴 변경은 `4fc36600`이다.

## 현재 문제와 목표

장중 사업군 알림에서 이전에 알렸던 상태가 해소된 뒤 기존 재발송 대기를 충족해 다시 발생해도, 그 회차의 구역 한도에 밀리면 관측 상태가 ‘이어짐’으로 남는다. 다음 회차에도 조건이 이어지고 발송 자리가 생겼을 때 후보로 다시 들어오지 않는 것이 K2다. 개발자가 코드와 메모리 재현으로 확인했으며, 실제 운영 발생 빈도는 미확인이다.

이번 목표는 **구역 한도 때문에 전달되지 않은 재진입 신호를 다음 회차에 현행 조건으로 다시 검토하는 것**이다. 구역 한도에 밀린 상태 변화는 다음 회차 후보가 될 수 있다는 기존 운영 계약을 적용한다.

## 변경 범위와 적용 기준

- K2가 재현된 `sector_signal_state.py`의 관측·후보 처리와 그 결과를 쓰는 직접 경로를 다룬다.
- 재진입을 관측한 사실과 알림을 성공적으로 전달한 사실을 구분한다. 성공 전달은 기존 절차대로 실제로 본문에 포함되어 전체 전송이 성공했을 때 기록한다.
- 기존 신호 판정 기준, 정렬, 구역·일일 상한, 재발송 대기와 전송 실패·부분 전송 처리 계약을 적용한다. 재발송 대기 경계에 관한 K3는 기존 RESULT 판정을 따른다.
- 운영 확인에는 「승인·운영 → 받은 알림 기록」의 [원장 새로고침]과 기존 기록을 사용한다. OCI 적용과 실제 발송은 각각의 승인 범위를 따른다.

## 완료 기준

| 기준 | 확인할 결과 |
|---|---|
| AC1 · K2 재현 | 이전 발송 성공 → 조건 해소 → 재발송 대기 충족 후 재진입 → 구역 한도로 본문 제외 → 다음 회차에도 조건 유지·자리 확보. 같은 고정 사례로 변경 전 누락과 변경 후 후보 재진입을 확인한다. |
| AC2 · 발송 조건 | 다음 회차에 조건을 벗어난 건은 발송 대상에서 빠진다. 구역·일일 상한과 재발송 대기를 적용하고, 전송이 성공한 동일 재진입 건의 반복 발송을 억제한다. |
| AC3 · 운영 확인 근거 | 기존 동기화 전후의 PC 사본 시각과 원장 최신 실행·전송 상태를 같은 실행 건 기준으로 대조한다. 운영 반영 확인 시 자연 발송이 있으면 같은 건의 텔레그램 수신을 대조한다. K2의 고정 사례 검증과 실제 운영에서의 K2 관측 여부는 각각 기록한다. |
