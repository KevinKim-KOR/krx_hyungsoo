# POC6-32 주간 ETF 점검 · V2 RESULT 판정

2026-11-18 KST · 설계자 판정 · 수신 개발자

**조건부 PASS.** 검증자 r2 `VERIFIED`와 실제 화면 확인을 수용한다. 현재 진행 중인 서버 전체 회귀 결과와 [비교 상세]의 선택 인계를 아래 기준으로 기록하면 RESULT를 PASS로 확정한다. I-18의 교체 대안 목록은 후속 보완으로 등록한다.

## 1. I-18 판정 · 교체 대안 목록은 필요하다

11/16 실측에서 **보유 ETF 26개 중 수익률 상·하위 30개 목록 안에 같은 공식 기초지수의 후보가 있는 보유 ETF는 0개**였다. 이 결과는 순위 목록의 범위에서 확인한 것이다. 주간 점검은 고른 후보의 투자 대상·성과·보유 겹침을 읽는 데 쓸 수 있고, 승인된 AC1의 상세 비교는 사용자가 고른 두 상품의 비교 가능 여부를 보여 준다. 같은 지수를 따르는 교체 대안을 **찾는 기능**은 후속 범위로 잡는다.

- [비교 상세]에서 한쪽 ETF를 고르면, 보관된 전체 ETF 기준정보에서 **같은 공식 기초지수의 다른 ETF**를 고를 수 있게 한다. 실제 조회에는 보관된 목록과 기준정보의 날짜를 사용한다. 기준정보에서 지수를 확인할 수 없는 경우와 확인한 범위에 다른 상품이 없는 경우를 표시한다.
- 상품 구조·환헤지·비용의 확인된 차이는 상품을 고를 때 함께 보여 준다. 사용자가 대안을 직접 고른 뒤, 비교 기간과 가격 상태가 맞으면 비교를 표시한다. 주간 수익률 순위는 후보 발굴에 쓴다.
- 결과서에 `I-18 · 같은 공식 기초지수 교체 대안 조회`를 후속 항목으로 남긴다. 재검토 시점은 실제 보유 상품의 교체 대안을 고를 필요가 생겼을 때다. 그때 전체 보관 목록에서 공식 지수가 일치하는 사례를 먼저 확인한다.

## 4. PASS 확정 조건

1. **진행 중인 서버 전체 회귀의 통과 결과**를 결과서에 기록한다. 최종 반영 대상과 맞는 검사 결과를 남긴다.
2. **[비교 상세]의 선택 인계**를 한 번 확인한다. 보고서의 ‘두 칸 빈 선택’은 선택 없이 직접 열 때의 동작으로 수용한다. 주간 ③ 또는 보유 화면에서 사용자가 ETF 하나를 골라 열었다면 그 ETF를 해당 칸에 표시하고 상대 칸의 선택은 사용자에게 맡긴다. 이는 11/17 Q11의 인계 기준이다. 이미 적용된 경우 확인 근거를 기록하고, 양쪽이 모두 비는 경우 해당 진입 동선을 정정한 뒤 확인을 기록한다.

두 조건이 충족되면 결과서에 바로 **설계자 RESULT PASS**를 기록하고, 사용자 승인에 따른 커밋·main 합치기 절차로 이어 간다. 실제 Safari·Chrome의 클립보드 동작은 개발자 보고상 미확인이다. 운영 화면에서 처음 복사를 쓸 때 사용 브라우저의 동작을 확인한다.
