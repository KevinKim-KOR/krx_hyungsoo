## 2. F3 — 이번 단계 안에서 표시를 맞춘다

### 2-1. 판단

`etf_master`가 통째로 비었을 때 `[대상]`과 상태 줄이 ‘개별 종목’으로 단정하고 새 이동평균은 ‘ETF 구분 확인 불가’로 표시되는 상태를 최종 결과로 남기지 않는다. 같은 원문을 AI에 전달하는 기능이므로, 분류를 모르는 상태와 개별주로 확인된 상태를 구분해야 한다.

개발자가 기존 줄의 변경을 임의로 확대하지 않고 F3를 판단 요청으로 남긴 처리는 적절하다. **이 판정으로 해당 PC 미리보기의 표시 정정을 이번 POC6-07 안에 포함한다.** 새 단계나 새 PLAN을 만들지 않는다.

### 2-2. 정정 범위

- 새 이동평균 조립에서 이미 얻는 ETF·개별주·확인 불가의 분류 결과를 PC 미리보기의 대상·관련 상태 줄에도 재사용한다. 추가 분류 조회는 하지 않는다.
- 분류 자료가 비어 확인할 수 없는 경우 `[대상]`의 종목명·ticker는 유지하고, 종목 구분은 `구분 확인 불가`로 표시한다.
- 이 경우 기존 `대상 아님(개별 종목)` 문구를 만드는 해당 분기는 `확인 불가(ETF 구분 자료를 확인하지 못했습니다)`로 맞춘다. 이동평균의 기존 확인 불가 사유와 뜻이 같아야 한다.
- 정상 분류 자료에서 확인된 개별주는 기존 대상 밖 처리를 유지한다. 확인된 ETF와 정상 후보의 기존 글은 바꾸지 않는다.
- 분류와 무관하게 유효한 가격 근거까지 지우지 않는다. 반대로 분류 확인이 필요한 값을 0·정상·대상 밖으로 대신하지 않는다.
- 분류 자료의 실제 읽기 실패는 기존 시스템 오류 계약을 유지한다. 자료가 비어 있는 경우와 DB 오류를 하나로 합치지 않는다.

정정은 PC 미리보기 조립에 한정한다. 공유 보유 builder·PUSH·OCI·DB 스키마·세션 저장 구조를 바꾸거나 다른 화면의 분류 처리까지 일괄 정리하지 않는다. 예전에 저장한 원문은 당시 글 그대로 보존한다.

## 3. 같은 D 가격 근거 대조 — 설명을 실제 범위로 좁힌다

### 3-1. 수용하는 검사

제출 결과서의 대조 입력은 다음과 같다.

| 경로 | 기존 입력과 대조하는 것 | 해석 |
|---|---|---|
| 보유 | 기존 응답의 시작일 2개·5/10/20 변화율을 새 60행에서 같은 정의로 재계산한 값과 비교 | 일부 가격 근거의 모순 검사다. 기존 응답의 원시 종가 4개를 직접 비교하는 검사는 아니다. |
| 후보 | 기존 목록의 기간·변화율 대조와, 미리보기에서 이미 읽은 최근 최대 21행의 날짜·종가·출처 대조 | 보고된 행 범위의 직접 대조를 포함한다. 전체 60행이나 미리보기 전체의 동일 판을 보장하지 않는다. |

추가 조회 없이 이미 확보한 입력으로 모순을 확인하는 이 범위를 수용한다. 이번에 보유 응답에 원시 가격을 추가하거나 전체 조회를 단일 트랜잭션으로 개편하라고 요구하지 않는다.

### 3-2. 결과서 정정

결과서 §4-1 표의 ‘대조되는 원시 자료’와 §5의 ‘보유는 D·D-5·D-10·D-20 행만 대조’라는 표현을 위 실제 방식으로 정정한다. 해당 행은 변화율 계산에 관여하는 끝점이지, 기존 응답에서 각 종가를 직접 받아 일치 여부를 확인한 행이 아니다. §0·검증자 전달 메모 등 현재 요약에 같은 뜻의 표현이 있으면 함께 맞춘다. 과거 검증자 판정 원문은 고치지 않는다.

보유 경로는 검사 사이 행의 변경뿐 아니라 **비교하는 변화율이 그대로인 동일 배율의 가격 변경도 검출하지 못할 수 있다.** 이는 제출된 검사 방식에서 도출되는 한계이며, 실제 발생 사실로 기록하지 않는다. 대조 가능한 기존 값이 없거나 60행 밖이라 검사하지 않은 항목도 동일 판이 확인됐다고 쓰지 않는다.

`basis_checked`는 수행한 검사 항목의 기록으로 해석한다. 수신 판 전체가 같다는 보증이나 완전한 원시 가격 대조 결과로 설명하지 않는다. 수신 시각·NAV 시장가·평단을 비교 대상에서 제외한 처리는 수용한다.

## 4. 시장 흐름 차트 사건 점 수정

사용자가 이번 단계에 함께 고치도록 승인했고, 수정 전 실패·수정 후 통과 시험과 경고 소멸 기록이 있으므로 수용한다.

허용한 변경은 **같은 자료·같은 날짜·같은 위치의 표시 점만 하나로 만드는 것**이다. 그날의 사건 두 건, 사건 설명 줄, 원래 수치·문장은 모두 유지한다. 서로 다른 자료의 사건이나 날이 다른 점까지 합치지 않는다. 백엔드 사건 계산·응답·수집 정책의 변경은 포함하지 않는다.

이 수정을 이유로 POC6-01 전체를 다시 검증하거나 새 차트 개편을 시작하지 않는다.

## 5. 정정 후 확인 — 변경분만

F3는 코드 변경이므로 r2 검증 범위와 그 뒤 변경분을 구분한다. 다음을 격리 자료로 확인하고 검증자는 이 차이만 확인한다.

1. **분류 표가 비어 있는 보유 미리보기:** 종목명·ticker는 보존되고, 대상·관련 상태·이동평균이 모두 구분 확인 불가의 뜻으로 일치한다. 개별주로 확정하는 문구나 대체 숫자가 생기지 않는다.
2. **정상 분류 자료의 ETF와 개별주:** 기존 구분·대상 밖 처리와 정상 근거가 유지된다. 실제 DB 읽기 실패도 기존 오류 계약을 유지한다.
3. **같은 원문 연결:** 정정된 분류 문구도 미리보기·복사·AI 세션에 같은 canonical 글로 전달된다. 기존 관련 시험을 재사용하고 변경 파일에 필요한 정적 검사를 수행한다.

§3 문서 정정은 제출된 검사 입력·코드 설명과 대조한다. 이를 위해 새 가격 대조 구현이나 별도 대규모 변이 시험을 추가하지 않는다.

F3는 정상 자료의 화면 배치·숫자를 바꾸지 않는 오류 상태 문구 정정이다. 격리 상태의 원문 확인으로 마무리할 수 있으며, 전체 목업·사용자 정상 실화면 확인·전체 백엔드 회귀·전체 프론트 시험·기존 57종 변이를 다시 반복하지 않는다. 새로운 실패나 다른 코드 변경이 생기면 그 영향 범위만 추가 확인한다.

## 6. 종료 절차

1. 본 판정 원문을 보관하고, 결과서에 F3 정정 내용·§3 설명 정정·변경분 확인 결과를 추가한다. 판정 시점에는 아직 정정 전임을 구분한다.
2. 검증자가 F3 변경분의 통과를 확인하면 본 조건 충족으로 본다. **이 판정 범위대로 끝났다면 설계자 RESULT를 다시 요청하지 않는다.**
3. 종료 기록과 STATE·PLAN·PROGRAM_TRUTH의 상태를 맞추고, 사용자 승인 범위로 커밋·push한다. 아직 유효한 승인이 없다면 정정 결과를 보여 준 뒤 그때 승인받는다. 본 판정은 원격 push의 새 사용자 승인으로 대신하지 않는다.
4. PC 반영과 커밋·push 성공 사실을 보고하고 `IMPLEMENTED_VERIFIED_CLOSED`로 종료한다. OCI pull·cron·키·업로드·별도 handoff 문서는 없다.

종료 범위는 선택 ETF 관측과 검토 질문의 기존 AI 흐름 연결이다. #3·#55·#57의 관측 제공분만 기록하고 정량 기준·종합 위험 분류·결합 효용은 미완료로 유지한다. #62·Q6 OPEN·운영 ML 미승격과 POC6-06 전향 기록은 바꾸지 않는다.
