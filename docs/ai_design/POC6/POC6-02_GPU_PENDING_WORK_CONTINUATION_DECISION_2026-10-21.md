# POC6-02 GPU 실측 대기 중 진행 판정
판정자: 설계자 · 2026-10-21 · 독자: 개발자 / 사용자

**GPU 실측은 POC6-02 최종 종료의 남은 확인 항목이다. 맥북 구현·CPU 실행·코드 검증·실행 묶음 준비·독립적인 후속 설계까지 중단시키는 전체 프로젝트 게이트가 아니다. PC 환경 답이나 GPU 실행 가능 시각을 기다리며 개발을 멈추지 않는다.**

근거: 설계 개정 2, PLAN V1, PLAN 판정(최소 4종·맥북/RTX 실행 분리), 사용자 '5시간 이상 기다리지 않고 다른 작업 진행' 요청.

## 1. 지금 바로 마무리할 POC6-02 작업
현재 제공된 보고는 PLAN 단계다. 아직 다음 작업을 진행할 수 있다.
1. 맥북에서 snapshot·표본·기존 두 기준·CPU HGB·MLP 공통 학습 코드·평가·보고서·GPU 결과 취합을 구현한다.
2. 알려진 fixture로 표준화·가중 손실·gradient 누적·시간 분리·행 연결·결측·실패·누수·판정 경계를 확인한다. CUDA가 없어도 가능한 수학·형식 검증은 수행한다.
3. 4종의 잠긴 snapshot·recipe로 공식 CPU 부분을 실행해 저장한다. 입력·설정·제외 사유를 고정하며 GPU 결과를 보고 다시 고르지 않는다.
4. Windows 실행 묶음과 실행 안내를 완성한다. Python/torch/CUDA 환경 확인, GPU 부재·실패 기록, 결과 파일 작성과 맥북 취합을 임시 결과로 시험한다. 가짜 결과를 실제 GPU 근거로 쓰지 않는다.
5. 독립 검토·관련 검사·필요한 전체 회귀와 검증자 코드 검증을 GPU 실측 전에 할 수 있다. 실제 GPU 실행만 '미확인'으로 구분한다. 이를 위해 검증 전체를 나중으로 미루지 않는다.

검증자는 코드·CPU·격리 검증의 확인 범위와 실제 CUDA 실행 미확인을 구분해 기록한다. GPU가 아직 없다는 사실을 코드 결함과 혼동하지 않으며, GPU 실측까지 완료됐다고 VERIFIED 범위를 넓히지도 않는다.

## 2. 장비 사용 가능 뒤 남는 일
- 같은 검증 대상 코드에서 만든 묶음·같은 입력/recipe로 RTX PC에서 GPU 부분만 실행한다.
- 맥북이 digest·구간·행 ID·장치·환경·실행 상태를 확인해 이미 저장된 CPU 결과와 취합한다. GPU_NOT_RUN을 실학습으로 대체하지 않는다.
- 코드와 recipe가 검증 이후 그대로라면 실제 실행 기록·출력의 확인만 보완한다. 이를 이유로 전체 회귀·CPU 공식 실행·전체 검증을 처음부터 반복하지 않는다. 새 결함이나 코드 변경이 생겼을 때만 해당 범위를 재검증한다.
- 그 뒤 최종 RESULT·설계자 판정·기존 커밋 승인 절차로 종료한다. GPU 미실행인 동안 POC6-02 전체 종료를 선언하지 않는다.

## 3. 앞 작업이 끝나도 GPU를 기다려야 한다면
독립적인 후속 설계로 **가격 이력의 기준 일관성 보완**을 준비한다. 이는 모델 성과와 무관하게 이미 발견된 실제 자료 문제다.
- PLAN 실측상 긴 이력이 있어도 가격 경계 때문에 제외되는 ETF가 8종이며, 그중 6종은 2026-04-20 경계 하나의 영향을 받는다. 상장이 짧은 14종과 구분한다.
- 목적은 가격 의미를 무시하고 종목 수를 늘리는 것이 아니라, 다른 수집 시점의 가격 묶음이 섞인 문제를 일관된 연구용 자료로 다룰 방법을 정하는 것이다.
- 현재 저장 행·원천·수집 시점과 기존 가격 조회 경로를 재사용해 최소 보완 계획을 세운다. 이미 보고된 원인을 저장소 전체 재감사로 다시 조사하지 않는다.
- 필요하면 같은 원천에서 같은 기준 시점의 이력을 한 번에 확보해 **별도 연구 사본**으로 검증하는 안을 PLAN에 적는다. 새 조회·저장 변경의 실제 범위와 필요한 승인 여부는 그 PLAN에서 확정한다. 이 판정만으로 새 수집·라이브 DB 덮어쓰기를 실행하라는 뜻은 아니다.
- 현재 4종 실험의 snapshot·기간·모델·판정 기준은 그대로 둔다. 새 자료를 그 실험에 끼워 넣거나 GPU 결과 전후로 공식 실험을 교체하지 않는다. 보완 자료로 새 성과 실험을 자동 시작하지 않는다.
- 신규 factor·메뉴·API·운영 알림 기능을 추가하지 않는다. 후속 설계는 지금 작성할 수 있으며, 실제 구현은 그 보완 범위를 확정한 뒤 별도로 진행한다.

이는 기다리는 시간을 채우려고 기능 목록을 늘리는 지시가 아니다. 현재 ML 비교의 대상 범위를 제한한 자료 문제를 다음에 정확히 다룰 준비다.

## 4. 작업 분리와 유지 계약
- 검증 중인 02 소스·staged 범위를 고정한다. 후속 문서나 코드가 섞일 수 있으면 별도 작업 경로나 worktree를 사용하며, 고정 목적으로 승인 없는 커밋을 강요하지 않는다.
- 02 성과에 의존하는 운영 모델 채택·PUSH 변경·위험 등급 도입은 앞당기지 않는다. 결과와 무관한 구현·검증·후속 설계의 진행은 허용한다.
- 가격 경계 무시·샘플 복제 부하 시험·새 모델 탐색으로 시간을 쓰지 않는다. CPU·GPU 실제 활용 요구와 기각 가능성은 그대로다.
- 키움·Yahoo·KRX 추가 조회나 회사 IP 설정을 02 진행 조건으로 넣지 않는다. 추가 환경 설치가 필요하면 실제 필요한 최소 범위만 한 번 확인한다.
