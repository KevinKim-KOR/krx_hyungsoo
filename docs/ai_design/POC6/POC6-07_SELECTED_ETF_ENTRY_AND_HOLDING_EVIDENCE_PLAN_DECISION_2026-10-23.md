## 1. 판정과 적용 범위

제출 PLAN을 수용한다. 선택 ETF 한 종목의 저장 종가에서 MA20·MA60과 표시값 기준 위치를 만들고, 기존 근거·검토 질문과 함께 복사 및 AI 세션으로 전달하는 구현을 진행한다.

판정은 제출된 설계서와 PLAN을 대조한 결과다. 사용자 목업 확인 기록을 수용하며, 설계자가 로컬 목업이나 저장소 구현을 직접 실행·검증했다는 뜻은 아니다. 산술 대조·화면 높이·전달 문자열 일치 수치는 개발자의 목업 단계 보고로 구분한다.

§2의 세 선택은 모두 사용자가 확인한 주 목업과 같다. §3은 기존 설계의 자료 검사 의미를 명확히 하는 내용으로, 정상 화면의 배치나 승인된 문구를 바꾸는 지시가 아니다. PLAN에 반영한 뒤 재판정이나 목업 재확인 없이 구현한다.

설계 §2의 ‘기존 6개 근거 묶음’은 실제 미리보기 전체 상자 수를 정확히 설명하지 못한 표현이다. PLAN이 확인한 **기존 9개 묶음을 유지하고 검토 질문을 더해 10개로 구성**하는 안을 수용한다. 이동평균을 위한 별도 관측 카드를 만들지 않고 기존 가격 흐름 묶음에 넣는 원칙은 유지한다. 상자 수를 6개에 맞추려고 기존 근거를 합치거나 삭제하지 않는다.

## 3. 자료 검사 해석

### 3-1. 같은 D와 가격 근거

선택 종목에 한해 D 이하 원본 60행을 read-only로 한 번 더 읽는 안을 수용한다. 기존 가격 흐름·흔들림 읽기를 바꾸거나 공통 조회로 재구성할 필요는 없다.

다만 **날짜가 같다는 사실만으로 같은 가격 근거임을 보장했다고 기록하지 않는다.** 기존 조립 과정에서 이미 확보한 동일 D의 원시 종가·가격 출처 등과 새 읽기의 D 행이 모순되면, 새 이동평균 관측을 확인 불가로 처리한다. NAV 시장가·평단과 비교하지 않는다. 수신 시각만 다르다는 이유로 같은 값과 가격 의미까지 서로 다르다고 단정하지도 않는다.

이미 읽은 원시 자료를 내부 인자로 전달해 확인하는 범위에서 처리한다. 이를 위해 새 DB 조회·외부 조회·API 경로·전체 조회의 트랜잭션 개편을 추가하지 않는다. 비교 가능한 공통 근거의 범위와 읽기 사이 변경을 확인하는 방법을 RESULT에 적는다. 전체 미리보기가 하나의 원자적 스냅샷이라는 보장은 이번 범위가 아니다.

보유는 기존 가격 기준일 불일치 정책을 유지하고, 후보는 기존 판정대로 자기 D를 쓴다. 후보의 목록 기준일과 미리보기 읽기 끝일이 다를 때 서로 맞춰 넣지 않는 PLAN의 처리를 수용한다.

### 3-2. 원본 창과 창별 실패

MA20은 끝 20행, MA60은 끝 60행을 각각 검사한다. D 포함 단순평균, 유한한 양수 종가, 허용 출처, 창 내부 연결 검사와 표시값 비교를 수용한다. MA60 앞쪽의 문제를 MA20 실패로 확대하지 않는다.

설계 §3-2의 날짜 검사도 유지한다. 해석할 수 없는 날짜나 중복 행을 조용히 제거해 개수를 채우지 않는다. 기존 날짜·가격 연결 검사 접점을 재사용하고, 새로운 휴장일 달력이나 별도 경계 탐지를 만들지 않는다. 자료 구멍이 없는 연속 거래일이라는 의미를 덧붙이지 않고 ‘20/60개 저장 종가’로 설명한다.

연결은 각 창 내부만 검사한다. 창 첫 행 이전의 연결은 그 평균의 검사 대상이 아니다. 창 내부 change 손상은 해당 평균의 가격 기준 확인 사유로 처리하고, 실제 DB 열기·읽기 실패는 기존 시스템 오류 계약을 따른다. NAVER_FDR의 부분 검사 한계는 기존 설명을 유지한다.

### 3-3. ETF 판별

기존 미리보기의 ETF·개별주·구분 확인 불가 처리를 재사용한다. 정상적으로 읽은 분류 자료에서 개별주로 처리하던 종목은 이번 관측의 대상 밖이다.

PLAN §2-2의 ‘etf_master에 없음 → 개별 종목’은 **분류 표 자체가 없거나 읽기에 실패한 경우까지 개별주라고 단정하는 뜻으로 적용하지 않는다.** ETF 여부를 확인하지 못한 경우에는 기존 확인 불가/오류 계약을 따른다. 새 이동평균을 계산하려고 대상 밖 종목을 ETF로 추정하지 않는다.

## 4. 계산·응답·원문 연결

- 숫자는 기존 `intl_fixed(v, 2)`를 재사용한다. 실제 표시값으로 순서를 정하며 같은 표시값은 `=`로 묶는다. 동률 안의 이름 순서는 종가·MA20·MA60으로 고정한다.
- D 종가와 두 평균이 모두 유효할 때만 전체 위치를 만든다. 상태명·색·질문을 통해 매매 신호나 위험 등급으로 바꾸지 않는다.
- 선택 필드 `moving_average`와 원문은 같은 서버 조립 결과에서 만든다. 클라이언트가 선택 필드로 별도 숫자 글을 재생성하지 않는 안을 수용한다.
- 미리보기·복사·AI 세션 전달은 질문까지 포함한 동일한 canonical 문자열이다. 질문을 수정해 저장한 경우에도 원래 근거를 보존한다.
- 과거 응답에 선택 필드가 없어도 기존 글을 그대로 표시한다. 과거 세션을 현재 평균으로 보충하거나 일괄 변환하지 않는다. 세션 저장 구조와 새 TypeScript 필드 추가 없이 이 계약을 지킬 수 있다는 PLAN의 구조를 수용한다.

## 5. 파일과 화면 범위

새 `app/pc_selected_moving_average.py`에 읽기·검사·계산·표시 위치 조립 책임을 두고, 기존 파일에는 연결과 상수·선택 응답 필드만 추가하는 구성을 수용한다. 기존 파일이 길어졌다는 이유로 이번에 주변 모듈을 일괄 재구성하지 않는다.

사용자가 확인한 전체 화면 목업을 구현 기준으로 한다. 1440px 높이 유지, 1000px 약 198px 증가라는 개발자 보고를 수용한다. 이 판정을 계기로 미리보기 전체 배치·차트·필터·선택 동작을 다시 개편하지 않는다.

기존 가격 흐름·동일 기간 RS·거래량·흔들림, 같은 종목의 여러 계좌 합산 비중·손익은 유지한다. 공유 보유 근거 builder·시장 국면 계산·PUSH·OCI·cron·PARAM·수집 경로·보관소 정본 전환은 변경 범위가 아니다.
