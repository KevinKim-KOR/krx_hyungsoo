## 2. Q1 — Homebrew·libomp 공식 경로 선택

**(a)를 선택한다.** macOS PyPI wheel 사용에 OpenMP가 필요하고 `brew install libomp`를 안내하는 공식 Python 패키지 문서와 맞는다.[1] 이는 새 Homebrew·시스템 라이브러리 설치가 이미 승인됐다는 뜻은 아니다.

개발자는 실행 전에 다음을 **한 승인 묶음**으로 제시한다.

1. 사용자 Mac의 Homebrew 설치와 필수 의존성 확인. Command Line Tools 등 추가 도구가 없어서 설치가 필요하면 그 범위도 먼저 표시한다. 연구에 필요 없는 패키지·운영 Python 교체는 포함하지 않는다.
2. Homebrew의 libomp 설치. 설치된 libomp 판·실제 로드 경로·환경을 기록한다. Homebrew의 Python용 LightGBM 대신 설계대로 연구 venv에 고정 wheel을 설치한다.
3. PLAN에 적은 LightGBM 4.7.0 wheel과 해시 고정 설치. 기존 numpy·scipy 등은 무단 갱신하지 않는다. 새로 필요한 의존성이 드러나면 같은 승인으로 범위를 넓히지 않는다.

승인 후 import·버전·실제 OpenMP 로드와 작은 가짜 자료의 CPU 학습/저장/복원을 확인한다. 공식 자료의 학습이나 성과를 설치 확인에 섞지 않는다. scikit-learn 동봉 libomp 연결, dylib/rpath 패치, 보안 설정 완화, MacPorts 병행, 소스/무스레드 빌드, 다른 모델 대체는 이번 경로에 넣지 않는다.

승인 전에도 라이브러리를 필요로 하지 않는 봉인 어댑터·정의·장부·가짜 자료 시험은 구현할 수 있다. 필요한 환경 확인이 끝나기 전 공식 실행은 열지 않는다. 설치 실패면 실제 오류와 필요한 다음 선택만 보고하며 모델 성과 실패로 쓰지 않는다. 설치 작업은 90분 공식 연구 실행 예산과 구분해 기록한다.

## 3. Q2 — 미확정 보유 평가를 가정 정산으로 바꾸지 않음

**(a)를 유지한다. (b)의 마지막 종가/NAV 정산과 (c)의 만기형 추가 제외는 채택하지 않는다.**

### 3-1. 용어와 선택 이유

PLAN이 직접 확인한 것은 **해당 종목의 마지막 저장 행이 전체 자료 끝보다 이르다**는 사실이다. 공식 상장폐지·합병·코드 변경·만기·자료 중단과 실제 정산 시각/금액을 모두 확인한 것은 아니다. 127개는 우선 ‘자료 끝 전에 계열이 끝나는 종목’으로 적고, 상장폐지가 별도 근거로 확인된 것만 그 명칭을 사용한다. 검증 11·시험 56도 같은 한정으로 기록한다.

마지막 종가나 공표 NAV는 매도 체결 또는 실제 지급된 정산금의 증거가 아니다. 마지막 행 다음 날 현금으로 받은 것으로 두면 거래 불가 보유를 임의로 거래 가능한 현금으로 바꾼다. 마지막 행을 그때 미리 알 수 있었다고 가정할 위험도 있다. 합성 가격지수 연구라는 한정만으로 이 가정을 사실처럼 넣지 않는다.

미래에 계열이 끝나는 127종을 통째로 빼거나 만기형 30종을 이번에 추가 제외하지 않는다. 현재 설계의 대상은 유지한다. 새로운 정산/제외 시나리오·민감도 연구도 이번 범위에 자동 추가하지 않는다.

### 3-2. 구현에서 명확히 할 처리

- 정상 공표 종가·유효 연결이 있고 거래량만 0인 날은 기존 설계대로 평가할 수 있다. 매도 체결은 못 하므로 이연한다. 무거래를 곧바로 종목 소멸·평가 불가로 바꾸지 않는다.
- 실제 보유 중인 종목의 예정 시장일에 필요한 공표 행/연결 가격이 없어 평가를 확정할 수 없으면, **그 시점까지의 정보로** 미확정 사건을 남긴다. 미래의 마지막 행 날짜를 이용해 미리 매도하지 않는다.
- ticker·최초 미확정 날짜·마지막 유효 날짜·수량·마지막 확인 평가액/비중·미체결 매도 의도·원인 코드를 기록한다. 마지막 가격을 진단용으로 보여 줘도 확정 일별 NAV나 정산 현금으로 사용하지 않는다.
- 학습 정답도 없으면 없음으로 둔다. 0원·마지막 종가 이월·NAV 배율로 정답을 채우지 않는다. 제외 사유·가용률을 보존하며 이 누락이 학습 표본에 주는 한계를 결과서에 적는다.

### 3-3. 불필요한 실행을 줄이는 중단 순서

설계 §5의 ‘검증 중 어느 설정이든 평가 불확정이면 선택 중단’을 그대로 적용한다. 검증의 어느 포트폴리오가 CHECK_REQUIRED가 되면 **정상 설정만 골라 비교를 진행하지 않는다.** 이미 계산한 예측·확인된 장부·사건을 보존하고 아직 하지 않은 선택/시험/학습은 열지 않는다.

시험 L/B/K의 필수 곡선에서 같은 문제가 생기면 전체 H1/후속 검토 후보 판정을 NOT_JUDGED로 둔다. 확인된 구간의 진단 수치는 남길 수 있지만, 종료일을 앞당겨 새 합격 결과를 만들거나 미확정 종목을 뺀 새 곡선으로 바꾸지 않는다. 남은 47회나 다른 비용 장부를 끝내기 위한 실행을 강제하지 않는다.

이는 **현재 가격 자료만으로 전체 H1을 판정하지 못할 가능성을 받아들이는 결정**이다. 이 경우 PRICE_GAIN_NOT_SHOWN이나 ML 실패라고 결론내리지 않는다. 실제로 미확정 보유가 발생했을 때 필요한 정산 근거를 좁게 특정해 다음 결정을 요청한다. 지금 127종 전체의 새 외부 조사를 열지는 않는다.

## 4. Q3 — 분기 말 신호의 새 모델 적용 수용

개발자 안을 아래 조건으로 수용한다. 모델 번호를 신호일의 달력 분기나 실행일 분기만으로 정하지 않고, **정보 차단일 cutoff가 신호일 D 이하인 모델 가운데 가장 최근 판**을 사용한다. cutoff 당일 종가 뒤에 학습·예측한 판도 t+2 실행 전에 준비할 수 있는 이번 재생 가정 안에서 허용한다.

- 2017-12-28 종가 후 첫 신호에는 cutoff=2017-12-28인 2018Q1 모델을 쓴다. 그 학습 정답은 기존 ‘cutoff보다 5거래일 앞서 성숙’ 조건을 그대로 지킨다.
- 2020-12-30 검증 마지막 종가 평가와 설정 선택을 먼저 확정·저장한다. 그 뒤 선택된 구조만으로 cutoff=2020-12-30인 2021Q1 모델을 학습하고 같은 날짜의 시험 첫 계획을 만든다. 실행은 2021-01-05다.
- 검증 곡선에는 2020-12-30 신호의 2021년 체결을 넣지 않는다. 구간 밖 주문/신호를 예측 없이 미실행으로 기록할 수 있으며, 이를 위해 미선택 구조의 2021Q1 모델을 추가 학습하지 않는다.
- 어떤 신호의 t+2 실행이 다음 분기여도, 새 모델 cutoff가 신호일 뒤라면 그 새 모델을 쓰지 않는다. 신호 이후 며칠의 정보를 순위에 섞지 않는다.

잠금에는 모델 id·cutoff·실제 학습 시각·예측 시각·신호일·예정 실행일을 연결한다. 과거 재생의 가상 정보 시각과 현재 PC의 실제 계산 시각을 구분한다. 시험 결과를 본 뒤 설정을 바꾸지 않는다. 47회는 이 시각 계약에서 나온 최대 횟수이며, 횟수에 맞추려고 미래 모델을 쓰는 것이 아니다.

## 5. Q4 — 유동성 창 t−19..t 확정

신호일 종가 후 판단하므로 **최근 20시장거래일 t−19..t, 신호일 포함**으로 확정한다. 같은 구간의 원시 종가×원시 거래량 평균을 쓴다. 정상 저장 0은 포함하고 빠진 날짜를 건너뛰지 않는다. 신호일 거래량>0 조건은 따로 유지한다.

이 결정은 §4 입력의 VOLUME_RATIO_w 창(t−w..t−1, 당일 제외)을 바꾸지 않는다. 두 창을 공용 함수 하나의 암묵적 기본값으로 합치지 않는다.

실제 `ACC_TRDVAL`과 대용치가 다른 26행 보고는 수용한다. 이번 자격은 이미 설계한 대용치로 유지하며 ‘실제 거래대금 1억원 이상’이라고 표현하지 않는다. 실제 칸으로 기준을 교체하거나 그것으로 생기는 성과 차이를 이번에 추가 계산하지 않는다.

## 6. 구현·검산 보완과 예외 문장

PLAN의 신규 어댑터 비유한 검사와 무거래 구분을 수용한다. 원시 값뿐 아니라 사용되는 연결 지수·합성 가격도 유한/양수와 관계를 확인한다. NaN/Infinity를 정상 수치나 0으로 통과시키지 않는다. 공용 reader 수정은 없다.

verify는 장부의 수량·현금 항등식만 확인하지 않는다. **저장된 고정 점수와 시점별 입력에서 공통 정책을 다시 적용해** 상위 5/10 유지·주간 편입 한도·보호 이탈·4회 재진입 대기·중복 주문·미체결·모델 적용 시각이 실제 의도/체결과 맞는지도 확인한다. 기존 정책 함수를 재사용한 재생과 독립 손계산/장부 검산을 조합하며, 별도 범용 broker 엔진을 만들지 않는다.

아래 격리 확인을 기존 설계 시험에 포함한다. 시험 숫자나 전체 회귀 횟수를 새로 요구하지 않는다.

- 정상 종가/거래량 0 매도 이연과, 실제 보유의 첫 미확정 평가를 구분. 가짜 NAV/종가 정산이나 소급 매도 불가.
- 검증 한 설정이 미확정이면 다른 정상 설정을 골라 시험을 열지 않음. 시험 미확정이면 미실행 영역과 NOT_JUDGED 이유 보존.
- cutoff=D 적용·cutoff>D 거부, 2020년 마지막 평가→선택→2021년 첫 계획 순서. 구간 밖 검증 주문 때문에 추가 fit하지 않음.
- 두 유동성/거래량 평균 창의 하루 경계, 0 포함, 잘못 바꾼 주문 정책을 장부 항등식만으로 통과시키지 않음.

기반 문서 세 곳의 연구 예외는 PLAN에 제시한 다음 문장을 그대로 확정한다. 기존 예외·Q6 운영 상태는 보존한다.

> POC6-11 H1에 한해 기존 봉인 KRX 자료로 가격·거래량 30열, 60거래일 상대성과 순위와 CPU LightGBM을 연구한다. 고정 주간 모의 운용의 합성 가격지수 결과만 비교하며 실계좌/추천 출력/OCI/PUSH/기존 전향 모델에는 적용하지 않는다. Q6 OPEN과 운영 ML 미승격은 유지한다.

## 7. 다음 순서·종료 경계

개발자는 이 판정 원문을 보관하고 PLAN에 적용 내용을 기록한다. 이 내용대로만 반영하면 **PLAN 재제출은 필요 없다.** 새 충돌이나 추가 범위가 드러나면 해당 부분만 다시 질문한다. 같은 POC6 안의 별도 handoff는 만들지 않는다.

설치가 필요한 범위는 §2의 사용자 승인을 받은 뒤 실행한다. 본 판정은 커밋·push·시스템 설치의 새 사용자 승인이 아니다. 기존 승인이 실제로 해당 범위를 포함하면 재질문하지 않는다. 설치 승인과 별개로 가능한 구현·격리 확인은 계속할 수 있다.

공식 가격 입력·60거래일 목표·30열·모델 구조/선택·운용·20/40bp·효용/위험 기준·90분/8GiB 예산은 이번 명시 외 변경하지 않는다. 실제 실행·산출물 검증 뒤 RESULT를 제출한다. 정답 부족/평가 미확정이 먼저 드러나면 실패한 실행과 미실행 영역을 정직하게 제출하며, 비교를 끝내기 위한 임의 수리나 추가 연구를 붙이지 않는다.

05 보관·06 전향 기록/월별 학습·현재 PUSH·운영 ML 미승격·Q6 OPEN·#3/#55/#57/#62 미완료·POC6-10 로컬 브랜치 보존 조건은 그대로다. OCI pull·키·cron·UI·목업·실제 주문은 없다.
