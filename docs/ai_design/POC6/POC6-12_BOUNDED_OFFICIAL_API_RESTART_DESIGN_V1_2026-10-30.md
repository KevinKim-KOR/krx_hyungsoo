# POC6-12 보완 DESIGN V1 — 공식 API 한 경로 확인과 총수익 자료 검증 재개

작성: 설계자 · 2026-10-30 · 독자: 개발자·사용자·검증자

저장 권장 위치: docs/ai_design/POC6/POC6-12_BOUNDED_OFFICIAL_API_RESTART_DESIGN_V1_2026-10-30.md

**지시:** 기존 POC6-12를 이어서 진행한다. 추가 출처 확인은 공공데이터포털의 지정 서비스 한 가지·개발자 작업 합계 60분으로 제한한다. 아래 자료 조건과 유효한 사용자 승인 범위가 충족되면 기존 PLAN으로 구현·검증한다. 충족되지 않으면 부족한 근거를 특정하고 이번 범위를 종료한다. 새 POC·새 PLAN 파일·전체 기반 조사는 만들지 않는다.

이 문서는 기존 DESIGN V1과 PLAN 판정의 산식·고정 표본·원본 보존 계약을 유지하며, 출처 확인 순서·예산·착수/종료 조건만 보완한다. 기존 “문의부터” 또는 같은 SEIBro 가입 재시도는 지금의 선행 작업이 아니다.

## 1. 목적과 고정 범위

목적은 다음 투자 효용 검증에서 **ETF와 KODEX200을 같은 가격·분배금 기준으로 평가할 자료를 구성할 수 있는지** 확인하는 것이다. 분배금 때문에 과거 ML이 미채택됐다고 가정하지 않으며 POC6-10·11을 다시 실행하지 않는다.

| 항목 | 고정 |
|---|---|
| 대상 | 069500 KODEX 200 · 379800 KODEX 미국S&P500 · 458730 TIGER 미국배당다우존스 · 214980 KODEX 단기채권PLUS |
| 기간 | 2025년 분배락 사건. 봉인 판의 공통 평가일 2025-01-02~12-30, 종목당 242행 |
| 가격 | 기존 봉인 KRX 판의 원가격, 읽기 전용. 같은 판·기존 reader 접점을 재사용 |
| 지수/원장 | A 이론적 분배락 종가 재투자 · B 미재투자 보유의 현금/미수 원장 · C 기존 KRX_BASEPRICE_CHAIN 대조 |
| 저장 | PC_ONLY 연구 폴더. 원자료·금액 표를 공개 Git·문서·OCI로 옮기지 않음 |
| 제외 | 새 모델·성과 탐색·추천 출력·운영 수집기·화면·API·DB 스키마·PUSH·OCI 변경 |

최신 PLAN §1~§7과 기존 원문을 재사용한다. 봉인 판 전수 조사·같은 4종/242행 개수 세기·이미 차단된 세 사이트 조사를 처음부터 반복하지 않는다. 이름 변경·분배 정책 변경·기준가 조정 후보 4/3/12/5건은 기존 관찰이며 확정 현금 사건의 대체 자료가 아니다.

## 2. 이번에 허용하는 출처 경로 하나

**공공데이터포털 → 한국예탁결제원_증권예탁통계서비스_GW → 그 서비스에서 공식적으로 공개한 상세기능·명세·정상 활용신청 경로**만 추가 확인한다.[1]

설계자는 2026-10-30 공개 목록에서 서비스의 존재, 무료 표시, 공공누리 제2유형 표시, 개발/운영 자동승인 표시와 개발계정 트래픽 100 표시를 확인했다. **ETF 분배금 상세기능·2025년 이력·필수 필드·실제 개인 활용신청 성공은 확인하지 못했다.** 설명의 “기업 배당 정보”를 ETF 분배금 제공의 증거로 쓰지 않는다.

- 먼저 해당 서비스의 실제 상세기능/명세에서 ETF 지원 여부를 확인한다. 주식 배당총액·예탁 통계·기업 배당 정보만 있으면 이번 필수 입력에 맞지 않는다.
- 공식 명세의 주소·파라미터만 쓴다. 검색 글·옛 코드의 endpoint·키를 가져오거나, SEIBro 화면 내부 요청 주소를 Open API로 간주하지 않는다.
- 같은 서비스가 이미 가입 불가로 확인한 사업자 전용 경로로 연결되면 그 사실로 멈춘다. 서비스 이름이 비슷하다는 이유로 가입·계정 탐색을 반복하지 않는다.
- 다른 공공데이터 API·운용사 공지 전수·비공식 배당표·증권사 API로 차례로 넘어가지 않는다. 다른 경로의 참고 링크를 발견해도 이번 범위에서는 미조사 항목으로만 남긴다.

이 경로를 고른 이유는 기존 사업자 전용 가입 시도와 별도로 **공개된 데이터 상품·이용 조건·명세를 확인할 접점**이 있기 때문이다. 사용할 수 있다고 미리 판정한 것은 아니다.

## 3. 시간·요청 상한

| 작업 | 상한과 중단 |
|---|---|
| 추가 출처·필드·이용 범위·필요 날짜 근거 확인 | 이 문서 이후 개발자 작업 합계 **60분**. 세션/접근 실패를 이유로 새 60분을 시작하지 않음 |
| 공개 문서 조회 | 지정 서비스의 목록·명세·이용 안내와 필요한 공식 권리 규칙/달력 문서만, GET 최대 12회. 기존 확보 문서 우선 |
| 승인 뒤 실제 데이터 확보 | GET 합계 최대 16회, 종목별 최대 4회. 표본 확인·페이지·필요 지급 확인을 모두 포함. 명세가 정한 더 낮은 한도가 있으면 그 한도 적용 |
| 실제 자료 산출 | 기존 계약대로 경과 10분·최대 RSS 4GiB. 설치·학습 없음 |

자동 재시도·날짜별 전수 호출·원천 변경으로 한도를 우회하지 않는다. 첫 069500 표본 응답도 정식 수신 원본으로 재사용하며 확인용이라는 이유로 다시 받지 않는다.

로그인·활용신청·승인 대기가 발생하면 자동으로 작업 범위를 늘리지 않는다. 외부 대기는 작업 시간에 넣지 않되 **그 회차 확인은 접근 대기 사실을 적고 끝낸다.** 사용자의 다른 개발이나 05·06 운영을 대기시키지 않는다. 이번 한도 안에 이용 가능한 입력을 확보하지 못하면 아래 §8의 차단 사유로 보고한다. 미래에 승인이 나거나 새 원본을 받는 것은 별도의 새 근거이며 이번에 확보한 것으로 소급하지 않는다.

## 4. 확인할 자료 조건 — A와 B를 한꺼번에 막지 않는다

| 조건 | 필요한 근거와 처리 |
|---|---|
| 종목 식별 | 지정 ETF를 구별할 공식 코드/ISIN 또는 조회 선택과 공식 식별 근거. 운용사 회사명만으로 ETF를 연결하지 않음 |
| 확정 금액 | 해당 사건의 좌당 현금 분배금·원화/통화·단위. 회사 배당총액·분배율·예상 금액으로 대체하지 않음 |
| 권리 시점 | 분배락일 직접 제공 또는 기존 설계의 공식 적용 규칙·달력으로 유일하게 도출. 지급기준일·지급일을 분배락일로 쓰지 않음 |
| 실제 지급 | 확인된 실제 지급일과 예정일 구분. 없으면 null+사유. **이 필드만 부족하다고 A 검증까지 중단하지 않음** |
| 기간·완전성 | 날짜 필터의 의미·이력 보유 범위·페이지/전체 건수·누락 여부. 2025년 연간 범위를 제공하지 않으면 연간 완전성을 승인하지 않음 |
| 원본/시각 | 응답 원문·조회 조건·수신 시각·해시, 정정/공표 시각은 확인한 범위만. 인증키를 제거한 요청 참조 사용 |
| 이용 범위 | 해당 API 응답에 적용되는 표시 조건과 예외 확인. 다른 웹 화면·다른 데이터 상품의 조건을 대신 적용하지 않음 |

원천의 날짜 필터가 지급기준일 기준인지 실제 지급일 기준인지 먼저 확인한다. “2025년 조회” 한 번으로 분배락 기준 2025년 사건을 모두 받았다고 하지 않는다. 연말 권리의 다음 해 지급 등 기존 설계에 필요한 사건만 한도 안에서 추가 확인한다. 다음 해 전체 가격은 받지 않는다.

분배락일이 없을 때는 기존 보충 판정의 공식 규칙·매매/결제 달력 경로를 재사용한다. 추가 규칙 확인도 위 60분에 포함한다. 과거에 본 분배락일 4건은 보조 대조다. 기준가가 조정된 날을 분배락일로 골라 만든 뒤 같은 가격으로 맞다고 검증하지 않는다. 날짜가 유일하게 정해지지 않으면 그 사건은 미확인이다.

API 0행은 분배 없음이 아니다. ETF 지원·입력 식별·날짜 의미·이력 범위를 확인하지 못한 빈 응답은 unknown이다. 화면에서 봤던 4/3/5/12행을 채우려고 사건을 만들거나 공식 응답에서 행을 버리지 않는다.

## 5. 이용 조건·인증·한 번의 승인 묶음

표시된 공개 이용허락이 **실제로 해당 응답에 적용되고 이 작업의 비상업 연구·원본 저장·가공 범위를 포함하는지** 확인한다. 조건과 출처를 기록해 적용할 수 있으면 그 근거로 진행하며, 기존 웹 화면의 “별도 문의부터”를 같은 API에 추가 선행 요건으로 되풀이하지 않는다. 별도 제3자 권리·유료/사업자 계약 조건이 표시되면 그 차이만 기록한다. 표시에 없는 금지를 새로 만들어 내지 않는다.

정상 개인 활용신청이 필요한지는 기능 지원을 확인한 뒤 사용자에게 안내한다. 개발자가 대신 새 계정을 만들거나 인증정보를 요구하지 않는다. 사용자는 정상 신청과 키 입력만 직접 하며, 키를 대화에 붙이지 않는다. 요청 URL·로그·원본 metadata에도 키가 남지 않게 한다.

실제 원본 확보 전 기존 유효 승인 범위를 확인한다. 포함되지 않았다면 **정확한 서비스·데이터 범위·최대 16요청·PC 연구 폴더 보관·종료 시 커밋/push**를 한 번에 제시해 승인받는다. 이번 설계 요청을 계정 생성·실제 데이터 수집·원격 push의 포괄 승인으로 해석하지 않는다. 명세에서 이미 필수 기능이 없다고 확인되면 사용자에게 가입·키 발급을 먼저 요구하지 않는다.

새 서비스키·새 비밀 파일을 코드나 공개 저장소에 넣지 않는다. 기존 로컬 비밀 설정 방식을 재사용하며 설치·OCI 키 등록은 없다.

## 6. 확보됐을 때의 진행 — 기존 PLAN 재사용

개발자는 기존 PLAN에 이 보완의 경로·상한·필드 표·승인 상태만 덧붙인다. **전체 PLAN을 다시 쓰거나 동일 사항으로 설계자 PLAN 재판정을 받지 않는다.** 기존 reader·모듈 책임·A/B/C 산식·PC_ONLY·작은 시험 계획은 이미 수용된 범위로 유지한다.

§4의 근거와 §5 승인이 충족되면 다음 순서로 진행할 수 있다.

1. 허용된 실제 원본을 한 번 받고 원본·조회 범위·이용 근거·해시를 보존한다.
2. 네 종목 각각 A 가능성, B 권리 평가 가능성, B 실제 현금 시점, 기간 완전성을 표로 정리한다.
3. 적어도 한 종목에서 고정 기간의 사건·권리 시점·금액 범위를 검증할 근거가 있어야 계산 구현으로 넘어간다. 다른 종목은 자동 제외하지 않고 네 종목 표의 미확인으로 남긴다. 데이터 부족을 가짜 자료만의 공식 실행으로 대신하지 않는다.
4. 기존 작은 모듈·CLI를 구현하고 격리 시험 → 고정 입력 자료 산출 1회 → 저장 산출물 검산 → 검증자 확인 → RESULT와 실제 report.md/json 제출로 진행한다.

원본은 일부 확보됐지만 기간/필드가 부족해 어떤 종목의 연간 수익도 검증할 수 없으면 **자료 목록과 부족 표까지만** 만들 수 있다. A/B/C를 모두 구현하기 위한 빈 뼈대·수집기를 먼저 만들지 않는다.

관측/수신 시각은 이번 실제 시각이다. 이 원본을 2025년에 시스템이 알았던 특징값·PIT 자료로 인증하지 않는다.

## 7. 계산·검증에서 유지할 핵심

- **A:** 단위 변경이 없으면 일간 배율 = (당일 원종가 + 그날 분배락 확정 분배금) / 전일 원종가. 분배락 종가 즉시 재투자의 이론 규약이며 지급 전 가용 현금이 아니다.
- **B:** 첫 평가일 종가에 1좌 보유를 시작하고, 권리에 맞춰 미수를 인식한다. 실제 지급 확인일에만 미수에서 현금으로 옮긴다. 실제 지급일이 없으면 현금으로 옮기지 않으며 그 검증은 미완료다. 확정 권리가 있는 미수 평가와 실제 현금 지급 검증을 구분한다.
- **C:** 같은 판·종목·기간의 기존 연결 지수를 나란히 비교한다. A/B와 같아지도록 보정하지 않는다.
- 세전·거래비용 0인 자료 검증이다. NAV·분배율·조정종가로 원가격/현금을 대체하거나 분배금을 이중 반영하지 않는다. 단위 변경은 공식 비율·적용일 근거가 있어야 한다.
- 연간 완전성이 없으면 2025년 연간 수익을 확정하지 않는다. 계산 가능한 국소 사건 검산과 연간 기준 검증은 별도로 표시한다.
- 100/95/5 손계산, 미수→현금 자산 항등식, 권리 경계, 연말 미수·예정/실제 지급, 0/null·중복·정정·손상·분할 단위는 기존 설계의 격리 시험을 유지한다.
- 검증자는 원본→사건→일별 계산→보고 상태의 필수 연결과 재계산을 확인한다. 미사용 파일의 생성 이력 인증·일관된 전체 기록 위조 방지·범용 기업행사 엔진은 만들지 않는다.

코드가 생기면 새 경로·재사용 접점의 관련 시험을 한 번 수행하고 필요한 변경만 재확인한다. 운영 코드를 바꾸지 않는 이번 범위에 전체 회귀·다른 모델 재학습·OCI 재점검을 추가하지 않는다. 실제 없는 사건 유형은 가짜 자료 시험이라는 표시를 유지한다.

SOURCE_BLOCKED에는 차단된 **서비스·상세기능/미확인·필드·기간·확인 시각·근거 URL·실제 호출 수/작업 시간**을 적는다. 접근 대기·일시 응답 실패를 “공식 데이터가 존재하지 않는다” 또는 “모든 개인 API 불가”로 일반화하지 않는다.

**차단/미확인으로 계산 구현을 하지 않은 경우:** 간결한 기존 POC6-12 RESULT에 사실·미실행 영역·한계를 정리하고 종료 사실을 보고한다. 같은 내용의 PLAN·검증자·설계자 RESULT 재판정 라운드는 요구하지 않는다. 구현하지 않았는데 IMPLEMENTED_VERIFIED_CLOSED라고 기록하지 않는다. 자료 결론과 “이번 출처 확인 작업 종료”를 구분한다.

**계산 코드를 구현한 경우:** 기존 절차대로 검증자와 설계자 RESULT 판정을 한 번 거친다. 부분 결과도 종료할 수 있다. 좋은 수익·A/C의 작은 차이를 통과 조건으로 삼지 않는다.

새로운 실제 결함은 영향 있는 부분만 정정한다. 시간 한도 뒤 대체 사이트·다른 ETF/연도·새 모델을 자동으로 열지 않는다. 나중에 정확한 새 원본·허용 근거가 생기면 그 사실로 재개를 별도 판단한다.

## 9. 문서·운영·다음 범위

필수 갱신은 보완 설계 원문, 기존 PLAN의 보완 절, RESULT, STATE/실제 해당하는 상태 문서다. 별도 조사보고·handoff·새 백로그를 관성적으로 추가하지 않는다. 원자료가 없는 차단 결과에는 실제 계산 report가 있는 것처럼 경로를 만들지 않는다.

POC6-13은 종료 상태로 유지한다. 이미 stage된 **13 결과서·STATE 두 파일은 다음 승인된 문서 커밋에 함께 포함**한다. 사용자 소유 handoff 문서는 제외한다. 원문 판정·검증 이력은 바꾸지 않는다. 커밋/push는 유효한 승인 범위에서 한다.

05 일일 보관과 06 맥북 자동 전향 기록·월별 학습은 현재 계약으로 계속한다. 13을 다시 열거나 OCI 추론 이관을 이번 자료 검증의 선행 조건으로 두지 않는다. 기존 PUSH·Q6 OPEN·운영 ML 미승격·미완료 요구 #3/#55/#57/#62는 유지한다.

이 작업이 끝나면 **확인된 가격/분배/지급 범위와 부족 목록**을 다음 추천 효용 설계의 입력으로 삼는다. 성공해도 전체 ETF 총수익 검증·추천 기능·유용한 ML 연결이 완료됐다고 하지 않는다. 부족해도 모든 ML이 불가능하다고 하지 않는다. 후속 실험은 자동 개방하지 않는다.
