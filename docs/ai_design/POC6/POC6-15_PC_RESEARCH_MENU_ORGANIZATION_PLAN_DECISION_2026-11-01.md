## 2. Q2 — 두 화면으로 구분하고 연결 관계를 사실대로 설명

「진단·상태 › ML 연구」 폴더는 유지하고, 하위 화면은 두 개로 한다.

| 화면의 사용자용 이름 | 내용 | 키·접점 |
|---|---|---|
| **예측과 결과 비교** | POC6-14의 전향 비교 카드 하나. 미리 기록한 예측·이후 실제 결과·누적 비교 | 기존 `ml` 유지 |
| **이전 자료·실험** | 준비도·자료 점검·다시 만들기·Baseline v0·상대상승 참고점수의 다섯 카드 | 새 키 하나(예: `ml_legacy`) |

‘전향 ML 비교’는 연구 문서에서 쓰는 기존 명칭으로 보존한다. 메뉴와 페이지 제목은 다른 사람도 뜻을 알 수 있도록 ‘예측과 결과 비교’로 풀어 쓴다. `ml_data`·`ml_experiments`는 구현 전 제안이므로 만들거나 호환 경로를 추가할 필요가 없다. 기존 진입 호출자·저장 선택 값이 없다는 확인도 수용한다. 실제 최종 메뉴 수는 이 두 화면 기준으로 맞춘다.

‘지난 실험(8월)’이라는 월 고정 이름은 쓰지 않는다. 8월 27일은 확인된 옛 자료의 마지막 날짜이며 다섯 카드 전부의 생성일·종료일을 뜻하지 않는다. 이후 명시적 다시 만들기로 날짜가 바뀔 수도 있다. 각 카드에는 해당 응답의 실제 자료일·실행일·당시 결론을 표시한다.

페이지 소개는 다음을 기본으로 한다.
- 예측과 결과 비교: **‘미리 기록한 예측과 이후 실제 결과를 비교합니다.’**
- 이전 자료·실험: **‘현재 예측 비교와 별개인 이전 자료와 실험 결과를 확인합니다.’**

이전 자료 화면에는 ‘이 자료를 다시 만들어도 현재 예측 비교의 입력이나 모델이 갱신되는 것은 아닙니다’라는 짧은 설명을 둔다. 재생성 버튼이 어떤 자료·실험을 다시 만드는지 범위를 이름과 설명에서 드러낸다. 기존 재생성 범위·실행 조건은 바꾸지 않는다.

현재 연구의 흐름은 기존 도움말에 짧게 설명할 수 있다. 시장 자료를 가져와 필요한 학습·예측을 기록하고, 이후 20거래일 자료가 확보되면 결과와 비교하는 구조라는 설명이다. 이는 **구조 설명**이며 각 단계의 오늘 완료 여부를 새로 판정한 상태판이 아니다. ‘매일’·‘월 1회’를 무조건 실행된다는 보장으로 적지 않는다.

사용자가 요청한 **자료 → 학습 → 예측 → 결과 전체의 실제 상태를 한 화면에서 확인하는 기능**은 이번 메뉴 구분만으로 해소됐다고 기록하지 않는다. 기존 응답에 있는 입력 시각·모델 판·공개 확인·평가 출처는 유지한다. 새 05/06 현황 조회가 필요한 부분은 STATE의 후속 설계 요구로 남기고 이번 구현에 자동으로 붙이지 않는다.

## 3. Q1 — 결론과 주요 조작을 먼저, 근거는 아래

카드의 기본 순서는 **제목 → 현재 결론 한 줄 → 주요 버튼·선택 → 설명·상세**다. 결론은 기존 응답과 판정으로 확인할 수 있는 사실이며 새 투자 판단·모델 승자·효용 판정을 만들지 않는다.

- **예측과 결과 비교:** 보고의 현재 결론을 짧게 먼저 보인다. 정상 보고에 비교 행이 없으면 ‘아직 비교할 결과가 없습니다’, 보고가 없으면 ‘비교 보고가 아직 없습니다’, 손상이 있으면 ‘최신 보고를 확인해야 합니다’처럼 기존 구분을 보존한다. 보고 유무와 평가 가능한 결과 유무를 합치지 않는다. 그 아래 기준일·다시 읽기, 선택 기준일 근거·예측 표, 누적 비교의 상세 표를 둔다.
- 누적 비교는 여러 표와 분모를 가진 **근거 묶음**이다. 이를 전부 맨 위로 옮겨 버튼과 예측 표를 밀어내지 않는다. 결론 줄에 보고의 범위·비교 건수 등을 덧붙일 때는 이미 받은 값을 쓰고, 아래 누적 보고와 선택한 기준일의 결과를 혼동하지 않게 한다.
- **준비도·자료 점검·기존 기준선·참고점수:** 현재 응답의 상태·실제 날짜·당시 채택/미채택 결론을 설명보다 앞에 둔다. ‘정상 조회/자료 준비’와 ‘추천에 사용할 수 있음’은 서로 바꾸어 쓰지 않는다.
- **자료 다시 만들기:** 기존 긴 상태 영역의 결론 한 줄을 먼저 보이고, 실행·다시 읽기 버튼 뒤에 설명과 단계 표를 둔다. 상태 영역이 길다는 이유로 결론을 버튼 아래로 미루지 않는다. 결론을 분리하는 작은 표시 컴포넌트는 허용한다.
- **복사 버튼:** 선택 행 상세의 맨 위에 둔 기존 위치를 유지한다. 선택한 행을 복사하는 버튼을 전역 실행 버튼으로 바꾸지 않는다. 다른 버튼도 작동 대상이 속한 카드 안의 상단에 둔다.

손상·이전 보고 사용·회차 읽기 실패 같은 경고는 접힌 상세에만 숨기지 않는다. 현재 결론 근처에서 확인 가능하게 하고 같은 응답의 복사문에도 유지한다. 기존 미채택·실행 제한에 따라 막혀 있는 버튼을 위로 옮기면서 활성화하지 않는다.

## 4. Q3 — 여섯 카드의 사용자용 문구 전체를 쉬운 한국어로

이번에는 메뉴·제목만 바꾸고 영어 본문을 다음 단계로 미루지 않는다. 여섯 카드의 제목·설명·결론·버튼·표 머리·상태·안내·오류 요약·도움말·복사문을 정리한다. 다른 메뉴 화면 전체의 일괄 번역으로 넓히지는 않는다.

다음은 표현의 기준이다. 예시의 날짜·건수는 하드코딩하지 않는다.

| 현재 표현 | 사용자용 표현·주의점 |
|---|---|
| feature / sanity / evidence | 문맥에 따라 ‘학습에 쓰는 값’·‘자료 점검’·‘자료와 실험 다시 만들기’ 등 실제 기능을 설명 |
| latest asof / row | ‘마지막 자료일’·‘자료 건수’. 숫자는 기존 값을 쉼표로 구분하며 임의로 줄여 정밀도를 잃지 않음 |
| warn / warning / error | ‘주의’·‘경고 n건’·‘오류 n건’. 서로 다른 상태를 전부 ‘실패’로 바꾸지 않음 |
| 날짜 균형 MAE | **‘평균 오차(%p)’** + 짧은 설명 ‘날짜마다 같은 비중으로 계산’. 도움말에 절대 오차와 날짜별 평균 방식을 설명 |
| D20 | 기본 표시는 **‘20거래일 내 종가 하락폭(%)’**, 방법 열은 ‘예측’, 실제 열은 ‘실제’로 구분. D20 약어는 도움말·상세에서 연결 |
| success · job_id | ‘완료’와 실제 실행 시각. 작업 번호는 접힌 상세로 이동. 완료가 연구 채택을 뜻하지 않음 |
| coverage 등 비율 | 실제 분모·대상을 확인해 ‘자료가 있는 비율’ 등으로 설명. 뜻을 추측해 번역하지 않음 |
| Ridge · HGB · MLP(CPU) | 모델 고유 이름은 유지 가능. 기존 도움말에 선형 모델·나무 모델·신경망이라는 짧은 설명을 둠 |

평균 오차의 산식·단위는 그대로다. 각 기준일에서 종목별 절대 오차를 평균하고, 기준일별 값을 같은 비중으로 합친 기존 의미를 보존한다. 큰 하락 보조값 등은 평균 오차와 다른 값이므로 같은 이름으로 합치지 않는다. %와 %p, 부호·반올림·null 처리는 POC6-14를 유지한다.

D20 도움말은 ‘기준일 종가 대비 이후 20거래일 종가 중 가장 낮은 변화이며, 모두 기준일보다 높으면 0’이라는 기존 뜻을 보존한다. 20일째 수익률·고점 대비 최대 낙폭·장중 저점·보유 기간으로 바꾸어 설명하지 않는다.

표 이름·파일 참조·작업 번호·모델 판 식별자·필드 이름·원시 진단은 **접힌 ‘자세한 정보’ 안의 ‘개발 정보’**로 옮길 수 있다. 기본 화면의 대상 날짜·보고 범위·여러 모델 판 여부·핵심 경고는 유지한다. 상세 원문은 기존 응답이 허용한 범위만 보이며 새 절대 경로나 개인 정보를 노출하지 않는다.

사용자용 실패 요약은 한국어로 표시하고 기술 원문은 상세에서 확인하게 한다. 사유를 해석할 근거가 없으면 실패·미실행 등 원래 상태를 유지하면서 ‘원인 확인 필요’와 원문을 함께 제공한다. 모르는 사유를 임의의 원인으로 번역하거나 오류를 숨기지 않는다. 코드·API 키·저장 상태값은 그대로이며 전역 문자열 치환은 하지 않는다.

화면과 복사는 기존 공용 표시·경고 함수를 함께 고친다. 기술 정보를 접었다는 이유로 복사문에서 경고·날짜·판의 근거를 누락하지 않는다. 한국어 문구 정리는 표시 변경이며 연구 판정이나 데이터의 값 변경이 아니다.

## 5. 구현·검증 범위 조정

기존 PLAN의 작은 사이드바 폴더·선택된 화면만 렌더링·기존 `ml` 키 유지·카드 재사용·추가 라우터/저장 장치 없음은 수용한다. 화면은 두 개로, 카드 분배는 1개와 5개로 수정한다. 기존 다섯 카드를 한 화면에 두더라도 긴 기술 정보는 상세로 내려 현재 결론과 버튼을 먼저 읽을 수 있게 한다.

카드 내부 순서·문구·필요한 표시 함수·관련 시험까지 이번 허용 범위에 포함한다. 명령 버튼의 핸들러·재생성 대상·사용 제한, 백엔드·API 계약·저장 구조·통계·모델 설정은 바꾸지 않는다. 같은 값에서 결론과 경고를 표시하는 코드를 재사용하며 새 상태 조회나 연구 계산은 넣지 않는다.

시험은 다음에 집중한다.
- 두 화면의 분배·선택·접힘·기존 `ml` 진입·선택하지 않은 카드 미마운트·메뉴 이동의 명령 호출 0.
- 결론·해당 버튼이 긴 설명/상세보다 앞에 있고, 접기만으로 본문이나 선택 값이 초기화되지 않음.
- 정상 비교 없음·보고 부재·손상·실패의 뜻과 경고가 한국어 화면/복사에서도 구분됨. 날짜·건수·숫자·단위·분모는 변경 전과 같음.
- 기존 14의 읽기·오류·복사·도움말 시험과 프런트 타입·lint·관련 및 전체 프런트 시험. 표시 문구 기대값 변경은 실제 의미를 맞춰 수행.

‘영어 단어 0개’ 같은 금지어 필터나 380개 전수 계수 게이트는 만들지 않는다. 고유 명칭·식별자·개발 원문은 예외가 있다. 모든 정적 문장을 각각 검사하는 시험을 늘리기보다 상태 구분과 실행 경계의 기존 시험을 활용한다. 저장소의 필수 검사는 지키되 백엔드 전체 회귀·모델 재실행·06/13/OCI 재검증을 붙이지 않는다.

## 6. 다음 순서와 기록

1. 이 판정 원문을 보관하고 PLAN 현행 메뉴·범위·시험·상태에 반영한다. 원설계 원문과 사용자 의견은 보존한다. PLAN §4의 2026-11-01 ‘토요일’ 표기는 **일요일**로 바로잡는다. 당시 NO_INPUT 기록의 수치나 실행 사실은 바꾸지 않는다.
2. **목업 3 한 번**으로 두 화면, 결론·버튼 위치, 쉬운 한국어 기본 화면, 접힌 기술 정보의 위치를 함께 보여 준다. 1440px·1000px 전체 화면을 같은 목차에서 확인한다. 카드 이미지를 늘려 흐리게 하지 않으며 문구·배치 확인은 실제 글자로 구현해도 된다. 라이브 API 실행·갱신 버튼은 연결하지 않는다.
3. 기존 ‘메뉴 괜찮다’는 확인은 종전 세 화면 안에 대한 기록이다. 바뀐 두 화면과 문구는 사용자 확인을 받는다. 이 확인은 이미 사용자에게 예고된 목업 3에서 한 번에 끝내며 별도 PLAN 재판정은 없다.
4. 확인 뒤 구현·검사 → 사용자 실화면 확인 → 검증자 → RESULT 판정으로 진행한다. 설계자에게 구현 전 같은 PLAN을 다시 제출할 필요는 없다.
5. 이번 완료는 두 자료 흐름의 올바른 구분·결론 우선 배치·해당 여섯 카드의 쉬운 한국어다. 전체 단계 현황 기능은 후속 요구로 남기고, 총수익 자료 확보·추천 효용·운영 ML 채택까지 완료로 적지 않는다.

커밋·push는 그 시점의 실제 파일 범위와 기존 사용자 승인을 따른다. OCI pull·설치·새 수집·키·cron 변경은 없고 같은 POC6 안의 handoff도 없다. 사용자 소유 handoff·연구 산출물·개인 캐시·로컬 연구 브랜치는 넣지 않는다. Q6 OPEN·운영 ML 미승격·기존 미완료 요구·05/06/13 운영은 유지한다.
