# POC6-13 C 보완 PLAN 판정 — 별도 PC의 윈도우 공유 폴더 백업

작성: 설계자 · 2026-10-29 · 독자: 개발자·사용자·검증자

**판정: PASS_WITH_REQUIRED_CORRECTIONS. Q-C1의 SMB 한 가지 방식을 수용하고, Q-C2의 내구성 한계를 아래 범위로 수용한다. 본문 보완 뒤 구현하며 PLAN 재제출은 필요 없다.**

저장 권장 위치: docs/ai_design/POC6/POC6-13_PC_SMB_BACKUP_SUPPLEMENT_DECISION_2026-10-29.md

이 문서는 기존 RESULT 판정 V1.1 §5의 “별도 PC 연결 보완”에 대한 판정이다. 이미 통과한 A·B와 연구 계산을 다시 판정하는 문서가 아니다.

## 1. 근거와 현재 상태

제출된 POC6-13 PLAN §8 전체와 기존 RESULT 판정 V1.1을 대조했다. 첨부 PLAN SHA-256은 96df6d118d36bce94ea7da8dd8ce8aef3f2a0d69428d953d8a94526eb52101da다.

- 사용자 환경: 별도 윈도우 PC의 2TB 저장장치·유선 LAN, 맥북의 Wi-Fi. 백업할 때 같은 공유기에 연결 가능.
- PLAN 머리말과 개발자 회신에 따르면 맥북 보조 A·B는 10-29 설치됐고 첫 정기 실행 확인을 기다린다. 설계자가 설치·등록·실제 실행을 직접 확인한 것은 아니다.
- C는 보완 계획 단계다. 이번 SMB 코드·실제 공유 설정·첫 사본·복원은 아직 완료되지 않았다.
- 초기 백업은 약 2.4~2.5GB이며, 2TB는 PC 저장장치 용량이다. 준비와 빈 경로 복원에 필요한 맥북 임시 공간은 별도로 확인한다. 매일 전체 사본을 다시 만드는 작업은 아니다.

## 2. Q-C1 — SMB 한 가지 방식 수용

사용자가 고른 PC의 백업 전용 폴더를 Finder로 연결하고, 기존 backup run / backup verify에 명시적인 --pc-share 경로만 추가한다. 별도 전송 프로그램·윈도우 서비스·학습 환경은 설치하지 않는다.

PC의 폴더와 계정·공유 설정, Finder 인증은 사용자 조작이다. 원격 공유 접근은 지정한 계정으로 제한하고 공유 권한과 폴더 권한을 함께 확인한다. Everyone·게스트·동기화 폴더는 사용하지 않는다. 비밀번호는 대화·소스·실행 인자·로그에 넣지 않으며 키체인 사용은 사용자 선택이다. 연결 범위는 같은 로컬 네트워크로 한정한다.

구현에는 다음 세 가지를 명확히 반영한다.

1. **실제 마운트와 승인된 목적지를 확인한다.** /Volumes 아래에 있다는 사실이나 st_dev가 다르다는 사실만으로 통과시키지 않는다. 실제 파일 시스템이 smbfs이고, 마운트의 서버와 공유 이름이 사용자가 승인한 PC·전용 공유에 대응하며, 목적지가 그 공유 안인지 확인한다. 서버 이름의 별칭은 확인된 주소 대응으로만 처리한다. localhost·루프백·맥북 자신의 주소·확인 불가는 거부한다. 인증정보가 섞인 마운트 원문을 그대로 기록하지 않는다.
2. **외장 경로와 SMB 경로를 분리한다.** --pc-share가 없으면 기존 외장 장치 검사를 그대로 쓴다. SMB를 외장 장치로 통과시키지 않는다. SMB가 해제돼 같은 이름의 로컬 폴더만 남으면 그곳에 대신 쓰거나 복원하지 않는다. 시작 전·복원 전과 실제 파일 접근에서 기존 경로 이탈·링크 검사도 유지한다.
3. **관측한 연결과 물리 장치 인증을 구분한다.** 사용자가 해당 PC와 저장 폴더를 확인하고, 도구는 그 PC의 SMB 연결을 검사한다. 이 검사가 PC의 실제 디스크 모델·모든 윈도우 내부 경로·장치 고유번호를 원격 인증한다는 표현은 쓰지 않는다. 이를 위해 새 장치 인증 체계를 만들지 않는다.

PC 이름·공유 이름·마운트 경로의 실제 값은 연결 승인 때 확정한다. 지금 사용자에게 설정이나 값을 요구하지 않는다.

## 3. Q-C2 — 보장 범위를 한정해 수용

**RESTORE_VERIFIED는 지정한 PC 공유의 사본에서 자료를 되가져와, 빈 맥북 경로의 복원 내용이 보관 목록·해시·필요 커밋과 일치했음을 뜻한다.** 서버의 성공 응답과 그 복원 사실까지 확인하며, 전원 상실 뒤 보존·매체의 영구 무결성·실험 전체의 재실행 가능성까지 보장하지 않는다.

SMB 규격의 FLUSH는 서버에 캐시된 파일 정보를 저장소로 반영하도록 요청하는 기능이다.[2] 이 규격만으로 현재 맥북의 fsync가 실제 PC에서 어떤 저장 계층까지 완료됐는지 실측한 것으로 쓰지 않는다. PLAN §8-3의 캐시·내구성 한계를 유지한다.

- F_FULLFSYNC가 해당 환경에서 **지원되지 않는 경우** fsync로 처리하는 안을 수용한다. 사용한 방식은 기록한다. 실제 I/O 오류·연결 해제·권한 오류까지 “미지원”으로 바꿔 성공 처리하지 않는다. fsync도 실패하면 완료로 올리지 않는다.
- 쓰기·동기화·목적지 해시 대조·이름 변경 중 실패하면 완료 사본이라고 쓰지 않는다. 기존 미완료 기록과 .partial 보존 흐름을 재사용한다.
- COPY_HASH_OK와 RESTORE_VERIFIED는 따로 남긴다. 복원 확인 실패로 이미 확인된 사본을 임의 삭제하지 않으며, 앞 단계 성공으로 복원 실패를 가리지 않는다.
- **첫 실제 확인에서는** 복사와 파일 닫기가 끝난 뒤 사용자가 Finder에서 공유를 정상 해제하고 다시 연결한 다음 verify를 수행한다. PC를 재부팅하거나 전원을 끄는 시험은 하지 않는다. 재연결 후에도 목적지를 다시 확인하며, 해제·재연결이 안 됐다면 복사 확인까지만 기록하고 실제 복원 확인을 기다린다.

재연결은 같은 연결의 캐시만 되읽는 상황을 줄이기 위한 실제 절차다. 모든 캐시 제거·물리 매체 내구성의 증명으로 해석하지 않는다. SMB 캐시를 조작하는 새 기능이나 패킷 분석은 요구하지 않는다.

## 4. 변경분 시험·검증 범위

PLAN §8-4의 목적지 검사 함수·backup run/verify 분기·CLI 인자 범위를 수용한다. 필요한 내부 도우미 분리는 가능하지만 06·A·B 동작을 바꾸지 않는다.

변경분 시험과 검증자는 아래 경계만 확인한다. 기존 C의 대상 목록·원본/사본 해시·빈 경로 복원·코드 bundle 검사는 재사용한다.

| 경계 | 확인할 동작 |
|---|---|
| 목적지 | 승인된 서버·공유의 smbfs 통과, 다른 서버/공유·맥북 자신·확인 불가·마운트 없는 로컬 폴더 거부 |
| 분리 | SMB 명시 경로만 새 검사 사용, 기존 외장 검사 유지, 경로 이탈·링크가 허용 경로로 바뀌지 않음 |
| 실패 | 연결 중단·쓰기/동기화 실패·해시 불일치가 COPY_HASH_OK 또는 RESTORE_VERIFIED로 올라가지 않음 |
| 복원 | 공유 사본을 읽은 빈 경로 복원과 해시·커밋 대조, 손상 사본 거부 |

가짜 마운트 정보와 임시 경로의 시험은 실제 SMB 호환성을 확인한 것으로 쓰지 않는다. 실제 연결에서는 잠금/파일 열기·동기화·이름 변경·복원 흐름이 동작하는지 한 번 확인한다. 예상과 다르면 해당 단계에서 멈추고 사실을 보고한다.

A·B 전체 회귀·전체 검증자 라운드·공식 연구 재실행은 요구하지 않는다. 고의로 모든 기록을 함께 바꾸는 위조나 윈도우 저장 계층 전체의 검증으로 범위를 넓히지 않는다.

## 5. 진행·승인·완료

1. 이 판정 원문을 보관하고 PLAN §8에 반영한다. 새 PLAN·새 POC는 만들지 않는다.
2. 구현 → 변경분 시험 → 검증자 변경분 확인을 진행한다. 사용자에게 먼저 폴더를 만들도록 요구하지 않는다.
3. 준비된 실제 PC·폴더·계정/연결 범위·예상 용량·복원 임시 경로를 제시하고, PC 공유 설정·연결·첫 백업 쓰기·복원 확인·커밋/push에 대한 기존 유효 승인을 적용하거나 한 번의 구체적인 승인 묶음으로 받는다. **이 판정은 해당 쓰기 승인을 대신하지 않는다.**
4. 승인 범위로 구현을 커밋해 실행 코드 판을 남기고, 사용자의 정상 공유 연결 뒤 첫 복사·해시 대조·재연결·빈 경로 복원을 수행한다. 시간·실제 바이트/파일 수·대상·사용한 동기화 방식·결과를 같은 13 결과서에 기록한다.
5. 기존 대상과 입력/코드 보존 공백을 그대로 명시한다. PC 사본과 복원 확인까지 끝났을 때만 C 완료를 기록한다. 종료 문서 커밋/push는 승인 범위로 한다.

실제 확인이 이 조건대로 끝나면 추가 설계자 RESULT 재판정 없이 짧게 완료를 보고한다. 실제 SMB에서 계약을 지키지 못하거나 범위 밖 변경이 필요하면 그 차이만 보고한다. 다른 연결 방식을 연속 탐색하지 않는다.

## 6. A·B와 병행 처리

내일 2026-10-30의 첫 정기 일정 확인은 C 구현·PC 연결을 기다리지 않는다. 정상 수집 뒤 실제 D·주 기록·마감 전 영수증·보관 결과를 확인한다. 이미 자동으로 기록됐으면 같은 D 예측을 강제로 다시 만들지 않는다.

A·B 완료와 C 대기는 따로 적는다. 기존 RESULT 판정 V1.1의 잔여 분리 종료 조건은 유지한다. A·B 종료 보고에 이 C 보완 판정을 연결할 수 있지만, C의 실제 사본이 없는데 전체 백업 완료라고 쓰지 않는다.

POC6-12 보류·OCI 읽기 전용 가능성 확인의 상한·운영 ML 미승격·Q6 OPEN·사용자 handoff 제외·로컬 연구 브랜치 공개 금지는 그대로다. 이번 C 연결을 위해 OCI pull·설치·원자료 전송·새 cron을 하지 않는다.
