# POC6-29 개발 PLAN V1 설계자 판정

**2026-11-12 KST · PASS_WITH_REQUIRED_CORRECTIONS**

대상은 첨부된 `POC6_29_ETF_MARKET_DISCOVERY_REFOCUS_PLAN_V1.md`와 개정 목업이다. 화면 구성과 기본 저장은 목업 소스에서 확인했고, PC 응답과 기존 경로의 동작은 개발자 실측인 PLAN §1을 근거로 삼았다. 오늘의 투자 점검에서 시장과 보유를 빠르게 읽고, ETF보유 및 후보 선정에서 종목을 비교해 판단 근거를 볼 수 있게 통합한다. 아래 결정이 반영된 PLAN과 목업을 구현 기준으로 삼는다. 범위는 PC 화면과 해당 조회·미리보기·갱신 경로다.

## 1. 사용자 결정과 주요 보완

### Q1·Q2 · 화면별 조건과 기본 기간

- 오늘의 투자 점검의 「잘 오르는 ETF」 카드는 자체 기간으로 상위 3개를 계산한다. 기간 선택과 [이 기준을 기본으로]를 카드에 둔다. 요약 카드의 인버스·레버리지·합성·선물형 제외는 고정한다.
- 오늘의 투자 점검, 보유, 섹터요약, 후보리스트, 보유와 후보 비교는 조회 조건과 저장된 기본 기간을 각각 쓴다. 화면을 이동하면 도착한 화면의 조건으로 읽는다. 수익률 산식과 공통 기간을 판단하는 규칙은 함께 쓴다. 조회·저장된 결과는 각 화면이 실제 요청한 조건과 기준일에 맞춰 표시한다.
- 첨부 목업은 A·섹터요약·후보리스트·보유와 후보 비교에 기본 저장 동작이 있다. 「보유」는 1개월 고정 예시다. 보유의 약세 묶음 접점에도 자체 기간과 기본 저장이 있음을 목업과 구현에서 확인한다.

### Q4-1 · 기존 상세 수치는 어떻게 붙이는가

- **종목을 펼칠 때 해당 종목의 상세를 읽는다.** 기존 저장 가격과 NAV 자료, 계산 규칙으로 1·3·6·12개월, 20구간 KODEX 200 차이, 시장가·NAV·괴리율을 제공한다. 보유와 후보 비교는 선택한 두 종목에 같은 상세를 쓴다.
- 후보리스트의 **[표]는 행을 펼치기 전에도 위 수치를 볼 수 있게** 현재 표시 범위의 상세를 묶어 읽는다. 표와 행 상세에서 같은 값·단위·사용 날짜를 쓴다. 20구간 차이(%p)는 종목과 KODEX 200의 실제 시작일과 끝일이 모두 같을 때 계산한다. 시장가와 NAV의 날짜가 다르면 각각 표시한다. 계산된 0, 자료 없음, 기간 다름, 개별 주식의 NAV 해당 없음은 구분한다.

### Q4-2 · 판단 근거 미리보기는 어느 목록에서 찾는가

- **선택한 화면의 공통 기간 목록**에서 찾는다. 서버가 화면의 조건, 선택 종목의 실제 시작일·끝일, 가격 시점과 선정 순위를 현재 조회 결과와 대조한다. 판단 근거에는 그 목록의 상위·하위와 선정 순위를 적는다. 갱신으로 선택 당시 순위나 가격이 달라졌으면 목록을 다시 읽고 선택하도록 안내한다.
- 보유 미리보기는 보유 종목으로 계속 열 수 있다. B의 판단 근거에서 후보 목록과의 관계는 현재 화면 조건으로 확인된 경우에 표시한다.

### Q7 · 최신 자료 갱신

- **기본안은 [최신 자료 갱신] 한 번이다.** PC 서버가 기존 보유 현재가 → 기존 시장 자료 순으로 연결하고, 화면에서 각 단계의 진행과 결과를 읽는다. 처리 중 연타하거나 다른 탭·「보유 현황」에서 같은 갱신을 누르면 서버에서 실행 중인 작업으로 연결한다. 시장 갱신의 기존 대기 규칙을 적용한다. 시장이 대기 중이면 가능한 보유 현재가는 먼저 처리하고 시장의 다음 가능 시각을 표시한다.
- 기존 경로로 한 번의 실행과 상태 공유를 안정적으로 구성하기 어렵다면 **[① 보유 현재가 갱신]과 [② 시장 자료 갱신]**을 같은 자리에서 제공한다. 안내 문구는 “① 보유 현재가를 먼저 갱신하고, 결과를 확인한 뒤 ② 시장 자료를 갱신하세요.”로 둔다. 분리해도 작업별 서버 중복 방지를 적용한다. 일부 작업을 실패하거나 건너뛰면 가능한 작업과 현재 기준일을 각각 안내한다.
- 자료별 성공·실패·대기와 남아 있는 기준일을 보여 준다. VIX 갱신 실패의 개별 재시도는 시장 근거 상세에서 찾는다. [요약 다시 읽기]는 PC에 저장된 자료를 기준으로 읽는 동작으로 표시한다. PLAN §1-5의 PC 갱신 경로는 네이버·기존 시장 공급자·OCI 수급 보관본을 쓰며, 개발자가 확인한 키움 호출은 0건이다.

### Q14 · C 전용 파일은 별도 보관

- 이전한 C의 전용 화면·카드·보조 코드와 전용 시험은 **운영 소스와 자동 빌드·시험 탐색 범위 밖의 보관 폴더 한 곳**에 모은다. 원래 경로와 대체 화면을 기록한다. 실제 사용처를 대조해 A·B에서 쓰는 공용 카드·계산·시험은 활성 경로에서 사용한다.
- 새 진입점을 연결한 뒤 C 메뉴를 정리한다. 「종목 관리」 재진입 창은 PC 서버가 보내는 메뉴 값까지 새 경로로 맞춘다. 자료 갱신, AI·구성종목 전달, 기존 저장 기록도 각각의 새 진입점에서 이어지는지 확인한다.

## 3. 완료 확인

1. **화면별 조건** · A를 3개월, 후보리스트를 1개월로 기본 저장한 후 다시 열어 두 값과 순위를 확인한다. B에서 기간·정렬·제외를 바꾸고 A의 조건과 표시 순위를 대조한다. 「보유」의 기간 저장과 A·B의 종목 단위 하락 집계도 확인한다.
2. **판단 근거** · 재현된 B 3개월 10위 사례, 상위 11~30위의 한 행, 하위의 한 행, 보유 한 종목을 확인한다. 선택 화면의 기간·선정 순위·기준일이 미리보기와 AI 초안에 이어지는지 본다. 갱신 전 목록과 갱신 후 선택이 엇갈릴 때 다시 읽기 안내를 확인한다.
3. **상세와 표** · 같은 종목을 목록 상세·표·나란히 비교에서 열고, 날짜가 같은 값과 자료 부족 사례를 대조한다. A의 시장 근거는 「자료·연구 상태」 바로 위에서 접힌 채 시작하고, 열면 KODEX 200·VIX·수급·환율·유가를 읽을 수 있다.
4. **갱신** · 연타·다른 탭·보유 현황의 동시 실행, 시장 대기, 일부 실패 사례에서 서버 실행 수와 자료별 결과를 확인한다. 분리안을 적용하면 번호와 순서 안내를 실화면에서 확인한다.
5. **메뉴 이전** · 재진입 창, 정비 목록, AI·구성종목 초안과 두 수동 초안의 진입을 확인한다. C 전용 파일 보관 목록과 활성 빌드·시험의 참조를 대조한다. 변경 지점 중심으로 확인하고 통합 회귀는 마감 때 한 번 실행한다.
