## 2. 연구 결론 — NO_REFERENCE_CASE 수용

### 2-1. 기본 비용 11.5bp

수치는 합성 가격지수의 비용 반영 결과이며 실제 원화 계좌 수익이나 분배금 포함 총수익이 아니다.

| 곡선 | 전체 변화율 | 연환산 변화율(CAGR) | 최대낙폭(MDD) | 평균 현금 |
|---|---:|---:|---:|---:|
| A: REF_EMA20_60 | +92.08% | +5.93% | −22.36% | 31.93% |
| B: MOM20_WEEKLY | +144.84% | +8.23% | −28.17% | 표시상 0.00% |
| M: KODEX200_HOLD | +421.23% | +15.70% | −40.81% | 표시상 0.00% |

- **가격지수 변화 개선 사례:** A의 CAGR 차이는 B 대비 **−2.2948%p**, M 대비 **−9.7628%p**다. 두 기준보다 1%p 높다는 조건을 충족하지 못했고, 구간 변화율도 두 기준을 모두 넘은 구간은 0/3이다.
- **낙폭 개선 사례:** A의 MDD 개선은 B 대비 **+5.8109%p**, M 대비 **+18.4485%p**다. 5%p 개선 및 구간 MDD 2/3 우위는 충족했다. 다만 CAGR 열위를 2%p 이내로 제한한 조건은 양쪽 모두 미충족이다.

따라서 `NO_REFERENCE_CASE · JUDGED`를 수용한다. B와의 CAGR 차이가 한도보다 약 0.29%p 더 컸다는 이유로 한도를 바꾸지 않는다. 특히 M 대비 열위가 약 9.76%p임을 함께 읽어야 한다.

### 2-2. 비용 영향을 작게 해석하지 않음

A는 편도 비용을 11.5bp에서 25bp로 높이면 CAGR이 **5.93% → 2.07%**, MDD가 **−22.36% → −33.07%**로 변한다. B 대비 MDD 개선도 **5.81%p → 0.43%p**로 줄어든다. 기본 비용의 연환산 편도 회전율은 A 약 **14.39배**, B 약 **11.21배**다.

보고서의 `cost_sensitive=false`는 **‘11.5bp에서 충족한 사례가 25bp에서만 탈락하는 경우가 없음’이라는 사전 정의된 상태값**이다. 두 비용 모두 사례 미충족이어서 false다. **비용 영향이 작다거나 비용에 둔감하다는 뜻은 아니다.**

결과서 §0·§8의 ‘비용 민감 사례 없음/비용 민감 없음’에는 위 상태 정의와 실제 비용 변화 수치를 짧게 덧붙인다. 공식 report.md/json 원본·생성 코드·판정 상태값은 바꾸지 않는다.

### 2-3. 효용과 한계의 해석

확인된 부분은 이 표본·기간에서 A의 전체 MDD가 두 기준보다 작았다는 것이다. 반면 수익 열위와 높은 회전율 때문에 사전 사례가 되지 못했다. **낙폭 절감은 관측됐지만 그 대가가 이번 기준 안에 들어오지 않았다**고 기록한다.

A의 평균 현금 31.93%와 채권·현금 관련 ETF를 포함한 표본을 고려해야 한다. 현금 비중을 맞춘 대조군 등으로 분리하지 않았으므로 개선을 EMA 또는 주중 이탈 하나의 효과로 단정하지 않는다. 이를 확인하려고 이번에 추가 실험을 열지는 않는다.

현재 24종에서 이름 필터 후 20종을 쓴 회고 표본이다. 시장 전체 PIT 성과·처음 보는 독립 시험·친구 운용의 재현으로 일반화하지 않는다. 마지막 구간과 2026년 M 낙폭에 대한 의존도도 결과서 §5대로 보존한다. 원천 시세의 외부 진실성까지 이번 검산이 증명한 것은 아니다. 유리한 해석을 위해 그 구간을 제거하거나 종료일을 바꾸지 않는다.

이 결과로 KODEX200 보유를 사용자에게 추천하거나, 추세 전략 전부가 무효라고 결론내리지 않는다. 새 ML 성능을 평가한 연구도 아니다.

## 4. 공개 라이선스 선택 — (나) 권고 · (가)는 현재 형태로 공개 불가

이 절은 공개/보관 경로에 대한 설계 판단이다. 모든 Python import의 법적 결합 범위를 확정하는 판정은 아니다.

### 4-1. 선택지 판단

| 선택지 | 판정 |
|---|---|
| (가) 새 연구 파일만 GPL 고지, 기존 54개 모듈 허락은 나중에 | **현재 형태로 공개 승인하지 않음.** 결합·배포 부분의 허락을 미해결로 남겨 둔 채 새 파일 머리글만 붙여 문제를 해결했다고 할 수 없음 |
| (나) 연구 코드는 로컬 전용 브랜치, 공개 main은 문서만 | **이번 단계의 권고안.** 코드·실험 근거는 보존하면서 기존 프로젝트의 라이선스 범위를 지금 바꾸지 않고 연구를 마무리할 수 있음 |
| (다) 저장소 비공개 | 이번 연구 때문에 기본 선택으로 삼지 않음. 비공개는 접근 설정이며 라이선스 충족 여부와 같은 판단이 아님. 다른 사람에게 코드 사본을 전달하는 범위는 별도로 봐야 함 |

GPL 본문은 비배포 연구/실행과 배포의 조건을 구분한다. 공개 소스라는 사실만으로 코드 사용·결합·배포의 허락이 자동으로 갖춰지는 것도 아니다.[1][2] 54개가 import된다는 사실만으로 그 전부가 반드시 GPL 대상이라고 단정할 수 없으며, Git 작성자가 사용자라는 기록만으로 모든 코드의 독점 저작권을 확정하지도 않는다.

따라서 지금은 (가)를 통과시키기 위한 전면 라이선스 감사·재라이선스·엔진 교체·별도 POC를 열지 않는다. **공개할 필요가 생겼을 때 구체적인 권리·결합 범위와 허락을 정한다.** 현재 개인 연구 결과를 보관하는 목적은 (나)로 달성할 수 있다. 사용자 선택을 받기 전에는 (나)에 동의한 것으로 기록하지 않는다.

### 4-2. (나)를 선택하면 적용할 보관·공개 조건

개발자는 현재 23개 경로를 다음과 같이 구분해 사용자에게 **한 번의 구체적인 승인 묶음**으로 제시한다. 이 판정은 그 승인을 대신하지 않는다.

| 보관 위치 | 포함 범위 |
|---|---|
| 로컬 전용 연구 브랜치(예: `research/poc6-10-local`) | 검증된 연구 Python 11파일·requirements-research.txt·원문/PLAN/결과/판정 및 그 연구 상태 문서. 연구 구현 커밋과 기존 base 커밋을 함께 참조 |
| 기존 PC_ONLY 연구 폴더 | 공식 8산출물 그대로. 입력·코드·엔진 근거와 원본 해시 유지 |
| 공개 main | 코드 없는 설계/PLAN/결과/판정·종료 요약·상태 문서만. 연구 구현과 연구 의존성·시험은 미포함임을 표시 |

로컬 연구 브랜치는 원격에 올리지 않는다. **연구 코드가 들어 있는 커밋을 공개 main에 merge한 뒤 파일을 삭제하는 방식도 쓰지 않는다.** 공개 문서 반영은 그 코드 커밋을 조상으로 포함하지 않는 문서 변경으로 만든다. 문서만 올린다는 말과 실제 공개 커밋 이력이 일치해야 한다.

브랜치 전환·분리 전 기존 stage와 사용자 handoff 문서를 보존한다. 완료 뒤 로컬 연구 브랜치명·구현 커밋·공식 실행 ID·산출물 해시·공개 문서 커밋을 종료 기록에서 연결한다. 미래 검산은 그 로컬 연구 코드 판과 고정 입력으로 수행하도록 명시한다. 공개 main의 PROGRAM_TRUTH 등에는 이 CLI가 main 코드로 제공되는 것처럼 쓰지 않는다.

이 작업은 Git 보관/문서 분리다. 연구 Python이나 공식 산출물을 수정하지 않으며, 분리 후 원래 연구 코드 해시가 같은지만 확인한다. 실제 연구 경로를 바꿔 구현을 다시 검증할 작업으로 확대하지 않는다. OCI 업로드·새 보관 형식은 추가하지 않는다.

## 5. 종료 기록과 기존 PLAN 판정 보완

현재는 **RESULT PASS · 보관 방식/커밋 승인 대기**다. 연구 결론 판정은 완료됐으며, 사용자가 아직 고르지 않은 공개/보관 처리가 남아 있다.

기존 PLAN 판정 §7의 ‘공개 조건 미충족 상태를 단계 종료로 기록하지 않음’은 연구 코드를 공개 배포하는 절차를 전제로 했다. **이번 RESULT에서는 사용자에게 (나)가 선택되고 아래 보존/문서 처리가 완료되면 공개 코드 배포 없이 연구 단계를 종료할 수 있도록 명시적으로 보완한다.**

(나) 선택과 승인된 작업의 성공 확인 뒤 다음을 기록한다.

```text
STATUS             = IMPLEMENTED_VERIFIED_CLOSED
RESEARCH_STATUS    = NO_REFERENCE_CASE
CODE_DISTRIBUTION  = LOCAL_ONLY
PUBLICATION        = DOCS_ONLY (공개 문서 push 성공 시)
운영 채택          = 없음
```

‘23개 구현 파일 공개 push 완료’, ‘main에서 연구 CLI 제공’, ‘라이선스 해결 완료’로 적지 않는다. 로컬 연구 보관과 공개 문서 반영의 실제 범위를 각각 적는다. 공개 main과 로컬 연구 브랜치가 서로 다른 커밋인 것은 이 방식의 의도된 상태다. 실제 문서 push가 실패하면 성공한 부분과 남은 부분을 구분한다.

결과서 끝에 이 판정 원문과 종료 절을 추가하고 PLAN·STATE·PROGRAM_TRUTH·BACKLOG에는 연구 결론·보관 범위를 맞춘다. §2-2 해석 주석도 결과서에 추가한다. **공식 report.md/json·protocol·원래 실험 산출물과 실행 코드는 그대로 둔다.**

추가 실화면 확인·PC 재기동·OCI pull·cron·키 변경·별도 handoff는 없다. 종료 작업 성공 사실과 보관 커밋/공개 문서 커밋을 짧게 보고하면 재판정 없이 닫는다. 사용자가 다른 공개 방식을 선택하면 그 선택의 미해결 조건부터 처리하며, 이 문서를 해당 방식의 공개 승인으로 사용하지 않는다.
