## 1. 조사 판정 — 원인은 확인됐고, 복구는 아직 실행하지 않았다

개발자 회신: 2026-11-02 17:47~17:52 KST, 약 5분. PC·API·OCI·갱신 기록 읽기만 했고 OCI SSH 읽기 1회. 요청한 30분 상한과 읽기 전용 경계 안이다. 추가 조사·검증자 라운드 없이 **이번 원인 확인을 수용**한다.

| 수용한 사실 | 판단 |
|---|---|

설계자는 요청서 첨부와 회신을 검토했다. 실행 로그·DB·코드를 직접 재현한 것은 아니다. PC 수급 10-30 반영과 화면 복구는 아직 미실행이며, 조사 수용을 구현 완료로 기록하지 않는다.

## 2. 선택 이유와 이번에 바꾸는 계약

맥북은 이동하며 쓰는 개발·판단 장치다. OCI가 이미 수집한 수급을 두고 맥북에서도 등록 IP를 맞춰 같은 공급자에 재조회하도록 요구하면 같은 문제가 반복될 수 있다. 이번에는 **수급 수집은 OCI, PC 반영은 기존 시장 갱신 동작**으로 연결한다.

- **C 채택:** 이미 검증·보관된 수급을 사용하므로 새 원천·키·가입·공급자 호출을 추가하지 않는다.
- **B 함께 적용:** 연결 실패나 공통 기간 제한을 사용자가 알 수 있어야 한다. 원래 기간 계산은 유지한다.
- **A는 선택적 임시 수단:** 당장 필요하면 기존 승인 범위에서 사용할 수 있으나, 이번 구현을 위해 IP 등록이나 PC 키움 인증 재시험을 먼저 요구하지 않는다.

기반 문서의 ‘PC는 OCI DB의 일관된 분석 복제본을 사용한다’는 방향과 부합하는 **수급 한 표의 연결**이다. 이 한 표를 연결했다고 PC 시장 DB 전체가 OCI와 같은 판이 됐다고 선언하지 않는다.

POC6-05 §6-8은 PC 수집의 전면 교체를 하지 않았고, §7·§9-6은 pull/export의 운영 DB 쓰기를 금지했다. 그 원문과 기존 명령 동작은 유지한다. 이번 새 PC 반영 함수에만 아래 범위를 적용한다.

> POC6-17에 한해, PC 시장 갱신은 POC6-05의 완료·검증된 OCI 수급 보관 사본을 PC의 `market_investor_flow_daily` 중 KOSPI 자료에 반영할 수 있다.
>
> 기존 pull/export는 보관 사본 전송·조회 기능을 유지하며 운영 DB 반영을 암묵적으로 수행하지 않는다. 반영은 별도 PC 함수에서 명시적으로 수행한다.
>
> OCI 운영 DB 원격 쓰기, SQLite 파일 전체 덮어쓰기, 가격·환율·WTI·보유·원장·PARAM 표 전환 및 ML 연구 입력 변경으로 이 허용을 확대하지 않는다.

PLAN은 현재 저장소의 직접 관련 계약과 이 문장을 대조한다. 설계자가 참고한 기반 문서 사본은 최신 git 전체를 대신하지 않는다. 실제 충돌이 추가로 있으면 해당 문장과 대안을 올린다.

## 3. 사용자 동작 — 기존 갱신 버튼을 사용

**「요즘 잘 오르는 ETF」의 [최신 시장 데이터 갱신]을 누르면, 기존 다른 갱신 단계는 유지하고 수급 단계만 다음처럼 바꾼다.**

1. 기존 POC6-05 가져오기 기능으로 OCI 완료 보관본을 PC에 받는다. 수신·해시 검증·재사용은 기존 기능을 쓴다.
2. 별도 수급 반영 함수가 검증된 수급 자료만 PC 운영 표에 반영한다.
3. 수급 반영 결과·실제 자료일을 갱신 결과에 남기고, 기존 화면 재조회에서 시장 흐름을 읽는다.

- **PC 갱신의 수급 단계에서는 키움 직접 조회를 호출하지 않는다.** 실패하면 기존 PC 수급을 유지하고 이유를 알린다. 직접 조회로 조용히 대체하지 않는다.
- 기존 키움 공통 수집 함수와 OCI 09:40 수집 경로는 유지한다. PC 호출부만 연결을 바꾼다.
- 기존 05 `pull`, 06 `run --pull`, 13 자동 실행·보관·백업 동작은 바꾸지 않는다. 이번에 별도 PC 일정이나 매일 자동 운영 표 반영을 추가하지 않는다.
- 따라서 **06 자동 실행으로 보관본을 받았다는 사실만으로 PC 운영 표가 갱신되지는 않는다.** PC 화면에 반영하는 동작은 위 버튼이다. 이 차이는 안내에 적는다.
- 새 메뉴·독립 수급 대시보드·별도 공개 API는 만들지 않는다. [요약 다시 읽기]와 `GET /market/flow-context`는 저장 자료 읽기만 한다.

갱신 버튼은 다른 자료에 대한 기존 공급자 조회·PC DB 쓰기도 수행한다. ‘외부 호출 0’은 **새 수급 반영 단계**에 대한 설명이며 버튼 전체가 읽기 전용이라는 뜻이 아니다.

## 4. 수급 반영 규칙

### 입력과 대상

- PC `state/ml/evidence/`의 기존 완료 묶음과 참조된 수급 object만 읽는다. 최신 연구 등록 묶음이나 가격 object를 수급으로 읽지 않는다.
- 05의 기존 schema·완료 공개·hash·참조 검증과 수급 단위·필수 필드 검사를 재사용한다. 묶음 전체가 PARTIAL이어도 **수급 자료 자체가 정상인지**로 구분한다. 실패·미시도·없는 자료를 0이나 정상 빈 자료로 바꾸지 않는다.
- 대상은 PC `state/market/market_data.sqlite`의 `market_investor_flow_daily`, market=KOSPI뿐이다. 기존 종목·날짜·투자자 구분과 단위를 그대로 쓴다.

### 정정·중복·실패

- 아직 반영하지 않은 수급 관측 판을 원래 OCI 확보 시각 순으로 처리한다. 서로 겹치는 날짜는 더 나중에 확보된 유효 관측으로 정정할 수 있다. PC 수신·반영 시각을 OCI 확보 시각으로 대체하지 않는다.
- 같은 묶음의 재반영은 중복 행·새 정정으로 만들지 않는다. 더 오래된 판으로 이미 반영된 최신 값을 덮지 않는다. 같은 관측 식별자의 다른 내용은 충돌로 보고한다.
- 기존 PC 직접 조회 값과의 최초 전환도 날짜·출처·확보 시각을 대조한다. 비교에 필요한 시각이 없거나 서로 다른 값의 우선순위를 정할 수 없으면 임의 덮어쓰기 대신 해당 충돌을 보고한다.
- 각 묶음의 수급 내용 전체를 검증한 뒤 한 트랜잭션으로 반영한다. 그 묶음의 반영 식별자·출처 기록도 같은 성공 경계에 둔다. 예외 시 해당 묶음 반영은 되돌리고 이전 성공 자료를 유지한다.
- 미반영 묶음 중간에 실패하면 그 사실과 앞서 완료된 범위를 표시하고 멈춘다. 뒤의 묶음만 처리해 전부 성공했다고 쓰지 않는다.
- 손상된 최신 입력을 숨기고 과거 입력만으로 정상 완료했다고 표시하지 않는다. 최신 수급 수집 실패가 기록돼 있으면 그 사실과 사용할 수 있는 마지막 성공 자료를 구분한다.
- 없는 날짜의 값을 보간하거나, 보관본 범위 밖의 기존 행을 삭제하거나, 새 과거 수급을 받지 않는다.

원래 묶음 ID·수급 object hash·OCI 확보 시각·PC 반영 시각·실제 반영 범위와 결과를 추적한다. 기존 출처·갱신 기록을 우선 재사용한다. 필요한 구분을 기존 구조로 보존할 수 없다면 PLAN에서 최소 저장안 하나를 제시한다. 범용 동기화 DB·새 보관 서버를 만들지 않는다.

## 5. 날짜와 실패 설명 — 같은 근거를 여러 출력에 사용

기존 D, 기간별 계산식·기간 선택·단기 변화 계산은 유지한다. 비교 날짜 설명은 서버의 공통 문장 생성부 한 곳에서 만들고 「시장 흐름 자세히」·대시보드·AI 복사문·판단 근거 미리보기에 같은 의미로 전달한다.

| 상태 | 문구 예시와 동작 |
|---|---|
| 코스피·수급이 모두 10-30까지 | ‘기간 비교 기준일 10/30 · 수급은 OCI 수집본을 PC에 반영’ |
| 코스피 10-30, 수급 10-22 | ‘코스피는 10/30, 수급은 10/22까지 있어 기간 비교는 10/22까지입니다.’ |
| 최신 반영 실패, 이전 값 있음 | ‘수급 자료 반영 실패 · 이전 수급 10/22까지 사용 중’ + 실제 실패 시각·정제된 이유 |
| 반영한 기록 없음·확인 불가 | ‘수급 연결 상태 확인 필요’ 또는 ‘아직 반영한 기록 없음’. 성공·실패로 추정하지 않는다. |
| 나중 수급 반영은 성공했고 과거 키움 오류만 있음 | 과거 인증 실패를 현재 장애로 계속 표시하지 않는다. 현재 반영 결과와 과거 기록을 구분한다. |

- 위 날짜는 예시다. 실제 각 자료일과 **공통 기간을 제한한 근거**로 문구를 만든다. 단순 날짜 차이를 근거로 모든 자료가 같은 날까지라고 표현하지 않는다.
- 환율·WTI의 최신 단기 관찰이 10-30이면 그대로 보인다. 기간 요약이 10-22라고 원자료도 10-22에서 멈췄다고 쓰지 않는다.
- 수급 외의 누락 때문에 공통 끝일이 제한되면 수급만 원인으로 지목하지 않는다.
- 갱신 전체가 `completed`여도 수급 반영 실패·미완료를 구분해 보인다. 서버 재기동으로 상태를 잃었으면 ‘확인 불가’이며, 자료 날짜를 새 성공 증거로 쓰지 않는다.
- 인증·전송 오류는 짧은 한국어 사유로 정리한다. 키·토큰·IP·원시 인증 응답은 노출하지 않는다.

### 필요한 버튼 안내

코스피의 저장 기준일보다 수급이 앞서 기간을 제한하거나, 수급 반영 실패가 확인되면 기존 [시장 자료 갱신 화면] → [최신 시장 데이터 갱신] 동선을 안내한다. 확인된 수급 상태를 근거로 POC6-16의 기존 ‘지금 할 일’에 작은 항목을 연결할 수 있다. 같은 작업 버튼을 여러 개 강조하지 않는다.

공통 날짜 비교는 **확인된 기간 제한**을 설명하는 것이며 새 ‘N일 지연’ 기준이 아니다. 코스피·수급이 함께 오래됐는데 날짜가 같다는 이유로 ‘전체 최신’이라고 표시하지 않는다. GET 실패·자료 미확인만으로 갱신이 필요하다고 단정하지 않는다. OCI 수급 자체의 최근 수집이 실패했다고 확인되면 반복 버튼 클릭으로 해결된다고 안내하지 않는다.

## 6. 변경 범위와 검증 보장 범위

- 새 PC 수급 반영 모듈을 두고 PC 시장 갱신 오케스트레이터의 해당 단계에 연결한다. 공통 수집 함수에 PC·OCI 전환 분기를 흩뿌리지 않는다.
- 기존 시장 흐름 응답·공유 문장과 필요한 표시부만 보완한다. 반영 성공 뒤 기존 관련 캐시·재조회가 실제 새 응답을 읽게 한다. 화면 열기·이동·다시 읽기가 수집이나 DB 쓰기를 유발해서는 안 된다.
- 새 의존성·OCI 배포·키 변경·cron·ML 학습/예측 변경은 목표 범위에 없다. 파일 크기 등 기존 구현 규칙은 지키되 관련 없는 분리 작업은 붙이지 않는다.
- 검증 보장은 **검증된 입력의 선택·정정 순서·단위·원자적 반영·재실행 안전성과 표시 일치**다. 기존 05 검증을 재사용하며 새 서명 체계나 기록 전체의 의도적 동시 위조를 판별하는 시스템을 요구하지 않는다.

## 7. 짧은 PLAN에 필요한 확인 — 구조만, 30분 이내

이미 확인한 원인·IP·OCI 수집을 다시 조사하지 않는다. 아래 다섯 묶음만 확인하고, 30분 안에 부족하면 해당 칸을 질문으로 남긴다. 라이브 DB 쓰기·새 외부 호출·새 pull·수집 실행은 PLAN에서 하지 않는다.

1. **입력 연결:** 현재 PC에 있는 05 수급 object 한 개의 구조·단위·성공 구분·확보 시각과 실제 검증·가져오기 함수. 새로 조회하지 않고 기존 사본을 사용한다.
2. **쓰기·정정:** 대상 표의 실제 키·출처·시각·갱신 기록과 재사용 가능한 upsert·트랜잭션·실행 잠금. 최초 전환의 충돌 유무, 추가 저장 구조가 필요한지.
3. **PC 호출 경계:** 기존 갱신 버튼에서 직접 키움 수급 조회를 바꿀 한 지점, 기존 pull을 명시적으로 호출할 방법과 시간 상한. 다른 단계 실패와 수급 반영 결과를 분리하는 방법.
4. **출력 경계:** 공통 설명 생성부, 네 출력·캐시·기존 할 일로 전달할 필드, 정상·기간 제한·반영 실패의 부분 화면 문구 예시. 전체 화면 목업·새 목업 서버는 요구하지 않는다.
5. **격리 검사와 실제 확인:** §8의 검사 접점, 실제 반영 대상·예상 변경 범위·사용자 승인 항목. 현재 기반 문서 충돌은 원문 문장과 최소 보완안을 함께 적는다.

질문은 실제 불일치에 한정한다. 형식이 맞으면 질문을 만들지 않는다. PLAN 판정 뒤 구현하며 실제 PC 운영 표 반영은 별도로 제시한 승인 범위에서 한다.

## 8. 수용 기준과 실제 연결 확인

격리 자료·임시 DB로 다음을 확인한다.

- 회신과 같은 입력이면 수급 10-22 → 10-30 반영, 공통 D도 10-30. 다른 원천의 값을 미래 날짜로 밀지 않는다.
- 같은 묶음 재반영, 최신 판 뒤 과거 판, 겹친 날짜의 후속 정정, PC 최초 전환의 시각·값 충돌을 구분한다.
- 수급 정상/다른 자료 실패인 묶음과 수급 실패/손상인 묶음을 구분한다. 필수 값 결측을 0으로 만들지 않는다.
- 전송·검증·DB 반영 실패에서 이전 표와 원본 보관본을 보존하고, 성공 기록만 앞서 남지 않는다.
- 다른 market·가격·환율·WTI·보유·원장·PARAM 표와 연구 원본을 바꾸지 않는다. 기존 pull/export·06·13 동작에 운영 DB 쓰기가 새로 생기지 않는다.
- 기간 제한·정상·첫 조회 실패·이전 값이 있는 실패·옛 실패 뒤 성공을 출력별로 대조한다. 직접 키움 조회 대체 호출과 GET의 쓰기는 0이다.

관련 검사 뒤 변경 범위에 맞는 최종 회귀를 한 번 수행한다. 과거 학습·공식 성과 연구·GPU 실행을 다시 하지 않는다.

실제 연결 확인은 사용자 승인 범위에서 **기존 보관본을 쓰는 PC 반영 1회**로 한다. 반영 전후 수급의 자료일·행 범위·출처와 비대상 표 불변, 실제 공통 D·화면·복사문을 확인한다. 기존 전체 갱신 버튼을 사용하면 그 버튼의 다른 외부 조회·쓰기 범위도 승인 설명에 포함한다. 단독 확인 함수가 필요하면 동일 핵심 함수를 호출하게 하며 별도 수집 도구는 만들지 않는다.

OCI 쓰기·pull 배포·등록 IP 변경·수급 재수집은 실제 확인 조건이 아니다. 현재 보관본으로 해결할 수 없다는 사실이 드러나면 그 부족분만 보고한다.

## 9. 진행과 종료

조사 요청서·이번 회신의 핵심 사실 보관 → 짧은 PLAN → 설계자 판정 → 구현·검토·관련 검사·필요한 부분 화면 확인 → 검증자 → RESULT 판정 → 승인된 실제 PC 반영·커밋·push → 종료 기록.

- 조사 회신은 이번 PLAN에 출처·관측 시각과 함께 보존해도 된다. 조사만의 별도 커밋이나 결과서·재검증을 추가하지 않는다.
- RESULT에는 수급 입력의 수신/확보/반영 시각, 반영 범위·D·출력, 기존 직접 조회 제거 범위와 미변경 경계를 적는다.
- 기존 POC6-15·16은 종료를 유지한다. 05·06·13 연구·자동 실행, Q6 OPEN, 운영 ML 미승격과 미완료 요구는 유지한다.
- 완료 뜻은 **OCI에서 확보한 수급을 PC 기존 갱신 동작으로 반영하고, 기간 제한·실패를 알아볼 수 있게 연결한 것**이다. 전체 시장 자료 자동 동기화·전체 ML 상태 화면·추천 효용 달성으로 확대하지 않는다.
- 사용자 소유 handoff 문서와 로컬 연구 브랜치는 기존 경계를 유지한다. 새 handoff·후속 ML 연구를 자동으로 열지 않는다.
