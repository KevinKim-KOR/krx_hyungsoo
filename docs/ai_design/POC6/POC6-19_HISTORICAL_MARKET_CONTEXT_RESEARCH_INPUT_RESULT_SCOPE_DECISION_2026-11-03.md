# POC6-19 RESULT 범위 확정과 선반영 판정

저장 권장 위치: `docs/ai_design/POC6/POC6-19_HISTORICAL_MARKET_CONTEXT_RESEARCH_INPUT_RESULT_SCOPE_DECISION_2026-11-03.md`

## 1. 판정

**POC6-19 전체 상태는 PARTIAL로 유지한다. 구현·시험·원/달러·WTI 선행 사본의 수용은 지금 확정하고, 검증된 코드·문서는 먼저 커밋·push할 수 있다. 키움 실제 실행과 결과 확인은 같은 POC6-19의 남은 보충 작업이다.**

이번 요청의 Q1은 **(a)의 선반영 방식**을 채택한다. 다만 ‘최종 RESULT’는 현재 확인된 범위에 대한 판정 확정을 뜻한다. 수급과 세 자료 공통 범위까지 확보한 전체 종료·완료 판정은 아니다. 현재 확보되지 않은 자료를 포함한 PASS로 바꾸지 않는다.

변경 이유: 직전 판정의 코드 정정은 끝났고, 검증자 §14가 변경분을 VERIFIED로 확인했다. 등록망 연결을 기다리는 일이 이미 확인된 구현과 Yahoo 자료의 품질을 더 확인해 주지는 않는다. 확인된 범위를 먼저 반영하고 미확인 범위를 문서에 남기는 것으로 충분하다.

**직전 RESULT 판정의 ‘키움 결과 확인 뒤 커밋·push’ 조건은 이번 판정의 선반영 허용으로 변경한다.** 직전 판정 원문은 당시 판단으로 보존하고, 현재 상태·다음 행동은 이 문서를 우선한다. 다른 계약과 기존 운영 경계는 유지한다.

## 3. Q2 — 커밋·push

**지금 선커밋·push를 허용한다.** PLAN·RESULT에 기록된 사용자 ‘모두 승인’ 범위를 재사용하며 같은 승인을 다시 요청하지 않는다.

- 대상은 검증된 연구 코드·시험과 현재 사실을 기록한 설계/판정·PLAN·RESULT·STATE·PROGRAM_TRUTH 등 관련 문서다. 이 판정문도 원문으로 보관한다.
- 커밋 직전 실제 변경 목록만 확인한다. 최신 사용자 전달의 18개 stage는 개발자 보고이며, 이번 판정문 추가 등으로 수가 달라질 수 있다. 과거 17/18개를 맞추려고 파일을 넣거나 빼지 않는다.
- 연구 원자료·산출물·실행 망 지문/주소·키·토큰·개인 자료와 사용자 소유 7월 26일 handoff는 제외한다. OCI pull·배포·설정 변경은 없다.
- 검증 완료 이후 새 코드 변경이 없으면 코드 검증·전체 회귀·프런트 검사·변이 전수를 반복하지 않는다. 문서의 상태·판정 연결을 맞추는 일을 별도 POC로 만들지 않는다.
- 기존 대기나 수집을 커밋 때문에 멈출 필요는 없다. 대기/실행 중인 검증된 코드와 입력은 바꾸지 않는다. 실제 실행의 커밋·파일 해시는 당시 기록을 유지한다.

키움 결과가 나중에 나오면 결과 부분 확인과 설계자 보충 판정 뒤 문서 보충 커밋·push로 반영한다. 선커밋 전에 결과가 이미 도착하면 확인을 마친 내용은 함께 반영할 수 있다. 미확인 결과를 먼저 완료로 쓰지는 않는다.

## 4. Q3 — 원/달러·WTI 판정 근거

**첫 번째 선택, 낮 선행 폴더를 판정 근거로 고정한다.** 오늘 밤 새 Yahoo 응답으로 이번 수용의 근거를 교체할 필요가 없다.

근거 묶음은 다음과 같다.

1. 선행 실행 `20261103T044323Z_92947186`의 원시·당시 코드/보고/파일 목록.
2. r1~r3의 원시→정규화 독립 대조와 파일 불변 확인.
3. §14의 새 형식 대조: 원시와 기존 정규화 3파일은 같고, 새 제외 목록과 report.json/md 형식만 다르다는 확인. 검증자는 별도 임시 사본에서 현행 형식의 verify=OK도 확인했다.

**낮의 원본 폴더는 정정 전 형식 그대로 보존한다.** 현행 verify에서 새 제외 목록·report.json·report.md의 차이 3건이 나오는 것은 알려진 형식 차이다. 원본 손상이나 새 조회 필요로 판단하지 않는다. 낮 폴더 자체를 ‘현행 코드로 verify 완전 일치’라고 보고하지도 않는다.

지금 별도 변환 사본 생성이나 재수신은 요구하지 않는다. 표와 문서에는 낮 원본, 검증자의 새 형식 대조, 향후 새 실행을 구분해 적으면 된다.

이미 승인된 오늘 밤 전체 실행에서 Yahoo 8회 재수신이 이뤄지면 새 판으로 보존한다. 그 판을 더 좋은 수치·더 편한 형식이라는 이유로 기존 수용 근거와 조용히 바꾸지 않는다. 해당 새 실행의 검산·결과는 별도 실행 ID로 기록한다. 차이가 발견되면 차이와 해석을 보충한다.

## 5. Q4 — 등록망 대기의 의미

**지금은 ‘접근이 계속 막힌 자료의 종료 범위를 확정’하는 상황으로 적용하지 않는다.** 현재는 집 인터넷에 연결한다는 실행 전제를 아직 충족하지 않은 상태다. 수급 공급자가 과거 이력을 제공하지 않는다는 근거가 아니다.

오늘 밤의 사용자 요청에 따른 1회성 대기는 유지할 수 있다. 이번 판정은 새 예약·LaunchAgent·상시 데몬이나 추가 망 탐색을 만들라는 지시가 아니다.

다만 결과서 §9-3의 실제 방식은 **미등록으로 확인된 망과 다른 망을 감지해 실행을 시도하는 것**이다. 이를 ‘등록 IP 망임을 확인했다’고 표현하지 않는다. 키움 인증이 거절되면 기존 계약대로 자료 요청 없이 중단하고, 성공 여부와 실제 실행 ID로 사실을 기록한다. 기존 요청·재시도·자원 예산과 사용자 승인 범위를 늘리지 않는다.

대기가 끝나도 실행되지 않았다면 ‘등록망 연결 미충족·공식 실행 미실행’을 기록한다. 실제 등록망 실행에서도 접근이 거절됐다면 그 응답을 기록한다. 어느 경우도 SOURCE_UNAVAILABLE이나 과거 이력 미제공으로 바꾸지 않는다. 이후 종료 범위가 필요하면 그 새 사실로 판단하며, 재연결·재실행을 무한히 자동 반복하지 않는다.

## 6. 남은 전달과 종료 조건

**지금 다음 전달 대상은 개발자다.** 이 판정을 문서에 연결하고 현재 확인된 범위를 커밋·push한다. 새로운 PLAN과 개발자 전체 완료보고 묶음을 다시 만들지 않는다. 실제 커밋 해시·push 결과·키움 대기/실행 상태를 짧게 보고하면 된다.

키움 실행이 끝나면 같은 POC6-19 결과서에 다음을 보충한다.

- 실행 ID, 실제 등록망/인증·자료 요청 결과, A→B 진행 또는 중단 근거.
- 요청일과 응답 날짜의 직접/간접 확인, 지수 대조·13분류·단위, 실제 범위·개수·실패/미요청 구분.
- 원본 검산과 봉인 가격 및 다른 자료와의 공통 날짜/주 범위, 자료별 최종 상태.

검증자는 새 실제 산출물·결과 부분만 확인한다. 코드가 바뀌지 않았다면 기존 코드 심사 전체를 반복하지 않는다. 그 확인 뒤 설계자가 같은 POC6-19의 보충 RESULT와 전체 종료 여부를 판단한다. 키움 완료 보고만으로 자동 PASS하거나 다음 연구를 시작하지 않는다.

이 판정으로 ML 효용·총수익·당시 공개 판·새 미사용 시험을 확보했다고 하지 않는다. Q6 OPEN·운영 ML 미승격·기존 미완료 요구와 05·06·13·17 운영은 유지한다.

## 7. 근거와 확인 주체

직접 읽은 자료: 최신 첨부 RESULT(1)의 §4-4·§7·§9-3·§14 및 관련 현재 상태, 사용자 전달의 2026-11-03 20:00 개발자 요청. 직전 설계와 PLAN/RESULT 판정은 앞서 읽은 원문을 재사용했다.

검증자 §14는 변경 경로 11건과 Yahoo 통신 실패 독립 확인 1건, 합계 12건 통과를 보고했다. 개발자의 전체 관련 96건·변이 7종과 검증자의 직접 실행을 구분한다. 대기 프로세스·19:49 망 상태·stage 18개는 최신 개발자 보고이며 설계자가 사용자 맥북이나 저장소를 직접 실측한 사실이 아니다.

설계자는 이번 요청에서 API 조회·사용자 저장소 구현·대기 프로세스 제어·커밋·push·OCI 작업을 직접 수행하지 않았다.
