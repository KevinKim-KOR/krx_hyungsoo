# POC6-21 PLAN 판정 — 추세 참여와 단기 재진입·재이탈의 ML 효용 검증

## 1. 판정

**PLAN = PASS.** 첨부 PLAN V1의 §0~§6 전체를 설계 검토 판정 및 통합 설계 V1 개정 2와 대조했다. Q1~Q10 반영, 절대 정답 분모 확인, 재사용/신규 구현 경계, 실행·확인·승인 범위를 수용한다.

**§3의 집계 모수 설명을 보완해 잠금에 반영한다. 실제 분기별 학습 행·공통 날짜·35 fit이 확인된 값대로라면 문서 보완으로 끝내며 PLAN 재제출·새 설계 검토는 요구하지 않는다.** 현재 판정은 기술 PLAN의 통과이며 사용자 실행 승인이나 투자 효용 판정은 아니다.

설계자가 실제 저장소·봉인 DB에서 새 분모를 계산하거나 stage·원격을 검사한 것은 아니다. 첨부 본문과 최신 개발자 보고를 근거로 한다. 학습·정답 크기·점수 분포·성과를 보지 않은 읽기 전용 확인이라는 보고를 수용한다.

## 2. 구현·문서 경계 수용

- 새 `app/trend_switch/`에서 절대 정답·주간 규칙·별도 감사·거래/묶음 분석·최장 고점 미회복 기간·연구 실행/검산을 맡는 안을 수용한다. CLI와 변경 경로 중심 시험도 같은 범위다.
- H1의 `_State`·`_open`·`_close`를 체결·이연·보호에 재사용하고, POC6-20의 시장 4열·34열 학습·잠금 구조를 재사용한다. H1·POC6-19·20 코드·잠금·산출물 수정과 monkey patch는 없다. 직접 의존 코드는 이번 잠금에 연결한다.
- H1 주간 규칙과 `audit_book`의 10위·SMA60·검토 4회 대기를 이번에 재사용하지 않는 이유를 수용한다. 별도 규칙과 감사는 실제 계약 충돌을 해소하는 구현이며, 새 일반 거래 엔진·증거 플랫폼은 추가하지 않는다.
- 파일·helper 분리는 개발자가 같은 책임 경계 안에서 정한다. 추정 줄 수를 채우거나 기존 자료/지표 기능을 다시 만드는 목표로 쓰지 않는다.
- 세 기반 문서에 독립 예외 원문을 추가했고 원설계에 우선 문서를 연결했다는 보고를 수용한다. 기존 예외·제한·원문은 보존한다. 이미 완료한 문서 작업을 반복하지 않는다.
- PLAN §0은 당시 검토 회신과 질문의 이력이다. 현행 적용은 §1 및 설계 검토 판정의 확정값이며, §0의 과거 권장안 Q2(a)·Q4(a)를 다시 적용하지 않는다.

## 3. 분모 수용과 집계 설명 보완

다음은 개발자가 읽기 전용으로 확인한 값으로 수용한다. 잠금/prepare는 같은 입력과 계약에서 실제 값을 대조한다.

| 항목 | 수용한 값·의미 |
|---|---|
| 절대 정답 가능 행 | 113,269. ETF 자체 판정에서 069500 미래 행 요건을 제거해도 이번 사본에서 제외 차이 0건이라는 보고 |
| 선행 재생 정기 계획 | 153주, 첫 신호 2017-12-28, 공통 K 실행일 2018-01-03 |
| 주 평가 정기 계획 | 289주, 첫 신호 2020-12-30, 공통 K 실행일 2021-01-05, 마지막 계획 2026-09-11 |
| 보조 구간 정기 계획 | 99/100/90주 |
| 정기 계획 없는 주 | 선행 재생 4주·주 평가 9주. 보유 평가·일별 보호까지 생략하는 날짜가 아님 |
| 분기 학습 | 35분기 모두 최소 104주·5,000행 충족. 실측 최소 161주·7,427행, 최대 72,418행 |

069500 조건을 제거한 결과가 이번 사본에서 같아도, **ETF 절대 정답에 그 조건을 되살리지 않는다.** 정답은 연결 종가/합성 시가에서 직접 계산하며, 이미 순위화·중심화된 H1 정답에서 복원하지 않는다. K 장부의 가격 유효성은 별도 필수다.

**필수 설명 보완 1건:** PLAN §2는 ‘주간 신호 663 / 자격 20종 이상 636 / 4열 정의 627’과 ‘학습 사용 621 / 성숙했으나 사용 불가 2 / 미성숙 13’을 함께 적고 있다. `621+2+13=636`이므로, 이 표를 동일한 모집단에서 필터를 순차 적용한 결과로 읽으면 모호하다. 이는 숫자가 틀렸다고 확정하는 지적이 아니라 **서로 다른 집계 모수·교집합·적용 순서를 밝혀야 한다는 보완**이다.

아래를 기존 셈 결과로 명시한다.

1. 627은 전체 신호 중 시장 4열 정의일인지, 자격 조건까지 적용한 교집합인지 구분한다.
2. 621/2/13과 113,269행은 시장 공통 조건 적용 전/후 어느 집계인지 표기한다. 서로 다른 모수를 같은 순차 제외 표처럼 쓰지 않는다.
3. **실제 fit에는 자격·절대 정답 성숙/유효성·날짜 요건·시장 4열 정의가 모두 반영된 공통 학습 날짜/행만** 들어간다. 그 최종 집계와 분기별 최소값·35 fit의 연결을 분명히 하고 prepare 기대값도 같은 의미로 둔다.

이미 산출한 분기별 교집합 결과를 재사용한다. 설명에 필요한 기존 결과가 남아 있지 않은 경우에만 해당 가용성 집계를 한정 보완하며, 정답 값·분포·성과는 계산하지 않는다. 설계자는 미확인 교집합 수치를 임의로 만들어 잠금값으로 정하지 않는다. 최종 날짜/행·최소 학습 조건·필수 fit이 보고와 다르면 그 차이만 보고하고 잠금·공식 실행을 진행하지 않는다. 같은 값을 얻기 위한 전체 재조사는 없다.

강화 검토 기회·비적격 보류·직전 손익별 거래·10거래일 묶음은 실행 경로에 의존하므로 지금 셈을 요구하지 않는다. 정의를 잠그고 실행 뒤 실제 분모를 보고한다.

## 4. 실행 계약 유지

이번 PLAN은 아래 계약을 바꾸지 않는다.

- R0/R1/M0/M1은 같은 RET_120 후보 순서·공통 시점·체결/현금·보호 계약을 사용한다. 정책 간 차이는 점수 종류와 최근 구간 강화뿐이다.
- 최근 구간은 판단일−실제 체결일의 한국 시장 거래일 위치 차이 0~10이다. 강화 문턱은 2h이고, 보호청산을 늦추는 조건이 아니다. 40bp에서도 문턱은 바꾸지 않는다.
- 정상적인 신규 편입 자격 탈락으로 점수가 없는 보유는 통상 판단을 보류하며 보유 평가·보호는 유지한다. 필수 계산 실패·비유한 값·가격 불확정은 CHECK_REQUIRED다.
- 강화 분모는 문턱 통과·체결 이후가 아닌, 2h를 대입하는 문턱 판정 직전의 유효한 검토 기회다. 주 평가 20bp M1 기회 0은 강화 축 NOT_JUDGED이며 결합 후보로 삼지 않는다. 기회가 있고 효과가 같으면 유효한 미관측이다.
- 선행 재생 5개 20bp 장부가 유효하면 같은 실행 안에서 주 평가 10개 장부로 이어간다. 선행 성과가 낮다는 이유로 멈추거나 설정을 선택하지 않는다. 필수 장부·가격·자료·학습·복원·예산 유효성 실패는 정상 성과로 덮지 않는다.
- 이미 본 기간의 탐색적 합성 가격지수 연구라는 한계를 유지한다. ML 추가 효용·강화 효용·목적/위험/부담·40bp 축과 불확실성을 함께 보고하며, 총수익 검증·운영 채택은 NO다. 성과가 낮아도 같은 조건을 바꿔 재시도하지 않는다.

## 5. 확인·예산 범위

PLAN §5의 손계산·새 독립 감사·실행 흐름/변이 확인·실제 LightGBM 작은 가짜 자료의 34열 절대 목표 학습/저장/복원을 수용한다. 격리 확인은 공식 가격·성과를 사용하지 않고 공식 35 fit과 구분한다. 새 감사가 새 주간 정책 함수를 그대로 호출해 같은 오류를 재현하는 방식으로 독립 확인을 대신하지 않는다.

확인은 새 절대 정답과 069500 의존 제거, 0/10/11거래일 경계·이연 체결일, 보호 우선·중복 취소·초기 예외, 비적격 보류와 실제 장애 구분, 검토 기회·거래/묶음·회복 계산, 판정에 집중한다. 기존 연구·전체 회귀·프런트 검사를 관성적으로 반복하지 않는다. 실행 전 독립 검토는 개발자가 제시한 확인 범위로 수용하며 별도 역할·새 승인 게이트를 추가하는 뜻이 아니다.

**F1/F2 교훈 적용:** 지표·거래 분석·bootstrap·최종 판정뿐 아니라 보고 본문 생성·파일목록·해시 등 후처리 계산까지 끝난 뒤 정상 완료 직전 최종 예산을 한 곳에서 판정하고 verify가 그 기록을 확인한다. 마지막 계산 이후 상한 초과가 OK로 남는 두 종류의 경계를 새 flow에서도 놓치지 않는다. 과거 연구 전체를 다시 돌리거나 최종 요약 파일 I/O의 끝까지 완벽 인증하는 새 과제는 추가하지 않는다.

3분·RSS 3GB 안팎은 추정이다. 공식 상한은 **35 fit·90분·RSS 8GiB·CPU 4스레드**다. 기존 환경과 OpenMP 로드 순서를 기록하며 설치·버전 변경은 없다. 초과/실패·정정 전 기록은 보존한다.

## 6. 사용자 승인 한 묶음

PLAN §6대로 이 단계의 다음 범위를 한 번에 확인한다. 이전 POC6-20 승인은 POC6-21로 넓히지 않는다.

1. **구현·격리 확인:** 확정 PLAN의 PC 연구 패키지·CLI·시험, 작은 가짜 자료의 실제 LightGBM 확인.
2. **공식 실행 1회:** 봉인 가격/POC6-19 사본 읽기 전용, 새 `state/ml/research/poc6_21/` 쓰기, 최대 35 fit·90분·8GiB·4스레드. 선행 재생과 주 평가를 포함한다. 외부 조회·설치·운영 DB·OCI·PUSH·UI 작업은 없다.
3. **종료 반영:** 검증자 확인과 설계자 최종 RESULT 수용 뒤 관련 코드·문서 커밋·push. 연구 산출물·잠금/모델·원자료·사용자 handoff는 제외한다. OCI 배포는 포함하지 않는다.

이 승인을 받으면 같은 범위의 중간 작업마다 다시 묻지 않는다. 코드 결함으로 추가 공식 실행이 필요하면 원인·동일 조건 여부·기존 실행 보존을 보고하고 그 정정 실행만 별도로 승인받는다. 성과 미달은 정정 실행 사유가 아니다.

## 7. 다음 행동과 종료 경계

판정 원문 보관 → §3의 집계 설명을 기존 PLAN에 반영·현행 상태 표시 → 부족한 사용자 승인 한 묶음 → 구현·격리/독립 확인 → 사전 잠금·분모 대조 → 공식 1회 실행·verify → RESULT 및 검증자 확인 → 설계자 최종 RESULT 순서다.

새 충돌이 없고 실제 공통 분모/35 fit이 보고와 같으면 PLAN 재제출·설계 재검토·새 조사 문서는 없다. 설계자·개발자·검증자 체계를 유지한다. 운영 ML 미승격·Q6 OPEN·기존 운영/전향 축적·미완료 요구는 그대로다. 새 BACKLOG 등록·UI·공급자·별도 handoff를 묶지 않는다.
