# POC6 자료 사용·축적·PUSH 연결 현황 — 읽기 전용 점검 요청

작성: 설계자 · 2026-10-27 · 독자: 개발자·사용자

**목적:** 추가 정보가 어디에 쓰이고 실제로 계속 보관되는지 현재 코드·운영 자료로 한 번 연결 대조한다. POC 번호·새 개발 단계·감사 시스템을 추가하지 않는다. POC6-12의 공식 원본 확보·구현 전에 회신하며, 그 PLAN의 출처 확인과 병행할 수 있다.

이 문서는 점검 지시다. 설계자가 현재 PC·OCI를 직접 실측한 결과가 아니다. 코드·DB·cron·환경·알림·수집/학습·보관 정책은 이번 점검으로 바꾸지 않는다.

## 1. 이미 정한 사용자 방향과 남은 선택

2026-10-26 계약 V1.1 §2-1의 A·B·C는 확정이다. 주 1회 정기 검토·일별 큰 변화 확인, 기대 보유 수주~수개월, 비용 후 KODEX200 대비 성과 우선, PC 권고 목표·Telegram 관찰/브리핑·자동 주문 제외를 다시 묻지 않는다.

실제 참고용 추천을 채택하기 전에는 사용자 개인의 허용 손실/낙폭과 감당 가능한 매매·보유 부담을 권장안과 함께 확정해야 한다. 연구에서 쓴 −15% 보호 이탈·회전율 6·상위 5개를 개인 계좌 승인으로 쓰지 않는다. 모델·목표·특징·실험 문턱을 사용자에게 임의로 정하라고 넘기지 않는다. POC6-12 자료 검증을 시작하기 위해 새 투자 목표를 정할 필요는 없다.

이번 점검은 PUSH에 새 추천이나 수급·환율을 자동 연결하라는 지시가 아니다. 의도된 PC/연구 분리와 실제 연결 누락을 구분한다.

## 3. 확인할 다섯 묶음

### A. 실제 PUSH의 입력·판정·문장

현재 OCI 실행 경로에서 시장 브리핑·보유 브리핑·장중 위험 알림의 진입점→읽는 표/자료→계산/조건→렌더러를 좁게 추적한다. 최근 정상 발송 기록을 유형별 1건 대조한다. 새 메시지·테스트 발송은 하지 않는다.

가격/국면·수급/환율/WTI·거래량/흔들림·동일 기간 비교·종목 이동평균·새 ML 가운데 **이번에 추가한 값**이 실제로 어느 경로에 연결됐는지 적는다. 과거부터 있던 유사한 거래량·이동평균 계산과 새 PC 선택 필드를 혼동하지 않는다.

date_mismatch의 현재 발생 여부, 비교 못 한 대상과 조건, 어떤 판단을 못 하는지, 사용자에게 보이는 경고를 확인한다. 발송 sent만으로 위험 판단이 정상이라고 판정하지 않는다. 과거 10-23 경고가 현재 해소됐으면 근거와 함께 해소로 적는다.

### B. 실제 일일 축적·정정·PC 가져오기

현재 점검 시각(KST), 배포 코드, 활성 시각/스케줄을 기록한다. 최근 **완료된 국내 거래일 최대 7개**에 대해 09:40 보관 작업의 예정/실제 실행·기준일·소스별 기대/성공/실패·미완료·SKIPPED 사유를 대조한다. 도입 전 날짜를 누락으로 세지 않고 휴장·외국 시장 날짜 차이·공급자 미제공을 구분한다.

최신 1묶음과 이전 1묶음에서 목록·OHLCV·수급·환율·WTI·KRX/지수의 파일/표·범위·수신/공개 시각을 표본 대조한다. 기대 종목 수는 당시 목록을 쓰고 1,183을 영구 분모로 고정하지 않는다. 이미 있는 검사 결과와 읽기 전용 상태 조회를 재사용한다.

PC 최신 수신일·미수신 묶음 수·불일치/실패를 확인한다. 점검 중 pull·재수집·복구·색인 재생성처럼 자료를 쓰는 명령은 실행하지 않는다. 필요하면 ‘미수신’으로 보고한다. 120일 수신 창을 단순 접합하지 않는 현재 선택 규칙도 확인한다.

### C. 원자료에서 룰·ML 입력으로 이어지는 경로

수신 판→해시/관측·공개 시각→연구 입력 선택→특징 계산/저장→예측→목표 성숙의 실제 접점을 적는다. 이미 실제로 쓰는 입력과 수집만 해 둔 잠재 입력을 구분한다.

오래된 etf_ml_feature_daily의 현재 최신일·생산 작업·실제 소비자가 있는지 확인한다. 새 연구가 별도 사본에서 특징을 다시 계산한다면 ‘옛 표 미사용’으로 적는다. 오래된 표를 현행 기능이 최신처럼 읽는다면 그 영향 기능을 특정한다. 이 표를 이번에 갱신하거나 전체 특징 저장소를 재설계하지 않는다.

KRX 운영 원응답 중 미보관 칸, 현재 확보하는 OHLCV, 별도 보관하는 수급/거시, 분배·기업행사의 미확보 범위를 구분한다. 자료일과 실제 확보 가능 시각을 혼동하지 않으며, 과거 backfill을 당시 수신한 PIT 자료로 인증하지 않는다.

### D. POC6-06 전향 비교의 현재 실행 상태

최근 입력 기준일·마감 전 유효 기록일·종목/방법 수·진단/미확인·실행 실패·PC 미실행을 구분해 센다. PC 미실행일을 자동 장애나 정상 예측 완료로 바꾸지 않는다.

현재 모델 판·학습 시각·다음 학습 조건과 성숙 예정/도래 상태를 읽는다. 기존 기록 기준 첫 목표 성숙은 11-19 종가 뒤이므로 그 전 성숙 결과가 없다는 사실을 실패로 쓰지 않는다. 월별 학습은 새로운 성숙 예제와 유효 run이 필요한 조건부 동작임을 확인한다. 점검을 위해 새 예측·학습·성과 계산을 실행하지 않는다.

### E. 보존과 다른 장비에서의 복구 가능 범위

POC6-02~11의 연구별 코드/입력/설정/예측/정답/학습 가중치가 어디에 남아 있는지, PC_ONLY인지 등록된 OCI 사본이 있는지, 마지막 복원 확인 근거를 기존 목록/해시로 표로 적는다. 큰 파일의 불필요한 전수 재해시나 모델 로드는 하지 않는다.

원래 저장하지 않은 가중치, 절대경로 때문에 무수정 재실행이 안 되는 과거 산출물, 의도된 POC6-10 로컬 브랜치 조건을 분리한다. 바이트 복원과 실험 재실행 가능을 같은 것으로 쓰지 않는다. 현재 허용된 보관 형식을 넓히거나 새 연구를 업로드하지 않는다.

## 4. 회신 형식·예산·우선순위

별도 PLAN·POC·검증자 라운드 없이 **현재 현황표 1개와 발견 사항**으로 회신한다. POC6-12 PLAN에 부록으로 넣어도 된다. 전 저장소 재감사나 신규 UI/로그 시스템 개발은 없다.

현황표 열: 자료/기능 | 수집 주체·시각 | 저장 범위·최근일 | PC 표시/AI 사용 | 실제 PUSH 판단/문장 사용 | 룰·ML 소비 경로 | 사본/복원 범위 | 근거 날짜·상태.

상태는 운영 정상 / 의도된 미연결 / 미구현 / 운영 결함 / 확인 불가로 구분한다. 운영 결함은 사용자에게 실제로 무엇을 못 보여 주거나 잘못 판단하는지 적고, 미연결이라는 이유만으로 모두 결함으로 올리지 않는다.

**실제 읽기 전용 점검은 60분 상한**이다. 기존 결과·원장·수집 manifest·상태 명령을 먼저 재사용한다. 제한된 시간 안에 못 확인한 칸은 확인 불가와 필요한 근거를 적는다. 비밀 키·개인 보유 상세·수량/평단을 회신에 노출하지 않는다.

현재 알림 판단 누락·오래된 자료의 정상 표시·실제 누적 중단이 발견되면 POC6-12 신규 수집/구현보다 먼저 영향과 최소 정정 범위를 보고한다. 점검 도중 코드·DB·cron·PUSH를 임의 수정하거나 신규 발송·수집·학습·원격 업로드를 하지 않는다. 발견만으로 또 다른 개발 단계를 자동 생성하지 않는다.

점검 결과와 별개로 05 보관·06 기존 전향 절차·현재 PUSH를 정지하지 않는다. 이 요청서를 위한 별도 커밋·push·handoff는 요구하지 않는다. 이번 확인 이후 무엇을 정정하거나 연결할지는 실제 현황을 보고 설계자가 판단한다.
