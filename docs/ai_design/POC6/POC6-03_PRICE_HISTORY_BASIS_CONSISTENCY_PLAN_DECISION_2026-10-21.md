## 1. 진행 상태 정정

최신 개발자 보고에 따라 POC6-02는 **구현 · CPU 공식 실행 · CPU 범위 검증자 r3 VERIFIED 완료, GPU 실측 · 취합 대기**로 바로잡는다. 앞선 판정의 “현재 제공된 보고는 PLAN 단계”라는 상태 설명은 이 보고로 대체한다.

POOLED_HGB의 RESEARCH_PROMISING(MEDIAN 대비 10.0% · RIDGE 대비 8.8% 개선 · 세 구간 우위)은 **적격 ETF 4종에 한정된 개발자 보고**로 접수한다. 이번에 심사한 원문은 POC6-03 PLAN이며, POC6-02 결과서 전체의 최종 판정이나 운영 채택을 뜻하지 않는다.

**아래 정정을 PLAN에 반영하면 재제출 없이 POC6-03 구현 · 격리 시험을 시작한다. GPU를 기다리지 않는다.** 실제 외부 조회만 §3의 사용자 승인 뒤 실행한다.

## 2. 질문 네 가지 판정

| 질문 | 결정 | 적용 범위 |
|---|---|---|
| Q1 대상 | **(b) 보유 ETF 26종** | POC6-02 공식 snapshot의 목록으로 고정. 경계 제외 8종 · 적격 4종 · 나머지 14종을 구분하며 전체 ETF 시장으로 넓히지 않는다. |
| Q2 승인 · 선행 작업 | **구현 · stub 시험 먼저 진행** | 실제 신규 조회만 별도 사용자 승인. 대상 ETF별 한 번씩 실행하는 최대 26종의 한 묶음이다. |
| Q3 다음 쓰임 | **자료 검증 보고까지** | 라이브 갱신 변경, POC6-02 자료 교체, 새 성과 실험, 모델 채택은 포함하지 않는다. |
| Q4 단계 번호 | **POC6-03 확정** | 연구 사본의 가격 기준 일관성 검증 단계다. POC6-02 재실행으로 취급하지 않는다. |

새로 받는다고 상장이 짧은 종목의 과거 이력이 생기는 것은 아니다. 26종으로 정하는 이유는 같은 연구 범위의 자료를 한 묶음으로 비교하기 위해서다.

## 3. 조회 · 저장 경계

- 기존 FinanceDataReader/NAVER 조회 경로만 사용한다. 키움 · Yahoo · 신규 KRX 조회나 계정 설정은 추가하지 않는다.
- “외부 조회 1회”는 **한 묶음 실행**이라는 뜻이다. 종목별 DataReader 호출은 최대 26회이며, 라이브러리 내부 HTTP 요청이 하나라는 뜻은 아니다. 자동 재시도나 실패 종목의 반복 조회를 추가하지 않는다.
- 조회 시작일은 종목별 기존 연구 대상 저장 이력의 시작일, 종료 기준은 POC6-02 snapshot의 기준일 T로 고정한다. 비교에는 T 이하 행만 사용한다. 이 범위보다 앞선 상장 이력까지 확보했다고 표현하지 않는다.
- 묶음 시작 · 종료 시각, 종목별 수집 시각 · 요청 구간 · 반환 구간 · 원천 · 라이브러리 버전 · 행 수를 남긴다. 같은 날 받았다는 사실이 동시점 snapshot을 보장하지는 않는다.
- 기존 조회의 읽기 부분만 재사용한다. 라이브 DB 저장부를 호출하지 않는다. 기존 요청 timeout을 재사용하되 전체 작업 시간의 절대 상한으로 표현하지 않는다.
- 새 연구 폴더에만 저장한다. 라이브 가격 DB · 보유 · 원장 · OCI에는 쓰지 않는다. KRX 봉인 DB는 기존 봉인 자료 읽기 계약을 유지한다.
- 사용자 승인 전에는 실제 DataReader 호출을 하지 않는다. 개발자는 **26종 · 원천 · 연구 사본 저장 · 라이브 무변경**을 한 번에 제시해 승인받는다. 이미 승인된 범위를 다시 승인받을 필요는 없다.

## 4. 반드시 고칠 해석과 대조 규칙

### 4-1. 사실과 가설

개발자 조사에서 확인된 것은 최근 120일 덮어쓰기와 수집 묶음이 갈리는 위치가 가격 경계와 일치한다는 점이다. 모든 경계의 원인과 공급자의 조정 방식까지 확인한 것은 아니다.

| PLAN 표현 | 정정 |
|---|---|
| 한 시점 · 한 출처 = 한 기준 | 같은 수집 묶음으로 만든 사본의 일관성을 **검증한다** |
| 종가 차 ≠ 전일 대비인 날 = 분배락 식별 | 연속 거래일과 유효한 값이 확인된 경우의 **기준가 조정 후보** |
| 사본 경계 기대값 0 | 경계 수를 관측한다. 0을 만들기 위해 판정이나 값을 바꾸지 않는다. |
| 조정률을 더해 경계 크기 확정 | 합은 설명용 근사다. 검증에는 조정 배율의 곱을 쓴다. |

기준가 조정 후보를 분배금 지급으로 단정하지 않는다. 사건 근거가 없으면 **조정 사유 미확인**으로 남긴다. 이를 위해 새 사건 자료원을 조사 · 수집하는 단계로 넓히지 않는다.

### 4-2. 기존 경계 검사와 KRX 대조 범위

POC5-06의 AxisSeries · link_break를 수정하지 않고 사본에 적용한다. 원천 이름만 바꾸어 경계를 없애거나, 새 종가에 맞추어 저장 change를 재작성하지 않는다. 경계 0은 해당 검사에서 경계를 찾지 못했다는 뜻이며, 공식 수정주가 · 총수익률 · PIT 자료라는 보증이 아니다. 사본도 **받은 날 기준의 사후 자료**다.

KRX 자료가 확인된 것은 제외 8종과 적격 4종이다. 나머지 14종은 기존 DB의 자료 유무를 읽기만 해서 확인한다. 자료가 없으면 대조 불가로 두며 새 KRX 조회를 하지 않는다. 보고된 2026-09-21 이후 행을 KRX로 검증했다고 쓰지 않는다.

같은 종목의 **기존 연구 거래일 축에서 연속인 두 거래일**만 짝짓는다. 중간 행이나 값이 없으면 직전 저장 행으로 건너뛰어 계산하지 않는다. 유효한 0과 결측도 구분한다.

### 4-3. 산식 · 허용 오차를 결과 전에 고정

기존 KRX 원응답의 종가 · 부호 있는 전일 대비 금액이라는 의미를 상승일 · 하락일 fixture로 확인한 뒤 다음 정의를 적용한다. 부호나 단위를 해석할 수 없으면 대조 불가다.

- A_t = 새 사본 종가, C_t = KRX 무조정 종가, Δ_t = KRX 전일 대비 금액.
- B_t = C_t − Δ_t: 공개 값에서 역산한 비교 기준가.
- B_t와 직전 거래일 C_prev의 차이는 기준가 조정 **후보**를 찾는 근거다.
- 새 사본의 일간 배율 A_t / A_prev와 KRX 기준가 대비 배율 C_t / B_t를 대조한다.
- PLAN의 A_t / C_t도 보고하되, 여러 조정의 누적에는 배율의 곱을 쓴다. 반올림된 FLUC_RT를 누적해 가격을 복원하지 않는다.

이번 원화 종가 대조는 사본 종가 각각 **±1원**의 보수적 진단 범위로 고정한다. A_prev − 1이 양수일 때 아래 구간에 C_t / B_t가 들어가면 “표기 오차 허용 범위 내 일치”, 밖이면 “불일치”로 센다.

```text
하한 = (A_t − 1) / (A_prev + 1)
상한 = (A_t + 1) / (A_prev − 1)
```

종가와 기준가는 유한한 양수여야 한다. 원화 단위가 확인되지 않거나 위 범위를 계산할 수 없으면 대조 불가로 둔다. 계산에는 표시용 반올림을 적용하지 않는다.

±1원은 **이번 진단의 허용 폭**이며 공급자의 실제 반올림 방식을 알아냈다는 뜻이 아니다. 기준가 조정 후보 여부와 대조 일치 여부는 별도로 기록하고, 결과를 본 뒤 허용 폭을 넓히지 않는다.

## 5. 보고 · 검증 · 완료 기준

PLAN의 연구 DB와 report.md · report.json으로 충분하다. 다음을 분리해 기록한다.

1. 조회 성공 · 실패와 실제 확보 구간.
2. 기존 이력과 새 사본의 경계 수 · 날짜 · 종류.
3. KRX 대조 가능 범위, 허용 범위 내 일치 · 불일치 · 대조 불가와 사유.
4. 기존 이력과 사본의 차이, 조정 사유가 확인되지 않은 부분.
5. **POC6-02와 같은 기준일 · 시험 구간 · 최소 표본 규칙**으로 다시 센 적격 수와 제외 사유. 모델 학습 · 예측 · 오차 계산은 하지 않는다.

조회 실패 · KRX 자료 부재 · 경계 잔존도 보고 대상이다. 모든 종목이 통과해야만 끝나는 단계로 만들지 않는다. 구현 · 검증을 마치고 **어디까지 확인됐는지를 재현 가능하게 보고하는 것**이 완료 기준이다. 성공한 종목만 골라 전체 통과로 표현하지 않는다.

시험은 PLAN 범위에 정상/상승/하락, 조정 후보, 중간 거래일 결측, 유효한 0과 손상값, 허용 구간 안팎, 일부 조회 실패, 저장 실패, 원본 쓰기 없음을 포함한다. 격리 fixture를 먼저 검증하고 실제 사본은 승인된 한 묶음으로 생성한다. 같은 오류 때문에 전체 자료를 반복 수집하지 않는다.

## 6. 작업 분리 · 진행 지시

POC6-02의 공식 snapshot · 모델 · 시험 구간 · 판정 기준 · CPU 결과와 검증 대상은 고정한다. 별도 작업 트리 또는 명시적인 파일 구분으로 POC6-03 변경을 분리한다.

PLAN의 “POC6-02 종료 커밋 전에는 stage하지 않는다”는 문장은 **검증 대상을 섞지 않는다**는 뜻으로 정정한다. GPU 대기를 POC6-03 구현 · 검증의 중단 조건으로 만들지 않는다. POC6-03 파일을 POC6-02 검증 완료 범위에 포함했다고 기록해서는 안 된다.

- **POC6-03:** 판정 반영 → 구현 · 격리 시험 → 실제 조회 사용자 승인 → 연구 사본 한 묶음 생성 · 보고 → 검증자 → 결과서와 실제 보고서로 설계자 RESULT 요청.
- **POC6-02:** 기존 RTX 실행 묶음 실행 → GPU 결과 취합 → GPU 부분 검증 → 최종 RESULT 요청.

코드가 바뀌지 않은 POC6-02의 CPU 공식 실행이나 전체 회귀를 GPU 결과 수령만을 이유로 다시 돌리지 않는다. POC6-03 변경에 필요한 회귀 검증과는 구분한다.

**현재 지시: GPU를 기다리지 말고 POC6-03 구현 · 격리 시험을 진행한다. 실제 조회 승인 전에는 외부 조회를 실행하지 않는다.**
