## 1. 세 구간의 종료 기준

기존 목표는 한국 상장 ETF의 후보와 보유를 주간에 검토하고, 비용 후 KODEX 200 대비 성과와 위험·회복·교체 부담을 확인해 유용한 권고를 PC에 연결하는 것이다. 최종 판단과 주문은 사용자가 맡는다. 구간은 POC 번호와 별도로, 사용자에게 실제로 제공할 수 있는 결과를 기준으로 닫는다.

| 구간 | 닫는 기준 | 현재 판단 |
|---|---|---|
| **1. 운영 흐름 완결** | PC에서 보유·평가·후보 비교·근거 미리보기·AI 검토·사용자 판단 저장과 재조회가 실제로 된다. 승인된 보유·운영 기준의 OCI 반영과 Telegram 운영은 각 기존 경로의 확인 근거로 대조한다. 이 흐름을 막는 현재 결함이 0건이면 종료한다. | **마감 대조 대상.** PC 사용과 OCI 운영의 기존 확인 근거가 있다. 최신 원장에서 차단 항목과 실제 운영 근거의 빈자리만 대조한다. |
| **2. 판단과 결과 연결** | 실제 주간 검토 한 사례에서 당시 근거, 사용자 판단·이유, 다음 확인 사항을 남기고, 정한 시점에 같은 기록을 열어 관측된 결과와 대조할 수 있다. 기존 AI 투자 세션과 사후 가격 결과를 사용할 수 있는 범위에서 재사용한다. | **일부 확인.** POC6-18에서 보유·비보유 사례를 저장하고 다시 열었다. 이유·다음 확인 사항과 이후 결과의 대조가 남았다. |
| **3. 성과 검증과 권고 채택** | 같은 기간·체결·비용·수익률 정의로 전략과 KODEX 200을 비교하고, 단순 기준 대비 ML의 추가 효용과 위험·회복·교체 부담을 검증한다. 기준을 충족한 권고의 PC 연결과 실제 사용을 확인하면 목표 달성으로 종료한다. 정한 검증 범위의 미달 후보는 기각으로 닫고, 남은 프로젝트 목표의 상태를 별도로 적는다. | **운영 채택 미달.** POC6-20·21·23의 시험 후보는 최종 판정으로 종료됐다. 유용한 운영 ML과 분배금을 포함한 프로젝트 전체 성과 검증은 미확보 상태다. |

구간 1의 PC 검토와 OCI·Telegram 운영은 승인된 각각의 경로를 확인한다. 구간 2의 한 사례는 기록과 결과 대조가 가능한지를 확인하는 기준이다. 투자 효용과 운영 채택은 구간 3에서 판정한다. 현재 구체화할 작업은 구간 1의 마감 대조 한 건이다.

## 2. 지금 수용할 종료 근거

- PC의 사용자 검토·기록 재조회는 POC6-18의 확인을 재사용한다. POC6-24 자금·비중 근거, POC6-25 미확인 값 표시 정정은 최신 종료 보고대로 닫힌 범위에 둔다.
- OCI 운영과 Telegram·사후 가격 기록은 POC3 운영 확인, POC5-01B~04 기록과 `PROGRAM_TRUTH`의 현행 경로를 재사용한다. 백로그의 ‘PC에서 OCI 운영 기준(PARAM) 활성화’는 **POC5-27 종료로 해결을 수용**한다. 실제 OCI는 동일값 확인, 변경·복구는 격리 검증이라는 확인 범위를 함께 남긴다. 원장에 이미 반영됐다면 기존 근거를 연결해 사용한다.
- POC6-26은 사용자 종료 보고의 `2dcba050`과 최종 HEAD `e00af5a1`을 기준으로 **069500·2025년·1주 검산을 종료**로 둔다. 분배금 포함 성과 비교는 구간 3에 귀속한다. 채택 판정이 걸린 비교에서 필요한 기간·보유 종목과 자료 확보 범위를 먼저 확정한다. 같은 기준의 분배금 자료가 확보된 범위에서 성과를 판정한다.
- 종합 위험 판단(Q6·#3), 진입·보유 검토 기준(#55), 복합 지표 효용(#57), ML 기반 seed 품질(#62)은 기존 판정의 미완료 범위를 구간 3의 목표에 귀속한다. 원장에서는 기존 ID 또는 원제목을 사용한다.

## 3. 기존 백로그에서 닫는 방법

2026-10-19의 처리 판정은 당시 등록 62항목을 이미 분류했다. 등록 건수에는 종료 이력도 포함된다. 당시 판정과 그 뒤 종료 근거를 대조해 상태가 바뀐 항목을 처리한다. 기준은 저장소의 최신 `docs/backlog/BACKLOG.md`다.

| 상태 | 처리 기준과 닫는 시점 |
|---|---|
| **종료** | 완료·대체·중복·폐기 판단의 근거를 남기고 활성 할 일에서 뺀다. 실제로 해결된 항목은 해당 종료 결과로 바로 닫는다. |
| **현재 구간에서 해결** | 이 구간의 완료 기준을 직접 막는 항목이다. 막히는 사용자 동작과 근거를 적고, 해결 후 해당 동작 확인으로 닫는다. 다음 실제 Step은 이 가운데 우선 한 건을 정한다. |
| **정해진 구간에서 판단** | 해당 구간 번호와 그때 확인할 결과를 적는다. 담당자는 그 구간 마감 때 채택·기각·미확보를 판정한다. |
| **조건부 보류** | 사유·보류된 위험·재검토 트리거를 원장에 남긴다. 예를 들어 POC6-18의 편의 개선은 실제 사용에서 판단 또는 기록을 막은 사례가 생길 때 해당 항목을 다시 본다. |

구간 종료 때 `STATE_LATEST`에 종료 근거, 직접 차단 항목 수, 다음 실제 Step 하나를 남긴다. `BACKLOG`의 현재 처리 요약에는 이번에 달라진 항목과 그 근거를 반영한다.

## 4. 다음 작업 한 건 · 구간 1 마감 대조

개발자는 최신 `STATE_LATEST` 머리와 `BACKLOG`의 현재 처리 요약에서 **구간 1을 실제로 막는 항목과 후속 종료로 닫을 항목만** 확인한다. 이미 확인한 PC·OCI·Telegram 근거는 해당 종료 기록의 위치로 대조한다. 확인할 사실은 한 회신에 담는다.

1. 구간 1 직접 차단 항목의 수와, 있다면 원제목·막힌 동작·근거.
2. 후속 종료로 상태를 바로잡을 원장 항목과 대응하는 종료 근거. POC5-27은 현행 원장 반영 여부를 확인한다.
3. 구간 1의 기존 실제 확인 근거 중 빈자리가 있다면 해당 경로와 필요한 증거 하나.

이 대조는 기존 기록을 읽는 작업이다. 총괄 설계자는 필수 근거가 있고 차단 0건이면 구간 1을 바로 종료 판정하고, 기존 두 문서에 반영할 상태를 정한다. 실제 차단이나 필수 근거의 빈자리가 확인되면 가장 먼저 해결하거나 확인할 한 건만 다음 Step으로 확정한다.
