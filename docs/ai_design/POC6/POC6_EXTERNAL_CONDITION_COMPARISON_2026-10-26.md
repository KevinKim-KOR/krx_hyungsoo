3. **다음 실행 설계 후보는 ‘저빈도 운용에서 ML의 ETF 상대성과 선별 효용’ 하나로 고른다.** D20 하락폭 오차를 다시 묻거나 POC6-10의 EMA 기간을 조정하는 작업을 자동으로 붙이지 않는다.

### 3-1. 표를 잘못 읽지 않기 위한 네 가지

- Qlib의 `n_drop=5`는 매일 정확히 5개가 반드시 바뀐다는 보장이 아니다. 거래 가능 여부·순위·보유 조건이 관여한다.[4] 반대로 이 설정을 우리 저빈도 기준이라고 부르지도 않는다.
- Alpha158의 기본 rolling 기간은 5·10·20·30·60이다.[3] 이 숫자는 과거 입력 기간이고 미래 label·보유 기간과 다르다. 우리의 과제에 더 긴 정보가 필요하면 별도 근거를 들어 정한다.
- Qlib 기본 label은 ‘오늘 종가→다음 종가’나 D20과 같지 않다.[2] 목표·처리·체결이 다른 실험 결과를 바로 비교하지 않는다.
- 공식 표에는 신호 지표와 포트폴리오 지표가 함께 있다. 현재 성과 코드에는 벤치마크와 비용을 뺀 일별 시계열을 분석하는 경로가 있다.[5][6] 표의 Annualized Return 하나를 실제 계좌의 분배금 포함 CAGR이라고 단정하지 않는다.

## 4. 왜 가져올 만하며, 무엇이 아직 입증되지 않았는가

가져올 만한 것은 **판단하려는 행동과 학습 목표를 연결하는 방식**, 여러 기간·형태의 정보를 비교 가능한 입력으로 만드는 방식, 그리고 모델 점수와 교체 정책을 분리하는 구조다. Qlib을 설치해야만 가능한 원칙은 아니다.

우리의 최근 D20 연구는 미래 최저 종가 변화 추정·큰 하락 검토 우선순위가 중심이었다. 사용자가 지금 확정한 주목적은 비용 후 초과성과다. 이 차이를 반영해 후보 선별을 먼저 연구하는 것은 목적에 맞는 과제 조정이다. 다만 POC4에서도 모멘텀·학습 모델·초과성과를 비교했으므로 **상승 후보 ML을 프로젝트에서 처음 시도한다**고 설명하지 않는다. 다음 실행 설계는 그때의 대상·입력·목표·운용과 무엇이 달라지는지 명시해야 한다.

POC6-10은 유지·이탈을 자주 적용했을 때 높은 회전율과 비용 대가가 드러났다. 이는 참고해야 할 기존 결과다. 다음 비교에서는 **정기적인 후보 순위 변경과 실제 교체를 분리**하고, 동일한 유지 여유·교체 한도·일별 예외 규칙을 룰과 ML에 적용한다. 구체 한도는 아직 확정하지 않았다. 기존 10의 결과를 성공으로 만들려고 한도를 소급 변경하지 않는다.

이 대조로 다음은 입증되지 않는다.

- 158개 입력이 기존 입력보다 좋다거나 LightGBM이 기존 HGB·Ridge보다 좋다는 주장.
- 같은 지수를 추종하는 ETF가 많으므로 국내에서는 ML이 불가능하다는 주장.
- 친구 모의 성과가 검증됐거나, 반대로 과적합이라 무효라는 주장.
- 거시·수급을 추가해야만 성과가 생긴다거나 가격·거래량만으로는 불가능하다는 주장.

외부 전체 workflow와 우리 결과를 나란히 두는 것은 **조건 비교**다. 입력 폭의 효과를 입증하려면 나머지 조건을 맞춘 별도 비교가 필요하다. 이번 후속 가설에서 모델·입력·목표 묶음을 바꾼다면 그 묶음의 효용만 결론내리고 특정 요소 하나의 효과라고 주장하지 않는다.

## 5. 선정한 후속 가설 H1 — 저빈도 ETF 후보 선별의 ML 추가 효용

**질문:** 개인 보유와 독립된 ETF 모집단에서, 여러 기간의 가격·거래량 정보를 학습한 상대성과 점수가 단순 모멘텀 순위보다 나은 후보를 고르고, 같은 주간 검토·유지·교체·현금 정책 아래 비용 후 포트폴리오 성과를 개선하는가?

| 설계 항목 | 이번 선택 |
|---|---|
| ML 역할 | 진입·정기 검토 후보의 상대성과 점수/순위. 하락 예측·확정적 매도 시점·자동 주문을 한 모델에 모두 요구하지 않음 |
| 실행 설계의 우선 모델 후보 | 외부 참고에 직접 연결되는 **LightGBM 한 종류**. Qlib 전체를 설치하는 선택과 분리. 설정·설치 필요·허용 탐색 예산은 실행 설계에서 결정 |
| 입력 방향 | Alpha158에서 OHLC·가격 위치·여러 기간의 흐름/흔들림·거래량 관련 정의를 대조해 고정 묶음으로 선택. 전부 도입·입력 중요도에 따른 사후 선별은 전제하지 않음 |
| 목표 | 실제 실행 시각 이후의 미래 상대성과. 주간 판단·기대 보유와 연결해 기간 하나를 사전 고정. Qlib의 짧은 label이나 D20을 자동 승계하지 않음 |
| 비교 | 같은 대상·날짜·정보·비용·운용 정책의 단순 모멘텀 룰과 ML. KODEX200 보유는 별도 목적 기준. 불리한 기존 기준선을 버리고 약한 비교 대상을 만들지 않음 |
| 행동 경계 | 주간 순위가 바뀌어도 유지 조건이면 거래 없음. 일별 예외는 공통 규칙으로 고정. 새 추천으로 목록을 매주 전량 바꾸지 않음 |
| 결론 범위 | 그 입력·모델·목표·운용 묶음의 효용. 최적 모델·전체 ML·한국 ETF 전체에 대한 결론으로 확대하지 않음 |

이 가설이 긍정적이어도 진입·보유·청산 권고 기능 전체가 바로 완료되는 것은 아니다. 첫 역할의 효용을 확인한 범위에서 연결하고, 보유 중 축소·청산의 남은 기준은 미완료로 추적한다. 처음부터 모든 역할이 한 번에 성공해야만 연구 가치가 있는 것으로 판정하지 않는다.

공식 중국 실험 재현은 **지금 실행 대상으로 선택하지 않는다.** 국내 후보 선별의 추가 효용을 직접 답하지 못하기 때문이다. 후속 구현에서 연산·label·정규화·엔진 호환성을 확인할 필요가 생기면, 해당 질문을 풀 작은 대조만 실행 범위로 제시한다. 외국 시장 전체 재현을 관문으로 만들지 않는다.

수급·환율·유가는 계속 보관한다. 이번 H1에 함께 넣으면 입력 효과·표본 기간·공표 시각까지 동시에 달라진다. **이번 첫 입력 묶음은 가격·거래량 계열을 우선 설계하고, 거시·수급 결합은 자동 추가하지 않는다.** 이는 해당 자료가 무용하다는 판단이나 수집 중단이 아니다.

## 7. 개발자 전달과 종료 범위

이번 외부 조건 대조는 이 문서로 끝낸다. 같은 조사만을 위한 PLAN·검증 라운드·공식 실행·handoff를 만들지 않는다. 개발자는 다음 두 파일을 보관하고 STATE의 다음을 연결하면 된다.

이 문서 저장 자체를 위해 별도 커밋을 강제하지 않는다. 커밋·push는 사용자의 유효한 승인 범위에서 처리한다. 다음 실험의 가설·자료·운용·평가·예산을 정하는 책임은 설계자에게 있다. 개발자에게 외부 전략을 다시 조사하거나 투자 기준을 임의로 채우도록 넘기지 않는다.
