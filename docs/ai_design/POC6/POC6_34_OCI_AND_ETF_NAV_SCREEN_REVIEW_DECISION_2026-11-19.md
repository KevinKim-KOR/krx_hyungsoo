# POC6-34 OCI 운영·적용과 ETF NAV 조회 화면 판정

2026-11-19 KST · 설계자 · 운영 PC 캡처 기준

**판정은 OCI 운영·적용 유지 및 상태 문구 보완, ETF NAV 전체 조회 유지 및 메뉴·버튼 이름 정리다.** 이 변경은 POC6-34로 잡는다. 앞 단계는 POC6-33이며 main 반영과 push는 개발자 완료 보고를 기준으로 한다.

## 1. 이번 단계의 목표

사용자가 기존 두 화면에서 **무엇을 언제 확인했고, 지금 어떤 조치가 필요한지** 읽을 수 있게 한다. OCI는 운영 설정과 적용을 담당한다. ETF NAV 화면은 전체 ETF의 저장 자료에서 수집 상태나 큰 괴리를 찾아보는 조회용 표다.

## 2. OCI 운영·적용

**유지한다.** 알림 기준의 PC·OCI 일치 여부를 확인하고, 필요한 경우 사용자가 승인한 기준을 적용하는 기능이 있다. 예약 확인과 실제 발송 근거를 같은 상태처럼 읽게 하는 문구는 바로잡는다.

| 캡처에서 확인한 문제 | POC6-34 변경 방향 |
|---|---|
| ‘지금 OCI 상태’와 ‘정상 운영 중’은 실시간과 전체 운영 정상으로 읽힌다. 캡처의 실제 근거는 11/19 09:04 PC 백엔드 기동 점검과 자동 발송 예약 3종 등록이다. 화면의 발송 결과 행은 Telegram을 안내한다. | ‘마지막 OCI 점검’ 아래 확인 시각을 적고 요약에는 ‘자동 발송 예약 3종 확인’처럼 확인한 범위만 쓴다. 실제 발송 확인은 Telegram으로 안내한다. |
| 보유 종목 파일과 운영 설정 DB에는 ‘정상’과 파일 수정일이 보인다. | 읽기에서 파일을 찾은 경우 ‘파일 확인’과 수정일을 표시한다. 보유의 마지막 적용·확인 결과는 기존 ‘종목 관리’의 보유 OCI 적용 상태로 안내한다. |
| ‘현재 운영 기준’ 카드에서 14/14 일치, 10/20 마지막 적용, [현재 기준 OCI 적용] 버튼이 한꺼번에 보인다. | ‘OCI 활성값 마지막 확인’과 ‘마지막 적용 요청 및 결과’를 구별한다. 확인 근거가 충분한 일치 상태에는 ‘적용할 변경 없음’을 앞에 둔다. 이전 적용에서의 일치와 현재 확인 불가는 각각 그 근거대로 표시한다. 기존 수동 적용은 적용이 필요한 경우에 찾을 수 있게 한다. |
| ‘장중 알림 발송 중’이 켜진 설정과 실제 발송을 섞어 읽히게 한다. ‘자료 기준일 2026-09-11’이 무엇의 날짜인지 불분명하고, 확인할 변경이 없는데 ‘적용될 판정 기준’ 표가 펼쳐져 있다. | 실제 필드가 켜짐 상태이면 ‘장중 알림 설정 켜짐’으로 쓴다. 날짜에는 코드에서 확인한 대상의 이름을 붙인다. 기본 화면에서는 현재 적용 상태와 확인할 변경 유무를 먼저 읽고, 적용된 기준의 세부값은 기존 [자세히 보기]에 둔다. 승인할 후보가 있을 때는 적용 전 확인에 필요한 차이를 바로 보여 준다. |

파일 수정일은 파일 행에, 설정의 기준일은 해당 설정에 표시한다. 지연·미적용은 해당 상태의 확인 근거가 있을 때 표시한다. 적용 상태에는 기존 비교 결과와 실제 확인 시각을 사용한다.

## 3. 데이터 상태

**진단·상태 아래 ETF 전 종목 조회를 유지한다. 화면 제목과 메뉴명은 ‘ETF NAV·괴리율 조회’로 바꾼다.** 시장가·NAV·괴리율·기준일·출처·수집 상태를 같은 행에서 읽을 수 있다. 전체 범위의 상태를 살피고 특정 ETF를 검색하는 데 현재의 표 구성이 맞다.

- ‘다시 불러오기’는 ‘저장 자료 다시 읽기’로 표시한다. 새 자료를 받는 경로는 「오늘의 투자 점검」의 [최신 자료 갱신]으로 안내한다.
- 조회 요약에서 전체 건수, 필터 결과 건수, 표에 표시한 건수를 구별한다. 캡처처럼 전체 1,212건 가운데 정렬 결과 200건만 보이는 경우, 표 위에서 그 범위를 읽을 수 있게 한다.
- 행의 기준일·재저장일과 수집 상태에 POC6-33의 구분을 사용한다. ‘수집됨’은 그 행의 수집 상태다. 표에는 ‘수집됨’과 ‘괴리 주의’가 동시에 보이는 사례가 있다. 큰 괴리율로 표시된 행의 시장가·NAV·기준일을 보고 원자료를 대조할 대상을 찾을 수 있다.

## 4. 완료 확인

1. **OCI.** 기동 점검 값만 있는 상태에서 자동 발송 예약과 확인 시각을 읽을 수 있다. 실제 발송은 해당 확인 경로에서 읽는다. 파일 수정일·활성값 확인일·적용 요청일·장중 설정의 기준일은 각 의미로 보인다. 일치·다름·확인 불가에서 적용할 일이 있는지 해당 근거로 판단할 수 있다.
2. **ETF NAV.** 제목만으로 조회 범위를 알 수 있고, 저장값 다시 읽기와 새 자료 갱신을 구별한다. 200건을 넘는 응답에서 목록의 표시 범위와 검색 결과를 모두 읽을 수 있다. 수집 상태와 괴리율 주의가 함께 있는 행과 이전 목록 재사용 행으로 확인한다.
3. **검토 범위.** 사용자가 보는 화면 이름·문구·기존 영역의 배치와 조회 동선을 다룬다. 확인은 기존 응답과 화면을 읽는 방식으로 한다. 데이터·발송 정책·적용 계약은 현재 확정값을 사용한다.

## 5. 개발자가 PLAN 전에 확인할 사실

- OCI 카드의 ‘일치’·‘마지막 적용’이 각각 현재 응답인지 저장된 직전 결과인지, 출력에 제공되는 확인 시각을 확인한다. ‘장중 알림 발송 중’의 판정 조건과 ‘자료 기준일’의 원본 필드를 같은 회신에 적는다.
- 근거는 관련 화면과 기존 읽기 값만 대조한다. 표 구성·수치 경고·200건 표시에는 위 판정의 실화면 근거를 사용한다. 확인한 날짜와 상태의 의미를 합쳐 짧은 PLAN으로 정리한다.

근거는 2026-11-19 사용자가 올린 운영 화면 캡처, POC6-33 최종 결과서 §15.2~§15.4, PROGRAM_TRUTH의 OCI 운영 상태와 적용 계약이다.
