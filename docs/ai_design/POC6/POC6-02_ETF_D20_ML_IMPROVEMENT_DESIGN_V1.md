## 4. 목표와 입력 고정
D20(t) = min(0, min(C(t+h)/C(t)-1, h=1..20)).
기존 연구 축의 다음 20거래일 **최저 종가 변화**다. MDD·장중 저점·손실 확률·개인 손익이 아니다. 미래 20일이 온전히 없으면 정답을 만들지 않는다.

입력 5개는 POC5-06 그대로다.
- C(t)/C(t-5)-1
- C(t)/C(t-20)-1
- C(t)/C(t-60)-1
- 최근 20개 일별 로그수익률의 모집단 표준편차(ddof=0)
- C(t)/max(C(t-59)..C(t))-1

모든 feature는 t 이하만 사용한다. 미래 가격은 정답에만 쓴다. source 경계·날짜 누락·비정상 값이 창 안에 있으면 그 표본을 제외하고 이유를 센다. 빠진 날짜를 지워 연속 표본으로 만들거나 다른 원천으로 채우지 않는다.

## 5. 비교하는 네 방법 — CPU·GPU 각 후보 하나
| 방법 | 학습 |
|---|---|
| MEDIAN | ETF별 해당 학습 표본 D20 중앙값을 고정 예측 |
| RIDGE_EXISTING | ETF별 StandardScaler → Ridge(alpha=1, solver=svd, fit_intercept=True). 기존 06의 같은 입력·규칙을 재사용 |
| POOLED_HGB | 해당 구간의 적격 ETF 표본을 함께 학습하는 HistGradientBoostingRegressor 하나 |
| POOLED_GPU_MLP | 같은 표본·feature의 고정 PyTorch MLP 하나를 RTX 4070 SUPER의 CUDA에서 실제 학습 |

CPU 후보 설정은 loss=absolute_error, learning_rate=0.05, max_iter=100, max_leaf_nodes=7, max_depth=3, min_samples_leaf=50, l2_regularization=1.0, max_bins=63, early_stopping=False, categorical_features=None, random_state=42로 고정한다. 나머지는 설치 버전의 기본값을 recipe에 남긴다. ETF 식별자·이름은 feature가 아니다.

GPU 후보는 5→64→32→1의 Linear·ReLU·Linear·ReLU·Linear, float32, Adam(lr=0.001, weight_decay=0.001), 200 epoch, seed=42로 고정한다. dropout·BatchNorm·early stopping·AMP는 쓰지 않는다. feature는 해당 공동 학습 표본의 날짜 균형 가중 평균·모집단 표준편차로만 표준화한다(상수 열 0). raw 출력에 날짜 균형 가중 L1 손실을 적용하고, epoch마다 전체 학습 표본의 가중 손실을 기준으로 한 번 업데이트한다. 메모리에 맞춰 나눌 때도 가중 합/전체 가중치로 gradient를 누적한 뒤 한 번만 업데이트한다. 예측 범위 제한은 평가 때 네 방법 모두 동일하게 적용한다.

두 공동 학습 후보의 가중치는 학습 날짜 d의 표본 수 n_d에 대해 각 행 1/n_d다. 날짜별 합이 1이며 최신 종목이 많은 날짜에 학습이 치우치지 않게 한다. 종목별 MEDIAN/RIDGE는 그 종목의 유효 학습 날짜를 같은 비중으로 사용한다. HGB에는 표준화를 적용하지 않고 Ridge의 scaler는 해당 학습 자료에서만 fit한다.

네 방법의 예측은 모두 [-1,0]으로 제한하고 같은 정답에 평가한다. 중앙값은 짝수 개일 때 가운데 두 값 평균인 기존 06 규칙을 확인해 재사용한다. 기존 규칙이 다르면 PLAN에 정확한 차이만 질문한다. 결측 feature 대입·새 feature·성과를 보고 하는 모델 설정 탐색·RF/XGB/LGBM은 넣지 않는다. 설치 버전은 그대로 우선 사용한다.

이는 공동 학습+비선형 후보 한 묶음과 기존 방법의 비교다. 개선돼도 공동 학습과 비선형성 중 무엇이 원인인지 개별 입증한 것으로 쓰지 않는다.

### 5-1. 실제 자원을 활용하는 범위와 재현
- CPU는 학습 표본에 대해 1스레드·가용 논리 코어의 절반·전체를 소규모로 재서 병목과 유효 병렬도를 확인한다. 기존 모델이 CPU인 점을 유지하고, HGB를 GPU 모델이라고 부르지 않는다.
- GPU는 동일 학습 자료·초기값으로 microbatch=min(N,256), min(N,4096), N의 세 크기(중복 제거)에서 짧게 실학습해 처리량·peak VRAM을 잰다. 한 번에 안 들어가면 OOM을 기록하고 작동한 크기를 쓴다. 예비 측정은 각 설정 1회 warm-up+3 epoch 이내이며 시험 성과를 보지 않는다. 데이터를 복제해 부하를 부풀리지 않는다.
- 정식 실행의 학습 파라미터는 고정한다. 위 CPU/GPU 실행 크기는 예비 측정의 처리량·메모리로 선택해 PLAN에 남긴다. 초과 사용률이나 몇 시간 실행을 목표로 삼지 않는다. 실제 데이터 전체를 처리했을 때의 실익·병목을 보고한다. 자료가 작아 GPU가 느리거나 여유가 많이 남으면 그 사실이 유효한 결과다.
- GPU 속도 이득은 같은 MLP·같은 자료·epoch 작업량의 CPU/CUDA 예비 실행으로 비교한다. HGB와 MLP 시간 차이를 장치만의 가속 효과로 주장하지 않는다. GPU 시간에는 동기화 경계를 두고 데이터 전송 포함 여부를 명시한다.
- Python·numpy·torch seed와 결정적 알고리즘을 고정하고 TF32는 끈다. 같은 장비·환경·입력에서 예비 재현 오차를 확인한다. CPU와 GPU의 bit 동일성이나 다른 버전 간 완전 재현은 요구하지 않는다. 허용 수치 오차와 판정 경계 근처 처리 규칙은 성과 열람 전에 PLAN에서 제시한다. 재현 오류를 유리한 seed 선택으로 해결하지 않는다.
- CPU·RAM·GPU·VRAM, OS·Python·라이브러리·CUDA, fit/predict·벽시계 시간·사용량을 기록한다. 기존 계측으로 얻을 수 없는 세부 사용률만을 위해 상시 모니터링 시스템을 만들지 않는다.
- CUDA가 없는 맥북/회사 환경에서는 CPU 구현·시험을 먼저 할 수 있다. 실제 GPU 실행은 해당 Windows PC에서 같은 snapshot·recipe로 이어간다. GPU 미실행은 GPU_NOT_RUN으로 공개하고 GPU 요구 완료나 후보 기각으로 표시하지 않는다. 필요한 실행을 마치거나 사용자가 명시적으로 보류하기 전에는 CPU·GPU 비교 전체 완료를 선언하지 않는다.

## 6. 날짜 분리와 동일 표본
- T보다 연구 축 20거래일 전을 anchor로 하고, anchor로 끝나는 마지막 189개 축 날짜를 오래된 순서로 63일씩 세 구간으로 나눈다. 사건 없는 날·가격 없는 날을 지워 구간을 붙이지 않는다.
- 각 구간 시작일 s마다, **D20 정답 종료일이 s보다 이른** 표본만 학습한다. 모든 ETF에 같은 날짜 경계를 적용한다. 구간 안에서 재학습하지 않는다. 고정 후보에는 무작위 validation 분할·early stopping을 쓰지 않는다.
- ETF별 각 구간 학습 날짜 252일 이상과 구간별 공통 시험 날짜 42/63일 이상을 요구한다. 이 조건을 세 구간 모두 충족한 ETF를 주 비교 모집단으로 고정한다. 적격 ETF가 5종 미만이면 DATA_SHORT다. 후보 학습도 이 적격 ETF들의 해당 구간 과거 표본만 사용한다.
- 적격 판정은 날짜·가격 품질·표본 수로만 한다. 수익 방향·모델 오차를 보고 ETF를 빼지 않는다. 탈락한 ETF와 각 사유·기간별 수를 모두 보고한다.
- 각 구간의 네 방법은 **같은 ETF×시험 날짜의 교집합**으로 비교한다. GPU 대기 중 CPU 부분 결과는 별도 표시한다. 어떤 방법의 계산이 실패하면 그 행을 몰래 지워 비교하지 않고 실행 오류로 처리한다.
- 이 252/63/42일·5ETF 기준은 실험 길이와 최소 비교 범위를 정한 설계 선택이며 통계적 충분성이나 투자 성능 보장 기준이 아니다.
- 기존에 이미 조사했던 역사 구간을 쓰므로 신규 독립 확증 시험이라고 부르지 않는다. 공식 실데이터 성과 실행 전에 대상·날짜·설정·판정 기준을 잠그고, smoke는 실행 시간·형식·누수·표본 수만 확인한다.

## 7. 평가·채택 후보 기준·종료
주 지표는 날짜 균형 MAE(%p)다. 날짜마다 적격 ETF 절대오차 평균을 구하고, 날짜들을 같은 비중으로 평균한다. 전체·세 구간과 ETF별 값을 함께 보고한다. 상대 개선율 = (기준 MAE-후보 MAE)/기준 MAE. 기준 MAE가 0이면 우위 판정 없이 REJECT다. 판정은 반올림 전 값으로 한다.

CPU·GPU 후보 각각에 대해 다음 세 조건을 **두 기준(MEDIAN·RIDGE) 각각에 대해 모두** 만족하면 해당 후보를 RESEARCH_PROMISING으로 둔다.
1. 전체 MAE가 5% 이상 감소.
2. 세 구간 중 두 구간 이상에서 후보 MAE가 더 작음.
3. 어느 구간도 후보 MAE가 기준보다 5% 넘게 커지지 않음.

이 통과선은 이번 소규모 연구의 사전 선택이며 보편적 금융 기준이 아니다. 연구 유망은 투자 유효성·운영 채택을 뜻하지 않는다. 겹치는 20일 목표와 비슷한 ETF를 독립 표본으로 가정한 유의확률·적중률·승률 배지는 만들지 않는다. 정식 신뢰구간 계산을 이번 개발의 선행 조건으로 추가하지 않는다.

두 후보를 비교했다는 사실을 모두 보고하며 결과가 좋은 하나만 남겨 단일 사전 후보였다고 쓰지 않는다. 둘 다 통과해도 자동 우승 모델·자동 배포를 만들지 않는다. 같은 문제의 정확도와 실행 비용을 함께 보고 최종 연구 연결 여부를 판단한다. GPU가 더 빠르기만 하고 품질 기준을 못 넘으면 채택 후보가 아니다.

보조 보고: D20이 -8% 이하인 행의 오차와 위험을 작게 추정한 정도 max(추정-실제,0), 해당 날짜·행 수. 종목별 개선/악화 분포도 보여 특정 ETF의 큰 오차 감소가 전체를 끌어올렸는지 확인한다. 보조 결과로 주 판정을 뒤집거나 종목별 맞춤 모델을 선택하지 않는다. 유망 결과라도 이 진단이 나쁘면 사용 범위를 넓히지 않는 판단 근거로 삼는다.

| 결과 | 의미와 다음 |
|---|---|
| RESEARCH_PROMISING | 고정 회고 연구에서 통과. PC 수동 연구 기능 연결 여부를 설계자·사용자가 별도 판단 |
| REJECT | 개선·안정성 기준 미충족. 기존 방법 유지, 이 가설의 연구 종료 |
| DATA_SHORT | 비교 범위 부족. 가능 범위와 부족 사유를 보고하고 개발 종료. 새 수집·대기·기준 완화는 자동 추가하지 않음 |
| GPU_NOT_RUN | CUDA 장비·환경 미준비 또는 아직 미실행. CPU 부분 결과만 보고. GPU 학습 완료·성능 실패로 대체하지 않음 |
| CHECK_REQUIRED | 입력 손상·계열 계약 위반. 해당 문제를 바로 보고하며 정상 부족으로 대체하지 않음 |
| RUN_FAILED | 구현·학습·산출물 오류. 결과를 성능 기각으로 숨기지 않고 결함 정정 |

구현 결함 정정 후의 재실행은 허용하지만 결과가 불리하다는 이유의 재설정·재실험은 금지한다. 기각·자료 부족도 계약대로 계산하고 보고하면 개발 완료다.
