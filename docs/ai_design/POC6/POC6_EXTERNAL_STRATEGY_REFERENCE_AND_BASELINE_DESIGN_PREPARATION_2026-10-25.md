친구 저장소: <https://github.com/jasonisdoing/momentum-etf>

친구분이 말씀하신 모의투자 성과를 부정하거나 검증 완료로 선언하지 않는다. 이번에 읽은 자료에는 그 실제 운용을 재현할 종목풀 판·설정 판·거래 기록·동일 조건의 성과 묶음이 없어 **성과 자체는 미확인**이다. 전략 구조를 참고하는 일은 이 자료 없이도 진행할 수 있다.

## 3. 친구 코드의 핵심 — 지표보다 의사결정 연결을 참고

| 항목 | 확인한 사실 | 근거 |
|---|---|---|
| 순위 | 장기 이동평균 이격 `(종가/장기 MA−1)×100`이 높은 순서. 단기 이격은 점수에 섞지 않음 | `core/strategy/scoring.py :: rank_score` |
| 보유 자격 | 장기 이격 > 0, 단기 이격 ≥ 0 | 같은 파일 `hold_eligible` |
| 이동평균 | 공개 config의 현재 종류는 **EMA**. 기간은 종목풀/전략 DB 설정을 따름. SMA로도 바꿀 수 있음 | `config.py`, `utils/moving_averages.py` |
| 이력 | 모멘텀 경로는 장기 일수+4행 미만이면 점수를 내지 않음 | `utils/momentum_service.py :: momentum_metrics` |
| 종목 수 | 공개 config는 상위 **5개**. 자격 종목이 모자란 슬롯은 현금 | `TOP_N_HOLD=5`, `select_top`, `utils/momentum_backtest.py` |
| 주기·시각 | 주 마지막 거래일 종가로 판단 → 다음 주 첫 거래일 시가에 교체하는 흐름 | `week_rebalance_pair`, 백테스트의 signal_dates/start 구분 |
| 보유 중 관리 | 주중 자격 이탈/손절은 설정 옵션. 이탈분은 다음 거래일 시가 매도, 빈 슬롯은 다음 교체까지 현금 | 전략 문서, `simulate_intraweek_exits` 호출 경로 |
| 시장 폭 | 선택적으로 ADR 하한을 적용해 후보를 비울 수 있음. ADR은 일정 기간 상승 종목 수 합/하락 종목 수 합 | `adr_gate_blocked`, `utils/market_breadth_service.py` |
| 배분·비용 | 슬롯 단위 배분·정수 주수·잔여 현금, 유지 종목의 비중 재조정과 매수/매도 슬리피지를 고려 | `utils/momentum_backtest.py`, `utils/share_allocation.py` |
| 공통 규칙 | 현재 후보와 백테스트가 `select_holdings`·`hold_eligible`·`rank_score`를 공유 | `select_top`과 백테스트 호출 확인 |

이는 **추세를 따라가는 규칙**이다. 상승이 확인된 종목을 고르는 구조이므로 실제 저점·고점을 식별하거나 ‘무릎/어깨’가 입증됐다는 뜻은 아니다. 우리 목적에 맞는지 검증할 대상이다.

중요한 상세 조건도 구분한다.

- 공개된 값만으로 친구의 실운용 단기/장기 기간·주중 이탈·손절·ADR·슬리피지 설정을 확정할 수 없다. 선택지와 실제 저장값은 다르다. ‘친구의 20/60 SMA 전략’처럼 임의로 이름 붙이지 않는다.
- ADR은 종목별 MA와 다른 시장 전체 정보다. 현재 확인한 우리 보관 범위에서 같은 시장 구성·상승/하락 개수 이력을 재현할 수 있는지는 미확인이다. 보유 24종이나 전체 ETF의 등락 수를 KOSPI 전체 ADR로 대신 부르지 않는다. 지금 수집 확대 대상으로 지정하지 않는다.
- 친구 문서도 현재 종목풀에 따른 생존편향을 밝힌다. 튜닝은 선택지 조합을 과거 구간에서 비교한다. 그 설정과 성과를 독립 검증된 우리 운용 기준으로 가져오지 않는다.
- 원본의 전체 데이터 로더·시간/결측 처리·DB·발송 경로를 복사하는 것은 이번 참고 대상이 아니다. 예컨대 원본 일부 계산의 결측 0 처리·부분 MA, 시가 `asof` 조회는 우리 고정 가격/거래일 계약과 별도 대조가 필요하다. 친구 코드를 결함 판정하거나 수정하라는 요청도 아니다.

## 4. 우리 연구와 달랐던 점

| 비교 | 최근 POC6 D20 연구 | 친구의 주력 모멘텀 경로 | 설계에 반영할 것 |
|---|---|---|---|
| 질문 | 향후 최저 종가 변화를 얼마나 잘 추정/우선 검토하는가 | 어떤 종목을 선택하고 언제 보유·이탈·현금으로 둘 것인가 | 평가할 투자 판단부터 정함 |
| 입력 사용 | 고정 가격 feature, 일부 V/R 추가 비교 | 가격/MA를 선정·보유 자격에 직접 연결, 선택적 시장 폭 조건 | 많은 지표보다 각 입력의 역할을 명시 |
| 출력 | 추정·오차·선택 적중 비중 | 선정·유지·교체·비중·현금의 상태 | 사용 목적과 결과를 연결 |
| 평가 | MAE·U, 이후 큰 하락 P/R | 비용과 체결 시점을 둔 포트폴리오 수익·낙폭 등 | 다른 목적의 성적을 직접 우열로 비교하지 않음 |
| 재사용 | 자료/평가/기록 인프라 | 현재 판정·백테스트의 공통 규칙 | 기존 자산 위에 순수한 규칙을 연결 |

**친구 코드도 핵심은 가격 정보다.** 따라서 ‘새 거시 자료가 없어서 우리 연구가 실패했다’거나 ‘해외 ML을 쓰면 같은 결과였을 것’이라는 단정은 이 참고 결과로 뒷받침되지 않는다. 이번 소스 확인은 목표·표현·운용 규칙의 차이를 보여주며 수익 우위를 입증하지 않는다.

우리도 POC4-03에서 20일 모멘텀·월별 바스켓·비용 반영 비교를 했다. 모멘텀을 처음 발견한 것처럼 다시 시작하지 않는다. 친구의 장기 MA 순위·보유 자격·주간 교체·빈 슬롯 현금과 기존 MOM의 정확한 차이를 먼저 연결해야 한다. 과거 기각 결과는 보존한다.

## 6. 다음 설계 방향 — ML이 개선할 투자 기준선부터 명시

다음 후보 목적은 **‘추세에 따른 ETF 선정·보유·이탈·현금 규칙의 실용성 검증’**으로 잡는다. 친구의 구조를 참조해 고정된 규칙 하나를 정의하고, 같은 시점·범위·비용에서 단순 보유와 시장 기준을 비교할 수 있게 하는 방향이다. 이후 ML은 그 기준선의 어느 판단을 얼마나 개선하는지 묻게 한다.

최근 D20 오차 연구에서 연구 대상을 바꾸는 결정이다. 전체 프로젝트의 ETF 선정·진입·보유 판단 지원 목적에 연결하며, 새로운 ML 모델을 반드시 채택한다는 목표로 바꾸지는 않는다. 손실 회피와 수익 선별을 같은 목표로 섞지 않고 거래 빈도·현금 비중·낙폭의 대가를 함께 판단할 것이다.

현재는 고정 기간·종목 수·대상·비용·평가/채택 조건이 확정되지 않았다. 친구의 숨은 실운용 설정을 추정하거나 과거에 잘 된 값을 고르지 않는다. **아래 두 빈칸을 받은 뒤 설계자가 범위·가설·비교 기준을 먼저 확정한다.** 아직 POC6-10의 구현 PLAN이나 수익 실험을 시작하라는 지시가 아니다.

- 구상 범위는 연구용 고정 규칙 한 개와 비교 기준이다. 신고가·합성·레버리지·ADR·수급/환율/WTI 결합·파라미터 전수 탐색을 한꺼번에 붙이지 않는다.
- 실제 종목 추천·주문·PUSH·보유 변경·모의계좌 자동 실행으로 연결하지 않는다. 긍정 연구 결과가 나와도 운영 연결은 별도 결정이다.
- 05·06은 그대로 진행한다. 특정 날짜까지 모든 설계를 멈출 필요는 없으며, 반대로 시간만 지나면 새 자료가 충분해진다고 가정하지도 않는다.

## 7. 개발자에게 필요한 사실 두 묶음 — 1쪽 표만

**읽기 전용으로 다음 두 묶음만 확인한다. 친구 코드는 설계자가 이미 읽었으므로 재조사하지 않는다. 기존 조사와 원문 위치를 우선 재사용한다.**

### A. 기존 저장 자료로 종가 판단 → 다음 거래일 시가 비교가 가능한가

06의 보유 독립 24종 장기 사본, 03의 069500 장기 사본, 기존 봉인 KRX 자료 중 이미 등록된 입력에 한정한다. 자료별 아래를 표로 적는다.

- Open·Close의 존재, 실제 같은 날짜 범위, 시가의 결측/0/비정상 개수. 서로 다른 수신 판을 이어 붙이지 않고 쓸 수 있는 범위.
- Open과 Close의 조정 의미를 기존 코드/원천 기록으로 확인할 수 있는지. 알 수 없으면 미확인. 새 원천 대조·가격 재수집은 하지 않는다.
- 실제 거래일·상장 전/후 구분과 종목 유형 자료의 접점. 기존 보유 독립 표본을 설명하고, 성과를 보고 종목을 선정하지 않는다.

새 MA 값·순위·포트폴리오 수익·낙폭·가상 거래는 계산하지 않는다. 05의 약 120달력일 창이 장기 EMA 전체 이력을 대신한다고 가정하지 않는다. 가격 경계 검사는 기존에 확인된 규칙/결과를 재사용하고 새 전수 감사를 열지 않는다.

### B. 이미 했던 MOM과 재사용 가능한 계산의 접점

- POC4-03 MOM의 점수·자격·교체 주기·체결 가격·비중/현금·비용을 원문/해당 함수 위치로 한 줄씩 연결한다. 이번 친구 구조와 같음/다름/미확인만 적고 과거 연구를 다시 실행하지 않는다.
- 기존 코드에 있는 MA/EMA, 거래일 정렬, 포트폴리오/매매 비용 계산 중 그대로 쓸 수 있는 함수·책임 위치만 적는다. 친구 엔진·Backtrader 설치나 새 엔진 작성은 하지 않는다. 이미 같은 기능이 있으면 그 위치만 전달한다.

**결과 형식:** 위 두 묶음의 표 1쪽 안팎, 미확인 항목과 설계자 판단이 필요한 충돌만. 새 PLAN·감사 보고서·handoff·이 확인만을 위한 별도 커밋은 요구하지 않는다. 저장소 코드는 바꾸지 않는다. 외부 가격 조회·설치·학습·성과 계산·튜닝·라이브 DB 쓰기·OCI 쓰기는 없다.

자료를 받은 뒤 설계자가 정식 다음 설계와 종료 조건을 작성한다. 같은 기능의 반복 개발이면 열지 않으며, 필요한 자료가 없으면 없음 표시/대체 가능한 기존 자료/수집의 필요성을 구분해 사용자와 판단한다. 기다리기나 신규 수집을 자동 정답으로 두지 않는다.
