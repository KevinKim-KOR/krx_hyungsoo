# POC6-14 DESIGN V1 — 전향 ML 비교 결과의 PC 조회

작성: 설계자 · 2026-10-30 · 독자: 개발자·사용자·검증자

저장 권장 위치: docs/ai_design/POC6/POC6-14_FORWARD_MODEL_COMPARISON_PC_VIEW_DESIGN_V1.md

**다음 단계:** 기존 06의 예측·공개 확인·성숙 결과·비교 보고를 PC에서 읽어 볼 수 있게 연결한다. 새 모델·가설·성과 계산·투자 권고를 추가하지 않는다. **먼저 §10의 짧은 PLAN과 전체 화면 목업을 제출한다. PLAN 판정과 사용자 목업 확인 전 구현하지 않는다.**

## 1. 목적·선택 이유·이번 단계의 한계

사용자 목적은 비용 후 KODEX200보다 나은 후보 선별과 진입·유지·축소·청산 검토 권고, 유용한 ML 연결이다. 그 목적은 미완료로 유지한다.

현재 05 자료 축적과 06 예측·월별 학습 연결은 있고, 13에서 맥북 자동 기록·OCI 보관과 별도 PC 백업을 확인했다. 반면 이 연구의 실제 예측과 성숙 비교는 CLI·연구 파일 중심이다. 기존 AI 투자 세션에는 선택 근거 전달·저장·재조회가 이미 있으므로 같은 기록 화면을 다시 만들지 않는다.

이번에는 **이미 돌아가는 ML·기준선 비교를 사용자가 화면에서 확인하고, 같은 기준일의 추정과 실제 결과를 볼 수 있게 한다.** 무엇을 추정하고 얼마나 기록됐으며 아직 평가할 수 없는 이유를 드러낸다. 연구를 운영 추천으로 잘못 읽게 하는 연결은 하지 않는다.

| 이번에 더하는 것 | 이번에 하지 않는 것 |
|---|---|
| 24종 연구 표본의 기준일별 예측·방법 상태·저장된 성숙 목표 조회 | 새 학습·튜닝·모델 선정·위험 등급·추천 순위 |
| 기존 비교 보고의 날짜 균형 오차·비교 분모·보고 시각 표시 | 목표/오차 재계산·새 통계·매매 성과 계산 |
| 선택 행을 화면과 같은 문구로 복사 | 외부 AI 자동 호출·AI 세션 새 저장 형식 |
| 기존 「진단」 영역 안의 연구 결과 조회 | 새 최상위 메뉴·PUSH·OCI 추론 이관·자료 수집 |

POC6-12는 SOURCE_BLOCKED로 이번 확인이 종료됐다. 분배금 포함 총수익 자료는 확보되지 않았다. 이번 조회는 종가 경로에 대한 D20 연구이므로 12 재개를 선행 조건으로 두지 않는다. 이 표를 총수익·KODEX200 초과성과·실제 매매 효용의 검증으로 쓰지도 않는다.

## 2. 기준 자료와 고정 해석

- 주체는 POC6-06의 고정 cohort다. 현재 보고된 분모는 24종이며 **보유·seed·추천 목록과 무관하다.** 보유 파일을 읽어 대상을 바꾸지 않는다.
- 방법은 MEDIAN·RIDGE·HGB·MLP_CPU 네 가지다. 모두를 “새 운영 ML 4개”로 부르지 않는다. 화면에는 중앙값 기준선, Ridge, HGB, MLP(CPU)처럼 짧게 구분한다.
- D20 = min(0, 다음 20거래일 종가/기준일 종가−1의 최솟값). 종가 기준의 연구 추정이며 20일째 수익률·MDD·장중 저점·손실 확률·의무 보유 기간이 아니다.
- 주 기록은 기존 06의 공개 확인 영수증·해시·기준일·마감 검사와 재시도 연결 판정을 통과한 기록이다. prediction 파일의 존재나 status 글자만으로 새로 판정하지 않는다.
- 늦은 진단·부가 기록·실패·미확인은 기존 구분을 보존한다. 정상 주 기록의 표본·오차·날짜 선택에 섞지 않는다.
- 월별 모델 판·당시 입력·예측은 기존 기록 그대로다. 지금의 최신 모델로 옛 날짜를 다시 예측하지 않는다.
- 10-30 종료 보고의 D=10-29·24종·마감 전 확인은 당시 실제 확인이다. 개발 때는 PC의 현재 자료를 읽고, 이 날짜·건수를 화면 상수로 넣지 않는다.

기존 「진단」의 실제 화면 이름과 삽입 위치는 PLAN에서 현재 코드를 좁게 확인한다. 예전 중단 특징 표의 준비도 카드를 06의 현황처럼 재사용하지 않는다.

## 3. 기본 화면 — 값은 기본 노출, 설명은 도움말

기존 「진단」 안에 **「전향 ML 비교 · 연구」** 영역을 추가한다. 다른 진단 기능을 개편하지 않는다. 기본 노출 순서는 다음과 같다.

1. **상태 한 줄:** “연구용 · 운영 미채택”과 고정 연구 표본/기록된 기준일 수. 기준일 선택은 유효 주 기록이 있는 날짜만 제공하고 기본값은 가장 최근 D다.
2. **선택 기준일의 근거:** D·해당 기록의 공개 확인 시각·입력 기준·사용 모델 판. 여러 판/확인 시각이면 하나로 가장하지 말고 범위 또는 “여러 판”으로 표시하며 행 상세에서 확인한다.
3. **24종 표:** 종목명/티커, 네 방법의 D20 제한 예측, 저장된 실제 D20 또는 성숙 상태. 기본 정렬은 티커 오름차순이며 예측 크기·개인 보유·성과로 순위를 만들지 않는다.
4. **누적 비교:** 선택 D의 표와 분리해 기존 누적 비교 보고의 범위·생성 시각·비교 표본·오차를 보인다. “선택한 하루의 성적”으로 오인하지 않게 한다.
5. **선택 행 상세:** 표에서 종목 하나를 고르면 그 행 바로 아래 또는 표 바로 옆에 보인다. 페이지 맨 아래로 보내지 않는다. 당시 모델 판·영수증 시각·입력 참조·방법별 사유와 [복사]를 둔다.

첫 화면에서 네 예측값과 성숙 상태를 보기 위해 종목마다 펼칠 필요가 없어야 한다. 긴 정의·제약은 기존 규격의 ? 버튼 한 곳으로 옮긴다. 클릭으로 열고 Esc/바깥 클릭으로 닫는 기존 도움말 방식을 재사용한다. 새 팝업 체계는 만들지 않는다.

1440px·1000px 전체 화면 목업으로 확인한다. 표는 두 폭 모두 핵심 값·단위를 읽을 수 있게 하고, 설명 문장이 셀마다 길게 반복되지 않게 한다. 차트는 이번에 추가하지 않는다.

## 4. 숫자·단위·성숙 상태

예측과 실제 D20은 %로, MAE와 큰 하락을 작게 추정한 정도는 %p로 표시한다. 저장 칸의 단위가 소수인지 이미 %p인지 PLAN에서 실제 산출물과 대조한 뒤 API 계약에 명시한다. 무조건 100을 곱하지 않는다. 화면과 복사는 같은 기존 포맷 함수를 쓴다.

| 원기록의 상태 | 기본 표시와 처리 |
|---|---|
| 방법 OK | 저장된 범위 제한 예측. 원시 예측을 제한 예측 대신 내보내지 않음 |
| 방법 실패/미실행/환경 불일치 | 숫자 없음 + 짧은 사유. 다른 방법·이전 판·0으로 대체하지 않음 |
| PENDING_NOT_DUE | “결과 대기”. 저장된 예정일이 있으면 함께 표시하며 평일 수로 새로 만들지 않음 |
| PENDING_CALENDAR | “결과 일정 확인 불가” |
| DUE_DATA_MISSING | “결과 자료 미확보” |
| DATA_CHECK_REQUIRED | “결과 자료 확인 필요”. 숫자를 정상 결과로 쓰지 않음 |
| 유효 주 기록 없음 | “공개 확인된 연구 기록 없음”. 진단만 있는 경우 이를 구분 |
| 비교 행 0 / MAE null | “아직 비교할 결과 없음”. 0%p·동률·실패·모델 기각으로 쓰지 않음 |

서로 다른 방법의 성공 수·같은 행 비교 수·성숙 행 수는 다른 분모다. UI에서 모두 “평가 완료 수” 하나로 합치지 않는다. 결측을 숨겨 성공한 종목만 목록에 남기지 않는다.

연구 표본 날짜가 시장 최신일과 다를 수 있다. PC 시장 최신일로 날짜를 채우지 않는다. 기록이 없는 평일을 모두 누락으로 확정하거나 조회 시 달력을 새로 계산하지 않는다. 과거 결측은 표시만 하며 소급 실행 버튼은 두지 않는다.

## 5. 누적 비교 — 기존 보고를 읽고 의미를 보존

06의 report.py가 만든 **저장된 비교 보고서**를 표시한다. 웹 조회에서 report CLI·run·mature·training을 실행하지 않는다. 기존 MAE·보조 지표를 UI/새 백엔드에서 다시 계산하지 않는다.

- 같은 protocol/cohort에 속한 보고의 생성 시각·대상 범위를 확인해 가장 최근 정상 생성 보고를 식별한다. 파일 수정 시각만으로 고르지 않는다. 단순히 “가장 최근 정상”이라는 이유로 뒤에 있는 손상 보고를 조용히 숨기지 말고, 최신 보고 확인 필요를 표시한다.
- 새 주 기록은 있지만 대응 보고가 아직 없거나 읽기 도중 게시 중이면 예측 표와 보고 상태를 나눈다. 보고를 새로 쓰지 않고 “보고서 확인 대기”로 두며 사용자가 [다시 읽기] 할 수 있게 한다.
- HGB와 MEDIAN/RIDGE 비교, MLP와 MEDIAN/RIDGE 비교는 기존 보고의 각각 공통 유효 행을 사용한다. 서로 분모가 다른 수치를 네 방법의 단일 순위표로 합치지 않는다.
- 기존 보고에 네 방법 공통 행의 직접 비교가 있으면 그 분모를 명시해 표시할 수 있다. 없으면 새로 산출하지 않는다.
- 큰 하락 보조 지표를 보이면 기존 D20≤−8% 조건과 표본 수를 함께 적는다. 이 8%는 기존 연구의 보조 구분이며 새 경보 기준이 아니다.
- 기존 보고가 가진 종목별/모델 판별 정보를 행 상세에서 볼 수 있게 할 수 있으나 새로운 성과 필터·좋은 종목만의 주 표·우승 배지는 만들지 않는다.
- 성숙 전 화면으로 개발을 끝낼 수 있다. 11월 성숙·다음 학습·3개월 해석 시점을 기다리지 않는다.

“오차가 가장 작다”와 “추천에 사용할 수 있다”는 다른 판단이다. 채택 기준을 새로 만들거나 과거 5% gate를 자동 적용하지 않는다.

## 6. 행 복사와 기존 AI 세션 경계

선택 행의 [복사]는 **화면에 표시된 같은 응답**에서 문장을 만든다. 클릭 때문에 조회·입력 갱신·예측을 다시 실행하지 않는다.

복사문에는 연구용/운영 미채택, 고정 연구 표본이라는 점, 종목·D·공개 확인 시각·모델 판, 네 방법의 예측/실패 사유, 실제 D20 또는 대기/확인 필요, 읽은 보고의 범위·시각을 넣는다. D20의 뜻과 매매 수익률이 아니라는 설명은 한 번 적는다. 없는 정보는 “미확인”으로 두며 최신 시장 값으로 채우지 않는다.

POC5-24의 기존 선택 근거 초안·판단 저장은 유지한다. **이번에 06 기록을 그 초안의 ML 칸에 자동 보충하지 않는다.** 기존 화면의 선택 종목이 우연히 같은 티커여도 같은 시점/목적의 운영 근거라고 간주하지 않는다. 외부 AI에 보낼지는 사용자 선택이며 시스템은 전송하지 않는다.

## 7. PC 읽기 전용 접점과 구현 경계

작은 PC 전용 조회 모듈·GET 경로 하나와 화면 컴포넌트를 기본안으로 한다. 예: GET /ml/forward-comparison, 선택 D는 엄격한 날짜 인자. 실제 경로명·기존 진단 컴포넌트 접점은 PLAN에서 정한다. 기존 CLI 결과를 subprocess로 받아 오는 방식은 쓰지 않는다.

- 읽기 루트는 06의 서버 설정 경로다. 클라이언트가 임의 파일 경로·cohort·연구 폴더를 지정하지 못한다.
- 기본적으로 cohort·기존 records의 주 기록/영수증 판정·저장된 목표·보고 JSON만 읽는다. joblib/torch 가중치를 열거나 model을 load/import/predict하지 않는다. 새 패키지도 없다.
- 06·13의 run/학습/성숙/보관/일정 코드를 바꾸지 않는다. 조회 때문에 폴더 초기화·run/목표/영수증/보고 생성·잠금 파일 생성·SSH·외부 수집을 하지 않는다.
- 기존 records의 순수 읽기 함수를 우선 재사용한다. 원하는 읽기가 쓰기/무거운 패키지 import와 결합돼 있으면 PLAN에서 그 접점만 질문한다. 연구 코드 전체 리팩터링을 먼저 하지 않는다.
- 저장소가 아직 없으면 “기록 없음”, 접근/해석 실패는 “불러오기 실패/확인 필요”, 보고 미생성은 “보고 대기”로 구분한다. 모두 빈 정상 응답으로 바꾸지 않는다.
- 스키마·protocol/cohort·기준일·단위가 맞지 않으면 확인 필요다. 방법별로 이미 기록된 실패는 정상 사유로 표시하되 잘못된 숫자를 살려 내지 않는다. 비유한 값·범위 밖 제한 예측은 정상 숫자로 내보내지 않는다.
- 정상 작성 중인 자료를 읽을 때 기존 불변 게시/영수증 규칙을 따른다. 웹 조회가 쓰기 잠금을 지우거나 미확인 기록을 확정하지 않는다.
- 새 GET은 연구 숫자·식별·시각·필요한 사유만 반환한다. 모델 원문·절대 파일 경로·계정·키·보유 수량/평단·개인 메모를 응답하지 않는다.

POC6-06의 “화면/API 변경 없음”은 당시 개발 범위다. 이번에는 **저장된 연구 결과의 PC 읽기 전용 조회**만 별도 허용하며 운영 ML 승격은 아니다. 기반 문서의 실제 충돌 위치가 있으면 PLAN에서 그 문장만 제시한다. 관성적으로 기반 문서 세 개에 새 예외를 반복 추가하지 않는다. PUSH 금지 문구·기존 판단 화면의 위험 등급 검사도 일괄 해제하지 않는다.

## 8. 시험·사용자 확인·완료

필수 확인은 데이터 소비 경계다. 실제 연구 결과 파일은 공개 시험 fixture에 넣지 않고 가짜 cohort/예측/영수증/목표/보고를 쓴다.

| 확인 | 필수 사례 |
|---|---|
| 읽기 전용 | API/새로고침/복사 뒤 연구 파일·DB 변경 없음, run/학습/모델 로드/수집/SSH 호출 없음 |
| 주 기록 | 영수증 없음·해시 불일치·마감 뒤 확인·진단/부가를 정상 주 기록에 섞지 않음, 같은 입력 재시도는 기존 연결대로 |
| 실패/날짜 | 연구 폴더 없음·접근 실패·보고 없음·손상·cohort 불일치·선택 D 없음을 구분. 오래된 값을 새 D에 붙이지 않음 |
| 표시 | 제한 예측/실제 %와 MAE %p의 단위, null·방법 실패·아직 미성숙, 공통 행 분모와 보고 시각 |
| 연결 | 기준일/종목 변경 중 이전 응답이 늦게 와도 새 선택에 붙지 않음. 복사문이 그때 표시 응답과 같음 |
| 기존 경계 | 다른 진단 기능·선택 근거/AI 세션·06/13 실행 코드가 불필요하게 바뀌지 않음 |

새 경로와 실제 변경 접점에 필요한 시험·타입/정적 검사를 수행한다. 저장소 필수 검사는 따른다. 기존 운영 코드에 영향이 없는데 전체 연구 재실행·학습·성숙 처리·OCI 점검을 반복하지 않는다. 실제 성숙/실패 상태가 없으면 가짜 자료 검증이라고 기록한다.

목업 확인 → PLAN 판정 → 구현·관련 검사 → 사용자 실화면 확인 → 검증자 → RESULT 판정 순서다. 실제 PC에서 저장된 자료를 한 번 읽어 값·날짜·대기 상태·복사를 확인하면 실연결 조건을 충족한다. 신규 예측을 만들거나 미래 결과를 기다리지 않는다.

완료는 **“기존 전향 연구의 PC 조회·복사 연결 완료”**다. 추천 효용·총수익 검증·운영 ML 채택·프로젝트 전체 완료로 기록하지 않는다.

## 9. 승인·예산·유지할 상태

PC API·화면·테스트·문서 개발 범위다. UI 목업은 로컬 전용이며 실제 자료를 공개 게시하지 않는다. 새 외부 조회·새 DB 표·OCI pull/cron/패키지·원격 업로드는 없다. PC 반영과 커밋/push는 유효한 사용자 승인 범위로 한다. 사용자 handoff·로컬 연구 브랜치·연구 산출물을 공개 커밋에 넣지 않는다.

PLAN 구조 확인은 기존 06·13·진단 접점에 한정하고 **개발자 작업 60분 이내**로 한다. 새 자료를 수집하거나 성과를 계산하지 않는다. 전체 백로그/저장소 재감사는 하지 않는다. 예상 구현 규모·조회 비용은 실제 접점을 확인해 짧게 적는다. 현재 파일이 근접선이면 새 읽기/표시 책임을 작은 모듈로 분리한다.

05 수집·06 자동 전향 기록/월별 학습·13 백업은 유지한다. 12의 SOURCE_BLOCKED, Q6 OPEN, ML_OPERATION_PROMOTION=NOT_APPROVED, CURRENT_DEPLOYABLE_ML_MODEL=none, 미완료 요구 #3/#55/#57/#62도 그대로다. 같은 POC6 안이므로 별도 handoff는 없다.

12·13 종료 문서가 아직 stage 상태라면 다음 승인된 문서/종료 커밋에 함께 반영할 수 있다. 이번 단계와 섞어 구현 완료 범위를 부풀리거나 사용자 승인 없이 push하지 않는다.

## 10. 개발자에게 요청하는 짧은 PLAN과 목업

다음 네 묶음만 확인해 제출한다. 이미 알려진 숫자와 경로를 다시 전수 조사하지 않는다.

1. **현재 파일/읽기 접점:** 실제 06 cohort·주 기록·성숙 목표·reports의 스키마와 경로, 단위·보고 범위·판 선택 방법. 순수 records 읽기를 모델/실행 모듈 없이 쓸 수 있는지.
2. **현재 화면/API 접점:** 「진단」의 정확한 위치·기존 준비도 카드와 구분, 새 GET 한 개·작은 컴포넌트/포맷 재사용·변경 파일·KS-10. 실제 저장 예측 조회가 이미 구현돼 있으면 그 부분은 중복 구현하지 말고 연결만 제안.
3. **상태/시험:** 기록 없음·실패·미성숙·보고 대기·같은 행 분모·시각/응답 경합을 표현하는 방식과 실제 read-only 확인 범위. 성숙 자료가 없다는 이유로 실행이나 성과 계산을 하지 않음.
4. **전체 화면 목업:** 1440px/1000px 실제 현재 자료의 기본 화면, 가짜 자료의 성숙/방법 실패/보고 없음/기록 없음. 실제와 가짜를 구분하고 기본 노출·도움말·행 상세·복사문을 보여 줌.

질문은 실제 충돌·없는 필드·재사용 불가 접점만 올린다. 새 모델·추천 임계·성숙 날짜·별도 지표를 개발자가 임의로 정하지 않는다. 목업 서버가 필요하면 정상 연구 폴더를 쓰지 않는 GET 전용 목업으로 제한하고 확인 뒤 정리한다.
