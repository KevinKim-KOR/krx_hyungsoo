# 차기 추천·ML 연구 사전 확인 — 수급·환율·유가 입력의 검증 가능 범위

작성: 2026-11-03 · 설계자 → 개발자
저장: `docs/ai_design/POC6/POC6_NEXT_RESEARCH_MARKET_CONTEXT_FEASIBILITY_REQUEST_2026-11-03.md`

**이번은 새 모델 연구의 실행 설계 전 확인이다. 20분 이내, PC 기존 자료 읽기만으로 회신한다. 새 POC 번호·구현·학습을 먼저 열지 않는다.**

## 1. 다음으로 검토할 질문

**같은 ETF 선별·운용 조건에서, ETF 가격·거래량 입력에 코스피 수급·원/달러·WTI라는 시장 맥락을 더하면 추가 정보 가치가 있는지 검증할 수 있는가?**

실험을 열 경우의 주목적은 이미 합의한 비용 후 KODEX200 대비 성과이며, 위험·교체 부담도 같은 계약에서 관리한다. 이번 확인에서는 정보 가치가 있다고 가정하거나 효용을 계산하지 않는다. 먼저 그 질문을 검증할 자료·기간·정보 시점이 있는지 판단한다.

POC6-11의 입력·설정을 바꿔 자동 재실행하는 지시가 아니다. 새 정보가 검증 가능한지 확인한 뒤에만 별도 가설·목표·평가·예산을 확정한다. D20이나 원 H1의 60일 목표를 새 보유 기간으로 자동 승계하지 않는다.

## 2. 현재 상태와 이번에 하지 않을 것

- 사용자 보고: POC6-18 사용 흐름 확인 종료, 문서 커밋 `496bb342`, 보완 후보 6건 미개발. 그 종료와 기존 15~17을 유지한다.
- POC6-17은 수급 보관본 → PC 운영 표 연결을 확인했다. 이 연결의 성공이 연구에 충분한 장기 표본을 확보했다는 뜻은 아니다.
- 17 PLAN의 기존 실측은 수급 object 475개·262자료일, 2025-09-30~2026-10-30이다. 이를 출발 근거로 사용하고 같은 내용을 다시 전수 조사하지 않는다. 새 보관본으로 범위가 달라졌다면 차이만 적는다.
- 06 전향 모델과 H1 비교의 기존 입력에 새 시장 맥락을 연결한 것으로 전제하지 않는다. 과거 입력·모델·연구 결론은 그대로 둔다.
- 새 수집·pull·OCI 접속/쓰기·DB 쓰기·학습·예측·상관/성과/정답값 계산·설치·화면 수정은 하지 않는다. 운영 DB를 읽을 때는 읽기 전용 연결을 쓴다.
- 18의 다음 실제 주간 기록은 사용자 운영 일정이다. 그때까지 이번 확인이나 설계를 기다려야 하는 조건은 아니다.

## 3. 확인할 것 — 기존 근거 재사용, 빈 부분만 읽기

| 확인 항목 | 회신할 사실 |
|---|---|
| 시장 자료의 기간 | 수급·원/달러·WTI별 보관된 유효 날짜 범위·자료일 수. 기존 보고가 있으면 그 위치와 값만 재사용 |
| 원래 확보 시점 | 자료 기준일과 OCI 관측·공개 시각, PC 수신 시각을 구분. 과거 날짜를 뒤에 받은 자료와 실제 당시 확보 판을 나눔 |
| 가격과의 교집합 | 기존 연구 가격 사본·봉인 KRX 중 어떤 고정 판과 공통 날짜가 있는지. 가격의 끝일과 시장 자료 끝일을 따로 적음 |
| 시간상 검증 여유 | 기존 H1 학습·검증 최소 조건과 비교했을 때 가능한지. 날짜만으로 판단하고 정답 크기·성능은 계산하지 않음 |
| 실제 전향 기록 | 05 보관 시작 이후 실제 시점별로 확보됐다고 확인할 수 있는 범위. 회고 자료를 전향 실적으로 바꾸지 않음 |
| 대상 적합성 | 코스피 전체 수급과 국내주식·해외주식·채권 ETF를 구분할 기존 자료가 있는지. 시장 전체 값을 종목별 수급으로 해석하지 않음 |

시장 자료는 같은 날 여러 ETF에 공통으로 붙는 정보다. **ETF 행이 많다는 이유로 서로 독립적인 시장 관측일도 많아졌다고 세지 않는다.** 사용 가능한 날짜·주 단위 길이를 함께 적는다.

기존 H1의 최소 학습·평가 길이를 못 채우면 그 사실을 먼저 적는다. 이미 알고 있는 짧은 기간을 다시 세기 위해 20분을 쓰지 않는다. 설계자가 정하지 않은 짧은 창이나 낮은 기준을 임의로 골라 실험 가능으로 바꾸지 않는다.

POC6-12의 분배·총수익 자료 미확보도 유지한다. 가격 기준의 탐색적 비교 가능성과 실제 비용 후 총수익·운영 채택 근거의 가능성을 구분한다.

## 4. 회신은 표 한 장과 결론으로

| 구분 | 확인된 범위·근거 | 가능한 검증 수준·부족한 것 |
|---|---|---|
| 수급·환율·WTI | | |
| 공통 가격 기간·대상 구분 | | |
| 당시 확보 판·실제 전향 기간 | | |
| 학습/검증 분리·기존에 본 시험 기간 | | |
| 총수익·운영 채택 근거의 제한 | | |

마지막에 다음 중 해당하는 수준과 이유를 적는다.

- **연구 설계 가능:** 정한 목표에 맞는 자료·시점·평가 구간을 설계할 여지가 확인됨. 아직 효용 입증·학습 승인·운영 채택은 아님.
- **회고 탐색만 가능:** 당시 확보 판·독립 평가 등 한계 때문에 탐색적 질문으로만 다룰 수 있음. 이미 본 시험 기간은 새 미사용 검증으로 부르지 않음.
- **현재 연구 재개 근거 부족:** 필요한 기간·정보 시점·대상 자료 등을 특정. 부족한 증거 조건만 적고 새 코드·형식적인 DATA_SHORT 실험을 만들지 않음.

20분 안에 못 확인한 부분은 미확인으로 둔다. 전 저장소·과거 연구·공식 데이터 원천을 다시 조사하는 작업으로 늘리지 않는다.

## 5. 회신 뒤 설계자의 결정

연구가 가능하면 설계자가 **가설 하나·목표·기간·대상·입력 판·같은 기준선/운용 조건·탐색 예산·판정·기각 시 종료 범위**를 정한 실행 설계를 작성한다. 비교에서는 추가 시장 입력의 차이와 다른 변경을 구분하며 새 모델 종류를 여러 개 시험하는 계획을 자동으로 붙이지 않는다.

자료가 부족하면 코드부터 만들지 않는다. 무엇이 추가로 확보돼야 재개할지 조건을 남기고 기존 수집·전향 기록·실사용을 이어간다. 특정 달력 날짜나 ‘1년치’라는 말만으로 자동 재개하지 않는다. 새 원천·대량 과거 조회·평가 기준 완화는 별도 판단이다.

이 사전 확인에는 별도 PLAN·목업·검증자·결과서 묶음이 필요 없다. 회신을 대화 또는 이 요청서 후속 기록으로 남기면 충분하다. 확인만을 위한 별도 커밋·push·handoff는 요구하지 않는다.
