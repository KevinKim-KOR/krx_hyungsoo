## 1. 판정 요약

**Q1은 (b), POC6-19 전체 PARTIAL 유지다. 보충 실행 기록과 검증자 §15의 VERIFIED는 수용한다. 다음은 사용자 쪽 등록 IP 확인이며, 그 전의 추가 실행·자동 대기는 없다. 문서 보충 커밋·push는 지금 허용한다.**

구현·시험과 원/달러·WTI 선행 사본의 수용 확정은 유지한다. 이번 보충에서 확인한 것은 다른 망에서도 키움 인증이 거절됐다는 사실이다. 수급 자료를 실제로 요청하지 못했으므로 과거 이력 제공 여부·날짜·13분류·단위·장기 범위는 여전히 미확인이다.

Q1(a)의 확보 범위만으로 전체 종료는 지금 선택하지 않는다. 수급을 목표에서 제외하기 전에, 실제 등록 IP와 실행 망의 일치 여부를 확인하는 한 가지 전제가 남아 있다. 현재 거절 기록은 수급 이력 확보를 포기해야 할 자료 측 근거가 아니다. 이 확인을 새 수집 플랫폼이나 반복 조사로 넓히지 않는다.

이번 실행 시도와 대기는 끝난 것으로 수용한다. **PARTIAL 유지는 대기 프로세스를 계속 켜 두라는 뜻이 아니다.**

## 3. Q2 — 확인 주체와 재실행 조건

### 3-1. 다음 행동은 사용자 쪽 등록 현황 확인

**확인 주체는 사용자다.** 사용자가 키움의 이번 앱키에 적용되는 등록 IP 현황과, 실제 실행할 맥북의 외부 접속 IP가 일치하는지 확인한다. IP 숫자·키·토큰·화면 전체를 설계자나 공개 문서에 보낼 필요는 없다. ‘이번 앱키 기준 일치 확인 / 불일치 / 아직 확인하지 못함’과 확인 시점만 전달하면 된다.

집 와이파이에 연결됐다는 사실, 다른 공유기를 감지했다는 사실, 과거 어느 날 인증됐다는 사실을 현재 일치 확인으로 대신하지 않는다. 이번 확인을 위해 개발자가 전체 저장소를 재조사하거나 인증 API를 반복 호출하지 않는다.

현재 계약의 **개발자 임의 IP 등록 변경·OCI 우회 금지**는 유지한다. 불일치해서 등록 설정이나 실행 위치를 바꿔야 한다면 사용자가 필요한 조치를 선택하고 명시적으로 승인한다. 기존 OCI 운영에 쓰이는 설정을 임의로 덮어쓰거나 새 OCI 조회 작업을 만들지 않는다. 같은 범위의 확인을 이유로 새 PLAN을 작성하지 않는다.

### 3-2. 추가 실행은 확인 뒤 별도 1회 승인

이번 승인에 따른 낮·밤 실행 두 번은 이미 수행됐다. 남은 대기 시도는 사용하지 않은 채 종료됐다. **이번 판정 자체가 추가 API 실행을 승인하는 것은 아니다.**

사용자가 실행 망 확인을 마치고 ‘추가 실행 1회’를 승인하면 개발자가 같은 POC6-19에서 재개한다. 승인에는 다음 전체를 한 묶음으로 명시하고, A 이후 다시 승인을 묻지 않는다.

- 이번 앱키의 등록 현황과 실행 망 일치 확인.
- 기존 연구 명령의 추가 실행 1회: 키움 인증, A 표본 및 조건 충족 시 B 장기 확보, 기존 명령에 포함된 Yahoo 표본·장기 조회, 새 연구 폴더 쓰기.
- 기존 대상·요청/시간·재시도·메모리/용량 상한 유지. 이 승인을 추가 실행의 예산으로 기록하고, 이미 수행한 두 실행의 요청 수는 그대로 보존한다.

기존 상한은 인증 최대 2회, A 데이터 요청 32회·30분, B 데이터 요청 7,000회·120분이며 더 이른 중단 조건도 그대로 적용한다. 인증이 다시 거절되면 그 응답으로 멈추고 자료 요청·망 탐색·재시도를 자동으로 이어가지 않는다. 실행 뒤 검증자는 새 실제 결과 부분만 확인한다.

확인 결과가 불일치이거나 미확인이면 실행하지 않는다. 등록 일치를 확인한 뒤에도 거절되면 그 사실을 보고하며, 새 모델·공급자·프레임워크나 공유 코드 변경으로 문제를 우회하지 않는다.

## 4. Q3 — 문서 보충 커밋·push

**허용한다. 기존 ‘모두 승인’ 및 범위 확정 판정의 문서 보충 승인 범위를 재사용한다.** 이번 문서 반영을 위한 승인을 다시 요청하지 않는다. 수급 실행 승인은 §3의 별개 항목이다.

- stage된 RESULT·PLAN·STATE_LATEST·PROGRAM_TRUTH 4개 문서에 이번 판정 원문을 더해 한 커밋으로 반영하고 push할 수 있다. 실제 목록과 수는 커밋 직전 확인한 값을 사용한다.
- 현재 상태는 ‘구현/Yahoo 수용 확정·보충 실행 기록 VERIFIED·전체 PARTIAL·사용자 등록 IP 확인 후 추가 1회 승인 시 재개’로 연결한다. ‘수집 완료’, ‘등록망 확인 완료’, ‘과거 이력 미제공’으로 쓰지 않는다.
- 과거 설계자 판정·검증자 원문은 보존하고, 현재 상태와 다음 행동에는 이 보충 판정을 연결한다.
- 원자료·연구 산출물·망 지문/주소·계정정보·대기 스크립트와 사용자 소유 7월 26일 handoff는 제외한다. OCI 작업은 없다.
- 코드·시험 변경이 없으므로 코드 검증·전체 회귀·프런트 검사·변이를 반복하지 않는다. 문서 보충만을 위한 새 POC·별도 handoff도 필요 없다.

문서 반영 후에는 실제 커밋·push 결과와 현재 실행/대기 없음만 짧게 보고하면 된다. 이 사실 보고를 위한 설계자 재판정은 필요 없다.
