# POC6-22 설계 V1 — 저장 예측·장부로 추세 판단의 실패 지점 확인

작성: 총괄 설계자 · 2026-11-05(KST)

보관 위치: `docs/ai_design/POC6/POC6-22_SAVED_PREDICTION_AND_POLICY_DIAGNOSTIC_DESIGN_V1.md`

다음: 개발자가 지정된 산출물의 필드·접점·최소 분석 범위만 확인한 짧은 PLAN. 설계 검토·PLAN/RESULT 판정은 설계자, 분석과 보고는 개발자, 결과 수치 확인은 검증자가 맡는다. 이 문서는 새 학습·전략 재실행·운영 변경 승인이 아니다.

## 1. 출발 상태와 단일 목표

최신 사용자·개발자 보고에 따라 POC6-21은 `991b2500`을 origin/main에 push했고 로컬/원격 일치·IMPLEMENTED_VERIFIED_CLOSED로 인수한다. 설계자 PASS·검증자 r1 VERIFIED·공식 실행 1회·NOT_CANDIDATE/UNCERTAIN·운영 미채택이다. 종료 조건을 다시 심사하지 않는다.

POC6-20에서는 시장 4열의 추가 효용이 관측됐지만 목적·회전율을 충족하지 못했고, POC6-21에서는 절대 목표 ML과 최근 전환 강화 모두 효용이 관측되지 않았다. 두 실험은 목표·운용·대조군이 달라 성과 차이를 특정 요소 하나의 원인으로 해석할 수 없다.

**이번 단일 목표: POC6-21의 저장된 예측과 장부에서 ‘점수 자체가 실제 이후 가격변화를 구분했는가’와 ‘그 점수가 채택된 운용에서 어떻게 쓰였는가’를 나눠 확인하고, 다음 연구를 열 근거가 있는지 한 번 판단한다.**

새로 배울 것은 예측의 분별력 부족과 운용 연결의 제약을 어디까지 구분할 수 있는지다. 다음 모델을 만들기 위한 근거가 없다는 결론도 정상 종료다. 손실의 인과 원인을 반드시 확정하겠다는 목표가 아니다.

## 2. 읽을 자료와 경계

- 주 입력은 POC6-21 잠금 `20261104T112900Z_7220c733`, 실행 `20261104T112909Z_1fed7d17`의 protocol·저장 feature/절대 정답·예측·일정·검토·거래/평가 장부·보고다. PC 연구 사본만 읽는다.
- 실행 코드 판은 `991b2500`에 보존된 해당 연구 코드와 잠금의 직접 의존 관계로 식별한다. 새 포맷을 추측하지 말고 PLAN에서 실제 필드만 확인한다.
- 기존 POC6-20·21 결과와 판정은 배경 설명에만 사용한다. POC6-20 모델을 복원하거나 두 실험의 행·장부를 합쳐 재평가하지 않는다.
- 범위는 POC6-21 주 평가 2021-01-04~2026-09-21의 20bp R0/R1/M0/M1/K다. 40bp 결론은 기존 보고를 인용하고 별도 분석을 늘리지 않는다. 전체와 기존 보조 3구간 이외의 유리한 기간을 새로 고르지 않는다.
- 새 API·운영 DB·OCI·개인 보유/실거래·총수익 원천·새 날짜는 연결하지 않는다. 자료 끝일·사후 조정·가용 시각 가정·이미 본 기간·수급 사본 PARTIAL 한계는 유지한다.

## 3. 이번에 확인할 세 부분

### 3-1. 점수 자체 — 거래된 종목만 골라 보지 않음

같은 신호일·ETF의 저장 M 예측과 기존 정의의 R 점수를, 성숙한 저장 절대 정답 y_abs와 연결한다. 분석 모집단은 원래 공통 조건·당시 자격을 충족한 행이며, 그중 원래 RET_120 상위 5 후보도 별도로 표시한다. 두 점수·정답이 함께 있는 공통 행과 제외 사유를 공개한다.

M은 저장 예측만 사용한다. R 점수가 별도 저장되지 않았으면 저장된 RET_60에서 원래 식 log1p로 복원하는 산술만 허용한다. 모델 fit·새 predict 호출·새 feature/정답 생성은 없다. 미성숙 정답을 0으로 채우거나 유효 행만 당겨 기간을 바꾸지 않는다.

점수 구간은 원래 의사결정 경계 h=log(1.002/0.998)·2h만 사용한다: q≤−2h / −2h<q≤−h / −h<q<h / h≤q<2h / q≥2h. 분위수나 구간 경계를 결과를 보고 고르지 않는다.

각 구간의 행 수·서로 다른 날짜 수·평균 점수·실제 y_abs 평균·양수 비율과, 전체 MAE(|q−y_abs|의 평균·로그 변화 단위) 및 양수/비양수 부호 일치율을 R/M에 같은 정의로 보고한다. q>0과 y_abs>0 여부가 같은 경우를 일치로 세며 0은 비양수다. 평균·비율은 날짜 안에서 먼저 집계한 뒤 날짜를 같은 비중으로 요약한다. 행이 많은 날짜나 같은 시장 정보를 ETF 수만큼 독립 표본으로 부풀리지 않는다. 빈 구간은 자료 없음으로 표시한다. 이는 사후 설명이며 새 합격선·확률 교정·모델 채택 판정이 아니다.

### 3-2. 운용 경로 — 실제로 일어난 기록만 집계

기본 운용 연결은 강화 효과가 섞이지 않는 M0/R0의 기록부터 보고, M1/R1은 이미 관측된 최근 전환 효과와 연결해 설명한다. 곡선별로 다음을 확인한다.

- 주간 후보 → 문턱 검토 → 편입 의도 → 실제 체결까지의 건수·날짜/사유. 한도·현금·미체결·입력 공백·비적격 보류를 구분한다.
- 완료 거래의 보유기간·통상/단기/보호 이탈별 손익·비용과 열린 마지막 보유 평가. 저장된 비용 포함 손익에서 비용을 다시 빼지 않는다. 손익 합과 원래 장부 단위를 맞춘다.
- 현금 비중과 같은 기간 K의 움직임, 진입/이탈 시각을 함께 표시한다. 이 동시 관측을 ‘그 현금을 K에 넣었다면 벌었을 확정 수익’이나 단일 원인의 효과로 바꾸어 부르지 않는다.

CAGR 차이를 개별 거래 손익의 단순 합으로 정확히 분해했다고 주장하지 않는다. 새로 ‘계속 보유/조기 이탈/재진입했을 경우’의 장부를 만들지 않는다.

### 3-3. Q4 보류의 실질적인 범위

원래 보고된 R 126/289주·M 117/289주를 출발점으로 삼고, 저장된 기록에서 보류 종목·기간·당시 보유 비중과 통상/보호 처리가 이어진 경로를 정리한다. 주 비율·종목·주·종목·일·보유 금액 비중을 혼동하지 않는다.

이 기간의 실제 보유 손익이 어느 시점에 발생했는지는 장부에서 기술할 수 있다. **보류 때문에 생긴 손익 크기**는 대체 행동을 실행하지 않은 이번 진단으로 확정할 수 없다. 원래 점수가 산출되지 않은 비적격 보유에 새 점수를 만들거나, 강제청산으로 바꾸어 결과를 비교하지 않는다.

## 4. 결론 형식과 끝낼 경계

결과는 아래를 구분해 작성한다.

1. 저장 자료로 확인한 예측 분별력·운용 경로의 사실.
2. 그 사실과 일치하는 설명 또는 가설. 관측과 추정을 구분한다.
3. 저장 자료만으로 분리할 수 없는 원인과 빠진 필드.
4. 후속 가설을 검토할 구체적인 새 근거가 있는지. 없으면 추가 모델 연구를 보류한다고 명시한다.

이번 단계에서는 다음 모델·목표·임계·보유기간·Q4 대체 규칙을 정하지 않는다. 분석 중 유리한 조합을 찾았다는 이유로 새 전략을 시험하지 않는다. 진단이 끝나면 이 작업을 닫고, 실제 다음 가설의 필요성은 설계자가 별도로 판단한다.

POC6-21의 PASS/CLOSED·공식 결론은 바뀌지 않는다. 운영 모델 미승격·Q6 OPEN·#3/#55/#57/#62 및 총수익 미완료 상태도 유지한다. 사용자 목적은 비용 후 KODEX200 대비 성과와 현실적인 추세 참여이며, 설명 보고서가 생겼다는 이유로 그 목적을 달성했다고 하지 않는다.

## 5. 변경 범위·AC

제품 코드·새 패키지·CLI·새 잠금/검증 플랫폼·설치는 없다. 필요하면 PC의 일회성 분석 파일로 집계하고, 결과는 새 `state/ml/research/poc6_22/`에 보존한다. 기존 21 폴더·모델·공식 보고·장부에는 쓰지 않는다. 분석 파일을 상시 연구 서비스로 확장하지 않는다.

완료 기준:

- 입력 실행/파일과 원래 필드, 공통 행·날짜·제외·정답 성숙 기준이 확인된다.
- 고정 점수 구간·같은 날짜 가중치·기존 3구간과 실제 운용 경로로 한 번만 분석한다.
- 거래·비용·평가 단위가 기존 장부와 연결되고, 원래 검증 완료 여부를 다시 심사하지 않는다.
- 관측·가설·원인 미확정을 구분한 결과와 다음 연구의 근거 유무를 제시한다. 필요한 필드가 없으면 그 부분은 확인 불가로 종료하고 새 수집을 자동으로 열지 않는다.
- 검증자는 새 집계의 정의·대표 표본/합계 연결을 확인한다. 기존 70시험·공식 verify·전체 회귀를 반복하지 않는다.

분석은 한 묶음·최대 30분·RSS 8GiB·CPU 4스레드 안에서 수행한다. 새 학습은 0회, 전략 재실행은 0회다. 자료 부족·예산 초과도 원래 파일을 보존하고 확인된 범위로 보고한다.

## 6. 다음 행동

짧은 PLAN에는 지정 사본의 필요한 필드 존재 여부·직접 읽기 경로·기존 집계 재사용·없는 항목·일회성 분석/출력 범위·필요 승인만 적는다. 이미 읽은 결과서·전체 저장소·외부 방법을 다시 조사하지 않는다. 정확한 JSON 키·helper 위치는 개발자가 정한다.

설계자 PLAN 판정 뒤 부족한 승인만 한 번 정리해 분석·검증·RESULT로 끝낸다. POC6-21의 커밋 승인 ③을 새 분석 실행/커밋의 승인으로 자동 확대하지 않는다. 새 역할이나 단계별 별도 검토를 추가하지 않는다.

기존 05·06·13·17의 수집/보관·전향 기록과 실제 주간 판단 기록은 기존 계약대로 유지한다. 운영을 멈추거나 자체 수집 몇 년을 기다려야만 이 진단을 할 수 있다고 설명하지 않는다.
