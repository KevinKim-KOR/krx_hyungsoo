# POC6-10 DESIGN V1 — 외부 참고 주간 추세 기준선 검증

작성: 설계자 · 2026-10-25 · 독자: 개발자

**목적: 친구 프로젝트의 선정·보유·현금 연결 구조를 참고한 고정 규칙 하나를, 기존 자료와 백테스트 엔진으로 검증한다. 향후 ML이 개선할 투자 판단의 기준선을 정하는 연구이며, 새 ML 학습이나 운영 매매 지시를 만들지 않는다.**

**가격의 의미: 이번 성과는 KRX 기준가 중립 합성 가격지수의 변화다. 실제 원화 계좌 수익·분배금 포함 총수익·친구 모의투자 성과의 재현이 아니다. 이 한정은 준비·공식 보고·설계자 판정에 계속 표시한다.**

## 1. 준비 보고 수용과 네 가지 결정

## 2. 외부 참고와 기존 연구의 관계

참고 판은 `jasonisdoing/momentum-etf`의 `b23d1df9aaf8bace73dc01922210819c4d7b09f1`이다. 장기 MA 이격으로 순위, 장기/단기 추세로 자격, 주간 교체·주중 이탈·빈 슬롯 현금이라는 구조를 참고한다. 기간·대상·비용·실제 DB 설정까지 복제한 전략은 아니다. **‘외부 참고 개정 기준선’**으로 표기한다.

POC4-03 MOM은 월간·20일 변화·다음 종가·상위 10% 전액 투자였다. 이번은 주간·EMA 이격·다음 합성 시가·5슬롯·현금/이탈을 묶은 다른 운용 규칙이다. 묶음 전체의 효용을 비교하며 어느 한 요소의 인과 효과를 주장하지 않는다. 과거 MOM/RF·POC6-02/04/08/09의 판정은 그대로 보존한다.

이 단계는 최근 D20 오차 연구에서 **ETF 선정·보유 규칙의 가격지수 성과**로 평가 대상을 바꾼다. 원래 투자 판단 지원 목적에 연결하되, 이것만으로 실제 매매 유효성·무릎/어깨·종합 위험 분류를 완성했다고 쓰지 않는다.

## 3. 고정 입력·종목·시각

- 가격·원응답·member·거래일·벤치마크는 봉인 KRX만 사용한다. 기존 봉인/hash/member 계약과 `mode=ro&immutable=1`을 유지한다. 새 수집·운영 DB 읽기/쓰기·OCI 작업은 없다.
- 범위는 **POC6-06의 고정 보유 독립 24종 목록**으로 시작한다. 목록의 ticker·참조·전체 해시만 읽으며 FDR 가격은 사용하지 않는다. 개인 보유·계좌·평단·seed는 읽지 않는다.
- 이 목록에서 POC4와 같은 이름 꼬리표의 인버스·레버리지·합성·선물 제외 규칙을 적용한다. 해당 날짜의 봉인 member/이름을 사용하고, 7개 ML feature 완전 조건은 가져오지 않는다. 분류 자료가 불명확하면 대체 분류하지 말고 PLAN 질문으로 올린다.
- 채권·현금 관련 5종을 D20 보조 분석처럼 일괄 제외하지 않는다. 이번은 ETF 운용 규칙의 범위이므로 사전 이름 필터만 적용한다. 08 적격 21종이나 결과가 좋았던 종목으로 다시 고르지 않는다.
- 24종 자체는 2026년에 선정한 현재 표본이다. 과거 날짜의 member 확인을 해도 이 선택 편향이 없어지지 않는다. **시장 전체 PIT 전략 성과·처음 본 시험이 아니라 고정 표본의 회고 탐색**이다.
- 시장 날짜 축은 같은 판의 069500 자료와 기존 거래일 검사로 정한다. 달력 공백을 가격 이월로 메우지 않는다. 24종 각각의 상장 전·자료 공백·무거래를 구분한다.

**시작일:** 종목별 §4 EMA 준비 조건을 충족한 데이터 자격 종목이 5개 이상이고 069500 자료도 유효한 첫 완결 주의 마지막 거래일을 첫 신호일 D0로 한다. 추세가 양수인 종목 수나 이후 수익을 보고 고르지 않는다. 실제 평가 시작은 그 다음 거래일 시가, 끝은 2026-09-21 종가다. 신호일·체결일을 PLAN에서 개수/자료 자격만으로 고정한다.

평가 날짜를 오래된 순서로 세 구간으로 나누며, 앞의 두 구간은 floor(N/3)개, 나머지는 마지막 구간으로 둔다. 전체 756거래일 이상·구간별 252거래일 이상이 아니면 DATA_SHORT다. 날짜 여섯 개는 성과 계산 전에 고정한다. 학습/시험 분할이라고 부르지 않으며 포트폴리오를 구간 경계마다 초기화하지 않는다.

## 4. 가격 연결과 신호 — 정의 고정

### 4-1. 합성 OHLC의 의미

원 공표 종가 C_t, 부호 있는 전일대비 금액 Δ_t, B_t=C_t−Δ_t, 원 공표 시가 O_t를 사용한다. B_t는 이 연구가 역산한 비교 기준가이며 NAV가 아니다. 기존 `KRX_BASEPRICE_CHAIN`의 유효성 검사·연결 종가 지수 I_t를 재사용한다.

유효 연결에서 다음을 사용한다.

- I_t / I_prev = C_t / B_t.
- 합성 시가 O*_t = I_t × (O_t/C_t) = I_prev × (O_t/B_t).
- 고가·저가도 같은 날의 I_t/C_t 배율을 적용하며 합성 종가는 I_t다.
- 지수 스케일은 종목별 첫 유효 구간을 100으로 바꾸는 상수 정규화만 허용한다. 이후 가격이나 성과에 맞춰 바꾸지 않는다.

핵심은 같은 날 OHLC에 같은 배율을 적용하는 것이다. **정상적인 B_t≠C_prev와 관계식 실패·결측에 의한 구간 분리는 다르다.** 기준가 조정만으로 손상이라고 단정하지 않는다. 기존 reader가 실제로 무엇을 끊는지는 PLAN에서 해당 조건 한 곳을 대조한다. 기존 reader·과거 연구를 임의 수정하지 않는다.

합성 시가/종가 = 원시 시가/종가 관계와, 유효한 전일 지수에서 합성 시가로의 O_t/B_t 관계를 fixture와 준비 결과에서 확인한다. 이는 **연구 지수 구성의 정합성**이며 공식 수정시가 검증이 아니다. 현금 분배나 분할 수량을 B_t 차이로 추정해 계좌에 넣지 않는다.

예를 들어 가상 C_prev=100, B_t=98, O_t=98, C_t=99이면 이전 지수 100에서 합성 시가는 100, 합성 종가는 약 101.020408이다. 현금 2를 받았다고 가정한 실제 계좌의 101과 같은 계산이 아니다. 이 차이를 숨겨 ‘배당 포함 수익’으로 보고하지 않는다.

### 4-2. 준비·공백·무거래

- 종목별 연결 구간에서 유효 종가 지수가 180개 이상일 때 지표 데이터 자격을 준다. EMA는 구간 첫 지수를 초기값으로 하고 adjust=False, alpha=2/(기간+1)로 전체 과거 구간을 순차 계산한다. 마지막 20/60개만 잘라 재시작하지 않는다.
- 유효 종가가 공표된 거래량 0 날짜는 가격 표시/EMA에 사용할 수 있지만 체결 가능으로 보지 않는다. 없는 날짜의 종가를 새로 채우지는 않는다.
- 미보유 종목의 해석 불가 연결은 새 구간·준비도 재시작으로 기록한다. 이미 보유한 종목이나 069500에서 평가 가격 연결이 불가능하면 해당 손익을 추정하지 않고 CHECK_REQUIRED로 둔다. 유리한 종목·날짜만 빼서 전체 성과를 이어가지 않는다.

### 4-3. 후보 규칙 A — 고정 한 개

- EMA20·EMA60을 쓴다. 자격 = 종가 지수 > EMA60 AND 종가 지수 ≥ EMA20이며, 신호일에 원시 거래량 > 0이어야 한다.
- 순위 = 종가 지수/EMA60−1이 높은 순. 반올림하지 않는다. 정확 동점은 ticker 오름차순으로 정하고 사후 변경하지 않는다.
- 주 마지막 거래일 종가에서 상위 5개를 선택한다. 빈 슬롯은 현금이다. 슬롯 목표는 전체 자산의 1/5이며 임의로 남은 종목에 재분배하지 않는다.
- 주는 월요일~일요일이다. 봉인 시장 축의 다음 거래일이 다음 주에 속하는 D만 주간 신호일로 확정한다. 자료 끝의 불완전 주를 마지막 저장일이라는 이유로 완결 주처럼 다루지 않는다.
- 매일 종가에서 기존 보유의 자격을 확인한다. 종가 ≤ EMA60 또는 종가 < EMA20이면 다음 거래일 시가 이탈 대상으로 기록한다. 주중 신규 편입·빈 슬롯 채우기는 다음 주간 교체까지 하지 않는다.
- 주간 교체와 이탈이 같은 체결일이면 한 목표로 합쳐 중복 주문하지 않는다. 기존 미체결 이탈은 우선 처리한다.
- 별도 손절폭·익절·ADR·신고가·수급/환율/유가·ML 점수는 추가하지 않는다.

## 5. 체결·현금·비용과 엔진

### 5-1. 공통 실행 계약

이번은 합성 가격지수의 **소수 지수 단위**를 보유하는 연구다. 원화 자본·실제 ETF 정수 주수·개인 자산 규모는 사용하지 않는다. 시작 자산은 지수 100, 차입·공매도·이자는 없다. 기존 보유도 주간 교체 때 목표 비중으로 조정하고 실제 거래한 금액에만 비용을 부과한다.

- 신호 D 종가로 대상·순위를 고정한다. D 다음 거래일의 합성 시가만 체결 가격으로 쓴다. D+1 종가/고저/수익을 선정에 사용하지 않는다.
- 체결일 시가를 사용하는 것은 주문 수량·현금 예산 계산뿐이다. 이 용도와 신호 계산의 시각을 분리해 기록한다.
- 체결은 원시 거래량 > 0 AND 원시 시가 유한 양수 AND 같은 날 가격 관계 유효일 때만 가능하다. 일봉 거래량은 사후 체결 가능성의 근사일 뿐 시초가 유동성을 증명하지 않는다. 양수 거래량의 참여율·시장 충격은 이번에 모델링하지 않는다.
- **매수 불가:** 그 매수는 취소하고 슬롯은 현금으로 둔다. 다음 순위 종목 대체나 다음 날 자동 매수를 하지 않는다.
- **매도 불가:** 기존 보유와 위험을 유지하고, 첫 체결 가능 거래일 시가까지 이연한다. 이미 판 것으로 처리하지 않는다. 미체결 보유가 슬롯을 차지하며 총 보유 수를 5개 초과로 늘리지 않는다.
- 이연 매도는 추세 회복만으로 취소하지 않는다. 이연 매도 체결일에는 같은 종목을 다시 사지 않고 빈 슬롯을 다음 주간 선정까지 현금으로 둔다.
- 같은 날 매도→유지 종목 조정→매수 순서다. 거래 가능한 매도의 실제 모델 체결 대금을 반영한 후 매수 예산을 정한다. 비용 포함 현금이 부족하면 매수 계획 금액을 동일 비율로 줄이고 목표/실제 비중 차이를 기록한다. 현금을 음수로 만들어 목표 비중을 맞추지 않는다.
- 거래 불가 보유의 개장 시점 예산 평가는 직전 유효 종가 지수를 장부값으로 유지할 수 있다. 이 값은 **valuation_only**이며 체결가로 쓰지 않는다. 종료 시에도 미체결·잔존 보유·평가와 실현을 구분한다.
- 마지막 날은 종가 평가로 끝내며 임의 강제 청산/마지막 거래일 변경을 하지 않는다. 시가 공백을 `asof`의 직전 유효 값으로 체결하는 방식은 금지한다.

### 5-2. 비용

기본 통합 비용은 **편도 11.5bp**, 보조 비용은 **편도 25bp**로 고정한다. 기존 프로젝트의 연구 가정을 재사용한 것이며 실제 증권사 비용·세금 안내가 아니다. 매수와 매도 각각의 실제 지수 거래 금액에 부과한다. 슬리피지를 별도 가격 조정으로 다시 더하지 않는다. 현금 이자·분배금·세금·환율은 따로 추정하지 않는다.

두 비용은 같은 고정 실험 묶음이다. 비용 결과를 보고 다른 값을 찾지 않는다.

### 5-3. 엔진 재사용

**Backtrader를 연구용 엔진의 우선 적용안**으로 둔다. 선정 규칙·KRX 가격 어댑터·체결 가능 검사·보고만 얇게 연결하고 별도 broker/주문·현금 엔진을 새로 만들지 않는다. Qlib 전체 도입이나 서버 이전은 하지 않는다.

PLAN에서 설치 여부·고정할 판·Python 호환성·연구 전용 의존성 위치와 적용 가능성을 확인한다. Backtrader의 GPL-3.0, 참고 친구 코드의 MIT 표시·사용 범위를 명시한다. 실제 코드 복사 시 고지를 보존한다. 설치/배포 관련 현행 프로젝트 규칙을 확인하고 유효한 기존 승인을 재요청하지 않는다. PLAN 단계에서는 새 설치를 하지 않는다.

Backtrader는 기본적으로 거래량을 무시하므로 기본 체결 동작을 그대로 승인하지 않는다. filler/주문 수명/콜백으로 §5-1을 구현할 수 있는지 PLAN에 적는다. 소수 지수 단위에 원시 거래량을 주수 한도로 적용하지 말고 0 여부만 체결 불가 조건으로 쓴다. 개장 콜백을 쓴다면 이전 종가에서 고정한 신호와 현재 시가의 예산 산정만 허용한다.

설치·라이선스·입력 동기화·주문 정책을 이 범위에서 맞출 수 없으면 PLAN 질문으로 올린다. 임의 대체 엔진·엔진 자체 수정·전체 시스템 이식으로 넓히지 않는다. 판정 전 실제 전략 실행이나 친구 프로젝트의 DB·브로커·발송 모듈 import를 하지 않는다.

## 6. 비교 기준·보고·사전 해석

같은 날짜·범위·합성 가격·현금·체결 검사·비용 모델에서 아래 세 곡선만 비교한다.

| 곡선 | 규칙 |
|---|---|
| A: REF_EMA20_60 | §4-3의 고정 추세 선정·주중 이탈 |
| B: MOM20_WEEKLY | 같은 180행 데이터 자격·신호일 거래량 조건에서 20거래일 지수 변화가 높은 상위 5개, 주간 교체. 추세 자격·주중 이탈 없음. 빈 슬롯 현금 |
| M: KODEX200_HOLD | 같은 최초 체결일에 069500 전액 목표(5슬롯 배분의 예외)로 비용 반영해 보유하고 마지막 종가 평가 |

B는 POC4 공식 MOM을 다시 실행한 결과가 아니다. 이번 체결·슬롯·가격 조건에 맞춘 비교 기준이다. 연속 보유 가치·비용·주문을 기록하고 세 평가 구간에서 초기화하지 않는다.

전체 및 세 구간의 가격지수 변화율·연환산 변화율(CAGR)·최대낙폭(MDD), 현금 비중, 회전율·매매 건수·거래 비용, 이연/취소·실제 보유 비중·시장 노출을 공개한다. CAGR은 실제 경과 달력일로 연환산한다. 구간 비교는 직전 평가값(첫 구간은 최초 자산 100)을 기준값으로 포함한다. MDD는 그 구간 내 기준값부터 고점 대비 저점을 계산하며 단순 기준일 대비 최저 변화인 D20과 다르다.

기본 11.5bp에서 아래 두 사례를 **각각** 판단한다. 미래 ML/운용 승격 기준이 아니라 후속 검토 가치가 있는 가격지수 사례의 사전 정의다.

1. **PRICE_RETURN_CASE:** A의 전체 CAGR이 B·M 각각보다 1%p 이상 높고, MDD가 각각보다 2%p 초과 나쁘지 않으며, 구간 변화율도 2/3구간 이상에서 두 기준보다 높음.
2. **PRICE_DRAWDOWN_CASE:** A의 전체 MDD가 B·M 각각보다 5%p 이상 개선되고, CAGR 열위가 각각 2%p 이내이며, 구간 MDD도 2/3구간 이상에서 두 기준보다 개선됨.

MDD는 음수이며 예를 들어 −30%→−20%는 10%p 개선이다. 판정은 표시 반올림 전 값으로 한다. 두 사례의 참/거짓과 각 차이를 모두 남긴다. 어느 것도 아니면 NO_REFERENCE_CASE, 표본 미달이면 DATA_SHORT, 입력/평가 해석 불가면 CHECK_REQUIRED다. 보조 25bp에서도 같은 수치를 공개하되 통과할 비용으로 기준을 바꾸지 않는다. 기본 비용에서만 나타난 사례는 비용 민감성을 명시한다.

하나 이상 충족하면 연구 상태는 REFERENCE_CASE_OBSERVED로 두고 충족 사례 이름을 모두 남긴다. DATA_SHORT/CHECK_REQUIRED가 우선이면 사례 지위는 NOT_JUDGED로 두며 가능한 진단 수치는 보존한다. 실행 성공 여부와 이 연구 상태를 분리한다.

이 정의는 모든 지표가 다 좋아야 한다는 조건이 아니다. 수익 쪽 개선과 낙폭/기회비용의 교환을 미리 구분한 것이다. 1·2·5%p는 이번 설계 선택이며 보편적 투자 기준이 아니다. 합성 가격 정의·현재 고정 표본·회고 구간 때문에 어느 사례가 나와도 실제 계좌 수익이나 운영 채택을 확정하지 않는다.

## 7. 구현·검증·공식 실행을 한 범위로

PC 연구 패키지 `app/reference_trend/`와 CLI `scripts/run_reference_trend.py`를 두는 안으로 PLAN을 작성한다. 코드 책임·파일 수는 KS-10에 맞춰 제안한다. 기존 봉인 reader·과거 연구·운영 코드·UI/API/DB/cron/PUSH는 바꾸지 않는다.

새 `state/ml/research/poc6_10/<run_id>/`에 입력/코드/엔진 판·고정 설정·비교 정의·종목·날짜·분모를 둔 protocol, 가격 변환의 출처/배율·원시 무거래 표식, 신호·주문·체결/취소/미체결·일별 장부, report.md/json, run 상태를 저장한다. 임시 소스 경로만으로 재현 근거를 남기지 않는다. 결과는 PC_ONLY이고 새 OCI 업로드 형식은 만들지 않는다.

- PLAN PASS → 구현·격리 확인 → 원본 해시/계약·변환 관계·가격/날짜 준비 확인 → protocol 선행 저장 → **세 곡선×두 비용의 공식 묶음 1회** → 새 결과의 검산·검증 → 설계자 RESULT 순서다.
- 준비 확인에서 시가 체결·이탈 가능성·정상 기준가 조정과 연결 실패가 구분되지 않으면 성과를 먼저 계산하지 않는다. 새 실행 ID 뒤의 실패/중단은 기록하고 원래 오류를 보존한다. 실패나 낮은 성과 때문에 몰래 다른 자료·기간·설정으로 다시 돌리지 않는다.
- 꼭 필요한 fixture: 정상 OHLC, 가상 분할/분배 기준 변화, 원시/합성 시가 관계, 무거래 매수 취소·매도 이연, 이탈과 주간 교체 중복, 비용/현금 부족·5슬롯 상한, 결측/연결 실패, 상장 전·EMA 준비, 미래 고저/종가를 바꿔도 앞선 신호가 같음, 마지막 불완전 주·평가 종료.
- 검산은 정상/무거래를 포함한 작은 고정 주문 경로에서 날짜·잔고·비용을 손으로 계산한 값과 엔진 결과를 비교하고, 공식 저장 장부에서 곡선·지표·판정을 다시 계산한다. 별도 전체 broker 엔진을 또 구현하지 않는다.
- 회귀는 새 연구 경로·재사용 reader 접점에 맞춘다. 기존 실행 경로를 바꾸지 않는다면 이미 끝난 4,599건 전체 회귀·06 모델 실행을 반복할 필요는 없다. 검증자는 새 가격 변환·시각·회계·결과를 확인하며 과거 연구를 재검증하지 않는다.

모델 학습·GPU·최적 파라미터 탐색·목업·실화면·실계좌/모의계좌 연결은 없다. 가격 처리를 떼어 별도 POC/새 프레임워크 구축으로 만들지 않는다. 자료가 부족한 결과도 유효한 종료 결과로 보고한다.

## 8. PLAN에 필요한 확인 — 이미 조사한 범위 재사용

성과·EMA/순위·가상매매는 계산하지 말고 다음을 적는다. 표·근거를 재사용하고 저장소 전체 재조사를 하지 않는다.

1. 봉인 판·24종 목록·reader의 참조/전체 해시, 날짜·이름 필터 후 목록, 기존 관계식이 구간을 나누는 실제 조건. FDR 가격이나 새 원천은 추가하지 않음.
2. 180행 데이터 자격만으로 정한 D0/최초 체결일·끝일·세 구간·날짜/종목 수. 5개 미달·상장 전·연결 불가를 따로 셈. 추세 자격이나 이후 결과는 세지 않음.
3. raw OHLC·거래량과 기존 지수의 연결 접점, §4-1 변환·무거래 전달 방식, 과거 reader 무변경 여부.
4. Backtrader의 현재 환경/제안 판·연구 의존성·사용 고지, filler·개장 예산·소수 지수 단위·주문 이연의 적용 방식. 충돌은 질문으로 올림.
5. 재사용 코드와 신규 어댑터의 경계·KS-10·실행 비용/메모리 추정·격리 확인 및 검증 범위. 비용 추정만으로 실데이터 전략을 예비 실행하지 않음.
6. 기반 문서의 새 연구 한정 예외 필요 문장. 기존 05/06과 Q6 OPEN·운영 ML 미승격은 유지하고 예외는 PLAN 판정에서 확정.

새 외부 데이터 조회·KRX 로그인·계정/키·가격 보완 수집·라이브 저장은 없다. 설치나 원격 쓰기 승인이 현행 규칙상 필요하면 구체화한 PLAN 범위로 처리한다. 본 설계가 새 원격 쓰기 승인을 대신하지 않는다.

## 9. 완료와 다음 쓰임

완료는 가격지수/체결 의미를 드러낸 고정 규칙의 구현·한 번 계산·검산·검증·설계자 판정이다. 사례 미관측을 코드 실패로 보지 않는다. 실제 report.md/json을 RESULT와 함께 제출한다.

참고 구조의 가격지수 효용이 보이면 실제 운용과의 차이(총수익·정수 주수·가용 시각·표본 선택·체결)를 먼저 판단한다. 이 결과만으로 UI 매매 문구나 새 ML·운영 승격을 자동 추가하지 않는다. 효용이 없으면 이 고정 구조의 연구를 종료하며 EMA 기간·필터·모델을 바꿔 합격을 찾는 후속을 자동으로 열지 않는다.

05의 보관·06의 기존 전향 기록과 월별 학습은 계속한다. Q6 OPEN·#3/#55/#57/#62 미완료를 유지한다. 같은 POC6의 별도 handoff는 없다. 사용자 승인 범위 커밋·push는 RESULT 판정 뒤 기존 절차를 따른다.
