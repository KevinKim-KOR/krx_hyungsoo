# POC6-35 장중 재진입 알림 누락 정정 · PLAN 판정

2026-11-19 · **보완 후 구현 승인** · 대상은 개발 PLAN V1, 기준 main `631b14a9`다.

대기를 충족해 발송 후보가 된 같은 상태 재진입은 다음 회차에도 현행 조건으로 평가한다. 개발자가 확인한 구역 한도, 전송 실패·부분 전송, 보유 급등 사례는 같은 원인과 직접 경로를 공유한다. OPS-02의 성공 전달 기준을 적용하는 **A1을 채택**한다. 제출된 재현은 실제 조립·저장 함수를 사용했고, 전체 실행 경로의 확인은 구현 시험에서 한다.

## PLAN에 반영할 보완

1. **Q3 · 성공 전달 우선.** 최종 본문에 실제 포함됐고 전체 전송까지 성공한 항목에 성공 근거를 적용한다. 첫 상태 저장이 실패해도 후속 상태 저장이 가능하면 그 저장에서 성공 사실을 보존해 같은 재진입이 다시 후보가 되는 일을 막는다. 성공 기준 시각과 일일 발송 건수는 같은 회차를 한 번만 반영한다. 첫 저장만 실패하는 경우를 포함해 두 저장 경로를 검증한다. 발송 전 차단·전송 실패·부분 전송에는 기존의 성공 판정과 재시도 규칙을 적용한다. 두 저장 경로가 모두 실패하는 경우는 일반 상태 저장 장애로 기록한다.
2. **Q5 · 다음 회차의 대기 판정.** 다음 정상 평가에는 그 회차의 활성 정책과 마지막 성공 전달 시각을 사용한다. 정책이 바뀌어 그 회차에 재발송 대기를 충족하지 못하면 K3의 지속 억제로 전환한다. 평가 자료 부족으로 해당 신호를 판정하지 못한 회차에는 대기 상태를 유지한다. 기존 K3 재현과 정책 변경 경계를 시험에서 확인한다.
3. **Q10 · 운영 근거.** 같은 날 다음 정규 회차에서 같은 대상·상태가 억제된 패턴은 **K2 의심 건**을 찾는 질의로 사용한다. 원장의 `sent` 처분은 본문 포함을 뜻하므로 실제 전송은 같은 `event_id`의 `delivery`로 확인한다. 당시 평가 결과·정책·한도 조건으로 누락 원인을 확인한 사례에 한해 K2로 판정한다. OCI revision 확인은 반영 증거로 기록한다. 운영은 반영 후 첫 정규 장중 회차의 처리 결과와 원장·PC 사본 대조로 확인한다. 자연 발송 건이 있을 때 같은 메시지의 사용자 수신을 확인하고, 그 회차에 발송이 없으면 수신 대조 대상 없음으로 기록한다. 실제 K2 발생 유무와 고정 사례 검증 결과를 구분한다.

## 진행

세 보완을 PLAN과 관련 시험·운영 확인 항목에 반영한 뒤 POC6-35 구현을 시작할 수 있다. 이 보완의 수용 범위를 충족하면 추가 PLAN 판정 없이 진행한다. A1의 직접 경로에서 성공 전달 근거를 전달하기 어려워 상태 저장 계약 변경이 필요해지면 해당 지점을 설계자에게 먼저 돌려준다.

[원장 새로고침]은 형수님 실행을 기다리는 중이다. 실행 전후 사본 시각과 OCI 최신 기록 대조 결과를 PLAN §0에 덧붙인다. 이 운영 확인은 구현과 병행한다.

근거는 개발 PLAN V1 §0~§4·§6·§7, POC6-35 설계 V1의 AC1~AC3, POC6-34 RESULT 판정의 K2·K3, PROGRAM_TRUTH의 POC3-02D-OPS-02 전달 상태 계약 및 POC5 원장 처분 정의다.
