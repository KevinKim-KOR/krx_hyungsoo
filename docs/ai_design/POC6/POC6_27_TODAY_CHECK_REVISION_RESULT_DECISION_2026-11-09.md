## 3. 실사용 반영 전 마감 사항

1. **저점 문장은 비교 날짜를 직접 적는다.** 결과서 §5의 `d1.from_date`는 직전 저장 종가일이다. 최신 종가가 있어도 중간 거래일 종가가 비어 있으면 실제 직전 거래일과 다를 수 있다. 비교 날짜를 확인할 수 있으면 ‘11/5의 최근 저점 5,383.80을 밑돌았습니다’처럼 쓴다. ‘직전 거래일’은 실제 거래일의 인접성이 확인될 때만 사용한다. 같은 자료를 ‘전일 대비’로 부르는 표시도 같은 기준을 적용한다. 새 달력 조회는 필요 없다. 중간 거래일의 저장 종가가 없는 사례로 비교 날짜 문구만 확인한다.
2. **[보유 현황 보기] 경로를 확인한다.** 기준서 §4와 PLAN 판정 뒤 전달한 링크 보완에 따른다. 결과서 §9의 화면 설명으로는 이 경로의 동작을 확인할 수 없다. 구현에 있으면 버튼 위치와 「보유 현황」으로 이동한 결과를 한 줄 기록한다. 빠졌으면 아래 「보유 자세히」에 기존 링크를 연결해 「보유 현황」의 자금 기준까지 갈 수 있게 한다. 보유 금액과 자금 자료는 그 화면에서 읽는다.
3. **OCI 예약 문구는 기동 확인값에 맞춘다.** 격리 서버의 예약 3건은 모두 ‘확인 불가’였다. 결과서 §5의 ‘재기동 뒤 3/3 확인’은 예시로 정정하고, 실제 PC 기동 뒤 받은 상태와 확인 시각을 기록한다. 원장 사본의 기록일과 동기화일은 별도로 읽는다. `crontab` 주석 줄을 셀 수 있는 기존 예약 판독 한계는 남는다. 활성 예약과 주석을 구분해야 하는 운영 작업에서 그 판독을 별도 정리한다.

제품 변경이 생긴 항목은 변경된 문구와 이동 경로만 검증자가 확인한다. r2의 응답 순서·날짜 재현과 전체 회귀는 기존 결과를 사용한다. 격리 화면 배치는 형수님의 기존 확인을 근거로 쓴다.

## 4. 기록과 승인 순서

1. 개발자는 이 판정 원문을 `docs/ai_design/POC6/`에 보관하고, 결과서의 r1·r2 기록 뒤에 설계 판정과 마감 근거를 추가한다. `STATE_LATEST`에 **r2 VERIFIED · 설계자 RESULT PASS_WITH_CLOSING_CORRECTIONS · 실사용 반영 대기**를 기록한다. `PROGRAM_TRUTH`의 화면 동작과 두 정책 선택은 실제 적용 상태와 구분해 적는다. 양쪽 stage 목록은 보완 뒤 다시 기록한다.
2. 마감 근거가 정리되면 **검증된 변경의 본 저장소 반영과 PC 서버 재기동**에 대해 형수님 승인을 받는다. 파일을 옮기는 동안 자동 재기동이 반복되지 않게 하고, 정해진 한 번의 백엔드 기동에서 기존 OCI 예약 읽기를 한다. 실제 화면에서 차트·두 카드와 자금 기준 이동을 확인하고, 예약과 과거 발송 기록이 각각 어떻게 표시됐는지 남긴다.
3. 실사용 확인을 보고하고 **커밋·push는 별도 사용자 승인**으로 진행한다. 사용자 handoff와 개인 자료는 제출 대상에서 제외한다. 실제 PC 반영, 실화면 확인, 승인된 커밋·push 결과를 기록한 뒤 `IMPLEMENTED_VERIFIED_CLOSED`로 정리한다.
