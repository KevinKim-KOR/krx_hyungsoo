## 1. Q11 · 보유와 후보를 언제 비교하는가

**(d) 채택.** 주간 화면의 ③은 **「선택한 후보 검토」**다. 후보를 고르면 후보 자체의 근거와 내 보유 전체의 확인된 노출을 표시한다. 기본값으로 보유 비중 1위와 후보 순위 1위를 짝짓던 동작은 이 흐름에서 제거한다.

- **보유에 더할 후보를 볼 때**는 전체 보유를 기준으로 겹침을 읽는다. 보유 ETF 한 종목을 고르는 단계는 필요 없다. 보유 종목이 없거나 구성 자료가 부족해도 후보 자체의 근거는 읽을 수 있다.
- **보유를 대체할 상품을 볼 때**는 [비교 상세]에서 두 상품을 명시적으로 고른다. 다른 화면에서 고른 ETF가 있으면 그 한쪽만 채운다. 먼저 확인된 공식 기초지수와 투자 대상·상품 구조를 보여 준다. 기간 시작·종료일과 가격 상태가 맞고 같은 공식 지수가 확인된 경우에만 수익률 차이 요약을 표시한다. 상품 구조 차이는 확인된 값으로 붙인다. 지수가 다르거나 확인되지 않으면 그 상태와 각 ETF 수치를 보여 준다.
- 개발자 실측의 24.19%p는 −13.06%와 +11.13%의 1개월 성과 차이다. 그 숫자로 읽을 수 있는 범위는 해당 기간의 가격 성과까지다. 두 상품이 같은 투자 목적에 맞는지는 기초지수와 투자 대상을 보고 확인한다.

## 2. Q12 · 후보만 고르고도 검토할 수 있게 한다

**(c) 채택. 후보 단독 근거 요약을 주간 화면의 기본으로 둔다.** 현재 아무 후보에나 쓸 수 있는 것은 판단 근거 미리보기다. 개정본에서는 그 근거 중 먼저 읽을 항목을 기존 저장값으로 한 줄씩 내놓는다.

| 사용자가 볼 질문 | 표시할 근거 |
|---|---|
| 어떤 상품인가 | 확인된 공식 기초지수·투자 대상. 구성 자료가 있는 경우 주요 편입과 비중, 실제 구성 기준일. |
| 실제로 올랐나 | 1·3개월 수익률과 실제 기간으로 각 기간의 상승·하락을 읽는다. 날짜가 맞으면 KODEX 200 대비를 ‘같은 기간 국내시장 대비’로 붙여 실제 상승과 시장보다 덜 하락한 경우를 구별한다. |
| 지금 무엇을 더 확인해야 하나 | 비어 있거나 기준일이 다른 자료, 보유 겹침의 확인 범위를 표시한다. 필요할 때 [판단 근거 보기]에서 기존 이동평균 등 상세 근거를 읽고, [AI 투자 세션으로 넘기기]의 최신 자료 확인으로 이어 간다. |

시장 판정과 후보의 가격 관측은 각각 현재 근거에 맞는 이름으로 표시한다. 후보가 쓸 만한지에 대한 판단은 AI 설명을 참고해 사용자가 기록한다. 시스템에서 이번에 확정할 것은 후보의 가격 방향과 비교 가능 범위다. 가격·상품 자료가 충분한 행과 부족한 행을 구별한다.

## 3. ETF 구성종목은 무엇에 쓰는가

| 실제 질문 | 읽는 곳과 의미 |
|---|---|
| 이 ETF를 사면 사실상 어디에 집중되는가 | [구성종목 보기]에서 주요 편입과 합산 비중을 본다. 보고 사례에서는 주요 두 주식의 비중이 30.07%와 20.90%로 합계 50.97%다. ETF 이름보다 실제 집중 대상이 잘 보인다. |
| 후보 두 개를 같이 담으면 새로운 노출이 생기는가 | 목록 모드의 후보끼리 중복률을 본다. 서로 다른 이름의 후보에서 겹침이 크면 확인한 범위 안에서 비슷한 노출을 담고 있다는 뜻이다. 여러 지수에 공통 편입된 주식은 반복되는 노출을 보여 준다. |
| 이 후보가 담은 주식을 내가 이미 얼마나 갖고 있는가 | 주간 ③의 보유 전체 노출을 본다. 보고 사례의 0.16%는 한 편입 주식에 대해 보유 평가액에서 확인된 노출이다. 후보끼리의 중복률과 구별하고, 보유 구성의 미확인 범위를 같이 본다. |

개발자 실측에서 구성 자료는 1,210개 중 91개에 있었고 ETF당 최대 30행을 저장했다. 실제 표시에는 대상 ETF별 저장 행 수·구성 기준일과 전체 구성 확인 여부를 쓴다. 미수집·상위 행만 확인·전체 확인 상태를 구별한다. 주간 첫 화면에는 판단에 필요한 요약을, 전체 행과 후보 간 중복은 상세에 둔다.

## 4. Q1~Q10 판정

| 질문 | 판정과 반영 내용 |
|---|---|
| Q1 · 메뉴 | **(a) 수용.** 「오늘 확인」에서 「오늘의 투자 점검」 바로 아래에 형제 메뉴 「주간 ETF 점검」을 둔다. 구성종목과 두 상품 비교는 필요한 화면에서 여는 상세로 두고, 뒤로 돌아가면 보낸 화면의 선택과 조건을 복원한다. 주간 화면에 ‘후보’ 표현을 허용하고 기록 출처 `today_weekly_review`를 사용한다. |
| Q2 · 자료 갱신 링크 | **(b) 채택.** 앞 판정의 링크 위치 설명을 실측에 맞춰 정정한다. 「자료·연구 상태 › 자료 확인 › 자료 업데이트 목록」의 NAV 4개 이동은 「진단·상태 › 데이터 상태」로 연결한다. 「자료 최신화 필요」의 보유 구성 자료 작업은 기존 [최신 자료 갱신]을 실행한다. 구성종목 상세는 후보 검토 경로에서 연다. |
| Q3 · 기간 다름 | **(a) 채택.** ETF의 실제 기간·값과 ‘기간 다름’을 표시한다. KODEX 200 대비는 시작일·종료일과 가격 상태가 맞는 자료로 표시한다. |
| Q4 · 사용자 판단 | **(c) 보완 수용.** 새 주간 기록은 기존 판단 항목을 **‘미기록’**으로 시작하고 그 상태로도 저장할 수 있다. 사용자가 직접 고른 ‘보류’는 메모·다음 확인이 비어도 유효하다. 기존 기록은 원래 값을 보존하고 직접 선택 증거가 없으면 ‘사용자 판단 미확인’으로 표시한다. |
| Q5 · AI 확인 시각 | **(a) 채택.** 기존 AI 구분과 원문을 사용한다. AI가 적은 확인 시각·출처는 세션 저장 시각과 구별하고, 확인 시각이 비어 있으면 ‘확인 시각 미기재’로 표시한다. 한 AI 답변으로도 기록할 수 있다. |
| Q6 · 과거 자료 | **(a) 채택.** 이번 확인 대상은 실제 저장한 검토의 복원이다. 과거 자료는 확인된 기존 보관 경로에서 읽는다. 실측상 최신 한 건만 남는 빠른 시세와 덮어쓰는 수집 시각은 당시 검토 기록에 있었던 값만 복원 근거로 인정한다. |
| Q7 · 오늘 시세 | **(a) 채택.** 검토일의 저장 시세가 있을 때만 원천 시각·장중/마감과 함께 ‘오늘 시세 참고’에 표시한다. 미확보 상태는 자료 상태에 표시한다. |
| Q8 · 일일 시장 복사 | **(a) 채택.** 오늘 화면은 공통 시장 근거와 최신 확인 질문을 복사한다. 실제 후보 판단에 쓴 시장 근거와 AI가 추가로 확인한 값은 기존 주간 검토 기록에 보존한다. |
| Q9 · 후보리스트에서 전달 | **(a) 보완 수용.** 목록 전체를 넘기는 경로와 한 ETF를 여는 경로를 둔다. 상세 제목과 안내는 실제로 전달된 대상과 현재 표시 내용을 설명한다. 기존 목록 탭이 상위 10개 기본 조건으로 계산하는 경우 ‘1개월 상위 10개 기준’과 실제 기간을 명시한다. 주간 후보의 보유 겹침은 선택한 ETF의 근거를 쓴다. |
| Q10 · 수급 | **(a) 채택.** 60거래일 수급에는 외국인·개인·기관계와 함께 기존 저장 자료의 기타법인·내국인대우외국인을 각각 표시한다. 실제 날짜 구간과 집계 구분을 붙인다. 기관계 합계와 세부 항목이 중복 합산되지 않게 한다. |

## 5. 격리 화면 수용 기준

| AC | 확인할 결과 |
|---|---|
| AC1 · 검토 동선 | 주간에서 후보 하나를 선택해 투자 대상·실제 수익률·비교 범위·보유 겹침을 읽는다. 비슷한 보유가 없거나 구성 자료가 부족한 후보도 단독 근거로 검토한다. 상세에서 동일 지수·다른 지수·기준 미확인과 기간이 다른 사례를 구별한다. |
| AC2 · AI 최신 확인 | 일일·주간 복사에 같은 기준의 시장 근거와 최신 공개 자료 확인 질문이 들어간다. 저장값과 같음·새 값 또는 정정·확인 불가를 읽을 수 있고, AI가 보완한 값에는 기준일과 출처가 따른다. |
| AC3 · 기록 복원 | 실제 검토를 한 건 저장하고 갱신 뒤 다시 열어 선택 후보·기간·겹침과 미확인 범위·당시 근거·AI의 추가 확인을 복원한다. 새 기록의 판단 미기록과 직접 고른 보류를 구별한다. |
| AC4 · 사용자 확인 | 형수님이 격리 화면에서 후보 하나를 골라 ‘무엇을 담았는지’, ‘실제로 올랐는지’, ‘내 보유에 무엇이 겹치는지’를 읽고 다음 확인과 저장한 근거를 찾을 수 있다. |
