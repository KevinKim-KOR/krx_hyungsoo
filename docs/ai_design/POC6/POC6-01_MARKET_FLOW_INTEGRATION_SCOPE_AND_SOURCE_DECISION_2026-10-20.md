# POC6-01 시장 흐름 통합 — 범위 이관·자료원 판정
작성: 설계자 · 2026-10-20 · 독자: 개발자 / 사용자

**결정: 미구현 POC5-28을 별도 대단계 POC6 「시장 흐름 통합」의 첫 작업 POC6-01로 이관한다. 기존 설계·PLAN·승인은 이어 쓴다. 수급은 사용 중인 키움증권의 공식 REST API ka10051 한 경로로 좁힌다. 실제 API·앱키 사용은 사용자 승인 뒤다.**

## 1. 분리 이유와 상태
처음의 백로그 #48 자료원 보완에서 수급·환율·유가의 수집, 시계열 저장, 장단기 계산, 통합 화면·AI 근거까지 확장됐다. 기존 기능 보정과 다른 사용자 기능 묶음이므로 별도 대단계로 관리한다. 번호 변경을 이유로 기능이나 검토 절차를 더 늘리지 않는다.

| 구분 | 처리 |
|---|---|
| POC5 기존 완료 작업 | 완료 기록 유지. 남은 운영 점검은 기존 기록대로 별도 진행 |
| POC5-28 | TRANSFERRED_TO_POC6_01 — 설계·조사만 완료, 구현 완료로 기록하지 않음 |
| POC6-01 | 시장 수급·환율·유가를 일별로 모아 장기 흐름과 단기 큰 변화를 함께 읽는 기능 |
| ML 고도화 | 별도 주요 개발 목표로 유지. 새 자료를 ML 입력으로 자동 추가하거나 본 작업의 범위를 ML 학습까지 늘리지 않음 |

저장소 마스터에 POC6 번호가 이미 예약돼 있다면 그 예약은 보존하고 가용 대단계 번호만 조정한다. 재번호만으로 재판정을 요청하지 않는다. 설계자는 Mac 저장소의 전체 단계 예약표를 직접 확인한 것은 아니다.

## 2. 기존 작업을 이어 쓰는 방법
- 기준 문서: 기존 POC5-28 설계 개정 3, PLAN §8~§9-5, PLAN 판정 §7. 이 문서와 충돌하는 자료원·단계 표기는 본 판정을 우선한다.
- 원문 파일을 복사해 설계·PLAN 두 벌을 새로 작성하지 않는다. 기존 문서 머리에 새 작업 ID와 이관 사실을 적고 이어 쓴다. 지난 판정은 경과로 보존한다. 새 코드·결과서부터 새 ID를 쓴다.
- Yahoo 환율·WTI 조회, 같은 시장 DB 표 2개, GET /market/flow-context의 사용자 승인은 유효하다. 표본 확인과 계산 정의를 다시 조사하거나 재승인받지 않는다.
- KRX 회원 웹 자동조회는 중단 상태 유지. KIS는 사용자 계좌가 없어 기본 경로에서 제외한다. 토스·카카오페이·네이버·CSV를 병행 개발하지 않는다.
- STATE·BACKLOG #48에 이관 관계와 실제 미구현 범위를 한 번 반영한다. 다른 문서의 역사 기록까지 전면 재작성하지 않는다.

## 3. 키움 공식 자료에서 확인한 사실
공식 REST 가이드와 키움증권 공식 저장소의 예제를 설계자가 확인했다. 옛 OpenAPI+의 Windows 방식이나 제3자 블로그만으로 판단한 것이 아니다.

| 항목 | 공식 예제에서 확인한 내용 |
|---|---|
| 서비스 | 업종별투자자순매수요청 · ka10051 |
| 경로 | POST /api/dostk/sect |
| 요청 | mrkt_tp=0: 코스피 · amt_qty_tp=0: 금액 · base_dt: 기준일 |
| 거래소 | stex_tp=1: KRX · 2: NXT · 3: 통합 |
| 응답 | 업종 코드/이름, 개인·외국인·기관계 및 기타/세부 순매수 필드 |
| 이용 준비 | API 신청·앱키와 등록 IP 필요. 공식 안내상 허용 IP에서만 인증 |

이번 범위는 **KRX 코스피 현물**이므로 stex_tp=1을 기준으로 확인한다. 공식 예제의 통합=3을 그대로 복사해 기존 코스피 계열에 섞지 않는다.

**미확인:** 코스피 전체를 뜻하는 응답 행의 코드·범위, 값의 금액 단위, 과거 base_dt의 실제 지원 범위, 당일 확정 시점, 사용자 계정의 이용 가능 여부와 적용 이용 조건. 업종 행들을 임의로 더해 코스피 전체를 만들지 않는다. API 이름·날짜 인자가 있다는 사실만으로 연초 이력을 확보했다고 쓰지 않는다.

## 4. 다음 한 번의 확인
1. 개발자는 위 공식 명세에서 미확인 항목을 해당 TR에 한정해 확인한다. 공식 예제 자체에 이미 있는 요청·필드 조사를 다시 반복하지 않는다.
2. 실제 호출 준비가 되면 **키움 REST 신청·앱키의 PC 내 사용 및 인증·시장 통계 조회**만 사용자에게 한 번 승인받는다. 이는 기존 KRX 승인과 다른 자료원이다. 근거는 PLAN이 인용한 CLAUDE.md §7의 외부 API 추가 승인 규칙이며, 해당 원문을 설계자가 직접 읽은 것은 아니다. 비밀값은 사용자가 PC에 직접 설정한다.
3. 승인 후 최근 완료일·연초·준비 구간의 과거일을 작은 표본으로 확인한다. 기존 KOSPI 저장 자료와 거래소 범위를 대조하고 단위·분류·날짜를 고정한다. API 제한에 맞춰 최초 전체 이력 수집 비용도 계산한다. 날짜별 조회만 가능하다는 이유로 바로 불가 처리하지 않는다.
4. 표본이 맞으면 기존 PLAN §9에 사실만 덧붙이고 전체 화면 목업 → 사용자 확인 → 구현으로 진행한다. 별도 조사 단계나 전체 PLAN 재제출은 추가하지 않는다. 핵심 범위가 불가능한 경우에만 제한을 보고한다.

키움은 등록 IP 인증이므로 핫스팟 등의 공인 IP가 바뀔 때 재등록이 필요한지와 그 실제 운영 부담을 확인한다. PC 수동 갱신·현행 네트워크를 기준으로 판단하며 이를 해결하려고 별도 인프라 구축을 기본 범위에 넣지 않는다. 앱에서 사용하는 호출은 인증과 위 시장 통계뿐이다. 조회 준비에 주문·잔고 연동, SDK·CLI·MCP 설치, 기존 Python 업그레이드는 필요 조건으로 넣지 않는다.

## 5. 이 작업의 완료 범위
- 자료: 코스피와 투자자별 순매수 대금, 원/달러, WTI의 완료된 일별 관측. 일중 감시는 요구하지 않는다.
- 계산: 연초·1/3/6개월 흐름, 20/60일 수급, 최신 일별 큰 변화. 순매수만 제공되면 매수·매도 총액은 NULL, 분모를 못 구한 비율은 사유와 함께 생략한다. 기존 누적 첫날 포함·정정 반영·날짜·완료 봉 규칙은 유지한다.
- 사용자 경험: 두 기존 화면에서 함께 읽는 요약·축/단위/날짜가 있는 차트·조건부 해석, 같은 문장을 쓰는 복사문·미리보기 연결까지 한 기능으로 제공한다. 부족한 자료는 범위를 명시한다. 수급이 빠진 상태를 전체 기능 완료로 기록하지 않는다.
- 검증·실화면 확인 뒤 종료한다. 자료원 하나·계산 하나·차트 하나를 별도 소단계로 잘게 나누지 않는다. 새 자료원·점수·등급은 완료 범위에 계속 보태지 않는다.
- Yahoo 시각 처리·계산 fixture·전체 화면 배치 준비는 지금 진행한다. 기존 판정이 허용한 작업이므로 사용자에게 착수 여부를 다시 묻지 않는다. 목업 승인 전 앱 구현 경계는 유지한다.

**ML 고도화의 목표·평가 기준 설계는 이 작업과 병행할 수 있다. 이 기능의 모든 자료가 갖춰져야만 ML 고도화 설계에 착수할 수 있다는 게이트는 두지 않는다.**
