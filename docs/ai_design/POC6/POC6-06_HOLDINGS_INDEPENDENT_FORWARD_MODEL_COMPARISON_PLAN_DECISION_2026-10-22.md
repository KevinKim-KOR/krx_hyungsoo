## 1. Q1 — 기반 문서의 한정 예외 문장

다음 문단을 `PROJECT_ORIGIN_INTENT`·`KILL_SWITCHES`·`ASSUMPTIONS`의 현재 관련 위치에 날짜와 본 판정 경로를 붙여 그대로 추가한다. 기존 제한과 과거 판정은 기록으로 보존하고 이번 범위를 연결한다. 문서 전체를 다시 정리하지 않는다.

> 연구 한정 예외(2026-10-22, POC6-06 PLAN 판정): 보유·seed·사용자 평가와 독립된 고정 ETF 표본 최대 24종을 대상으로, PC에서 기존 MEDIAN·RIDGE·HGB·MLP의 고정 recipe를 사용한 전향 D20 예측 기록·성숙 결과 비교 및 월 최대 1회 조건부 재학습을 허용한다. MLP는 이번 단계에서 CPU로 실행한다. 초기 장기 자료의 추가 조회와 OCI 증거 보관은 명시한 사용자 승인 범위로 수행한다. OCI는 수집·보관 역할을 유지한다. 이 예외는 운영 경보·종목 추천·자동 매매의 허용이 아니며, ML_OPERATION_PROMOTION=NOT_APPROVED, CURRENT_DEPLOYABLE_ML_MODEL=none, Q6 OPEN을 유지한다. 기존 POC6-02·04 결과와 미완료 요구 #3·#55·#57·#62는 변경하지 않는다.

이 예외는 본 설계의 연구 재개 범위에만 적용한다. 자료 손상·시각 누출 등 나머지 중단 조건은 그대로 적용한다.

## 2. Q2 — (a) 종목마다 가장 이른 유효 입력 판 수용

한 날짜에 모든 ETF를 같은 수신 묶음으로 강제하지 않는다. 다음 규칙으로 선택한다.

1. 회차의 공통 기준일 D와 input_cutoff를 먼저 고정한다. 정상 공개된 manifest와 참조 파일의 무결성, 실제 available_at·copied_at_pc가 모두 cutoff 이하인지 검사한다.
2. 그 종목의 한 가격 창에 D 및 feature에 필요한 날짜·유효 가격이 있어 기존 가격·연결 검사를 통과하는 후보만 남긴다. 상태 글자 OK만으로 사용 가능하다고 보지 않는다. 누락·실패 사유를 기록한다.
3. 이 후보 중 원래 공개 시각이 가장 이른 판을 선택한다. 동률은 원래 run_id 순이다. 모든 방법은 그 종목·D의 동일한 선택 입력을 사용한다. 예측값·오차를 보고 판을 바꾸지 않는다.
4. PARTIAL 묶음의 유효 종목은 05 계약대로 사용할 수 있다. FAILED·미완료·손상 파일은 정상 입력으로 쓰지 않는다. SKIPPED/effective가 이전 자료를 참조하면 그 원본의 가용 시각과 참조를 보존한다. 수급만 재실행한 시각을 새 가격 수신 시각으로 만들지 않는다.
5. 입력을 선택한 원본 run/object와 수신 창, 선택에 사용한 inventory·cutoff를 남긴다. 서로 다른 종목이 다른 묶음을 썼다는 사실이 재현 가능해야 한다.
6. 최초 예측 입력을 주 기록으로 고정한 뒤에는 새 판이 도착해도 덮지 않는다. 후속 판은 부가 기록이다. 동일 입력·학습 판의 실패 방법 재시도는 설계의 마감·실제 재시도 시각 규칙을 따른다.

이 규칙은 종목별 **하나의 온전한 창**을 고르는 것이다. 종목 안에서 서로 다른 수신 가격을 이어 붙이는 허용은 아니다. 성숙 목표의 판 선택은 설계 §8의 별도 규칙을 그대로 따른다.

## 3. 표본 24종 유지와 해석 범위

### 3-1. 유형 때문에 다시 뽑지 않는다

선정된 24종을 그대로 유지한다. 이번에는 전향 비교 연결과 이 고정 표본에서의 오차를 관측하며, 매수 후보나 seed를 선정하는 것이 아니다. 인버스·선물·합성·채권·혼합형의 포함을 숨기지 않고, 기존 투자 화면의 필터를 적용했다고 설명하지 않는다.

PLAN의 “D20이 거의 0일 종목”은 계산으로 확인한 사실이 아니다. 명칭만으로 하락폭·저위험을 단정하지 않는다. 특히 채권혼합도 그런 가정을 하지 않는다. PLAN에는 “유형 혼합에 따라 통합 오차 해석에 주의가 필요한 종목”이라는 관찰로 정정한다.

주 표는 24종 전체의 같은 행 비교로 유지한다. 종목별 결과와 함께 아래 세 묶음을 사전 고정 보조 표로 추가한다. 새 원천·유형 분류기·feature·별도 학습은 추가하지 않는다.

| 보조 묶음 | ticker | 의미 |
|---|---|---|
| PLAN에서 채권·단기자금·혼합형으로 관찰한 5종 | 458030 · 130730 · 114100 · 488720 · 447620 | 0 하락이나 안전을 전제하지 않는 오차 분리 관측 |
| PLAN의 인버스 2종 | 271050 · 282000 | 역방향 상품의 결과를 구분 |
| 나머지 17종 | 위 7종을 뺀 고정 목록 | 모두 순수 주식형·투자 적격이라는 뜻은 아님 |

각 표에도 비교 가능 날짜·종목·행 수와 누락을 표시한다. 보조 표로 주 표본을 교체하거나 유리한 군만 통과라고 판정하지 않는다. 24종 통합 오차가 작아졌다는 이유로 주식형 ETF·전체 시장·사용자 보유에서 개선됐다고 쓰지 않는다.

### 3-2. ticker와 선정 근거 고정

- `0015K0`를 포함한 선정 24종을 유지한다. 설계의 “6자리 ticker”는 **원래 ETF 식별 문자열 6자**이며 숫자 전용이 아니다. 정수 변환·알파벳 제거·다른 종목 대체는 하지 않는다.
- 기존 조회·검사·파일명 경로가 이 식별자를 보존하는지 코드로 확인한다. 실제 원천에서 지원하지 않거나 조회에 실패하면 해당 사유와 미확보로 남긴다. 성과 계산 없이 필요한 식별자 처리를 최소 보완할 수 있으며, 별도 데이터 우회 경로는 추가하지 않는다.
- cohort 고정 시 목록 object, 후보군 ticker·저장일 수의 작은 선정 요약, 선정 hash·규칙·시각을 함께 저장한다. 기존 PC DB 전체를 복사할 필요는 없다. 그 요약으로 첨부의 24종이 재현되는지 확인한다.
- cohort 고정 후에는 계속 갱신되는 라이브 DB로 다시 순위를 매겨 표본을 바꾸지 않는다. 최초 요약부터 제출 표와 다르면 원인을 확인하고 보고하며, 자동 재선정하지 않는다.

## 4. 시각·성숙 설명 정정

1. **약 09:50은 예상 실행 가능 시각일 뿐이다.** 실제 수집 완료·공개·PC 수신 뒤이며 D 다음 거래일 15:30 전 정상 공개한 기록만 전향 주 기록이다. 09:40 작업이 늦거나 일부 종목을 받지 못하면 그대로 지연·누락으로 남긴다. 예정 cron 시각으로 입력 가용성을 대신하지 않는다.
2. 금요일 D라면 다음 거래일의 마감이 상한이다. 주말 실행도 실제로 금요일 D의 창을 확보한 뒤에만 가능하다. 매일 cron이 있다고 주말 시작부터 자동으로 입력이 있다고 가정하지 않는다.
3. 이미 시간이 지났으면 SKIPPED_TOO_LATE로 남긴다. 해당 입력의 진단 예측은 별도 종류로 기록하고 성과 집계와 LOGGED_FORWARD 학습 예제에서 제외한다. 지연 실행에서 초기에 모델을 만들더라도 학습 경계·실제 시각을 남기며, 이후 전향 기록의 학습 판을 소급하지 않는다.
4. 목표는 한국 연구 축의 다음 20거래일 종가가 모두 확정된 뒤만 성숙한다. 날짜 개수만 맞추거나 아직 마감 전인 D+20 행을 정답으로 쓰지 않는다. 연구 축과 운영 캘린더의 연결은 기존 06/02 규칙을 사용하고 축 불확실은 PENDING_CALENDAR로 구별한다.
5. PLAN의 “D+21~약 D+58에 받은 창”을 고정 범위로 쓰지 않는다. 120일은 수신 요청의 달력 범위이며, 실제 창에 D와 다음 20거래일의 21개 종가가 함께 있는지 검사한다. PC를 늦게 켜도 OCI가 이미 보관한 과거 창을 가져와 성숙 평가할 수 있다. 그 대신 지난 예측을 새로 만들지는 않는다.

## 5. 학습·복원·자원 계획

- MEDIAN/RIDGE JSON, HGB joblib, MLP state_dict와 표준화 JSON을 수용한다. feature 순서·scaler·가중치·라이브러리 판·hash를 함께 보존한다. 동일 입력 복원 대조와 ENV_MISMATCH 처리를 검증한다. OCI에서는 이 파일을 bytes로만 보관한다.
- 기존 함수·고정 recipe를 재사용하고 Ridge 저장용 얇은 학습 접점을 두는 안을 수용한다. 기존 06/02의 같은 입력 결과와 대조한다. CPU MLP는 이 단계의 방법이며 과거 CUDA 실행을 다시 요구하지 않는다.
- 초기 학습 후 새 달에 유효 신규 예제가 생길 때 한 번만 재학습한다. 새 예제가 없어서 건너뛴 실행은 그 달의 학습 기회를 소진하지 않는다. 같은 달의 재시도·재실행이 중복 fit을 만들지 않게 한다. 실패 방법의 복구와 정상 방법의 불필요한 재학습은 구분한다.
- 새 학습 예제는 입력과 성숙 목표의 실제 가용 시각을 확인한 주 기록만 사용한다. 목표 종료일은 그 회차 첫 예측 기준일 D보다 이르다. 동일 X/y/가중치·예제 hash이면 새 월이라는 이유만으로 다시 fit하지 않는다.
- “최소 저장일 407 → 예제 최대 약 327 이상”을 적격성 보장으로 읽히게 쓰지 않는다. 반환 창·축·결측·연결·엄격한 목표 종료 경계에 따라 실제 예제 수를 센다. 252 미달과 가격 기준 실패를 분리한다.
- 38,000행과 수 초~수십 초는 기존 PC 저장일을 이용한 추정이며 새 수신 자료의 상한·실행 보장이 아니다. 실제 반환 범위, 학습 행 수, 시간·최대 메모리·산출물 크기를 첫 실행에서 기록한다. 이 추정 확인을 위해 별도 대규모 학습 benchmark를 만들지 않는다.

## 6. 구현·검증 범위

새 PC 모듈·CLI, 05 등록/전송 허용 형식의 한정 확장을 수용한다. 허용 경로를 문자열 접두어만으로 판정하지 않고 정규화한 상대 경로·schema·참조·hash를 함께 확인한다. 02/03/04의 기존 파일 계약과 05 수집은 그대로 보존한다.

PLAN의 시험 범위에 이번 판정의 입력 판 선택·PARTIAL/effective 참조, 영숫자 ticker, 고정 cohort 재사용, 늦은 진단의 학습 제외를 포함한다. 월별 갱신·무학습 재사용·방법별 실패·같은 행 분모·복원 일치는 기존 계획대로 검증한다. 관련 시험·의미 있는 변이 확인·필수 전체 회귀 1회를 수행하고, 통과 뒤 이유 없이 반복하지 않는다.

화면 변경이 없으므로 목업·사용자 실화면 확인은 없다. 실제 성숙 결과가 아직 없으면 미성숙/표본 0을 정상으로 보고하고 정답 연결은 알려진 격리 경로로 검증한다. 실제 20거래일·두 번째 달·GPU PC·모델의 성과 통과를 개발 종료 조건으로 추가하지 않는다.

## 7. 승인과 실제 연결 순서

1. 본 판정 반영 뒤 격리 구현·검사를 시작한다. PLAN 재제출이나 여기서 확정한 기술 선택의 사용자 재확인은 필요 없다.
2. 구현과 대상 목록·명령·허용 경로가 준비되면 PLAN §6의 묶음으로 필요한 실제 작업 승인을 한 번 확인한다. 초기 24종 조회, 커밋/push와 OCI 받기 도구 배포, POC6-06 산출물 추가 보관, 종료 기록 커밋/push를 구체적으로 제시한다. 같은 범위의 기존 승인은 재사용한다. **본 설계 판정 자체가 추가 외부 조회·새 커밋·원격 쓰기의 사용자 승인은 아니다.**
3. 승인 범위에서 초기 자료 확보 → 초기 학습·저장/복원 → 실제 첫 run → 검증자 확인 → 설계자 RESULT 판정으로 진행한다. 첫 run이 늦으면 §4대로 확인하며 다음 날까지 개발을 멈추지 않는다. 실제 확인 중 입력·가중치·평가가 바뀌면 그 변경 범위만 검증한다.
4. RESULT 판정 뒤 승인된 범위로 커밋/push·OCI 보관 도구를 반영한다. 기존 거래일 08:05~15:45 배포 회피를 유지한다. CPU 개발·검증은 OCI 반영 시각까지 기다리지 않는다.
5. 산출물 업로드와 양쪽 복구를 실제 확인한 뒤 해당 범위의 종료 기록을 정리한다. 업로드 전에는 PC_ONLY다. 이후 동일 승인 형식·경로의 추가 보관은 매번 새 승인을 받지 않는다. OCI의 모델 load·학습·예측·새 cron·새 키는 없다.
6. 05 첫 정기 실행·기존 R0 운영 확인은 별도로 수행한다. 이번 구현의 대기 조건으로 섞지 않는다. 같은 POC6 안이므로 handoff는 추가하지 않는다.
