## 2. 대상과 평가 범위

1. 일일 ETF 수집 대상은 기존 ETF 마스터에서 식별 가능한 유효 국내 상장 ETF 전체를 기본으로 한다. 보유 여부·최근 수익률·모델 성적으로 고르지 않는다. 자료 수집과 향후 투자 대상 필터는 구분한다.
2. 날마다 기존 ETF 목록 수집을 재사용해 마스터를 확인하고 실제 대상 목록·마스터 기준일·분류 출처·목록 hash를 남긴다. OCI에서 이미 갱신한 목록은 중복 조회하지 않는다. 갱신 실패·비정상 빈 응답 시 마지막 확인 목록과 그 날짜를 사용하고 낡은 목록이라는 사실을 표시한다. 새 목록인 것처럼 기록하지 않는다.
3. 새 상장·편입·자료 부족·수집 실패·목록에서 사라진 종목을 기록한다. 이전 종목 자료를 삭제하지 않는다. 매도했다고 연구 자료 수집 대상에서 빠지지 않는다.
4. 상장폐지 종목의 새 자료원 확보·과거 모집단 복원은 이번 범위 밖이다. 오늘 목록을 과거 시장 전체의 목록으로 소급하지 않는다.
5. 기존 4종·12종·26종은 기존 연구의 대상 목록으로 고정 보존한다. 일일 수집 모집단과 합쳐 과거 연구가 넓어진 것처럼 기록하지 않는다.
6. 보유 수량·평단·계좌·매수 시점·개인 손익·메모·AI 세션 본문은 이 수집·보관 묶음에 넣지 않는다. 보유 여부에 따른 보조 분석은 이후 연구에서 필요할 때 정한다.

새로운 후보 선별·투자 전략 성과를 이번에 계산하지 않는다. 그때는 보유와 독립된 대상·선정 시각·규칙·비교 기준을 먼저 정한다. 이번 자료는 그 준비 자산이다.

### 3-1. 가격 수신 창

- 일일 네이버/FDR 요청은 기존 PC의 최근 120일 조회 범위를 기본으로 한다. 같은 날 받은 한 응답의 필요한 종가·거래량·change·날짜·출처를 함께 보존한다. 모델 feature를 만들려면 최소 61개의 필요한 축 날짜가 있어야 하며, 부족하면 부족으로 남긴다.
- 미래 연구의 장기 학습 이력은 기존 연구 사본과 앞으로 쌓는 자료를 활용한다. 이번에 전 종목의 2014년 이후 이력을 외부에서 다시 받지 않는다. 초기 연구 사본의 부족분을 새 대규모 백필로 자동 확대하지 않는다.
- `change`가 같은 응답 종가에서 계산된 값인 점을 표시한다. 이 값으로 일관성 판정이 통과했다는 사실을 독립 품질 증거로 쓰지 않는다.
- 수신 묶음마다 요청/반환 범위·수집 시작/완료 시각·라이브러리 판·가격 의미를 기록한다. 공식 수정주가·총수익률·당시 가용 가격이라고 보증하지 않는다.
- 기존 `etf_daily_price`의 오래된 창과 새 창을 합쳐 연구 정본을 만들지 않는다. 일일 보관본은 수신 창 자체를 남긴다. 기존 PC·OCI 가격 저장/운영 계산의 전면 교체는 하지 않는다.
- 같은 종목의 다른 날 수신 창에서 과거 종가가 바뀌면 이전 창도 남긴다. 수신 시점별 차이는 정정 이력이며 원래 값을 틀린 값으로 삭제하지 않는다. 비정상 행·결측은 사유를 남기고, 그 행을 지운 뒤 더 과거의 행으로 61일을 채우지 않는다.
- 일일 요청 전 종목 수·예상 요청 수·보관 바이트·시간을 PLAN에 제시한다. 현 OCI에서 무리한 범위면 단순히 보유 종목만 남기거나 전체 수집 완료라고 쓰지 말고, 실제 제한과 보유 독립적인 축소안을 질문한다.

### 3-2. 시간과 후속 결과의 연결

자료의 날짜(`observation_date`)와 실제 확보 시각(`observed_at`, UTC 저장)을 구분한다. 검증된 묶음을 읽을 수 있게 공개한 시각(`available_at`)도 남긴다. 원천이 제공하는 공표 시각이 있으면 별도 저장하되 없으면 미상이다. 국내·미국·런던 날짜를 하나로 맞추기 위해 앞당기거나 진행 중 행을 확정 행으로 바꾸지 않는다.

기존 DB/연구 사본을 처음 보관한 시각은 `imported_at`이다. 과거 날짜의 값을 오늘 가져왔다고 당시 알고 있던 값이 되지 않는다. 05 이후 실제 수집 시각부터 확보 시점 추적이 가능하며, 그것도 공급자의 최초 공표 시각을 증명하지는 않는다.

후속 모델 입력은 기준 시각 이하에 확보·공개된 판만 읽을 수 있어야 한다. 과거 날을 요청했는데 뒤에 받은 정정값을 자동 선택하지 않는다. 확보 시각을 모르는 과거 자료는 회고 자료로 명시한다. PC 사본은 OCI의 원래 시각과 PC 수신 시각을 모두 보존하며 전송이 과거의 정보 가용성을 새로 증명한 것으로 쓰지 않는다.

기존 D20은 다음 20거래일 최저 종가 변화다. 운영 원장의 +20일 수익률과 다르다. 미래 D20 결과는 같은 수신 판 안의 기준일~종료일 가격으로 계산하고 결과 판을 고정하는 계약을 후속 비교 설계에서 정한다. 서로 다른 수신 시점의 조정 종가를 무검사로 나눠 계산하지 않는다. **이번에는 새 D20 정답·예측·오차를 생성하지 않는다.**

## 4. 보관 구조 — 최신 자료와 증거 사본

- 최신 시장 자료는 기존 OCI 시장 DB·기존 표를 우선 재사용한다. 01의 두 시장 흐름 표를 OCI에 연결하며, 별도 분석용 DB나 모델 등록 서비스를 만들지 않는다.
- 불변 증거는 OCI `state/ml/evidence/` 아래에 둔다. PC에는 같은 구조의 연구용 사본을 둔다. 둘 다 git 제외 대상이다. 정확한 하위 경로·CLI 이름은 PLAN에서 정한다.
- 논리 구조는 `catalog` + 내용 hash로 식별하는 자료 파일 + 실행 manifest다. 파일은 표준 JSON/JSONL과 gzip 등 기존·표준 도구만으로 읽을 수 있게 한다. 큰 가격 묶음은 종목별 처리해 전 종목을 메모리에 한 번에 쌓지 않는다.
- 같은 내용은 한 번 보관하고 manifest가 참조할 수 있다. 내용 hash는 확보 시각을 대신하지 않는다. 같은 값을 다시 받은 관측 기록도 구별된다.
- 먼저 임시 경로에 자료·manifest를 쓰고 hash/필수 항목을 검증한 뒤 한 번에 공개한다. 완료 manifest가 없는 묶음은 정상 입력으로 조회하지 않는다. 과거 완료본을 덮어쓰지 않는다. 일일 수집과 연구 등록은 같은 보관 인덱스 쓰기 잠금을 재사용해 충돌을 막는다.
- 일일 작업 상태는 `OK / PARTIAL / FAILED`와 자료원·종목별 성공/실패/미시도 수·이유로 남긴다. 파일 손상은 자료 부족이 아니다. 0·결측·미시도를 구별한다. 부분 성공은 받은 자료를 보존하되 전체 확보 성공으로 보고하지 않는다.
- 실행별 manifest에는 schema_version, run_id, 목적/종류, 코드 commit, 실행/수집 시각, 대상 목록 참조, 날짜 축·가격 기준, 자료 파일 hash/바이트, 요청·반환 범위, 이전 보관본 참조와 실패 사유를 넣는다. JSON 응답 전체·인증 헤더·토큰을 보관하지 않는다.
- 보관은 추가 방식이다. 압축·중복 제거는 가능하지만 자동 삭제·최근 N일만 유지·원본 정정 덮어쓰기는 없다. 초기 보관량과 연간 증가량을 실측 표본으로 추정해 남긴다. 실제 디스크 부족 때는 새 묶음을 실패 처리하고 기존 완료본을 보존한다.

이 구조는 이번 자료·기존 연구에 한정한다. 범용 데이터 레이크·새 메타데이터 서버·모든 원응답의 영구 저장 체계로 확대하지 않는다.

## 5. 기존 모델·연구 보존

필수 보관 대상은 02 공식 입력/CPU 결과/GPU 원본·취합 결과/recipe·환경, 03 가격 사본·조회 기록·대조 보고서, 04 입력 manifest/B·C snapshot/공식 결과다. 결과서와 최종 판정은 저장소 경로·commit으로 연결한다. 기존 06/08의 이미 생성된 연구 파일은 실제 있는 경로가 확인될 때 함께 등록할 수 있으며 새 실행을 요구하지 않는다.

- 명시한 연구 폴더만 한 번 확인한다. 원본 파일을 고치거나 공식 학습·GPU 실행·과거 보고서 생성을 다시 하지 않는다. 받은 파일과 hash가 다른 경우 그 파일만 확인 필요로 보고한다.
- `experiment_id`, 코드 commit, 입력/recipe hash, 대상 목록, 목표/feature 정의, 실행 환경, 실제 예측·정답 파일, 원래 판정을 한 manifest로 연결한다. 원래 `REJECT`도 그대로 보존한다.
- 모델 설정과 실행 결과를 보존한 것을 학습된 모델 가중치까지 저장한 것으로 쓰지 않는다. 02는 대형 모델 pickle을 저장하지 않는 계약이었다. 기존에 학습 파일이 없다면 `trained_artifact=not_saved`로 두며 이를 만들려고 재학습하지 않는다.
- 이후 새 모델·새 설정은 새 식별자로 등록할 수 있도록 둔다. 이번에 모델 로딩·서빙·자동 재학습 기능을 만들지 않는다. 출처 불명의 pickle을 불러와 보관 무결성을 검사하지 않는다.
- 과거 예측은 `RETROSPECTIVE_TEST`다. 등록 시각만 오늘로 바꿔 실제 미래 예측(`FORWARD_RESEARCH`) 실적으로 계산하지 않는다. 미래 예측 기록 형식은 기준 시각·실제 생성 시각·학습 자료 종료/확보 시각·모델/입력 판·대상·목표·예측값을 연결할 수 있게 정하되, 이번에 예측 생산 작업은 추가하지 않는다.
- 보관 대상은 허용된 시장/연구 데이터 파일뿐이다. 프로젝트 전체, `.env`, 키, 사용자 handoff, 보유·AI 세션 DB를 통째로 묶어 OCI에 보내지 않는다. 배포 commit을 참조하며 저장소 전체 사본을 별도 보관하지 않는다.

## 6. OCI 일일 실행

1. 기존 08:10·09:20 배치와 발송 cron은 유지한다. 새 수집·보관 진입점은 독립 CLI 하나, cron 최대 한 줄이다. 기본 제안은 **매일 09:40 KST 1회**이며 PLAN에서 실제 종료 시각·중첩·호스트 시간대를 대조해 확정한다. 기존 배치 안에서 기다리게 연결하지 않는다.
2. 국내 자료는 마지막 완료 거래일, 해외 자료는 기존 완료 봉 규칙을 따른다. 휴장일에도 자료원별 새 자료 존재 여부를 구분한다. 국내 휴장일을 새 가격 날짜로 만들지 않는다. 이미 받은 자료는 불필요하게 다시 조회하지 않되 원천 정정 구간은 01 계약대로 받는다.
3. 기존 KRX·VIX 등 이미 자동으로 받는 자료는 같은 내용을 재조회하지 않고 그 수신/저장 경계를 재사용한다. 09:40에 읽어 보관했다는 이유로 08:10에 받았던 값의 확보 시각을 새로 발명하지 않는다. 실제 수집 시각이 확인되지 않으면 그 사실을 남긴다.
4. 새 OCI 네이버/FDR 수집은 기존 PC 순차 조회·timeout·연속 timeout 중단 규칙을 재사용한다. PC 서버 전체를 OCI에 띄우거나 시장 화면 갱신 API를 호출하지 않는다. 이미 있는 DNS·느린 연속 응답 한계를 해결하는 새 프로젝트를 붙이지 않는다.
5. 01의 환율·WTI 최근 90일·수급 누락/최근 20거래일·최신 날짜 우선·인증 실패/연속 실패/시간 예산을 재사용한다. 값이 바뀌면 기존 최신 표는 갱신하되 당시 보관본은 유지한다. 수신 허용 수치와 완료 시각을 최신 표 반영 전에 보존할 수 있는 작은 경계를 둔다. 두 쓰기 중 일부가 실패하면 불일치를 실행 상태에 남기고 성공으로 감추지 않는다.
6. 프로세스 중복 실행은 기존 단일 실행 수단을 재사용한다. 수집 중 DB 쓰기 트랜잭션을 오래 잡지 않는다. 가격 보관 파일 생성·압축·외부 대기를 운영 DB 잠금 안에서 하지 않는다. ML 학습·GPU 사용은 없다. 수집·보관·전송은 torch/CUDA와 모델 학습 모듈을 불러오지 않는 경계로 둔다.
7. 키움은 OCI의 실제 외부 접속 IP 등록과 기존 앱키의 OCI 설정이 필요하다. 사용자가 설정하며 키를 채팅·문서·로그로 받거나 PC `.env`를 통째로 복사하지 않는다. 기존 토큰 발급/갱신 코드를 재사용한다. KRX 회원 웹 자동 로그인은 재개하지 않는다.
8. 기존 PC 수집은 즉시 삭제하지 않는다. 이번 단계에서는 연구 사본 가져오기를 연결하고, 모든 PC 화면의 데이터 정본 전환·수동 갱신 버튼 폐지는 하지 않는다. 동일 자료를 두 곳에서 받았으면 원천/확보 시각과 생산 장소를 구별한다.
9. POC6-01의 81초/6.8초는 PC 실측이며 OCI 보장 시간이 아니다. 첫 승인 실행에서 시간·최대 RSS·디스크 증가·기존 작업 중첩 여부를 기록한다. 필요하면 기존 스레드 제한만 적용한다. 지연/자원 문제를 확인하면 그 원인만 다룬다.

## 7. PC 가져오기 · 연구 입력 연결 · 복구

- 기존 SSH 설정·읽기 전용 export 전송 방식을 재사용한다. 별도 서버·포트·웹 API·로그인 화면은 없다. OCI에서는 읽기만 하는 export 스크립트로 완료 manifest와 필요한 파일만 가져온다. 운영 원장 동기화의 5표 계약을 시장 자료 전체로 바꾸지 않는다.
- 최초 연구 보관 업로드와 일일 자료 내려받기는 구분한다. 업로드는 허용 목록의 검증된 연구 파일을 새 보관 경로에 추가하는 전용 명령뿐이며 임의 원격 파일 쓰기 도구로 만들지 않는다. 이후 동기화는 아직 없는 내용 hash만 전송한다.
- PC 임시 폴더에서 schema·자료 범위·hash·참조 무결성을 확인한 뒤 공개한다. 같은 식별자의 다른 내용은 덮어쓰지 않고 충돌로 보고한다. 중단된 전송 뒤에는 필요한 파일만 재개할 수 있어야 한다. SSH 실패가 기존 PC 사본을 지우지 않는다.
- 로컬 읽기 함수/CLI는 보관 목록·자료원별 최신일/확보 시각·실패/누락·해당 연구 입력/예측/정답의 연결을 보여 준다. 기준 시각 이하의 입력 판을 고르는 연구용 export를 제공한다. export는 외부 조회·재학습·라이브 DB 쓰기 없이 새 출력 파일을 만든다.
- export에서 수신 창과 가격 의미를 유지한다. 기존 02 JSON과 무손실 호환되는 부분은 재사용할 수 있다. 부족한 장기 이력을 여러 판에서 몰래 합쳐 02 호환 입력이라고 만들지 않는다. 호환 안 되는 사유와 적용 가능한 범위를 남기며 과거 공식 입력은 그대로다.
- OCI 보관본과 PC 검증 사본으로 복구 경로를 확보한다. `git 제외 폴더에 파일 있음`만으로 백업 완료라고 쓰지 않는다. 완료 묶음 하나를 별도 임시 경로에 복구해 같은 hash/목록/읽기 결과를 확인한다. 실행 중 SQLite 파일의 단순 복사나 원본 위 복구를 하지 않는다.
- 별도 NAS·유료 저장소·상시 PC 동기화 서비스를 추가하지 않는다. PC가 꺼져 있어도 OCI 수집은 진행하고, PC를 켜면 밀린 완료 묶음을 가져올 수 있다. PC 동기화 전의 새 OCI 자료는 아직 두 번째 사본이 없다는 사실을 보고한다.

## 8. 개발자 PLAN — 필요한 확인만

짧은 PLAN 하나에 다음을 적는다. 전체 저장소·전체 백로그를 다시 감사하지 않는다. 새 성과 계산·학습·실제 외부 조회·OCI 쓰기는 PLAN 판정 전 하지 않는다.

1. 현재 OCI DB/기존 배치의 실제 수집 범위와 PC 전용 경로: 표·원천·읽기/쓰기 접점·수집 시각 필드. 기존 기록을 먼저 사용하고 빠진 부분만 읽기 전용으로 확인한다.
2. ETF 마스터의 비보유 포함 대상 수, 목록 작성 접점, 종목/수신 창 단위 아카이브와 기존 KRX 중복 방지 접점. 새 투자 대상 분류기를 만들지 않는다.
3. 기존 02/03/04 산출물의 실제 경로·hash·바이트·recipe/예측 포함 위치·가중치 파일 유무. 없는 파일을 복원하려고 공식 연구를 재실행하지 않는다.
4. 기존 PC 수집 기록과 OCI 사양/빈 디스크에 따른 요청 수·시간/메모리·연간 보관량 추정. 기존 timeout/잠금/SSH 재사용 위치와 오전 정기 작업의 중첩. 조사만을 위한 부하 시험은 없다.
5. OCI/PC 보관 경로·manifest/자료 파일 형식·소규모 구현 위치·업로드/가져오기/export CLI와 실패 상태. 새 DB·공개 API·의존성 없이 가능한지 확인한다.
6. 기존 코드의 작은 수정 목록: 01 수집 접점·표 생성·당시 값 보존 경계, cron, 키움 설정, 일관된 날짜 축·가격 창 선택. 공유 파일이 KS-10 기준에 걸리면 이 변경에 필요한 책임만 분리한다.
7. 격리 시험·복구 확인·첫 승인 OCI 실행·일일 cron 확인 절차와 개발 종료/정기 운영 확인의 구분. 원래 PUSH·원장 결과를 바꾸지 않는 확인 범위를 적는다.
8. 실제 충돌만 질문한다. 특히 전체 ETF 동일 원천 수집의 자원/이용 조건 문제나 기존 경계로 당시 값을 보존할 수 없는 사실은 추천 대안과 함께 올린다. 근거 없이 대상 축소·수집 원천 교체·모델 실행 추가를 하지 않는다.

화면 변경이 없으므로 목업은 없다. PLAN에서 OCI 쓰기 경로·cron·원격 전송·기존 키 설정의 실제 변경을 한 번에 제시한다. 외부 실제 수집·업로드·배포는 사용자 승인 범위에 따라 진행하며, 이미 받은 동일 승인을 다시 묻지 않는다.

## 9. 수용 기준과 검사

1. 기존 연구 원본/판정은 바이트 불변이며 별도 보관본이 같은 hash다. 연구 종류·원래 대상·과거 예측/정답·recipe가 연결되고 미저장 가중치를 있다고 표시하지 않는다.
2. 일일 목록은 보유와 독립적이다. 보유·개인 손익·사용자 평가를 바꿔도 수집 대상/파일이 변하지 않는 격리 자료로 확인한다. 마스터 변경·부족·실패 분모도 보존한다.
3. 같은 관측일의 값이 바뀌어도 이전 수신 판이 남는다. 기준 시각 이전 조회에 나중 정정값이 섞이지 않는다. import 시각을 과거 공표 시각으로 대체하지 않는다.
4. 가격 창·원천·날짜 축이 드러나고 KRX 무조정/네이버 수신 가격·+20 수익률/D20·회고/미래 예측 기록이 섞이지 않는다. 새 모델 결과는 생성하지 않는다.
5. 일부 수집 실패·미시도·저장 실패·손상·중복 실행·중단된 전송을 정상 완료로 만들지 않는다. 받은 유효 자료·이전 완료본은 보존한다. 복구 후 동일 읽기 결과를 얻는다.
6. PC 가져오기/export는 승인된 OCI 보관 경로 읽기만 하며 시장/원장/보유 DB에 쓰지 않는다. 새 자료가 없어도 기존 사본으로 읽힌다. 완료되지 않은 묶음·hash 충돌은 거절한다.
7. API 키·토큰·인증 헤더·개인 수량/평단/계좌/메모가 산출물·오류에 들어가지 않는다. 허용 파일 업로드와 상대 경로 검증을 확인한다.
8. 기존 PUSH·PARAM·운영 원장·PC 화면 계산은 바뀌지 않는다. 수집 라이브러리의 프로세스 전역 timeout 교체는 독립 수집 프로세스 안에 한정한다.

자료 fixture·임시 DB·임시 경로로 경계 시험을 하고, 관련 검사 후 변경 범위에 맞는 회귀를 마지막 한 번 수행한다. 기존 02/04 학습·GPU 실행·성과 보고·전 연구 회귀를 반복하지 않는다. 실제 API 오류를 일부러 만들거나 살아 있는 DB에 시험 값을 넣지 않는다.
