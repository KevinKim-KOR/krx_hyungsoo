## 3. Q2 — 일회성 분석 파일은 PC 연구 출력에 보존

제품 코드·scripts·시험 파일을 추가하지 않는 안을 수용한다. **분석 파일의 실제 원문 사본과 SHA-256을 새 출력 폴더에 함께 보존하며, Git에는 넣지 않는다.** 해시만 남기고 분석 파일을 버리는 방식은 아니다.

PLAN의 `inputs.json`·`diagnostic.json`·`diagnostic.md`·분석 파일 사본 구성을 수용한다. 다음 최소 사실도 결과에 연결한다.

- 사용한 POC6-21 잠금/실행 ID·입력 파일과 해시·원래 코드 판 `991b2500`.
- 실제 실행에 사용한 분석 파일과 보존 사본의 바이트 일치·해시, 실행 환경의 Python/numpy 판·시각/경과·모집단/집계 정의.
- 분석 파일은 커밋된 제품 코드가 아니라 PC 산출물이라는 점과 실제 보존 경로. 다른 PC의 git pull만으로 원문/입력이 전달된다고 쓰지 않는다.

표준 라이브러리+기존 numpy, 저장 JSON 읽기만 사용하고 `app/trend_switch` import·모델 복원/호출·봉인 DB 열기·다른 실행 탐색은 하지 않는다. 복원은 저장 RET_60의 고정 산술뿐이다. 새 재현 프레임워크·CLI·설치·상시 모듈은 필요 없다.

## 4. Q3 — 공통 계획 실행일과 성숙 기준

**점수/정답 행의 보조 구간은 신호 D의 원래 공통 계획 실행일 E=D 뒤 두 번째 한국 거래일로 배정한다.** 곡선별 실제 편입일·이연 체결일·최초 실제 거래일로 배정을 바꾸지 않는다. 그래야 같은 D/ETF 행이 R/M에 같은 구간으로 들어간다.

E는 POC6-21에 저장된 원래 일정·계획과 거래일 축에서 확인한다. 임의 달력일 +2로 만들거나 새 외부 캘린더를 연결하지 않는다. 첫 신호 2020-12-30은 원래 공통 E=2021-01-05에 따라 첫 구간에 포함한다.

정답 성숙은 원래 목표의 끝, **E를 첫 번째로 센 60번째 한국 거래일(E+59)**이 저장 축 끝 2026-09-21 이하인지로 판정한다. 이는 원래 축에서 D+61과 같은 뜻이다. 첫 신호가 장부 축 앞에 있다는 이유로 제외하거나, 날짜 비교가 안 된 것을 성숙으로 간주하지 않는다. 성숙했어도 y_abs가 없는 행은 양쪽 공통 분석에서 제외한다.

## 6. 집계의 의미를 명확히 할 사항

### 6-1. 점수 구간·가중치

원래 h·2h의 고정 5구간과 전체/기존 보조 3구간/원래 상위 5 부분집합을 수용한다. 구간별 평균·비율은 해당 구간에 행이 있는 날짜 안에서 먼저 계산하고, 그 날짜들을 같은 비중으로 요약한다. 따라서 R/M의 각 구간에 속한 날짜 집합은 다를 수 있으며 날짜 수·행 수를 함께 표기한다. 전체 MAE·부호 일치도 같은 공통 행의 날짜 균형 요약이다.

R의 MAE는 과거 추세 점수와 미래 절대 정답의 같은 단위 거리이며, R이 미래 수익 예측으로 검증됐다는 뜻이 아니다. 빈 구간·미성숙·정답 부재는 구분하고, 집계에서 정확도·확률의 새 합격선이나 신뢰구간을 만들지 않는다.

### 6-2. 후보 미검토 사유

기록 없는 사유를 당시 계획·보유·살아 있는 의도·한도와 연결해 복원하는 것은 허용한다. **직접 저장된 사유와 사후 복원한 사유를 구분한다.** 판단일 이후 체결이나 나중 손익을 이용해 당시 미검토 이유를 붙이지 않는다.

조건이 겹치면 적용 우선순위를 분석 파일에 고정하거나 복수 조건으로 표시하고, 유일한 이유를 확인할 수 없으면 확인 불가로 남긴다. 미검토 후보를 문턱 실패로 세지 않는다. 실제 매수 의도 취소 0건은 생성된 의도가 모두 체결됐다는 뜻이며, 한도/현금 등으로 후보 검토 이전에 기회가 제한된 적이 없다는 증거가 아니다.

### 6-3. Q4 기간·일별 비중

원래 126/117주·171/150 종목·주는 원래 계획 기록과 대조한다. 동일 종목이라도 보유 cycle이 바뀌면 별도 구간이다. 첫/마지막 보류 계획일은 그 날짜에서 관측한 사실이며, 매일 유동성 자격을 새로 검사한 결과가 아니다.

일별 비중을 계산할 때는 **직전 유효 정기계획의 보류 표시를 다음 유효 정기계획 또는 실제 이탈까지 연결한 노출 집계**임을 명시한다. 중간 무계획 9주에 해당하는 구간은 따로 표시하고, ‘그날 자격 탈락이 직접 확인됨’으로 쓰지 않는다. 수량·종가·평가액은 각 장부 날짜의 실제 값을 사용한다. 평균에는 정상적으로 확인 가능한 현금/비보류일의 0도 포함하고 날짜 분모를 적는다. 자료로 상태 연결을 할 수 없는 날은 미확인으로 분리하며 0으로 대체하지 않는다.

이 집계는 보류 상태에 연결된 실제 노출·평가 경로다. Q4 때문에 생긴 손익이나 강제 매도했을 때의 차이는 계산하지 않는다. 비적격 보유의 새 점수는 만들지 않는다.

### 6-4. 월별 요약·손익 연결

달력 월 요약은 선택 없이 모든 월을 같은 정의로 나란히 표시하는 설명 표로 수용한다. 유리한 월을 골라 새 시험/판정 구간을 만들지 않는다. 첫/끝 불완전 월은 범위를 표시하고, 곡선/K의 같은 월 경계를 사용한다. 월 수익은 직전 월말 저장 평가 대비 해당 월 마지막 저장 평가이며 첫 월의 기초는 원래 장부의 시작 100이다. 현금 평균은 그 월의 저장 거래일 기준이다.

공식 거래의 비용 포함 완료 손익과 열린 보유 평가손익을 재사용하여 끝 평가−100과 연결한다. 비용을 다시 차감하거나, 연결 차이를 임의 보정값으로 없애지 않는다. 이탈 사유별 손익·현금/K 동시 움직임은 실제 경로의 기술이며 CAGR 차이의 인과 분해가 아니다.

## 7. 중단 기록·확인 범위

PLAN의 ‘일관성 확인이 다르면 결과를 쓰지 않고 멈춤’은 **정상 완료 진단을 쓰지 않는 것**으로 보완한다. 입력/분모/손익 연결 불일치·자료 부족·예산 초과가 나면, 새 POC6-22 출력에 최소한 상태·멈춘 단계·원인·기대/관측값·확인한 범위·경과와 분석 파일 식별을 남긴다. POC6-21 원본에는 쓰지 않는다. 거대한 실패 기록 구조는 만들지 않는다.

대표 표본의 고정 경계·날짜 가중 집계·손익 연결 확인을 수용한다. 검증자는 새 집계/복원 정의와 대표 표본·합계를 확인한다. 필요시 PC에 보존된 분석 파일을 사용하며, 제품 코드의 Git 추적 여부를 검사하는 기준으로 이 일회성 파일을 부적합 처리하지 않는다. 기존 70시험·공식 verify·전체 회귀·프런트 검사는 반복하지 않는다.

상한은 분석 한 묶음 **30분·RSS 8GiB·CPU 4스레드**, 새 학습 0·모델 예측 호출 0·전략 재실행 0이다. 1분/1GB는 개발자의 추정으로 남긴다. 분석 뒤 결론이 불리하거나 원인이 미확정이라는 이유로 기간·문턱·점수·모집단을 바꿔 반복하지 않는다.

## 8. 승인과 다음 행동

판정 원문 보관 → Q1 예외와 Q2/Q3·§5~§7 명확화를 기존 PLAN에 반영 → 부족한 사용자 승인 한 묶음 → 일회성 분석 → 결과서/검증자 확인 → 설계자 RESULT 순서로 진행한다. 같은 입력·분모·계약이면 PLAN 재제출이나 별도 설계 검토는 없다.

다음 두 가지를 한 묶음으로 확인한다.

1. **일회성 분석 파일 작성·분석 1회·관련 확인:** 지정 POC6-21 파일 읽기 전용, 새 POC6-22 출력과 분석 파일 사본 보존, 위 예산/범위. 검증자의 새 집계 확인은 이 분석의 검산 범위이며 새 모델 실험이 아니다.
2. **종료 반영:** 검증자 확인·설계자 최종 RESULT 뒤 설계/판정/PLAN/RESULT·관련 기반/상태 문서만 커밋·push. 분석 파일·연구 산출물·원자료·사용자 handoff는 제외한다.

이 승인으로 같은 범위 중간 작업마다 재확인을 요구하지 않는다. POC6-21 승인 ③은 이번 단계 승인으로 확대하지 않는다. 운영·OCI 배포·새 원천·다음 모델/임계/목표 설계는 포함하지 않는다. 이번 진단의 마지막 결론은 관측 사실·가설·분리 불가 원인·후속 연구 근거 유무까지다.
