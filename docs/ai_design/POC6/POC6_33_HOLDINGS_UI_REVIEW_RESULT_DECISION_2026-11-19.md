# POC6-33 보유·자료 관리 화면 정리 · RESULT 판정

2026-11-19 KST · 설계자 판정 · 수신 개발자

**조건부 PASS.** 검증자 r2의 VERIFIED를 수용한다. 결과서 §13~§14에 따라 「확인 근거」 재진입 시 순위를 다시 읽고 실패를 표시하는 동작(F1), 서버 시험이 프런트 소스에 의존하던 문제(B-6)는 해소됐다. 형수님이 정하신 보유 상세 한 줄도 수용한다. 아래의 화면 표기와 문서를 맞추고 커밋 전 확인을 기록하면 RESULT를 PASS로 확정한다.

## 1. 1개월 순위와 보유 목록 정렬

| 화면 | 정렬과 표시 기준 |
|---|---|
| 「후보리스트」 | 기본 기간은 1개월이다. 1일·1개월·3개월 중 고른 기간 하나에서, 공통 시작일과 종료일을 충족한 ETF의 가격 수익률로 상·하위를 정한다. |
| 「주간 ETF 점검」 | 1개월 가격 수익률 상위 30개를 검토 대상으로 읽는다. 인버스·레버리지·합성·선물 제외 조건을 적용한다. |
| 「확인 근거」 | 보유 목록은 기본 ‘5저장일 변화’ 순이다. 기존 평가 비중·손익률·20저장일 변화 정렬도 제공한다. 행을 펼치면 「주간 ETF 점검」과 같은 조건에서 그 종목의 순위 또는 상태를 보여 준다. |

순위 계산에 쓰는 값은 해당 기간의 가격 수익률 하나다. KODEX 200 대비, 거래량과 괴리율은 종목을 해석할 때 각각 읽는 근거다.

- 상세의 순위 줄에는 **‘1개월 수익률 상위 30 중 n위’**, 순위권 밖에는 **‘1개월 수익률 상위 30 밖’**을 쓴다. 실제 비교 기간·제외 조건·해당 가격 상태는 같은 조회 결과에서 표시한다. 규칙상 제외, 개별 주식, 자료 부족, 조회 실패는 각각의 사유로 읽는다.
- 화면에 진입할 때마다 공통 순위를 한 번 새로 읽는 r2 동작을 적용한다. 진행 중과 조회 실패를 표시하고 해당 종목의 가격·구성·NAV 근거는 계속 읽을 수 있게 한다.

## 4. PASS 확정과 인계

1. **공개 문서와 목업을 맞춘다.** PLAN·목업의 실제 보유 종목 수·계좌별 행 수·계좌 수·상태별 보유 건수는 가림 값이나 명시한 합성 예시로 바꾼다. STATE 및 결과서에 이번에 넣은 보유 집계도 같은 기준을 적용한다. 시장 전체 집계와 규칙을 설명하는 수치는 쓸 수 있다. 개발 기록에는 실제 보유 이름·코드·계좌·수량·평가액과 종목을 유추할 수 있는 개별 수치를 넣지 않는다.
2. **최종 화면을 확인한다.** 사용자 확인이 끝난 보유 상세는 결과서 §8-1에 완료로 갱신한다. 개발자가 격리 화면에서 History의 비교 시작일·종목 관리 행 단위와 「확인 근거」의 행 아래 상세·순위 라벨을 확인한다. 주간 두 화면은 동일한 조건과 자료 시점으로 한 번 대조한다. 실제 상위 30에 해당하는 보유가 없으면 순위 숫자 사례는 기존 고정 자료로 확인한다. 「데이터 상태」의 수집 상태와 괴리율 표시를 독립적으로 읽을 수 있고 재저장일이 새 원천 자료일로 읽히지 않는지 확인한다. 사용자에게 확인을 받은 항목과 개발자가 확인한 항목을 표에 각자의 근거로 기록한다.
3. **완료 검사를 기록한다.** 변경한 화면의 관련 시험, 타입 검사와 PLAN §5의 린트를 확인한다. 백엔드 전체 회귀는 최종 반영본에서 한 번 실행해 결과를 적는다. 기존 420px 가로 스크롤과 React `act` 경고는 결과서의 한계와 검사 기록에 남긴다.
4. **결과와 상태를 갱신한다.** 이 판정문을 `docs/ai_design/POC6/POC6_33_HOLDINGS_UI_REVIEW_RESULT_DECISION_2026-11-19.md`에 보관한다. 결과서 §15에 판정과 보완 확인을 적고, 머리·§1-2·§5·§7·§8-1의 이전 대기 문구를 실제 확인 범위로 고친다. `STATE_LATEST.md`와 `PROGRAM_TRUTH.md`는 격리 상태와 main 반영 상태를 실제 진행 시점대로 기록한다.

이 조건을 충족하면 개발자가 **설계자 RESULT PASS · 운영 반영 승인 대기**를 기록한다. 커밋 및 main 반영은 형수님 승인 후 진행한다. 운영 화면 확인과 격리 정리까지 끝난 시점에 종료를 기록한다.

Q55는 결과서 §1-2의 POC6-32 상태 문서 단독 반영 기록으로 수용한다.

판정 근거는 첨부 결과서 §4·§5·§7·§8·§10~§14, 확정 PLAN V1 §3·§5·§9-1, 11/18 PLAN 판정, 네 화면 목업과 11/19 사용자 결정이다. 검사는 개발자 및 검증자의 제출 기록을 근거로 판정했다.
