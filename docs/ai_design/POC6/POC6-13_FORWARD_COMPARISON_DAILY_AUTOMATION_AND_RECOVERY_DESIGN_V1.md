## 1. 근거와 작업 분리

사용자·개발자 보고와 POC6-12 PLAN 부록 A를 근거로 한다. 설계자가 현재 맥북·OCI를 직접 점검한 보고가 아니다.

- 06은 10-23 이후 수동 실행이 없어 누적이 멈췄다가, 10-28 D=10-27의 24종 기록·공개 확인 10:53:38 KST로 정상 재개됐다. 미수신 보관본도 따라잡았다. 기존 모델은 KEEP이며 이번 기록은 PC_ONLY다.
- D=10-23·10-26은 마감이 지난 미기록으로 유지한다. 소급 생성하지 않는다. 첫 성숙 예정은 기존 D=10-22 기록의 11-19 종가 뒤다.
- 08~11 산출물 약 374MB와 봉인 KRX DB 약 1.86GB는 점검상 맥북 한 곳에만 있다. 02~04·06의 기존 OCI 보관과 구분한다.
- 이 빈자리는 모델 성능과 다른 운영 문제다. 이번 완료가 운영 ML 채택·추천 효용 입증·프로젝트 전체 완료를 뜻하지 않는다.

| 묶음 | 개발 범위 | 다른 묶음을 기다리지 않는 부분 |
|---|---|---|
| A 정기 실행 | 맥북 일정에서 기존 06 명령 호출·마감·중복·실패 상태 확인 | 12 API·역사 자료 백업 목적지와 무관하게 구현·검증 |

PLAN·결과서는 각각 한 파일 안에서 A·B·C를 구분한다. 한 묶음의 승인·접속·전송 대기가 다른 묶음의 격리 개발을 막지 않는다.

- 기존 기반 문서와 실제 충돌이 있으면 PLAN에 위치와 필요한 한 문장만 적는다. 관성적으로 세 기반 문서 전체에 예외를 덧붙이지 않는다.

## 3. A — 맥북 정기 실행

### 3-1. 일정과 가동 조건

기본안은 macOS 사용자 단위 launchd LaunchAgent다. 기존 사용자 권한·Python 가상환경·SSH 설정을 쓴다. 관리자 상주 서비스·새 패키지·자동 부팅·절전 설정 변경은 추가하지 않는다.

| 시각(Asia/Seoul) | 동작 |
|---|---|
| 매일 10:05 | 09:40 OCI 수집 뒤 첫 실행 시도 |
| 매일 12:05·14:35 | 입력 지연·네트워크 실패·늦은 기동에 대비한 제한된 추가 점검 |
| 매일 15:25 | 상태 확인·필요한 로컬 알림만 수행. 새 예측 실행은 시작하지 않음 |
| 로그인/일정 복귀 | 실행 가능한 시간인지 먼저 판단하고, 필요하면 따라잡기 1회 |

요일만으로 건너뛰지 않는다. 금요일 종가가 토요일 수집에 들어오는 경우도 기존 06의 실제 거래일·마감 규칙으로 처리한다. 새 한국 휴장일 계산기를 만들지 않는다.

- 자동 예측 호출 시작 창은 **10:00 이상~15:20 미만 KST**다. 그 밖에는 상태만 확인한다. 이 창은 운영 여유이며, 전향 기록의 실제 마감은 기존 06의 D 다음 거래일 15:30이다.
- 맥북이 로그인되어 있고 깨어 있으며 연결 가능한 동안 동작한다. 잠든 동안의 일정은 깨어난 뒤 호출될 수 있지만, 꺼져 있던 동안의 실행을 보장하지 않는다. 로그인 시 따라잡기와 실제 마감 검사가 필요한 이유다.
- 일정 설치 때 macOS의 실제 시간대와 KST 일정이 일치하는지 확인한다. OS 시간대를 몰래 바꾸지 않는다. 다르면 PLAN에서 실제 차이만 질문한다.
- StartCalendarInterval과 로그인 시 호출을 사용하고 KeepAlive로 반복 재시작하지 않는다. 일정 시도 3회와 추가 따라잡기를 합쳐 자동 예측 명령은 KST 하루 최대 4회다. 같은 시각 중복 호출은 하나로 합친다. 이 제한은 사용자의 기존 수동 명령을 막지 않는다.
- 맥북을 하루 종일 켜 둘 의무는 없다. 유효 시간대에 한 번도 가동되지 않으면 예측은 없고, 다음 가동 때 미실행 사실을 보여 준다. 실행 중 절전·전원 종료의 한계도 기록한다.

Apple 공식 문서는 LaunchAgent의 로그인 사용자 범위와 달력 일정의 수면/전원 종료 차이를 설명한다. 설치 대상 macOS에서의 실제 동작은 PLAN·연결 확인으로 확인한다.[1][2]

### 3-2. 호출과 마감

실제로 재사용할 명령은 기존 가상환경의 Python으로 실행하는 **scripts/run_forward_compare.py run --pull**이다. 새 CLI 이름과 파일 배치는 PLAN에서 제시하되 기존 명령을 대체하지 않는다.

1. 자동화 상태 기록을 먼저 만들고 실제 시각·호출 사유를 남긴다. 절대 경로의 interpreter·저장소 작업 경로를 쓴다. 터미널의 대화형 PATH나 가상환경 activate에 기대지 않는다.
2. 자동 호출끼리의 잠금과 기존 06 실행 잠금을 구분한다. 수동 실행과 겹치면 기존 잠금 결과를 존중하며 강제로 잠금을 지우거나 실행 중 프로세스를 종료하지 않는다.
3. run --pull 한 번으로 기존 입력 수신·성숙·학습 조건 판단·예측·보고를 수행한다. 자식 프로세스 실제 경과 상한은 20분이다. 시간 초과 시 안전하게 종료하고 자동화 실패 사실을 남긴다. 공식 06 산출물의 상태를 바깥에서 고쳐 쓰지 않는다.
4. exit code 0만으로 성공이라고 쓰지 않는다. 기존 구조화 결과·주 기록·공개 확인을 연결해 D·종목/방법별 상태·실제 확인 시각을 읽는다. ALREADY_RECORDED도 그 기록의 D와 확인 근거를 표시한다. 오래된 기록을 “오늘 예측 완료”로 바꾸지 않는다.
5. 같은 D의 호출은 기존 중복 방지 계약을 따른다. 추가 점검이 새 모델 선택·강제 재학습·다른 입력으로 주 기록 교체를 일으키게 하지 않는다. 첫 실행 실패를 성공한 호출로 덮어 이력에서 지우지 않는다.
6. 시작이 빨라도 공개 확인이 15:30 이상이면 주 기록 성공이 아니다. 마감 뒤 깨웠다면 미실행/늦음으로 남긴다. 테스트 전용 가짜 시각을 운영 명령 인자로 받아 시각을 소급하지 않는다.

외부 원천 API를 이 자동화에서 새로 호출하지 않는다. --pull이 사용하는 기존 OCI 사본 수신만 자동화 범위다. 비대화형 SSH 인증이 안 되면 실패로 기록한다. 비밀번호 입력 대기·키 복제·호스트 검증 완화를 해결책으로 쓰지 않는다.

## 4. B — 새 06 산출물의 두 번째 사본

자동화 설정을 실제 활성화할 때, 기존 **06 archive의 upload 절차를 자동 실행 후 호출하는 범위**도 한 번에 승인받는다. 정확한 기존 CLI 인자와 허용 자료 유형은 PLAN에서 대조한다. 새로운 임의 업로드 도구로 바꾸지 않는다.

- 유효 실행 뒤 허용된 미보관 산출물을 기존 05/06 등록·업로드·해시 확인으로 보관한다. 이전 실행의 밀린 허용 산출물도 기존 명령이 지원하는 범위에서 처리한다.
- 새 protocol·입력/예제·모델·예측·목표·보고·공개 확인 영수증을 기존 참조와 묶는다. 새 자동화 로그는 06 연구 폴더 밖에 두어 미승인 자료 유형을 섞지 않는다.
- 공개 확인 시각은 기존 06의 근거 그대로 보존한다. 나중의 업로드 시각을 과거 공개 시각으로 대체하지 않는다.
- **예측 정상·보관 대기는 가능한 조합**이다. 업로드 실패로 예측을 취소하거나 다시 학습하지 않는다. 이후 정해진 점검에서 보관만 다시 시도할 수 있게 한다. 자동 업로드의 한 번 경과 상한은 10분이며 무한 재시도하지 않는다.
- 같은 내용의 재등록·업로드는 기존 중복 처리를 따른다. 대상 서버에서 모델을 load/import하지 않는다. PC_ONLY 수·보관 완료 묶음/해시·마지막 실패를 상태에 따로 표시한다.
- 기존 OCI 도구가 이미 이 형식을 처리한다면 서버 코드 pull은 필요 없다. 실제 공백이 확인될 때만 필요한 변경을 PLAN에 질문하며, 그것으로 A의 개발을 기다리게 하지 않는다.

## 5. 사용자에게 보이는 상태

새 웹 화면·메뉴·API는 만들지 않는다. **상태 CLI 하나와 같은 내용의 읽기 쉬운 최신 상태 파일**, 오류가 있을 때의 짧은 macOS 로컬 알림을 제공한다. Telegram 발송은 하지 않는다. PLAN에 정상·실패·마감 경과의 출력 예를 넣으면 되며 전체 화면 목업은 필요 없다.

| 항목 | 표시할 내용 |
|---|---|
| 실행 장치·일정 | 설치/활성 상태·KST 기준 확인 시각·다음 시도 |
| 이번 시도 | 실제 시작/종료·사유·06 run_id·종료 코드·실패 요약 |
| 전향 기록 | 실제 D·입력 정상/미확인 수·방법별 정상/실패·공개 확인 시각과 마감 |
| 수신·학습 | 사용 입력 묶음·기준일·KEEP/실제 학습 여부·model_version |
| 평가 | 미성숙과 도래 후 결측을 기존 06 상태대로 구분 |
| 보관 | 미업로드 수·마지막 보관 성공/실패·C의 백업/복원 상태 |

- “일정 호출이 없었음”, “호출은 됐으나 실패”, “입력/달력을 확인할 수 없음”, “이미 같은 D를 기록함”, “새 주 기록 완료”, “마감 경과”를 구분한다. 정확한 상태명은 기존 출력과 연결해 PLAN에서 정한다.
- 상태를 읽을 때 날짜와 실제 마지막 실행을 다시 비교한다. 어제의 성공 파일이 남아 있다는 이유로 오늘도 녹색으로 표시하지 않는다. 거래일을 확정할 수 없으면 필요한 D도 확인 불가다.
- 15:25 점검은 미실행·실패·미확인·방법 일부 실패·보관 대기를 알려 준다. 맥북이 그 시각 꺼져 있었다면 다음 로그인/가동 때 지난 점검의 상태를 알려 준다. 맥북이 꺼진 동안의 실시간 감시·알림을 보장한다고 쓰지 않는다.
- 로컬 알림은 새 실패 상태마다 한 번으로 제한하고 D·짧은 사유·상태 확인 방법만 담는다. 권한 차단/미지원이면 알림 미전달을 표시하고 상태 파일·CLI는 유지한다. 보유 내역·키·응답 본문을 알림에 싣지 않는다.
- 자동화 상태는 예를 들어 state/ml/operations/poc6_13/처럼 06 연구 산출물과 분리한다. 호출별 작은 기록을 남기고 latest는 원자적으로 교체한다. 중단된 RUNNING은 다음 점검에서 실제 프로세스와 대조해 중단/확인 필요로 표시한다.

## 6. C — 기존 연구 자산 백업 1회

### 6-1. 대상과 권장 목적지

목적지 권장안은 **기존 개인 OCI의 운영 DB·05 보관소와 분리된 비공개 디렉터리**다. 기존 SSH 연결을 재사용한다. 예: OCI 사용자 홈의 private_backups/investment_model_v2/poc6_13/<backup_id>/. 실제 경로·소유권·남은 디스크는 PLAN에서 확인하고 원격 쓰기 전에 승인받는다. 다른 저장소를 선택해도 A·B 설계는 바뀌지 않는다.

첫 대상은 08·09·10·11의 보존된 연구 폴더, 해당 봉인 KRX DB 1개, 그 결과를 읽는 데 필요한 코드 참조·환경 정보다. 과거의 첫 실행·정정 실행도 보존하며 최신 실행만 골라 옛 것을 버리지 않는다.

- POC6-10은 로컬 research/poc6-10-local과 해당 커밋을 포함한 **복구 가능한 비공개 Git bundle 등**으로 보관한다. 원격 Git 브랜치를 만들거나 main에 합치지 않는다. 현재 main과 필요한 커밋도 참조가 실제 복원되도록 보관한다.
- 08~11이 참조하는 02~06 입력은 기존 OCI 보관 묶음/해시로 복원 가능한지 연결 목록만 만든다. 이미 검증된 입력을 모두 재업로드하거나 연구를 재실행하지 않는다. 없는 필수 입력은 누락으로 보고하고 필요한 파일만 목록에 추가한다.
- 실제 보존된 코드가 없는 옛 실행은 그대로 “코드 보존 공백”이다. 최신 HEAD를 과거 실행 코드로 기재하거나 새로 실행해 옛 결과를 대체하지 않는다.
- 선택한 자료만 포함한다. 사용자 handoff 문서·.env·SSH/인증키·보유/계좌 파일·브라우저 자료·가상환경·node_modules·라이브 DB를 통째로 백업하지 않는다.
- 최초 이관은 약 2.3GB+코드로 예상하되 실제 크기를 PLAN에 적는다. 이미 닫힌 자료의 초기 사본 1회다. 매일 이 용량을 다시 전송하는 작업을 만들지 않는다.

### 6-2. 무결성과 복원

1. 대상·상대 경로·크기·SHA-256·실제 백업 시각·코드 참조·기존 입력 참조를 고정한다. 봉인 DB는 기존 봉인 상태를 확인하고 읽기만 한다.
2. 출처 파일을 변경하지 않고 PC에서 묶는다. 읽는 중 대상 파일이 바뀌면 완료로 처리하지 않는다. 절대 경로·상위 경로 이탈·대상 밖 심볼릭 링크를 묶음에 포함하지 않는다.
3. 기존 SSH로 별도 임시 이름에 전송하고, 원격 바이트 해시가 맞은 뒤 완료 상태로 전환한다. 실패/불완전 묶음을 정상 목록으로 노출하지 않는다. 같은 backup_id의 기존 파일을 덮어쓰지 않는다.
4. OCI 보관 파일을 다시 가져와 **빈 별도 경로**에서 복원하고 목록·내용 해시를 대조한다. 코드 bundle은 임시 저장소에서 필요한 참조/커밋이 복구되는지 확인한다. 라이브 저장소·DB 위로 복원하지 않는다.
5. 모델 파일은 bytes로만 대조한다. 과거 모델 학습·성과 재계산·현재 환경에서의 전 모델 로딩은 요구하지 않는다. “바이트 복원 완료”와 “과거 실행의 완전 재현 가능”을 구분한다.

보관 결과는 PC_ONLY / 전송 불완전 / 원격 해시 확인 / 복원 확인 완료를 구분한다. 같은 물리 디스크의 다른 폴더를 두 번째 사본으로 세지 않는다. OCI 자체의 장애까지 대비한 세 번째 사본은 이번 범위 밖이다.

## 7. 자원·실패·일정 제한

- A·B는 기존 06 계산과 사본 전송을 사용한다. 새 설치는 기본 0이며, 새 학습 예산·스레드·메모리 설정을 임의로 늘리지 않는다.
- C의 최초 전송·복원 확인은 15:45 KST 이후 별도 수행한다. 최초 작업 상한은 60분이며 대역폭상 어렵다면 예상 시간과 필요한 조정만 보고한다. 대용량 백업이 다음 전향 실행의 잠금을 차지하게 하지 않는다.
- 디스크 여유는 계획된 임시 묶음·전송·빈 경로 복원까지 포함해 확인한다. 여유가 없으면 C만 보류하고 기존 자료를 삭제해 공간을 만들지 않는다. 과거 사본의 자동 삭제·보존 기간 변경은 이번에 도입하지 않는다.
- 예측·보관·백업의 상태를 분리한다. 예측 성공만으로 백업도 완료했다고 쓰지 않으며, 백업 실패 때문에 정상 예측을 실패로 바꾸지 않는다.
- WTI 날짜 간격 조사, 옛 특징 표 갱신, 추천 화면 개편, 새 알림 판단, 12 API 구현은 붙이지 않는다. 발견한 기존 문제는 현재 작업을 막는 것만 질문하고 추가 연구를 자동으로 열지 않는다.

## 8. 검증 범위

가짜 시각·입력·자식 프로세스·전송 실패를 사용하는 격리 시험을 우선한다.

- 시간: 10:00 전·유효 창·15:20 경계·실제 공개 15:30 경계·수면 후 복귀·로그인·금요일/주말·달력 미확인. 기존 06 마감 계산은 재사용하고 다른 계산식으로 복제하지 않는다.
- 중복/실패: 일정·로그인 겹침, 수동 실행과 잠금 경합, 최대 시도 수, SSH 실패, 자식 시간 초과/중단, ALREADY_RECORDED의 실제 D, 방법 일부 실패, 새 달의 기존 학습 조건 유지.
- 상태: exit 0이지만 공개 확인 없음, 이전 날짜 성공, 입력 지연, 마감 경과, 예측 정상·업로드 실패, 알림 권한 없음. 어떤 것도 정상 완료로 조용히 바꾸지 않는다.
- 보관/복원: 끊긴 전송, 원격 바이트 손상/누락, 잘못된 경로, 재전송 중복, 원본 무변경, 빈 경로 해시 일치·Git 참조 복구.
- 검증 보장은 실제 경로의 누락·손상·상태 오판과 공식 시각 계약이다. 모든 파일/시각/기록을 함께 고친 악의적 위조를 입증하는 별도 체계는 만들지 않는다.

기존 06 및 05의 변경 접점 관련 시험을 돌린다. 공유 코드 변경 때문에 필요할 때만 전체 회귀를 한 번 수행한다. 공식 연구 재실행·전체 저장소 재감사·실제 미성숙 자료의 가짜 성숙은 하지 않는다. 통과 뒤 같은 검사를 문서 변경만으로 반복하지 않는다.

## 9. 작은 구현 구조

새 진입점 1개, 일정/실행·상태·보관 연결 등 필요한 작은 모듈, LaunchAgent 템플릿, 관련 시험으로 구성한다. 기존 06·05의 대형 파일에 스케줄·백업 로직을 쌓지 않는다. 정확한 파일 책임은 PLAN에서 정한다.

운영용 설치/해제와 dry-run을 구분한다. dry-run·상태 조회는 예측·학습·pull·업로드를 실행하지 않는다. 설치 시 interpreter·작업 경로·자기 Label의 파일만 생성하고, 기존 다른 작업·crontab을 바꾸지 않는다. 해제는 자기 일정만 비활성화하며 연구 결과를 삭제하지 않는다.

## 10. 개발자가 제출할 짧은 PLAN — 다섯 묶음

1. **현재 장치:** 실제 macOS·Python 경로·시간대·비대화형 SSH의 기존 지원·launchd 설치 위치. 사용자에게 확인할 실제 가동 제약이 있으면 한 번에 질문한다. 새 인증키·API 신청을 선행 조건으로 두지 않는다.
2. **기존 연결:** run --pull·archive/upload·상태/보고·공개 확인의 실제 CLI/구조화 필드·잠금·월별 학습·중복 처리 접점. A·B에서 공유 코드 변경이 필요한 곳만 적는다. 예측·학습은 실행하지 않는다.
3. **일정과 표시:** 정상·입력 지연·이미 기록·실패·마감 경과·보관 대기의 짧은 출력과 로컬 알림 예, 3회 일정+따라잡기/상태 점검의 구현 방식. 새 화면 목업은 없다.
4. **백업:** 허용할 실제 경로·파일 수·용량·코드/입력 참조, OCI 비공개 목적지 권장안·남은 디스크·예상 전송/복원 시간. PLAN에서는 목록·크기·기존 해시 참조만 보고 대용량 전수 재해시는 실제 백업과 합친다. 목적지 미정이어도 A·B PLAN을 먼저 확정할 수 있다.
5. **변경·검증·승인:** 새 파일 책임·기반 문서 실제 충돌·의미 있는 시험·원격 변경 필요 여부·승인 묶음. 12의 API를 조사하거나 새 모델·성과를 계산하지 않는다.

설계와 충돌하는 사실만 질문한다. 조사를 위해 정상 예측을 추가로 만들거나 상태 확인에 pull을 몰래 붙이지 않는다. 기존 06·05·사용자 보고의 확인 결과를 재사용한다.

## 11. 실제 반영과 종료

PLAN 판정 → 격리 구현/시험 → 검증자 → 설계자 RESULT 판정 → 구체적인 실행 범위의 사용자 승인 → 실제 연결 확인·종료 기록 순서다. **설계 작성 요청은 지금 스케줄 설치나 원격 쓰기를 실행하라는 승인이 아니다.** 이미 유효한 승인이 있는 동작은 반복해서 승인받지 않는다.

한 번에 제시할 실제 승인 범위는 맥북의 자기 LaunchAgent 설치·정해진 --pull/기존 upload 자동 호출·로컬 알림, C의 대상/용량/비공개 원격 경로·빈 경로 복원·자기가 만든 임시 파일 정리, 커밋/push다. OCI 코드 변경이 필요하면 그 diff·필요성·기존 반영 시간 규칙도 함께 제시한다.

- A: 활성화·정상/실패/늦음 확인. 실제 유효 시간대면 기존 절차 1회만 호출한다. 이미 기록된 D면 기존 기록 반환으로 확인하고 새 기록을 강제로 만들지 않는다.
- B: 밀린 허용 산출물 보관과 PC/OCI 해시·기존 빈 경로 복원 확인을 재사용해 연결을 확인한다.
- C: 별도 저장소 실제 사본과 되가져온 빈 경로 복원·코드 참조 확인을 완료한다.
- RESULT에는 A/B/C를 각각 기록한다. A·B를 먼저 반영할 수 있다. C 미완료를 전체 백업 완료로 적지 않는다. C를 보류한 채 단계를 닫아야 한다면 사용자·설계자가 그 잔여를 명시적으로 결정한다.
- 첫 정기 실행은 한 번 별도 운영 확인으로 남긴다. 미성숙 결과나 다음 월 학습을 기다려 개발을 붙잡지 않는다. 정상 확인을 이유 없이 며칠 반복 요구하지 않는다.

운영 ML 미승격·Q6 OPEN·#3/#55/#57/#62 미완료는 유지한다. 사용자 소유 handoff 문서를 커밋에 넣지 않는다. 같은 POC6 안의 별도 handoff는 만들지 않는다.

## 12. POC6-12와의 병행 지시

12의 원천 존재 확인은 완료로 유지하고, 다음은 **공식 API의 정확한 제공 범위·이용 조건 확인 우선**이다. 이전 보충 판정의 “문의부터”는 후속 사용자 대화에 따라 보류한다. API 조건으로 이번 저장/가공 범위가 명확하면 별도 허락 문의를 필수로 반복하지 않는다. 이것이 API의 필수 필드 제공이나 실제 이용 승인까지 확인됐다는 뜻은 아니다.

사용자는 집에서 정상 로그인으로 API 서비스명·ETF의 2025년 분배 이력 지원·지급기준일/실지급일/분배락일·금액 필드·요금/이용 조건을 확인한다. 키·비밀번호·개인정보는 대화에 붙이지 않는다. 개발자는 그 회신을 기다리며 13의 PLAN·구현을 진행한다. 실제 12 수집·구현 보류는 필요한 조건이 충족될 때까지 유지한다.

13은 자료를 계속 쌓고 보관하는 운영 개선이며, 이후 추천 효용 검증을 위한 비교 자산을 유지한다. 새로운 모델 연구나 “모든 연구를 12가 끝날 때까지 중단”하는 지시로 넓히지 않는다.
