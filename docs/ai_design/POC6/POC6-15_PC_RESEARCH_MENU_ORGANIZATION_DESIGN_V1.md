# POC6-15 DESIGN V1 — PC 메뉴 구분과 ML 연구 화면 정리

작성: 설계자 · 2026-11-01 · 독자: 개발자·사용자·검증자

저장 위치: docs/ai_design/POC6/POC6-15_PC_RESEARCH_MENU_ORGANIZATION_DESIGN_V1.md

**먼저 §9의 짧은 PLAN과 전체 화면 목업을 제출한다. PLAN 판정과 사용자 목업 확인 뒤 구현한다. 이번 변경은 기존 화면의 메뉴·배치·이름 정리다.**

## 1. 목적과 출발 상태

사용자 요청은 ‘한 메뉴에 기능이 계속 늘어나므로 메뉴(폴더)를 구분해 달라’는 것이다. POC6-14에서 하나의 「ML 실험」 화면에 전향 비교 카드와 기존 다섯 카드가 함께 놓였다. 사용자는 진행 중인 예측 비교, 학습 입력 상태, 기존 실험 결과를 서로 다른 목적으로 찾는다. 이 세 가지를 메뉴에서 바로 구분하게 한다.

POC6-14는 IMPLEMENTED_VERIFIED_CLOSED이며, 사용자 보고상 구현 89afeba6·종료 기록 50ed2597이 main에 반영됐다. 기존 조회·상세·복사·오류 구분은 유지한다. 이번에 14의 완료 판정을 다시 열지 않는다.

이 설계는 앞선 결과서·목업·종료 보고를 근거로 한다. 설계자가 현재 저장소의 사이드바·화면 선택 코드를 직접 확인한 것은 아니다. 실제 컴포넌트 이름·메뉴 키·기존 진입 링크는 개발자가 §9 범위에서 대조한다.

이번 완료는 **ML 화면의 메뉴 과밀 해소**다. 검증된 투자 추천과 유용한 ML이라는 프로젝트 목표는 별도로 미완료를 유지한다.

## 2. 메뉴 구조 — 「ML 연구」 아래 세 화면

기본안은 기존 「진단·상태」 그룹 안의 「ML 실험」 한 항목을 **펼침·접힘이 있는 「ML 연구」 폴더**로 바꾸는 것이다. 새 최상위 그룹은 만들지 않는다.

| 위치 | 변경 후 | 역할 |
|---|---|---|
| 진단·상태 › 데이터 상태 | 기존 위치 유지 | 운영 자료의 저장·수집 상태 확인 |
| 진단·상태 › ML 연구 | 폴더 | 아래 세 화면의 이름·선택 상태 표시 |
| ML 연구 › 전향 ML 비교 | 첫 하위 메뉴 | 이미 저장된 예측·이후 결과·누적 비교 확인 |
| ML 연구 › 학습 자료 | 둘째 하위 메뉴 | 학습 입력의 저장 범위·준비 상태 확인 |
| ML 연구 › 기존 실험 | 셋째 하위 메뉴 | 기존 실험·참고값의 상태와 결론 확인 |
| 진단·상태 › 받은 알림 기록 | 기존 위치 유지 | 운영 알림 원장 확인 |
| 진단·상태 › 개발·실험용 | 기존 위치 유지 | 현재 개발 기능의 기존 진입점 유지 |

표의 기존 메뉴명은 최근 목업 기준이다. 현행 이름이 다르면 대응 관계를 PLAN에 적고, 다른 메뉴까지 임의로 개명하지 않는다. 「오늘 확인」·「비교·판단」·「보유·자료 관리」·「승인·운영」 등 나머지 그룹의 위치·순서는 유지한다. 받은 알림 원장은 전향 예측 기록과 합치지 않는다.

여기서 폴더는 **사용자에게 보이는 메뉴 묶음**을 뜻한다. 소스 폴더를 대규모로 옮기거나 파일명을 전부 바꾸는 작업은 필요하지 않다.

## 3. 카드의 이동과 각 화면

현재 보고된 여섯 카드를 다음처럼 나눈다. PLAN에서는 실제 코드와 이 표를 1:1로 대조한다.

| 현재 카드 | 새 화면 | 처리 |
|---|---|---|
| 전향 ML 비교 · 연구(POC6-14) | 전향 ML 비교 | 기존 카드 전체 재사용. 표·누적 비교·도움말·상세·복사 유지 |
| 시계열 준비도 | 학습 자료 | 기존 카드 재사용 |
| Feature Sanity | 학습 자료 | 기존 카드 재사용 |
| ML 증거 갱신 | 학습 자료 | 기존 카드·버튼·명시적 실행 조건 재사용 |
| Baseline v0 | 기존 실험 | 기존 카드·상태·결론 재사용 |
| 상대 상승 참고점수 | 기존 실험 | 기존 카드·기준일·용도 설명 재사용 |

‘기존 실험’이라는 분류가 모든 결과의 채택·중단·갱신 여부를 새로 결정하지 않는다. 각 카드의 현행 결론과 실제 기준일을 그대로 표시한다. 8월에 멈춘 자료를 현재 자료처럼 바꾸거나, 전향 연구 상태를 다른 카드에 복사하지 않는다.

페이지 제목과 소개 문장은 각각 다음을 기본으로 한다.
- **전향 ML 비교** — ‘저장된 전향 예측과 이후 결과를 비교합니다.’
- **학습 자료** — ‘학습 입력의 저장 범위와 상태를 확인합니다.’
- **기존 실험** — ‘기존 실험과 참고값의 상태·결론을 확인합니다.’

전향 비교의 ‘연구용·운영 미채택’ 표시와 D20 도움말은 그대로 둔다. 연구 결과를 투자 추천으로 읽게 하는 명칭을 붙이지 않는다. 새 요약 카드·점수·차트·연구 보고서 목록은 추가하지 않는다. 08~11 연구 산출물 탐색기를 만드는 단계도 아니다.

## 4. 메뉴·화면 전환 규칙

1. 폴더 제목이나 펼침 버튼은 **펼침·접힘만** 한다. 화면 선택·조회·갱신 실행을 겸하지 않는다. 하위 메뉴를 선택해야 해당 화면으로 이동한다.
2. ML 화면이 선택돼 있으면 처음 표시할 때 폴더를 펼쳐 현재 위치를 보인다. 사용자가 폴더를 접어도 열린 본문과 선택 값은 바꾸지 않는다.
3. 하위 메뉴에는 활성 표시를 둔다. 키보드로 펼침·접힘·메뉴 선택이 가능하고 선택/펼침 상태를 접근성 속성으로 전달한다. 기존 사이드바 패턴을 재사용한다.
4. 기존 「ML 실험」 메뉴 키·저장된 선택 값·직접 진입이 남아 있으면 새 **전향 ML 비교**로 연결한다. 다른 화면에서 목적이 명시된 기존 진입점은 세 화면 중 그 목적에 맞는 곳으로 연결한다(예: ‘학습 자료 확인’ → 학습 자료). 이 대응을 작은 매핑으로 정리하고, 기존 키를 지워 화면이 비는 결과를 만들지 않는다.
5. 화면 선택·URL·새로고침·저장된 메뉴 복원은 현재 앱의 방식을 따른다. 기존에 URL 경로가 없으면 새 라우터를 도입하지 않고, 메뉴 선택 저장이 없으면 이를 위해 새 저장 장치를 만들지 않는다. 이미 지원하는 복원 동작은 유지한다.
6. 다른 하위 화면은 숨겨 둔 채 모두 실행하지 않고 **선택한 화면만 렌더링**한다. 전향 표를 떠나 학습 자료에 갔다는 이유로 전향 API를 새로 호출하거나, 그 반대의 조회를 시작하지 않는다. 기존 폴더 접기만으로 본문을 다시 마운트하지 않는다.
7. 전향 비교를 다시 열면 기존 POC6-14의 최초 조회 규칙을 따른다. 기준일·펼친 행을 화면 이탈 후에도 새로 영속 저장하라는 요구는 없다. 단, 같은 화면에서 폴더만 접었다 펼칠 때는 값과 본문을 초기화하지 않는다.

기존 AI 세션의 초안 전달·덮어쓰기 확인 규칙, 알림 원장 동기화, 운영 설정의 저장 경로는 변경하지 않는다.

## 5. 실행과 자료의 경계

메뉴나 폴더를 클릭해서 **자료 갱신·연구 실행이 새로 시작되면 안 된다.** 기존 UI 선택 값 저장은 유지할 수 있다. 기존 「ML 증거 갱신」 등의 명시적 버튼은 지금의 기능·확인·실패 표시를 유지한다. 이동 과정에서 버튼을 자동 호출하거나, 쓰기 결과를 단순 조회로 취급하지 않는다.

- 백엔드 API·저장 형식·DB·모델·06/13 실행·05 보관·PUSH는 변경하지 않는다. GET `/ml/forward-comparison` 계약과 숫자·단위·경고·복사문도 유지한다.
- 새 수집·학습·예측·성숙 평가·보고 생성·SSH·업로드·cron·키·패키지 설치는 없다. PC에서 이미 저장된 자료를 확인하는 동선만 바꾼다.
- 카드 재사용을 위해 필요한 프런트 컴포넌트 추출과 props 분리는 허용한다. 기존 API 함수를 복제하거나, 같은 카드의 사본을 세 벌 만들지 않는다.
- 공유 훅이 여섯 카드 조회·명령을 한꺼번에 호출한다면 선택된 화면의 책임에 맞게 최소한으로 분리한다. 백엔드나 연구 코드의 리팩터링으로 확대하지 않는다.
- 이번 한 단계의 하위 폴더에 필요한 변경만 한다. 범용 메뉴 프레임워크·권한 체계·임의 깊이의 트리·새 상태 관리 라이브러리는 만들지 않는다.

기반 문서에 새 ML 연구 예외를 넣을 필요는 없다. 14에서 제외했던 메뉴 변경을 이번 15에서 명시적으로 다루는 것이며, 기존 연구·운영 계약을 바꾸는 것이 아니다.

## 6. 목업 확인 범위

전체 메뉴가 보이는 **한 목업 목차**에서 세 화면을 확인할 수 있게 한다. 각 화면은 1440px·1000px 두 폭으로 보여 준다. 본문은 기존 카드의 모양을 재사용하고 이동 결과를 확인하는 데 필요한 만큼만 재현한다.

목업에서 볼 것은 네 가지다: ① 폴더와 세 하위 메뉴의 이름·순서 ② 현재 화면의 활성 표시와 펼침·접힘 ③ 각 화면으로 옮긴 카드의 누락·중복 여부 ④ 1000px에서 메뉴·본문을 함께 읽을 수 있는지.

실제 자료가 없는 상태는 기존 카드의 없음/대기 문구로 보여 준다. 미래 성숙 수치나 예측을 새로 만들 필요는 없다. 목업용 가짜 자료가 필요하면 격리하고 표시한다. 라이브 기록·세션 초안·서버 설정을 바꾸지 않는다. 사용자 서버를 내리지 않으며, 임시 목업 서버를 썼으면 확인 뒤 내린다.

## 7. 필요한 검증

변경한 사이드바·화면 선택·카드 연결을 중심으로 확인한다.

| 검증 | 통과 기준 |
|---|---|
| 기존 카드 분배 | 기존 여섯 카드가 정한 세 화면에 한 번씩 연결됨. 빠짐·중복 없음 |
| 메뉴 동작 | 폴더는 펼침·접힘만, 하위 메뉴는 해당 화면 선택. 접기 때문에 본문 초기화·추가 조회 없음 |
| 기존 진입 호환 | 구 ML 선택 값과 실제 사용 중인 관련 진입점이 빈 화면 없이 올바른 새 화면으로 연결됨 |
| 선택 화면 실행 | 다른 하위 화면은 마운트되지 않음. 명령 버튼을 누르지 않은 메뉴 이동에는 기존 쓰기·갱신 함수 호출 0 |
| 14 재사용 | 저장 예측·대기/확인 필요·행 상세·복사·도움말의 기존 시험 통과. 이동 때문에 단위·경고·보고 분모가 달라지지 않음 |
| 기존 경계 | 다른 메뉴의 연결과 AI 초안 전달·원장 기능의 변경 없음. 05/06/13·백엔드·의존성 무변경 확인 |

프런트 타입·lint와 변경된 메뉴/상위 화면/14 카드의 관련 시험을 실행하고, 저장소가 명시한 필수 검사를 지킨다. 이번 배치 변경만을 이유로 백엔드 전체 회귀·연구 재실행·OCI 점검을 붙이지 않는다. 필요한 검사가 통과한 뒤 새 변경이나 실패 근거 없이 반복하지 않는다.

사용자 실화면 확인은 세 메뉴 진입·카드 위치·폴더 동작·전향 상세/복사로 충분하다. 실제 성숙·월 변경 학습·장중 운영을 기다리지 않는다. 검증자도 이번 연결과 실행 경계에 한정해 확인한다.

## 8. 완료 기준

- 사용자가 메뉴에서 전향 비교·학습 자료·기존 실험을 구분해 들어갈 수 있다.
- 기존 카드와 진입점이 누락되지 않고, 화면 이동으로 새 명령이 실행되지 않는다.
- 목업·실화면 확인과 필요한 검사를 마치고 검증자가 변경 범위를 통과시킨다.
- 결과서는 이동 전후 표·실제 변경 파일·검사·한계를 짧게 기록한다. 이번 작업을 위한 공식 연구 report.md/json은 없다.

이 네 조건이 충족되면 RESULT 판정을 받고 종료한다. 전체 앱의 정보 구조 개선·검증된 추천·운영 ML 채택까지 완료로 적지 않는다. 이번 요청 범위가 해소됐는지 사용자 확인을 기록하고, 별도로 남은 메뉴 의견이 있으면 그 사실만 남긴다.

## 9. 개발자가 먼저 제출할 짧은 PLAN

기반 문서의 현행 지시와 STATE를 읽고 이 설계 원문을 보관한다. 다음 네 묶음만 확인한다. 구조 조사는 **읽기 전용 30분 이내**로 잡고 전체 저장소·과거 연구를 다시 감사하지 않는다. 조사 중 실제 충돌이 있으면 그 접점과 선택지만 질문한다.

1. **현재 → 변경 후 표:** 실제 메뉴 키·렌더링 파일·여섯 카드·기존 진입 호출자를 정리한다. 이 설계와 카드명/역할이 다르면 차이만 적는다.
2. **최소 변경안:** 재사용 컴포넌트·화면 선택 방법·필요한 추출과 메뉴 호환 매핑을 적는다. 전체 파일 예상 건수보다 기존 동작을 보존하는 접점을 먼저 설명한다.
3. **실행 부작용과 검사:** 현재 마운트 때의 조회·명령을 구분하고, 선택 화면만 렌더링하는 방법과 §7의 관련 시험을 적는다. 실제 갱신·수집·학습을 실행해서 조사하지 않는다.
4. **전체 화면 목업:** §6의 목차와 두 폭 화면을 제출한다. 질문은 실제 충돌·미확인 사실이 있을 때만 올린다. 충돌이 없으면 질문 없음으로 제출한다.

PLAN을 쓰는 동안 구현·새 설치·커밋·외부 조회·DB/OCI 쓰기를 하지 않는다. 목업은 저장소 밖에서 만든다. 설계 원문·PLAN·STATE 진행 기록만 저장소에 기록한다.

## 10. 진행과 종료 처리

PLAN·목업 제출 → 사용자 목업 확인 및 설계자 PLAN 판정 → 구현·관련 검사 → 사용자 실화면 확인 → 검증자 → 설계자 RESULT 판정 순서다. 목업 확인과 PLAN 심사는 같은 제출물로 진행하며 별도 문서를 반복해서 만들지 않는다.

PC 화면 정리이므로 OCI pull·배포·cron 변경·키 입력은 필요 없다. 커밋·push는 해당 시점의 사용자 승인 범위를 적용한다. 사용자 소유 handoff·연구 산출물·개인 캐시·로컬 전용 연구 브랜치는 포함하지 않는다. 같은 POC6 안의 별도 handoff 문서는 만들지 않는다.

POC6-05·06·13의 자료 축적과 전향 자동 기록은 계속 유지한다. POC6-12 지정 출처 SOURCE_BLOCKED, Q6 OPEN, 운영 ML 미승격, 백로그 #3·#55·#57·#62 미완료도 유지한다. 다음 알고리즘 연구나 추천 채택은 메뉴 정리와 별도로 목적·가설·자료·평가 기준을 정해 다룬다.
