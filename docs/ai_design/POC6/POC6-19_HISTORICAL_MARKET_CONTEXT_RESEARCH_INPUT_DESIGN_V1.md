**목적: 기존 공급자의 과거 이력을 이용해, 수급·원/달러·WTI를 ETF 가격·거래량과 함께 연구할 수 있는 사본을 확보한다. 자체 자료가 몇 년 쌓일 때까지 기다리는 방식을 연구의 기본 경로로 삼지 않는다.** POC6 안의 다음 작업이며 POC7로 넘어가는 인계가 아니다.

## 1. 방향과 이전 사전 확인의 해석 보완

프로젝트 목적은 한국 상장 ETF의 진입·유지·축소·청산 검토를 지원하고, 비용 후 KODEX200 대비 성과와 ML의 추가 효용을 검증하는 것이다. 사용자 확정 A·B·C(주간 정기 검토·수주~수개월 기대 보유·PC 권고·주문은 사용자·Telegram은 관찰/브리핑)를 유지한다.

- 과거 자료를 오늘 받아 학습·회고 비교에 사용할 수 있다. 발표 시차·사후 정정·가격 조정·이미 본 시험 기간의 한계를 기록하며 연구의 주장 범위를 맞춘다.
- 당시 원본 보관은 그날 실제 확보한 정보의 확인에, 전향 예측은 정한 방법을 새로운 자료에서 확인하는 데 쓴다. 두 가지가 부족하다는 이유로 모든 회고 연구를 금지하지 않는다.
- 이전 사전 확인의 **57주**는 저장된 시장 자료 범위이며 API가 제공하는 최대 과거 범위가 아니다. **10일**은 자료일 뒤 4일 안에 처음 확보한 범위라는 개발자 집계다. 모두 실제 판단 마감 전에 확보됐다는 뜻은 아니다.
- H1의 최소 학습 **104주**와 실제 최소 **165주**는 각각 그 연구의 계약과 실측이다. 모든 ML의 공통 최소 길이로 적용하지 않는다.
- 기존 POC6-02·04·08·11은 과거 자료로 수행한 연구다. 이번은 새 시장 입력의 더 긴 이력 확보이며, 기존 기각 결과를 취소하거나 같은 가격 입력을 다시 튜닝하는 단계가 아니다.

이 해석은 `POC6_NEXT_RESEARCH_MARKET_CONTEXT_FEASIBILITY_REQUEST_2026-11-03.md`와 그 회신의 사실을 유지하면서 적용 범위를 보완한다. 기존 요청서 원문을 다시 쓰거나 별도 정정 라운드를 만들지 않는다.

## 3. 근거와 아직 확인하지 않은 것

개발자 사전 회신상 수급 262일·원/달러 282일·WTI 272일은 2025-09-30~2026-10-30에 저장돼 있다. 봉인 가격과 공통 범위는 237일·52주다. 이 값은 개발자 측정이며 설계자가 현재 PC를 다시 검사한 결과가 아니다.

키움 공식 `ka10051` 예제에는 `base_dt` 날짜 인자가 있고, 코스피·금액·KRX를 지정하는 인자도 있다.[1] **과거 날짜를 지정하는 경로가 있다는 근거이며, 2014년까지 실제 응답한다거나 요청 날짜를 정확히 지킨다는 보장은 아니다.** 예제의 대기시간·페이지 수를 공급자의 공식 호출 한도로 인용하지 않는다.

기존 POC6-01 기록은 코스피 종합 행의 지수값을 같은 날 코스피 종가와 대조하고, 수급의 억원 단위를 원으로 바꾼다고 명시한다. 그 접점을 재사용한다. Yahoo의 과거 범위·시각 해석과 각 공급자의 이력 정정 가능성은 실제 응답과 기존 코드로 확인한다. 공개 웹 문서만으로 수집 성공을 선언하지 않는다.

## 4. A — 소수 표본으로 실제 과거 조회 확인

### 4-1. 조회 전 고정

짧은 PLAN에서 사용 함수·자료 위치·원천 파라미터·실제 날짜 목록·예상 요청 수를 정한다. 표본 날짜는 아래 규칙으로 선택하며 가격 상승/하락이나 모델 결과를 보고 바꾸지 않는다. 초기 실행 정보는 첫 외부 조회 전에 기록한다. 기존 인증 설정을 재사용하고 키·토큰·개인 계좌정보를 출력하거나 산출물에 넣지 않는다.

조회는 키움 등록 IP의 망에서 실행한다. IP 미등록이면 해당 상태로 중단한다. OCI로 우회하거나 새 IP·키·계정을 자동 등록하지 않는다. 키움 자료 조회가 HTTP POST인 것은 허용하지만 주문·계좌 조회 API는 부르지 않는다.

### 4-2. 표본

| 자료 | 고정 표본 |
|---|---|
| 수급 | 2026-09-21, 2025-09-30 및 2024·2022·2020·2018·2016·2014년의 첫 저장 코스피 거래일, 총 8일. 앞 두 날짜가 달력에 없다면 멈추고 사실 보고 |
| 원/달러·WTI | 심볼마다 2014년 1월, 2020년 4월, 2026년 9월 1~21일의 세 창, 총 6개 창 요청. 요청 종료일의 포함/제외 규칙은 기존 어댑터에 맞춰 기록 |

수급은 최근 대조일에서 과거 순으로 조회한다. 페이지가 있으면 필요한 연속 조회를 포함하되 예산 안에서만 수행한다. 빈 응답·오류·미완료 페이지는 성공으로 세지 않는다.

### 4-3. 과거 날짜와 의미 확인

- 수급의 시장·거래소·종합 행 코드, 13분류·부호·단위, 지수값이 실제 요청일의 기존 코스피 자료와 맞는지 검사한다. 기존 검증의 단위 변환·허용 오차를 재사용하고 PLAN에 위치를 적는다.
- 응답에 날짜가 없다면 **요청 날짜를 붙였다는 사실만으로 날짜 검증 완료로 삼지 않는다.** 날짜 인자의 공식 의미와 해당 일 지수 대조를 근거로 한 간접 확인이라고 기록한다. 날짜를 무시하고 같은 최신 값을 반복 반환하는 경우를 잡아야 한다.
- 기존 저장 범위와 겹치는 수급·환율·WTI는 원단위·동일 날짜 기준으로 대조한다. 차이가 있으면 새 값과 옛 값을 함께 보존하고 개수·사유를 기록한다. 원천 정정 가능성도 있으므로 차이 자체를 모델 실패나 자동 위조로 판정하지 않는다.
- Yahoo는 반환한 전체 시각·시간대·일봉 날짜·종가 종류와 실제 범위를 확인한다. 주어진 시작일보다 늦게 시작한 응답을 전체 확보로 기록하지 않는다.

**B 진행 조건:** 해당 자료에서 요청한 과거 범위의 유효 값이 있고 날짜·단위 해석을 지지하는 근거가 확인돼야 한다. 앞 두 수급 대조일이 실패하면 오래된 날짜의 대량 조회로 넘어가지 않는다. 한 자료가 막혀도 조건을 충족한 다른 자료는 진행할 수 있다.

## 5. B — 같은 승인 안에서 장기 사본 확보

A 조건을 충족하면 중간 설계자 판정을 기다리지 않고 B로 진행한다. 단, 승인받은 대상·요청 수·시간·저장 경계를 모두 지켜야 한다.

- 수급은 **성공 확인된 가장 이른 표본 날짜**부터 2026-09-21까지 기존 코스피 거래일만 요청한다. 그보다 앞을 이분 탐색하거나 날짜별로 무한 탐색하지 않는다. 이 시작일은 확인된 범위이며 공급자의 절대 최초 지원일이라는 뜻은 아니다.
- Yahoo는 2014-01-02~2026-09-21을 명시해 기존 어댑터가 지원하는 큰 구간 단위로 요청한다. 임의의 최근 1년 기본값을 쓰지 않는다. 반환 시작이 늦으면 실제 범위를 그대로 보존한다.
- 표본에서 이미 받은 응답은 재사용한다. 성공한 날짜를 검산 명목으로 전부 재조회하지 않는다.
- 과거 자료는 연구 폴더에 새 판으로만 쓴다. 기존 운영 표·05 보관 묶음·봉인 판·06 모델·이전 연구 입력을 덮어쓰지 않는다.
- 멈춘 경우 이미 받은 원본과 실패 목록을 보존한다. 시간 초과나 일부 결측을 자료 자체의 무가치·ML 실패로 분류하지 않는다.

### 요청·자원 상한 — 이번 설계의 선택값

| 구간 | 상한 |
|---|---|
| PLAN 구조 확인 | 30분. 기존 조사·기능을 재사용하며 전 저장소 재조사 없음 |
| A 표본 조회 | 데이터 HTTP 요청 32회·30분 중 먼저 도달한 것 |
| B 장기 조회 | 데이터 HTTP 요청 7,000회·120분 중 먼저 도달한 것 |
| 인증·공개 명세 | 전체 인증 요청 최대 2회, 공개 명세 조회 최대 6회. 데이터 요청 예산과 별도 기록 |
| 대기·재시도 | 같은 공급자 요청 시작 간격은 기존 제한·확인된 공식 제한·1초 중 가장 긴 것. 연속 조회·재시도도 요청 수에 포함. 일시적 통신/서버 오류만 동일 요청 최대 1회 재시도 |

| PC | 메모리 4GiB·새 원시/파생 파일 합계 512MiB 이내. 넘으면 정리 없이 중단·보고 |
| 후처리 | 기존 원본 읽기와 검산 15분 이내. 외부 재조회 없이 수행 |

상한은 공급자의 공식 이용 한도나 실행 시간 실측이 아니다. PLAN에는 거래일 수·페이지 수에서 산출한 예상 요청 수와 예상 시간을 적는다. A에서 확인된 실제 속도로 B가 상한을 넘을 것으로 보이면, 예산을 늘리거나 무한 분할하지 않고 부분 확보로 보고한다. 시간은 해당 수집 구간의 실제 경과시간이며 사용자 승인 대기·코딩 시간은 포함하지 않는다.

06 자동 실행과 같은 인증·파일 자원을 방해할 우려가 있으면 그 실행 종료 뒤 수집을 시작한다. 새 운영 잠금 구조나 상시 데몬을 추가하지 않는다.

## 6. C — 사본 구성과 연구에 넘길 정보

예시 루트: `state/ml/research/poc6_19/<run_id>/`. 개발자가 기존 연구 관례에 맞춰 간단한 구조를 PLAN에 적는다. 별도 DB나 데이터 플랫폼은 필요 없다.

필수 산출물은 **실행 정보·원시 응답·정규화 자료·report.md·report.json**이다. 기존 도구로 충분한 항목은 재사용한다.

| 파일 목록 | 상대 경로·바이트 수·sha256. 기존 입력 판의 경로·해시와 새 산출물을 구분 |
| 보고 | 자료별 첫/끝 날짜·개수·중간 빈 날짜·중복·충돌·비교 결과·시간 의미·미확인·가격과 공통 범위 |

수급은 음수·0도 정상 관측일 수 있다. 기관계와 세부 분류를 다시 더하지 않는다. 빈 값과 0을 바꾸지 않는다. 원/달러는 유효한 양수여야 한다. **WTI는 0 이하를 일률적으로 가격 손상으로 삭제하지 않는다.** WTI 선물의 음수 거래 사례가 있으므로 원본을 보존하고 해당 행과 해석을 따로 표시한다.[2] 이번에는 WTI 비율 수익·로그·계약 교체 조정값을 계산하지 않는다. 현물·다른 월물로 대체하지 않는다.

달력이 다른 자료끼리 같은 날짜 문자열로 바로 붙이지 않는다. 원/달러와 WTI는 원래 시장의 날짜·시간대를 보존한다. 한국 신호 시점에 쓸 수 있는 시각은 후속 실행 설계에서 고정할 항목이다. 공급자가 과거 공개 시각을 주지 않으면 미확인으로 적고 수신 시각을 과거 날짜로 소급하지 않는다. **실제 공개 시각 미확인과 날짜별 회고 자료의 저장 가능성을 구분한다.**

빈 날짜는 자동으로 0·직전 값·보간값으로 채우지 않는다. 자료별 달력이 확정되지 않은 부분은 '기대 거래일 미확정'으로 구분한다. 비교할 때는 같은 시점 기준으로 확인 가능한 관측끼리만 연결한다. 가격 판과 교집합 날짜 수는 자료 범위 확인용이며, 당일 거래 전에 모두 이용 가능했다는 증거가 아니다.

## 7. 검산과 검증 범위

구현 검사는 이번 연구 명령의 책임에 맞춘다. 새 수집기·정규화·집계에 대한 필요한 시험과 기존 어댑터 재사용 구간의 관련 시험을 수행한다. 공유 코드를 바꾸지 않았다면 백엔드·프런트 전체 회귀를 관성적으로 돌리지 않는다.

필수 확인:
1. 원본 해시·요청 인자·실제 응답 범위가 정규화 자료와 이어지는가.
2. 수급 날짜를 무시한 응답, 잘못된 단위/부호, 중복 충돌, 미완료 페이지, 누락을 0으로 바꾸는 문제가 검출되는가.
3. 원본에서 정규화 값·단위 변환·범위/결측 개수를 다시 계산했을 때 맞는가. 요약끼리만 비교하지 않는다.
4. Yahoo 날짜/시간대, 완료된 봉 처리, WTI 0 이하 값 보존이 확인되는가.
5. 실행 중 실패·상한 중단에서도 확보한 원본·종료 이유가 남는가. 운영 DB·기존 연구 폴더에 쓰지 않았는가.

실제 수집 결과 뒤 검증자 확인은 한 범위로 묶는다. 실제 API를 전부 다시 호출하거나, 누군가 모든 파일을 서로 일치하게 바꾼 위조까지 인증하는 체계는 만들지 않는다. 외부 공급자의 원래 과거 공개 판·가격 정확성 전체를 이번 verify가 보증하지 않는다. 코드 정정이 필요하면 해당 부분을 수정·재검산하며, 성공한 데이터 전부를 다시 받는 것을 기본 절차로 삼지 않는다.

표본에서 출처/접근이 막혀 계산 구현·장기 수집을 하지 못했다면 그 근거를 짧게 회신하고 종료 판정을 요청한다. 이를 위해 형식적인 구현 완료나 검증자 라운드를 만들지 않는다.

## 8. 결과 판정과 다음 연구 연결

자료별로 `ARCHIVE_READY`(사본 확보·정의/검산 확인), `PARTIAL`(일부 범위·필드만 확보), `SOURCE_UNAVAILABLE`(해당 과거 범위 미제공), `ACCESS_BLOCKED`(인증/IP/이용 접근), `FETCH_FAILED`(통신·구조·예산 중단)를 원인과 함께 기록한다. HTTP 200만으로 첫 상태를 부여하지 않는다. 공급자 공지 없이 빈 과거 응답만 나온 경우 '해당 요청일 미확보'라고 쓰며 제공 불가를 확정하지 않는다.

**ARCHIVE_READY는 수집 사본의 상태다. ML 효용·학습 표본 충분성·과거 공개 판 일치·새 미사용 시험 확보를 뜻하지 않는다.** 자료 하나가 부분 상태여도 다른 자료의 확인된 범위를 버리지 않는다. 전체 2014년 이력이 없다는 이유만으로 모든 회고 연구를 금지하지 않는다.

결과서의 핵심은 다음 표다.

| 자료 | 요청/실제 범위·유효 개수 | 날짜·단위 대조/미확인 | 고정 가격 판과 공통 범위·주 수 | 후속 사용 한계 |
|---|---|---|---|---|
| 코스피 수급 | | | | |
| 원/달러 | | | | |
| WTI | | | | |
| 세 자료 공통 | | | | |

시장 공통 입력의 독립 시간 표본은 날짜·주 단위로 센다. ETF가 많다는 이유로 시장 관측 주 수도 늘려 세지 않는다. 상관·모델·정답·수익·순위·선별 효용은 이번에 계산하지 않는다. 범위/개수와 단위/값 일치 대조는 허용한다.

사본이 준비되면 설계자는 **추가 시장 입력의 효과를 비교하는 고정 실험 하나**를 다음 실행 설계로 정한다. 대상·정보 이용 지연·목표·시간 분할·모델·기준선·공통 운용·비용·판정·탐색 예산을 성과 계산 전에 확정한다. H1과 같은 기간을 쓰는 부분은 '이미 본 기간의 회고 비교'로 공개한다. 자료를 새로 내려받았다는 이유로 새로운 미사용 시험이라고 부르지 않는다.

당시 원본이 없다는 이유로 추가 수집 몇 년을 자동 요구하지 않는다. 반대로 회고 비교의 좋은 숫자만으로 운영에 승격하지 않는다. 준비 자료가 부족하면 이번에 확인한 제한과 다음 선택지만 한 번 보고한다. 다른 원천 조사·조건 완화·새 실험을 자동으로 이어 붙이지 않는다.

POC6-12 총수익 미확보는 유지한다. 이는 가격 기준의 회고 연구 자체를 막는 조건이 아니며, 그 결과를 분배금 포함 최종 투자 효용으로 주장할 수 없다는 제한이다. D20·60일 목표·H1 채택 수치를 이번 수집에서 다시 정하거나 자동 승계하지 않는다.

## 9. 짧은 PLAN·승인·마무리

PLAN은 아래 네 묶음만, 읽기 전용 구조 확인으로 작성한다.

1. 기존 인증·수급/Yahoo 어댑터·코스피/봉인 reader의 재사용 위치, 날짜/단위 검사, 실제 표본 날짜.
2. 연구 전용 코드의 최소 추가 범위와 저장 구조. 설치 없이 가능한지, 공유 코드 변경이 필요한 정확한 이유.
3. 요청 수·시간 추정, 읽는 기존 입력 경로/해시, A→B 조건과 중단 기록 방식.
4. 유효한 승인 범위와 부족한 승인. 실제 충돌·의미 미확인만 질문하며 기존 표·PUSH·OCI 전체 재조사는 하지 않음.

PLAN 판정 뒤 **등록 IP 망의 외부 자료 조회(A와 조건부 B 전체)·연구 폴더 쓰기·필요한 코드/문서 커밋·push**를 한 묶음으로 제시한다. 이번 설계 요청은 실제 계정 접속·대량 조회를 즉시 실행하라는 승인이 아니다. 기존 세 기반 문서는 관련 연구/운영 경계와 실제 충돌이 있을 때만 필요한 한정 문장을 올린다. 단계마다 자동으로 예외 문장을 추가하지 않는다.

순서는 **짧은 PLAN → 판정·필요 승인 → 최소 구현/격리 확인 → A → 조건부 B → C/검산 → 결과서와 실제 report.md/json → 검증·설계자 RESULT 판정**이다. 정상 수집 경로의 구현 검증은 §7에 묶고, 중간 조회 결과마다 재판정을 요구하지 않는다. 커밋·push는 승인 범위로 수행한다. 사용자 소유 handoff와 원자료는 공개 git에 넣지 않는다. 같은 POC6의 별도 handoff, OCI pull·배포는 없다. 로컬 GPL 연구 브랜치는 사용·병합·push하지 않는다.

현재 05·06·13·17 운영과 ML 미승격, Q6 OPEN·백로그 #3/#55/#57/#62 미완료를 유지한다. 이번 완료는 **과거 자료를 사용하는 다음 연구의 입력 확보**이며 프로젝트 추천·ML 목적의 완료가 아니다.
