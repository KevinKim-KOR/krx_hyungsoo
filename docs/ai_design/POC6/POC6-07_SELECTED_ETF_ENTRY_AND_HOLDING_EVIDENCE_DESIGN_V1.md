# POC6-07 — 선택 ETF의 진입·보유 검토 근거 연결 DESIGN V1

작성: 설계자 · 2026-10-23 · 상태: 개발 PLAN·전체 화면 목업 요청

**목적: 선택한 ETF의 가격 흐름·동일 기간 비교·거래량에 종목 자체의 MA20·MA60 위치를 보태고, 그 근거를 기존 AI 검토 흐름에 그대로 전달한다. 사용자는 진입 검토와 보유 점검에서 유리한 근거·반대 근거·부족한 정보를 함께 검토할 수 있다.**

## 0. 이번에 결정한 범위

| 항목 | 결정 |
|---|---|
| 새 관측값 | 선택 ETF의 MA20·MA60과 종가/두 평균의 위치 관계 |
| 재사용 | 기존 가격 흐름·같은 기간 KODEX200 대비·거래량·흔들림·자료 상태 |
| 사용자 흐름 | 「요즘 잘 오르는 ETF」 → 「보유와 비교」의 기존 판단 근거 미리보기 → 복사/AI 투자 세션 |
| 진입점 | 기존 미리보기가 지원하는 후보·보유 ETF 선택. 새 메뉴·새 진입 버튼 없음 |
| 검토 질문 | 미리보기 원문에 진입·보유·부족 정보 질문을 넣고 같은 글을 복사·전달 |
| 처리 장소 | PC의 기존 저장 자료·미리보기 조립/화면 |
| 운영 영향 | 새 외부 조회·DB 표·API 경로·의존성·OCI 반영·cron·PUSH·PARAM 변경 없음 |

본 단계는 관측 근거와 검토 흐름의 보완이다. 무릎·머리·어깨 기준, RS·거래량·정배열의 복합 점수, 위험 등급, 매수/매도 신호를 정의하지 않는다. 기존 AC-10/AC-12와 Q6 OPEN을 유지한다. 새 ML 학습·feature 실험·모델 승격은 하지 않으며 POC6-06의 고정 recipe와 전향 기록은 독립적으로 계속 운영한다.

## 1. 사실 확인에 따른 판단

- 개발자 2026-10-23 읽기 전용 보고를 수용한다. 이미 있는 개별 지표를 새로 만드는 단계가 아니다. 확인된 기능 공백은 종목 자체의 MA20·MA60/위치 관계다. 기존 시장 국면의 이동평균은 KODEX200의 값이므로 선택 ETF의 추세로 대신 읽으면 안 된다.
- 05의 한 일일 창에는 종목과 KODEX200, 최근 종가·거래량이 함께 있다. 24종 초기 장기 사본에도 OHLCV가 있다. 다만 이번에는 PC 화면의 데이터 정본을 보관소로 전환하지 않는다. 기존 미리보기의 PC 가격 기준일을 따라 계산한다.
- 서로 다른 ticker의 온전한 계열을 같은 날짜로 비교하는 것과, 한 ticker의 서로 다른 조정 가격 창을 이어 붙이는 것은 다르다. 초기 24종과 다른 판의 KODEX200으로 RS를 검토하려면 가격 의미·기간·가용성을 별도로 정해야 한다. 이번에는 그 장기 연구나 추가 수집을 시작하지 않고 기존 동일 기간 RS를 재사용한다.
- PC 파생 표 `etf_ml_feature_daily`의 08-27 값은 사용하지 않는다. 그 표를 재생산하거나 멈춘 원인을 조사할 필요도 없다. 새 관측값은 현재 선택 근거와 같은 원시 저장 종가에서 만든다.
- 해석은 기존 AI 검토 흐름이 담당한다. 시스템 안에 별도 종합 해석 엔진·AI 호출·토론 기능을 만들지 않는다. 시스템은 정확한 수치·기간·불확실성과 질문을 전달한다.

## 2. 사용자가 보게 되는 것

기존 판단 근거 미리보기의 **가격 흐름 묶음 안**에 다음을 더한다. 기존 6개 근거 묶음은 유지하고 새 일곱 번째 관측 카드는 만들지 않는다.

1. `종목 이동평균: MA20 [값]원 · MA60 [값]원`
2. `표시값 기준 위치: 종가 > MA20 > MA60`와 같은 실제 관계
3. 기존 가격 흐름 기준일과 다른 날짜를 만들어 붙이지 않는다. 이동평균 계산 기간은 해당 항목의 설명/펼침에서 확인할 수 있다.

원문 끝에는 다음 검토 질문을 줄별로 붙인다.

> 진입 검토: 이 ETF를 검토할 때 유리한 근거와 반대 근거는 무엇인가요?
> 보유 점검: 이미 보유 중이라면 어떤 변화와 주의 요인을 확인해야 하나요?
> 판단 한계: 지금 자료로 판단할 수 없는 부분과 추가 확인할 정보는 무엇인가요?

이 질문은 고정된 검토 관점이며 사용자에게 매일 평가·매매 의사를 입력시키는 폼이 아니다. AI 답변이나 매매 결론은 자동 생성하지 않는다.

### 2-1. 배치·표현

- 이동평균 값과 위치는 미리보기에서 바로 보인다. 정의·기간의 자세한 설명은 기존 `?` 체계에 넣는다. 새로운 접힘 버튼을 하나 더 두지 않는다.
- 값이 하나만 계산되면 계산되는 값과 나머지의 짧은 사유를 보인다. 자료 문제가 있으면 도움말에만 숨기지 않는다. 관계를 만들 수 없으면 위치는 확인 불가다.
- 위치는 중립적인 관측이다. ‘좋음/나쁨’, ‘안전/위험’, ‘진입 적기’, ‘무릎/어깨’, ‘매수/매도’ 배지를 붙이지 않는다. 일반 가격 등락의 기존 색 규칙은 유지하고 위치 관계에 경보색을 붙이지 않는다.
- 질문은 각각 줄을 나눠 표시한다. 설명 문단을 모든 근거 아래 반복하지 않는다. 미리보기 전체 화면의 높이·정렬을 목업에서 확인한다.
- 기존 차트·차트 기간 선택·상세 위치·정렬·필터·종목 선택·종목 합산값은 그대로다. 이번에 가격·거래량 차트를 또 개편하지 않는다.

## 3. 이동평균 계산 계약

### 3-1. 기준과 정의

- 대상은 기존 미리보기가 ETF로 확인한 선택 ticker 한 개다. 여러 계좌의 같은 종목도 같은 관측값을 쓴다. `0015K0`와 같은 영숫자 식별자를 원형 그대로 보존한다.
- D는 **그 미리보기의 가격 흐름이 실제로 사용하는 종목 기준일**이다. 실제 키/전달 접점은 PLAN에서 확인한다. 전체 ETF 최신일·오늘 날짜·실시간 현재가·NAV로 대신하지 않는다.
- MA20 = D를 끝으로 한 최근 20개 저장 종가의 단순평균, MA60 = 최근 60개 저장 종가의 단순평균이다. D 종가는 포함한다. 가격 단위는 원이며 시각·가격 의미는 기존 PC 가격 근거와 같다.
- `종가`는 이 계산의 D 저장 종가다. 계좌 평단이나 별도 실시간 현재가를 넣지 않는다. 비교 대상 세 값의 이름을 관계식에 적는다.
- 관계식은 화면에 표시하는 소수 둘째 자리 수치로 비교한다. 동률은 `=`로 묶고 제목에 ‘표시값 기준’을 붙인다. 내부의 미세한 차이 때문에 같은 표시값에 `>`를 붙이지 않는다. 기존 최종 숫자 포맷터를 재사용하고 별도 Python/JS 포맷 규칙을 새로 만들지 않는다.
- ‘정배열’ 여부만 boolean으로 내려 주거나 이를 점수화하지 않는다. 종가·MA20·MA60의 실제 순서를 보여 준다.

### 3-2. 기간별 검증

- D 이하 원본 행을 읽는다. 비정상 종가 행을 먼저 거른 뒤 더 오래된 행을 끌어와 개수를 채우지 않는다. MA20은 끝 20개, MA60은 끝 60개 창을 각각 검증한다.
- D의 종가 없음·기준일 불명·기존 가격 기준과 불일치, 창의 행 부족·중복 날짜·유한 양수 아닌 종가·기존 규칙의 날짜/가격 연결 문제를 사유로 구분한다. 날짜 축·연결 경계는 기존 PC 가격 기준/06 연결 검사 접점을 재사용한다. 별도 경계 탐지 모델은 만들지 않는다.
- MA60 창만 문제가 있으면 MA20까지 무조건 숨기지 않는다. 경계가 창 밖에 있는 경우를 창 안 문제로 확대하지 않는다. 두 값과 D 종가가 모두 유효할 때만 전체 위치를 만든다.
- 계산 기간은 각 평균에 사용한 시작일→D, 저장 종가 수를 남긴다. ‘20일/60일’이 달력일 평균이나 장중 이동평균으로 읽히지 않게 도움말에서 ‘20/60개 저장 종가’를 명시한다. 자료 구멍을 지워 연속 거래일이었다고 설명하지 않는다.
- 기대된 자료 검사 실패는 해당 관측의 사유로 처리한다. 실제 DB 읽기 실패 같은 시스템 오류는 기존 오류 계약을 따르며 정상적인 자료 부족으로 위장하지 않는다.

## 4. 자료 접점과 API 범위

- 현재 미리보기가 재사용하는 두 PC 응답과 선택 종목 조립 접점을 유지한다. 이동평균 계산은 선택 종목·D의 동일한 가격 근거에 연결한다. 기존 5·10·20일 변화/동일 기간 RS·거래량을 다시 다른 정의로 계산하지 않는다.
- 선택 종목에 필요한 PC read-only 조회 한 번을 추가하는 안은 허용한다. 필요한 원본 60개(기존 읽기와 공유할 때 최대 61개)를 읽고, 전체 ETF에 대해 매번 새 MA 조회를 돌리지 않는다. 실제 접점·추가 조회 수·동일 D/가격 기준을 유지하는 방법을 PLAN에서 적는다.
- 기존 가격 근거 입력과 새 평균의 자료가 같은 D·가격 기준을 공유해야 한다. 수신 중 갱신 등으로 서로 모순되는 입력을 발견하면 해당 추세 관측을 확인 불가로 두고 사유를 남긴다. 서로 다른 판을 몰래 맞춰 수치를 만들지 않는다.
- 기존 미리보기 응답에 선택 필드를 추가하고 UI와 canonical 원문을 같은 서버 조립 결과로 만든다. 새 API 경로는 추가하지 않는다. 큰 기존 파일에는 작은 연결만 두고 새 PC 전용 모듈로 분리할 수 있다.
- PC 가격 자료가 10-20까지라면 이 관측도 그 날짜 기준이다. 05를 pull했다고 PC 시장 DB가 최신화됐다고 쓰지 않는다. 이번에 05/PC 전체 가격 정본 전환·수집 버튼 변경을 함께 하지 않는다.
- 후보의 자기 기준일과 보유의 가격 기준일 처리 차이 등 기존 22/23 판정은 보존한다. 같은 기간 RS의 날짜가 맞지 않으면 기존 사유를 유지하고 대체값을 넣지 않는다. 해외 자료/VIX의 서로 다른 날짜를 억지로 D로 맞추지 않는다.
- 개별주·ETF 구분 확인 불가 등은 기존 미리보기의 처리 범위를 따른다. 이번 새 이동평균 관측은 ETF만 대상이며 대상 밖을 ETF로 추정하지 않는다.

## 5. 복사·AI 세션 연결

- 화면에서 보는 미리보기, `[복사]` 내용, `[AI 세션에서 검토]`에 넘기는 원문은 **한 canonical 문자열**이다. 이동평균 관측과 §2 질문도 여기에 포함한다. 클라이언트가 따로 요약·수치 재계산을 하지 않는다.
- 질문 문자열만 뒤늦게 붙여 미리보기와 전달문을 다르게 만들지 않는다. 기존 AI 세션은 넘어온 원문을 질문 초안으로 받고, 사용자가 질문을 고친 뒤에도 원래 근거를 별도로 보존하는 현 계약을 유지한다.
- 선택 종목·목록 조건·원래 질문/근거·새 초안 덮어쓰기 확인·기록 저장/재조회 연결은 기존 24 계약을 재사용한다. 새 AI 모델/API·자동 답변·새 세션 표·기록 일괄 변환을 추가하지 않는다.
- 예전에 저장한 세션은 당시 원문 그대로 읽힌다. 새 이동평균이 없다고 과거 기록을 손상으로 처리하거나 현재 값으로 덧붙이지 않는다.
- 해석용 원문에는 자료 기준·원천·계산 못 한 사유를 유지한다. 이동평균/RS/거래량이 매수 적기나 향후 수익을 입증한 것으로 쓰지 않도록 기존 한계 설명과 `?`에 연결한다.
- 계좌·수량·평단·메모를 새 입력으로 추가하지 않는다. 세션/미리보기의 기존 개인 정보 경계를 유지한다. 개인 검토문을 OCI 증거 보관 대상으로 확장하지 않는다.

> 자료 범위(2026-10-23): 코스피 시장 전체의 투자자별 순매수는 POC6-01/05로 수집·보관한다. 종목별 외국인·기관 수급은 미수집이며 시장 전체 수급을 종목 수급으로 대체하지 않는다. Q6 운영 계약은 OPEN이고 이 자료 확보만으로 종합 위험 분류의 검증이 완료된 것은 아니다.

## 7. 개발자 PLAN과 전체 화면 목업

다음 순서로 진행한다: **짧은 조사 → PLAN·전체 화면 목업 → 사용자 목업 확인 → 설계자 PLAN 판정 → 구현**. 목업은 개발자가 만든다. 설계자에게 다시 원 요구/전체 소스를 조사시키기 위한 자료를 요청하지 않는다.

PLAN에는 다음 5개만 적는다.

1. 현재 미리보기의 후보/보유 분기·선택 종목·가격 기준일·canonical 문자열·복사/세션 전달 접점. 이미 확인된 경로는 재사용한다.
2. 동일 D의 원본 60/61개 읽기·기존 연결 검사·추가 조회 횟수·응답 선택 필드. 기존 숫자 포맷터와 표시값 순서 비교 방법.
3. 새 모듈/변경 파일·KS-10. 기존 큰 파일의 책임을 넓히지 않고 연결하는 방법. 공유 PUSH 계산·OCI 소비 코드 변경이 없는지 확인.
4. 아래 목업의 실제 자료/fixture 구분과 사용자 확인 결과. 기존 근거 묶음·질문 줄바꿈·`?` 위치·정보량.
5. 의미 있는 검증·기존 세션 하위 호환·배포 범위. 설계와 실제 코드가 부딪히는 곳만 질문한다.

목업은 사용자 PC 저장 자료를 한 번 읽어 현재/변경안을 같은 응답·1440px/1000px 전체 화면으로 비교한다. 선택 상세와 미리보기의 주변 문맥까지 보여 준다. AI 세션 수신은 실제 전달 텍스트가 같은지 함께 제시한다. 개인 자료는 기존처럼 로컬 목업으로 두고 게시하지 않는다.

실제 자료로 후보·보유 ETF를 보여 주고, 없는 상태는 격리 fixture로 보여 준다: 두 평균 유효·동률, MA60만 부족, 가격/기준일 문제, 이동평균 필드 없는 과거 세션. 실제 라이브 DB·보유·세션 원본은 바꾸지 않는다. 승인받은 목업과 구현의 차이는 RESULT에서 명시한다.

## 8. 검증과 완료

1. 산술이 알려진 경로로 MA20/60을 독립 대조한다. 일정 가격의 동률, 오래된 부분만 문제인 창, D 이후 가격 배제·잘못된 종가·행 부족·대상 밖·영숫자 ticker를 확인한다. 표시 숫자와 관계식이 맞아야 한다.
2. 같은 종목·여러 계좌에서 관측은 같고 기존 합산 비중·손익은 바뀌지 않는다. 기존 동일 기간 RS·거래량·가격 흐름 결과와 소스 선택 정책을 바꾸지 않는다.
3. 후보/보유 미리보기·복사·AI 세션 전달 문자열이 같고 새 초안 확인·수정 질문/원문 보존·과거 세션 재조회가 유지된다. 해당 경로의 계약을 검증하며 모든 과거 세션을 다시 만들지 않는다.
4. 실제 PC 조회와 사용자 실화면에서 선택 ETF의 숫자·기간·`?`·질문 줄바꿈·세션 전달을 확인한다. 실제 매매 입력이나 개인 세션에 시험 기록 저장을 강제하지 않는다.
5. 변경 범위 검사와 저장소 필수 검증을 수행한다. 통과 후 이유 없이 전체 회귀·POC6-02/04 학습·06 전향 실행을 반복하지 않는다. 검증자 판정 후 설계자 RESULT 판정을 받는다.
6. 사용자 승인 범위로 커밋/push·PC 반영·종료 기록을 정리한다. PC 전용 접점만 바꾸므로 OCI pull·키·cron·원격 업로드는 없다. 실제 코드상 이 범위를 지킬 수 없으면 PLAN에서 먼저 질문한다.

이 단계가 끝나면 선택 근거 생성→진입·보유 검토 질문→AI 세션 저장/재조회의 기능 범위로 마무리한다. 이후 새 화면이나 모델 실험을 자동으로 붙이지 않는다. 현재 버전의 기능 충족분·미채택/미검증 한계·계속 쌓이는 연구 운영을 함께 놓고 다음 범위를 별도 판단한다. 같은 POC6 안이므로 handoff 문서는 만들지 않는다.
