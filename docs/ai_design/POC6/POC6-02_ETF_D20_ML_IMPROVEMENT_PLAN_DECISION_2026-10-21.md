**PASS_TO_IMPLEMENT_WITH_CORRECTIONS. Q1은 (b) 최소 ETF 4종, Q3은 개발자 해석을 채택한다. Q2는 맥북에서 CPU 개발·실행, Windows에서는 작은 GPU 실행 묶음만 돌리는 방식으로 정한다. 아래를 PLAN에 반영하고 재제출 없이 구현한다.**

## 1. Q1 — 최소 4종으로 정정, 가격 경계는 유지
- 최소 5종은 설계자가 정한 연구 범위였으며 통계적 충분성의 보장 기준이 아니었다. 성과 미열람·공식 잠금 전인 지금 최소 수를 4종으로 바꾼다. 최초 기준 5종과 변경 이유를 recipe/보고서에 보존한다.
- 현재 적격 4종(PLAN 실측): 367760 · 381170 · 395160 · 442580. 학습 252일·구간별 시험 42/63일·3구간·동일 표본·목표·feature·모델·5% 개선 기준은 그대로다.
- 2026-04-20과 다른 가격 경계는 기존 06 판정대로 유지한다. 서로 다른 수집 묶음의 가격 기준 불일치가 의심되는 지점을 임의로 연결하거나 change를 고쳐 통과시키지 않는다. 분배금 조정이라는 원인 추정과 경계 검출 사실을 구분해 적는다.
- 이번에는 가격을 새로 받거나 라이브 시세 DB를 수리하지 않는다. 누락·기준 차이가 있는 ETF가 제외됐다는 사실은 그대로 보고한다.
- **결과 범위는 이 4종에 한정한다.** 소수·유사 투자 스타일의 ETF이며 시장 전체·현재 보유 ETF 26종의 개선 입증으로 확대하지 않는다. 수천 행을 독립적인 수천 사례로 부풀리지 않는다. 유망 판정도 이 한정된 회고 연구의 채택 후보다.
- 적격 판단만 다시 계산하고 성과와 무관하게 대상·입력·기준을 잠근다. 성과가 나쁜 뒤 종목·기간·설정을 바꾸지 않는다. 실제 snapshot에서 4종도 충족하지 못하면 기존 DATA_SHORT 규칙을 쓴다.

## 2. Q3 — 42/63의 뜻
개발자 해석이 맞다. **ETF 각각이 각 구간에서 유효 시험 날짜 42일 이상을 갖는 조건**이다. 네 방법의 '공통'은 같은 ETF×날짜 행으로 비교한다는 뜻이다. 적격 ETF 전부의 날짜 교집합이 42일 이상이어야 한다는 추가 조건은 두지 않는다.

날짜 균형 MAE는 해당 날짜의 유효 ETF 행을 평균한 뒤 날짜별로 평균한다. 날짜별 ETF 수·실제 평가 날짜 수와 제외 사유를 남긴다. ETF마다 다른 날짜 분모를 숨기거나 방법별로 시험 행을 바꾸지 않는다.

## 3. Q2 — Windows에 전체 프로젝트를 다시 설치하지 않는다
맥북 개발·PC 실행이라는 사용자 흐름을 유지한다. 네 방법 모두를 RTX PC에서 실행하자는 PLAN 제안은 필수가 아니다. 다음으로 바꾼다.

| 위치 | 작업 | 필요한 것 |
|---|---|---|
| 맥북 | snapshot·표본 생성, MEDIAN/RIDGE/HGB 공식 실행, MLP CPU 시험, 결과 취합 | 기존 저장 자료·현재 개발 환경 |
| RTX PC | GPU MLP 공식 학습·예측, 같은 MLP의 CPU/CUDA 짧은 속도 비교 | 필요한 연구 코드만 담은 묶음·실험 입력·사용 가능한 Python/PyTorch CUDA |
| 맥북 | GPU 예측을 같은 시험 행에 연결, 네 방법 지표·최종 보고서 작성 | PC 결과 파일 |

**PC에 전체 저장소·시장 DB·보유 파일·scikit-learn·Next/백엔드 서버·키움/API 키를 요구하지 않는다.** Python 3.12로 맥북과 버전을 억지로 맞추지 않는다. 현재 설치된 Python/PyTorch에서 실행 코드와 CUDA가 지원되는지 먼저 확인하고, 그 환경으로 지원되는 버전을 recipe에 적는다.

### 3-1. 작은 실행 묶음
- 맥북에서 필요한 학습 코드·고정 recipe·실험 입력·Windows 실행 안내를 한 묶음으로 만든다. CPU/GPU 학습 본문을 별도 구현으로 복제하지 말고 같은 MLP 코드를 재사용한다. 필요한 파일 구성은 개발자가 정한다.
- 입력은 구간별 학습 feature·정답·가중치와 시험 feature·행 ID, 해당 학습 구간에서 확정한 변환/입력 근거다. 시험 정답을 GPU 학습에 사용하지 않는다. ticker·가격 표본은 있을 수 있지만 개인 수량·평단·계좌·메모·비밀값은 제외한다.
- 사용자는 묶음을 PC에 옮기고 준비된 실행 파일/명령 한 개를 실행한다. 기존 Python 환경 활성화가 필요하면 해당 방법까지 짧게 안내한다. 전체 저장소 pull·개발 서버 실행·새 시장 수집을 요구하지 않는다.
- 시작 시 Python·torch·CUDA·장치만 확인한다. GPU가 없거나 torch가 CPU 전용이면 원인을 적고 GPU_NOT_RUN으로 끝낸다. CPU로 조용히 바꿔 성공 처리하지 않는다.
- 환경이 없으면 필요한 GPU 연구 환경 설치 범위만 한 번 제시한다. 자동 전체 설치·프로젝트 의존성 교체·새 VM/원격 서비스 구축으로 확대하지 않는다. 설치 승인 전에도 맥북 구현·CPU 검증은 진행한다.
- PC는 GPU 시험 예측·재현/자원 측정·환경과 입력 digest를 파일로 반환한다. 맥북이 study ID·입력/recipe digest·구간·행 ID의 완전한 일치를 확인해 합친다. 누락·중복·다른 실험 결과는 거절한다. CPU 결과를 GPU 결과를 본 뒤 다시 유리하게 고르지 않는다.

### 3-2. 비교의 정확한 의미
- 모델 오차는 동일한 ETF×날짜·정답에 맞춰 맥북 CPU 후보와 PC GPU 후보를 비교한다. 운영체제/라이브러리 차이는 공개하며 장치 간 bit 동일성을 요구하지 않는다.
- **GPU 가속 효과는 RTX PC 안에서 같은 MLP·자료·작업량의 CPU/CUDA 실행으로만 비교**한다. 맥북 HGB와 Windows MLP의 시간 차이를 GPU 가속 배수로 쓰지 않는다.
- CPU/GPU의 자원 예비 측정은 기존 설계의 한도 안에서 수행한다. 입력이 작은 탓에 전체 코어/GPU가 덜 쓰이면 그대로 기록한다. 이 실험을 장비 물리 성능 한계까지 시험한 것으로 쓰지 않는다.
- GPU가 없어도 CPU 부분 산출물은 만들 수 있다. 실제 GPU 한 번의 실행은 남으며, 이를 아예 하지 않고 RTX 활용 완료라고 선언하지 않는다. 사용자에게 GPU 실행 보류를 다시 묻는 것을 현재 개발 착수 조건으로 두지 않는다.

## 4. PLAN의 나머지 판단
- 06의 목표·feature·Ridge·연구 축·가격 경계와 작은 공개 median 접점 재사용을 수용한다. 광범위한 기존 코드 정비는 하지 않는다.
- input snapshot→run 분리, 읽기 전용·라이브 불변·외부 호출 0과 최소 산출물 계획을 수용한다. PC 실행 묶음 생성·GPU 결과 취합을 같은 CLI에 필요한 작은 동작으로 더한다. 새 서비스나 별도 개발 단계가 아니다.
- 재현 허용값 제안(MEDIAN/RIDGE/HGB 같은 장비에서 동일, MLP 예측 차이 최대 1e-6)을 수용한다. PyTorch의 장치·버전 간 완전 재현을 요구하지 않는 기존 계약을 유지한다. 성과 경계 근처는 PLAN대로 표시하며 결과에 맞춘 seed 변경은 없다.
- GPU 부분의 'torch 없음' 처리는 CPU 경로 전체 실패가 아니라 GPU_NOT_RUN이다. 데이터 손상·학습 오류·GPU 부재는 구분한다.
- 백로그 ML 4건은 이번 목표로 해결되지 않는다는 대조를 수용한다. 조건부 아이디어 3건은 승인된 보관 범위대로 기록하고 지금 개발 대상으로 만들지 않는다.
- POC6-01의 원격 반영은 최신 PLAN 보고에 따라 e525dc37 push 완료로 정정한다. 과거 'push 미완료'는 당시 경과로 보존할 수 있으며 별도 정정 커밋은 필요 없다.

## 5. 진행·종료
1. 본 판정을 원문으로 저장하고 PLAN의 최소 ETF 수·Q3·PC 실행 방식을 반영한다. 전체 설계/PLAN 재작성·재제출·새 목업은 필요 없다. 기존 설계와 충돌하는 위 항목은 본 판정을 우선한다.
2. 맥북에서 구현·시험·공식 CPU 결과·GPU 실행 묶음 준비까지 진행한다. PC 환경 확인 답을 기다리며 멈추지 않는다.
3. 같은 잠긴 실험의 GPU 부분을 PC에서 한 번 실행하고 맥북에서 취합한다. 이는 **하나의 연구 실행을 장비별로 나눈 것**이다. 네 방법 전체를 PC에서 다시 돌릴 필요는 없다.
4. RESULT에 4종 한정 결과·제외 22종·가격 경계·장비/버전 차이·자원 실측과 판정 이유를 적고 기존 검증·설계자 RESULT 절차로 진행한다. GPU가 미실행이면 부분 완료 상태를 명시한다. 자료가 작다는 이유로 새 수집·무한 튜닝·장시간 부하 시험을 더하지 않는다.

키움·Yahoo·KRX 추가 조회, 회사 IP 등록, 새 데이터 준비는 이번 작업의 조건이 아니다. 미래에 전체 ETF 적용을 원할 때의 자료 일관성 문제와 이번 4종 연구를 구분하며, 이번 유망/기각을 전체 ML 가능성의 증명/부정으로 확대하지 않는다.
