### B-1. 현재 문제와 이번 Step의 단일 목표

2026-11-06 개발자의 「자금·비중 계약 확인 — 사실 회신」을 수용하고, 해당 읽기 전용 확인은 완료로 처리한다. 설계자가 현재 저장소를 직접 검사했다는 뜻은 아니다.

확인된 사실은 다음과 같다. 이 네 항목을 다시 조사하지 않는다.

- 현재 종목 시장 비중의 분모는 시세가 있는 주식·ETF 평가액 합계다. 현금은 포함되지 않는다.
- 현금·투자 총예산·추가 투입 한도의 입력·저장 기능은 없다.
- AI 세션으로 전달되는 선택 종목 근거는 평가비중·손익률이며, 비중의 분모 설명은 없다.
- 현재 보유 매입금액은 보유 수량 × 평단이다. 누적 납입원금이나 투자 총예산이 아니다.

PLAN의 추가 확인도 수용한다. holdings_latest.json은 OCI 반영 때 문서 전체가 전달되므로 자금 값을 넣지 않는다. 자금 부가정보는 같은 폴더의 capital_context.json 한 파일에 따로 두고 git 제외한다. 기존 PC AI 세션 원문은 PC의 decision_evidence.sqlite에 저장되며, 이 Step에서 새로운 OCI 전달을 만들지 않는다.

**단일 목표: 사용자가 선택한 현금과 이번 검토의 추가 매수 상한을 구분해 기록하고, 분모와 기준일이 명시된 같은 자금 맥락을 보유 화면에서 확인하여 선택 종목의 AI 검토로 전달한다.**

POC6-23은 최종 보고 HEAD 1a4a4698의 CLOSED 상태를 유지한다. 이 Step은 새 ML 연구가 아니며, 운영 ML 효용·비용 후 KODEX200 초과성과·총수익 검증의 미완료 상태를 바꾸지 않는다.

### B-2. 입력과 금액의 뜻

범위는 기존 보유 목록의 모든 계좌를 합산한 한 묶음, 통화는 원화다. 계좌별 현금 원장은 만들지 않는다.

| 항목 | 이번 계약 |
|---|---|
| 검토에 포함할 현금 C | 사용자가 이 보유 목록과 함께 검토하기로 선택한 현재 현금 합계. 예수금과 선택한 외부 현금을 중복 없이 합산한다. 생활비·비상금까지 입력하도록 요구하지 않는다. |
| 이번 검토의 추가 투입 한도 A | 위 C 중 이번 검토에서 주식·ETF 추가 매수에 사용할 의사가 있는 총액의 상한. 매도대금 재투자·미래 입금은 포함하지 않는다. 실제 매수나 주문의 승인이 아니다. |
| 현금·한도 확인 기준일 | 사용자가 위 값을 확인한 날짜. 첫 입력의 기본값은 오늘(KST), 과거 날짜 입력 가능. 미래 날짜는 허용하지 않는다. 저장 시각과 구분해 보존한다. |
| 보유 평가액 V | 현재 등록 보유의 기존 평가액. 기존 평가·가격·손익 계산을 그대로 사용한다. |
| 보유+입력 현금 합계 T | 완전한 V와 입력된 C가 있을 때 V+C. 0원도 유효한 합계다. 이 목록과 선택 현금의 평가 기준 합계이며, 투자 총예산·누적 원금·사용자의 전체 재산이 아니다. |

C와 A는 선택 입력이며 원 단위의 유한한 0 이상 정수다. 공란은 미입력, 0원은 사용자가 입력한 값으로 구분한다. A가 입력되면 C도 있어야 하고 0 ≤ A ≤ C여야 한다. C만 입력하고 A를 비워 둘 수 있다. 이때 한도는 '미정'이며, C 전액을 한도로 간주하지 않는다. C가 입력되면 유효한 확인 기준일을 함께 저장한다. 둘 다 공란이면 기준일도 없는 미입력 상태다.

입력은 한 묶음으로 저장·수정·비우기가 가능해야 한다. 일부만 저장되는 상태는 허용하지 않는다. 기존 사용자는 미입력 상태로 시작하며, 기존 자료·자유 메모·개인 대화에서 금액을 추정해 채우지 않는다.

A는 검토 당시 사용자의 의사를 기록한 값이다. 매매나 입출금 뒤 C·A를 자동 갱신하거나, 누적 사용액을 계산하거나, 주문을 차단하지 않는다. 화면과 전달 근거에 **'직접 입력한 확인일 기준 값 · 거래/입출금 후 자동 반영되지 않음'**을 표시한다. 다음 검토 때 사용자가 확인·수정한다. 자동으로 날짜만 오늘로 바꾸지 않는다.

### B-3. 비중과 부분 자료 처리

기존 시장 비중·매입 비중의 정의와 필드 의미를 유지한다. 현금 도입을 이유로 기존 시장 비중의 분모를 몰래 바꾸지 않는다.

| 표시값 | 계산과 뜻 |
|---|---|
| 보유 내 평가비중 | 기존 행 평가액 ÷ 기존 시세 있는 보유 평가액 합계. 현금 제외. 부분 자료이면 부분 평가액 기준임을 명시한다. |
| 입력 현금 포함 비중 | 행 평가액 ÷ T. 모든 평가 대상 보유에 유효한 평가액이 있고 C가 입력됐으며 T > 0일 때만 계산한다. |
| 보유 / 현금 구성 | V/T와 C/T. 같은 계산 가능 조건을 적용한다. |

- 시세 없는 보유가 있으면 기존 부분 합계 경고를 유지하고, T·입력 현금 포함 비중·보유/현금 구성은 계산하지 않는다. C와 A 자체는 입력값과 기준일을 표시할 수 있다.
- C 미입력과 C=0을 구별한다. 완전한 V=0·C=0이면 합계 T는 0원으로 표시하고 비중만 계산 불가로 둔다. 합계가 0원이라는 이유로 미입력/null로 바꾸지 않는다. 보유가 없고 C>0이면 합계는 C, 현금 구성은 100%다.
- 화면의 보유 표는 기존 계좌 행 단위를 유지한다. AI의 선택 종목 비중은 기존처럼 같은 종목의 계좌를 합산한다. 해당 종목의 어느 계좌 행이라도 미평가면 '미확인'으로 두는 기존 AI 규칙도 유지한다. 두 표현의 집계 단위를 명시한다.
- 평가 가격 기준일과 현금 확인일을 함께 보여 준다. 평가된 보유의 가격 기준일 최소~최대가 여러 날짜이면 범위를 표시한다. 모든 평가 행의 가격 기준일이 현금 확인일과 같을 때만 동일 기준일이며, 범위 안에 확인일이 있다는 이유로 동일 기준으로 보지 않는다. 다르면 기준일이 다른 참고 합계/비중, 날짜를 확인하지 못하면 가격 기준일 확인 불가를 표시한다. 보유가 없으면 가격 기준일은 대상 없음이다. 새 시세 조회나 임의의 최신성 임계는 도입하지 않는다.
- 총 매입금액은 현재 보유분의 취득금액이라는 뜻을 유지한다. 이를 투입원금·총예산으로 대체하지 않는다. A는 T의 구성요소가 아니므로 합계에 더하지 않는다.

### B-4. 사용자가 수행할 과업과 화면

사용자 과업은 '현재 보유와 함께 검토할 현금은 얼마인지, 그중 얼마까지 추가 매수를 검토할지 정하고, 해당 기준이 AI 질문에 들어갔는지 확인하기'다.

#### 보유 현황

기존 HoldingsHero 바로 아래, 보유 목록보다 위에 **'자금 기준'** 영역을 기본 노출한다. 새 메뉴는 만들지 않는다.

- 기본 노출: 검토에 포함할 현금, 이번 검토의 추가 투입 한도, 확인 기준일, 보유+입력 현금 합계, 보유/현금 구성, [입력·수정]. 미입력·미정·계산 불가를 각각 표시한다.
- 입력·수정: 위 두 금액과 확인 기준일, 범위 설명, [저장]·[취소]·[비우기]. 현재 저장값과 편집 중인 값을 구분하고, 미저장 값은 계산·AI 근거에 사용하지 않는다.
- 보유 표의 기존 비중 셀: 기본 줄은 '보유 내' 평가비중, 계산 가능하면 둘째 줄에 '입력 현금 포함' 비중. 계좌 구성 막대는 '보유 평가액 기준'임을 명시하고 현금이 포함된 계좌 구성처럼 보이지 않게 한다.
- 기본 노출에 분모·부분 자료·수동 확인일을 둔다. 생활비 제외 안내, 매입금액/누적 원금의 차이, 자동 반영 한계의 상세 설명은 도움말로 보완한다.
- 저장 실패: 입력값을 유지하고 사유를 표시한다. 기존 저장값을 성공한 새 값처럼 바꾸지 않는다. 불러오기 실패: '자금 기준 확인 불가'로 표시하고 0원으로 취급하지 않는다. 기존 보유 조회와 판단 흐름은 사용할 수 있다.

제출된 목업의 자금 영역과 종목 비중 셀 배치는 사용자 확인을 수용했다. 구현에서는 해당 배치를 재현하고, 기본 화면에서 금액·분모·확인일·입력 동작이 보이는지 확인한다.

#### 선택 종목 근거 → AI 투자 세션

기존 「요즘 잘 오르는 ETF」 → [보유와 비교] → [판단 근거 미리보기 생성] 흐름을 유지한다. 미리보기 본문에 **'보유·자금 기준'** 묶음을 기본 표시한다.

포함할 내용은 보유 평가액과 평가 범위/기준일, C·A와 확인일, T의 뜻과 계산 가능 여부, 선택 보유 종목의 두 비중과 집계 단위다. 원문에 새로 넣는 금액은 V·C·A·T 네 종류에 한정하며, 개별 종목의 평가금액은 넣지 않는다. 기존 [대상]의 평가비중은 이 묶음으로 옮겨 한 번만 표시하고 손익률의 기존 의미·집계는 유지한다.

선택 출처가 후보여도 현재 등록 보유에 같은 종목이 있으면 '후보 · 현재 보유 중'으로 표시하고 같은 종목 모든 계좌를 합산한 두 비중을 적용한다. 출처·후보 순위·필터는 바꾸지 않는다. 보유 여부는 시세 유무와 분리하여 판정한다. 등록 보유의 일부가 미평가라면 현재 보유 중이라는 사실은 유지하고 해당 비중은 미확인으로 둔다. 실제 미보유 후보는 '후보 · 현재 보유 아님 — 보유 비중 없음'으로 구분한다. 미입력과 읽기 실패, 부분 평가도 각각 설명한다.

질문에는 '현금 보유를 추가 매수 승인으로 해석하지 않고, 입력된 추가 투입 한도와 기준일·포함 범위를 전제로 검토'한다는 맥락을 넣는다. 새 매수/매도 판단 규칙이나 자동 추천을 생성하지 않는다.

미리보기의 복사·AI 세션 전달 버튼 근처에 '복사·AI 세션 원문에 보유 평가액·현금·한도·합계 금액이 포함됩니다. 외부 AI에 붙여 넣으면 해당 금액도 전달됩니다'라는 안내를 기본 표시한다. 도움말만 열어야 알 수 있게 숨기지 않는다. 별도 팝업이나 새 승인 기능을 만들지는 않는다.

미리보기 표시·[복사]·[AI 세션에서 검토]로 넘기는 글은 같은 원문이다. 생성 당시 저장값을 원문에 고정하고, 그 뒤 자금 값을 수정해도 이미 생성된 글이나 저장된 세션을 다시 쓰지 않는다. 새 값을 반영하려면 [다시 생성]한다. AI 세션은 기존 질문/선택 근거 원문 저장 경로를 재사용하며, 자금 전용 세션 모델·별도 이력 표는 만들지 않는다. 기존 세션과 다른 진입 화면의 동작은 유지한다.

현금·한도가 미입력이거나 읽기 실패여도 기존 미리보기·AI 세션 사용을 막지 않는다. 어떤 자금 정보가 확인되지 않았는지 원문에 남긴다.

### B-5. 변경 경계와 재사용

- 추가 범위: 현재 보유 범위에 대응하는 개인 자금 부가정보 한 묶음의 입력·저장·읽기, 두 비중의 구별 표시, 선택 종목 근거 연결.
- 자금 저장 위치는 holdings.HOLDINGS_DIR 아래 capital_context.json이다. holdings_latest.json과 별도 문서로 원자 저장하고 별도 잠금을 사용한다. .gitignore에 이 개인 파일의 정확한 경로를 추가한다. 임시 저장 산출물에도 실제 금액이 공개되거나 전송되지 않는 기존 개인 자료 원칙을 적용한다. 현금을 가짜 종목코드나 보유 행으로 넣지 않으며, 기존 보유 정본의 구조·revision을 자금 저장 때문에 바꾸지 않는다. 새 DB·계좌 원장·동기화 체계를 만들지 않는다.
- 자금 값은 비공개 사용자 자료다. 실제 금액·계좌 정보를 문서·시험 고정 자료·로그·git에 넣지 않는다. POC6-24 선택 종목 미리보기에 한해 V·C·A·T 네 종류의 원 단위 금액을 [보유 · 자금 기준] 원문에 표시하고 그 원문을 사용자가 복사하거나 기존 PC AI 투자 세션에 저장할 수 있다. 이것을 PLAN에 인용된 POC5-23 금액 제한의 한정 예외로 둔다. 수량·평단·계좌 이름·개별 종목 평가금액·거래 금액·이력 메모를 새로 원문에 넣는 예외는 아니다. 다른 화면·옛 세션·OCI·Telegram/PUSH·운영 PARAM·외부 자동 전송으로 넓히지 않으며 cash_allocation 금지 정책을 유지한다.
- 우선 접점: app/holdings_enrich.py::enrich_holdings, frontend/app/components/EnrichedHoldingsSection.tsx, HoldingsHero, frontend/lib/holdings_view.ts, app/api_decision_draft_preview.py::_load_holdings_evidence, app/decision_draft_preview_service.py, holdings_compare/DecisionDraftPreviewCard.tsx. 기존 개인 보유 저장의 직접 호출 경로만 추가 확인한다.
- 이미 확인된 사실을 재조사하거나 저장소 전체를 스캔하지 않는다. 내부 함수명·파일 배분·전송 필드명은 동일 계약 안에서 개발자가 정한다. 구현 중 기존 계약과의 새 충돌이나 OCI 쓰기/별도 원장 필요가 실제 확인되면 그 사실과 선택지만 설계자에게 알린다.

### B-6. 유지할 것과 하지 않는 것

기존 보유·매매 이력·시세·평가손익·시장 근거·사람의 최종 판단을 유지한다. H1·POC6-19~23의 연구 코드와 결론, 운영 모델·수집·cron·PUSH는 바꾸지 않는다.

이번 Step에서는 누적 납입원금/실현손익 원장, 고정 투자 총예산, 계좌별 현금 자동 수집, 매매 후 현금/한도 자동 차감, 섹터 분류와 비중 한도, 신규 자산배분·물타기·손절 규칙, 매수/매도 신호·주문 계획, 새 ML·백테스트·성과 계산을 만들지 않는다.

특히 '보유+입력 현금 합계'를 투자 총예산으로 대신 부르지 않는다. 현금·한도 입력은 사용자의 의사와 범위를 전달하는 기능이며 수익 개선이나 급락 예측이 검증됐다는 뜻이 아니다.

### B-7. 완료 기준 AC

1. 초기 미입력, 명시적 0원, 양수, 수정·비우기를 구분해 저장·복원한다. A>C, 음수·비유한 값·원 미만 금액, C 없이 A 입력, C 입력 시 확인일 누락, 미래 확인일은 저장되지 않는다.
2. 가상 보유 평가액 60만원·입력 현금 40만원·해당 행 평가액 12만원이면 보유 내 20%, 입력 현금 포함 12%, 현금 구성 40%다. A=10만원이어도 T는 100만원이다. 기존 매입 비중과 평가손익은 바뀌지 않는다.
3. 다계좌 동일 종목의 화면 행/AI 종목 합산 차이, 보유 중인 후보, 미보유 후보, 일부 미평가 보유, C 미입력, C=0, T=0, 보유 없음의 계약을 지킨다. T=0의 알려진 금액과 비중 계산 불가를 구분하며, 부분 자료를 완전한 자산 비중으로 표시하지 않는다.
4. 첫 기본 화면에서 현금·한도·확인일·계산 범위·입력 동작을 찾을 수 있다. 실제 보유 화면에서 사용자가 입력·수정 후 두 비중의 뜻을 구분할 수 있는지 확인한다. 보고에는 실제 금액을 옮기지 않는다.
5. 미리보기에는 분모·집계 단위·수동 입력의 기준일과 범위가 포함되고, 미입력/읽기 실패가 0원·무한 한도로 바뀌지 않는다. 미저장 편집값은 전달되지 않는다.
6. 미리보기·복사·AI 초안이 같은 원문이고, 세션 저장/조회 후에도 생성 당시 자금 맥락이 유지된다. 입력 수정 뒤 옛 원문·세션이 바뀌지 않으며 예전 세션도 열 수 있다. 새로 포함되는 금액은 V·C·A·T에 한정하고 기본 노출 안내를 제공한다.
7. 읽기/저장 실패가 기존 보유 조회와 AI 검토를 불필요하게 막지 않는다. 사용자에게 실패·미반영 상태가 보이고 성공으로 오인되지 않는다.
8. 변경 범위 검사와 기존 관련 동작의 회귀 확인, 변경된 프런트엔드의 lint/build를 통과한다. 검증자 확인과 설계자 RESULT 판정으로 완료를 판단한다. 새 연구 실행·외부 조회·OCI 변경·공개 자료에 개인 금액 포함은 0이다. 가상 자료로 자금 저장 뒤 holdings_latest.json에 자금 값이 추가되지 않고 capital_context.json이 git 제외됨을 확인한다. 이 확인을 위해 실제 OCI 적용을 실행하지 않는다.

### B-8. 남는 한계와 다음 작업

수동 현금·한도는 매매/입출금 후 자동으로 맞춰지지 않는다. 이번에는 확인일·범위·수동 입력임을 드러내는 것으로 제한한다. 실제 사용에서 반복적인 잔액 불일치나 한도 관리 실패가 확인되면 그 사례를 근거로 자동 연계 필요를 별도 판단한다. 현재 자동 원장 기능을 BACKLOG에 정식 등록하거나 후속 구현으로 확정하지 않는다.

PLAN은 본 판정으로 PASS이며 사용자 목업 배치 확인을 수용했다. 개발자는 기존 PLAN과 목업에 이번 확정 문구·예시만 반영하고 새로 작성하지 않는다. 다음은 이 금액 포함 계약을 명시한 기존 세 항목의 사용자 승인 절차다. 구현 후 실제 금액은 사용자가 직접 입력하고 개발자는 그 금액을 기록·보고하지 않는다. 실제 화면 사용 확인·검증자 확인·설계자 최종 RESULT는 아직 수행 전이며, 현재를 Step 완료로 표시하지 않는다.
