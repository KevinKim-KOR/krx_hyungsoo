# POC6-34 OCI 운영·적용과 ETF NAV 조회 · PLAN 판정

2026-11-19 KST · 단계 POC6-34 · 선행 POC6-33 · 수신 개발자

대상 PLAN V1 · `docs/ai_plan/POC6/POC6_34_OCI_AND_ETF_NAV_SCREEN_REVIEW_PLAN_V1.md`

**PLAN 조건부 PASS.** 아래 판정을 PLAN V1에 반영하면 구현할 수 있다. **Q6은 11/19 형수님 결정대로 판정 기준을 항상 펼쳐 둔다.** 숫자마다 판정 대상·기준과 표시된 값의 뜻을 바로 읽게 한다.

이번 단계의 목표는 기존 두 화면에서 확인한 사실과 기준 시각을 명확히 읽는 것이다. 변경 범위는 화면 표시·배치, 기존 조회 동선, OCI 활성값 확인 시각·출처 전달까지다. 판정값·발송 정책·적용에는 기존 계약을 사용한다.

## 1. PLAN §3 판정

| 질문 | 판정 |
|---|---|
| Q1 · OCI 점검 시각 | **보완 수용.** 제목은 ‘마지막 OCI 점검’. ‘PC 백엔드가 시작될 때 한 번 읽음’으로 안내한다(재시작 포함). 확인 실패 때는 `checked_at`을 ‘마지막 점검 시도’로 표시한다. |
| Q2 · 예약표 요약 | **보완 수용.** 성공 요약은 ‘예약표에서 필수 3종 표기 확인’으로 쓴다. 화면의 판단 범위는 읽어 온 예약표의 종별 표기다. 기존 응답으로 일부 누락·확인 불가를 구별한다. 실제 수신 확인은 Telegram으로 안내한다. |
| Q3 · 파일 상태 | **보완 수용.** 점검에서 확인한 파일에는 ‘파일 확인’과 수정 시각을 표시한다. 운영 설정 DB는 알림 실행 기록도 저장하므로 날짜 이름은 ‘DB 파일 수정 시각’이다. 보유의 적용 상태는 「종목 관리」의 ‘OCI 적용’에서 확인하도록 글로 안내한다. |
| Q4 · OCI 활성값과 요청 기록 | **보완 수용.** 기존 GET에 메모리의 `param_read_at`·`param_source` 두 읽기 필드를 전달한다. 활성값을 읽은 시각이 확인되지 않으면 빈 값으로 전달한다. 화면 상단은 같은 응답의 구조화된 ‘운영 기준 활성’ 상태와 시각을 사용한다. 일치일 때 ‘확인값 기준으로 적용할 변경 없음’, 다름일 때 ‘적용할 변경 있음’, 상태 또는 확인 시각을 받지 못하면 ‘적용할 변경 확인 불가’로 표시한다. 차이 건수는 구조 필드가 제공할 때만 쓴다. 확인된 마지막 활성값이 일치할 때만 기존 버튼을 [자세히 보기] 안에 두고, 다름·확인 불가에서는 기존 위치에서 적용을 선택할 수 있게 한다. 적용 요청 종료 시각과 결과는 ‘마지막 적용 요청’으로 표시한다. |
| Q5 · 장중 설정의 출처 | **보완 수용.** ‘PC 기록 기준 · 장중 알림 설정 켜짐/꺼짐’을 쓴다. 정책이 미설정이거나 상태를 확인할 수 없는 경우에는 각 경우를 표시한다. 후보·반영 후 안내도 설정 상태로 적는다. 날짜는 ‘대표 ETF 선정에 사용한 종가일’로 표시한다. 판정 기준은 버전에 담긴 고정값이며, PC가 계산하는 것은 사업군·대표 ETF 목록임을 한 줄로 설명한다. |
| Q6 · 판정 기준 표 | **사용자 결정 수용.** 후보 유무와 관계없이 항상 펼친다. 배치와 설명은 §2를 적용한다. |
| Q7 · NAV 메뉴·제목 | **원안 수용.** 메뉴 ‘ETF NAV·괴리율 조회’, 제목 ‘ETF 순자산가치(NAV)·괴리율 조회’. 연결 문구와 오류 시 재시도 버튼 이름도 맞춘다. |
| Q8 · NAV 다시 읽기 | **보완 수용.** [저장 자료 다시 읽기]와 「오늘의 투자 점검」의 [최신 자료 갱신] 경로를 안내한다. 마지막 시장 갱신 성공 뒤 6시간 이내에는 NAV 수집이 건너뛰어진다는 기존 동작을 한 줄로 쓴다. 표 도움말에 ‘기준일은 PC가 목록 갱신을 시작한 날짜’라고 적는다. NAV 원천의 산정일은 현재 응답에서 확인할 수 없다. 이전 목록 재사용의 ‘재저장일’ 표시는 POC6-33 판정을 적용한다. |
| Q9 · 표시 범위 | **원안 수용.** 표 위에 ‘전체 A건 · 필터 결과 B건 · 표에 표시 C건’을 쓴다. C는 검색·필터·정렬 뒤 실제 표시한 건수다. 필터 결과가 200건을 넘으면 현재 정렬의 앞 200건임을 안내한다. 표 아래는 검색·필터 안내를 제공한다. |
| Q10 · 후보 차이 | **원안 수용.** 기존 응답에서 확인되는 대표 ETF의 추가·제외·교체, 설정 켜짐 변화로 후보 차이를 설명한다. 판정 기준은 후보 버전의 값으로 보여 준다. 기준값 차이와 OCI 장중 설정 적용 시각은 결과서에 응답으로 확인할 수 없는 항목으로 기록한다. |

Q4의 현재 판단과 과거 기록을 대조할 사례는 11/19 09:04 점검의 활성값 확인과 10/20 13:14 요청 종료다. 10/20 요청 결과는 ‘이미 일치’였고 OCI 쓰기는 0건이었다. 두 날짜는 각자의 라벨에 붙인다. 현재 활성값을 읽지 못하면 과거의 ‘이미 일치’는 마지막 요청 기록에서만 읽는다.

## 2. Q6 판정 기준 표시

- **세 묶음**으로 읽는다. ‘보유 종목 급등락’, ‘사업군 대표 ETF 검토’, ‘발송 한도와 자료 조건’. 각 항목은 **항목 · 설정값 · 무엇을 보는지 · 이 값이면 어떻게 동작하는지**를 기본 화면에 보인다. 좁은 화면에서는 값 바로 아래에 문장을 배치한다.
- 후보가 없으면 **‘PC에 기록된 적용 기준’**, 후보가 있으면 **‘승인 시 적용될 기준’**을 제목으로 쓴다. 적용값과 후보값은 각 응답이 제공하는 범위에서 읽는다. 설명은 해당 표의 실제 값과 단위를 사용한다. 값이 빠진 항목은 ‘확인 불가’를 표시한다.
- 다음은 11/19 캡처 값으로 작성한 화면 문안이다. 조건의 포함 경계, 순위 모집단과 정렬 지표, 성공률 분모, 재발송의 대상·예외는 해당 실행 코드와 기존 시험에 맞춰 적는다. 등락률은 알림 후보를 가리는 데 쓰이며, 최종 발송에는 중복 억제와 발송 한도 같은 기존 조건도 적용된다.

| 묶음 | 항목·캡처 값 | 무엇을 보는지 | 이 값의 뜻 |
|---|---|---|---|
| 보유 종목 급등락 | 보유 급등 +5% | 보유 종목의 직전 종가 대비 당일 등락률 | 당일 +5.2%인 보유 종목은 급등 후보의 등락률 조건을 충족한다. |
| 보유 종목 급등락 | 보유 급락 −5% | 보유 종목의 직전 종가 대비 당일 등락률 | 당일 −5.2%인 보유 종목은 급락 후보의 등락률 조건을 충족한다. |
| 사업군 대표 ETF 검토 | 진입 검토 하한 +1.5% | 대표 ETF의 진입 검토에 필요한 당일 등락률 하한 | 당일 +1.6%인 대표 ETF는 등락률 하한을 충족한다. 추세·순위 등 기존 조건을 함께 본다. |
| 사업군 대표 ETF 검토 | 추격 주의 +4% | 당일 상승이 큰 경우를 구별하는 등락률 | 당일 +4.2%면 추격 주의의 등락률 조건을 충족한다. |
| 사업군 대표 ETF 검토 | 진입 회피 −1.5% | 당일 하락이 큰 경우를 구별하는 등락률 | 당일 −1.6%면 진입 회피의 등락률 조건을 충족한다. |
| 사업군 대표 ETF 검토 | 순위 조건 20% | 실제 실행 규칙이 순위를 매기는 대상과 지표 | 확인한 모집단과 정렬 지표를 밝혀 20%가 어느 쪽 순위 구간인지 명시한다. |
| 발송 한도와 자료 조건 | 재발송 대기 120분 | 재발송 판단에서 사용하는 중복 억제 시간 | 대기를 적용하는 경우 120분은 2시간이다. 기준 시각과 대기가 적용되는 대상은 실행 규칙으로 확인해 설명한다. |
| 발송 한도와 자료 조건 | 하루 최대 4건 | 조건을 충족한 장중 급등락 알림의 일일 발송 한도 | 그날 4건을 발송하면 추가 장중 급등락 알림에 일일 상한이 적용된다. 점검 회차당 최대 1건이다. |
| 발송 한도와 자료 조건 | 구역별 최대 3건 | 한 알림 본문의 구역마다 수록하는 종목 수 | 한 구역에 조건을 충족한 종목이 5개여도 본문에는 최대 3종목이 실린다. |
| 발송 한도와 자료 조건 | 최소 조회 성공률 80% | 실제로 세는 조회 대상 가운데 성공한 비율 | 해당 조회 대상이 10건이고 7건이 성공하면 70%로 기준 미달이다. 분모와 미달 때 보류되는 범위를 실행 규칙에 맞춰 명시한다. |

표 해석의 기준은 `IntradayConfigCard`의 응답과 장중 판단·발송 경로의 실제 사용처다. 개발자는 기존 정책 12개 중 화면에 보이는 10개 값과 현재 안내에 있는 ‘중복 억제 창’, ‘회차당 최대’의 연결을 짧게 대조한다. 설명에는 정책을 소비하는 쪽에서 사용하는 뜻을 반영한다. 설정 버전·확인값·산출 규칙은 기존 [자세히 보기]에서 읽는다.

## 3. 완료 기준

1. 같은 화면에서 예약표 점검과 실제 발송 확인 경로, 파일 수정 시각과 적용 요청 시각, 활성값 확인 시각을 각각 읽을 수 있다. 점검 실패·다름·이전 요청만 확인되는 경우를 고정 자료로 대조한다.
2. 장중 표는 기본 펼침이다. 모든 기존 값 옆에 판정 대상과 표시된 값의 해석이 있다. 현재값과 승인 후보값이 다른 예에서 제목·값·설명이 같은 응답을 가리킨다. ‘순위 20%’와 ‘성공률 80%’는 해당 판정에서 실제로 사용하는 범위와 함께 읽힌다.
3. NAV 화면에서 저장 자료를 다시 읽는 동작과 새 자료를 받는 경로를 구별한다. 전체·필터 결과·실제 표시 건수, 기준일과 재저장일, 수집 상태와 괴리율 표시를 한 표에서 읽을 수 있다.
4. 격리 화면 및 읽기 자료로 검증한다. PLAN O10·O11과 Q6, 확인한 판정 근거는 PLAN과 결과서에 남긴다. 두 메뉴의 실제 표기와 조회 범위는 `PROGRAM_TRUTH.md`에 반영한다.
