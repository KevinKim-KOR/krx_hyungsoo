## 1. 선행 상태와 방향

- 사용자 배포 보고 기준 POC6-05는 종료했다. 구현 8bda752f, 종료 5fae233e, 문서 정리 c77a71f3이며 첫 정기 실행 확인은 별도다. 그 확인을 기다려 PLAN 작성을 멈추지 않는다. 이 문서는 설계자가 OCI를 직접 확인했다는 보고가 아니다.
- 05의 일일 120일 수신 창은 현재 feature에 활용할 수 있지만, 기존 252일 학습 표본 조건을 충족하는 장기 학습 자료는 아니다. 일일 창을 그냥 이어 붙이거나 몇 달을 기다리는 안으로 대신하지 않는다.
- 처음 한 번 선정 표본의 일관된 장기 가격을 확보하고 학습 예제를 고정한다. 이후에는 실제 예측 때 저장한 feature와 나중에 확정한 목표를 새 학습 예제로 추가한다. **원시 가격 창을 접합하는 것과, 출처가 있는 학습 예제 행을 추가하는 것은 구분한다.**
- 기존 연구에는 재사용할 학습 가중치가 저장돼 있지 않다. 초기 학습은 기존 가중치를 복원하는 작업이 아니라 고정 recipe를 새 표본에 적용하는 작업이다. 이번부터 학습 결과도 보관한다.
- 현재 보유의 계좌 손익은 모델 성과가 아니다. 보유 ETF의 예측 오차 자체는 평가 가능하지만, 이번 주 표본은 보유 파일을 읽어 선정하지 않는다. 사용자 평가·매매·피드백 유무로 표본을 거르지 않는다.

## 2. 평가 표본 — 결과를 보기 전에 고정

1. PC에 가져온 05의 정상 ETF 목록 판 하나를 기준으로 한다. 목록의 available_at, hash, 종목 수와 선정 시각을 남긴다. seed와 보유 목록은 선정 입력이 아니다.
2. 초기 장기 자료가 있을 가능성을 확인하는 용도로만 기존 PC 저장 가격의 종목별 날짜 개수를 읽는다. 목록 안에서 기준일 이하의 유효 종가 저장일이 365개 이상인 ETF를 후보군으로 한다. 이 검사는 가격 일관성 통과나 252개 유효 학습 예제를 보증하지 않는다.
3. 후보군의 6자리 ticker에 대해 UTF-8 문자열 `poc6-06-v1:<ticker>`의 SHA-256을 계산하고, hash 오름차순·동률 ticker 순으로 앞 24종을 선정한다. 후보가 적으면 그 수를 그대로 적고 PLAN에서 범위 부족을 질문한다. 수익률·D20·모델 오차·사용자 관심도는 선정에 쓰지 않는다.
4. PLAN에 후보군 수, 선정된 ticker, 저장일 개수와 자료 근거를 넣는다. 이는 학습·성과 계산 없이 한다. 명세와 다르게 선정해야 한다면 그 이유만 질문하며 임의 대체하지 않는다.
5. 선정 목록과 선정 근거를 cohort_v1으로 고정한다. 이후 이력 부족·수집 실패·상장폐지·가격 공백이 나와도 이름과 사유를 남기며, 잘 계산되는 다른 ETF로 바꾸지 않는다. 월별 보유 변경으로 바뀌지 않는다.

24종은 초기 수집·학습량을 제한하는 설계 선택이지 통계적 충분성 기준이 아니다. 오래된 이력이 있는 현재 상장 ETF의 고정 표본이며, 신규·상장폐지 ETF를 포함한 전체 시장 대표성이나 투자 후보 선별 성능을 주장하지 않는다. 실제 선정된 보유 종목과의 우연한 중복은 독립 규칙을 훼손하지 않으며, 중복 여부는 필요 시 부가 설명으로만 계산한다.

## 3. 초기 자료와 쌓이는 학습 예제

### 3-1. 장기 자료를 한 번 준비

- 이미 보관한 사본에 선정 종목의 일관된 장기 창이 있으면 먼저 재사용한다. 없는 종목만 기존 POC6-03의 같은 네이버/FDR 경로로 종목당 1회, 최대 24종을 조회하는 안을 PLAN에 적는다. 전 ETF 장기 백필·새 원천·새 키는 추가하지 않는다.
- 이 외부 조회는 05의 일일 수집과 구분한 추가 행위다. 구현과 선정 목록을 준비한 뒤 실제 조회 전에 사용자 승인을 받는다. 재사용 수·추가 요청 수·요청 범위·상한과 저장 위치를 한 번에 제시한다.
- 같은 종목의 초기 학습 feature와 D20 목표는 한 수신 판의 장기 가격에서 함께 만든다. 오래된 운영 가격과 새 가격을 붙이지 않으며 KRX 무조정 가격을 대체값으로 넣지 않는다. 기존 06/02의 허용 가격·연결·날짜 축·공백 검사를 재사용한다.
- 미래/진행 중 가격은 제외하고 실제 확보·공개 시각을 보존한다. 같은 응답에서 계산한 change와의 일치만으로 가격 조정의 정확성을 입증했다고 쓰지 않는다. 새 전 종목 KRX 대조나 03 재실행을 선행 과제로 붙이지 않는다.
- 초기 학습 종료 경계 아래에서 유효 예제 252개 이상인 종목을 initial_trainable에 고정한다. 부족한 종목도 cohort 분모에 남기고 DATA_SHORT로 표시한다. 누락 종목 때문에 다른 종목의 기록까지 전부 막지는 않는다. 이력 부족 종목의 편입은 후속 cohort 판에서 정하며 이번에는 자동 교체하지 않는다.

### 3-2. 이후의 예제

- 예측 때 실제 사용한 feature 5개, 원시 가격 창 참조, 당시 가용 시각을 그대로 저장한다. 성숙 뒤의 최신 가격으로 과거 feature를 다시 계산해 대체하지 않는다.
- 각 예제는 (ticker, 기준일, feature 판, 목표 판, origin)을 갖는다. 초기 회고 예제는 BOOTSTRAP_RETROSPECTIVE, 실제 전향 예제는 LOGGED_FORWARD다. 초기 자료가 당시 가용했던 PIT 자료라고 주장하지 않는다.
- 새 LOGGED_FORWARD 예제는 §7의 유효 예측 입력과 §8의 성숙 목표가 연결된 행만 쓴다. 예측하지 못한 과거 날짜를 나중에 메워 전향 기록으로 만들지 않는다.
- 초기 예제와 신규 예제는 (ticker, 기준일)로 중복 학습하지 않는다. 같은 종목·기준일의 다른 입력 판이나 재생성은 부가 기록이며, 주 기록의 변경은 새 protocol 판 없이는 하지 않는다.
- 환율·유가·수급·VIX·거래량은 05에서 계속 보존한다. 이번 기존 모델의 입력에는 자동 추가하지 않는다. 활용 가설과 시간 연결·검증 기준을 정한 다음 feature 판에서 사용할 수 있다.

## 4. 목표·feature·네 방법

D20(t) = min(0, min(C(t+h)/C(t)-1, h=1..20)). 한국 연구 축의 다음 20거래일 **최저 종가 변화**다. +20일 수익률·MDD·장중 저점·손실 확률·개인 손익으로 부르지 않는다.

feature는 기존 02의 순서와 계산을 고정한다.
1. C(t)/C(t-5)-1
2. C(t)/C(t-20)-1
3. C(t)/C(t-60)-1
4. 최근 20개 일별 로그수익률의 모집단 표준편차(ddof=0)
5. C(t)/max(C(t-59)..C(t))-1

| 방법 | 이번 적용 |
|---|---|
| MEDIAN | 종목별 유효 학습 목표의 중앙값. 짝수 개이면 가운데 두 값 평균 |
| RIDGE | 종목별 기존 StandardScaler → Ridge(alpha=1, solver=svd, fit_intercept=True) |
| HGB | initial_trainable 종목 공동 학습. 기존 02 고정 설정 |
| MLP_CPU | 기존 02 MLP 구조·학습 규칙을 PC CPU에서 실행. 과거 CUDA 결과와 별도 model_version |

HGB: loss=absolute_error, learning_rate=0.05, max_iter=100, max_leaf_nodes=7, max_depth=3, min_samples_leaf=50, l2_regularization=1, max_bins=63, early_stopping=False, categorical_features=None, random_state=42.

MLP: 5→64→32→1, 중간 ReLU, float32, Adam(lr=0.001, weight_decay=0.001), 200 epoch, seed=42. dropout·BatchNorm·AMP·early stopping 없음. 기존 날짜 균형 가중 표준화·가중 L1·epoch당 전체 예제 기준 한 번 업데이트를 재사용한다. 메모리 때문에 나누더라도 같은 목적함수의 gradient를 누적한다.

HGB/MLP의 날짜 d 행 가중치는 1/n_d로 한다. MEDIAN/RIDGE는 종목 내 날짜 동일 비중이다. scaler는 해당 학습 자료에만 fit한다. 네 방법 모두 예측을 [-1,0]으로 제한한다. ticker·이름은 feature가 아니다. 설치된 라이브러리 판·기본값·스레드·seed를 recipe에 남기며 자동 업그레이드하지 않는다.

과거 CPU/GPU 실측은 이미 보존됐다. 이번 목적은 장치 속도 비교가 아니므로 RTX 실행을 요구하지 않는다. CPU 결과를 과거 GPU 모델과 비트 단위로 같다고 주장하지 않는다. CPU MLP 실행이 환경상 불가능하면 방법별 NOT_RUN_ENV로 보고하고 PLAN에서 필요한 조치만 질문한다. 다른 CPU 방법의 개발을 GPU 대기로 막지 않는다.

## 5. 학습 갱신 — 수집은 OCI, 학습은 PC

- 초기 학습 후 **달이 바뀌고 새 유효 학습 예제가 생긴 경우**, 그 조건을 처음 만족하는 유효 예측 실행에서 같은 recipe로 재학습한다. 실제 학습은 달마다 최대 한 번이다. 새 예제가 없으면 기존 학습 판을 유지하고 NO_NEW_TRAINING_EXAMPLES로 기록하며, 그 달의 학습 기회를 소진한 것으로 보지 않는다. 밀린 달의 가상 학습을 차례로 재현하지 않는다.
- 초기 예제와 그때까지 확정된 LOGGED_FORWARD 예제를 합친다. 학습에 쓰는 모든 목표 종료일은 그 회차 첫 예측의 기준일 D보다 이르고, feature·목표·예제의 실제 가용 시각은 training_started_at 이하이어야 한다. 알려지지 않은 목표를 0으로 대입하지 않는다.
- training_started_at, 기준일 D, 종료일 상한, origin별 예제 수, 실제 X/y/가중치·예제 참조 hash를 고정한다. 늦게 성숙한 행은 다음 달부터 쓴다. 월별 학습 중 자료를 재조회해 표본을 바꾸지 않는다.
- 학습 데이터 hash가 같으면 불필요하게 다시 fit하지 않는다. 새 모델 판은 recipe + cohort + 학습 예제·환경·실행 식별자로 구분한다. 월별 갱신은 결과를 보고 고르는 튜닝이 아니다.
- 가중치와 변환값도 보관한다. MEDIAN/RIDGE는 읽을 수 있는 수치 구조를 우선 쓰고, HGB/MLP는 기존 설치 도구의 저장·복원 방식을 PLAN에서 정한다. 복원 뒤 같은 고정 입력의 예측을 대조한다. 자신이 생성·검증한 hash의 모델 파일만 읽고 실행 환경 불일치를 무시하지 않는다.
- 방법 하나의 학습/예측 실패는 해당 방법의 실패다. 다른 방법의 값을 복사하거나 0·이전 방법의 값으로 채우지 않는다. 성공한 방법의 기록은 보존하고 비교 가능 행 수를 분리한다. 새 달의 실패 방법을 이전 학습 판으로 조용히 대체하지 않는다.

## 6. PC 실행 흐름과 시각

한 번의 수동 실행으로 **PC 사본 확인 → 성숙 결과 연결 → 필요한 월별 학습 → 새 예측 기록 → 비교 보고서**를 수행한다. 새 명령 이름·모듈 위치는 PLAN에서 정한다. 파일 읽기만 하는 report와 실제 예측/학습을 수행하는 run은 구별한다.

- 05의 pull은 명시적으로 선택했을 때만 수행한다. 기본 실행은 현재 PC 보관본을 사용하며 새 외부 수집·SSH를 몰래 시작하지 않는다. 늦게 가져온 자료의 OCI available_at와 PC copied_at를 모두 보존한다.
- 기준일 D는 검증된 한국 연구 축의 최근 완료일이다. 각 ETF의 입력 창은 그 D까지 있어야 한다. 오래된 ETF만 자기 최신일로 옮겨 오늘 예측인 것처럼 기록하지 않는다. 창 안 결측·가격 기준 문제는 사유별로 남긴다.
- 실제 예측 기록의 공개 시각은 D 다음 거래일의 기존 CLOSE_CUTOFF(15:30 KST)보다 빨라야 한다. 즉 목표의 첫 종가가 확정되기 전에 기록을 남겨야 한다. 계산 시작은 빨랐어도 공개가 늦으면 전향 주 기록이 아니다. 경계 이후에는 SKIPPED_TOO_LATE로 남기고 과거 시각을 입력받아 우회하지 않는다.
- 날짜 축으로 다음 거래일을 확정할 수 없으면 판정하지 않는다. 장래 20일의 예정일은 확정할 수 있는 범위만 안내하고, 실제 목표의 날짜는 §8에서 검증한다. 평일 수를 임의 거래일 수로 쓰지 않는다.

## 8. 성숙 목표 — 같은 수신 판의 기준일과 미래 가격

- 검증된 한국 연구 축에서 D 다음 20거래일이 모두 지난 뒤만 계산한다. 부족하면 PENDING_NOT_DUE, 날짜 축 자체를 확정할 수 없으면 PENDING_CALENDAR로 구별한다.
- 한 수신 판 안에 D와 다음 20거래일의 유효 종가가 모두 있는 가격 창을 쓴다. 주 대상은 05가 계속 보관하는 120일 창이다. 서로 다른 날 받은 D 종가와 미래 종가를 섞어 나누지 않는다.
- 첫 평가 실행이 가진 정상 보관본 중 조건을 충족하는 가장 이른 available_at의 판을 택하고, 동률은 run_id 순으로 정한다. 평가 입력 inventory와 as-of를 함께 고정한다. 실제 원천의 최초 발표 판이라고 주장하지 않는다.
- 이미 성숙했지만 완전한 가격 창이 없으면 DUE_DATA_MISSING, 손상·비정상 값·가격 기준 검사가 실패하면 DATA_CHECK_REQUIRED다. 받은 값이 없다고 0·상승으로 처리하지 않는다. 날짜를 지워 20일을 줄이지 않는다.
- 목표 판에는 사용한 전체 21개 종가·날짜 또는 그 불변 참조, 날짜 축, 계산값, 실제 계산 시각·가용 시각을 남긴다. 예측 당시 기준 종가와 목표 판의 기준 종가가 다르면 두 값을 남긴다. 목표값은 목표 판의 한 가격 기준으로 계산한다.
- 처음 평가한 목표 판을 주 비교에 고정한다. 더 오래된 묶음이나 정정 가격을 나중에 받아도 조용히 바꾸지 않는다. 향후 정정 재평가는 새 목표 판·영향 범위를 명시하는 별도 실행으로 하고 이번에는 정정 편집 UI를 만들지 않는다.

## 9. 비교 보고서 — 정확도·범위와 미성숙을 함께

- 주 지표는 기존 날짜 균형 MAE(%p)다. 날짜마다 공통 유효 종목의 절대 오차 평균을 구한 뒤 날짜 평균을 낸다. 종목 수가 많은 날짜를 더 크게 가중하지 않는다.
- HGB 대 MEDIAN/RIDGE는 세 방법과 목표가 모두 있는 같은 행에서, MLP 대 두 기준도 해당 세 방법의 같은 행에서 비교한다. 비교별 표본·날짜 수와 차집합을 적는다. HGB와 MLP를 직접 비교하는 표는 네 방법 모두 있는 공통 행으로 제한한다.
- 예측 누락·목표 결측·방법 실패로 잘 되는 행만 남은 효과를 숨기지 않는다. cohort 전체 대비 입력 가능·예측 성공·성숙·실제 비교 행 수를 각각 표시한다. 평가할 행이 없으면 MAE는 null이며 0이나 모델 기각으로 쓰지 않는다.
- 종목별·달별/학습 판별 결과와 D20≤−8% 행의 MAE·max(예측−실제,0)를 보조로 남긴다. 이 값은 큰 하락을 작게 추정한 정도이지 매매 수익률이나 사전 감지율이 아니다.
- 누적 결과는 **월별 갱신 recipe의 결과**이며 단일 고정 가중치의 성과로 쓰지 않는다. 평가한 model_version을 함께 보여 준다. 20일 목표가 겹치므로 행 수를 독립 사건 수라고 설명하지 않는다. 이번에는 새 신뢰구간/유의성 검정 도구를 추가하지 않는다.
- 결과를 본 뒤 잘 된 ETF·국면만 골라 주 표를 바꾸지 않는다. 이전 5% 개선 gate를 반복 실행의 자동 합격선으로 가져오지 않는다. 이 단계는 전향 비교 연결의 개발 판정이며, 관측된 수치와 악화 구간을 그대로 남긴다.
- 최초 실제 예측일부터 3개월 뒤를 첫 누적 해석 시점으로 기록한다. 표본이 적으면 그렇게 판정하고, 우승 모델 선출을 강제하지 않는다. 개발 종료나 다른 요구사항의 설계가 이 날짜를 기다릴 필요는 없다. 운영 승격·새 feature·모델 변경은 목적과 기준을 따로 정한다.

8. 검증자 판정·설계자 RESULT 판정 후 승인 범위로 반영·종료한다. 일일 수집의 첫 정기 운영 확인과 이 단계 성숙 결과의 누적 운영 확인은 별도 상태로 기록한다.

이 단계로 #3 종합 위험 구간 분류, #55 무릎·머리·어깨 기준, #57 RS·거래량·정배열 복합, #62 후보/seed 품질을 완료로 바꾸지 않는다. 이번에는 #62에 필요한 보유 독립 비교 기반과 새 모델 검증에 재사용할 실제 입력/결과 연결을 마련한다. 남은 사용자 기능의 설계는 이 기록이 쌓이는 동안 병행할 수 있으며, 항목의 현재 근거·범위를 보고 별도로 정한다.

- 프로젝트 기준: 02/04 설계·최종 판정, 03 가격 기준 검증, 05 설계·PLAN/RESULT 판정과 사용자 배포 종료 보고. 새 단계가 과거 결과나 운영 계약을 덮지 않는다.
