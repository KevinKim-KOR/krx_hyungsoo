## 1. 판정과 현재 상태

**판정: PASS_WITH_REQUIRED_CORRECTIONS — 아래 두 보완을 기존 PLAN에 반영하는 조건으로 수용한다.**

PLAN을 처음부터 다시 작성하거나, 보완만을 위한 별도 POC·설계자 재제출 라운드를 만들 필요는 없다. 실제 조회 전 보완 반영 여부와 필요한 사용자 승인을 확인한다. 현재 POC6-19는 PLAN 판정 단계이며 구현·외부 조회·연구 사본 확보·검증은 완료되지 않았다.

이번 목표는 기존 공급자의 과거 수급·원/달러·WTI를 별도 연구 사본으로 확보하는 것이다. 자료가 준비된 뒤 추가 시장 입력의 효과를 비교할 실험 하나를 별도로 설계한다. 이번 판정에서 모델·목표·시간 분할·채택 기준을 정하지 않는다.

## 2. 수용하는 계획

| 항목 | 판단과 이유 |
|---|---|
| 기존 어댑터 재사용·연구 코드 7개 파일 | 수용. 보고된 HTTP 주입 기능으로 원본을 보존하고 운영 갱신 함수를 호출하지 않는 범위가 설계와 맞는다. 신규 설치·공유 코드 변경은 없다. |
| 운영 DB의 코스피 종가를 읽기 전용으로 대조 | 수용. 봉인 ETF 판에 코스피 지수가 없다는 구조 차이를 합리적으로 해소한다. 실행 시 날짜·종가·출처 사본과 해시를 남긴다. |
| 수급 첫 표본 2014-04-10 | 수용. 설계의 ‘첫 저장 코스피 거래일’에 부합한다. 앞선 68일은 지수 대조 근거 부재로 미요청이며, 공급자 미제공·결측으로 집계하지 않는다. |
| 원/달러·WTI 목표 시작 2014-01-02 유지 | 수용. 수급의 대조 가능 시작일을 다른 자료에 강제하지 않는다. |
| A 표본 → 조건부 B 장기 확보 → 원본 검산 | 수용. 조건을 충족한 자료는 동일 승인·예산 안에서 이어가며 A 뒤에 새 PLAN·판정 단계를 만들지 않는다. |
| 요청·자원 예산 | 수용. A 예상 14회, B 예상 최대 3,048회는 재시도 전 추정값이다. 실제 요청·재시도는 설계 상한에 포함한다. 시간·용량은 성공 보장값이 아니다. |
| 원시 보존·실패 기록·격리 시험·원본 재계산 | 수용. 공유 코드를 바꾸지 않는 이번 범위에서 관련 시험과 검산을 수행하며, 프런트 검사·전체 회귀를 추가 요구하지 않는다. |

봉인 판의 거래일 수·운영 DB 구성·달력 일치·기존 코드의 동작은 개발자 보고에 근거한다. 설계자가 사용자 저장소·DB·API를 직접 재검사한 사실로 바꾸지 않는다.

## 3. 필수 보완 두 가지

### 보완 1 — 수급 값의 날짜 간 동일성을 자동 무효 사유로 쓰지 않는다

PLAN §1-2·§3-3·§3-4의 ‘서로 다른 날짜의 13분류 값이 모두 같으면 유효로 세지 않음’을 정정한다.

- 13분류 값의 동일성은 반복 응답 의심 표시로 남긴다. 동일성만으로 무효 처리하거나 연속 구조 실패 횟수를 늘리지 않는다.
- 날짜 유효성은 응답 날짜가 있으면 요청일과의 일치, 그리고 해당 일 코스피 지수 대조 등 독립적인 날짜 근거로 판단한다. 응답 날짜가 없으면 설계대로 간접 확인임을 기록한다.
- 날짜를 무시한 최신 응답은 요청일 불일치·지수 대조 실패 등 확인된 근거로 실패 처리한다.
- 유효한 0과 음수를 유지한다. 관련 시험에서도 ‘동일한 13분류 값이지만 날짜·지수 대조는 정상인 관측’을 오탐으로 제외하지 않는지 확인한다.

이유: 값의 반복 자체는 날짜 오류의 증거가 아니다. 설계의 정상 0 보존 원칙과 날짜 진위 검사를 함께 지켜야 한다.

### 보완 2 — Yahoo의 기존 저장 날짜 집합 완전 일치를 B의 필수 조건으로 쓰지 않는다

PLAN §3-3의 ‘2026-09 창과 기존 저장값의 날짜 집합이 같아야 함’을 정정한다.

- 최근 표본 창에 요청 범위 안의 유효한 완료 일봉이 있고, 날짜·시간대·단위 해석을 뒷받침하는 근거가 있는지 확인한다.
- 기존 저장본과 공통 날짜는 값 대조에 사용한다. 한쪽에만 있는 날짜는 각각 목록·개수·확인된 사유 또는 미확인으로 기록한다.
- 날짜 집합 차이만으로 B를 막거나 공급자의 과거 자료 미제공으로 판정하지 않는다. 실제 요청일 무시·범위 오류·날짜 해석 실패는 그대로 실패 사유다.
- 기존 조건인 ‘2014년 1월 또는 2020년 4월 창 중 적어도 하나의 유효 과거 관측’은 유지한다.
- 결측을 0·직전 값으로 채우지 않고, 기존 저장본을 새 응답에 맞춰 수정하지 않는다.

이유: 기존 저장본은 대조 자료다. 날짜 차이는 원인을 확인할 대상이며 그 자체가 새 응답의 날짜 오류를 뜻하지 않는다.

## 4. 실행·승인 경계

설계 §9의 승인 범위는 그대로다. 이번 PLAN 판정은 외부 조회·커밋·push에 대한 사용자 승인을 대신하지 않는다.

- 개발자는 보완을 기존 PLAN에 반영하고, 실제 외부 조회 A와 조건부 B 전체·연구 폴더 쓰기·해당 코드와 문서의 커밋·push 중 부족한 승인을 한 묶음으로 제시한다. 이미 유효한 승인은 다시 묻지 않는다.
- 조회는 키움 등록 IP 망의 맥북이라는 실행 전제가 충족될 때 수행한다. 현재 맥북 망이 등록됐다고 추정하지 않는다. IP 미등록이면 키움은 ACCESS_BLOCKED로 기록하고, 조건을 충족한 Yahoo 자료는 계속할 수 있다.
- 기존 05·06·13·17 운영은 유지한다. 연구 실행 구간이 기존 작업과 겹치지 않도록 시작 시각을 정하고, 운영 자동 실행을 끄거나 새 잠금 체계를 만들지 않는다.
- 운영 파일 지문 변화가 있으면 실제 연구 코드의 쓰기와 기존 자동 작업의 변화를 구분한다. 전후 지문 차이만으로 연구 코드가 썼다고 단정하거나 운영 파일을 되돌리지 않는다.
- 성공한 자료를 검증 목적으로 전부 재조회하지 않는다. 원자료와 사용자 소유 handoff는 공개 git에서 제외한다.
- 현재 보고된 미커밋 문서 3개는 개발자 보고로 유지한다. 이번 판정문을 포함한 실제 변경 목록은 마무리 때 확인한다. 지금 별도 커밋은 요구하지 않는다.

정상 경로는 보완 반영·필요 승인 → 최소 구현과 격리 확인 → A → 조건부 B → 검산·RESULT·검증 → 설계자 결과 판정이다. 출처·접근 차단으로 수집을 못 한 경우에는 그 근거를 보고하고, 형식적인 구현 완료·검증 라운드를 만들지 않는다.

## 5. 유지할 결론

- ARCHIVE_READY는 자료 사본의 상태이며 ML 효용·새 미사용 시험·당시 공개 판 일치·운영 채택을 뜻하지 않는다.
- 실제 확보 범위와 주 수를 확인한 뒤 후속 연구 수준을 정한다. 저장된 57주나 기존 H1의 104주·165주를 보편적인 연구 금지 기준으로 쓰지 않는다.
- 과거 자료 연구와 기존 전향 축적을 병행한다. POC6-12의 총수익 미확보, Q6 OPEN, 운영 ML 미승격과 기존 미완료 요구는 유지한다.
- 이번 판정으로 새 기능·공급자·UI·ML 학습·OCI 작업이나 새 BACKLOG 항목을 추가하지 않는다.
