# POC6-16 DESIGN V1 — 기존 대시보드의 요약 구조와 이동 동선 재정비

작성: 설계자 · 2026-11-02 · 독자: 개발자·사용자·검증자

저장 위치: docs/ai_design/POC6/POC6-16_PC_DASHBOARD_SUMMARY_AND_NAVIGATION_DESIGN_V1.md

**먼저 §9의 현재 화면·자료 연결 대조와 짧은 PLAN, 전체 화면 목업을 제출한다. 사용자 목업 확인과 설계자 PLAN 판정 뒤 구현한다. 기존 대시보드와 영역별 요약을 재사용하며, 현재 코드에 없는 연결을 있다고 가정하지 않는다.**

## 1. 목적과 출발 상태

사용자는 기능과 정보가 늘어난 만큼 ‘어디에 있는가’뿐 아니라 **전체에서 무엇을 확인하면 되는가**를 먼저 알 수 있는 요약이 필요하다고 했다. 자료·UI·ML은 투자 판단을 돕는 같은 프로젝트의 개발 축이다. 이번 개선을 ML 성능 향상의 부속 작업으로 취급하지 않는다.

POC6-15 종료 보고를 수용한다. 표시 두 곳 보완과 같은 Baseline 상태의 단계 요약을 ‘보고 있음’으로 맞춘 세 번째 문구 변경도 표시 일관성 범위로 수용한다. 보고된 228d2239·be37b47d push 및 PC 반영을 근거로 15는 닫힌 채 유지하며 추가 재판정은 없다.

이번 설계는 다음 자료를 참고했다.
- 최신 POC6-15 종료 결과서·RESULT 판정·사용자의 대시보드 개선 의도.
- 과거 POC3-01 오늘의 투자 점검 결과서와 POC3-03 대시보드 확정 설계. 이들은 **7월 시점 자료**이며, 당시 미완료·보류·승인 게이트를 현재 상태로 되살리지 않는다.

과거 자료에는 ‘오늘의 투자 점검’과 별도 기존 대시보드, 판단 항목과 자료 정비 항목, 무거운 후보 계산을 자동 호출하지 않는 계약이 있었다. 설계자가 11월 main의 실제 화면·응답을 직접 확인한 것은 아니다. 현행 파일·메뉴·응답·이미 개선된 부분은 PLAN에서 좁게 대조한다.

## 2. 화면의 역할 — 전체 요약, 영역별 결론, 상세 근거

| 층 | 사용자가 얻는 것 | 이번 처리 |
|---|---|---|
| 기존 주 대시보드 | 지금의 상태·확인할 내용·자료 기준과 이동 목적지 | 이번 재정비 대상 |
| 시장·보유·후보·연구 화면 | 영역별 결론과 주요 근거, 해당 기능의 조작 | 기존 기능·요약을 재사용 |
| 종목 상세·연구 기록·개발 정보 | 기간·숫자·원문·실행 근거 | 기존 상세로 이동하거나 펼침 |

주 요약은 현행 ‘오늘의 투자 점검’ 계열 화면을 우선 대상으로 한다. 실제 사용 중인 주 대시보드가 다르면 PLAN에 그 사실과 기존 진입점을 적는다. 새 세 번째 대시보드나 새 최상위 메뉴부터 만들지 않는다. 별도 ‘기존 대시보드’가 남아 있다면 중복 내용을 대조하되 이번에 임의로 삭제하거나 기능을 누락하지 않는다.

기존 판단 요약·시장 흐름·판단 근거 미리보기·AI 세션을 새로 복제하지 않는다. 사용자가 요약에서 관심 항목을 고르면, 이미 있는 해당 화면의 근거로 이어지게 한다.

## 3. 기본 배치 — 결론과 주요 조작이 먼저

페이지 기본 순서는 **제목·요약 다시 읽기 → 현재 확인할 내용 → 시장 흐름 → 보유·후보 요약 → 자료·연구 상태**다. 이는 역할 순서이며 영역마다 새 카드를 하나씩 더 만들라는 뜻이 아니다. 기존 영역을 재배치·압축하고 중복을 줄인다.

- 첫 요약은 기존 응답이 말하는 확인 대상·자료 문제·현재 상태를 짧게 보여 준다. 여러 숫자로 새 종합 점수·투자 위험 등급·오늘의 매수/매도 결론을 만들지 않는다.
- 기존 판단 확인 대상과 자료 정비 항목을 구분한다. ‘자료를 읽지 못함’을 투자 위험처럼 표시하거나, 투자 판단 항목을 단순 자료 오류로 바꾸지 않는다.
- 영역별로 **결론 한 줄 → 관련 화면으로 이동 → 짧은 근거·기준일**을 기본으로 한다. 결론이 없는 상태도 ‘아직 불러오지 않음’·‘확인할 수 없음’ 등 사실대로 표현한다.
- 상세 표 전체·24종 예측표·연구의 모든 오차표·긴 개발 설명은 대시보드에 옮기지 않는다. 원래 화면에서 확인한다.
- 기존 KOSPI 대표 차트가 전체 폭을 쓰고 있으면 이를 기본으로 유지한다. 요약을 넣으려고 차트를 반쪽으로 줄이거나 글자를 작게 만드는 안은 기본안으로 쓰지 않는다. 변경이 필요하면 목업에서 사용자에게 그 배치를 명시해 확인받는다.

1440×900 첫 화면에서 전체 요약과 주요 이동 목적지를 파악할 수 있게 한다. 모든 근거·차트·상태를 첫 화면에 억지로 넣지 않는다. 1000px에서는 읽을 수 있는 크기를 유지하며 자연스럽게 세로로 배치한다.

## 4. 요약에 담을 내용과 재사용 기준

아래는 확인할 정보 범위다. 실제 필드의 존재를 보장하는 목록이 아니다. PLAN에서 **현재 응답 → 요약 → 상세 목적지**로 연결한다.

| 영역 | 요약할 내용 | 의미를 보존할 조건 |
|---|---|---|
| 시장 흐름 | 기존 KOSPI·KODEX200 국면/변화, 이미 제공하는 코스피 수급·원/달러·WTI의 핵심 관측 | 기존 요약·표시값 재사용. KOSPI와 KODEX200, 서로 다른 자료일·기간을 구분 |
| 보유 점검 | 기존 보유 근거·확인 대상과 관련 화면으로의 이동 | 기존 대상 선정·문구·순서 재사용. 새 종합 위험 분류를 만들지 않음 |
| 후보 살펴보기 | 이미 저장·조회된 후보 목록의 현재 조건·기간과 짧은 요약 | 기존 순위 유지. 저장된 목록이 없으면 부재와 목록 화면 이동을 표시 |
| 자료·연구 상태 | 기존 자료 정비 항목과 저장된 전향 기록·비교 결과의 간단한 현황 | 운영 자료 상태와 연구 상태를 나누고, 연구 수치를 투자 권고로 표시하지 않음 |

목록을 압축하면 기본은 기존 순서의 첫 3개 이내다. 전체 건수가 기존 응답에 있으면 함께 보이고 ‘전체 보기’를 제공한다. 서로 다른 확인 항목을 임의로 합쳐 총 위험 건수를 만들거나 중복 건수를 유일 종목 수로 부르지 않는다. 영역에 이미 적절한 요약 문장이 있으면 그 문장을 우선 재사용한다.

후보의 수익률·순위를 보여 줄 때는 해당 목록의 실제 기준 기간·사용 필터를 확인할 수 있게 한다. 저장된 기본 1개월 목록을 사용자의 3개월 설정 결과처럼 표시하지 않는다. 후보 요약을 만들기 위해 무거운 목록 계산을 자동으로 실행하지 않는다.

수급·환율·유가는 이미 만들어진 시장 흐름 관측과 그 기준일을 요약한다. 그 조합에서 새로운 ‘상승/하락 원인’·경보·매매 권고를 추론하지 않는다. 관측값이 없거나 응답이 실패했으면 없는 이유와 상세 동선을 보인다.

## 5. 숫자·날짜·상태와 쉬운 한국어

- 상단의 **조회 시각**은 이 PC가 요약을 읽은 시각이다. 시장 종가일·수급일·해외 자료일·연구 기준일과 구분한다. 전체를 하나의 ‘오늘 기준’으로 덮지 않는다.
- 기간이 다른 변화율은 기간을 각각 적고, %·%p·통화·금액 단위를 원래대로 유지한다. 요약에서 수익률·평균 오차·위험 정도를 다시 계산하지 않는다.
- 기존 자료일·검사 결과만으로 확인되는 상태를 보인다. 새 휴장 달력·며칠 경과 임계값·자료 신선도 판정을 만들지 않는다. 정식 원인 없이 ‘오래됨’을 ‘수집 실패’로 단정하지 않는다.
- ‘자료 없음’·‘아직 조회 안 함’·‘불러오기 실패’·‘일부만 확인됨’·‘정상적으로 비교할 결과가 아직 없음’을 구분한다. null·누락·실패를 0·정상·미채택으로 바꾸지 않는다.
- 한 영역의 조회 실패는 해당 영역에 표시하고 다른 정상 영역은 유지한다. 이전 정상 결과를 남겨 보일 때는 그 조회 시각과 현재 실패를 함께 표시한다.
- 문구는 쉬운 한국어로 쓴다. 표 이름·작업 번호·식별자·원시 진단은 기본 요약에서 제외하고 기존 상세로 이어 준다. 오류·경고 자체는 접힌 기술 정보에만 숨기지 않는다.

기존 ‘정상’이라는 글자가 실제로 보고 존재·조회 성공·자료 준비만 뜻한다면 그 범위에 맞춰 표현한다. 전체 시스템 정상이나 투자에 사용 가능하다는 결론으로 확대하지 않는다.

## 6. 조회와 실행 경계

기본은 **현행 대시보드의 순수 조회·캐시·요약 함수를 재사용**하는 것이다. 기존 상세 API를 여러 개 무조건 호출해 놓고 그 화면들을 숨겨 렌더링하는 방식은 쓰지 않는다.

1. 현행 초기 조회·명시적 재조회·캐시 무효화 계약을 확인해 유지한다. 새 자동 수집·계산을 추가하지 않는다. 조회하지 않은 상태라면 명확한 안내와 읽기 버튼을 제공한다.
2. ‘요약 다시 읽기’는 필요한 저장 자료를 다시 읽는다. `/market/topn/latest` 같은 후보 재계산 경로를 초기 진입·재마운트·요약 재조회에서 새로 호출하지 않는다. 후보 스냅샷 부재를 무거운 계산으로 대체하지 않는다.
3. 이미 있는 저장 결과·기존 순수 GET에서 필요한 필드를 얻을 수 있으면 그대로 연결한다. 현행 캐시가 있으면 사용하고, 캐시가 없다는 이유로 새 장기 캐시·DB·스냅샷 저장 계약부터 만들지 않는다.
4. 기존 자료 정비 구역에 명시적 갱신 버튼이 있으면 읽기 버튼과 역할을 구분하고 기존 실행·성공/실패·재조회 조건을 유지한다. 이 단계에서 정비 버튼을 자동 실행하거나 ‘전체 자료 한 번에 최신화’로 넓히지 않는다.
5. 이번 연결에 새 조회가 꼭 필요하면 PLAN에 현재 제공되지 않는 필드·정확한 원천·읽는 범위·비용·부작용을 질문으로 올린다. 작은 읽기 API 하나로 해결되는지 판정하며, 조사 중 새 API·테이블을 먼저 만들지 않는다. 신규 수집·모델 로드·학습·예측·성숙·보고 생성·SSH·파일 쓰기 API는 허용하지 않는다.

새 외부 자료원·패키지·차트 라이브러리·라우터·권한 체계·운영 일정은 없다. 요약을 만들려고 현재 시장/연구 계산을 프런트에 복제하지 않는다. 공용 표시 부품과 짧은 연결 함수는 허용하되 대형 파일에 영역별 처리를 모두 쌓지 않는다.

## 7. ‘자료 → 학습 → 예측 → 결과’ 요구의 처리

이번 대시보드에서 연구 현황을 압축해서 보여 줄 수 있지만, 확인 범위를 사실대로 적는다.

| 확인 가능한 자료 | 요약할 수 있는 뜻 | 대신 확정하면 안 되는 것 |
|---|---|---|
| 기존 예측 응답의 입력 판·수신 시각 | 해당 예측이 사용한 입력 | OCI 전체 수집 완료·PC 전체 최신화 |
| 사용 모델 판 식별 | 그 예측에 쓰인 모델 판 | 오늘 학습 완료·월별 학습 성공 |
| 정상 주 기록·공개 확인 | 확인된 기준일의 예측 기록 | 매 거래일 무누락·마감 전 기록의 영구 보장 |
| 저장된 성숙 상태·누적 보고 | 기존 비교 결과의 유무와 범위 | 투자 효용·총수익·운영 채택 |

실제 학습 시각·수집 상태가 기존 경량 응답에 없다면 모델 판 번호나 파일 수정 시각에서 추정하지 않는다. 완전한 전체 단계 상태판이 이번 연결만으로 만들어지지 않으면 미완료 요구로 유지한다. 이를 완성하려고 05/06/13의 기록 형식을 바꾸거나 새 감시 원장을 추가하지 않는다.

연구 상태는 자료/연구 구역에 두고, 시장·보유 요약과 같은 투자 판단 신호로 섞지 않는다. 이전 자료·실험의 준비도를 현재 전향 모델의 입력 상태로 다시 가져오지 않는다.

## 8. 목업과 확인할 사용성

목업은 기존 대시보드와 개선안을 같은 목차에서 비교할 수 있게 만든다. 1440×900·1000px 폭의 전체 화면을 제시한다. 기본 배치는 하나로 제안하고, 실제 충돌이 있을 때만 대안을 올린다.

확인할 장면은 정상 자료, 일부 영역만 조회 실패/자료 없음, 연구 비교 결과 대기다. 실제 없는 상태만 격리 자료로 만들고 표시한다. 목업에 라이브 실행 버튼을 연결하지 않는다.

사용자는 다음을 확인한다.
- 첫 화면에서 전체 상태와 살펴볼 내용, 자료를 확인해야 하는 내용을 구분할 수 있는가.
- 상세 화면을 돌아다니며 숫자를 머릿속으로 다시 조립하지 않아도 요약을 이해할 수 있는가.
- 기준일·기간이 달라도 오해하지 않고, 원하는 근거로 바로 이동할 수 있는가.
- 글자 크기·설명량·KOSPI 대표 영역·버튼 위치가 적절한가.

기존 개발 중 안내가 현재도 필요한지 대조한다. 이미 구현된 기능을 ‘개발 중’으로 남기지 않고, 아직 없는 기능을 다른 범위의 비슷한 값으로 대체하지 않는다. 긴 개발 목록은 상세 안내로 옮길 수 있지만 기존 기능과 진입점을 누락하지 않는다.

## 9. 개발자가 먼저 할 좁은 조사와 PLAN

현행 기반 문서·STATE와 이 설계를 읽고 **읽기 전용 구조 확인 45분 이내**로 아래 네 묶음을 제출한다. 현행 대시보드·직접 호출 요약·화면 이동만 따라가며 전체 저장소·과거 연구·OCI를 다시 감사하지 않는다.

1. **현재 화면 대조:** 주 대시보드·별도 기존 대시보드·영역별 요약이 실제로 무엇을 표시하는지 파일·메뉴 키·역할로 정리한다. 유지·이동·압축할 항목을 한 표로 연결한다.
2. **자료 연결:** 각 요약의 원래 응답 필드·판단 함수·자료일·상세 목적지를 적는다. 현재 응답으로 충분한지, 없는 필드인지, GET이 실제로 읽기만 하는지 구분한다. 새 조회가 필요하면 그 한계만 질문한다.
3. **조회·실행 비용:** 최초 진입·화면 왕복·다시 읽기의 호출 목록과 캐시·정비 버튼의 실제 효과를 대조한다. 외부 수집·후보 재계산·연구 실행으로 조사하지 않는다. 필요한 코드·검사 변경 범위를 적는다.
4. **개선 목업:** §8의 정상/부분 실패/연구 대기와 두 폭 화면을 보여 준다. 실제 자료로 기본 화면을 그릴 때는 순수 조회가 확인된 경로만 쓴다. 실제 수치·계정·개인 보유 원문은 보고서에 불필요하게 복사하지 않는다.

기존 요약을 연결하는 데 충분한 사실이 모이면 조사를 끝낸다. 아직 자료가 없는 영역 때문에 나머지 설계를 멈추지 않으며, 부족한 범위와 대안을 명시한다. PLAN 단계에서는 설계·PLAN·STATE 기록만 하고 구현·설치·외부 조회·DB/OCI 쓰기·커밋은 하지 않는다.

## 10. 검증·완료·진행

검증은 이번 요약과 이동·조회 경계에 집중한다.
- 요약 문구·숫자·기준일·기간·개수·상태가 같은 입력의 원래 영역과 일치한다. 비교 분모나 서로 다른 자료일을 합치지 않는다.
- 일부 실패·누락·정상 0·아직 안 읽음이 구분되고, 다른 정상 영역을 가리지 않는다. 이전 결과를 남겨 보이면 그 시각과 현재 실패가 표시된다.
- 실제 메뉴/요약 컴포넌트 관통 시험에서 상세 목적지가 맞고, 초기 진입·왕복·다시 읽기의 호출이 PLAN 계약과 같다. 외부 수집·후보 계산·모델 명령은 새로 실행되지 않는다.
- 자료 정비 버튼의 기존 실행·실패·재조회 동작을 보존한다. 중복 버튼으로 같은 명령을 두 번 호출하지 않는다.
- 프런트 타입·lint·관련 시험과 저장소 필수 검사를 수행한다. 백엔드 변경이 승인되면 그 읽기 경로 시험을 더한다. 새 변경·실패 근거 없이 전체 연구·06/13/OCI 재검증을 반복하지 않는다.

사용자 목업 확인·설계자 PLAN 판정 → 구현·필요 검사 → 사용자 실화면 확인 → 검증자 → RESULT 판정 순서로 진행한다. 실화면은 요약을 읽고 필요한 상세로 이동하는 것까지 확인하면 되며, 월 변경 학습·성숙 결과·새 투자 성과를 기다리지 않는다.

완료는 **기존 대시보드에서 현재 확인할 내용을 이해하고 기존 근거로 이동할 수 있는 요약 구조**다. 새 추천 효용·위험 등급·운영 ML 채택을 완료로 적지 않는다. 자료·UI·ML을 함께 발전시킨다는 사용자 방향, Q6 OPEN·운영 ML 미승격·기존 미완료 요구·POC6-12 SOURCE_BLOCKED·05/06/13 운영을 유지한다.

커밋·push는 그때의 사용자 승인 범위로 진행한다. OCI pull·cron·키·새 업로드·별도 handoff는 이번 UI 단계에 필요 없다. 사용자 소유 handoff·연구 산출물·개인 캐시·로컬 연구 브랜치는 커밋에 넣지 않는다.
