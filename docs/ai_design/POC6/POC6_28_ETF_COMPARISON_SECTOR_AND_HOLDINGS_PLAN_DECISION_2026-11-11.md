## 3. 섹터 요약과 AI용 근거

- 11/9 종가 표본에서 1개월·3개월 상위 30개 중 사업군 사전으로 분류된 ETF는 각각 1개다. 첫 줄은 1개월 ‘해외 주식 26개’, 3개월 ‘국내 채권 23개’처럼 공식 기준정보에서 확인한 구성이다. 이어서 ‘사업군 분류 1/30 · 공통 업종 확인 어려움’을 보여 준다. 기초지수별 묶음과 미분류는 펼쳐서 본다. 지역·자산·운용 전략과 업종을 구분한다.
- 하위권은 실제로 반복된 묶음을 먼저 보여 준다. 1개월 하위의 ‘반도체 ETF 16개 · 서로 다른 지수 15종’이 한 사례다. 공통 종목은 ‘구성 자료 있는 ETF 4/16 · 각 비중 상위 10종목 · 구성 기준일 10/2’처럼 실제 확인 범위를 붙인다. 표본 0개와 겹침 0건을 구분한다. 묶음별 수익률은 선택한 기간의 실제 값으로 읽는다.
- **상위 또는 하위 목록 전체를 AI에 복사할 수 있게 한다.** 같은 지수의 단일 묶음만 복사하면 상위권에 흩어진 테마를 비교하기 어렵다. 선택한 쪽의 ETF명·기초지수·수익률과 기간, 확인된 구성종목·비중·자료일을 담고 구성 자료가 없는 범위도 알려 준다. 고정 질문은 여러 ETF에서 반복된 근거, 이름에서 유추한 가설, 판단에 부족한 자료를 나눠 달라는 내용이다. 복사는 PC 클립보드에서 끝난다.

## 4. 가격 시점과 보유 근거

- **가격의 시점과 저장 시각을 구분한다.** 예를 들어 11/10 13:18에 저장한 KODEX 200 가격은 ‘장중 저장값 · 11/10 13:18 저장’으로 읽는다. 여러 종목의 요약에는 ‘장중 저장값 포함 · 잠정’으로 표시한다. 저장 시각은 저장 사실이며 시세 관측 시각을 확인한 경우에만 관측 시각을 쓴다. 종가 여부를 구분할 근거가 부족하면 ‘PC 저장 가격 · 마감값 확인 필요’로 표시한다. 다음 날에도 실제 자료 상태로 표시하며 다시 읽은 뒤에는 새 자료의 상태를 반영한다.
- 기준 줄과 선택 행의 가격·비교 설명, 차트의 가격 이름, AI 복사문에 같은 의미를 적용한다. 국면은 같은 기준일의 국내 KODEX 200 판정을 사용한다. 장중 판정은 잠정이라고 밝히고, 같은 기준일의 판정을 확인하기 어려우면 기본 표시 순서를 쓴다.
- **보유 기본 행은 종목명·보유 내 비중·매입 대비 손익을 먼저 보여 준다.** 상세에서 최근 가격 변화의 실제 두 날짜와 같은 기간 KODEX 200 비교를 읽는다. 비교는 기존 비교 상태와 양끝 날짜가 맞을 때만 표시한다. 확인된 후보 조회 기간의 수익률과 상·하위 위치는 해당 보유에 연결한다. 상·하위 밖은 순위 포함 여부로만 읽고 보유 가격 자료의 유무는 따로 판단한다. 보유 월간 수익률은 확인된 값이 있을 때 상세에 표시한다.
- 직접 보유가 하위권이면 순위와 해당 기간 수익률을 사실로 표시한다. 해당 수익률이 음수일 때 가격 점검 사유로 연결한다. 기존 보유 하락 배지는 기존 판정 기준을 쓴다. 후보와 보유 근거의 기준일이나 장중·마감 상태를 맞춰 읽을 수 없으면 두 근거를 날짜와 함께 따로 보여 준다. 장중 근거의 하락 표시는 장중임을 함께 밝힌다. 구성종목 겹침은 ‘노출 확인’으로 표시하고 양쪽 구성 기준일을 붙인다.

## 5. 순위표와 비교 가능한 기간

- **조회 기간은 목록을 고르고, 정렬 버튼은 그 목록을 다시 배열한다.** 예를 들어 ‘1개월 하위 30 · 3개월 수익률 낮은 순’이면 1개월 하위 목록이 그대로 표시 대상이다. 원래 선정 순위와 정렬 기준을 구분해서 표시한다. 1일 조회에서는 1일 수익률과 선정 순서를 먼저 보여 주고, 네 정렬 버튼은 목록 안에서 사용한다. 조회 조건 변경 후에는 요약과 순위에 같은 응답의 결과를 적용한다.
- 네 기준은 **1개월 수익률 · 3개월 수익률 · 1개월 KODEX 200 대비 · 최근 고점 대비**다. 행은 순위·ETF명·선택 기준값을 중심으로 읽는다. 실제 PC 화면에는 ‘보유’ 표시를 제공한다. KODEX 200 비교와 고점은 날짜와 기준값을 상세 한 줄에서 확인한다. 행에서 본 수익률을 상세 박스로 반복하지 않는다. 계산 원값이 0인 **0.00%**는 유효값이다. 계산 근거가 부족한 행은 해당 기준을 읽을 때 사유를 표시한다.
- 기준별 공통 시작일·끝일을 확인한다. 1개월과 3개월은 해당 기간의 공통 가격 날짜, 1개월 KODEX 200 대비는 그 두 날에 ETF와 KODEX 200 가격이 모두 유효한지를 본다. 최근 고점은 기존 계산으로 확인한 KODEX 200의 비교 창과 시작·끝 날짜가 맞고 유효 가격 수를 충족하는 값끼리 정렬한다. 3개월보다 늦게 상장된 ETF는 ‘기간 다름’으로 표시하고 상세에서 실제 구간을 볼 수 있다. 순위표는 기간이 맞는 값부터 정렬하며, 기간 다름·값 없음은 어느 방향에서나 뒤에 둔다. 동률과 비교 제외 행의 표시 순서는 선정 순서를 사용한다.
- 같은 1개월 구간의 유효 값에서는 KODEX 200 수익률이 공통이므로 두 기준의 순서가 같다. 이 설명은 비교 가능한 행에 적용하고 값이 빠진 행은 따로 표시한다. 11/9 종가 표본은 KODEX 200 **−22.64%**, 11/10의 장중 저장 행을 사용한 사례는 **−19.83%**였다. 두 사례의 기준일을 나누고 실화면에서는 해당 조회의 실제 값과 기간을 쓴다. 수익률 차이는 **%p**로 표기한다.

## 6. 완료 확인과 다음 작업

| 확인 대상 | 확인할 내용 |
|---|---|
| 후보 · AC1 | 실제 자료에서 상위권의 확인 범위와 하위권 묶음 한 건을 읽는다. 11/9의 1개월 하위 목록을 3개월로 다시 정렬해도 목록은 같고, 기간이 짧은 4개는 양쪽 정렬에서 뒤에 놓인다. 최근 고점과 같은 유효 0.00%를 결측과 구분한다. |
| 보유 · AC2 | 한 행을 열어 매입 대비 손익과 최근 가격·시장 비교를 구분한다. 직접 하위권·실제 하락·노출 확인이 섞이지 않고, 서로 다른 가격 기준일도 읽을 수 있다. |
| 확인 경로 · AC3 | 구성 자료가 없는 ETF에서 기존 확인 경로에 도달한다. 개별 주식의 해당 없음은 조치 목록에서 빠진다. VIX 등 공통 자료는 기존 자료 확인 경로에서 찾는다. |
| 국면 · AC4 | 국면에 따라 표시 순서와 강조가 바뀐다. 장중 저장값이 다음 날짜에 남는 사례와 새 가격을 다시 읽은 사례에서 실제 날짜와 가격 상태를 구분한다. |

개발자는 판정을 PLAN과 필요한 목업 문구에 반영한 뒤 격리 구현한다. 구현 중 기존 자료로 확인할 수 있는 범위가 달라지면 해당 부분의 자료와 화면을 설계자에게 돌려준다. 변경 범위의 집중 시험을 우선하고 전체 회귀는 구현 마감 때 한 번 수행한다. 검증자는 구현 뒤 실제 화면과 필요한 응답을 대조한다. 형수님은 **어느 묶음을 더 볼지**, **보유 한 건에서 어떤 근거를 다시 볼지** 찾을 수 있는지 본다.

복합 순위·가중치, 새 분류 자료, OCI 장중 요약·PUSH는 기존 설계의 BACKLOG 후보로 관리한다. 장중·마감 시세를 수집 단계에서 구분하는 작업도 별도 후보로 둔다. 지금 섞인 저장 이력만으로는 마감값을 일관되게 식별하기 어렵다. 시세의 종류와 실제 관측 시점을 저장·조회 경로에서 구분할 수 있는지가 재검토 기준이다.
