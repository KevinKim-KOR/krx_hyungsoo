## 4. 구현 전에 PLAN에 반영할 필수 기준

### 시장 수치와 자료 날짜

- 실제 종가와 비교 저점은 각각 관측값과 기준값·기준일로 표시한다. 사례의 11/6 종가는 **5,059.69**, 비교 저점은 **5,383.80(11/5)**이다. 날짜가 같아야 붙일 수 있는 문구에는 ‘직전 거래일’을 쓰고, 그 외에는 기준값의 실제 날짜를 적는다. 기존 화면 문장은 그대로 제공하고, 표시·복사에 쓰는 구조화 필드만 추가한다. 새 `freshness` 최상위 필드와 새 하위 필드가 실제 GET 응답에 전달되는지 확인한다. 옛 응답에서 구조화 값이 빠졌으면 해당 값은 ‘확인 불가’로 표시하고, 남기는 사건 원문은 비교 기준값임을 명시한다.
- 코스피 20·60거래일, 6개월 공통 비교 종료일, 자료별 최신성은 각각의 기준을 유지한다. **11/9 확인의 국내 기대일 11/6과 수급·원/달러 관측일 11/5**가 1거래일 지연으로 보이고, 6개월 비교가 11/5까지라는 설명도 따로 보인다. 기존 달력의 평일 대체를 쓰는 경우 그 기준을 함께 밝힌다. 날짜가 깨졌거나 기대일을 알 수 없으면 ‘기준 확인 필요’다.
- **WTI에는 VIX의 마감 시각과 1평일 허용 규칙을 적용하지 않는다.** PLAN에 WTI 전용 완료일 근거가 없으므로 이번 화면은 WTI의 관측일과 기존 자료 상태를 보여 준다. WTI 자체의 날짜만으로 새 지연 경고나 확인 창을 만들지 않는다. 시장 흐름 응답 전체가 실패하거나 핵심 비교 자료가 빠진 경우에는 기존 확인 필요 처리로 보여 준다. VIX는 기존 정비 기준을 사용한다.

### 확인 창과 조건 공유

- [요약 다시 읽기]는 기존 6개 저장 자료 조회를 사용하고, 확인할 때 화면에 함께 쓰는 시장 판정·코스피 기간 수치의 기존 스냅샷도 기준일을 대조한다. 그 스냅샷과 OCI를 다시 조회하는 경로는 추가하지 않는다. **[취소]는 임시 조회 결과를 버리며, 이전 화면·공유 캐시·성공 시각을 보존한다.** 일부 조회가 실패하면 남겨 둔 값의 기준일과 실패 사유를 밝힌다. [이 자료로 계속]은 창에 제시한 같은 자료를 적용한다.
- [AI용 시장 정보 복사]는 화면에서 확인한 자료와 기준서 §6 고정 프롬프트를 사용한다. 기준 확인이 필요한 핵심 자료도 요약과 같이 사용자 선택을 받는다. 복사가 실패하면 원문을 펼쳐 직접 복사할 수 있게 한다. 요약 확인을 기다리는 동안 같은 동작을 중복 실행하지 않는다.
- 같은 탭의 메뉴 이동 중에만 기간·정렬·제외 조건을 공유한다. 새로 고침 때는 기존 저장 기본 기간과 기존 기본 정렬·제외 조건을 사용한다. 위 요약과 아래 첫 3개는 같은 응답과 실제 조건을 사용한다. 오름차순을 선택하면 ‘수익률 낮은 순’으로 쓴다. 조건 조회 실패에 이전 목록을 보여 준다면 이전 목록의 실제 조건도 같이 적는다.

### OCI와 갱신 버튼

- 예약별 상태는 기동 때 이미 읽은 스냅샷에서 구분한다. 확인 실패를 예약 누락으로 세지 않는다. `latest-by-kind`는 기존 목록 조회에서 빠지는 ‘건너뜀·실패’를 보여 주기 위한 **PC 원장 사본 전용 읽기**로 수용한다. 실행 발생일시, 실행 결과, 마지막 동기화 시각을 분리한다. 조회 실패와 사본 없음은 서로 다른 상태다. 발송 여부를 알 수 없는 경우 기존 「받은 알림 기록」으로 이동해 확인할 수 있게 한다.
- 상단 최신화는 기존 작업과 진행 상태를 재사용한다. 보유 갱신은 전건 실패와 일부 실패를 구분한다. 시장 갱신은 완료 뒤 다시 읽은 자료의 실제 기준일을 대조해 성공·일부 실패와 날짜 차이를 알려 준다. 같은 작업을 화면 이동으로 새로 실행하지 않는다.

### 구현 환경과 확인

- 현재 PC 백엔드는 `--reload`로 코드 저장 때마다 기존 OCI 기동 조회가 발생한다. **그 서버가 감시하는 경로 밖의 격리 사본이나 작업 트리에서 구현과 시험을 시작한다.** 개발 중에는 기동 SSH와 외부 시세 갱신을 대체 응답으로 확인한다. 화면을 실제 서버에 올리는 재기동·OCI 읽기는 형수님의 실제 화면 확인 시점에 필요한 범위를 따로 맞춘다.
- PLAN의 관련 시험을 우선한다. 위 보완에 따라 **요약 취소 시 캐시·시각 유지**, **당일 동기화와 과거 실행 구분**, **정확히 일치한 사건만 중복 제거**, **두 카드 재진입 시 접힘**, **최근 최대 120개 차트 위치**, **조건 왕복 및 새로 고침**을 확인한다. 전체 회귀는 구현을 마감할 때 한 번 수행한다. 실제 저장 자료 화면에서 형수님이 시장·보유·후보와 자료 상태를 순서대로 읽고, 필요한 버튼을 찾을 수 있는지도 완료 기준에 포함한다.

## 5. 개발자 회신과 다음 절차

개발자는 PLAN §2의 화면 배치 1~7번을 연속된 표로 정리하고, 이 판정의 선택과 필수 보완을 PLAN에 반영한다. **위 조건을 반영한 뒤 격리 구현으로 이어가면 된다.** 코드에서 전제가 달라져 자료 의미·운영 경계나 범위를 바꿔야 할 때는 그 부분을 설계자에게 돌려준다.

개발자가 시험 결과와 저장 자료를 띄운 화면을 제출하면 검증자는 백엔드 응답과 화면 동작을 확인한다. 형수님은 첫 화면에서 시장·보유·후보를 읽고 필요한 버튼을 찾을 수 있는지 확인한다. 설계자는 두 확인 결과를 받고 RESULT를 판정한다. 실사용 반영과 커밋·push는 결과 판정 뒤에 다룬다.
