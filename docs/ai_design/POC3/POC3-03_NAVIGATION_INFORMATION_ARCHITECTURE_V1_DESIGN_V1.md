## 0. 설계 판정

POC3-03은 데이터나 투자 기능을 추가하는 단계가 아니다.
현재 완료된 9개 화면과 기존 화면 전환 key를 그대로 유지하면서, 평면적인 좌측 메뉴를 사용자의 실제 과업 순서로 묶는 순수 Navigation Step이다.
조언자의 원칙은 다음과 같이 적용한다.

- 데이터 정비와 화면 개발을 억지로 한 Step에 묶지 않는다.
- 이번 Step에는 데이터 작업 자체가 없으므로 데이터 선행 소Step을 만들지 않는다.
- 기존 메뉴만으로 구조를 만들 수 없다면 신규 route나 데이터를 추가하지 않고 BLOCKED로 설계자에게 복귀한다.
- 완료된 POC3-02 Judgment Workbench를 다시 열지 않는다.
- Workbench benchmark 시계열은 통합지도의 P-16 조건부 보류를 유지한다.

## 1. 현재 문제

현재 좌측 메뉴는 화면이 추가된 순서대로 평면 배치되어 있어 각 메뉴가 동일한 중요도로 보인다.
이 때문에 사용자는 다음을 머릿속으로 다시 조립해야 한다.

- 오늘 처음 열어야 할 화면
- 시장과 보유 ETF를 비교하는 화면
- 보유 정보와 원자료를 관리하는 화면
- 판단 초안과 알림 결과를 확인하는 화면

Dashboard와 Workbench는 이미 완성됐지만, 두 화면과 기존 상세 화면 사이의 관계가 메뉴에 표현되지 않는다.
이 상태에서 이후 실행·운영 화면을 추가하면 기능은 늘어도 사용 순서는 더 불명확해진다.

## 2. 이번 Step의 단일 목표

기존 화면·화면 전환 key·기능을 유지한 채 좌측 메뉴를 네 개의 과업 그룹으로 재편하여, 사용자가 현재 위치와 다음에 들어갈 화면을 즉시 찾게 한다.
이번 Step에서 사용자가 새로 수행할 수 있어야 하는 과업은 다음이다.

- 좌측 메뉴만 보고 현재 화면의 역할을 이해하고, 필요한 다음 화면으로 한 번의 메뉴 선택으로 이동한다.

## 3. 확정 메뉴 구조

### 3.1 그룹 순서

오늘 확인 → 비교·판단 → 보유·자료 관리 → 승인·운영

그룹명은 사용자 노출 문구다. 내부에서 Dashboard, Workbench, Operations Panel 같은 명칭을 노출하지 않는다.

### 3.2 화면 귀속

| 그룹 | 메뉴명 | 담당 역할 |
|---|---|---|
| 오늘 확인 | 오늘의 투자 점검 | 시장·보유·자료 상태에서 오늘 볼 것이 있는지 확인 |
| 비교·판단 | ETF 비교하기 | 시장 ETF와 보유 ETF를 한 화면에서 비교 |
| 비교·판단 | 요즘 잘 오르는 ETF | 시장 후보 조회·필터·갱신 |
| 비교·판단 | ETF 구성종목 | 구성종목·집중도·중복 노출 상세 확인 |
| 비교·판단 | AI 투자 세션 | AI 답변·사용자 판단·확인 항목 기록 |
| 보유·자료 관리 | 내가 가진 ETF | 보유 수량·평균단가·평가 정보 관리 |
| 보유·자료 관리 | 데이터 상태 | 자료 기준일·수집 상태·품질 확인 |
| 보유·자료 관리 | 기존 대시보드 | 초기 상태 화면을 삭제하지 않고 참고용으로 유지 |
| 승인·운영 | 승인·알림 | 판단 초안 승인·거절과 발송 결과 확인 |

각 기존 화면은 정확히 한 그룹에만 속한다. 같은 화면을 여러 그룹에 중복 노출하지 않는다.

### 3.3 우선순위 원칙

- 오늘의 투자 점검은 계속 첫 진입 기본 화면이다.
- ETF 비교하기는 비교·판단 그룹의 첫 번째 메뉴다.
- 기존 상세 화면은 삭제하거나 Dashboard에 합치지 않는다.
- 기존 대시보드는 보존하되 일상 진입 흐름의 중심으로 다시 올리지 않는다.
- 승인·알림은 자동 매매 화면이 아니라 기존 초안 상태 전이와 발송 결과 확인 화면이다.

## 4. 그룹과 접힘 동작

### 4.1 최초 진입

- 네 그룹은 기본적으로 모두 펼쳐진다.
- 오늘의 투자 점검이 선택된 상태로 표시된다.
- 네 그룹의 제목은 기본 PC 화면에서 즉시 식별할 수 있어야 한다.

### 4.2 사용자가 그룹을 접는 경우

- 그룹 제목을 선택하면 해당 그룹의 메뉴만 접거나 펼친다.
- 그룹 제목 자체는 화면으로 이동하지 않는다.
- 접기·펼치기만으로 API 호출이나 데이터 갱신이 발생하지 않는다.
- 접힘 상태는 현재 브라우저 세션의 UI 상태로만 관리한다.
- DB·파일·URL query·localStorage·sessionStorage에 저장하지 않는다.
- 접힘 상태 영구 저장은 기존 B-057 조건부 보류를 유지한다.

### 4.3 화면 내부 버튼으로 이동하는 경우

접힌 그룹에 속한 화면으로 기존 화면 내부 버튼이 이동시키면 다음처럼 동작한다.

- 목적지 그룹을 자동으로 펼친다.
- 목적지 메뉴를 선택 상태로 표시한다.
- 기존 방식대로 화면을 전환한다.
- 다른 그룹의 사용자가 직접 접은 상태는 임의로 초기화하지 않는다.
- 현재 선택된 메뉴가 숨겨진 채 화면만 바뀌는 상태는 허용하지 않는다.

## 5. 반드시 보존할 기존 이동 흐름

메뉴 재편 후에도 다음 직접 이동은 그대로 동작해야 한다.

- 오늘의 투자 점검 → ETF 비교하기
- 오늘의 투자 점검 → 요즘 잘 오르는 ETF
- 오늘의 투자 점검 → ETF 구성종목
- 요즘 잘 오르는 ETF → ETF 구성종목
- 요즘 잘 오르는 ETF → AI 투자 세션
- ETF 구성종목 → AI 투자 세션
- 보유 초안 생성 → 승인·알림

기존 draft와 선택 정보의 전달 방식, sessionStorage 기반 Context Bridge, 화면별 캐시와 조회 조건을 변경하지 않는다.
화면 이동 후 대상 그룹과 메뉴의 선택 표시가 실제 열린 화면과 일치해야 한다.

## 6. 화면 표현 원칙

- 그룹 제목과 메뉴명의 정보 계층을 시각적으로 구분한다.
- 현재 메뉴는 색상 또는 배경과 글자 굵기로 명확히 표시한다.
- 현재 그룹도 과하지 않은 방식으로 활성 상태를 나타낸다.
- 그룹 제목에는 접힘 상태를 알 수 있는 표시를 둔다.
- 메뉴명은 잘리거나 한 글자씩 세로로 내려가지 않아야 한다.
- 보조 설명은 기존 의미를 유지하며 최대 두 줄 안에서 읽혀야 한다.
- 사이드바의 기존 폭과 전체 화면 레이아웃을 불필요하게 변경하지 않는다.
- 새로운 아이콘 체계나 디자인 시스템은 도입하지 않는다.
- 내부 key·API명·컴포넌트명은 사용자 화면에 노출하지 않는다.

## 10. 완료 기준 AC

1. 좌측 메뉴가 오늘 확인 / 비교·판단 / 보유·자료 관리 / 승인·운영 네 그룹으로 표시된다.
2. 현재 존재하는 모든 화면 전환 key가 정확히 한 그룹에 귀속되며 중복·누락·신규 key가 없다.
3. 첫 진입 화면은 계속 오늘의 투자 점검이다.
4. 선택한 화면과 좌측 메뉴의 활성 표시가 항상 일치한다.
5. 접힌 그룹의 화면으로 내부 이동이 발생하면 해당 그룹이 자동으로 펼쳐진다.
6. 그룹 접기·펼치기는 화면 전환·API 호출·데이터 갱신을 발생시키지 않는다.
7. 기존 직접 이동과 Context Bridge가 모두 유지된다.
8. 메뉴에서 내부 명칭 Workbench, Market Discovery, Holdings, ETF Exposure, Data Status, Operations Panel이 사용자 문구로 노출되지 않는다.
9. 접힘 상태를 DB·파일·브라우저 저장소·URL에 영구 저장하지 않는다.
10. 1440×900 실제 화면에서 네 그룹 제목과 현재 위치가 가로 잘림 없이 식별된다.
11. 메뉴명과 보조 설명이 한 글자 단위로 세로 줄바꿈되지 않는다.
12. 기존 각 화면의 데이터 조회·저장·승인·알림 동작과 캐시 의미가 변경되지 않는다.
13. 신규 API·DB·화면·데이터 계약과 백엔드 변경이 없다.
14. 실제 화면에서 사용자가 오늘의 투자 점검 → ETF 비교하기 → 내가 가진 ETF → 승인·알림을 각각 한 번의 메뉴 선택으로 이동할 수 있다.
15. 자동 검증만으로 완료하지 않고, 사용자가 실제 화면에서 메뉴 구조와 이동을 확인한다.
