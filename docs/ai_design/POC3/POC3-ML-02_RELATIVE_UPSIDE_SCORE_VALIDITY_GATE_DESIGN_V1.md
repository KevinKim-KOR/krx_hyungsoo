## 1. 역할

당신은 개발자다.

이번에는 구현하지 말고, 현재 화면에 연결된 `relative-upside baseline v0` 점수의 실제 유효성을 검증하기 위한 개발플랜만 작성한다.

플랜은 채팅으로 제출하며 별도 PLAN 문서를 만들지 않는다.

- POC3-ML-01 feature/evidence 체인 복구 완료·VERIFIED
- `market_risk_feature_daily`: 3,013행
- ETF feature DB: 전 구간 backfill 완료

## 4. 개발플랜에 반드시 포함할 것

### 4.1 검증 대상 동결

- 평가할 모델·score 버전
- feature 컬럼
- 학습 데이터 기준일
- model/artifact 경로와 식별 방법
- 검증 중 feature·모델·점수 산식을 변경하지 않는 방법

### 4.2 시점 정합성과 누수 방지

- 각 기준일 당시 사용 가능한 feature만 사용하는 방법
- 학습·검증 기간 분리 방식
- forward label 생성 방식
- 동일 ETF의 중첩된 미래 구간 처리
- benchmark 거래일 정렬
- 미래 데이터 누수 검사
- 현재 universe 사용에 따른 생존편향 여부와 한계

point-in-time universe를 기존 데이터로 복원할 수 없다면 숨기지 말고 판정 제한 조건으로 명시한다. 신규 외부 데이터는 추가하지 않는다.

### 4.3 평가 기간

- 1개월 forward 초과수익: 주 기준
- 3개월 forward 초과수익: 보조 기준
- 전체 평가 기간과 연도별 표본 수
- train/validation/test 또는 walk-forward 구간
- 최소 표본 수 부족 시 처리

### 4.4 필수 평가 지표

- score와 향후 초과수익의 순위 상관
- 상위 점수군과 하위 점수군의 성과 차이
- 상위 점수군의 KODEX200 대비 평균·중앙값 초과수익
- KODEX200 대비 승률
- 연도별 결과
- 기존 시장 상태별 결과
- 점수 산출 가능 ETF 비율과 결측 원인
- 저빈도 리밸런싱 turnover
- 거래비용 반영 전후 결과
- 결과의 불확실성 또는 신뢰구간

### 4.5 운영 가정

- 직장인형 저빈도 운영 주기
- 동일 시점 중복 ETF 처리
- top-N 또는 점수군 구성 방식
- 거래비용 가정과 민감도
- 신규 상장·상장폐지·가격 결측 처리
- 매수·매도 자동화 없이 참고점수의 유효성만 평가하는 경계

### 4.6 사전 판정 기준

결과를 본 뒤 기준을 바꾸지 않도록 구현 전에 다음을 수치로 제안한다.

- `ADOPT` 필수 조건
- `RESEARCH_ONLY` 조건
- `REJECT` 조건
- 누수·생존편향·표본 부족 등 결과 수치와 관계없이 판정을 제한하는 조건

- 전체 결과와 연도별·시장별 결과가 충돌할 때의 판정 규칙

각 기준에는 선택 근거를 적는다.

### 4.7 산출물

- 재현 가능한 평가 결과 JSON
- 사람이 판단할 수 있는 결과 요약

## 9. 설계자 판정 — `PLAN_REVISE_REQUIRED` (2026-08-29)

> 현재 상태로는 구현에 들어가면 안 됩니다.
>
> 가장 큰 이유는 **E2가 현재 `relative-upside v0`를 검증하는 것이 아니라, purge·embargo가 추가된 다른 재학습 방식의 성능을 검증하게 된다는 점**입니다. 나머지 구조는 잘 잡혔지만 검증 대상이 달라지면 결과 전체가 무의미해집니다.
>
> ## M-1~M-5 판정
>
> | 항목 | 판정 | 결정 |
> | --- | --- | --- |
> | M-1 평가 universe | 수용 | 필터 universe 전체를 주 평가, 전체 universe를 진단, 실제 화면 슬레이트를 필수 보조 평가로 사용 |
> | M-2 E1/E2 | 부분 수용 | E2 주·E1 보조는 유지하되, E2는 현재 실행 레시피를 그대로 재현해야 함 |
> | M-3 생존편향 | 수용 | 최대 판정은 `RESEARCH_ONLY`로 제한 |
> | M-4 평가 달력 | 부분 수용 | 월말 신호는 유지하되 실제 진입가격은 다음 거래일 가격을 사용 |
> | M-5 판정 기준 | 부분 수용 | 25bp와 경제적 기준은 유지하되 통계 기준과 화면 슬레이트 기준을 수정 |
>
> ## 반드시 수정할 내용
>
> ### 1. E2에서 별도 embargo를 제거해야 합니다
>
> 현재 계획은 기준일마다 `purge + 추가 20거래일 embargo`를 적용합니다. 이것은 현재 운영 모델의 실행 레시피가 아닙니다.
>
> E2는 다음처럼 정의해야 합니다.
>
> 1. 기준일 `t` 이후 가격을 입력에서 제거
> 2. 기존 feature/model/score 함수를 변경 없이 호출
> 3. 현재 `train_walk_forward`의 80/20 split과 학습 동작을 그대로 사용
> 4. 해당 시점에 실제로 생성됐을 점수를 재현
> 5. 별도 purge·embargo 규칙을 추가하지 않음
>
> `target_end < t`인 행만 사용할 수 있다는 시점 정합성은 유지합니다. 하지만 추가 20거래일 embargo는 제거합니다.
>
> 현재 방식대로 embargo를 추가하면 평가 대상은 `relative-upside v0`가 아니라 **수정된 신규 레시피**가 됩니다.
>
> C-2도 다음처럼 표현을 고쳐야 합니다.
>
> > train/test 경계의 target 중첩으로 내부 `test_loss`의 독립성이 훼손됐다. 다만 충분히 뒤의 E1/E2 forward 평가까지 곧바로 누수됐다는 뜻은 아니다.
>
> ### 2. E1은 '동결 모델'이 아니라 '재현 모델'입니다
>
> 현재 모델 가중치가 저장되지 않았으므로 동일 모델이라고 먼저 선언할 수 없습니다.
>
> 다음을 추가해야 합니다.
>
> * 입력 데이터는 현재 DB 전체가 아니라 기존 실행 기준일인 `2026-08-20`까지로 제한
> * 당시 snapshot의 1,157개 ticker 목록과 재현 후보 목록 대조
> * 재생성한 2026-08-20 점수와 저장 snapshot 점수 비교
> * 점수 오차 허용범위와 순위 일치율 사전 정의
> * 위 조건을 통과해야만 `E1_RECONSTRUCTED`로 인정
> * 재현에 실패하면 `E1_UNAVAILABLE`로 보고하고 E2만 수행
>
> 현재 계획처럼 8월 27일까지의 입력 데이터 해시를 사용하면 8월 20일 모델의 동결 기술자가 아닙니다.
>
> PyTorch 결과는 실행 환경에 따라 미세하게 달라질 수 있으므로 비트 단위 완전 일치보다 다음을 사용합니다.
>
> * 후보 집합 일치
> * 계수 허용오차
> * 점수 최대 절대오차
> * 순위 일치율
>
> ### 3. 같은 날 종가로 신호 생성과 매수를 동시에 가정하면 안 됩니다
>
> 현재 계획은 월말 `t` 종가로 feature를 만들면서 같은 `t` 종가를 진입가격으로 사용합니다. 실제 사용자는 종가를 확인한 뒤 그 종가로 소급 매수할 수 없습니다.
>
> 평가 계약을 다음으로 수정합니다.
>
> * 판단일: 월말 거래일 `t`
> * 진입일: `t` 다음 KODEX200 거래일
> * 진입가격: 다음 거래일 종가
> * 청산·교체가격: 다음 리밸런싱 진입일 종가
> * ETF와 KODEX200은 동일한 진입·청산 날짜 사용
> * 해당 날짜 가격이 없으면 제외하고 결측 사유 기록
>
> 1개월 구간은 이 방식으로도 서로 겹치지 않습니다.
>
> ### 4. U2는 실제 화면 후보 생성 순서를 재현해야 합니다
>
> 화면의 Top 10은 ML 점수 상위 10개가 아닙니다.
>
> 각 과거 기준일에 다음 순서를 그대로 재현해야 합니다.
>
> 1. 인버스·레버리지·합성·선물 제외
> 2. `one_month desc` 기준으로 Top 10 선정
> 3. 그 10개에 relative-upside 점수 결합
> 4. 점수로 화면 표시 순서 재정렬
> 5. 상위 절반과 하위 절반의 향후 초과수익 비교
>
> 전체 universe에서 점수를 0~100으로 정규화해도 순위가 단조 변환이면 필터 universe 내부 순서는 바뀌지 않습니다. 따라서 전체 universe 평가는 "베타를 잡았다는 증명"이 아니라 **제외 상품군에 결과가 민감한지 보는 진단**으로 표현을 낮춰야 합니다.
>
> ### 5. 판정 기준을 다음처럼 수정합니다
>
> * A-1: 평균 IC `>= 0.03` 유지
> * 기존 `t >= 2.0` 대신 6개월 block bootstrap 95% CI 하한 `> 0`
> * t값은 참고 수치로만 보고
> * A-2: 편도 25bp와 월 `+0.30%` 기준 유지
> * 비용은 실제 월별 turnover에 적용
> * A-2의 net 상위군 수익도 bootstrap 95% CI 하한 `> 0`
> * A-4: 실제 화면 Top 10에서 점수 상위 절반−하위 절반 평균 `> 0`이며, 상위 절반이 이긴 월 비율 `> 50%`
> * R-4: bear 표본이 12개 이상이고, 평균 IC `< -0.02`이면서 bootstrap CI 상한도 `< 0`일 때만 적용
> * coverage 분모는 해당 날짜의 **PIT 편입 가능 필터 universe**
> * E1의 명백한 반박은 평균 IC와 화면 슬레이트 차이가 모두 음수일 때로 정의
>
> 25bp는 0·10·25·50bp 민감도와 함께 제시하므로 그대로 승인합니다.
>
> ### 6. label shuffle의 의미를 낮춰야 합니다
>
> label shuffle은 누수 전체를 발견하는 검사가 아닙니다. 미래수익이 feature에 들어 있어도 라벨을 다시 섞으면 상관은 사라질 수 있습니다.
>
> 따라서 다음처럼 수정합니다.
>
> * 고정 seed의 반복 permutation을 사용
> * shuffle은 통계·metric 구현의 negative control로 분류
> * 실제 누수 차단은 미래 입력 제거, 날짜 assertion, target 종료일 검사로 판정
> * shuffle 결과 하나만으로 "누수 있음/없음"을 단정하지 않음
>
> ### 7. 생존편향 판정 상한은 유지합니다
>
> M-3의 `(가)`를 승인합니다.
>
> 다만 "성과를 좋은 방향으로만 왜곡한다"는 단정은 삭제해야 합니다. 일반적으로 낙관 편향 위험이 크지만, 횡단면 IC와 분위 스프레드에 미치는 정확한 방향과 크기는 현재 데이터로 측정할 수 없습니다.
>
> 판정 상한의 근거는 다음입니다.
>
> > 편향의 크기와 방향을 정량화할 수 없으므로 `ADOPT`의 충분한 근거로 사용할 수 없다.
>
> 따라서 이번 Step의 실제 가능 판정은 다음 두 가지입니다.
>
> * survivor-only 데이터에서도 실패 → `REJECT`
> * 수치 기준 통과 → 최대 `RESEARCH_ONLY`
>
> 검증이 헛도는 것은 아닙니다. 낙관적일 가능성이 있는 데이터에서도 실패하면 현재 점수를 버릴 강한 근거가 됩니다.
>
> ### 8. 가격의 의미를 확인해야 합니다
>

>
> 신규 외부 데이터 수집은 하지 않습니다.
>
> ## 유지해도 되는 내용
>
> 다음은 그대로 승인합니다.
>
> * 1개월 주 기준·3개월 보조
