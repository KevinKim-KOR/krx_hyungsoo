## 1. 목표

남은 세 번째 PUSH인 08:00 시장 브리핑을 실제 판단에 쓸 수 있는 형태로 만든다.

사용자가 원하는 시장 브리핑은 다음 두 가지다.

1. 밤사이 미국시장 흐름이 한국시장 개장에 줄 압력
2. 오늘 관찰할 최근 상승 섹터

기존처럼 지수 수치와 '별도 확인 필요'를 나열하는 메시지는 만들지 않는다.

## 2. 먼저 고정할 실제 메시지

### A. 한국 개장 압력이 검증된 경우

```text
[시장 흐름 브리핑] 08:00

오늘 한 문장
미국 기술주와 반도체가 함께 약세이고 원/달러도 상승해,
한국 성장주 개장에는 하락 압력이 우세합니다.

오늘 볼 섹터
바이오헬스케어 — 최근 5일·20일 흐름이 모두 상승하고
같은 섹터의 여러 ETF가 함께 움직이고 있습니다.

근거
Nasdaq −1.2% · 반도체 −2.1% · 원/달러 +0.4%

기준
미국 09-07 종가 · 국내 09-07 종가 · 환율 09-08 07:50
```

> **V1.1 제한** — `환율 09-08 07:50` 은 **원천이 실제로 그 시각 값을 줄 때만**
> 쓴다. USD/KRW 가 일별 값만 제공되면 `07:50 현재` 로 표현하지 않으며, PIT 시점이
> 불명확하면 **예측 입력에서 제외**한다 (§10 Q2).

### B. 예측 관계는 통과하지 못했지만 섹터 정보가 유효한 경우

```text
[시장 흐름 브리핑] 08:00

오늘 한 문장
밤사이 미국시장은 혼조여서 한국 개장 방향을 정할 근거가 약합니다.

오늘 볼 섹터
바이오헬스케어 — 최근 5일·20일 상승 흐름이 이어지고
같은 섹터의 여러 ETF가 동행하고 있습니다.

근거
S&P500 +0.3% · Nasdaq −0.4% · 반도체 −0.8%

기준
미국 09-07 종가 · 국내 09-07 종가
```

숫자는 해석을 뒷받침하는 최소 근거로만 사용한다. 숫자 목록 자체가 본문이 되어서는 안 된다.

## 3. 발송 조건

매일 무조건 보내지 않는다.

다음 중 하나가 달라졌을 때만 발송한다.

- 한국 개장 압력 상태 변경
- 미국시장 주요 상태 변경
- 오늘 볼 상승 섹터 변경
- 기존 상승 섹터의 흐름 소멸 또는 새로운 섹터 등장

동일 상태라면 `no_change` 로 미발송한다.

다음 상태라면 발송하지 않고 실행 이력에만 남긴다.

- 모든 데이터가 stale
- 미국시장 사실만 있고 개장 압력도 상승 섹터도 유효하지 않음
- 표시할 가치가 있는 문장이 만들어지지 않음

부분적으로 데이터가 부족해도 나머지 내용이 독립적으로 유효하면 해당 부분만 사용할 수 있다. 다만 빈 제목이나 '별도 확인 필요' 목록은 표시하지 않는다.

## 4. 미국시장 → 한국 개장

### 입력 후보

한국시장 개장 전에 확정되는 최소 입력만 대상으로 한다.

- S&P500
- Nasdaq
- 미국 반도체 지수 또는 검증된 대표 지표
- Russell 2000
- VIX
- USD/KRW

새로운 ML 모델은 만들지 않는다. 투명한 규칙 또는 단순 통계 baseline만 사용한다.

### 예측 대상

```text
KODEX200_OPEN_GAP
= 당일 KODEX200 시가 / 직전 거래일 종가 - 1
```

미국시장 입력은 반드시 해당 한국 거래일의 개장 전에 알 수 있었던 값만 사용한다.

### 사전 판정

다음 세 결과 중 하나로 판정한다.

- `ADOPT_OUTLOOK`: 한국 개장 압력 문구 사용
- `FACT_ONLY`: 미국시장 사실만 사용하고 한국 방향은 단정하지 않음
- `REJECT`: **충분한 데이터로 평가했으나** 사전 기준 미달
- **`NOT_EVALUATED`** (V1.1 신설): **표본·입력 부족으로 평가 자체를 못 함.**
  `REJECT` 에 포함하지 않는다 (§10 Q4)

최소 검증 계약:

- 정렬된 미국–한국 거래일 표본 750일 이상
- 입력 커버리지 95% 이상
- walk-forward 평가
- 방향 적중률 95% CI 하한이 50% 초과
- 단순 다수 방향 baseline보다 5%p 이상 개선
- 강한 상승압력군과 강한 하락압력군의 실제 개장 수익률 차이 bootstrap 95% CI가 0을 초과

통과하지 못하면 표현을 약하게 바꾸는 것이 아니라 `FACT_ONLY` 또는 `REJECT` 로 내린다.

정확한 등락률 예측은 하지 않는다. 결과는 `상승 압력 / 혼조 / 하락 압력` 과 필요할 경우 `약·중·강` 구간까지만 사용한다.

## 5. 최근 상승 섹터

ETF명 문자열 추론으로 섹터를 만들지 않는다.

PLAN에서 다음을 먼저 확정해야 한다.

- 사용할 수 있는 공식 또는 구조화된 섹터 분류 원천
- ETF별 추종지수 또는 섹터 식별자
- 동일 지수를 추종하는 ETF 중복 제거 방법
- 분류 커버리지
- 기준일과 수집 시각

섹터 후보 최소 조건:

- 같은 섹터에 서로 다른 추종지수 또는 독립 상품이 2개 이상
- 5거래일·20거래일 섹터 대표수익률이 모두 양수
- 섹터 내 상승 상품 비율이 50% 초과
- 동일 지수 복제 상품을 여러 표로 세어 순위를 부풀리지 않음
- 상위 2개 섹터까지만 본문 후보
- 조건을 만족하는 섹터가 없으면 섹터 문단 자체를 생략

섹터 수익률은 개별 최고 ETF가 아니라 중복 제거 후 그룹의 중앙값을 사용한다.

## 6. KOSPI 결함 선행 해소

`DEF-KOSPI-BENCHMARK-VALUE-ASOF-INTEGRITY` 를 이번 Step에서 처리한다.

확인·수정 범위:

- KOSPI와 VIX 원천의 마지막 실제 기준일
- 원천 값으로 1개월·3개월 수익률 독립 재계산
- 각 benchmark 자신의 `as_of_date` 사용
- stale 값을 최신 market context 기준일로 표시하지 못하게 차단
- OCI PUSH·API·Mac UI 등 소비처 전수 확인
- freshness 실패 시 해당 benchmark 문장 미생성

KODEX200과 KOSPI 수익률 차이가 크다는 사실만으로 어느 한 값을 정답으로 간주하지 않는다. 원천 행과 독립 계산으로 판정한다.

기존 `market_discovery.extra_notes` 의 KOSPI 문장은 검증이 끝나기 전까지 새 브리핑에서 재사용하지 않는다.

## 7. 데이터 계약

모든 입력은 다음을 가져야 한다.

- 관측 대상
- 시장 세션 날짜
- 실제 기준시각
- 시장 timezone
- 수집시각
- 데이터 source
- freshness 상태

한국 날짜와 미국 거래일을 단순히 같은 날짜 문자열로 연결하지 않는다.

stale 또는 기준시각 불명 데이터로 문장을 만들지 않는다. 다른 날짜의 값으로 조용히 대체하지 않는다.

## 8. 기존 파이프라인 재사용

- 기존 `market_briefing` push kind 유지
- 기존 08:00 cron 유지
- 기존 Telegram·PARAM·registry·flag guard 재사용
- 신규 PUSH 종류 생성 금지
- UI·ML·자동 스케줄 추가 금지
- 뉴스 수집 제외
- 범용 데이터 플랫폼 구축 금지

이번 작업은 위 메시지의 문장을 만드는 데 필요한 데이터와 판정까지만 다룬다.

## 9. 개발 전 제출할 PLAN

아직 구현하지 말고 PLAN V1을 제출한다.

PLAN에는 다음을 포함한다.

1. 기존 코드·DB에서 재사용 가능한 데이터
2. 부족한 미국 지표별 최소 수집 방법과 예상 backfill 범위
3. 섹터 분류 원천 후보와 권고안
4. KOSPI/VIX 결함의 실제 원인과 수정 위치
5. 미국–한국 거래일 PIT 정렬 방법
6. 사전 평가 실행 방법과 `ADOPT_OUTLOOK / FACT_ONLY / REJECT` 판정
7. 상승 섹터 산출식과 중복 제거 계약
8. 세 가지 목업 — `ADOPT_OUTLOOK` · `FACT_ONLY` · `no_change / no-send`
9. 상태 fingerprint와 반복 억제
10. 테스트·역검증 계약
11. 변경 예상 파일과 OCI 배포 영향
12. 확인되지 않은 사항만 모호점으로 반환

데이터 수집이나 코드 구현은 PLAN 승인 후 시작한다.

## 10. [V1.1] 확정 사항 — 2026-09-08 설계자 판정

개발자 PLAN V1 조사에서 **설계서가 전제한 데이터 3축이 모두 비어 있음**이
확인됐다. 아래가 정본이며, §1~§9 와 충돌하면 이 절이 우선한다.

### 10.1 Q1 — Step 2분할 확정

| Step | 범위 |
|---|---|
| **`OPS-02B-1`** Market Input Readiness & Validity Gate | KODEX200 `open` probe·backfill · 미국 지표 source/symbol 검증·backfill · KOSPI/VIX 갱신·값·as-of 결함 수정 · 섹터/기초지수 메타데이터 원천 검증·최소 적재 · 미국→한국 개장 walk-forward 평가 · 상승 섹터 산출 가능성 판정 |
| **`OPS-02B-2`** Market Briefing Message & Operation | `02B-1` 판정을 입력으로 메시지·반복 억제·PUSH 구현 |

`02B-1` 에서 **Telegram 본문·반복 억제·autosend 활성화는 구현하지 않는다.**

`02B-1` 에서 전망과 섹터가 **모두** 사용 불가면 `02B-2` 를 억지로 만들지 않고
POC3 을 계속 열린 상태로 둔다.

### 10.2 Q2 — benchmark 스키마: 최소 변경안 (d)

기존 `market_benchmark_daily_price` 테이블을 **유지**한다.

- `date` = 해당 시장의 **session date**
- `created_at` = **적재 시각**
- `source` = 원천
- benchmark 별 **timezone · 통상 종료시각 · freshness 규칙은 코드의 정적
  catalog** 로 관리
- 반환 evidence 에 각 benchmark 의 **`as_of_date` 와 계산된 freshness** 포함
- 기존 행에 **알 수 없는 timestamp 를 소급 생성하지 않는다**
- **신규 테이블·대규모 컬럼 migration 금지**

미국 일별 지수는 session date 와 `America/New_York` 시간 규칙으로 한국 개장 전
이용 가능성을 계산한다. **DST 는 표준 `zoneinfo` 로 처리**한다.

### 10.3 Q3 — 섹터 원천: KRX **읽기 전용 probe 승인**

수집기를 바로 만들지 않는다. probe 에서 확인할 것:

ETF ticker · 기초지수 코드 · 기초지수명 · **구조화된 기초시장·국가·자산·업종·테마
분류 필드** · 전체 ETF 커버리지 · 응답 안정성 및 인증 필요 여부.

- 기초지수 코드는 **동일지수 ETF 중복 제거만** 해결한다.
- 서로 다른 기초지수를 같은 섹터로 묶으려면 **구조화된 분류 필드가 별도로**
  있어야 한다.
- **기초지수명 문자열을 개발자가 해석해 임의 섹터로 묶지 않는다.**
- 공식 원천에 구조화된 섹터/테마 필드가 없으면 **`SECTOR_NOT_EVALUATED`** 로
  반환한다. 이때 **Naver 분류를 자동 채택하거나 ETF명 추론으로 우회하지 않는다.**
- 필드·커버리지가 확인된 경우에만 **이번 Step 전용 KRX 메타데이터 수집기 1개**를
  허용한다. 범용 KRX 플랫폼·구성종목 100% 수집으로 확대하지 않는다.

### 10.4 Q4 — 판정 4상태

| 상태 | 의미 |
|---|---|
| `ADOPT_OUTLOOK` | 한국 개장 압력 문구 사용 가능 |
| `FACT_ONLY` | 예측 문구는 불가하나 미국시장 **사실 입력은 사용 가능** |
| `REJECT` | **충분한 데이터로 평가**했으나 사전 기준 미달 |
| `NOT_EVALUATED` | **표본·입력 부족으로 평가 자체를 못 함** |

`NOT_EVALUATED` 를 `REJECT` 에 포함하지 않는다.

### 10.5 Q5 — `open` backfill 실패 시  *(V1.2 §11.1 로 대체됨)*

- 먼저 FDR 반환값을 **1개 짧은 구간에서 probe**
- 성공하면 **기존 `close` 를 보존**하면서 `open` 만 backfill
- **정렬 표본 750일 이상일 때만** 평가 실행
- 750일 미만이면 통계 평가를 실행하지 않고 **`NOT_EVALUATED`**
- **126일 소표본으로 임계값을 완화하지 않는다**
- **당일 종가 수익률로 target 을 바꾸지 않는다**
- 한국 개장 전망 문구는 사용하지 않는다

미국시장 사실과 상승 섹터는 **각각 독립적으로** 사용 가능성을 판정한다.

### 10.6 Q6 — VIX 정체 영향: **읽기 전용 확인까지만**

확인할 것 — 2026-07-03 이후 기존 market-flow 산출물이 사용한 VIX source date ·
stale VIX 가 실제 artifact·API·UI·PUSH 에 소비됐는지 · 영향 기준일과 소비처.

이번 Step 에서 하지 않는다 — 기존 ML 재학습 · 기존 artifact 전면 재생성 ·
상대상승 모델 재개 · **영향이 확인되지 않은 산출물 수정**.

운영 소비가 확인되면 해당 경로를 **fail-closed 로 차단**하고 **별도 결함으로
기록**한다.

### 10.7 추가 필수 수정

**(1) 기존 모델 재사용 범위 축소**

`market_flow_walk_forward.py` 에서 재사용하는 것은 **구조뿐**이다 — 날짜 정렬 ·
기준일별 학습 · walk-forward · baseline 비교 · 결과 집계.

**재사용 대상이 아닌 것**: 기존 20일 target · feature · 학습 artifact ·
3모델 predictor.

`02B-1` 은 **투명한 단순 baseline 으로 시작**하며 신규 ML 튜닝·앙상블을 하지
않는다.

**(2) 미국 symbol probe 선행**

5종을 바로 적재하지 않는다. 각 후보 symbol 에 대해 먼저 확인한다 — 실제 지표
identity · 최초·최종일 · `close` 결측률 · source date · 동일 요청 재현성 ·
**한국 개장 전 확정 여부**.

`SOX` · `USD/KRW` 처럼 symbol 의미가 불명확하면 **확인 전 적재 금지**.

**(3) KOSPI/VIX 갱신**

07:20 배치에 benchmark 갱신을 연결하되:

- ETF 가격 성공과 benchmark 성공을 **별도 상태로 기록**
- benchmark 실패를 **전체 배치 성공으로 숨기지 않는다**
- 실패 때문에 **정상 ETF 가격 적재까지 롤백하지 않는다**
- 각 benchmark **자기 `as_of_date`** 사용
- **stale 이면 소비 문장 생성 금지**
- **위치 인덱스 대신 거래일 날짜 기준**으로 수익률 계산

### 10.8 `OPS-02B-1` 종료 산출물

데이터별 probe·backfill 결과 · 실제 정렬 표본 수와 커버리지 · KOSPI/VIX 독립
재계산 결과 · VIX stale 소비 영향 · 섹터 메타데이터 필드·커버리지 · 전망 판정 ·

## 11. [V1.2] probe 결과에 따른 정정 — 2026-09-09

§1~§10 과 충돌하면 이 절이 우선한다.

### 11.1 `OPEN_GAP` 원천 확정 — V1.1 의 FDR 지시 **폐기**

```text
OPEN_GAP_t  = KRX t일 무조정 시가 / KRX 직전 거래일 무조정 종가 - 1
source      = KRX_OPEN_API
price_basis = UNADJUSTED_TRADED_PRICE
```

- 시가·종가 **모두 KRX Open API 단일 원천**.
- FDR 시가와 기존 DB 종가를 **혼합하지 않는다.**
- 기존 `etf_daily_price` 의 `open`·`close` 를 **수정·덮어쓰지 않는다.**
- `02B-1` Gate 에서는 **평가용 snapshot 으로만** 보존한다.
- 일별 응답 전체를 적재하지 말고 **`069500` 평가 행만** 추출한다.
- 조회 구간·행 수·결측률·수집 시각·**snapshot hash** 를 기록한다.
- 운영 적재 구조는 Gate 결과 후 `02B-2` 에서 결정한다
  (`database_backfill = DEFERRED`).

KRX 무조정 가격에는 **분배락에 따른 실제 가격 변화**가 포함된다. 공식 분배락
날짜를 확보할 수 있으면 민감도 결과를 별도 보고하되, 확보할 수 없으면 **임의
보정하지 않고 한계로 기록**한다.

결과 표현은 **"미국시장과 개장 갭의 예측 관계"** 로 제한하고 **인과관계로
단정하지 않는다.**

### 11.2 DB 가격 기준 혼재 — 신규 결함

```text
DEF-ETF-DAILY-PRICE-BASIS-CONSISTENCY
status = INVESTIGATION_REQUIRED
```

근거 — KRX·DB·FDR 비율이 기간에 따라 다른 체계를 보임 · 2026-03-06 과
2026-04-20 사이 기준 전환 정황 · `NAVER_FDR` source 표기만으로 실제 조정 기준을
확정할 수 없음.

**이번 Step 에서 수정하지 않는다.** 읽기 전용 기록만 — 전체 기간 KRX/DB 비율
변화 · 전환 후보일 · 영향 ticker 범위 · 수익률·ML·UI·PUSH 소비 경로 · 현재 운영
수치 실영향 여부. **KRX 단일 원천 Gate 평가를 막지 않는다.**

### 11.3 USD/KRW PIT 재정렬

"6종 모두 16:00 ET 종료 후 이용 가능" 판정은 **그대로 인정하지 않는다.**

| 그룹 | 규칙 |
|---|---|
| S&P500·Nasdaq·SOX·Russell2000·VIX | 미국 세션 종료 기준 |
| **USD/KRW** | 일별 종가의 **실제 제공 완료 시각**이 한국 개장 전임을 확인해야 함 |

- 증명 불가 시 **primary feature 에서 제외.**
- 필요하면 한국 개장일보다 **날짜가 엄격히 앞선 행만** 쓰는 **보조 민감도
  평가**로 제한.
- **`07:50 현재 환율` 등 표현 금지.**
- 적용 후 **정렬 표본 수·커버리지를 다시 산출**하고 **Gate 에 사용한 feature
  집합을 명시**한다.

### 11.4 섹터·기초지수 판정

```text
SECTOR           = NOT_EVALUATED
INDEX_LEADERSHIP = AVAILABLE
화면·메시지 명칭  = 최근 강한 기초지수
```

- **API Key 가 섹터 분류를 해결한 것으로 기록하지 않는다.**
- `IDX_IND_NM` 은 **기초지수명**이며 업종·테마 분류가 아니다.
- 기초지수명 문자열을 해석해 **임의 섹터로 묶지 않는다.**
- 08:00 메시지에서도 **`상승 섹터` 라고 표시하지 않는다.**
- 사용자에게 **추가 계정·API Key 발급을 요청하지 않는다**
  (`krx_credentials = NOT_REQUIRED`).

**산출 계약** — 식별키 `지수산출기관 + 기초지수명` 완전일치 · fuzzy matching
금지 · 기초자산 **주식만** · **레버리지·인버스·합성 제외** · 동일 기초지수
그룹 중복 제거 · 그룹 수익률 **중앙값** · **5일·20일 모두 양수**인 지수만 후보 ·
**20일 기준 상위 2개**까지 · 추종 ETF 수와 가격 기준일을 evidence 에 기록.

**운영** — KRX API 로 **최신 메타데이터만** 갱신. 수동 CSV 는 정본 아님. 과거
2,800일 메타데이터 backfill 금지. `source`·`as-of`·`hash` 를 가진 versioned
snapshot 보존. join coverage **≥95% 사용 / <95% 미산출 / 미매칭 제외.**

**표현**

```text
오늘 볼 기초지수
• ○○지수: 5일 +x.x% · 20일 +x.x% (추종 ETF n개 기준)
```

공식 지수 분류에 따른 **가격 흐름**이지 섹터 상승을 검증한 결과가 아님을
결과서에 명시한다.

### 11.5 결정 순서

본문을 지금 확정하지 않고 **OUTLOOK Gate 를 먼저 실행**한다.

| 판정 | 목업 |
|---|---|
| `ADOPT_OUTLOOK` | 개장 압력 전망 + 최근 강한 기초지수 |
| `FACT_ONLY` | 미국시장 관측 사실 + 최근 강한 기초지수 |
| `REJECT` | 전망 문구 제외, 기초지수 중심 |
| `NOT_EVALUATED` | 원인 기록 후 기초지수 중심 |

**`REJECT`·`NOT_EVALUATED` 여도 세 번째 PUSH 를 폐기하지 않는다.** 모든
evidence 가 불가능한 경우에만 `REMAIN_BLOCKED`.

### 11.6 KOSPI/VIX 최소 계약

① OCI 운영 배치에서 갱신 경로 확보 · ② 각 benchmark 자기 `as_of_date` 유지 ·
③ 위치 인덱스가 아닌 **실제 거래일 기준** 수익률 · ④ **최신성 1거래일 초과 시
미산출** · ⑤ stale 을 다른 최신 `market_context.asof` 로 표시 금지 · ⑥ 일부만
실패하면 **실패한 블록만 제외** · ⑦ stale VIX 영향은 **읽기 전용 확인**,
ML 재학습으로 확대 금지.

**08:00 autosend 는 계속 `false`.**
