# POC3-01 오늘의 투자 점검 대시보드 전면 개편 설계서

* 문서 상태: 설계 통합본
* 작성일: 20260729
* 다음 절차: 레드팀 검수
* 개발 지시문 여부: 아님
* 적용 범위: PC 첫 화면 대시보드
* 기존 대시보드: 삭제하지 않고 별도 화면으로 보존

## 0. 설계 및 개발 후 사용자가 새로 확인할 수 있는 것

아침에 첫 화면을 열고 10초 안에 다음을 확인할 수 있다.

* 코스피가 현재 추세의 어디쯤 와 있는가
* 오늘 사용자가 생각할 일과 시스템이 처리할 일이 구분되어 있는가
* 갱신하거나 정비해야 할 자료가 몇 건인가

구현되지 않은 판단 기능도 숨기지 않고 `개발 중`으로 표시하여, 앞으로 무엇을 설계해야 하는지 사용자가 화면에서 직접 확인할 수 있게 한다.

---

## 1. 현재 문제

현재 대시보드에는 기능과 정보가 존재하지만, 사용자가 아침에 첫 화면만 보고 무엇을 확인해야 하는지 파악하기 어렵다.

구체적인 문제는 다음과 같다.

1. 시장을 `상승장·하락장`과 같은 단일 라벨로만 보여준다.
2. 현재 추세가 얼마나 지속됐고, 최근 고점에서 얼마나 내려왔으며, 흐름이 바뀌려면 얼마나 남았는지 알 수 없다.
3. 사용자가 판단해야 할 투자 항목과 시스템 자료를 갱신해야 할 정비 항목이 같은 큐에 섞여 있다.
4. 대시보드의 요약과 하단 상세 표가 같은 내용을 반복한다.
5. `후보`, `Evidence`, `Workbench`, `Unavailable` 같은 개발 용어가 사용자 화면에 노출된다.
6. 일부 표는 좁은 열에 정보를 억지로 배치해 글자가 한 글자씩 세로로 표시된다.
7. 아직 구현되지 않은 위험 판단 기능이 화면에서 보이지 않아, 무엇이 부족한지 사용자가 확인하기 어렵다.
8. 코스피보다 내부 비교 기준인 KODEX200이 화면 전면에 노출돼 사용자가 실제로 투자하는 시장과 화면의 기준이 어긋난다.

현재 문제는 단순한 디자인 미관 부족이 아니다. 사용자가 첫 화면에서 시장 상황과 오늘 할 일을 파악할 수 없으므로 대시보드 기능이 미완성인 상태다.

## 2. 이번 Step의 단일 목표

> 새 대시보드만 보고 10초 안에 코스피의 현재 위치, 사용자가 생각할 일, 시스템이 처리할 일을 구분할 수 있게 한다.

이번 Step은 개별 ETF의 최종 매수·매도 판단이나 새로운 위험 감지 산식을 만드는 단계가 아니다.

첫 화면의 역할을 다음 세 가지로 한정한다.

1. 시장이 현재 어디쯤 와 있는지 보여준다.
2. 사용자가 직접 판단해야 할 일이 있는지 알려준다.
3. 자료 갱신과 같은 시스템 정비가 필요한지 알려준다.

---

## 3. 이번 Step 완료 후 사용자가 새로 할 수 있는 것

사용자는 아침에 새 대시보드를 열고 10초 안에 다음 세 질문에 답할 수 있어야 한다.

1. 코스피는 현재 추세의 어디쯤 와 있는가?
2. 오늘 내가 **생각할 일**과 시스템이 **처리할 일**이 섞이지 않고 구분되어 보이는가?
3. 지금 자료를 갱신하거나 정비해야 할 일이 몇 건인가?

이번 Step의 핵심 증분은 기존 후보·보유 종목 건수를 다시 보여주는 것이 아니다.

* 사용자가 투자 관점에서 판단해야 하는 항목
* 자료를 최신 상태로 만들기 위해 시스템에서 처리해야 하는 항목

이 두 종류의 일을 첫 화면에서 혼동하지 않도록 분리하는 것이 핵심이다.

판단 항목과 정비 항목이 같은 영역에 섞이면 이번 Step은 완료되지 않은 것으로 판정한다.

## 4. 새 대시보드 화면 계약

새 기본 화면의 사용자 노출 명칭은 `오늘의 투자 점검`으로 한다.

### 4.1 코스피는 지금 어디쯤인가

대시보드 최상단 전체 폭을 사용하는 대표 영역이다.

단순히 `상승장` 또는 `하락장`이라는 결론만 보여주지 않고, 현재 시장의 위치를 설명해야 한다.

#### 필수 표시 항목

* 코스피 가격 흐름과 날짜
* 현재 시장 흐름
* 현재 흐름이 이어진 거래일 수
* 최근 고점 대비 현재 위치
* 기존 시장 판정 기준선까지의 거리
* 거래량 흐름
* 마지막 자료 기준일

예시 표현 형식은 다음과 같다.

> 하락 흐름 23거래일째
> 최근 고점 대비 -26.1%
> 현재 시장 판정 기준까지 +10.1%

위 숫자는 화면 구조를 설명하기 위한 예시이며, 실제 값처럼 고정하거나 임시 데이터로 사용하지 않는다.

#### 기준 시장

* 사용자 화면의 대표 시장은 `코스피`로 한다.
* KODEX200은 기존 내부 비교·초과수익 계산 기준으로 유지한다.
* KODEX200을 새 대시보드의 대표 시장처럼 표시하지 않는다.
* 화면 표시 기준과 내부 비교 기준은 서로 다를 수 있다.

#### 시장 전환 기준까지의 거리

신규 지표를 도입하지 않고 현재 프로젝트에서 실제 사용하는 MA20/MA60 기반 시장 판정 기준을 재사용한다.

프런트엔드가 임의로 별도 산식을 만들거나 백엔드와 다른 기준을 사용해서는 안 된다.

기존 응답 또는 데이터 경로에서 값을 제공할 수 없다면 숫자를 임의 계산하지 않고 다음과 같이 표시한다.

> 시장 흐름 전환 기준까지 거리
> `개발 중 ⓘ`

툴팁에는 다음 내용을 제공한다.

> 현재 시장 판정에 사용하는 이동평균 기준선까지의 거리입니다. 급격한 하락이나 반등에는 늦게 반응할 수 있으며, 미래의 추세 전환을 예측하는 값은 아닙니다.

#### 차트 구성

* 시장 차트는 최상단 대표 정보로 충분한 면적을 사용한다.
* 추세선과 거래량을 같은 시간축에서 확인할 수 있어야 한다.
* 핵심 숫자가 작은 카드 여러 개로 흩어져 차트보다 먼저 눈에 들어오지 않게 한다.
* 기준일과 자료 최신성을 차트 영역에서 확인할 수 있어야 한다.
* 차트가 장식용 배경으로 축소되거나 흐름을 판독할 수 없는 크기면 FAIL이다.

#### 금지사항

* SuperTrend 신규 도입
* 친구 화면의 전환 산식 복제
* 공격·방어 비중 표시
* BUY·SELL 표시
* 손절 또는 자동 주문 판단
* 데이터가 없는 항목에 임시 숫자 입력
* 프런트엔드만의 신규 시장 판정 산식 생성

### 4.2 오늘 내가 확인할 것

사용자의 생각과 판단이 필요한 투자 항목만 표시한다.

#### 표시 대상

1. `요즘 잘 오르는 ETF`
2. `내가 가진 ETF 중 확인할 종목`

각 항목에는 다음 정보만 표시한다.

* 확인할 항목의 건수 또는 개발 상태
* 왜 확인해야 하는지 한 문장
* 상세 화면으로 이동하는 버튼

예:

> 요즘 잘 오르는 ETF 10개
> 최근 시장보다 강한 흐름을 보이는 ETF를 확인합니다.
> `[ETF 비교하기]`

#### 내가 가진 ETF의 위험 점검

현재 보유 ETF의 위험을 판정할 수 있는 축이 구축되지 않았다면 기존 데이터 품질 문제나 단순 보유 목록을 위험 종목 수로 표현하지 않는다.

다음과 같이 정직하게 표시한다.

> 내가 가진 ETF 중 확인할 종목
> `개발 중 ⓘ`
> 보유 ETF 중 먼저 점검할 종목과 이유를 찾는 기능을 준비하고 있습니다.

이 항목을 화면에 표시했다는 이유로 기능 완료나 PASS로 판정하지 않는다.

#### 상세 정보 배치

대시보드에는 다음을 넣지 않는다.

* 개별 ETF 상세 표
* 종목별 수익률 비교표
* 구성종목 중복률 상세
* 긴 확인 이유
* 종목별 차트
* 기존 하단의 `먼저 볼 후보` 또는 `보유 중 확인` 표

상세 목록과 비교 정보는 별도의 `ETF 비교하기` 화면에서 제공한다.

대시보드의 역할은 `오늘 볼 것이 있는지 알려주고 해당 화면으로 데려가는 것`까지다.

### 4.3 자료 업데이트 필요

사용자의 투자 판단이 아니라 시스템 자료 상태와 갱신 작업만 표시한다.

#### 표시 항목

* 오래된 자료의 종류와 건수
* 수집되지 않은 자료의 종류와 건수
* 마지막 정상 업데이트 시각
* 바로 다시 불러올 수 있는 항목
* 별도 업데이트 화면에서 실행해야 하는 항목

#### 사용자 노출 표현

| 내부 또는 기존 표현              | 사용자 화면 표현                    |
| ------------------------ | ---------------------------- |
| VIX freshness            | 시장 불안 지표가 오래되었습니다            |
| Constituents unavailable | ETF가 담고 있는 종목 자료가 없습니다       |
| Evidence stale           | 내가 가진 ETF와 시장 비교 자료가 오래되었습니다 |
| Refresh                  | 지금 다시 불러오기                   |
| Operations Panel         | 자료 업데이트                      |
| Unavailable              | 자료 없음                        |
| Pending                  | 확인 필요                        |

#### 가벼운 갱신

기존 기능으로 저장값 재조회나 단건 갱신을 실행할 수 있는 경우 대시보드에서 `지금 다시 불러오기`를 제공한다.

실행 후 다음을 화면에서 확인할 수 있어야 한다.

* 실행 중
* 완료
* 실패
* 마지막 정상 완료 시각

#### 무거운 갱신

전체 ETF 수집, 대량 구성종목 수집, 전체 재계산처럼 시간이 오래 걸리는 작업은 대시보드에서 직접 실행하지 않는다.

대신 다음 정보를 제공한다.

* 무엇을 업데이트해야 하는지
* 왜 필요한지
* 예상되는 작업 범위
* `자료 업데이트 화면으로` 버튼

버튼은 기존 실행 화면으로 연결한다.

신규 갱신 API가 없다는 이유로 이번 Step에서 임의의 대량 실행 API를 추가하지 않는다.

#### 큐 분리 강제 규칙

다음 항목이 `오늘 내가 확인할 것`에 들어가면 FAIL이다.

* 자료 최신성
* 미수집 데이터
* 수집 실패
* 재계산 필요
* 구성종목 업데이트
* 저장값 갱신

이 항목들은 반드시 `자료 업데이트 필요`에만 표시한다.

### 4.4 개발 중인 판단 기능

구현되지 않은 기능도 화면에서 숨기지 않는다.

#### 우선 표시 대상

* 내가 가진 ETF의 위험 신호
* 시장 흐름 전환까지의 거리
* 위험하다고 확인해야 하는 구체적인 이유

#### 표시 규칙

* 기능 목적을 사용자의 언어로 표시한다.
* 값이 없으면 `개발 중` 또는 `자료 없음`으로 표시한다.
* `ⓘ` 툴팁으로 부족한 이유와 향후 제공할 내용을 설명한다.
* 임시 숫자, 샘플 숫자, 추정값으로 빈칸을 채우지 않는다.
* 상세 화면에서는 향후 필요한 표 제목과 열 구조를 먼저 보여줄 수 있다.
* 개발되지 않은 기능을 카드로 그렸다는 이유로 완료 기능 수에 포함하지 않는다.

#### 상태 구분

| 상태             | 화면 표현                  |
| -------------- | ---------------------- |
| 기능과 데이터 모두 제공  | 실제 값과 기준일              |
| 기능은 있으나 자료가 없음 | 자료 없음 + 이유             |
| 자료가 오래됨        | 업데이트 필요 + 마지막 기준일      |
| 기능 자체가 미구현     | 개발 중 + 기능 목적           |
| 실행 실패          | 업데이트 실패 + 마지막 정상 완료 시각 |

`0건`, `자료 없음`, `개발 중`, `업데이트 실패`는 서로 다른 의미이므로 같은 상태처럼 표시하지 않는다.

## 5. 개발계획 작성 전 데이터 실측

레드팀 통과 후 개발자는 바로 코드를 수정하지 않는다.

먼저 현재 데이터와 직접 호출 경로를 실측하고, 모호점을 포함한 개발계획을 작성한다.

### 5.1 실측 대상

* 코스피 시계열
* 코스피 거래량
* 현재 시장 흐름 판정
* 흐름 지속 거래일 수
* 최근 고점 대비 위치
* MA20/MA60 또는 현재 시장 판정 기준선
* 기준선까지의 거리
* 요즘 잘 오르는 ETF 목록과 건수
* 내가 가진 ETF 관련 기존 점검 데이터
* 자료 최신성 및 미수집 상태
* 기존 경량 갱신 기능
* 기존 대량 갱신 화면과 연결 경로

### 5.2 개발계획에 포함할 실측 결과

각 화면 항목별로 다음을 제시한다.

| 확인 항목     | 내용                  |
| --------- | ------------------- |
| 화면 표시명    | 사용자에게 보여줄 명칭        |
| 현재 데이터 출처 | 기존 API·응답·저장값       |
| 실제 응답 여부  | 현재 실제로 제공되는지        |
| 실제 기준일    | 값의 최신 시점            |
| 기존 산식 여부  | 이미 확정된 산식인지         |
| 계산 위치     | 백엔드·DB·기존 응답 중 어디인지 |
| 누락 시 처리   | 실제 표시 또는 개발 중 처리    |
| 모호점       | 설계자 판단이 필요한 선택지     |

### 5.3 중단 조건

다음 중 하나에 해당하면 개발자는 임의로 구현하지 않고 설계자 판정을 요청한다.

1. 화면 표시를 위해 신규 산식이 필요하다.
2. MA20/MA60과 실제 시장 판정 로직이 서로 다르다.
3. 기존 API로 제공되지 않는 값을 새 데이터 계약으로 추가해야 한다.
4. `내가 가진 ETF 중 확인할 종목`의 의미를 기존 데이터만으로 확정할 수 없다.
5. 갱신 버튼을 만들기 위해 신규 대량 실행 API가 필요하다.
6. 실제 데이터 구조가 설계 전제와 충돌한다.
7. 합리적인 화면 구현 선택지가 둘 이상이며 사용자 판단 의미가 달라진다.

단순한 함수명, 컴포넌트 분리, 내부 helper 위치 같은 구현 세부는 개발자가 판단한다.

## 6. 화면과 메뉴 구조

### 6.1 새 기본 화면

* 메뉴명: `오늘의 투자 점검`
* 첫 진입 기본 화면으로 사용
* 시장 위치, 오늘 확인할 것, 자료 업데이트 필요만 제공

* 비교와 참고 목적으로 접근 가능
* 새 화면에 기존 정보를 모두 복제하지 않는다

### 6.3 상세 비교 화면

* 사용자 노출 명칭: `ETF 비교하기`

* 대시보드에서 제거한 상세 종목표와 비교 기능을 담당
* 이번 Step에서는 상세 비교 기능 자체를 확장하지 않음

### 6.4 자료 실행 화면

* 사용자 노출 명칭: `자료 업데이트`
* 대량 수집과 재계산 등 무거운 실행을 담당
* 기존 내부 명칭 `Operations Panel`은 화면에 표시하지 않음

## 9. 표 가독성 강제 기준

첨부된 실패 사례처럼 표의 글자가 한 글자씩 세로로 배치되면 이유와 관계없이 FAIL이다.

### 9.1 즉시 FAIL 조건

* 글자가 한 글자씩 세로로 줄바꿈된다.
* 표 제목이나 열 이름을 정상적으로 읽을 수 없다.
* 종목명, 숫자, 날짜 또는 상태가 임의로 여러 줄로 잘린다.
* 좁은 폭에 열을 억지로 욱여넣는다.
* 확인 이유가 말줄임표에 가려져 사용자가 내용을 알 수 없다.
* 카드 안에 불필요한 가로 스크롤이 생긴다.
* 중요 항목이 작은 글자나 낮은 대비로 밀려난다.
* 내부 용어가 그대로 화면에 노출된다.
* 실제 데이터로 표시했을 때 구조가 무너진다.

### 9.2 폭이 부족할 때의 처리

화면 폭이 부족하면 다음 순서로 처리한다.

1. 사용자 판단에 불필요한 열을 상세 화면으로 이동한다.
2. 중요도가 낮은 정보를 행 내부의 보조 설명으로 내린다.
3. 표를 종목별 행 카드 구조로 전환한다.
4. 핵심 이유는 줄바꿈해서 전체 내용을 보여준다.

열 폭을 줄여 글자를 찌그러뜨리는 방식은 허용하지 않는다.

### 9.3 우선 확보할 폭

표를 사용해야 하는 화면에서는 다음 순서로 폭을 확보한다.

1. 종목명
2. 확인 이유
3. 수익률 또는 현재 위치
4. 자료 기준일
5. 사용자가 실행할 다음 행동

## 10. 기존 화면 처리

기존 대시보드는 폐기하지 않는다.

* 기존 화면은 `기존 대시보드`라는 별도 이름으로 유지한다.
* 새 기본 화면은 `오늘의 투자 점검`으로 한다.
* 기존 대시보드의 기능을 새 화면에 전부 복제하지 않는다.
* 기존 화면을 보존했다는 이유로 새 화면이 기존 구조를 그대로 따라갈 필요는 없다.
* 기존 화면과 새 화면이 같은 정보를 보여주더라도 각 화면의 역할이 달라야 한다.
* 메뉴와 첫 진입 경로에서 두 화면을 혼동하지 않게 한다.

## 12. 완료 기준 AC

### AC-1. 10초 사용자 과업

실제 데이터가 표시된 새 대시보드에서 사용자가 10초 안에 다음 세 질문에 답할 수 있다.

1. 코스피가 현재 추세의 어디쯤 있는가?
2. 내가 생각할 일과 시스템이 처리할 일이 구분되는가?
3. 자료 업데이트가 필요한 항목이 몇 건인가?

하나라도 답할 수 없으면 FAIL이다.

### AC-2. 코스피 시장 위치

최상단에서 다음 항목을 확인할 수 있다.

* 시장 흐름
* 흐름 지속 거래일 수
* 최근 고점 대비 위치
* 기존 판정 기준선까지의 거리 또는 `개발 중`
* 거래량 흐름
* 자료 기준일

단순한 `상승장·하락장` 라벨만 표시되면 FAIL이다.

### AC-3. 기존 데이터와 산식 재사용

시장 위치에 표시되는 실제 값은 기존 데이터·기존 시장 판정 기준에서 나온 값임이 개발계획의 실측 결과로 확인돼야 한다.

기존 경로로 제공되지 않는 값은 임의 구현하지 않고 `개발 중`으로 표시한다.

### AC-4. 사용자 판단 항목 제한

`오늘 내가 확인할 것`에는 사용자의 투자 판단이 필요한 항목만 표시된다.

### AC-5. 시스템 처리 항목 분리

자료 최신화, 미수집 데이터, 재계산, 갱신 실패는 `자료 업데이트 필요`에만 표시된다.

정비 항목이 판단 영역에 한 건이라도 포함되면 FAIL이다.

### AC-6. 대시보드와 상세 화면 분리

대시보드에는 건수·한 줄 요약·진입 버튼만 표시된다.

개별 ETF 상세 표나 종목별 비교표가 대시보드에 중복되면 FAIL이다.

### AC-7. 사용자 언어

사용자 화면에서 `후보`, `Evidence`, `Workbench`, `Operations Panel`, `Unavailable`, `Pending`이 노출되지 않는다.

전문용어가 불가피하면 `ⓘ` 설명을 제공한다.

### AC-8. 관찰 가능한 판정

`깔끔하다`, `직관적이다`, `적절하다` 같은 형용사만으로 완료를 판정하지 않는다.

모든 UI AC는 실제 화면 또는 스크린샷에서 참·거짓을 판정할 수 있어야 한다.

### AC-9. 미개발 기능의 정직한 표시

구현되지 않은 위험 신호와 데이터는 숨기지 않고 `개발 중` 또는 `자료 없음`으로 구분해 표시한다.

임시 숫자가 표시되면 FAIL이다.

### AC-10. 기존 대시보드 보존

기존 대시보드가 `기존 대시보드`라는 별도 화면으로 유지되고, 새 기본 진입 화면은 `오늘의 투자 점검`으로 연결된다.

### AC-11. MA20/MA60 한계 설명

시장 전환 기준까지의 거리에는 다음 내용의 툴팁이 표시된다.

* 현재 시장 판정 기준선까지의 거리
* 미래 예측값이 아님
* 급격한 하락과 반등에는 늦게 반응할 수 있음

### AC-12. 신규 위험 산식 금지

급락 대응을 위한 신규 산식·지표·임계값은 이번 Step에 추가되지 않는다.

해당 문제는 후속 `내가 가진 ETF의 위험 신호` Step 입력으로 기록돼야 한다.

### AC-13. 표 가독성

실제 데이터가 표시된 모든 표와 목록에서 다음 현상이 한 건도 없어야 한다.

* 한 글자 단위 세로 줄바꿈
* 열 이름 판독 불가
* 숫자·날짜의 임의 줄바꿈
* 중요 이유의 말줄임표 은폐
* 좁은 열에 의한 내용 붕괴

한 건이라도 발견되면 FAIL이다.

### AC-14. 이동 버튼

다음 버튼이 실제 목적 화면으로 이동한다.

* `ETF 비교하기`
* `자료 업데이트`
* `지금 다시 불러오기`가 제공되는 경우 해당 기존 갱신 기능

버튼이 표시만 되고 동작하지 않으면 FAIL이다.

### AC-15. 사용자 실화면 판정

자동 테스트, lint, build, 검증자 PASS만으로 이번 Step을 최종 완료 처리하지 않는다.

실제 데이터가 표시된 화면을 사용자가 확인하고 10초 과업과 표 가독성에 대해 PASS해야 최종 완료로 판정할 수 있다.

## 13. 보류된 위험 및 다음 Step 입력

### MA20/MA60 기반 시장 판정의 급락 대응 한계

이 항목은 이번 Step에 새로운 위험 판정 산식으로 넣으면 범위가 커지므로 `내가 가진 ETF의 위험 신호` Step의 필수 입력으로 넘긴다.

* **보류 사유:** 이번 Step의 목표는 시장 위치와 판단·정비 항목을 구분해 보여주는 것이다. 급락 감지 기준을 추가하면 위험 판정 모델과 임계값 설계까지 범위가 확대된다.
* **보류된 위험:** MA20/MA60은 후행 지표이므로 시장이 빠르게 조정되는 동안에도 상승 흐름으로 표시하거나 전환을 늦게 알릴 수 있다. 화면에서 해당 숫자의 비중이 커질수록 사용자가 이를 과신할 위험도 커진다.
* **현재 완화책:** 기준선까지의 거리가 미래 예측값이 아니며 급락·반등에 늦게 반응할 수 있다는 설명을 화면에 표시한다.
* **재검토 트리거:** 이번 대시보드 Step이 사용자 실화면 PASS로 종료되고 `내가 가진 ETF의 위험 신호` Step을 시작할 때 재검토한다.
* **다음 Step 제약:** MA20/MA60의 한계를 이유로 새로운 지표나 임계값을 즉시 확정하지 않는다. 기존 데이터 실측과 사용자 판단 과업을 먼저 정의한다.
* **다음 Step 시작 질문:**

  > 하락장 아침에 이 화면만 보고 오늘 점검할 보유 ETF와 그 이유를 고를 수 있는가?

## 14. 확정된 설계 판단

1. 새 대시보드의 대표 시장은 코스피로 한다.
2. KODEX200은 내부 비교 기준으로 유지한다.
3. 친구 화면에서는 정보 구성과 밀도만 참고하고 산식은 복제하지 않는다.
4. 시장 상태는 단일 라벨이 아니라 현재 위치로 설명한다.
5. 사용자의 판단 항목과 시스템 정비 항목을 분리한다.
6. 대시보드에는 상세 종목표를 넣지 않는다.
7. 기존 대시보드는 삭제하지 않고 별도 화면으로 보존한다.
8. 구현되지 않은 판단 기능은 `개발 중`으로 화면에 남긴다.
9. 사용자 화면에는 초보 투자자가 이해할 수 있는 명칭을 사용한다.
10. 표가 읽히지 않으면 데이터와 기능이 존재하더라도 FAIL로 판정한다.
11. MA20/MA60의 급락 대응 한계는 숨기지 않되 이번 Step에서 신규 위험 산식으로 확장하지 않는다.
12. 최종 완료는 사용자 실화면 판정을 통과해야 한다.
