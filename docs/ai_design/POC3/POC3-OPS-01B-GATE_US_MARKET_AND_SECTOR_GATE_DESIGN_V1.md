## 0. Step 목적 (설계자 원문)

> 미국시장 마감 흐름으로 한국시장 개장 방향을 설명할 수 있는지, 그리고 최근
> 상승 섹터를 신뢰할 만하게 식별할 수 있는지 먼저 검증한다.

아직 시장 브리핑을 **구현하는 단계가 아니다.** 두 기능 모두 과거에 제대로
완성하지 못했던 영역이므로, 이번에는 **연결 가능성을 확인한 뒤 채택·축소·폐기**한다.

---

## 1. 두 축 분리

### B1. 미국시장 → 한국시장

주 계약은 **한국시장 개장 영향**이다.

- 미국시장 마감 후 08:00 KST 시점에 **알 수 있는 데이터만** 사용
- 한국시장 **전일 종가 대비 당일 시가**의 변화가 주 평가 대상
- 장 마감 방향은 **별도 보조평가**
- 시가 데이터가 없다면 **종가로 몰래 바꿔 평가하지 않고 `DATA_GAP`**
- 미국과 한국의 휴장일·시차·서머타임 정렬
- "미국이 올랐으니 한국도 오른다" 는 가정을 **결과 전에 확정하지 않음**

### B2. 최근 상승 섹터

당일 상승 예측이 아니라 **현재 어느 섹터가 실제로 강한지 찾는 관찰 기능**이다.

- 단일 ETF 급등을 섹터 상승으로 부르지 않음
- 동일 지수 추종 ETF 여러 개를 독립 증거처럼 중복 계산하지 않음
- **ETF명만 보고 임의 분류하지 않음**
- 수익률 강도뿐 아니라 섹터 내 상승 종목·ETF의 **폭과 지속성** 확인
- 의미 있는 섹터가 없으면 **결과 없음**
- 임의의 `Top 3` 상한을 먼저 만들지 않음

## 2. 가능한 최종 판정 (축별 독립)

| 판정 | 의미 |
|---|---|
| `ADOPT` | 현재 데이터와 단순 규칙으로 운영 메시지에 연결 가능 |
| `OBSERVATION_ONLY` | 예측 근거는 부족하지만 현재 상태 설명에는 사용 가능 |
| `DATA_GAP` | 검증에 필요한 핵심 데이터가 없음 |
| `REJECT` | 데이터는 있으나 설명력·안정성이 부족 |
| `CONNECT_NONE` | 시장 브리핑에 아무것도 추가하지 않음 |

**한 축만 통과하면 그 축만 사용한다.** 미국시장 예측이 실패해도 섹터 관찰까지
억지로 버리거나, 반대로 섹터만 된다고 미국시장 예측을 끼워 넣지 않는다.

## 3. 착수 지시 (설계자 원문)

### 3.1 이번 단계

구현하지 말고, 기존 코드·OCI DB·artifact·현재 수집 경로를 **읽기 전용으로 조사**한
뒤 개발 PLAN을 제출한다. 평가 대상은 ① 미국시장 마감 흐름 → 한국시장 개장 영향
② 최근 상승 섹터 식별.

### 3.2 먼저 확인할 데이터

**미국시장 입력 후보** — 현재 저장·수집되는 범위에서만 확인한다.
S&P500 · Nasdaq(또는 Nasdaq100) · 반도체 지수 · Russell2000 · VIX · USD/KRW ·
그 밖의 기존 미국시장 지표. 각 항목별로 **source · OHLC 여부 · 기준시각 ·
보유기간 · 결측률 · OCI 적재 여부**를 제출한다.

**한국시장 평가 대상** — KOSPI 또는 KODEX200의 시가·종가 / 전일 종가 대비 당일
시가 / 당일 시가 대비 종가 / 전일 종가 대비 당일 종가.
**시가가 없으면 개장 영향 평가는 `DATA_GAP` 이다. 종가 지표로 대체하지 않는다.**

**섹터 식별 재료** — ETF master 분류 필드 · ETF명·태그 · 구성종목과 중복률 ·
5일·20일 수익률 · 거래대금 또는 거래량 · 운용사·추종지수.
**실제 존재하는 필드와 채움률을 구분한다.** 빈 태그나 이름 추론을 정식 분류로
보고하지 않는다.

### 3.3 PLAN에 반드시 포함할 것

- 미국·한국 거래일의 **PIT 정렬 규칙**
- 서머타임·휴장일 처리
- 미래 데이터 누수 방지
- 단순 baseline과 평가 지표
- 방향 적중률뿐 아니라 **변화 크기 구분 가능성**
- 연도별·시장 상태별 안정성
- 섹터 **중복 제거 또는 군집화** 방법
- 상승 **강도·폭·지속성** 정의
- 의미 있는 섹터가 없는 날의 조건
- **사전에 고정한** `ADOPT / OBSERVATION_ONLY / DATA_GAP / REJECT` 기준
- **평가 후 기준 변경 금지**

### 3.4 사용자 확인용 메시지 목업 계획

실제 구현 전에 **최소 다섯 상황**을 과거 데이터로 제시한다.

1. 미국시장과 한국 개장 방향이 명확히 이어진 날
2. 미국 지수끼리 방향이 엇갈린 날
3. 미국 흐름과 한국시장이 반대로 움직인 날
4. 최근 상승 섹터가 명확한 날
5. 유효한 변화가 없어 **시장 브리핑을 보내지 않는 날**

목표 형식은 숫자 나열이 아니라 다음 구조다.

```text
오늘 한 문장: {미국시장 흐름과 한국시장 개장 영향}
볼 섹터: {최근 상승이 확인된 섹터와 이유}
```

**근거가 없으면 문장을 억지로 만들지 않는다.** 면책문구와 매매지시 관련 문구도
넣지 않는다.

### 3.5 범위 제외

신규 ML 모델 · LLM 자동 해석 · 신규 외부 데이터 제공자 · DB backfill ·
UI·API·PUSH·cron 변경 · 자동주문 · 운영 배포 · OPS-01C 위험 알림 구현.

### 3.6 BACKLOG

전체 BACKLOG를 다시 조사하지 않는다. **미국시장·섹터·시장 브리핑에 직접 닿는
항목만** 찾아 이번 Gate와의 관계를 분류한다. Gate 결과 전에는 완료·폐기하지 않는다.

### 3.7 반환

기존 데이터 가용성 표 · 두 축의 검증 가능 여부 · 막히는 핵심 데이터 ·
**사전 판정 기준이 포함된 PLAN V1** · 구현은 `BLOCKED`.

월요일 OPS-01A 첫 스케줄 결과는 별도 운영 실측으로 나중에 추가하되, **PLAN 작성을
기다리지 않는다.**

## 4. Gate 의 성격 (설계자 강조)

> 이번 Step의 핵심은 **미국시장 이야기와 상승 섹터를 반드시 넣는 것**이 아니라,
> 실제 데이터로 말할 자격이 있는지를 먼저 가리는 것입니다. 여기서
> `CONNECT_NONE` 이 나와도 **Gate는 제대로 작동한 것**입니다.

## 5. 조사 중 확정된 부수 지시 (2026-09-06)

### 5.1 KOSPI stale 처리

개발자가 조사 중 "OCI KOSPI benchmark 가 2026-07-03 에서 정체" 를 보고했다.
설계자 판정:

> **현재 운영 PUSH가 stale KOSPI를 소비한다면 먼저 수정한다.** 운영 메시지의
> 사실성 문제라 별도 추적으로 미룰 수 없다. 다만 01B-GATE 자체는 읽기 전용
> 조사이므로 곧바로 수정하지 말고 먼저 소비 여부를 확인한다.

| 실측 | 처리 |
|---|---|
| 현재 PUSH가 stale KOSPI를 정상값처럼 표시 | **운영 결함** — 다음 관련 배포 전에 최소 수정 |
| stale임을 명시하거나 KOSPI를 제외 | 별도 추적, 01B-GATE 계속 |
| 현재 PUSH가 KOSPI를 소비하지 않음 | 01B의 `DATA_GAP` 근거로만 기록 |
| 소비 여부 확인 불가 | `UNKNOWN` 으로 두고 수정 금지 |

**수정이 필요해도 이번 Gate에 섞지 않고 짧은 운영 결함으로 분리한다.**

### 5.2 `DATA_GAP` 기록 수준

**"어떤 데이터가 있으면 검증 가능한지" 까지 반드시 적는다.** 그렇지 않으면
`DATA_GAP` 은 "안 됨" 이라는 막다른 표지판에 불과하다. 각 `DATA_GAP` 에 다음을
기록한다 — 필요한 지표·필드 / 필요한 단위(일봉 OHLC·시가·종가) / 최소 과거기간과
표본 수 / 허용 결측률·최신성 / 기준시각과 거래일 정렬 조건 / PIT 재현에 필요한
timestamp / 현재 데이터가 부족한 정확한 이유 / 데이터 확보 시 다시 열 수 있는 평가 항목.

**금지** — 특정 신규 제공자 선정 · 신규 수집기·DB 스키마 설계 · backfill 계획 확정
· `DATA_GAP` 발생만으로 BACKLOG 자동 등재.
