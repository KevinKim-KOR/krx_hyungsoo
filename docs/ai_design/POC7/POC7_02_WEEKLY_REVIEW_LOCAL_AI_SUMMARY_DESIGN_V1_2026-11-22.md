## 1. 형수님이 받을 것과 이번에 판단할 것

지금은 시장 근거를 복사한 뒤 여러 AI가 쓴 긴 답에서 날짜가 다른 수치, 해석이 갈리는 대목, 빠진 자료를 직접 찾는다. 이번에는 **선택한 ETF 한 건의 원문을 PC에 한 번 건네면, 평소 검토하는 기기에서 바로 열어 읽을 수 있는 한국어 요약 한 장**을 만든다. 저장한 AI 답변이 있으면 함께 읽고, 원문만 있어도 요약한다.

**단일 목표는 형수님이 ‘이번 후보에서 무엇을 알 수 있고, 무엇을 더 확인해야 하는가’를 정확하게 파악하는 데 드는 시간을 줄이는 것이다.** 연구 결과로 형수님께 실제 요약 한 장과 기존 방식 대비 소요시간·고친 내용이 적힌 비교표를 드린다. 수익률·추세 전환 예측은 별도 연구 주제다.

## 2. 한 장의 내용

첫 줄에 검토 기준일과 선택한 ETF를 쓴다. 아래 네 항목은 한두 문장씩 쓴다. 중요한 수치나 판단에는 기존 근거 번호를 붙인다. 번호가 없는 자료는 원문 항목명과 기준일로 찾을 수 있게 한다.

| 읽는 순서 | 한 장에서 답할 질문 |
|---|---|
| 시장 | 대표 ETF의 시장 판정과 코스피·수급 관측은 각각 언제 기준인가? 이번 검토에 영향을 주는 관측과 빈칸은 무엇인가? |
| 선택한 ETF | 원문에 표시된 기간에 실제로 올랐나, 덜 내렸나? 같은 기간의 시장 대비 차이가 있으면 `%`와 `%p`를 구별한다. 자료 일부만 확인한 보유 겹침에는 확인 범위를 붙인다. |
| AI 의견 | 답변 두 개 이상이면 판단에 영향을 주는 공통점이나 갈린 점을 답변 작성자와 함께 적는다. 한쪽 답변만 다룬 항목은 그렇게 표시한다. 답변 한 개면 그 의견만 싣고, 답변이 없으면 이 줄을 생략한다. |
| 최신 자료와 다음 확인 | 확인한 값·기준일·출처·실제 확인 시각이 원문에 들어 있으면 **누가 확인했는지** 밝힌다. 없으면 ‘최신 공개 자료 확인 불가’와 저장 자료의 기준일을 적는다. 더 확인할 것이 있으면 가장 중요한 한 가지를 짚는다. |

기존 복사문에 있는 **‘판단에 쓰는 항목의 최신 공개 자료를 확인해 달라’는 요청**을 로컬 입력에도 포함한다. 로컬 모델은 제공된 자료를 읽는다. 첨부된 원출처에서 확인한 새 값·정정값은 원래 저장값과 구별한다. 웹 AI의 확인 보고만 있으면 그 AI의 말로 표시한다. 링크만 있거나 확인 근거가 빠졌으면 공개값은 미확인이다. 확인 시각은 실제 확인 기록에서 가져온다.

## 3. 진행 순서

**STEP 1 · 실제 사례와 비교 기준 선정.** 11월 17일 공유한 GPT·Claude 답변은 **일일 시장 복사 사례**다. 당시 복사 원문이 있으면 시장 줄의 양식을 점검하는 데 쓴다. 두 답변에서 형수님이 바로 읽을 수 있어야 할 대목은 다음과 같다.

> **시장**　KODEX 200 판정은 11/16 기준. 코스피와 외국인 수급은 11/13까지 관측됐다. 〔GPT 첫 문단·수급, Claude 1·3〕
>
> **수급**　외국인은 계속 순매도했고, 최근 20거래일에는 직전 20거래일보다 하루 평균 매도 규모가 줄었다. 〔GPT 수급, Claude 3〕
>
> **다음 확인**　두 답변에서 확인되지 않은 11/16 코스피 종가와 외국인 수급. 〔GPT 마지막 문단, Claude 5〕

위 세 줄은 공유된 두 답변을 바탕으로 한 형식 예시다. 당시 복사 원문이 없는 경우 수치 정확성의 채점 자료는 아래 주간 사례에서 확보한다.

본 비교에는 후보를 선택한 **실제 「주간 ETF 점검」 원문 한 건**을 쓴다. 보관된 ‘당시 검토’가 있으면 그 원문을 쓰고, 없으면 현재 화면에서 고른 후보의 복사문을 현재 사례로 보관한다. 새 주가 올 때까지 기다릴 필요는 없다. 출력 전에 대상과 입력을 정하고, 날짜·필수 사실·빠진 자료·의견 차이를 채점용 메모에 따로 적는다. 두 방식에는 원래 자료만 제공한다. 답변끼리 다르면 해당 대목과 근거를 남기고, 사실 확인에는 해당 수치의 출처를 쓴다.

**STEP 2 · 같은 입력으로 한 장 생성.** 맥에서 보던 근거 묶음을 Windows 연구 PC의 RTX 4070 SUPER에서 로컬 언어모델 하나로 요약한다. PLAN에서 현재 실행 가능한 한국어 모델·버전과 실제 입력 길이를 확인해 모델과 지시문을 고정한다. 긴 원문 끝까지 전달됐는지, 실제 GPU 추론을 했는지 기록한다. 일부만 읽거나 실행이 실패하면 그 사유를 남긴다. 새 설치나 모델 파일 수신이 필요한 경우에만 기존 승인 범위와 필요한 용량을 PLAN에 적는다. 실행에는 유료 AI API나 새로운 웹 AI 답변이 필요하지 않다.

**STEP 3 · 평소 방식과 직접 비교.** 같은 후보·같은 복사 원문·같은 기존 AI 답변으로 비교한다. 한 번은 평소 쓰는 화면과 원문으로, 한 번은 로컬 한 장을 먼저 읽고 필요할 때 원문을 열어 본다. 둘 다 ‘후보의 실제 방향, 근거의 한계, 다음 확인’을 설명할 수 있을 때 끝낸다. 기존 방식을 일부러 길게 만들지 않는다.

- 복사문이 준비된 시점부터 실제 복사·기기 간 전달·읽기·수정에 쓴 **사람 시간**과 모델 대기를 포함한 **전체 경과시간**을 따로 잰다. 사실 수정 횟수와 원문을 다시 연 횟수도 적는다. 일회성 설치 시간은 별도다. 과거에 재지 않은 웹 AI 요청·대기 시간은 추정해서 절감분에 넣지 않는다.
- 같은 내용을 두 번 보면서 빨라질 수 있으므로 순서를 미리 정해 기록한다. 이미 있는 다른 주간 사례까지 쓸 수 있으면 순서를 뒤집는다. 한 건이면 그 사례의 관찰값까지만 말한다. 형수님은 실제 읽기 비교만 하고, 항목별 원문 대조와 기록 정리는 개발자가 맡는다.

## 4. 완료 기준과 결과의 쓰임

| AC | 결과서에 남길 근거 |
|---|---|
| AC1 · 실제 산출물 | 선택한 주간 사례의 원문, 사용한 모델·실행 기기·GPU 사용 근거, 최초 출력과 형수님이 열어 본 한 장이 서로 대응한다. 입력 누락과 실패를 표시한다. |
| AC2 · 근거 정확성 | 사전에 정한 필수 사실·자료 공백이 모두 드러난다. 판단을 바꿀 숫자·단위·부호·대상·날짜·출처 오류, 중요한 누락, 근거 없는 최신 확인·AI 합의·매매 결론은 최초 출력에서 0건이어야 한다. 고친 최종본과 최초 오류 수를 함께 보존한다. |
| AC3 · 실제 사용 | 형수님이 두 방식으로 같은 질문에 답한 결과, 사람 시간·전체 경과시간, 사실 수정·원문 재열기 횟수와 다시 사용하겠는지를 한 표에서 본다. 모르는 값은 미측정으로 둔다. |
| AC4 · 결론 | 정확성을 충족하고 사람 시간이 줄고 사실 수정이 늘지 않으며 형수님이 다시 쓸 만하다고 판단하면 ‘이 사례에서 사용 이점 관찰’이다. 중요한 오류는 ‘품질 미달’이다. 정확성이 충족된 나머지 경우는 ‘사용 이점 미확인’으로 적는다. 여기에는 단순히 두 번째로 읽어서 빨라졌을 가능성을 구별하기 어려운 경우도 포함한다. 주간 원문·실행·사용 실측이 부족하면 해당 항목은 ‘판정 불가’다. 운영 채택은 별도 결정이다. |

**운영 경계.** 기존 일일·주간 화면, AI 투자 세션 저장 규칙, 사용자 판단과 OCI·Telegram 운영은 현행 계약을 따른다. 이번 변경 범위는 PC 연구용 요약과 평가 기록이다. 실제 입력·AI 원문·개인 보유 정보는 로컬에 두고, 공개 결과서에는 식별 정보를 가린 예시와 집계만 싣는다. 새 뉴스 수집, 모델 학습, 후보 점수·추천, 자동 매매 및 운영 화면 연결은 이번 범위 밖이다.
