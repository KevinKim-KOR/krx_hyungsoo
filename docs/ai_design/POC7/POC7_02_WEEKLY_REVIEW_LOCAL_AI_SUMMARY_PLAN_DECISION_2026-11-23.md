# POC7-02 · 로컬 AI 주간 ETF 검토 요약 · 개발 PLAN 판정

2026-11-23 KST · 총괄 설계자 · **PLAN PASS · 맥북 개발 승인**

대상은 11월 22일 제출한 `POC7_02_WEEKLY_REVIEW_LOCAL_AI_SUMMARY_PLAN_V1.md`다. 형수님이 정한 작업 방식은 **맥북에서 개발하고 Windows PC에서 실제 모델을 실행하는 것**이다. PLAN §2-4·§2-5의 파일 왕복 구조를 수용한다. 아래 결정을 같은 PLAN V1에 반영하면 별도 재제출 없이 맥북 구현을 시작한다. Windows 신규 설치·모델 수신 승인은 그 작업이 필요할 때 받는다.

## 1. 어느 기기에서 무엇을 하는가

| 순서 | 기기 | 담당 작업과 산출물 |
|---|---|---|
| 1 | 맥북 | 프로젝트 저장소와 개발 환경을 둔다. 입력 준비, 요약 지시문, Windows용 실행기와 `.bat`, 한 장 HTML, 결과 회수·검산을 모두 여기서 개발한다. 합성 사례와 모의 Ollama 응답으로 `pack → 실행 결과 형식 → merge` 및 실패 처리를 시험해 실행 ZIP을 만든다. **맥북에 Ollama·CUDA·모델 가중치를 설치할 필요가 없다.** |
| 2 | Windows PC | 전달받은 ZIP을 풀고 `.bat`를 실행한다. Windows 내부의 Ollama가 RTX 4070 SUPER로 합성 입력을 먼저 점검한 뒤 실제 주간 입력을 요약한다. 최초 출력, 한 장 HTML, 모델 버전·GPU 사용·완료 상태를 결과 폴더에 남긴다. PC에 필요한 것은 실행 묶음과 로컬 추론 환경이다. |
| 3 | 맥북 | 결과 폴더를 가져와 같은 사례인지 확인하고 형수님이 한 장을 읽는다. 평소 방식과의 비교와 기록 보관도 맥북에서 한다. Windows 실행에서 수정할 점이 발견되면 개발자가 맥북 원본을 고쳐 실행 묶음만 다시 전달한다. |

Windows 전달 범위는 해당 사례의 입력·설정·실행기다. 전체 저장소·운영 DB·보유 파일·인증키·투자 앱 서버는 전달 대상에서 제외한다. Windows 실행기·드라이버 호환성, 입력 잘림, GPU 사용과 속도는 Windows에서 얻은 기록으로 확인한다. 맥북 모의 시험은 그 전까지 독립적으로 진행할 수 있다.

## 2. Q1~Q5 결정

| 항목 | 판정과 적용 기준 |
|---|---|
| Q1 · 본 사례 | **(b) 실제 주간 검토 복사문을 기본으로 채택.** 선택한 ETF, 기준일, 근거 번호·원문을 같은 조회 시점에 맥북 연구 폴더에 보관한다. `copy_text`와 같은 응답의 선택 정보로 입력을 만들 수 있게 한다. 운영 세션 저장과 기록 ID는 선택 경로다. 같은 검토 건에 이미 받은 AI 답이 있으면 작성자와 함께 넣을 수 있다. 답이 없으면 AI 의견 줄을 생략하고 ‘긴 AI 답 대조의 효용은 미측정’으로 기록한다. 사용자에게 새 웹 AI 답변이나 빈 메모의 운영 기록을 만들도록 요구하지 않는다. |
| Q2 · 순서와 보조 사례 | **본 사례는 로컬 한 장 먼저, 평소 방식 다음으로 한 번씩** 한다. 같은 맥북에서 같은 시점의 원문을 읽고, 두 번째 읽기의 영향을 기록한다. 11/17 00:14 후보 목록 기록은 별도 출처다. 이 기록을 역순 시간 측정에 추가하지 않는다. 실제 주간 사례가 한 건이면 결론도 그 한 건으로 한정한다. |
| Q3 · 모델과 설정 | **`qwen3.5:9b-q4_K_M` 한 개를 채택**한다. 생각 모드 켬, PLAN의 샘플링 설정과 고정 seed를 합성 시험의 시작 설정으로 수용한다. `num_ctx 49,152`와 `num_predict 24,576`은 시험할 수 있는 제안값이며 장비의 필수 조건은 아니다. 실제 입력과 한 장을 끝까지 생성할 여유를 확보하는 범위에서 같은 모델로 합성 시험의 길이 설정을 조정할 수 있다. 본 실행 전에 Ollama 버전·모델 digest·지시문·설정을 고정한다. 모델 교체나 추가 다운로드는 별도 결정이다. |
| Q4 · 세 답 정확도 | **채택.** 후보의 방향, 근거의 한계, 다음 확인을 항목별로 채점한다. ‘사용 이점 관찰’에는 로컬 방식의 세 답에 ‘틀림’이 0건이고 각 답이 평소 방식보다 낮지 않아야 한다. 원문이 뒷받침하는 다른 다음 확인 항목도 인정한다. 최초 한 장의 중요한 오류 0건, 사람 시간 감소, 사실 수정 비증가, 형수님의 재사용 의사도 함께 충족해야 한다. |
| Q5 · 전달 | **입력과 결과는 USB로 직접 왕복**하는 것을 기본으로 한다. 개인 클라우드는 제3의 저장 공간을 경유하므로 이번 로컬 전달 범위에서 제외한다. Windows의 모델 API는 해당 PC 내부에서만 호출한다. |

## 3. 결과가 달라질 수 있는 PLAN 문구 정정

- **같은 자료로 비교한다.** 갱신 뒤에 사례를 골라도 되고 이미 표시된 자료를 골라도 된다. 판단 기준은 보관 순간의 출처별 기준일·자료 상태다. 두 방식 모두 같은 복사문과 같은 선택 정보를 사용하므로 사례를 보관한 뒤 일상적인 자료 갱신을 멈출 필요가 없다. 예정된 공개 시각은 실제 수신 기록과 구별한다.
- **AI의 강조점과 이견을 구분한다.** 예시의 ‘순매도 지속’과 ‘하루 평균 매도 규모 감소’는 동시에 참일 수 있다. 예시 문구는 ‘GPT는 방향, Claude는 속도를 설명’으로 고친다. 상태 선택이 실제로 다르면 상태와 작성자를 적고, 상충하는 주장만 이견으로 표시한다. 최신 확인에는 확인 주체·값·기준일·출처·실제 확인 시각을 붙인다. AI의 보고만 있는 값은 그 AI에게 귀속하고, 공개값을 확인할 근거가 빠지면 ‘최신 공개 자료 확인 불가’와 저장 기준일을 쓴다.
- **완전한 입력과 최초 출력을 보존한다.** 글자 수, 앞뒤 표지의 복창이나 `prompt_eval_count` 한 값만으로 전체 수신을 확정하지 않는다. 동일 모델·템플릿의 입력 토큰과 출력 여유, 실제 할당 문맥·종료 이유·잘림 기록을 함께 대조한다. 표지 누락만으로 정상 완료한 답을 버리고 더 좋은 답을 고르지 않는다. 기술 실패·입력 미확인·내용 오류를 구별하고 첫 결과를 남긴다. GPU 사용률·메모리와 `ollama ps`를 기록한다. 혼합 실행이면 관측값을 적고, CPU 단독 실행과 GPU 측정 누락을 구분한다.
- **양쪽의 시작점과 사람이 들인 시간을 맞춘다.** 같은 원문이 준비된 상태에서 각 방식의 첫 조작부터 세 답을 제출할 때까지 잰다. 형수님 직접 시간, 개발자가 매회 포장·회수에 들인 작업 시간, 전체 경과시간을 구별한다. ‘사용 이점 관찰’은 형수님 직접 시간과 반복 포장 작업을 포함한 총 사람 시간이 모두 줄었을 때로 한정한다. 모델 대기는 전체 경과에, 일회성 설치는 별도에 둔다. 순서 효과나 실측 부족으로 절감을 가르기 어려우면 해당 효용은 미확인이다.

## 4. 형수님 확인과 다음 담당자

- **U1은 필요할 때 한 번 확인한다.** Windows에 사용 가능한 Ollama와 지정 모델이 이미 있는지 먼저 확인한다. 새로 필요한 경우 공식 Windows판 설치와 지정 모델 1개 수신만 형수님께 요청한다. 공식 안내상 설치 프로그램에 최소 4GB, 모델 태그의 파일 크기는 6.6GB다. 이는 디스크 규모이며 GPU 메모리 적재 여부는 실측한다. 설치 뒤 백그라운드로 실행되는 점도 안내한다. 드라이버 변경이 실제로 필요하면 그때 별도로 확인한다. 이 판정이 개인 PC 설치를 대신 승인하지 않는다.
