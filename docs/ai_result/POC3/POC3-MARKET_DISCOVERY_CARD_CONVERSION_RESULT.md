- **상태**: **DONE (코드·검증 완료) · 사용자 실화면 확인 대기**
- **선행**: `POC3-WORKBENCH_GRID_CARD_CONVERSION_RESULT.md` ·
  `POC3-EVIDENCE_GRID_AND_STOP_GUARD_RESULT.md` · `POC3-PNL_COLOR_AND_BADGE_CONSISTENCY_RESULT.md`

사용자 지시: "ETF 비교하기부터 지금까지 개발했던 형태와 다른 점을 바꿀 준비 및 실행".
표로 남아 있던 화면 중 **가장 넓은 `요즘 잘 오르는 ETF`(17열)** 부터 착수했다.

| 요구사항 | 결과 |
|---|---|
| 후보 표를 카드형으로 (기본 보기) | **DONE** |
| 표 형태는 **별도 탭**으로 유지 | **DONE** |

**진행 절차**: 목업(HTML)으로 17열 분류·배치를 먼저 승인받고 착수.

### 1.1 탭 구성

`기본 / 보유와 비교` → **`카드`(기본) / `표` / `보유와 비교`**.
기존 `기본` 탭 라벨을 `카드` 로 바꿨다(같은 데이터의 두 표시 형태가 생겨 "기본" 이 모호해짐).
첫 진입은 `카드`.

### 1.2 17열을 버리지 않고 나눴다

| 구분 | 항목 |
|---|---|
| 카드 상단 | 순위 · ETF명 · **참고점수**(큰 숫자) |
| 카드 하단 | **티커 / 시장가 / NAV / 괴리율** (사용자 지정) |
| 우측 지표 | 일간 · 1개월 · 3개월 + **KODEX200 대비 1M**(아랫줄) |
| 배지 | 보유 여부 3-state · 데이터 상태(**정상이면 숨김**) |
| 펼침 상세 | 6개월 · 12개월 · 3년 · KODEX200 대비 3M · 고점 대비 · 점수 근거 |

우측 지표 **아랫줄이 KODEX 대비 지표**인 것은 ETF 비교하기(`KODEX초과`)·확인 근거
(`KODEX200 대비 20일`)와 같은 배치다. 원래 카드 하단에 있던 `KODEX200 대비 1M` 이
사용자 지정 4항목에 밀려 이 자리로 왔고, `고점 대비` 는 펼침 상세로 갔다.

### 1.3 표가 답답했던 원인 — 글자가 아니라 **폭**

베이스 `.market-topn-table` 은 **이미 14px · 패딩 8px** 였다. 문제는 `width:100%` 인 표에
16열을 넣어 **열당 70px 남짓**으로 눌리면서 글자가 접히고 숫자가 붙어 보인 것이었다.

가로 스크롤 컨테이너(`.market-candidate-table-wrap`)로 감싸고 `min-width:1500px` 을 줘서
각 열이 제 폭을 갖게 했다. 패딩 `10px 12px` · `line-height 1.55` 로 행 높이도 키웠다.

### 1.4 `1년` 열 제거 (17 → 16)

기존 코드가 스스로 중복임을 적어두고 있었다.

```js
const twelveRet  = c.returns?.twelve_month?.return_pct ?? null;
// "1년" = backend twelve_month 와 동의어. 동일 값 또 표시.
const oneYearRet = c.returns?.twelve_month?.return_pct ?? null;
```

같은 필드를 두 열에 표시하던 것이라 `1년` 을 없애고 `12개월` 만 남겼다. 카드·표 양쪽 반영.

## 4) 지시문 외 변경

**보유 여부 배지를 위해 `MarketDiscoveryView` 에 보유 조회를 추가했다.**

목업에서 승인된 `보유`/`미보유` 배지를 채우려면 보유 목록이 필요한데 이 화면에는 없었다.
**Dashboard·ETF 비교하기와 같은 캐시 키(`DASH_KEY_HOLDINGS`)** 로 `useSharedQuery` 를 써서
이미 조회됐으면 재호출하지 않는다 — 신규 endpoint·N+1 없음.

조회 실패·미완이면 집합이 `undefined` 가 되고 배지는 **`보유 확인 불가`** 로 표시한다.
**미보유로 축약하지 않는다**(기존 3-state 계약과 동일).

## 5) 알려진 한계 / 미완성

1. **사용자 실화면 확인 대기.** 특히 표 탭의 가로 스크롤 폭(`min-width:1500px`)이 적정한지.
2. 표로 남은 화면 5개 — `HoldingsCompareView`(14열) · `OverlapTab`(11) ·
   `AISessionsListTab`(8) · `ConstituentsTab`(6) · `EvidenceDetails`(8). 미착수.
3. **표 탭에는 카드의 선택 상태가 반영되지 않는다.** 카드에서 고른 종목을 표로 전환해도
   강조되지 않는다. 두 보기가 선택을 공유해야 하는지는 지시받지 않아 그대로 뒀다.
4. `카드` 탭에는 정렬 UI 가 없다. 표 탭의 헤더 클릭 정렬은 그대로다. 목업에는 정렬 바를
   그렸으나 **후보 목록은 backend 가 순위대로 주는 것**이라 이번엔 넣지 않았다.

## 6) 다음 검증자(Codex)에게 알릴 점

1. **이 화면은 원래 테스트가 0건이었다.** 카드 전환으로 생긴 표시 계약만 6건 추가했다
   (`CandidateCards.test.tsx`) — 17열 미유실(펼침 확인) · 보유 3-state · 데이터 상태
   정상 시 미표시 · onSelect · 빈 상태. **표(`CandidateTable`)는 여전히 테스트가 없다.**
2. **`1년` 열 제거는 데이터 변경이 아니다** — 같은 필드를 두 번 표시하던 중복 해소다(§1.4).
3. **표 "크기 조절" 의 실제 조치는 폭 확보**다(§1.3). 글자 크기는 원래 14px 였고 줄이지도
   키우지도 않았다. 착수 전 "글자·여백 키우기" 로 보고했다가 원인 재진단 후 조정했다.
4. `MarketDiscoveryView` 에 보유 조회가 새로 붙었다(§4). 캐시 키 공유라 호출은 늘지 않지만,
   **이 화면이 보유 데이터에 의존하게 된 것은 계약 변화**다.
5. 탭 라벨 `기본` → `카드` 로 변경. `CompareViewMode` 타입도 `"default"` → `"card" | "table"`.
