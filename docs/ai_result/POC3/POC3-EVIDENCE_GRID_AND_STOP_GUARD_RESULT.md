### 1.2 기동 스크립트 주인 확인

**확인 결과**: 기존 `stop.sh` · `stop.bat` 은 **포트 번호만 보고 종료**했다. 3000(Next/React/Express)
과 8000(FastAPI/Django) 은 가장 흔한 개발 포트라, 다른 프로젝트가 그 포트를 쓰고 있으면
`./stop.sh` 는 물론 `./start.sh`(내부에서 stop 호출)만 눌러도 **남의 서버가 죽는다.**

- **`stop.sh`**: 종료 전 `lsof -a -p <pid> -d cwd` 로 작업 디렉터리를 확인해, **이 프로젝트 밑일 때만** 종료.
  경로 확인이 안 되면(권한 부족 등) **죽이지 않는다** — 남의 것을 죽이는 쪽보다 안전한 기본값.
- **`stop.bat`**: 윈도우는 작업 디렉터리 조회가 간단치 않아 2단계.
  (1) `start.bat` 이 붙이는 창 제목(`POC1 Backend` / `POC1 Frontend`)으로 `taskkill /T` 트리 종료 →
  정상 기동 경로는 여기서 끝난다. (2) 남은 포트 점유만 `ExecutablePath` 가 프로젝트 밑인지 검사.

## 5) 알려진 한계 / 미완성

1. **`stop.bat` 은 PC 실행 검증을 못 했다.** 맥에서 작업해 윈도우 실행 경로를 돌려보지 못했다.
   특히 2단계의 `node` 프로세스는 실행 파일이 nvm 경로라 경로 검사로 잡히지 않는다 —
   1단계 창 제목 종료에 의존한다. `start.bat` 이외의 방법으로 띄운 프론트는 stop.bat 이
   종료하지 못할 수 있다. **PC 에서 1회 확인 필요.**
2. **손익 색은 아직 현행(상승 초록/하락 빨강)이다.** 확인 근거 화면은 원래 색이 없었는데
   이번에 `directionColor` 를 적용해 색이 생겼다. 국내 관례 전환은 후속 ③ 에서 한다.
3. **`.hre-table` 계열 CSS 가 미사용으로 남았다.** 제거 여부는 다른 화면 사용처를 확인한 뒤 판단.
4. 후속 ②~④ 미착수.

## 6) 다음 검증자(Codex)에게 알릴 점

1. **행을 `role="button"` 으로 바꾸면서 접근가능 이름 충돌이 생겨 `aria-label` 로 고정했다.**
   `자료 확인 필요` 배지가 붙은 행은 접근가능 이름에 그 문구가 섞이는데, 빠른 보기의
   `자료 확인 필요 (N)` 버튼과 같은 문구라 `getByRole("button", {name: /자료 확인 필요/})`
   가 다중 매치로 터진다. **기존 테스트는 fixture 에 `need_check` 행이 없어 우연히 통과하던
   상태**였고, 실제 화면에서 해당 종목이 하나만 생겨도 깨졌다.
   `aria-label={"<종목명> 상세 보기"}` 로 이름을 고정하고 **그 상황을 재현하는 테스트 2건을 추가**했다.
2. **손익 색 함수가 두 곳이다** — `pnlClass()`(`frontend/lib/holdings_view.ts` → `.pnl-pos`/`.pnl-neg`,
   보유 현황·RunPanel·EvidenceDetails)와 `directionColor()`(`workbench/helpers.ts` 인라인,
   ETF 비교하기). 확인 근거는 후자를 쓰도록 했다. **후속 ③ 국내 관례 전환 시 두 곳을 함께
   고쳐야** 전 화면이 일관된다. (작업 중 "한 곳"이라고 보고했다가 코드 확인 후 정정한 사항.)
3. `stop.sh` 가드는 **가짜 외부 프로세스를 8000 에 띄워 실측 검증**했다 — 건너뛰고 살려두는 것,
   우리 프로세스는 정상 종료하는 것 양쪽 확인. `stop.bat` 은 미검증(§5-1).
4. 목록 루트에 `data-testid="hre-evidence-list"` 를 추가했다. 테스트 조회용이며 화면 영향 없다.
