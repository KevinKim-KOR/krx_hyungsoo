### 1.1 사용자 실화면 지적 반영 (2026-08-13)

1차 화면 확인에서 나온 지적 4건. 각각 사용자 선택지를 받아 반영했다.

| # | 지적 | 반영 |
|---|---|---|
| 1 | `ok` 배지가 무슨 뜻인지 알 수 없다 | 열 제목이 사라지며 `data_quality.status` 원문만 남았던 문제. **정상(ok)이면 배지를 띄우지 않고**, 비정상일 때만 `⚠ 데이터 <상태>` 로 원문과 함께 표시 |

| 3 | `KODEX초과` 가 계속 `—` | **기존 버그**. §4 참조 |
| 4 | 선택 상세가 모든 탭에 계속 나온다 | 선택 상세는 탭 분기 바깥에 있는데 탭 전환 시 `selected` 를 비우지 않아, 지금 목록에 없는 종목의 상세가 남았다(보유 탭이 "조건에 맞는 보유 종목 없음" 인데 후보에서 고른 상세가 붙어 있음). **탭 전환 시 선택 해제**로 수정 + 회귀 테스트 1건 추가 |

### 보존한 기존 계약 (전부 무변경)

집계·상태 판정 로직은 한 줄도 고치지 않았다. 표시 형태만 바뀐다.

- `aggregateHoldings` — 같은 ticker 다계좌 한 행 집계
- 부분 평가 `(N/M)` — 평가손익·비중·평가액 각각 (부분값을 전체값처럼 보이지 않게)
- 다계좌 `count > 1` → 평가수익률 "계좌별 상이"
- 후보포함 / 보유여부 **3-state** (`relationState`) — 미포함과 "확인 불가" 구분
- `holdingEvidenceState` — Evidence 부재/실패는 "정상" 아닌 "확인 불가"
- NAV / 구성종목 상태 **분리 표시**
- stale 줄 `⚠ 이전 조회값 (재조회 실패 — 최신 아님)`
- 행 클릭 → `onSelect(ticker)` → 하단 `PriceChart`
- 빠른 필터 4종 · 검색 (부모 컴포넌트, 무변경)
- 후보 탭 정렬 키 6개와 재클릭 asc/desc 전환 동작

## 4) 지시문 외 변경

**`candExcess` 필드명 버그 수정 1건** (`workbench/helpers.ts`). 사용자 승인 후 진행.

화면 확인 중 `KODEX초과` 가 전 종목 `—` 인 것을 발견해 API 응답을 직접 확인했다.

```
excess_return: {'vs_kodex200_1m_pctp': 29.55, 'vs_kodex200_3m_pctp': 35.56, ...}
```

값은 있는데 `candExcess` 가 응답에 **존재하지 않는 키** `excess_return_pct` 를 읽고 있어
항상 `null` 이었다. 같은 파일의 보유 탭용 `evidenceExcess` 는 이미 `vs_kodex200_1m_pctp` 를
읽고 있어, 그 1M 기준에 맞춰 정정했다 (`excess_return_pct` 는 fallback 으로 남김).

- **이번 카드 전환과 무관한 기존 버그**다. 표 형태였을 때도 `—` 로 보였다.
- 영향 범위: 후보 행 표시 · **정렬 키 `KODEX초과`**(지금까지 전부 `-Infinity` 라 정렬이
  사실상 동작하지 않았다) · 선택 상세. 세 곳이 같은 함수를 쓴다.
- 사용자에게 "지금 고칠지 / 분리할지 / 보류할지" 를 물어 **"지금 고치기"** 를 선택받았다.

## 5) 알려진 한계 / 미완성

1. **1차 화면 확인은 받았고 지적 4건은 반영했다**(§1.1). 반영분에 대한 재확인은 아직이다.
2. **`확인 필요` 탭 미전환** (`AttentionTab`). 표가 아니라 항목 목록이라 성격이 달라 손대지 않았다.
3. **`일간` 은 항상 `—`.** 목업에는 값이 있는 것처럼 그렸으나, Holdings 응답에 일간 필드가
   없어 값을 만들 수 없다. §7.6 명시 항목이므로 자리는 두고 미제공만 표시한다 (기존 동작과 동일).
4. **`보유` 배지가 보유 탭 모든 행에 붙는다.** 그 목록은 전부 보유 종목이라 정보량이 0이다.
   목업에서 승인된 형태라 그대로 넣었으나, 실화면에서 거슬리면 제거 후보다. **미결.**
5. **보유 탭의 정상 상태 배지 미정리.** 후보 탭의 `ok` 배지는 정상일 때 숨기도록 고쳤으나
   (§1.1-1), 보유 탭의 `NAV` · `구성종목` · `근거 정상` 은 같은 패턴인데도 그대로 두었다.
   사용자 지시가 후보 탭 `ok` 배지에 한정돼 임의 확대하지 않았다. **미결.**
6. 카드 본문 780px · 지표 열 236px 은 1차 조정값이다. 실제 사용 폭에서의 적정성 재확인 필요.
   900px 미만에서는 지표가 카드 아래로 내려간다.
6. 후보 탭 정렬 바는 보유 현황의 `.holdings-sortbar` 스타일을 재사용한다. 클래스명이
   holdings 계열이라 의미상 어색할 수 있다 (CSS 중복을 피하려는 선택).

## 6) 다음 검증자(Codex)에게 알릴 점

1. **테스트 10건의 표기 기준을 바꿨다.** 검사 항목은 유지하고 조회 방식만 고쳤으나,
   화면 문구 자체가 바뀐 곳이 있다. 과거 검증 라운드에서 확정된 표시 계약이므로 중점 확인 바람.
   - `◆ 후보` → `후보 포함` 배지 (보유 탭)
   - `◆ 보유` → `보유` 배지 / 미보유 행은 `미보유` 배지 (후보 탭)
   - 열 헤더 존재 검사 → 지표 라벨 존재 검사 (+ `일간` 값이 `—` 인지 함께 확인)
   - `getAllByText("확인 불가")` → `getAllByText(/확인 불가/)` (배지 문구가 `NAV 확인 불가`
     처럼 라벨을 포함하게 되어 완전일치가 깨짐)
   - 정렬 테스트: 열 헤더 클릭 → 정렬 바 버튼 클릭. 카드 안에도 `1M` 라벨이 생겨
     `.holdings-sortbar` 범위 안에서만 찾도록 좁혔다.
   - 3-state 구분(포함/미포함/확인 불가, 보유/미보유/확인 불가)은 문구만 바뀌고 구분은 유지.
2. **후보 탭 정렬은 "제거"가 아니라 "이전"이다.** 사용자는 보유 표 기준으로
   "정렬 바 빼고 카드 전환만" 을 선택했는데, 그때 전제는 "보유 표에는 정렬 기능이 없다" 였다.
   후보 표에는 헤더 클릭 정렬이 실제로 있어 그대로 빼면 기능 손실이므로, 그 답을 확대 적용하지
   않고 정렬을 세그먼트 바로 옮겨 보존했다. 이 판단의 타당성 확인 바람.
3. `role="button"` + `tabIndex={0}` + `aria-pressed` 로 행을 만들었다. 표에서 목록으로
   바뀌면서 접근성 시맨틱이 달라졌다 (`row`/`columnheader` → `button`).
4. 목록 루트에 `data-testid`(`wb-holding-list` / `wb-candidate-list`)를 추가했다.
   테스트 조회용이며 화면에는 영향 없다.
5. **`candExcess` 정정으로 화면에 없던 값이 새로 뜬다** (§4). `KODEX초과` 는 1M 기준
   (`vs_kodex200_1m_pctp`)이며 보유 탭 `evidenceExcess` 와 같은 기준이다. 3M
   (`vs_kodex200_3m_pctp`)도 응답에 있으나 화면에는 노출하지 않는다 — 어느 기간을 보일지는
   설계 판단으로 보고 기존 표기(`KODEX초과`, 기간 미표기)를 유지했다.
6. **탭 전환 시 선택 해제**는 동작 변경이다 (§1.1-4). 회귀 테스트 1건을 함께 넣었다.
7. **검증 환경 변화** — 2026-08-13 맥북의 시장 DB 를 OCI 정본으로 교체했다
   (4개월 → 12년, `etf_daily_price` 92,123행 → 1,344,177행). 후보 목록 구성과
   1M/3M 값이 그 전후로 달라진다. 이전 스크린샷과 값이 다른 것은 이 때문이며 코드 변경이 아니다.
