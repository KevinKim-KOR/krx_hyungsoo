## 0. 요약

- **「OCI 운영·적용」 ① '마지막 OCI 점검 (읽기만)':** 섹션 이름을 '① 지금 OCI 상태'에서 바꿨다. 부제는 점검 성공이면 '확인 시각 M/D(요일) HH:MM · PC 백엔드가 시작될 때 한 번 읽음(재시작 포함)', 점검 실패면 '마지막 점검 시도 …'다. 요약은 '정상 운영 중' 대신 '예약표에서 필수 3종 표기 확인'이고, 실제 수신은 Telegram 에서 확인하라고 쓴다. 파일 두 행은 '정상' 대신 '파일 확인'과 '파일 수정 시각' · 'DB 파일 수정 시각 … (알림 실행 기록도 이 파일에 씀)'이다. 보유 적용 상태는 「종목 관리」 맨 아래 ‘OCI 적용’에서 확인하라고 글로 안내한다(① 은 버튼 0 그대로). 판정 로직(`overall`)은 바꾸지 않았다.
- **백엔드 응답 두 칸:** `GET /oci/startup-status` 에 메모리에 이미 있는 `param_read_at`(OCI 활성값을 읽은 시각) · `param_source`('startup' · 'apply')를 싣는다. 확인되지 않았으면 둘 다 null 이다. 새 OCI 읽기 · 새 계산 · 새 쓰기는 없다.
- **「OCI 운영·적용」 ② '현재 운영 기준' 카드:** 머리 배지가 '지금 적용할 일'을 말한다. ① 과 **같은 응답**의 '운영 기준 활성' 행 상태와 읽은 시각으로 정한다. SUCCESS + 시각 = '확인값 기준으로 적용할 변경 없음' · STALE + 시각 = '적용할 변경 있음' · 그 밖 = '적용할 변경 확인 불가' · 응답 전 = '적용할 변경 확인 중…'. 줄은 '적용 기준' · 'OCI 활성값 마지막 확인' · '마지막 적용 요청 {시각} · 결과 {낱말}' · '요청 결과'다. [현재 기준 OCI 적용] 버튼은 '변경 없음'일 때만 기본 닫힌 [자세히 보기 (필요할 때 다시 적용)] 안에 두고, 나머지 경우는 기존 자리에 둔다. 적용 동작 · 확인 창 없음 · 진행 문구는 그대로다.
- **「OCI 운영·적용」 ② '장중 급등락 설정' 카드:** 배지를 'PC 기록 기준 · 장중 알림 설정 켜짐 / 꺼짐 / 정책 미설정 / 확인 불가'로 바꿨다(활성 정책 상태를 읽지 못하면 '… 켜짐 · 정책 상태 확인 불가' / '… 꺼짐 · 정책 상태 확인 불가' · RESULT 판정 C8 · §19). 조회 실패는 '불러오는 중...'에 멈추지 않고 '장중 급등락 설정을 불러오지 못했습니다.'로 따로 보인다. 날짜 이름은 '대표 ETF 선정에 사용한 종가일'이다. 판정 기준 표는 늘 펼친다(형수님 결정). 제목은 후보가 없으면 'PC에 기록된 적용 기준', 있으면 '승인 시 적용될 기준'이다. 세 묶음(보유 종목 급등락 · 사업군 대표 ETF 검토 · 발송 한도와 자료 조건) 아래 항목 · 설정값 · 무엇을 보는지 · 이 값의 뜻 4열을 두고, 문장은 같은 응답의 값과 사업군 수로 만든다. 후보가 있으면 '확인할 변경'에 장중 알림 설정 켜짐 변화 한 줄을 더한다.

### 18-1. A. 기능·산출물 검증

- **A-1 지시 일치 — 통과.** 활성 정책의 `enabled`가 문자열 `"false"`이거나 빠진 상태를 각각 임시 DB에서 재현했다. API는 두 경우에 `policy_enabled=null`을 응답했다. 이 응답을 렌더하면 배지와 현재 행은 ‘확인 불가’이고, 켜진 후보는 ‘켜짐 (지금 상태 확인 불가)’다. ‘지금과 같음’ 및 ‘지금 꺼짐 → 켜짐’이 표시되지 않았다. 정책 상태의 비문자열 값은 null로 반환됐으며, R1-F1~F3 관련 시험도 통과했다.
