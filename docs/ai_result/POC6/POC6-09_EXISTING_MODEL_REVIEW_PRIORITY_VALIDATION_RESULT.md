## 0. 요약

- **무엇**: 08 정정 실행에 저장된 **시험 예측 · 정답 · 가격 입력**만으로, 매일 3종목을 먼저 살펴본다면 기존 모델(RIDGE_P · HGB_P)의 '낮은 예측 순서'가 이후 큰 하락(실제 D20 ≤ -8%)에 해당한 종목을 단순 기준보다 잘 모으는지 비교했다. 새 학습 · 입력 추가는 없다.
  - **D20** = 기준일 종가 대비 다음 20거래일 최저 종가 변화(0 이하).
  - **기준**: PRICE20_RULE(20일 변화가 낮은 순) · MEDIAN_P(종목별 학습 중앙값) · UNIFORM_EXPECTATION(균등 선택 기대값).
- **결과**: 두 모델 · 두 범위 모두 `PRIORITY_GAIN_NOT_SHOWN` 이다. 표본은 두 범위 모두 충족했다.
  - **RIDGE_P**:
    - PRICE20_RULE 보다 G_ALL · G_REVIEW 모두 +11.82%p, UNIFORM 보다 +31.12 · +17.46%p 높고, 이 두 기준에 대한 네 조건을 모두 충족했다.
    - **MEDIAN_P 와의 비교에서 미충족**이다(G_ALL -2.65%p · G_REVIEW +0.35%p).
  - **HGB_P**: UNIFORM 보다만 높고, PRICE20_RULE(G_ALL -1.90 · G_REVIEW +4.81%p) · MEDIAN_P(-16.36 · -6.66%p)와의 조건을 못 넘었다.
- **뜻**: 고정 조건(매일 3종목 · -8% · 세 기준 각각 5%p · 2구간 · 구간 악화 한도 · R)에서 기존 두 모델의 검토 순서 효용을 **확인하지 못했다**.

- **단위(설계자 RESULT 판정 §5-4)**: P · R 은 비중을 소수로 저장한 값이다(P = 0.4921 은 약 49.21%). 두 비중의 차이 0.05 가 5%p 이며, 5% 상대 개선이나 투자 수익률이 아니다. 판정은 정확한 분수로 계산하고 보고만 소수로 표시한다.

## 4. 지시문 외 변경 · 구현 판단

### 4-1. 구현 판단

1. **`report.py` 분리**: PLAN(판정 수용)은 core · flow 두 파일이었다. 검토 반영(protocol 전체 대조 · 정정 사슬 · 종목별 표)으로 flow 가 650 을 넘을 것이라 보고서 · 글 · 한계 문구를 `report.py` 로 나눴다. 책임 분리일 뿐 기능 추가는 없다(flow 565줄).
2. **정확한 분수 계산(검토 L1)**: 선택 비중 · TP · P · R · 날짜 평균 · 차이 · 판정을 `fractions.Fraction` 으로 계산한다. 같은 값(예: 0.35 - 0.30)이 부동소수 오차로 0.05 경계의 반대쪽에 떨어지지 않게 하려는 것이다. 저장 · 보고 · 대조 값만 `to_json` 으로 float 로 바꾼다. 08 의 실제 D20 · 예측 · P 값(float)은 그대로 비교한다(-0.08 경계 포함).
3. **실행 ID 마이크로초 + 시계 확인(검토 L4)**: 실행 ID = `YYYYmmddTHHMMSSffffffZ_<8hex>`. 이전 실행보다 이르거나 같은 시각이면 CHECK_REQUIRED(폴더 없음)다. 그래서 폴더 이름 순서 = 실행 순서이고, verify 기본 = 가장 최근 실행이다.
4. **입력 기준 경로 분리**: `run(root, repo, …, inputs_root=None)` — 실행 코드 해시는 `repo` 에서, 고정 입력은 `inputs_root`(없으면 `repo`)에서 읽는다. 시험은 가짜 08 산출물을 tmp 에 두고 코드 해시는 실제 저장소에서 읽는다. CLI 는 둘 다 저장소 루트다.
5. **verify 기록 전체 대조(검토 M1 · L2)**: protocol · run.json 을 run 과 같은 함수로 다시 만들어 통째로 대조한다.
   - 근거: 고정 입력 해시 · 조건 · 범위 목록 · 개수 표 · 메모 · 실행 ID · 정정 관계(= 이 실행보다 앞선 폴더 전부) · 정정 사유 · 바뀐 코드 · 상태(OK 이면 사유 칸 없음).
   - 코드 근거는 형식만 확인한다(CODE_FILES 8개 · 64자리 hex · base_commit 40자리 hex 또는 없음). 지금 코드와의 일치는 보지 않는다(나중 정정 뒤에도 이전 실행을 검증할 수 있게).
6. **종목별 내역(검토 L7 · 설계 §7)**: 범위 · 종목마다 행 · 큰 하락 행 · 방법별 선택 비중 합 · 적중(w × Y) 합을 남긴다. 반복 선택 집중은 종목별 선택 비중 · 선택된 종목 수 · 상위 3 비중이다.
