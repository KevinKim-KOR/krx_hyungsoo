## 1. ML 관련 — 다음 작업(ML 고도화 설계)과 바로 이어짐

**원문 §7 'UI 이후의 프로젝트 진행 방향'**(2026-07 시점):

> 사용자의 최신 요청:
> - UI를 친구 프로젝트에 준하는 정보 밀도·차트·그래프 수준으로 개선
> - UI PASS 후 CPU/GPU를 실제 한계까지 활용해 보고 싶음
> - 한 달 집중 개발 기간에 최대한 많이 개발
> - 단, 설계의 꼼꼼함·검토 수준을 낮추라는 뜻은 아님
>
> 주의:
> - 다음다음 Step의 factor·라벨·산식·threshold를 지금 확정하지 않는다.
> - CPU/GPU Step은 단순 부하 테스트가 아니라 실제 투자 판단 품질 개선 산출물로 연결해야 한다.
> - RTX 4070 SUPER 및 CPU를 실제 사용하는 구조를 목표로 하지만, 모델·라벨·데이터 범위·평가지표는 해당 Step 시작 시 canonical 문서와 현재 데이터 상태를 보고 설계한다.
> - ML이 UI Step을 지연시키지 않으며, UI와 ML을 한 Step에 섞지 않는다.

**지금 문서**:
- GPU 는 성공 기준에 남아 있다.
  - `docs/PROJECT_ORIGIN_INTENT.md:75` '4070s의 동작 — ML 이외 작업을 못할 정도로 GPU가 돌아가는 상태'.
  - `docs/MASTER_PLAN.md:175 · 178` '실제 연산 부하 · 4070s 실제 배치 실행 로그 또는 사용 증거'.
  - `docs/ASSUMPTIONS.md:208` L-2 'GPU/큰 ML이 현재 병목을 해결하는가?'(OPEN).
- **CPU 를 실제 한계까지 쓰고 싶다는 희망은 어디에도 없다.**
- ML 설계 인계(`docs/handoff/POC5_CLOSEOUT_AND_POC6_ENTRY_HANDOFF_2026-10-21.md` §3)도 CPU · GPU 실사용 목표를 ML 설계 항목으로 잇지 않는다.

**판단 요청**: ML 고도화의 목표 · 평가 · 채택 기준 설계에 'RTX 4070 SUPER · CPU 실사용'을 목표 또는 제약으로 넣을지 정한다. 원문 주의는 '단순 부하 테스트가 아니라 판단 품질 개선 산출물로 연결'이다. 넣는다면 PROJECT_ORIGIN_INTENT 성공 기준(지금은 GPU 만)에 CPU 를 함께 적을지도 정한다.
