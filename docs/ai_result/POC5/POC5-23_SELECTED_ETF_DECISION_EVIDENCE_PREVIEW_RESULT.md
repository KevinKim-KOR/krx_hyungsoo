## 4. 지시문 외 변경 · 구현 판단

- **글 모듈 분리**: 서비스 파일이 묶음 글까지 담자 623줄(KS-10 근접 600 이상)이 돼 묶음별 글 줄을 `app/decision_preview_lines.py` 로 나눴다(최종 서비스 227줄 · 글 487줄 · 검증자 r2 실측 정정 · PLAN §6 기록).
- **구성종목 날짜 방식**: 「ETF 구성종목」 분석 API 는 요청 전체에 최신 날짜 하나를 쓴다. 그대로 쓰면 저장일이 다른 보유 ETF(06-19 · 06-22)와 후보(08-20 · 10-02)의 쌍이 모두 자료 없음이 되므로, 보유 근거 builder 와 같은 **종목마다 마지막 저장일**로 읽고 같은 쌍 계산(`compute_pair_overlap`)만 쓴다(PLAN §6).
- **고점 대비(판정 §3)**: 화면이 받는 날짜는 응답 맨 위 `relative_upside_score_asof_date`(스냅샷 전체 2026-08-27) 하나뿐이고 종목별 날짜는 오지 않는다 — 라이브 스냅샷 1,162행 중 18행은 06-24 ~ 08-26(읽기). 판정의 '날짜를 화면에서 확인할 수 없다면 값 · 정렬을 쓰지 않는다'를 적용해 「보유와 비교」 선택 상세 값 · 정렬을 뺐다. 다른 화면의 같은 값은 범위 밖(BACKLOG 관찰).
- **단기 문구의 날짜 검사(판정 §3 보충 사실)**: 판정 문구('기존 5/10/20구간 계산은 날짜 일치를 검사하지 않는다')와 달리 보유(PC 근거 사본 `pc_price_basis`)는 끝 · 시작 날짜가 KODEX200 과 다르면 값을 비운다. 후보(`compute_short_term_momentum_batch`)만 검사하지 않는다. 글 · 도움말은 실제 코드대로 둘을 나눠 적었다.
- **검토 반영 판단**: 보유 국면 날짜는 같은 응답의 PC 비교 기준일(`price_basis.reference_date` = KODEX200 최신 저장일 · 국면 계산 이력의 끝)로 적는다 — 공유 builder · API 의 `market_asof` 값은 바꾸지 않는다. NAV 경고 문구는 `etf_nav_fetcher` 의 3% · 5% 기준값을 그대로 가져와 만든다. 상세 단위(%p)는 같은 값의 표시 단위만 바꿨다(이름 · 값 그대로).

### 1) A. 기능/산출물 검증
