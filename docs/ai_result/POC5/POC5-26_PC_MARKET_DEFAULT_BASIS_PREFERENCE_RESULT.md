## 0. 요약

- **지금까지**:
  - 조회 기준(일간 · 1개월 · 3개월) 초기값이 코드 상수 1개월(`DEFAULT_MARKET_BASIS`)이었다. 그래서 화면을 열 때마다 1개월로 시작했다.
  - 기준은 표 보기 머리 클릭으로만 바뀌었고(카드 보기에는 선택 없음), 바꾼 기준은 저장되지 않았다.
- **이제**(설계 §2 · §3 · 판정 §1 · §2 · §3):
  - **표시**: 목록 카드 맨 위(카드 · 표 보기 공통)에 '기본 조회 기준 {기준}' 한 줄과 [이 기준을 기본으로](중간 40px)를 둔다.
    - 지금 보는 기준이 기본과 같으면 회색 '이미 기본'이고 누를 수 없다.
    - 다르면 '· 지금 보는 기준 {기준}'(파란 글자)과 누를 수 있는 버튼이 나온다.
    - 저장값이 허용 밖이면, 1개월(대신 쓴 값)을 보고 있어도 버튼을 누를 수 있다. 명시 저장으로 바로잡기 위해서다.
  - **저장**: 이 브라우저 localStorage 키 하나 `krx.marketDiscovery.defaultBasis.v1` 에 저장한다.
    - 값은 API `basis` 값 그대로다(`daily` · `one_month` · `three_month`).
    - 버튼을 눌렀을 때만 쓴다. 저장 클릭 전후 네트워크 요청 수는 같다(시장 GET · 갱신 시작 없음).
    - setItem 뒤 다시 읽어 같은 값일 때만 성공으로 본다.
  - **첫 조회**: 화면 상태 초기값에서 한 번 읽어 첫 시장 조회부터 그 기준을 쓴다. 1개월을 먼저 부르지 않는다. 메뉴를 다시 열 때도 화면이 새로 올라와 저장 기본으로 시작한다.
  - **읽기 문제**: 없음 · 허용 밖 값 · 읽기 실패는 1개월로 시작한다.
    - 허용 밖 값 · 읽기 실패는 같은 줄에 주황 짧은 안내를 보인다.
    - 읽기 · 기동 · 조회 · 메뉴 이동으로는 저장소에 쓰지 않는다. 저장값을 자동으로 고치지 않는다.
  - **저장 실패**: 빨간 한 줄 '기본값 저장을 확인하지 못했습니다. 현재 조회는 유지됩니다.'(판정 §3). 기본 표시 · 지금 조회는 그대로다.
  - **기준 바꾸기**: 지금처럼 표 머리에서만 한다.
    - 임시 변경 · 방향 전환 · 필터 변경 · 다시 읽기(갱신 끝 · 'VIX 다시 받기' 끝)는 기본을 저장하지 않는다.
    - 같은 동작 때문에 저장 기본으로 되돌아가지도 않는다.
  - **다른 탭**: 같은 브라우저의 다른 탭에서 기본을 바꾸면 이 줄의 '기본' 표시만 다시 읽는다. 지금 조회 · 시장 GET 은 그대로다.
  - **아래로 넘기는 값**: 표시 · 「보유와 비교」 조건 · 복사문 · AI 세션 · ETF 구성종목 전달 = 지금 조회 응답 그대로다(새 필드 0).
  - **저장 범위 설명**: 한 문장을 기간 상자 첫 줄 ? 끝에 둔다(설계 §2 '기존 도움말 안에').
- **바뀌지 않는 것**: 다른 화면(「오늘의 투자 점검」 · 대시보드 · 「ETF 비교하기」)은 기본 1개월 그대로다. 백엔드 변경은 없다.

## 4. 지시문 외 변경 · 구현 판단

- **저장 실패 안내는 그 줄의 상태로 둔다.** 기준을 바꾸거나 다시 읽으면 화면 전체가 '불러오는 중'이 되고, 줄이 새로 올라오면서 안내가 사라진다. 지난 시도의 안내를 다른 기준 화면에 남기지 않기 위해서다.
  - 카드 ↔ 표 전환, 다시 눌러 성공한 경우, 저장할 것이 없어진 경우(다른 탭이 같은 기준을 저장)에도 보이지 않는다.
- **읽기 안내(허용 밖 · 읽기 실패)는 저장에 성공하면 사라진다.** 그때부터 저장값이 정상이기 때문이다.
- **쓰기 성공 판정 = setItem 뒤 다시 읽어 같은 값.** PLAN §2 그대로이며, 판정 §3 문구('확인하지 못했습니다')의 근거다.
- **독립 검토 1회 반영(2026-10-19 · 세 관점 · 지적마다 반박 검증)**: 확인 12건(P1 0 · P2 3 · P3 9)을 모두 고쳤다. 반박 2건은 아래와 같다.
  - **[P3 · 화면] 저장값이 허용 밖일 때**: 1개월이 '이미 기본'(누를 수 없음)이라 1개월을 바로 저장할 수 없었고, 안내가 매번 다시 보였다.
    - 고친 내용: 허용 밖이면 기본을 '미확정'으로 보고 1개월에서도 버튼을 살린다. 명시 저장으로 바로잡으면 안내가 사라진다.
    - 읽기 실패는 사용자 확인 목업 ⑥ 그대로 '이미 기본'이다(저장소가 막혀 있으면 저장도 실패하기 때문).
    - 판정 §2 '읽는 과정에서 자동 수정 없음'은 그대로다.
  - **[P3 · 화면] 다른 탭**: 같은 브라우저 다른 탭에서 기본을 바꿔도 열린 화면의 '기본' 표시가 그대로였다.
    - 고친 내용: storage 이벤트(이 키 · 저장소 전체 지움)로 '기본' 표시만 다시 읽는다. 지금 조회 · 시장 GET · 저장값은 바꾸지 않는다.
    - 근거: 설계 §2-3 '저장된 기준을 알 수 있다'. 설계 §3 이 범위 밖으로 둔 것은 기기 · 브라우저 · 접속 주소 간 동기화뿐이다.

## 5. 알려진 한계 / 미완성

- **저장 범위는 이 브라우저 · 이 접속 주소(origin)다.** `localhost:3000` 과 `127.0.0.1:3000` 은 따로 저장된다. 설계 §3 저장 위치 그대로이고, 기간 상자 ? 에 한 문장으로 알린다.
- **카드 보기에서는 기준을 바꿀 수 없다**(지금과 같음 · 판정 Q1 (a)). 표 머리에서 기준을 고르면 카드 · 표 어느 보기에서든 저장할 수 있다.
- **카드 큰 숫자는 늘 1개월 수익률이다**(이번 변경 전부터 · POC3-ML-02 M-3).
  - 기본을 일간 · 3개월로 저장하면 첫 화면 카드는 그 기준 순서인데 큰 숫자는 1개월이다.
  - 기간 상자 첫 줄은 그 기준 계산 기간을 보이고, 카드 오른쪽 칸에 일간 · 1개월 · 3개월 값이 모두 있다.
  - 바꾸지 않았다(설계 §1 '조회 기준 하나만'). 필요하면 설계자 판단 사항이다.
- **다른 화면이 같은 API 를 1개월로 부르는 요청은 그대로다.** 예: 앱 첫 화면 「오늘의 투자 점검」의 1개월 요청. 판정 §2 '이 화면의 중복 요청으로 세지 않음'에 해당한다.
- **브라우저가 사이트 저장소를 막으면 늘 1개월로 시작한다.** 이때 같은 줄에 읽기 실패 안내가 보이고, 저장하면 실패 안내가 나온다.
