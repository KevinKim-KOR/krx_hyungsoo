- **계산** — 새 파일 `app/pc_price_volatility.py`

  - 통과(E = D)하면 **D 이하 원본 최근 41행**을 읽는다. null · 0 이하 종가를 거르지 않는다. 종목별 SELECT 한 번 · `mode=ro` · 같은 종목 여러 계좌는 결과 공유.

## 4. 지시문 외 변경 · 구현 판단

1. **새 파일 줄 수**: PLAN 은 약 120줄로 적었으나 실제 212줄이다. black 줄바꿈 · 설명문 · 응답 모델 · 손상 change 처리 포함이다.
2. **사유 코드 이름 `basis_unconfirmed`**: 판정 §4 '가격 기준 확인 필요'에 맞춰, 실제 기준 변화로 단정하지 않는 이름을 골랐다(목업 시제품의 `basis_break` 를 바꿈).
3. **E 없음 때 `end_date`**: 값이 없으므로 null 이다. 화면 기간 줄은 'PC 저장 종가'만 보인다.
4. **D 없음 · 기준일 다름일 때 기간 사유**: 두 값 모두 null 이다(칸을 그리지 않으므로 사유 칸이 필요 없음).
5. **허용 밖 출처**: POC5-06 의 허용 출처(FinanceDataReader · NAVER_FDR) 밖이면 그 기간을 `invalid_price`('가격 확인 필요')로 둔다. 06 은 별도 사유 이름을 쓰지만 이번 화면은 사유 세 가지로 묶었다(PLAN §3 표).
6. **읽기 연결**: 날짜 검사를 통과한 종목이 하나라도 있을 때만 `file:<절대경로 URI>?mode=ro` 로 한 번 연다. 없으면 열지 않는다.
7. **손상된 저장 change(검토 BE-3)**: 06 `link_break` 는 change 를 `float()` 로 읽는다. 텍스트 change 가 있으면 예외로 근거 응답 전체가 실패했다.
   - PC 쪽 `_link_unconfirmed` 에서만 `TypeError` · `ValueError` 를 그 기간의 `basis_unconfirmed`(연속성 확인 불가)로 둔다. 06 동작은 그대로다.
8. **종목을 바꾸면 다시 접힘(검토 F1)**: 구역에 종목별 `key` 를 줬다. 예전에는 한 종목에서 펼친 상태가 다음 종목에 남았다(설계 §5 '기본은 접힘').
