## 3. 구현 규칙(설계 · 판정 문장 그대로 적용)

| 항목 | 규칙 |
|---|---|
| 참조 상태 | POC6-21 `simulate` 와 같은 순서(`_open` → `_close` → `_protect_overlap`)를 돈 뒤, 공통 신호일이면 `_weekly` 직전에 상태를 복제한다. R0 원본 정책은 그대로 재생한다. 공식 실행에서 이 루프의 R0 장부가 같은 시작의 POC6-21 `simulate` 장부와 같은지 대조하고, 다르면 CHECK_REQUIRED. 실제 2014~2017 평가가 불확정이면 CHECK_REQUIRED 로 보고(판정 A-6 4) |
| 분기 | 복제 상태의 `end` = T. 행동 의도는 실행일 E = D+2(BUY priority 1) · D+1 ~ T 동안 체결 · 평가 · 보호만 돌리고 새 통상 계획은 없음 · NAV_T = T 장부 값 · NAV_D = 참조 장부 D 값. 분기 행동 집합은 아래 행동 경계와 같다. 분기 중 `_close` 가 평가를 확정하지 못하면 그 D 학습 상태 전체 제외 |
| 미결 통상 의도 | 매수 대기 또는 사유 EXIT 매도가 살아 있음 → 먼저 KEEP 만. 보호로 바뀐 이탈(사유 PROTECT)은 보호 매도로 보고 그 종목만 매도 대상에서 뺌 |
| 매도 대상 | 보유 ∩ 그날 자격(34열 있음) ∩ 살아 있는 매도 없음. 자격 밖 보유 = Q4 보류(매도 대상 아님 · 사유 기록) |
| 행동 경계(Q2) | 예정 슬롯 = 5 − 현재 보유 − 살아 있는 매수 대기 + 이번 행동의 매도 + 현재 보유 중 살아 있는 보호 매도(서로 다른 보유 · 보호 예정 종목은 이번 매도로 중복 선택 안 함) · BUY 포함 = 예정 슬롯 ≥ 1 그리고 h + (1−c)s > 10^-9(c = 그 장부 비용 · 보호 예정 대금 미포함 · 10^-9 = 잔차 경계일 뿐 최저 금액 · 문턱 아님). P/S 와 학습 분기에 적용 · R0 에는 적용 안 함 |
| 매수 직전 재확인 | H1 `_open` 은 매도 처리 뒤 매수 단계에서 보유 5 이면 CANCELED_SLOT_FULL · 예산 0 이면 CANCELED_NO_CASH 로 처리한다(코드 확인). 이 보장에 기대지 않고, 새 루프(참조 · 분기 · P/S)가 매일 `_open` 뒤 보유 ≤ 5 · 현금 ≥ −10^-9 를 다시 검사해 어기면 CHECK_REQUIRED · 체결된 매도는 되돌리지 않음 |
| 표준화 · 결측(Q1) | 분기 유효 학습 D 의 후보/보유 ETF 를 D · ETF 당 한 번 · 열마다 결측 아닌 ETF 날짜 안 동일 가중 → 관측 있는 날짜 사이 동일 가중으로 μ · 모집단 분산(같은 가중 (x−μ)²) · 열 전체 결측 날짜는 그 열 통계에서만 제외(D 삭제 없음) · 관측 0 열 = CHECK_REQUIRED · σ = 0 열 = 0 · 나머지 (x−μ)/σ 뒤 정상 결측(None) 칸만 0. 같은 μ · σ 를 P/S 학습과 그 분기 평가에 사용 · 결측 지시 열 없음. 가격 · 평가 장애 · 시장 공통 공백 · 예상 밖 비유한 값은 대치하지 않음 · KEEP/빈 역할 0 블록은 관측으로 세지 않음. 분기별 열 관측 · 결측 · 상수 여부와 장부별 대치 칸 수(D · ETF · 열 기준 · 행동 중복 수 별도) 기록 |
| 40bp(Q3) | 행동 예산 조건 · b · z 매수 블록 · k · 실제 체결 비용 모두 c = 0.004 · s · h · NAV_D = 40bp 자기 장부 상태 · β · μ · σ · s_g = 20bp 학습값 그대로 · 40bp 정답 · fit · 정규화 · 비용 탐색 없음 |
| 행동 순서 · 동점 | 통상 거래 수 → KEEP · SELL · BUY · SWITCH → 종목코드(SWITCH = 매도 코드 → 매수 코드). 학습의 a_star · 예측 선택 모두 같은 순서 |
| 모형 배정 | POC6-20·21 잠금의 `assign`(cutoff ≤ D 인 가장 최근 분기) 그대로. 학습 자료 T ≤ 위치(C)−20 이라 배정된 D 보다 앞선다 |
| LP | κ_a = k_a/s_g · q_a = βᵀz_a − κ_a · β = β⁺ − β⁻ · Σ(β⁺+β⁻) ≤ 1. MAE = 행마다 절댓값 보조 변수 t(제약 우변에 κ · y) · 날짜 균형 가중 → 목적에 상수 없음 · LP_full = solver.fun. | 수치 조건 | 상태 0 · L1 초과량 max(0, ‖β‖₁ − 1) 와 다른 제약 위반 ≤ 10^-7 · abs(직접 전체 평균 손실 − LP_full) ≤ 10^-7. SPO+ 의 상계 · 0/음수 경계는 전체 손실로 판정(상수를 뺀 raw solver.fun 음수 ≠ 결함) · 실패 시 다른 solver · 설정 대체 없음 |

## 4. 설계자 확인 결과(PLAN 판정 2026-11-05 · 확정)

제출 때 질문은 한 줄로만 남기고, 판정 확정 계약으로 바꿨다. 자세한 계약은 판정 A-2 ~ A-5 와 §3 표다.

- **Q1 — 34열 결측과 선형 점수**(제출: 선형 점수는 None 을 받을 수 없음 · 후보 행 9/3,095) → **(a) 수용.** P/S 선형 입력 사본의 표준화 단계에만 정상 특징 결측을 그 분기 학습 평균 위치 0으로 대치한다. 원본 특징 · H1 · R0 · 자격 · Q4 는 그대로이며 H1 의 '0 · 중앙값 채움 없음'을 전역으로 바꾸지 않는다. (b) 행동 삭제 · (c) 장부 중단은 채택하지 않았다.
- **Q2 — BUY 포함 경계**(제출: 보호 예정 슬롯 · 잔차 예산) → **(a) 수용.** 예정 슬롯 · 10^-9 예산 경계 · 보호 예정 대금 미포함 · 실제 매수 직전 슬롯 · 현금 재확인(5종 초과 없음 · 체결 매도 유지). R0 기준선은 바꾸지 않는다.
- **Q3 — 40bp 장부의 b**(제출: b 산식의 c) → **(a) 수용.** 예산 조건 · b · z 매수 블록 · k 모두 c = 0.004 · 학습값(β · μ · σ · s_g)은 20bp 그대로.
- **추가 명확화(판정 A-5)** — LP 검산은 한쪽 차이가 아니라 고정 상수항을 포함한 전체 목적값과 직접 손실의 **절대 차이**로 한다(§3 LP · 수치 조건).

## 6. 가짜 자료 시험(기존 연구 재실행 없음)

1. 행동 열거: 36 상한 · 미결 통상 의도 → KEEP 만 · 보호 예정 · Q4 보류 종목 매도 제외 · 순서 뒤집기 변이.
2. 행동 경계(Q2): 보호 예정 슬롯 포함 · 예산 h + (1−c)s 가 10^-9 위/아래인 두 장면 · 보호 예정 대금 미포함 · 실제 매수 직전 슬롯 부족 → 매수만 취소 · 보유 5종 초과 0 · 체결 매도 유지 · 재확인 검사를 끈 변이가 잡힘.
3. 분기 정답: 손계산 장면(BUY · SELL · SWITCH · 이연 · 매수 취소 · 분기 중 보호) g 일치 · KEEP g = 0 · 비용 1회 · 한 행동 실패 → D 전체 제외.
4. 참조 루프 = POC6-21 `simulate`(R0) 장부 일치.
5. 표준화(Q1): 날짜 안/사이 동일 가중 μ · 모집단 분산 손계산 · 같은 D · ETF 한 번만 · 열 전체 결측 날짜는 그 열에서만 제외 · 관측 0 열 → CHECK_REQUIRED · 상수 열 0 · 결측 칸만 0 · 평가에 같은 μ · σ · 대치 칸 수 기록.
6. 40bp(Q3): 예산 조건 · b · z 매수 블록 · k 가 c = 0.004 · β · μ · σ · s_g 는 20bp 값과 같음.
7. SPO+: 유한 행동 무작위 장면에서 전체 손실 음수 없음 · 예측 = 정답이면 0 · 실제 선택 손실 이상(상계).
8. LP: 작은 문제의 전수 탐색 · 손풀이와 LP_full 일치 · **비용 오프셋 κ ≠ 0 장면** · raw solver.fun < 0 이지만 전체 손실 ≥ 0 인 장면 · 목적 오차를 양 · 음 방향으로 넣은 변이가 모두 절대 차이 검사에 걸림 · L1 초과량 · 제약 위반 검사.
9. HiGHS 도우미: 도우미 밖 linprog 호출 0(소스 검사) · 기본값 선행 호출 뒤 실패를 기본값으로 대체하지 않음(이 확인은 하위 프로세스에서만 · 전체 pytest 의 다른 시험이 쓰는 HiGHS 전역 설정을 바꾸지 않게) · 경고 거르기가 `threads` 알림 한 종류뿐.
10. 시간순: 5년 창 · T ≤ 위치(C)−20 경계 · 104 미만 → INSUFFICIENT_DATA.
11. P/S 장부: 첫 공통 신호 R0 편입 · 이후 q 최대 · 40bp 같은 계수 · Q4 · CHECK_REQUIRED · 보조 구간 = 연속 장부 안 기간 수익.
12. 감사 · 판정: 독립 검산이 규칙 변이를 잡음 · AC3~6 · bootstrap 경계 조합 표 · 예산 판정 위치.
13. 잠금: 기대값 · SciPy/HiGHS/numpy 판이 다르면 거절 · 1회 규칙 · 라이브 DB 미사용(tmp · 고정 fixture).

## 7. 공식 실행 순서와 승인 요청 범위

공식 실행 = 새 Python 프로세스에서 한 번의 고정 묶음이다(설계 §6-2): 잠금(§1 의 달력 · 분기 상한 · 판 기대값 대조) → 참조 경로 · 정답 → 분모 · 성숙 · 수치 조건 → 최대 70 fit → 2018~2020 선행 4장부 → 2021~2026-09-21 주 평가 8장부 → 보고 · 검산 → 마지막 예산 판정. 성과에 따른 선택 · 재실행은 없다.

판정 A-7 에 따라 PLAN 재제출 없이 사용자에게 다음 네 항목을 한 묶음으로 확인했다(**사용자 한 묶음 승인 2026-11-05 · ① ~ ④ 모두**). 기존 POC6-21·22 승인과 적용성 판정은 이 승인이 아니다.

1. 기반 문서 세 곳(PROJECT_ORIGIN_INTENT · ASSUMPTIONS · KILL_SWITCHES)에 **판정 B §6-3 의 갱신된 독립 예외 원문** 추가(기존 제한 · 예외 삭제 없음).
2. 새 격리 연구 패키지 · CLI · 시험 구현과 §6 가짜 자료 확인.
3. PC 의 잠금 1회 · 공식 실행 1회 · 저장 산출물 검산(외부 조회 · 설치 · 운영 DB 쓰기 · OCI · PUSH 변경 없음).
4. 검증자 확인과 설계자 최종 RESULT 뒤 관련 코드 · 문서 종료 반영 및 커밋 · push(연구 원자료 · 모델/잠금/실행 산출물 · 사용자 handoff 제외 · OCI 배포 없음).

승인을 받으면 같은 범위의 중간 작업마다 다시 묻지 않는다. 코드 결함으로 별도 공식 정정 실행이 필요하면 원인 · 동일 조건 여부 · 기존 기록 보존을 보고하고 그 실행만 따로 확인받는다. 낮은 성과는 정정 실행 사유가 아니다.
