## 4. 계산 정의 대응 (설계 §4 ~ §6 · 구현할 식만)

- 날짜 d · 범위 s 마다 n · k = min(3, n). 점수가 낮을수록 먼저 검토한다(PRICE20 = `p[1]` · 세 구성 = 제한 예측).
  - 경계값 q = 낮은 순 k 번째 점수. m = q 보다 작은 수, b = q 와 같은 수. 비중 = 1(< q) · (k - m)/b(= q) · 0(> q).
  - 동등은 저장 숫자 그대로 비교한다(반올림 · epsilon 없음).
- Y = 1[truth ≤ -0.08] · M = ΣY · TP = Σ w·Y · FP = k - TP · FN = M - TP. P = TP/k. R = TP/M 은 M > 0 일 때만 계산하고, 아니면 null 이다.
- 균등 기대값(식 · 난수 없음): P = M/n · R = k/n(M > 0 일 때).
- 평균: P = 모든 시험 날짜 평균. R = M > 0 날짜만 평균하고 그 날짜 수를 함께 남긴다. 모두 날짜마다 같은 비중이다.
  - 전체 · 구간 1 · 2 · 3 을 각각 계산한다. R 이 정의되는 날짜가 없으면 null + 자료 부족이다.
- 표본 충족(범위별): 큰 하락이 있는 날짜 ≥ 20 · 종목 ≥ 3, 그리고 각 구간에서 날짜 ≥ 5 · 종목 ≥ 2. 아니면 두 모델 모두 `DATA_SHORT` 다(수치는 공개).
- 판정(범위 × 모델 RIDGE_P · HGB_P · 기준 PRICE20_RULE · MEDIAN_P · UNIFORM_EXPECTATION): 아래 네 조건을 모두 만족하면 `PRIORITY_RESEARCH_SIGNAL`, 아니면 `PRIORITY_GAIN_NOT_SHOWN` 이다. 조건별 참거짓 · 차이(%p)를 반올림 전 값으로 남긴다.
  1. 전체 P - 각 기준 전체 P ≥ 0.05.
  2. 각 기준과 구간별 P 차이가 양수인 구간 ≥ 2.
  3. 모든 구간 · 기준에서 P 차이 ≥ -0.05.
  4. 전체 R ≥ 각 기준 전체 R.
- 보고 내용:
  - 분모(n · k · M · 날짜 · 큰 하락 날짜 · 종목 · 행) · TP · FP · FN · 미포착 비중 · M > 3 인 날짜 수.
  - 동점 날짜 수 · 최대 동점 크기 · 방법별 종목 선택 비중(반복 선택 집중).
  - 두 범위 따로 · 자동 우승자 없음.

- **§6 다섯 사실 모두 수용**(판정 §2): 단일 `run` · PRICE20 = 예제 `p[1]` · 작은 새 동점 함수 + `partial_top` 대조 · MEDIAN_P 구간 안 같은 순위(기준선 성질 · 제외 · 변형 없음) · 08 verify 근거 = 기존 문서.
  - 고정 해시는 '같은 입력 판' 근거일 뿐, 입력의 연구적 타당성 · 이번 지표 정확성의 증명이 아니다.
- **같은 바이트(판정 §3-1)**:
  - 입력 파일마다 한 번 읽은 바이트로 sha256 을 대조하고, 그 바이트를 엄격 JSON 읽기로 파싱한 결과만 계산에 쓴다(다시 읽지 않음).
  - 연결은 `(ticker, date)` 일대일에 더해 예측 `fold` ↔ 예제 `i` ∈ `folds[fold]` 대조를 유지하고, `truth == y` 도 확인한다.
  - 20일 변화는 protocol `recipe.features.P` 가 고정 순서(`chg5 · chg20 · …`)이고 둘째가 `chg20` 일 때만 `p[1]` 로 읽는다.
  - 어긋나면 행 삭제 · 대체 없이 CHECK_REQUIRED 다.
- **run 순서(판정 §3-2)**:
  1. 실행 잠금 · 재실행 사유 확인 → 입력 6파일의 해시 · 형식 · 연결 · 개수를 사전 대조한다.
  2. 실행 ID 를 정한다. 그 직후부터 실패 기록 범위다(새 폴더도 범위 안에서 만든다).
  3. protocol 을 **계산보다 먼저** 저장한다(입력 해시 · 조건 · 방법 · 범위 · 코드 해시 · 출처 · 이전 실행 · 정정 관계).
  4. 그다음 Y · 순위 · 선택 비중 · P/R · 판정을 계산하고 rows · report · run.json(완료)을 저장한다.
  - 사전 대조 실패 = 새 실행 폴더 · 산출물이 없는 CHECK_REQUIRED 다. 실행 잠금 파일(`.run.lock`)은 그 전에 생길 수 있으며, 이를 '쓰기 0'으로 적지 않는다.
  - protocol 저장 이후의 실패 · 중단 = run.json FAILED 이고 원래 오류를 보존한다.
- **verify(판정 §3-3)**:
  - 고정 08 입력에서 다시 계산해 rows.json · report.json 전체와 report.md 를 대조한다.
  - 09 protocol 의 입력 해시 · 고정 조건 · 실행 ID 와 run.json 의 상태 · 정정 관계가 같은 실행을 가리키는지 확인한다.
  - protocol 의 조건은 코드의 고정 계약과 같아야 한다. 조작된 k · 경계 · 방법을 새 규칙으로 쓰지 않는다.
  - 실패 · 미완료 실행은 정상 결과로 돌려주지 않는다.
