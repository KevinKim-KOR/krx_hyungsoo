## 4. 운영 반영 · 확인(AC3 · 판정 보완 3 반영)

1. 커밋 · main 반영 · push(각 형수님 승인).
2. **OCI pull(형수님)**: 15:20 회차가 끝난 뒤나 비거래일에 한다. 08:05 ~ 08:35 는 배제한다. 개발자는 OCI 에 쓰지 않는다.
3. **반영 증거**: OCI revision(HEAD)이 반영 커밋과 같은지 확인해 기록한다(개발자 · OCI 읽기 전용 · 명령별 승인).
4. **운영 확인 = 반영 뒤 첫 정규 장중 회차**: 그 회차의 처리 결과(실행 status · 처분 · 상태 파일 `sent_today` · 진단 키)를 원장 · PC 사본과 대조한다.
   - 형수님 [원장 새로고침] 전후의 '마지막 성공 동기화' 시각을 기록하고, 같은 `event_id` 로 PC 사본과 OCI 원장을 대조한다.
   - 원장의 `sent` 처분은 '본문에 실림'이다. 실제 전송은 같은 `event_id` 의 `delivery` 로 확인한다.
   - 그 회차에 자연 발송이 있으면 같은 메시지를 형수님이 받았는지 대조한다. 발송이 없으면 '수신 대조 대상 없음'으로 기록한다. 수동 발송은 하지 않는다.
5. **K2 의심 건 질의**(사본 DB 읽기 전용): 같은 날 `off_schedule=0` · `FINALIZED` 에서 회차 N 에 (사업군 `sector_key` 또는 보유 ticker, state)가 `event_type=reentry_after_recovery` ∧ (`cut_by_section_cap` 또는 `sent` 인데 같은 `event_id` 의 delivery `failed` / `partial`) → 다음 정규 회차에 같은 (대상, state)가 `suppressed`.
   - 이 질의 결과는 **의심 건**이다. 당시 평가 결과 · 정책 · 한도 조건으로 누락 원인을 확인한 사례만 K2 로 판정한다.
   - 처분 집계는 반영 전후 운영 시점을 함께 적어 해석한다(Q9).
6. **구분해서 기록**: 고정 사례 검증(§3 · 변경 전 RED → 변경 후 GREEN)과 실제 운영의 K2 발생 유무를 따로 적는다.

## 7. 알려진 한계(지금 확인 범위)

1. 재현은 실제 조립 · 저장 함수를 운영 순서로 부른 것이다. Telegram · registry 를 포함한 `run()` 전체 관통은 아직이다(구현 단계 §3 rig 로 확인).
2. 운영 발생 빈도는 미확인이다(원장 대조 전 · §4).
3. 배포 전에 이미 K2 로 굳은 행은 그날 복구되지 않는다(회복 · 재진입하거나 다음 날 초기화될 때까지).
4. 15:20 회차에 잘린 재진입은 그날 다음 회차가 없다. 다음 날에는 전부 신규가 된다(`sector_signal_state.py:161-164`).
5. (판정 보완 1 로 해소 · 독립 검토 반영) 전송 성공 뒤 첫 상태 저장이 실패하면(예외를 삼킴 · `runner_evidence.py:199-200` · main `631b14a9` 기준 줄 번호 · 작업 사본(r1 F1 정정 뒤)에서는 `:226-227`) 변경 전에는 뒤의 관측 저장이 관측만 남겨 실제로 전달된 신호가 다음 회차에 한 번 더 나갈 수 있었다. 보완 1 은 두 번째 저장이 성공 사실을 대신 남기게 한다(§2 · §3 ⑩ ~ ⑬). 성공 사실이 남지 않는 경우는 셋이다.
   - 대신 저장(병합 · 쓰기)까지 실패: 관측만 다시 쓰고 `intraday_state_save_fallback_error` 를 남긴다(독립 검토 B-1).
   - 이번 회차 상태 쓰기가 모두 실패: 일반 상태 저장 장애(두 진단 키).
   - Telegram 전송 성공 뒤 `record_send_success` 의 `mark_sent` · `save_risk_state` 가 예외를 냄: `run()` 밖으로 전파돼 `_finish` 가 돌지 않는다(첫 저장 · 대신 저장 · 실행 기록 JSONL · 원장 마무리 없음). 변경 전부터 있던 경로이고 이번 범위 밖이다(독립 검토 B-2).
   - 세 경우 모두 다음 회차에 같은 신호가 한 번 더 나갈 수 있고, 앞의 두 경우는 `sent_today` 가 실제 발송 회차보다 1 적다(변경 전과 같음 · 결과서 §5).
6. 수동 실행(원장 `off_schedule=1`)이 조립과 저장 사이에 끼면 후보 집합이 어긋날 수 있다(기존 위험과 같은 성격).
