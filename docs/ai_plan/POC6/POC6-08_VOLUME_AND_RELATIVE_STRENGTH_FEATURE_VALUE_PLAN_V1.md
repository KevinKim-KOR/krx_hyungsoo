## 7. 판정 반영(2026-10-24 · PASS)

- **같은 행 · 같은 가중치의 범위(판정 §3-1)**
  - 여섯 구성은 P · D20 이 유효한 같은 행 집합을 쓴다. V · R 결측으로 빼는 행은 없다.
  - 날짜별 1/n_d 가중치는 **HGB 네 구성끼리만** 같다(공동 학습).
  - MEDIAN · RIDGE 는 같은 집합에서 종목별로, 학습 날짜마다 한 행씩 같은 비중이다(HGB 가중치를 쓰지 않음).
  - G_REVIEW 는 G_ALL 모델의 평가 행만 줄인다(다시 학습 · 가중치 재계산 없음).
- **A/B 판정(판정 §3-2)**
  - A = HGB_P **하나와만** 비교한다. 02 `judge` 를 계산 접점으로 쓰되, 02 의 두 기준(MEDIAN · RIDGE) 묶음 판정(`verdict_for`)은 쓰지 않는다.
  - `judge` 의 구간 규칙은 판정과 같다: 구간 기준 0 · 후보 0 = 동률(우위 아님), 후보 양수 = 악화.
  - 전체 기준 0(`base_zero`)만 `NO_BASELINE_HEADROOM` 이다. 02 함수는 바꾸지 않는다.
  - B 는 A 와 별도로 계산하고 A 결과를 지우지 않는다. 순서는 다음과 같다.
    1. RIDGE_P 전체 기준 0 또는 MEDIAN_P 전체 기준 0 → B `NO_BASELINE_HEADROOM`
    2. 비교(RIDGE 5% · MEDIAN 보다 작음) 미충족 → `FEATURE_GAIN_ONLY`(큰 하락 부족 여부 따로 표시)
    3. 비교 충족 · 큰 하락 표본 부족(20날짜 · 3종 미만) → `TAIL_DATA_SHORT`
    4. 표본 충분 · U 가 RIDGE 보다 5% 넘게 나쁨(RIDGE U = 0 이면 후보도 0 이어야 함) → `FEATURE_GAIN_ONLY`
    5. 그 밖 → `RESEARCH_CANDIDATE`
  - B 는 A 를 통과한 후보만 '사용 검증 후보'로 판단하고, A 미통과 후보도 B 수치는 보고한다. 모든 상태와 반올림 전 값, 실패 조건을 따로 남긴다.
- **Ridge 저장 · 복원(판정 §3-3)**
  - 종목별 `scaler mean · scale · coef · intercept · feature 순서(P 5열)` 를 그대로 저장한다(원시 입력 환산 없음).
  - 복원 예측 = `coef · ((x - mean) / scale) + intercept` 이고, 학습 직후의 원시 · 제한 예측과 복원 뒤 값을 모두 대조한다.
  - HGB 는 joblib bytes(+ sha256), 중앙값은 종목별 값이다.
- **실행 코드 근거(판정 §3-3)**
  - protocol 에 `base_commit`(HEAD)과 새 모듈 · CLI · 실제 재사용 계산 파일의 내용 sha256 · 환경 판(python · numpy · scikit-learn · joblib · threadpoolctl)을 적는다.
  - 재사용 계산 파일은 `reentry_review/prices.py · model.py` · `stored_volume_evidence.py` · `d20_pooled/study.py` 다.
  - `run` 은 지금 입력 · 설정 · 코드 해시가 잠금과 같을 때만 진행하고, 다르면 `CHECK_REQUIRED` 로 멈춘다.
  - 공식 1회는 연구 폴더 실행 잠금(06 `run_lock` 방식) + 결과 파일 1회 쓰기(`write_once`)로 지킨다.
  - 실패 · 복원 불일치는 부분 산출물과 실패 기록을 보존한다. 코드 결함 정정 뒤 재실행이 필요하면 기존 실행을 덮지 않고 정정 관계 · 이유를 남긴다. 성과를 바꾸려는 재실행은 하지 않는다.
