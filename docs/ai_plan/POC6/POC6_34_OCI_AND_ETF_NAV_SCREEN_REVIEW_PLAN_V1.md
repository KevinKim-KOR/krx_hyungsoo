  - 다른 행(발송 결과 '확인 불가' 등)도 보지 않는다. 지금도 발송 결과 행은 '확인 불가'인데 요약은 '정상 운영 중'이다.

- **파일 두 행:** 둘 다 OCI 에서 `stat` 만 한 결과다(내용 검사 없음).
  - '보유 종목 파일': 파일이 있으면 '정상'이고, 날짜는 파일 mtime 이다.
  - '운영 설정 DB': 크기가 0 보다 크면 '정상'이고, 날짜는 mtime 이다.
  - `runtime_state.sqlite` 에는 알림 실행 기록 표도 함께 있다. 그래서 이 날짜는 '설정 바꾼 날'이 아니라 '어느 표든 마지막으로 쓴 시각'이다(지금 11/19 08:30 = 시장 브리핑 시각).

### 2-3. Q6 판정 기준 표 문안

- **대조 범위(PLAN 판정 §2 끝).** 정책 12개 = 화면 10개 + 숨은 2개다. '중복 억제 창'(`dedup_window_minutes`)은 실행 코드가 읽지 않는 호환 별칭이다(`schema.validate` 가 `enabled=true` 일 때 재발송 대기와 같은지 · 0~1440 범위만 검사 · `schema.py:43-49` · `:102` · `:232-259`). ## 9. 개발자 적용 해석 I-n

판정이 문안 · 위치를 정하지 않은 곳에 적용한 해석이다. 설계자 판정과 다르면 RESULT 판정에서 바로잡는다.

**OCI ① (L1)**

- **I-1 · 부제 분기.** '점검 실패' = `reachable=false`(접속 실패 · 접속 대상 미설정 · 기동 읽기 예외)로 본다. 이때 시각이 있으면 '마지막 점검 시도 …'다. 접속은 됐는데 예약표를 못 읽은 경우(`reachable=true` · UNKNOWN)는 '확인 시각 …' 그대로 두고, 요약이 '예약표 확인 불가'를 말한다. 시각 표기는 지금 `fmtKst`(요일 포함)다.
- **I-2 · 요약 문안.** 성공 '예약표에서 필수 3종 표기 확인' / '시장 브리핑 · 보유 브리핑 · 장중 급등락 예약 표기가 OCI 예약표에 있습니다 · 실제 수신은 Telegram 에서 확인'. 일부 누락 '예약표에서 필수 3종 중 일부 표기 없음' / '빠진 예약: {이름}'. 그 밖 '예약표 확인 불가' / 지금 부제. 아이콘 · 색은 그대로다.
- **I-3 · 표 안 다른 행.** '자동 발송 예약' · '거래일 기준' · '미국 휴장일 달력' · '장중 대표 ETF' 의 상태 낱말 '정상'과 '운영 기준 활성'의 '일치' · '다름'은 바꾸지 않는다. 판정이 다룬 것은 요약과 파일 두 행이다.

- **I-6 · 바꾸지 않는 곳.** 메뉴 힌트 'OCI 상태 · 운영 기준 적용', 백엔드 `summary_line` · `note`, 「오늘의 투자 점검」 OCI 카드 문구는 바꾸지 않는다(판정 범위 = OCI 운영·적용 화면 · §7-7).
