## 2. 계산 · 읽기 · 표시 (설계 §7-2)

### 2-1. 읽기 — 미리보기 1회당 SQL 1번 추가

- D 가 정해진 뒤 선택 종목 하나만, `mode=ro` 연결로 한 번 읽는다.
  - `SELECT date, close, source, fetched_at, change FROM etf_daily_price WHERE ticker = ? AND date <= D ORDER BY date DESC LIMIT 60`
  - 원본 행 그대로(비정상 행을 거르지 않음). 가격 흔들림의 41행 읽기와 같은 꼴이다.
  - 기존 읽기(흐름 21행 · 흔들림 41행)는 바꾸지 않고 공유하지도 않는다. 그래서 61행 공유안 대신 60행 별도 1회다.
- 전체 ETF 대상 계산은 없다. 같은 종목의 여러 계좌는 종목 단위 미리보기 하나라 관측도 하나다. 평가비중 · 손익 합산은 손대지 않는다.
- DB 열기 · 읽기 오류는 자료 부족으로 바꾸지 않는다. 기존 계약대로 미리보기 전체가 짧은 실패 응답이 된다(보유 로더의 sqlite 오류 처리 · 후보 endpoint 경계).

### 2-2. 판정 순서 — 관측 전체

1. ETF 아님(`etf_master` 에 없음) → `대상 아님(개별 종목 · 이 관측은 ETF만)` · 읽지 않음
2. 보유인데 가격 흐름이 기준일 불일치 → 계산하지 않음(기존 보유 규칙 · 흔들림과 같음) · 읽지 않음
3. D 없음 → 계산하지 않음(가격 기준일 확인 불가)
4. 후보인데 목록 응답의 D ≠ 미리보기 읽기의 끝 날짜 → 확인 불가. 읽는 사이 자료가 바뀐 경우이며 서로 맞춰 넣지 않는다(설계 §4)
5. 읽은 마지막 행 날짜 ≠ D → 확인 불가(D 종가 다시 읽지 못함). D 행 종가가 유한한 양수가 아니거나 출처가 허용 밖 → 확인 불가(D 종가 확인 필요)
6. 통과 → 창별 판정(2-3)

### 2-3. 창별 판정 — MA20 = 끝 20행 · MA60 = 끝 60행 · 각각

| 순서 | 조건 | 결과 |
|---|---|---|
| 1 | 행 수 < n | `계산 불가(저장 종가 k/n개)` — 더 오래된 행으로 채우지 않음 |
| 2 | 창 안 날짜 중복 | `날짜 중복` — 표 기본키 (ticker, date) 라 실제로는 생길 수 없다. 순수 함수 방어만 둔다 |
| 3 | 창 안 종가가 유한한 양수 아님 · 허용 밖 출처(`valid_close` · `ALLOWED_SOURCES`) | `가격 확인 필요` |
| 4 | 창 안 연결에 POC5-06 `link_break` 경계, 또는 change 를 숫자로 못 읽음 | `가격 기준 확인 필요` |
| 5 | 통과 | 단순평균(D 종가 포함) |

- 연결은 창 첫 행부터 끝 행까지만 본다. 창 첫 행으로 들어오는 바깥 연결은 보지 않는다. 그래서 MA60 창 앞쪽 문제는 MA20 에 번지지 않는다.
- NAVER_FDR 구간은 change 가 없어 연결 검사가 부분적이다(POC5-06 한계 그대로 · 도움말 문장).
- 재사용: `app/reentry_review/prices.py` 의 `valid_close` · `link_break` · `ALLOWED_SOURCES`(흔들림과 같은 접점). 별도 경계 탐지는 만들지 않는다.

### 2-4. 표시 · 관계식

- 숫자: 기존 `intl_fixed(v, 2)`(화면 `toLocaleString("ko-KR")` 소수 둘째 고정 · 쉼표). 새 포맷 규칙은 없다. 종가도 같은 규칙으로 적는다.
- 관계식: 세 표시 글을 다시 수로 읽어 큰 순으로 적는다.
  - 같은 표시값은 `=` 로 묶는다. 같은 값 안의 이름 순서는 종가 · MA20 · MA60 고정이다.
  - 세 값이 모두 있을 때만 만든다. 하나라도 없으면 `확인 불가(없는 평균)` 이다.
  - 부분 관계(예: 종가와 MA20 만)는 만들지 않는다.
- 줄 배치: 가격 흐름 묶음 안 '변화율 …' 줄 바로 다음. 흐름 값이 없어 그 줄이 없으면 묶음 끝에 둔다.

```text
- 종목 이동평균: MA20 18,896.75원 · MA60 18,769.25원
- 표시값 기준 위치: MA20 > MA60 > 종가 (종가 16,775.00원)          ← Q1 괄호
- 이동평균 계산 구간: MA20 = 저장 종가 20개(2026-09-17 → 2026-10-20) · MA60 = 저장 종가 60개(2026-07-22 → 2026-10-20)   ← Q2
```

| 경우 | 원문 줄(목업 실제 출력) |
|---|---|
| MA60 만 부족 | `종목 이동평균: MA20 8,070.50원 · MA60 계산 불가(저장 종가 32/60개)` / `표시값 기준 위치: 확인 불가(MA60 없음) · 종가 7,750.00원` |
| MA60 창 안 연결 끊김 | `… MA60 계산 불가(가격 기준 확인 필요)` (MA20 은 값 그대로) |
| 동률 | `표시값 기준 위치: 종가 = MA20 = MA60 (종가 10,000.00원)` |
| 개별 종목 | `종목 이동평균: 대상 아님(개별 종목 · 이 관측은 ETF만)` / `표시값 기준 위치: 확인 불가` |
| 보유 기준일 불일치 | `종목 이동평균: 계산하지 않음 — 위 기준일 불일치(…)` / `표시값 기준 위치: 확인 불가` |

- 검토 질문 3줄은 설계 §2 원문 그대로다. 위치는 Q3 에서 묻는다.
- 도움말 `?`(카드 머리 하나 그대로)에 '종목 이동평균' · '검토 질문' 두 문단을 더한다. 내용: 20 · 60개 저장 종가(달력 · 장중 아님) · 표시값 비교 · 창별 사유 · ETF 만 · 매매 시점 아님.

### 2-5. 응답 선택 필드

- `PreviewResponse.moving_average`(선택)를 둔다. 값 = {상태 · 종가 · MA20/MA60 각각 상태 · 값 · 시작일 · 끝일 · 개수 · 필요 개수 · 관계식 글}.
- 원문 줄과 같은 서버 조립 객체에서 만든다. 화면은 이 필드로 숫자를 다시 만들거나 따로 그리지 않는다(원문 상자 그대로 · 설계 §5).
- 실패 응답 · 이전 응답에는 없다. 세션 저장 필드로 넣지 않는다. 화면 TS 타입도 바꾸지 않는다.

## 6. 질문 — 설계와 실제 코드가 부딪히는 곳

**Q1. 관계식의 '종가' 값 표시**
- 현재 미리보기에는 D 저장 종가가 어디에도 없다. NAV 줄의 '시장가'는 NAV 수집 값이고 반올림 정수라 같은 값이 아니다. 그래서 `MA20 > MA60 > 종가` 를 사용자 · AI 가 검산할 수 없다.
- (a) 관계식 줄 끝에 `(종가 16,775.00원)` 을 붙인다 **(권장 · 목업)**
- (b) 설계 줄 형식 그대로 두고 종가 값은 적지 않는다

**Q2. 계산 기간을 어디에 보이나**
- 설계 §2-3 은 '설명/펼침에서 확인'이고, §2-1 은 새 접힘 버튼 금지 · 자세한 설명은 기존 `?` 이다. 그런데 현재 `?` 는 카드 머리 하나의 고정 문단이라 요청마다 다른 시작일을 담을 수 없다. 미리보기 본문은 원문 그대로의 글 상자라 항목별 펼침도 없다.
- §3-2 '시작일→D · 저장 종가 수를 남긴다'를 지키려면 날짜가 원문에 있어야 한다.
- (a) 원문에 `이동평균 계산 구간:` 한 줄(기존 변화율 줄의 '(시작 → 끝)'과 같은 방식)을 두고, `?` 에는 정의만 둔다 **(권장 · 목업)**
- (b) 날짜를 원문에 넣지 않고 `?` 에 정의만 둔다(실제 시작일은 보이지 않음)

**Q3. 검토 질문의 위치('원문 끝')**
- 화면은 원문을 빈 줄 기준으로 나눠 상자로 그린다. 새 묶음은 상자 하나가 더 생기고, 그 첫 줄이 제목이 된다.
- (a) 끝에 `[검토 질문]` 묶음을 새로 둔다. 제목은 설계 §0 표의 용어다. 1440px 2열 격자에서 상자가 10개로 짝이 맞는다 **(권장 · 주 목업)**
- (b) 마지막 `[AI에게 요청]` 묶음 끝에 질문 3줄을 잇는다. 새 상자 · 새 제목이 없다(목업 1장)
- 어느 쪽이든 기존 미리보기 시험의 묶음 수 · 제목 기대는 그에 맞춰 바꾼다.

질문 밖 결정(설계 문장대로 적용 · 판정에서 다르면 고침)
- 보유는 기존처럼 기준일 불일치면 계산하지 않는다. 후보는 자기 D 를 쓴다(§4 기존 22 · 23 판정 보존).
- 부분 관계식을 만들지 않는다(§3-2 '모두 유효할 때만').
- 개별 종목은 '대상 아님' 한 줄을 남긴다(기존 '구성종목 겹침 · NAV 괴리율: 대상 아님(개별 종목)'과 같은 방식).

## 7. 판정 반영(2026-10-23 · PASS)

- Q1 · Q2 · Q3 = (a) — 확인한 주 목업의 줄 · 배치 그대로(종가 괄호 · 계산 구간 줄 · 끝 [검토 질문] 묶음 = 기존 9개 + 1 = 10개).
- **같은 D 의 가격 근거 대조(판정 §3-1)** — 날짜가 같다는 것만으로 같은 근거라고 보지 않는다. 이미 읽은 값만 쓴다(새 조회 · 트랜잭션 개편 없음).
  - 보유: 보유 근거 응답에는 원시 종가가 없다. 그래서 같은 읽기에서 나온 5 · 20저장일 시작일 · 5 · 10 · 20저장일 변화율을 새 60행에서 같은 규칙(`close IS NOT NULL AND close > 0` 행 · `_window_return_pct`)으로 다시 구해 같은지 본다. 원시 종가 직접 비교가 아닌 재계산 대조이며, 검사 사이 행 · 같은 배율 변경은 못 잡을 수 있다(RESULT 판정 §3 정정).
  - 후보: 미리보기 읽기 행(최근 21개 · 날짜 · 종가 · 출처) 전부 + 목록 응답의 5 · 10 · 20 시작일 · 변화율을 대조한다. 수신 시각 · NAV 시장가 · 평단은 비교하지 않는다.
  - 다르면 관측 전체를 `확인 불가 — 같은 기준일(D)의 가격 근거가 앞서 읽은 값과 다릅니다(읽는 사이 저장 자료가 바뀌었을 수 있음)` 로 둔다. 대조한 항목은 응답 선택 필드 `basis_checked` 에 남는다.
  - 60행 안에 거른 행이 40개 이상이라 비교 대상이 60행 밖이면 그 항목은 대조하지 않는다. 미리보기 전체가 하나의 스냅샷이라는 보장은 범위 밖이다.
- **날짜 검사(§3-2)** — 창마다 '행 부족 → 날짜 형식(실제 파싱 · 'YYYY-MM-DD' 그대로) → 날짜 중복 → 종가 · 출처 → 창 안 연결' 순서로 본다.
  - 해석할 수 없는 날짜 · 중복 행을 빼고 개수를 채우지 않는다. 사유는 `날짜 확인 필요` · `날짜 중복` 이다.
  - 창 첫 행으로 들어오는 연결(행 i 의 change = i-1 → i)은 그 창의 검사 대상이 아니다.
- **ETF 구분(§3-3)** — 보유는 `etf_master` 목록이 비었으면 개별 종목이 아니라 `확인 불가 — ETF 구분 자료를 확인하지 못했습니다(개별 종목으로 보지 않음)` 이다. 목록 읽기 실패는 기존 오류 계약(미리보기 실패)을 따른다. 후보는 기존대로 ETF 다.
- 도움말 `?` 의 '종목 이동평균' 문단에는 목업 문장에 날짜 문제 · 앞서 읽은 값과 다를 때 · NAVER_FDR 부분 검사 한계를 짧게 더했다(판정 Q2 '정의와 한계').
