## 3. 저장 형식과 검증(AC1)

- 경로 = `holdings.HOLDINGS_DIR / "capital_context.json"`(호출 때 해석 → 시험 자동 격리). 쓰기 = 같은 폴더 임시 파일 · fsync · os.replace(보유 저장과 같은 방식 · 별도 잠금).
- 형식: `{schema_version: 1, cash_krw: 정수|null, limit_krw: 정수|null, confirmed_on: "YYYY-MM-DD"|null, saved_at: KST 시각}`.
- 읽기 상태: 파일 없음 · 세 칸 모두 null = **미입력** / 값 있음 = **입력됨** / JSON · 형식 · 검증 실패 = **읽기 실패**(0원으로 바꾸지 않음 · 손상 파일 위에 쓰지 않음 — 보유 저장과 같은 정책).
- 저장 검증(하나라도 어기면 422 · 파일 그대로): 금액 = JSON 정수(불 · 소수 · 문자열 · 음수 · 비유한 거부) · 0 이상 · 2^53 − 1 이하(화면 숫자 정밀도) / 한도는 현금이 있을 때만 · 0 ≤ 한도 ≤ 현금 / 현금이 있으면 확인일 필수 · 유효한 날짜 · 오늘(KST) 이하 / 현금 · 한도 모두 비면 확인일도 비어야 함.
- [비우기] = 세 칸 null 로 저장(파일 삭제 아님) → 미입력. 일부만 저장되는 상태 없음(한 문서 원자 교체).

## 4. 계산 · 표시 규칙(AC2 · AC3 · 설계 §3)

`/holdings/enriched` 의 기존 행 계산 결과를 그대로 받아 아래만 더한다(기존 `market_weight_pct` · `buy_weight_pct` · 손익 불변).

| 값 | 규칙 |
|---|---|
| 보유 평가액 V · 범위 | 평가 계산된 행의 평가금액 합 · `계산 행 수 / 전체 행 수` · 가격 기준일 = 그 행들 `price_asof` 날짜의 최소 ~ 최대 |
| 완전 여부 | 전체 행이 평가 계산됨(보유 0 행 포함) |
| 합계 T | 완전 · 현금 입력이면 V + C(**0원도 알려진 합계로 표시** · null · 미입력으로 바꾸지 않음) · 아니면 null + 사유(현금 미입력 · 부분 평가 · 읽기 실패) |
| 보유 / 현금 구성 | T > 0 일 때만 V/T · C/T(보유 0 · C > 0 이면 0% · 100%) · T = 0 이면 '계산 불가'(합계 0원은 그대로 표시) |
| 행 입력 현금 포함 비중 | T > 0 일 때만 그 행 평가금액 / T(계좌 행 단위 · 화면) |
| 선택 종목 두 비중(AI) | 같은 종목 모든 계좌 합산(기존 `_aggregate_enriched_by_ticker`) · 보유 내 = 기존 값 · 입력 현금 포함 = 종목 합산 평가금액 / T · 종목 행 하나라도 미평가면 둘 다 '미확인'(기존 규칙) |
| 기준일 | 가격 기준일 = 평가 행 날짜의 최소 ~ 최대(여러 날이면 범위 표시) · **모든 평가 행 날짜가 현금 확인일과 같을 때만 '같은 기준일'**(범위 안에 확인일이 있어도 같다고 보지 않음) · 그 밖 = '기준일이 다른 참고 합계 · 비중' · 날짜를 못 읽은 평가 행이 있으면 '가격 기준일 확인 불가' · 보유 없음 = '대상 없음' |
| 한도 | 합계에 더하지 않음 · 현금만 있고 한도 없음 = '미정'(현금 전액을 한도로 보지 않음) |

반올림은 기존 비중과 같이 소수 둘째 자리. 설계 AC2 예(보유 60만 · 현금 40만 · 행 12만 · 한도 10만)는 보유 내 20.00% · 입력 현금 포함 12.00% · 현금 40.00% · T 100만으로 시험에 고정한다.

[AI에게 요청]에 한 줄: '현금 보유를 추가 매수 승인으로 해석하지 말고, [보유 · 자금 기준]의 추가 투입 한도 · 확인일 · 포함 범위를 전제로 검토해 주세요(한도가 미정 · 미입력이면 그 상태 그대로).'

미리보기 · [복사] · [AI 세션에서 검토]는 지금처럼 같은 `preview_text` 하나다. 생성 때 저장값이 글에 들어가 고정되고, 세션은 기존 원문 저장 경로 그대로라 나중에 값을 고쳐도 옛 글 · 세션은 바뀌지 않는다(AC6 · 새 세션 칸 0). 화면의 미저장 편집값은 서버 저장값만 읽는 미리보기에 들어갈 수 없다(AC5).

## 6. 시험 · 검수

- 백엔드: 저장 · 복원(미입력 · 0원 · 양수 · 수정 · 비우기) · 거부 조합 표(한도 > 현금 · 음수 · 소수 · 불 · 문자열 · 현금 없이 한도 · 현금 있는데 확인일 없음 · 미래 날짜 · 현금 없는데 확인일) · 손상 파일 = 읽기 실패 · 덮어쓰기 거부 · AC2 숫자 · 다계좌 행 / 종목 합산 · 부분 평가 · C 미입력 · C=0 · T=0 · 보유 없음 · 기준일 차이 · 자금 읽기 실패 때 `/holdings/enriched` 200 · 미리보기 묶음 글(보유 · 후보 · 미입력 · 읽기 실패) · 기존 금지 표현 · 응답 칸 시험 유지 · 묶음 순서 두 시험 갱신. 모든 금액은 가상 · tmp 파일.
- 프런트: 패널 상태별 글 · 저장 실패 때 입력 유지 · 미저장 값 미사용 · 행 둘째 줄 표시 조건(vitest).
- 형식 · 회귀: black · flake8 · py_compile · 관련 pytest → 전체 pytest 1회(백그라운드) · `npx tsc --noEmit` · `npm run lint` · `npx vitest run`.
- **build(AC8)**: 켜 둔 dev 서버의 `.next` 를 건드리지 않게, 저장소 밖 임시 사본(`frontend` 소스 복사 · `node_modules` 연결)에서 `next build` 한다. dev 서버는 내리지 않는다.
- 실화면(AC4): 사용자가 실제 「보유 현황」에서 직접 입력 · 수정해 두 비중의 뜻을 확인한다. 개발자는 실제 금액을 입력 · 기록 · 보고하지 않는다.

## 7. 설계자 확인 결과(PLAN 판정 2026-11-06 · 확정)

Q1 · Q2 · Q3 모두 (a) 확정(판정 A-2). 아래 제출 때 질문과 선택지는 이력으로 남긴다.


**Q1 — 미리보기 · AI 원문의 금액(POC5-23 §52 와 충돌).** 지금 원문에는 금액이 하나도 없고, POC5-23 은 '보유 비중 · 손익 표시 정책 유지 · 거래 금액 추가 안 함' 이다. POC6-24 §4 는 보유 평가액 · 현금 · 한도 · 합계 금액을 원문에 넣으라고 한다. 원문은 [복사]로 바깥 AI 서비스에 붙여질 수 있다.
- (a) **확정**: 설계대로 V · C · A · T 금액을 [보유 · 자금 기준]에만 넣는다(수량 · 평단 · 계좌 이름 · 거래 금액은 계속 넣지 않음) · 도움말에 '복사하면 금액이 함께 나감' 을 적는다.
- (b) 원문에는 비율 · 상태 · 기준일만 넣고 금액은 화면에만 둔다.

**Q2 — [대상] 줄의 기존 '평가비중'.** 새 묶음에 '보유 내 평가비중'을 분모 설명과 함께 적으면 같은 값이 두 번 나온다.
- (a) **확정**: [대상]은 '손익률 Y% · 비중은 [보유 · 자금 기준]에 적음' 으로 바꾸고, 비중은 새 묶음에만 둔다.
- (b) [대상] 줄을 그대로 두고 새 묶음에도 적는다.

**Q3 — 후보로 고른 종목을 이미 보유 중일 때.**
- (a) **확정**: '이 종목: 후보 · 현재 보유 중' 으로 구분하고 두 비중을 보유 규칙(종목 합산)대로 적는다 · 보유가 아니면 '보유 비중 없음'.
- (b) 후보는 보유 여부와 관계없이 비중을 적지 않는다.

그 밖의 세부(손상 파일은 덮어쓰지 않고 '확인 불가' 로 둠 · 금액 상한 2^53 − 1 · 비우기 = null 저장 · build 는 임시 사본)는 같은 계약 안의 구현 결정으로 정했다.
