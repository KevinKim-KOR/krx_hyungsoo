1. 「후보리스트」 [이 목록을 ETF 구성종목에서 보기]는 고른 쪽(상위 또는 하위) 30개 전체와 범위 문장을 넘긴다(`frontend/app/components/workbench/ListTransfer.tsx :: goExposure` · 기준일 = 목록 끝일).

  - **대조 1** = 보관 응답의 상위 30 요약 그대로(묶음 · 개요 · 공통 구성종목)
  - **대조 2** = 같은 30행 · 같은 분류 + 사본의 구성 자료를 기존 함수(`_read_constituents` · `build_groups` · `side_overview` · `common_constituents`)로 다시 계산한다. 공통 구성종목에 주식 외 행이 있으면 따로 표시한다(판정 Q5 · 운영 코드 수정 없음).
  - **대조 3** = 대조 2와 같은 구성 자료 · 주식 행만 → 서로 다른 확인 계열 2개 이상에 든 주식. 주식마다 계열 · 대표 ETF · 실제 비중 · 원천 기준일을 붙인다. 대조 2의 공통 구성종목에 이미 나온 주식은 '이미 보임'으로 구분하고, 새로 생긴 것만 추가 근거로 센다(판정 §3-1).
  - **사업군 ETF 편입 근거(판정 Q3)**: 사본에 구성 자료가 있는 모든 ETF 중 기존 사전으로 사업군이 분류되는 ETF의 원본 1 ~ 10행에 그 주식이 있으면 근거 ETF · 사업군 · 구성 기준일을 붙인다. 여러 사업군이면 모두 적는다. 업종 해석은 모두 '가설'로 표시한다(주식 자체의 업종 자료 없음 · 단독 근거로 쓰지 않음). 공개 대조표 적용 기준(검토 §2-1): 근거 ETF 이름은 표본(공개 순위 30개) 안의 것만 쓰고, 표본 밖은 사업군 · 개수 · 구성 기준일만 적는다. 이름 · 코드 · 개별 근거는 git 제외 실행 폴더 `report.json` 에 둔다.
  - **확인 범위**: ETF별 상태(새로 받음 · 기존 캐시 · 수집 실패(자료 없음 / 예전 자료) · 미확보(시간 초과로 부르지 않음 / 부르지 않음) · 확인 불가 — 공급자를 부르지 않은 것은 수집 실패로 쓰지 않는다(검증자 r1 F2)) · 원천 기준일 · 조회 시각 · 읽은 행 · 주식 행 · 주식 외 · 종류 미확인 · 원본 비중 합 · 주식 비중 합. 원천 기준일이 순위 끝날(11/13)과 같으면 '11/13 기준 구성', 끝날보다 뒤면 '현재 편입 참고'로 적는다(검토 §2-2 · 판정 §3-2 '11/13 이후' = 끝날보다 뒤). 순위 기간 중 편입 변화 · 수익 기여를 확인하려면 그 기간의 보유 내역과 수익률 자료가 필요하다.
- **S5 · Q5 재현**: 사본 DB 로 운영 요약(`build_summary` · 1개월 · 3개월 · 기본 제외 · 보유 정보 없이)을 만들어 공통 구성종목에 주식 외 행이 실제로 나오는지 기록한다. 운영 코드는 고치지 않는다. 요약을 만들지 못했거나(`status` ≠ ok) 구성 자료가 2개 이상인 묶음이 없으면 '0건'이 아니라 '비교 못 함'으로 적는다(검증자 r1 F4 · 대조 1 · 2 · 3 의 '없음 · 0건'도 같은 규칙).
- **S6 · 대조표 한 장**: `docs/ai_result/POC6/POC6_30_SECTOR_SUMMARY_CONSTITUENTS_COMPARISON.html`
  - 맨 위 = 읽을 수 있는 사례(검토 §1): 서로 다른 계열 ETF 가 비중 1 · 2위 주식을 똑같이 담은 묶음 · 두 종목 합산 비중(ETF별 범위). 같은 실행 자료에서 규칙으로 고른다(ETF 수 → 합산의 가장 작은 값 → 주식 키 순 · 결과서 §6).
