## 0. 요약

- **본 사례 원문(판정 Q1 (b)):** 맥북 기록 DB 에 「주간 ETF 점검」 기록이 0건이다(POC6-32 의 11/18 사례는 격리 사본과 함께 삭제됨). 그래서 현재 「주간 ETF 점검」 복사문 한 건을 본 사례로 쓴다.
  - 같은 조회 응답의 선택 정보 · 기준일 · 근거 번호 · 원문을 맥북 연구 폴더에 보관한다.
  - 같은 건에 이미 받은 AI 답이 있으면 작성자와 함께 넣는다. 없으면 AI 의견 줄을 생략하고 '긴 AI 답 대조의 효용은 미측정'으로 적는다.
- **실행 방식:** 맥북에서 실행 묶음(zip)을 만들면, 형수님이 USB 로 Windows PC 에 옮겨 `.bat` 를 한 번 실행한다(판정 Q5).
  - `.bat` 는 환경 확인 → 합성 입력 점검 → 실제 요약 순서로 돈다. 모델은 `qwen3.5:9b-q4_K_M` 하나다(판정 Q3).
  - Ollama · 모델이 Windows PC 에 없을 때만 형수님께 설치 승인을 받는다(U1).
- **비교 방식:** 같은 복사문 · 같은 선택 정보로 '로컬 한 장 먼저'(L) → '평소 방식'(U)을 한 번씩 한다(판정 Q2).
  - 끝나는 조건은 같은 세 질문에 답할 수 있을 때다.
  - 형수님 직접 시간 · 개발자 반복 작업 시간 · 총 사람 시간 · 전체 경과 · 다시 열기 · 사실 수정과 그 내용 · 세 답 정확도를 한 표에 적는다.
  - 채점용 메모는 모델 실행 전에 잠근다(§3).

### 1-2. 본 사례 만드는 법(판정 Q1 (b))

1. 형수님이 「주간 ETF 점검」에서 후보 하나를 고른다. 갱신 뒤에 골라도 되고, 이미 표시된 자료에서 골라도 된다.
2. 개발자가 `archive` 로 같은 서버 조회(`GET /weekly/etf-check?selected=<고른 ETF>`)의 응답을 받아 맥북 연구 폴더에 한 번만 쓴다. 저장하는 것은 다음과 같다.
   - 복사문(`copy_text`) · 선택 정보(코드 · 이름 · 순위) · 목록 조건 · 끝 날짜 · 근거 번호 목록 · `[자료 상태]` 줄 · 응답 생성 시각 · 응답 원본 · 해시
3. 같은 건에 이미 받은 AI 답이 있으면, 형수님이 주신 답 원문 파일을 작성자 이름과 함께 같은 보관에 넣는다. 없으면 AI 의견 줄을 생략한다.
   - 새 웹 AI 답, 빈 메모의 운영 기록, 「AI 투자 세션」 저장은 요구하지 않는다(판정 Q1).
4. 보관한 뒤에는 평소처럼 자료를 갱신해도 된다. 두 방식 모두 보관한 같은 복사문 · 선택 정보를 쓴다(판정 §3).
5. 로컬 입력에는 보관한 복사문과 AI 답 원문만 작성자 이름을 붙여 넣는다.

### 1-3. 채점용 메모(모델 실행 전 잠금)

- 개발자가 원문에서 아래 다섯 묶음을 적는다.
  - ① 자료마다 기준일과 늦음 표시(복사문 `[자료 상태]` 그대로): 시장 판정(아침 · 당일) · 코스피 · 수급 · 원/달러 · 목록 기간 · 고른 ETF 기간
  - ② 필수 사실: 고른 ETF 의 기간별 방향과 % · 같은 기간 KODEX 200 대비 %p(오름 · 덜 내림 · 더 내림의 구별) · 보유 겹침 확인 범위
  - ③ 자료 공백: 늦은 자료 · 확인 불가 칸 · '기간 다름'
  - ④ AI 답끼리 같은 점 · 갈린 점: 고른 ETF 와 시장에 대한 상태 · 이유 · 다음 확인(가장 중요한 갈린 점 하나 표시)
  - ⑤ AI 별 최신 확인 상태: 같음 · 새 값 있음 · 확인 불가와, 값 · 기준일 · 출처 · 확인 시각 칸이 다 있는지
- 묶음마다 '필수' 항목을 표시한다. 그런 다음 원문과 대조하는 독립 검토를 1회 하고, 해시와 시각을 맥북 잠금 파일에 남긴다.
- 잠금 뒤에는 메모를 고치지 않는다. 출력을 보고 정답을 바꾸지 않기 위해서다.

## 2. 모델 하나의 Windows 실행 가능성과 주고받는 방법(설계 §5 ②)

### 2-1. Windows PC 실측 기록(POC6-02 · 2026-10-21 · 결과서 §8-7)

- Windows 11(10.0.26200) · Python 3.13.12 · torch 2.6.0+cu124 · NVIDIA GeForce RTX 4070 SUPER(VRAM 12,878,086,144B)
- 로컬 언어모델 실행 도구의 설치 여부는 기록이 없어 **미확인**이다.
- 그때 설계자 제약(POC6-02 PLAN 판정 §3)은 다음과 같았다.
  - 'PC에 전체 저장소·시장 DB·보유 파일·scikit-learn·Next/백엔드 서버·키움/API 키를 요구하지 않는다.'
  - '환경이 없으면 필요한 GPU 연구 환경 설치 범위만 한 번 제시한다. 자동 전체 설치·프로젝트 의존성 교체·새 VM/원격 서비스 구축으로 확대하지 않는다.'
- 이 제약 아래에서 승인된 것은 GPU 학습용 파이썬 환경뿐이다. 항상 켜져 있는 Ollama 는 범위 밖이므로 새로 승인받는다(U1).

### 2-2. 실행 도구 · 모델 · 설정(판정 Q3)

| 후보(Ollama 공식 목록 · 2026-11-22 확인) | 파일 | 문맥 길이 | 라이선스 | 판단 |
|---|---|---|---|---|
| **`qwen3.5:9b-q4_K_M`**(채택 · 판정 Q3) | 6.6GB | 256K | Apache 2.0(공식 모델 카드) | 12GB 에 들어갈 것으로 예상(시험 실행에서 확인) · 생각 모드 · 201개 언어(카드) · 그림 입력용 부분 포함 |
| `gemma4:12b` | 7.7 ~ 8.0GB | 256K | 이번에 확인 못 함 | 채택하지 않음(모델 교체는 별도 결정) |
| `exaone3.5:7.8b` | 4.8GB | 32K | 목록에 표기 없음 · 확인 못 함 | 한국어 · 영어 두 언어 모델이지만 1년 전 판이고, 문맥 32K 가 보조 사례(약 3.2만 자)에 빠듯함 |

- **실행 도구:** Ollama Windows 판이다. NVIDIA GPU 를 스스로 쓰고, 맥북 · Windows PC 어느 쪽에도 새 파이썬 라이브러리가 필요 없다. 실행기는 표준 라이브러리만 쓰고, Windows PC 안의 `localhost` API 를 부른다.
- **설정(판정 Q3 · 합성 시험의 시작 설정 · 본 실행 전에 고정):**
  - 생각 모드를 켠다. 목적이 숫자 · 날짜 대조의 정확성이라서다. 생각 글은 로컬 기록에만 둔다.
  - 표본 설정은 모델 카드의 생각 모드 권장값(temperature 1.0 · top_p 0.95 · top_k 20 · presence_penalty 1.5)에 seed 를 고정한다. 0 고정(가장 높은 확률만)으로 바꾸지 않는 것은 카드가 권한 값에서 벗어나지 않으려는 것이다.
  - `num_ctx` 49,152 · `num_predict` 24,576 으로 시작한다. 장비의 필수 조건이 아닌 시험 제안값이다. 실제 입력과 한 장을 끝까지 쓸 여유가 있는 범위에서, 같은 모델로 합성 시험의 길이 설정만 조정할 수 있다(판정 Q3). 모델 교체 · 추가 다운로드는 별도 결정이다.
- **판 고정:** 태그를 `qwen3.5:9b-q4_K_M` 로 정한다. 결과 기록에 Ollama 버전과 모델 digest 를 남긴다.
- **합성 점검(본 사례 전 · 같은 `.bat` 안에서 먼저):** 실제 값이 없는 합성 복사문 · 합성 답을 같은 형식으로 만든다. 길이는 본 사례 입력 이상이고 2.2만 자보다 짧지 않다. 이 입력으로 다음을 확인한다.
  - 전부 GPU 에 올라갔는지 · VRAM · 한글 출력 · 끝 표지 · 글자당 토큰 수 · `done_reason` · 드라이버 판(551.61 이상)
  - 점검이 통과해야 실제 요약으로 간다. **설정 문제**(문맥 · 출력 길이 · 메모리)면 멈추고, 맥북에서 길이 설정만 고친 새 묶음을 다시 보낸다.
  - **모델 문제**(한글이 깨짐 등)면 본 실행으로 가지 않고 멈춘 뒤 설계자에게 보고한다(모델 교체는 별도 결정 · 판정 Q3).
  - 실제 요약 전에 그 입력의 토큰만 세는 호출을 늘 1회 한다(출력 1토큰 · 버림 · 끝나면 모델을 내려 본 호출이 캐시 없이 처음부터 읽게 함). 이 값과 본 호출의 `prompt_eval_count` 를 대조한다(§2-4).
- **본 실행:** 본 사례 출력을 본 뒤에는 모델 · 지시문 · 설정을 바꾸지 않는다. 다시 실행은 실행 실패(아래 세 종류)를 고친 경우에만 하고, 사유와 앞 실행을 보존한다.

### 2-3. 설치 · 용량(U1 · 필요할 때 한 번 확인 · 판정 §4)

- 먼저 묶음의 환경 확인으로 Windows PC 에 쓸 수 있는 Ollama 와 지정 모델이 이미 있는지 본다. 없을 때만 공식 Windows 판 설치와 지정 모델 1개 수신을 형수님께 요청한다. 묶음은 스스로 설치 · 수신하지 않는다.
- 아래 용량은 디스크 규모다. GPU 메모리에 다 올라가는지는 실측한다. 드라이버 변경이 실제로 필요하면 그때 따로 여쭙는다.

- **Ollama Windows 설치 1회:** 공식 문서상 바이너리 설치에 최소 4GB 가 필요하다. 관리자 권한은 필요 없다. 설치 뒤에는 백그라운드에서 계속 실행된다. 모델은 `%HOMEPATH%\.ollama`, 기록은 `%LOCALAPPDATA%\Ollama` 에 둔다.
- **모델 파일 1개 수신 1회:** `qwen3.5:9b-q4_K_M` 은 6.6GB 다. 설치와 합쳐 디스크가 **최소 약 11GB** 필요하다.
- **NVIDIA 드라이버:** 551.61 이상이어야 한다. 시험 실행에서 확인하고, 낮으면 업데이트 여부를 다시 여쭙는다.
- 저장소 · 시장 DB · 보유 파일 · 키는 Windows PC 에 두지 않는다. 인터넷은 모델 수신 때만 쓰고, 실행 중에는 쓰지 않는다.

## 3. 형수님이 받을 한 장 예시와 비교 측정 방법(설계 §5 ③)

### 3-1. 한 장 예시(모양 예시)

ETF 이름 · 코드는 가렸다. ETF 의 1개월 값과 AI 의견은 지어낸 예다. 시장 줄과 KODEX 200 값은 지금 맥북 복사문의 공개 시장 값이다.

```text
주간 ETF 검토 한 장 · 검토 기준일 11/18(목록 10/19 → 11/18) · 선택한 ETF: ETF ○○(코드 가림) · 1개월 상위 30 중 1위

시장       당일 시장 판정은 KODEX 200 '하락장 · 29거래일째'(11/18 가격)이고, 아침 판정은 11/20 마감 가격이 없어 미확인이다.
           코스피(4,968.48)와 외국인 수급 · 원/달러는 11/17 까지만 있어 기대일(11/20)보다 3거래일 늦다. 〔근거 1 · 2 · 3 · 8 · 자료 상태〕
선택한 ETF  1개월(10/19 → 11/18) +8.5% 올랐고, 같은 기간 KODEX 200(−11.58%)보다 +20.08%p 높다(3개월은 시작일이 달라 '기간 다름').
           내 보유와의 겹침은 구성 일부만 확인했다(확인 범위 예: 비중 67%). 〔근거 17 · 24 · 25〕
AI 의견    상태는 GPT '추가 확인' · Claude '근거 확인'으로 다르다. 외국인 수급은 GPT 는 방향(순매도 지속), Claude 는 속도
           (하루 평균 매도 축소)를 설명했고 서로 어긋나지 않는다. 〔GPT 상태 · 이유 · Claude 상태 · 이유〕
최신 자료와  Claude 는 11/18 코스피 종가를 값 · 기준일 · 출처 · 확인 시각과 함께 확인했다고 적었고(Claude 의 보고 · 저장값 11/17 과 다름),
다음 확인   GPT 는 확인 불가라 저장 자료(코스피 11/17)가 기준이다. 다음 확인 한 가지: 11/18 이후 외국인 수급. 〔Claude 최신 확인 항목 · GPT 최신 확인〕

로컬 AI(qwen3.5:9b-q4_K_M · digest 앞 12자리) · 위 원문만 읽고 쓴 요약 · 투자 권유 아님 · 생성 시각
```

- 첫 줄(기준일 · 선택한 ETF · 순위)과 마지막 줄은 기록에서 그대로 가져온다. 모델이 만들지 않는다. 네 칸만 모델이 쓴다.

### 3-2. 지시문 핵심(판 번호와 해시로 고정 · 전문은 구현 때 코드에)

1. 아래 원문(복사문 · AI 답)만 읽는다. 인터넷을 볼 수 없고, 원문에 없는 값 · 날짜 · 사실을 만들지 않는다.
2. 네 칸(시장 · 선택한 ETF · AI 의견 · 최신 자료와 다음 확인)을 이 순서로 쓴다. 칸마다 한두 문장이다.
3. 수치 · 판단마다 `[근거 n]` 을 붙인다. 번호가 없으면 원문 항목명과 기준일을 쓴다. AI 답은 작성자와 칸을 쓴다(예: GPT 이유).
4. **시장 칸:** 시장 판정 · 코스피 · 수급의 기준일을 각자 쓴다. `[자료 상태]` 의 늦은 자료와 확인 불가 칸 가운데 이번 검토에 영향을 주는 것을 쓴다.
5. **선택한 ETF 칸:** 원문 기간에 실제로 올랐는지, 시장보다 덜 내렸는지를 구별해 쓴다.
   - `%`(변화율)와 `%p`(차이)를 구별한다.
   - %가 음수이고 %p 가 양수면 '시장보다 덜 내렸다'로 쓴다. 순매도 규모가 줄어든 것을 순매수로 쓰지 않는다.
   - 보유 겹침에는 확인 범위를 붙인다.
6. **AI 의견 칸:** 고른 ETF 와 시장에 대한 의견만 쓴다(답이 다른 ETF 도 다루므로).
   - 답이 둘 이상이면 판단에 영향을 주는 공통점과 차이를 작성자와 함께 쓴다. 상태 선택이 실제로 다르면 상태와 작성자를 적는다.
   - 강조점이 다른 것(예: 한쪽은 방향, 한쪽은 속도)은 이견으로 쓰지 않는다. 서로 상충하는 주장만 이견으로 표시한다(판정 §3). 한쪽만 다룬 항목은 '(GPT 만)'처럼 표시한다.
   - 답이 하나면 그 의견만 쓰고, 없으면 이 칸을 쓰지 않는다.
7. **최신 자료 칸:** '누가 확인했다고 적었는지'로 쓴다.
   - AI 답에 값 · 기준일 · 출처 · 확인 시각이 모두 있으면 확인 주체와 함께 'Claude 가 확인했다고 적음'처럼 그 AI 의 보고로 표시한다. 그 값은 저장값과 구별해 쓴다.
   - 하나라도 빠졌거나 링크만 있으면 '최신 공개 자료 확인 불가'와 저장 자료의 기준일을 쓴다. 확인 시각은 답에 적힌 값만 쓴다.
   - 더 확인할 것은 가장 중요한 한 가지만 쓴다.
8. 매수 · 매도 · 보유 같은 매매 결론이나 추천, 'AI 들이 동의' 같은 합의 단정을 쓰지 않는다(KS-4).
9. 마지막 줄에 입력 맨 앞 · 맨 뒤 표지 두 개를 그대로 적는다.

### 3-3. 비교 측정(판정 Q2 · Q4 · §3)

- **두 방식(같은 복사문 · 같은 선택 정보 · 같은 맥북):**
  - **로컬 방식(L · 먼저):** 한 장을 먼저 읽고, 필요할 때만 보관한 원문(복사문 · AI 답)을 연다.
  - **평소 방식(U · 다음):** 보관한 같은 복사문(과 AI 답)을 평소처럼 읽는다. 화면의 지금 자료가 아니라 보관한 원문이다.
  - 두 번째로 읽는 U 가 빨라지는 영향은 결과서에 그대로 적는다. 본 사례 한 건이면 결론도 그 한 건으로 한정한다.
- **같은 세 질문(끝나는 조건):**
  - ① 이 후보는 원문 기간에 실제로 올랐나, 덜 내렸나(시장 대비 포함)?
  - ② 근거의 한계(늦은 자료 · 빈칸 · 확인 범위)는?
  - ③ 다음에 무엇을 확인할까?
  - 형수님이 세 답을 제출하면 끝낸다. 개발자는 답을 채점용 메모와 대조해 질문마다 맞음 · 부분 · 틀림을 적는다. 다음 확인은 원문이 뒷받침하면 메모와 다른 항목도 맞음으로 본다(판정 Q4).
- **시간(같은 원문이 준비된 상태에서 각 방식의 첫 조작부터 세 답 제출까지 · 판정 §3):**
  - **형수님 직접 시간:** 형수님이 손과 눈을 쓴 시간이다.
    - L: USB 로 옮기기 · `.bat` 실행 · 결과 옮기기 · 한 장 읽기 · 원문 확인 · 답하기
    - U: 원문 읽기 · 답하기
    - 모델을 기다리는 동안은 스톱워치를 멈춘다.
  - **개발자 반복 작업 시간:** 매회 해야 하는 포장(`pack`) · 회수(`merge`) 시간이다. 명령 기록의 시작 · 끝 시각으로 잰다. 일회성 개발 · 설치는 넣지 않는다.
  - **총 사람 시간:** 형수님 직접 시간 + 개발자 반복 작업 시간이다.
  - **전체 경과:** 첫 조작부터 세 답 제출까지의 벽시계 시간이다. 모델 대기를 포함하고, 실행기 기록과 대조한다. 일회성 설치 시간은 별도다.
- **다시 열기(두 방식 같은 정의):** 이미 읽은 원문 부분(복사문 근거 · AI 답)으로 되돌아간 횟수다. L 에서는 한 장에서 원문을 연 횟수도 여기에 넣는다.
- **사실 수정(두 방식 같은 정의):** 형수님이 처음 이해한 값 · 날짜 · 방향 · 대상을 나중에 고친 횟수와 그 내용이다.
  - U: 원문의 값을 잘못 읽었다가 고친 것
  - L: 한 장이 틀렸거나 한 장을 잘못 읽었다가 고친 것
- **다시 쓰겠는가:** 마지막에 예 · 아니오 · 모르겠음 + 한 줄로 묻는다.
- **기록지:** 형수님은 휴대폰 스톱워치와 종이 한 장(칸: 방식 · 시작 · 끝 · 멈춘 시간 · 다시 열기 · 고친 것 · 세 답 · 다시 쓰겠는가)만 쓴다. 정리와 원문 대조는 개발자가 한다.
- **한 장을 미리 고치지 않는다:** 형수님은 모델의 최초 출력을 그대로 읽는다. 채점 결과와 고친 최종본은 비교가 끝난 뒤 함께 보여 드린다.
- **형수님께 드릴 비교표(한 표):** 모르는 값은 추정하지 않고 '미측정'으로 쓴다.

### 3-4. 채점(AC2 · 최초 출력)

| 종류 | 예 | 기준(설계 AC2 와 같이 '판단을 바꾸는 것'만) |

### 3-5. AC4 판정(설계 §4 · 판정 Q4 · §3)

- **판정 불가는 그 항목에만:** 주간 원문 · 실행 · 사용 실측 가운데 빠진 항목만 '판정 불가'다. 출력이 있으면 AC2 판정은 계속한다.
- **품질 미달:** 최초 한 장의 중요한 오류가 1건 이상이면 '품질 미달'이다(사용 실측 유무와 무관).
- **사용 이점 관찰:** 아래가 모두 맞을 때만이다.
  - 최초 한 장의 중요한 오류 0건
  - L 의 세 답에 '틀림' 0건, 각 답이 U 의 같은 답보다 낮지 않음(맞음 > 부분 > 틀림)
  - 형수님 직접 시간 L < U, 총 사람 시간 L < U(둘 다)
  - 사실 수정 L ≤ U
  - 형수님이 '다시 쓰겠음'
- **사용 이점 미확인:** 정확성을 충족한 나머지 경우다. 순서 효과나 실측 부족으로 절감을 가르기 어려운 경우를 포함한다.
- 운영 채택은 별도 결정이다.

## 6. 형수님 확인(판정 §4)

- **U1 · 설치:** 묶음의 환경 확인으로 Windows PC 에 Ollama 와 지정 모델이 이미 있는지 먼저 본다. 없을 때만 공식 Windows 판 설치(최소 4GB · 설치 뒤 백그라운드 실행)와 모델 1개(6.6GB) 수신을 여쭙는다. 이 판정이 설치를 대신 승인하지 않는다.
- **U2 · 전달:** USB 로 정해졌다.
- **U3 · 11/17 기록:** 본 사례 선정에 필요하지 않아 확인하지 않는다.
- **U4 · 읽는 기기:** 맥북으로 정해졌다.
- **고를 후보:** 본 사례로 쓸 후보 하나는 형수님이 「주간 ETF 점검」에서 고른다. 같은 건에 이미 받은 AI 답이 있으면 원문을 함께 주시면 된다.

## 7. 알려진 한계

- **사례 하나:** 순서 효과를 완전히 가를 수 없다. 결론은 그 사례의 관찰값까지만 말한다(설계 §3).
- **Windows PC 환경 미확인:** Ollama 동작 · 디스크 · 드라이버를 아직 보지 못했다. 시험 실행 전까지 실행 가능성은 '근거 있음 · 미확인'이다(공식 목록 크기 6.6GB 와 VRAM 12.88GB 대조).
- **한국어 품질:** 이번에 따로 재지 않았다. 품질은 본 사례의 AC2 로만 판단한다.
- **채점 독립성:** 개발자가 메모를 쓰고 채점도 한다. 이를 보완하려고 잠금 전 독립 검토 1회 · 출력 전 잠금 · 애매한 항목 공개를 둔다.
- **AI 답이 없으면:** AI 의견 줄과 긴 AI 답 대조의 효용은 이번에 재지 못한다(미측정으로 기록).
