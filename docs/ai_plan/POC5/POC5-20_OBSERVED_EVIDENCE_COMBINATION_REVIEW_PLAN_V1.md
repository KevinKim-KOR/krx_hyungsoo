## 2. 재사용 계산과 과거 기준일 적용

종목마다 시장 DB 를 `mode=ro` 로 **한 번의 읽기 트랜잭션** 안에서 읽고(원본 행 `date · close · volume · source · fetched_at · change` · `--end` 이하만), 기준일 t 마다 **t 이하 행만** 잘라 기존 순수 함수에 넣는다. 결과 계산만 t 뒤 행을 쓴다.

| 관측 | 재사용 | t 적용 |
|---|---|---|
| 가격 하락 구간 | `short_term_momentum._window_return_pct(series, 20)` → `classify_decline(normalize_pct(...))`(PC `pc_price_basis._decline_band` 와 같은 식) | 종가 유효 행(`close > 0` · `fetch_recent_price_rows` 와 같은 조건) 중 t 이하 최근 21개. **마지막 행이 t 가 아니면**(t 종가 없음) 계산하지 않음. 21개 미만 = 자료 부족. 구간 = 5~8% · 8~10% · 10% 이상 · 구간 미해당 |
| 거래량 배수 | `stored_volume_evidence.compute_stored_volume_evidence(ticker, rows_desc)` | 같은 종가 유효 행의 t 이하 최근 21개(최신순). 0 · 결측 · 평균 분모 규칙 그대로(`ratio_status` ok 만 계산됨 · volume_missing / avg_insufficient / avg_zero 는 사유) |
| 가격 흔들림 비교 | `pc_price_volatility.compute_price_volatility(rows_asc, last_valid_date=t, reference_date=t)` | 원본 행(거르지 않음)의 t 이하 최근 41개. 41개 종가 · 공유 경계 종가 · 비정상 행 · 가격 기준 경계(POC5-06 `link_break` · `valid_close`) 규칙 그대로. 비교 = `higher` → 커짐, `lower` · `same` → 커지지 않음 |

- **이후 경로**: 캘린더에서 t 다음 20거래일 t+1 … t+20. 각 날짜에 종가 유효 저장 행이 정확히 있어야 한다(없으면 '저장 결측' · 더 먼 날로 채우지 않음). t+20 > `--end` 면 '미도래'. 인접 두 날(t→t+1 … t+19→t+20)에 POC5-16 과 같은 연결 확인(`_link_unconfirmed`)을 적용해 하나라도 확인 불가면 '가격 기준 확인 필요'. 완결이면 `끝점 변화 = C(t+20)/C(t) − 1` · `최저 종가 변화 = min(0, min_h C(t+h)/C(t) − 1)`(%).
- **공통 표본**: 세 관측 계산 + 결과 완결. 가격 구간 표와 네 조합 표는 이 표본 하나만 쓴다. 대상 4,134 에서 공통 표본까지 단계별 제외 사유 · 건수(저장 시작 전 · t 종가 없음 · 하락 구간 자료 부족 · 거래량 사유 3종 · 흔들림 사유 · 미도래 · 저장 결측 · 가격 기준 확인 필요)를 보인다. 한 건은 첫 번째로 걸린 사유 하나로 센다(순서 고정 · 리포트에 적음).
- **표**: 가격 구간 4행(10% 이상 · 8~10% · 5~8% · 구간 미해당) × [전체 · 네 조합(거래량 초과 / 이하 × 흔들림 커짐 / 커지지 않음)]. 각 칸 = 종목×기준일 수 · 서로 다른 종목 수 · 기준일 수 · 두 결과의 중앙값 · 25 / 75 분위수(`ml_score_validity_metrics.percentile` · 선형보간) · 날짜별 중앙값의 중앙값(보조값 · 구분 표시). 빈 칸 = '표본 없음'. 성공률 · 유의확률 · 점수 · 등급 없음.
- **앞 · 뒤 기간 부록**: 입력 범위 거래일(02-19 ~ `--end` · 159일)을 순서대로 반으로(앞 80 · 뒤 79) 나눠 같은 표.
- **결정성**: 같은 입력이면 생성 시각 외 같은 수치. 입력 식별 = `--end` · 대상 종목 목록 · 종목별 사용 행(날짜 · 종가 · 거래량 · 출처 · change) · 캘린더 파일 내용 · 계산 정의 버전의 정렬 해시(POC5-08 `canonical_hash` 방식).

## 4. 질문 (설계자 판단 · 권장은 (a))

### Q1. 거래량 '1배는 평균 이하' 경계에 쓸 값
- 설계 §4 는 흔들림 비교를 'POC5-16 과 같은 소수 둘째 자리 기준'으로 정했고, 거래량은 '1배는 평균 이하'만 정했다. POC5-09 는 배수를 원래 값으로 계산하고 화면에만 소수 둘째 자리로 보인다(1.004 → '1.00배').
- (a) **권장** — 화면 표시값(소수 둘째 자리 반올림)으로 나눈다. 1.00배 이하 = 평균 이하. 흔들림과 같은 '보이는 값' 기준이라, 사용자가 화면에서 본 '1.00배'가 '초과'로 분류되는 일이 없다.
- (b) 원래 계산값으로 나눈다(1.004 = 초과).
