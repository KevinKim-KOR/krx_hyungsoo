## 1. KRX 투자자별 통계 — 지금 쓰는 승인 API 에는 수급 경로가 없다 (설계 §6-1)

| 경로 | 확인 결과 | 근거 |
|---|---|---|
| KRX Open API(승인된 키 `KRX_API_KEY`) | 투자자별 수급 서비스 없음. 프로젝트가 쓰는 서비스 = `etp/etf_bydd_trd` · `idx/kospi_dd_trd` · `sto/stk_bydd_trd` 3개 | 저장소 사용처 · 공개 정리 문서(7분류 31개 API · 주식 = 일별매매정보 + 종목기본정보). **KRX 공식 서비스 목록을 직접 연 결과는 아니다** |
| KRX 정보데이터시스템 웹 통계(`data.krx.co.kr` JSON · `MDCSTAT02202` 일반 · `02203` 상세) | 로그인 없이 **`HTTP 400 LOGOUT`**(세션 쿠키가 있어도) | 2026-09-10 실측 기록(POC3-OPS-02B PLAN §2.3 · 02B-1 RESULT §3.5). 이번에 다시 조회하려던 명령은 자동 권한 검사가 막아 실행하지 않았다 |
| pykrx 1.2.8(설치본) `get_market_trading_value_by_date` | 위 웹 통계를 **KRX 회원 아이디 · 비밀번호 자동 로그인**으로 부른다(`KRX_ID`/`KRX_PW` · 지금 `.env` 에 없음). 요청에 시간 제한이 없고, 실패면 빈 표 · 빈칸은 `0` 으로 바뀐다 | 설치 소스 `pykrx/website/comm/auth.py:175-239` · `webio.py:42,76` · `wrap.py:664,732-733` |

- **결론(판정 §1 표현 정정)**: 현재 사용 중인 승인 API 3개에는 수급 경로가 없고, Open API 전체 목록의 직접 확인은 미완료이며, 회원 웹 조회 경로는 인증 전이다. 지금 알려진 자동 경로는 KRX 회원 로그인뿐이고, 설계 §5 는 자동 로그인을 넣지 않는다고 정했었다(판정 §1 로 본인 계정 정상 조회 한정 예외 · 사용자 승인 전). 빈 수급 칸을 만든 뒤 완료 처리하지 않는다(설계 §6-1) → **Q1**.
- **자동 권한 검사 차단 기록(판정 §1)**: 2026-10-20 KRX 웹 통계 재조회 명령(`curl` 로 `data.krx.co.kr/comm/bldAttendant/getJsonData.cmd` 에 `MDCSTAT02203` 일별 수급을 로그인 없이 POST · 브라우저형 User-Agent · Referer 헤더)은 개발 환경의 자동 권한 검사(Claude Code auto mode classifier)가 실행 전에 거절했다. 거절 사유 원문 = `[Third-Party Attack]`. KRX 서버 응답이 아니며 조회 불가 실측으로 쓰지 않는다. 우회하지 않았다. 계정 승인 뒤의 표본 확인도 이 검사가 허용하는 정상 절차(설치된 pykrx 의 함수 호출)로만 하고, 막히면 그 사유를 그대로 보고하고 멈춘다.
- **원천 정의**(웹 통계 기준 · 대안을 정하면 그 원천으로 다시 고정): 시장 = 유가증권(STK) 주식. 일반 표 = 기관합계 · 기타법인 · 개인 · 외국인합계 · 전체. 상세 표 = 기관 세부(금융투자 · 보험 · 투신 · 사모 · 은행 · 기타금융 · 연기금) · 외국인 · 기타외국인 분리. 기관 합계와 세부를 함께 더하지 않는다.
- **시장 거래대금 분모**: 같은 표의 '전체' 매수 거래대금(= 같은 범위 거래대금)을 쓴다. 매수 + 매도를 거래대금으로 쓰지 않는다. 코스피 지수 API 의 거래대금은 범위가 같은지 확인되지 않아 쓰지 않는다.

## 8. 설계자 판정 반영 (2026-10-20 · 판정 원문 `docs/ai_design/POC5/POC5-28_MARKET_FLOW_FX_AND_OIL_CONTEXT_PLAN_DECISION_2026-10-20.md`)

- **조건부 PASS**. 구현 · DB 변경 · 계정 사용 승인은 아직 아니다. 순서 = 사용자 승인(한 번에) → 작은 읽기 전용 표본 확인 → 목업 → 사용자 목업 확인 → 구현(판정 §5). PLAN 재제출은 자료원 · 권한 · 핵심 계산이 다시 달라질 때만.
- **Q1 (a) 본인 계정 정상 조회 한정**: 사용자가 PC `.env`(git 제외)에 KRX 계정을 직접 넣는다(채팅 · Git · 응답 · 로그 · OCI 에 계정 · 세션 없음). 설치 pykrx 인증 세션 · 조회 함수 재사용 + 원문 빈칸 · 실패를 0 으로 바꾸지 않는 얇은 읽기 adapter. 로그인 · 조회 모두 시간 제한 · 실패면 그 단계만 실패 · 이전 자료 유지 · 무한 재로그인 · 차단 회피 · CAPTCHA 우회 · 브라우저 쿠키 추출 없음. 출처 표기 = 'KRX 웹 통계'. 이용 조건 한 번 확인. 매수 · 매도 · 전체 거래대금 · 기관 합계/세부 중복 없음 · 매수 − 매도 = 순매수 · 날짜 · 단위를 작은 표본으로 대조. 제공 시각 이전 당일 잠정값은 넣지 않음.
- **Q2 (c)**: Yahoo 차트 계열을 좁은 adapter 로 읽어 원시 timestamp 와 공급자 시간대를 보존 · 과거 각 시점의 서머타임 적용(일괄 +1 · 요일 맞추기 보정 없음) · 진행 중 행 · 빈 행 제외 · 한국 15:30 환율로 부르지 않음. FRED 는 대체 · 보정 · 혼합 계열로 쓰지 않음. 근거가 부족하면 그 지점만 보고(FRED 자동 대체 없음).
- **Q3 (a)**: Yahoo CL=F 근월물 선물 · 완료 판단은 선물 계열 · 공급자 일봉 기준(NYSE · VIX 오후 4시 규칙 복사 아님) · 확인 못 하면 보수적 이전 일자 + 실제 기준일 · 지연 표시 · 공식 정산가라고 부르지 않음.
- **§3 수정**: 정정 수치 동결 철회 — 이후 수집은 환율 · WTI 최근 90일 · 수급 최근 20 한국 거래일을 겹쳐 받아 같은 계열의 유효한 원천 정정을 반영(성공 응답의 계열 · 날짜 · 단위 · 분류 · 값을 확인한 뒤 upsert · 수집 시각 기록 · 실패 · 결측으로 덮거나 지우지 않음 · 다른 계열 · 단위 섞임은 실패). 첫 수집 = 연초 + 준비 구간. 기간 요청 우선. 이 표는 최신 확보 자료이며 PIT 데이터셋이 아니다.
- **누적 첫날**: 기준점 0 = 선택 기간 시작 **직전**. 첫 거래일 표시값에 그날 순매수가 들어가고, 마지막 누적값 = 기간 안 모든 날의 합.

- **저장 · 응답 수용**: 같은 시장 DB 표 2개 · `GET /market/flow-context` 1개 · 서버 공통 빌더 문장 재사용. 투자자 거래대금 = 원천 단위를 정확히 바꾼 정수 원. `series_id` 는 공급자 · 가격 의미 · 단위가 고정되게(예: `YAHOO_KRW_X_CLOSE_KRW_PER_USD` · `YAHOO_CL_F_CLOSE_USD_PER_BBL`).
- **시험 기대값 변경**: '기존 값과 다르면 무조건 거절' → 정상 정정 반영 · 잘못된 계열 거절. 추가 = 누적 첫날 포함 · 과거 정정 반영 · DST 전후 날짜 · 진행 중 봉 · 실제 0 과 빈칸 구분.

## 9. 작은 읽기 전용 표본 확인 (2026-10-20 · 판정 §5-2 · 저장 0 · 앱 코드 0)

### 9-1. Yahoo 환율 · WTI — 원시 시각 · 공급자 시간대 (확인됨)

FDR 과 같은 주소(`query2.finance.yahoo.com/v8/finance/chart/<심볼>?interval=1d`)를 Python `requests`(시간 제한 20초)로 불러 `meta` 와 원시 `timestamp` 를 봤다(2026-10-20 08:04 UTC).

| 심볼 | 공급자 시간대(`meta.exchangeTimezoneName`) | 겨울(서머타임 해제) | 여름(서머타임 적용) | 최신 |
|---|---|---|---|---|
| `KRW=X` | Europe/London | 01-12 00:00Z → 런던 월 01-12 00:00 | 07-12 23:00Z → 런던 **월 07-13** 00:00 | 10-19 23:00Z → 화 10-20 00:00 · **close 없음**(진행 중) + 10-20 08:04Z 현재가 줄(자정 아님) |
| `CL=F` | America/New_York | 01-12 05:00Z → 뉴욕 월 01-12 00:00 | 07-13 04:00Z → 뉴욕 월 07-13 00:00 | 10-20 04:00Z → 화 10-20 00:00 · close = 현재가(진행 중) |

- **날짜 = 원시 timestamp 를 공급자 시간대로 바꾼 현지 날짜**(그 시점의 서머타임을 `zoneinfo` 가 적용). 일봉 시각이 공급자 현지 자정이라 겨울 · 여름 모두 실제 요일 날짜가 된다. FDR 의 하루 밀림은 UTC 날짜로 자른 탓이었다. 일괄 +1 · 요일 맞추기 보정은 쓰지 않는다.
- **완료 판단(두 자료 같은 규칙 · 공급자 기준)**: `meta.currentTradingPeriod.regular` 가 공급자의 '오늘 구간'이다(`KRW=X` = 런던 10-20 00:00 ~ 23:59 · `CL=F` = 뉴욕 10-20 00:00 ~ 23:59). 그 구간 날짜 이상인 봉은 진행 중이라 저장하지 않는다. 현지 자정이 아닌 줄(현재가 줄) · close 없는 줄도 저장하지 않는다. NYSE · VIX 오후 4시 규칙은 쓰지 않는다(판정 §3).
- **값의 뜻**: `KRW=X` = Yahoo 일봉 종가(런던 날짜 하루 구간 · 1달러당 원) · `CL=F` = Yahoo 근월물 선물 일봉 종가(뉴욕 날짜 · USD/배럴 · 공식 정산가 아님). 둘 다 한국 15:30 값이 아니다.

### 9-2. KRX 웹 통계 — 이용약관 때문에 계정 로그인 표본 확인 전에 멈춤

- 판정 §1 '정상 회원이 볼 수 있는 통계와 해당 웹 서비스의 이용 조건을 한 번 확인'에 따라 KRX Data Marketplace 홈페이지 이용약관(`data.krx.co.kr/contents/MDC/INFO/informationController/MDCINFO003.cmd` · 부칙 "이 약관은 2026년 8월 29일부터 시행한다.")을 웹 조회 도구로 읽었다.
  - **제10조(금지행위)**: "자동화 수단을 이용하여 정보를 무단 수집·복제·배포하는 행위"를 금지한다.
  - **제12조(이용자의 의무) ②**: "당 사이트의 정보를 거래소의 사전 허락 없이 복사·복제·배포·전송·공중송신하여서는 아니 됩니다."
  - **제6조 ②**: 약관 위반 시 사전 통지 후 이용 제한 · 계정 말소가 가능하다.
- 계획한 방식(갱신 작업이 pykrx 로 회원 로그인해 통계를 자동으로 읽어 PC DB 에 저장)은 제10조의 '자동화 수단을 이용한 수집'에 해당할 수 있고, 거래소의 사전 허락이 없다. 판정 §1 '이용 조건상 불가하면 그 사실을 보고한다'에 따라 **로그인 · 조회 표본 확인을 실행하지 않았다**(사용자 계정 정지 위험도 있음). 법무 판단으로 넓히지 않았고 우회 경로를 찾지 않았다.
