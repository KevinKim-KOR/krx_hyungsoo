## 1. 확인 결과 (설계 §5-1)

### 1-1. 지금 거래량 근거와 읽기
- PC 근거 응답(`app/api_holdings_market_evidence.py:263`)은 종목마다 최근 21행을 한 번 읽는다(`pc_price_basis.load_recent_price_rows` · 같은 종목 여러 계좌는 1회).
  - 조건은 `close IS NOT NULL AND close > 0` 이다(`market_data_store.fetch_recent_price_rows`).
- 같은 행으로 가격 흐름과 거래량 칸을 만든다(`:284` `compute_stored_volume_evidence`).
  - 거래량 칸(`app/stored_volume_evidence.py:65`): 기준일 D = 첫 행 · 비교 창 = 그 앞 20행.
  - 유효 거래량 = 값 있음 · 숫자 · 유한 · 0 이상(`_valid_volume` · 0 유효).
- 이 읽기는 **거래량이 비어 있는 행을 지우지 않는다**(거래량이 아니라 종가로만 거른다). 그래서 차트용 'D 포함 최근 최대 20행'은 이미 읽은 21행의 앞 20행으로 만들 수 있다.
  - 추가 DB 읽기 0 · 평균용 행을 버리지 않음.
- 기준일이 PC 가격 흐름 기준일과 다르면, 거래량 칸은 값을 그대로 보이고 머리에 안내를 붙인다(`frontend/lib/storedVolume.ts :: pastVolumeNote`).
  - 안내: '과거 저장 자료 · PC 비교 기준일은 D' / 'PC 비교 기준일(D)보다 늦은 날짜의 자료'.

## 3. 질문 (설계자 판단 · 권장은 (a))

### Q1. 창의 행 조건 — 이미 읽은 행을 쓰는가
- 설계 §3 은 '원본 저장 행'이라고 적었다. 지금 거래량 칸과 가격 흐름은 **종가가 유효한 행**만 읽는다(§1-1). 거래량이 빈 행은 지우지 않는다.
- (a) **권장** — 같은 읽기의 앞 20행을 쓴다. 추가 읽기가 없고, 기준일 D · 날짜가 위 네 칸 · 가격 흐름과 같다.
  - 종가가 비정상인 날은 차트에서도 빠진다(지금 실제 창에는 0건).
- (b) 종가와 무관한 원본 행을 따로 한 번 읽는다(종목당 SELECT 1회 추가). 종가가 비정상인 날도 거래량을 보인다. 다만 네 칸 · 가격 흐름과 날짜 집합이 달라질 수 있다.

### Q2. 날짜별 값 보기 — 기존 차트에 상세값 장치가 없음
- (a) **권장** — 목업처럼 막대를 누르면 차트 아래 한 줄에 '날짜 · 거래량 N주'(처음엔 기준일)를 보인다.
  - 마우스를 올리면 브라우저 기본 설명창에도 같은 값이 나온다.
  - 키보드로 고를 수 있도록 막대 묶음에서 좌우 화살표로 옮기게 한다(구현 때 추가 · 화면 모양 변화 없음).
- (b) 차트 아래에 날짜 · 값 표 20줄을 함께 펼친다.

### Q3. 기준일이 PC 가격 흐름 기준일과 다를 때
- (a) **권장** — 차트는 그대로 보이고, 제목 줄에 기존 거래량 칸과 같은 안내(`pastVolumeNote` 문구)를 붙인다. 기존 규칙도 숨기지 않고 안내로 구분한다.
- (b) 차트를 숨기고 안내만 보인다.
