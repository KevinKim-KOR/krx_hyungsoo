## 1. 지금 조회 기준 · 첫 조회 연결 (설계 §5-1)

- **선택지** = API `basis` 값 3개 `daily` · `one_month` · `three_month`(`frontend/lib/api/market.ts` `MarketBasis` · 표 머리 이름 일간 · 1개월 · 3개월). 초기값 = 코드 상수 `DEFAULT_MARKET_BASIS = "one_month"`(같은 파일).
- **상태 · 첫 GET**: `MarketDiscoveryView.tsx` 의 `useState(DEFAULT_MARKET_BASIS)` 하나. `useMarketTopnLoad`(POC5-12)의 useEffect 가 그 상태(필터 · 기준 · 방향)로 `fetchMarketTopnLatest(10, …)` 를 부른다. 화면이 올라온 첫 렌더의 상태로 한 번 부르고, 개발 모드의 두 번 실행은 POC5-12 진행 중 공유로 1회가 된다.
- **기준을 바꾸는 곳 = 표 보기 머리 3칸 클릭뿐**(`handleSort`): 다른 칸 = 기준 변경 + 내림, 같은 칸 = 방향 전환, 둘 다 서버 재조회. **기본 보기인 카드 보기에는 기준 선택이 없다.** 목록 위 기간 상자 첫 줄('1개월 수익률 계산 기간')에 지금 기준만 보인다 → Q1.
- 다시 읽는 동안 화면 전체가 '불러오는 중'으로 바뀐다. 그래서 목록이 보일 때 화면 상태 기준 = 받은 응답 기준(`data.basis`)이다.
- **아래로 넘기는 값**(모두 '실제 조회 중인 선택'이다. 저장 기본은 상태 초기값 한 곳에서만 읽게 한다):
  - 「보유와 비교」 후보 목록 조건 = 응답 `data.basis`(`HoldingsCompareView.tsx` `listQuery`).
  - 복사문 · AI 세션 전달 · ETF 구성종목 전달 = 응답 후보 목록 그대로. 기준 이름은 싣지 않는다(`lib/marketDiscoveryCopyText.ts` · `TransferToAISessionsCard`).
  - 카드 · 표 · 기간 상자 = 화면 상태 `basis`.
- **메뉴 이동**: `MainPanel` 이 메뉴마다 화면을 바꿔 끼운다. 그래서 지금도 다른 메뉴에 갔다 오면 화면이 새로 올라와 1개월로 다시 시작한다(임시 선택은 남지 않음). 바꾼 뒤에는 새로 올라올 때 저장 기본으로 시작한다. 화면을 유지하는 방식 자체는 그대로다.
- **서버 렌더**: 첫 메뉴가 「오늘의 투자 점검」이라 시장 화면은 브라우저에서만 올라온다. 따라서 상태 초기값에서 바로 읽어도 서버 화면과 어긋나지 않고, 첫 GET 전에 읽기가 끝난다.
- **다른 화면은 그대로**(설계 §1 · §4): 같은 API 를 기본 1개월로 부르는 「오늘의 투자 점검」 · 대시보드 · 「ETF 비교하기」. 목업에서도 앱 첫 화면 「오늘의 투자 점검」의 1개월 요청과 시장 화면의 3개월 요청은 따로였다.

## 2. 저장 helper · 변경 파일 (설계 §5-2)

- **기존 helper**: localStorage 를 쓰는 곳은 없다. 사이드바 접힘 영구 저장은 B-057 보류이고, 조회 캐시도 저장하지 않는다. sessionStorage 초안 helper 2개(`lib/aiSessionsDraft.ts` · `lib/etfExposureDraft.ts`)의 방식만 따른다. 저장소 접근을 try/catch 로 감싸 실패를 화면 오류로 만들지 않는 방식이다.
- **새 `frontend/lib/marketBasisPreference.ts`**:
  - 키 하나 `krx.marketDiscovery.defaultBasis.v1`. 값 = API 값 문자열 그대로.
  - 읽기 결과 = `{basis, status}`:
    - 허용 3값 → `saved`
    - 없음 → `none`(1개월)
    - 허용 밖 → `invalid`(1개월)
    - 읽기 예외 → `read_failed`(1개월)
  - 읽기 때문에 값을 지우거나 고쳐 쓰지 않는다.
  - 쓰기 = setItem 뒤 다시 읽어 같은 값일 때만 성공. 예외 · 다른 값은 실패다.
- **새 `frontend/app/components/MarketBasisDefaultRow.tsx`**:
  - hook `useMarketBasisDefault()`: 상태 초기값에서 한 번 읽는다. 저장 기본 · 확정 여부(허용 밖 값이면 미확정) · 읽기 안내 · `save(지금 기준)`(성공 여부)을 가진다. 같은 브라우저 다른 탭의 저장은 storage 이벤트로 '기본' 표시만 다시 읽는다. 저장 실패 안내는 줄 컴포넌트 상태다(구현 중 확정 · §6).
  - 줄 구성: '기본 조회 기준 {기본}'. 지금 기준과 다르면 '· 지금 보는 기준 {지금}'(파란 글자)을 붙인다.
  - 버튼 [이 기준을 기본으로]: 중간 40px(`btn-md`). 같으면 회색 '이미 기본'으로 누를 수 없다. 단 저장값이 허용 밖이면 1개월(대신 쓴 값)이어도 누를 수 있어 명시 저장으로 바로잡는다(§6).
  - 안내 문구:
    - 저장 실패 = 빨간 한 줄 '기본값 저장을 확인하지 못했습니다. 현재 조회는 유지됩니다.'(판정 §3 정정)
    - 읽기 실패 = 주황 짧은 안내 '저장된 기본을 읽지 못해 1개월로 시작했습니다'
    - 허용 밖 값 = 주황 짧은 안내 '저장된 기본 값을 쓸 수 없어 1개월로 시작했습니다'(설계 §3 '읽기 실패는 짧은 안내로 구분'과 같은 자리 · 판단)
- **`MarketDiscoveryView.tsx`**(864줄 · KS-10 근접 850):
  - 기본값 상수 대신 hook 이 처음 읽은 값으로 상태를 시작한다.
  - 카드 보기 목록 카드 맨 위에 줄을 두고, 표 보기에도 줄을 넘긴다.
  - 늘어나는 줄 = 4(목업 사본 실측 864 → 868 · 900 미만 유지 · 저장 · 표시는 새 파일).
- **`CandidateTable.tsx`**: 선택 prop `top` 하나. 목록 카드 맨 위에 그대로 그린다.
- **`ReturnPeriodLine.tsx`**: 첫 줄 ? 끝에 한 문장 '위 '기본 조회 기준'은 이 브라우저에만 저장됩니다(다른 기기 · 브라우저 · 접속 주소와 공유하지 않음).'을 넣는다(설계 §2 '기존 도움말 안에'). 이 기간 상자는 이 화면에서만 쓴다(「ETF 비교하기」 표는 다른 컴포넌트).
- **`globals.css`**: `.mbd-*` 몇 줄. 이름 칸은 기간 상자와 같은 150px 로 위아래를 맞춘다.
- 백엔드 · API · DB · 다른 화면은 바꾸지 않는다.

## 3. 확인 방법 (설계 §5-3)

- **helper 단위**(vitest · jsdom localStorage): 없음 · 허용 3값 · 허용 밖 · 읽기 예외 · 쓰기 성공 · 쓰기 예외 · 다시 읽은 값이 다름.
- **화면**(vitest · 기존 시장 화면 시험 방식 · 가짜 fetch):
  1. 저장 3개월 → 시장 GET 1회 · `basis=three_month`. 1개월을 먼저 부르지 않는다.
  2. 없음 · 허용 밖 · 읽기 예외 → GET 1회 · `basis=one_month` · 안내 문구.
  3. [이 기준을 기본으로] → GET 수 그대로 · 저장 값과 표시가 바뀜 · 버튼 '이미 기본'.
  4. 표 머리로 임시 변경 → 저장 값 그대로 · '지금 보는 기준' 표시. 화면을 새로 올리면 저장 기본으로 첫 GET.
  5. 저장 실패 → 안내 · 기본 표시 그대로 · 지금 조회 그대로 · GET 0.
  6. 다시 읽기(갱신 끝 · 재시도) → 지금 기준으로 GET. 저장 기본으로 되돌리지 않는다.
  7. 저장 기본 ≠ 지금 기준일 때 「보유와 비교」 목록 조건 · AI 세션 전달 초안 = 지금 기준 응답 그대로.
- **기존 시험 · 검사**: POC5-12 기존 시험(진행 중 공유 · 늦은 응답 무시 · 재조회 실패 시 받은 화면 유지)이 그대로 통과해야 한다. 그 밖에 tsc · eslint · 프론트 전체 vitest · 변이(사본 폴더) 몇 개를 한다.
- 백엔드 변경이 없으므로 백엔드 전체 회귀는 하지 않는다(설계 §6).

## 4. 질문 (설계와 현재 코드가 부딪히는 곳)

**Q1. 카드 보기에는 기준 선택이 없다**(설계 §2 '그 선택 옆' · §1 「요즘 잘 오르는 ETF」 기본 보기 = 카드).

- **(a) 권장** — 카드 · 표 보기 공통으로 목록 카드 맨 위에 '기본 조회 기준' 한 줄 + [이 기준을 기본으로]를 둔다.
  - 기준 바꾸기는 지금처럼 표 머리에서만 한다.
  - 카드 보기에서는 기본을 확인하고, 표에서 고른 기준을 저장할 수 있다.
  - 표 보기에서는 이 줄 바로 아래가 기간 상자 → 표 머리(기존 선택)다.
- **(b)** 표 보기에만 이 줄을 둔다. 카드 보기는 지금 그대로이고, 첫 조회만 저장 기본으로 한다.
- **(c)** (a) + 이 줄에 기준 선택 3버튼(일간 · 1개월 · 3개월)을 새로 둔다.
  - 카드 보기에서도 기간을 바꿀 수 있다.
  - 다만 설계 §2-1 '임시로 다른 기간을 보는 동작은 지금과 같다'를 넘는 새 선택 기능이라 설계 판단이 필요하다.

## 6. 설계자 판정 반영 (2026-10-19 · 판정 원문 `docs/ai_design/POC5/POC5-26_PC_MARKET_DEFAULT_BASIS_PREFERENCE_PLAN_DECISION_2026-10-19.md`)

- **PASS · Q1 (a)**: 카드 · 표 보기 공통 목록 카드 맨 위 줄 + 버튼. 기준 변경은 기존 표 머리 그대로이고, 카드 보기에 선택 버튼을 더하지 않는다.
- **§2 구현안 그대로 수용**: 기준 값 하나만 저장한다. 임시 변경 · 방향 전환은 기본 저장이 아니다. 상태 초기값에서 읽고, 메뉴 재진입 방식은 유지한다. 다른 화면의 1개월 요청은 이 화면의 중복 요청이 아니다. helper · 작은 컴포넌트 · 표 `top` 으로 나눈다. 허용 밖 값도 짧은 안내를 보이며, 자동 수정은 없다. 전달은 지금 조회 응답 그대로이고 새 필드는 없다. 저장 클릭에 시장 GET 은 없다.
- **저장 실패 문구 정정(판정 §3)**: '기본값 저장을 확인하지 못했습니다. 현재 조회는 유지됩니다.'(§2 교체 · 목업 재확인 없음).
- **검증(판정 §4)**: §3 그대로 하고, 변경 없는 백엔드 전체 회귀는 하지 않는다. OCI 운영점검은 선행조건이 아니다(별도 유지).
- **구현 중 확정한 세부(독립 검토 1회 반영 · 결과서 §4)**:
  - 저장 실패 안내는 hook 이 아니라 줄 컴포넌트 상태로 둔다. 기준을 바꾸거나 다시 읽으면 사라지고, 저장할 것이 없어지면 보이지 않는다.
  - 저장값이 허용 밖이면 1개월에서도 버튼을 살린다. 판정 §2 '자동 수정 없음'은 그대로이고, 명시 저장으로만 바로잡는다. 읽기 실패는 목업 ⑥ 그대로 '이미 기본'이다.
  - 같은 브라우저 다른 탭의 저장 · 삭제는 storage 이벤트로 '기본' 표시만 다시 읽는다. 지금 조회 · 시장 GET · 저장값은 바꾸지 않는다(설계 §2-3 '저장된 기준을 알 수 있다').
