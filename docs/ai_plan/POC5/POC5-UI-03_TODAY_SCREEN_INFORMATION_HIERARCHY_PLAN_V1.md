## 2. 접기 구현

- 상태는 각 컴포넌트의 React state 다. 기본은 접힘이고, 화면을 떠나면 처음 상태로 돌아간다. 저장소 · 설정 · DB 는 쓰지 않는다(설계 §4).
- 버튼은 기존 크기 규칙의 **중간 버튼 40px**(`btn-md` · '펼치기' 같은 보조 동작)이고, `aria-expanded` 를 단다. 기호는 붙이지 않는다.
  - '시장 수치와 거래량 펼치기' / '시장 수치와 거래량 접기'
  - '수치 더보기' / '접기'
  - '펼치기' / '접기'
- 접힌 칸은 그리지만 않는다. 조회 · 계산 · 값은 그대로이고, 펼치면 같은 응답의 같은 값이 보인다. 값을 지우거나 계산에서 빼지 않는다(설계 §6).

## 4. 판정 요청

### Q1. 기본 화면의 KODEX200 기준일

기존 시장 판정을 접으면 기본 화면의 MA20 · MA60 옆에 날짜가 없어진다. 그러면 KOSPI 기준일(실제 자료 10-12)만 보이고, KODEX200(10-13) 값이 그 날짜처럼 읽힌다(설계 §3 '각각 실제 날짜').

- 기준선 값 자체의 날짜 칸은 응답에 없다. 쓸 수 있는 값은 둘이다.
  - **`market_risk_reference.kodex200.as_of_date`**: 069500 · close > 0 최신 행이다. 기준선 계산(`fetch_price_history`)과 행 조건이 같다. 같은 응답 안이지만 읽기는 따로다.
  - **`market_context.asof`**: 기존 시장 판정 줄이 '기준일'로 쓰는 값이다(계약 ⑤ 'KODEX200 기준일').
    - 실제 계산은 `etf_daily_price` 전체 `MAX(date)` 다(`market_topn_helpers._latest_date_in_db`). 종목 조건이 없고, POC5-10 이후에는 보유 개별주 행도 이 표에 있다.
    - 그래서 KODEX200 마지막 행보다 늦을 수 있다(오늘 자료는 둘 다 10-13).
- OPS-03 시험(`KospiStatusSurfaces.test.tsx` 'STEP 4-3')은 KODEX200 날짜가 기존 시장 판정 줄에만 보인다고 확인한다. (a) · (b)를 고르면 이 시험을 같이 고친다.
- 선택지
  - (a) `market_risk_reference.kodex200.as_of_date` 를 기준선 옆에 둔다 — 목업이 이렇게 했다.
  - (b) `market_context.asof` 를 기준선 옆에 둔다(판정 줄과 늘 같은 값).
  - (c) 날짜를 표시하지 않는다(지금처럼).
  - (d) 응답에 기준선 날짜 칸을 더한다(backend · 설계 §6 범위 밖).
- 개발자 권장 = (a). (a)에서 펼친 판정 줄의 `market_context.asof` 와 날짜가 다르게 보일 수 있는 경우는 §5-2 에 적었다.

### Q2. 「자료 최신화 필요」 카드

설계 표 '자료 문제 — 실제 문제가 있을 때'에 해당한다.

- 지금 카드는 문제가 0건이어도 늘 보인다. 그때는 '최신 · 보유 종목 현재가는 최신 상태입니다 [업데이트]' 한 줄(경량 갱신 버튼)이 나온다.
- 목업은 카드 · 내용 · 자리를 그대로 두었다. 1440 에서는 보유 옆, 1000 에서는 보유 아래다(설계 '시장 또는 보유 영역 가까이').
- 선택지
  - (a) 그대로 둔다.
  - (b) 0건이면 카드를 숨기고 [업데이트]를 다른 자리로 옮긴다.
- 개발자 권장 = (a). 버튼 동작을 유지한다(설계 §4).

### Q3. 접힌 값이 비어 있을 때의 알림 문구

설계 §3 은 자료 부족을 접어 숨기지 말라고 한다. 목업은 접힌 상태에서 '확인 필요: …'를 보인다.

- 시장 칸은 펼치기 버튼 옆에 둔다. 최대 3개 행은 행 아래에 둔다. 예: 비교 기간이 달라 KODEX200 대비를 비운 종목은 상태가 정상이라 최대 3개에 남는다.
- 뒤 문구는 기존 '자료 없음' · '자료 부족 (n/20)' · '계산 불가'를 다시 쓴다. '확인 필요:'만 새로 붙인 말이다.
- 선택지
  - (a) 목업대로 한다.
  - (b) 최대 3개 행은 알리지 않는다(지금처럼 '-' · 사유는 「확인 근거」 상세).
