### STEP 1-2. T-1 자료가 사용 가능해지는 최초 시각 (설계자 사실조사 2)

**KRX 공식 규칙** — KRX OPEN API FAQ(`https://openapi.krx.co.kr/contents/OPP/COMM/faq/OPPCOMM004.cmd` · 2026-09-29 열람):

> 「데이터는 언제 업데이트되나요?」(2026-05-04 수정) — "모든 API 데이터는 전일 데이터 기준, 익일 영업일 오전 8시에 업데이트됩니다. (예시) 4월 28일 데이터 → 4월 29일 오전 8시부터 조회 가능 (예시) 금요일 데이터 → 다음 영업일(월요일) 오전 8시부터 조회 가능"
>
> (2026-05-06 수정) — "주말, 공휴일에 대한 데이터는 호출되지 않는 점 안내드립니다. 또한, 당일자 조회나 익일 오전 8시 전에 데이터를 호출하실 경우, 데이터가 조회되지 않습니다."
>
> 「당일 또는 실시간 데이터 조회가 가능한가요?」 — "불가능합니다. KRX OPEN API는 일별 단위 데이터만 제공하며, 당일·실시간·장중 데이터는 조회할 수 없습니다."

## STEP 3. 08:30 시장 흐름 브리핑 · KRX 수집 (설계자 계약 2 · 7)

1. **KRX 목표일 = 직전 거래일(T-1)** — `trading_day_lag.trading_axis_before(today, calendar_dir=…)[-1]`. **단일 날짜 조회**(`fetcher(T-1)` → `has_traded_prices` → `validate_snapshot`)로 시도한다. 지금의 `resolve_basis_date` 역탐색은 T-1 이 없으면 같은 호출 안에서 T-2 를 돌려주므로(`krx_sync.py:110-131`) 재시도가 걸리지 않는다 — 목표일 시도에 쓰지 않는다.
2. **시도 시각표** — KRX 단계 시작 시각으로 정한다(플래그 없음): **08:00 전 시작 → KRX 단계를 기다리지 않고 건너뛰고 기록**(배포 순서가 어긋나 옛 07:20 cron 에서 새 코드가 돌아도 헛재시도 · 08:00 러너와 겹침 없음) · **08:00~08:27 시작(정기 08:10)** → 08:10(단계 시작 즉시) · 08:15 · 08:20 · 08:24 가운데 남은 시각에 시도 · **최대 4회** · 시도당 timeout 40초(`krx_sync.py:56`) · 단계 **절대 마감 08:27** · **08:27 뒤 시작(수동 재실행 · 추가 수집)** → 1회만 시도.
3. **빠진 거래일 채우기** — 매 실행에서 **창(최근 21거래일 · 거래일 축) 안의 빠진 거래일 전부**를 날짜당 1회 받아 채운다(`initial_backfill` 의 `have` 방식만 가져온다 — 함수 자체는 저장일이 21개 이상이면 바로 끝나 그대로 못 쓴다 · `krx_sync.py:393-396`). 한 번 실패해도 다음 실행이 다시 채우므로 스스로 복구된다. 창은 저장 날짜의 순서로 잡히므로(`krx_store.py:266-276` · `sector_signal.py:141-155`) 빠진 날이 있으면 '5 · 20 거래일' 이 실제로는 6 · 21 이 된다 — **창의 날짜가 거래일 축과 어긋나면 fail-closed**(구역 생략).
4. **목표일은 캘린더로만 정한다** — 캘린더상 T-1 에서 0행이거나 가격이 비면 '아직 공개 전' 으로 보고 다음 시도로 넘긴다(응답으로 휴장을 판정하지 않는다 — 캘린더와 반대로 판정하면 `calendar.py:20` 이 정의한 결함이고, 공개 전 응답을 휴장으로 오판하면 재시도가 사라진다). **캘린더가 그해를 덮지 않으면**(평일 fallback · `trading_day_lag.py:61-66`) 평일 휴장 다음 날 T-1 이 휴장일이 되어 lag 0 관문 · 축 대조가 국내 구역을 생략한다 — 그해 캘린더(`krx_trading_days_YYYY.csv`)를 연말 전에 준비하는 것을 이 단계의 운영 전제로 둔다(`calendar.py:26` '캘린더 부재는 차단 사유 아님' 정책과 충돌 · STEP 10-6).
5. **공개 도중 불량 응답** — 가격이 일부만 비면(`validate_snapshot` 거부 · `krx_store.py:114-115`) 다음 시도로. 행 수 검사(직전 스냅샷 대비 비율)를 둘지는 STEP 10-3.
6. **시도별 기록** — 시각 · 목표일 · HTTP · 행 수 · 가격 채움 · 예외 종류를 배치 JSON 에 남긴다(키 · 가격 값은 남기지 않는다). 매 거래일 실제 공개 완료 시각이 운영 기록에 쌓인다.
7. **기초지수 구역 최신성 = `actual_basis_date == expected_previous_trading_day`**(확정 계약 6 · lag 숫자로 판정하지 않는다). `MAX_STALE_TRADING_DAYS=1` 은 KOSPI 적재 감지(`market_benchmark_store.py:260`) · 화면(`api_market_topn_service.py:318`) · 운영 판정(`market_regime.py:139` · `evaluate_freshness` 기본값)도 쓰므로 건드리지 않는다.
8. T-1 이 없으면 구역 생략 + '국내 기초지수는 직전 거래일 자료를 확인하지 못해 제외했습니다.'(설계자 예시 · `INDEX_NOTICE` 에 새 상태 1개 · `render.py:52-62`). T-2 값은 본문 · '기준' 줄에 쓰지 않는다.
9. 본문 머리 `"[시장 흐름 브리핑] 08:00"`(`render.py:37`) → `08:30`. 테스트는 `render.HEADER` 를 참조한다(`tests/test_market_briefing_flow_through.py:579,624`).
10. 목업 스크립트 · 역검증(ops02b2)의 08:00 표기 · lag 기대값을 함께 맞춘다.

2. 구역을 낼 때 구역 머리에 `추세 기준 YYYY-MM-DD 종가` 한 줄 — 본문 '기준' 줄(`현재가 … · 직전 종가 …` · `intraday_alert_render.py:233-237`)과 분리. 사업군 구역 렌더는 `intraday_alert_render.py:186-196`.

4. 08:27 마감까지 KRX 가 공개되지 않은 날은 그날 장중 신규 진입이 종일 생략된다 — 장중에 한 번 더 수집할지(예: 09:20)는 STEP 10-7.
