## 3. 조사 접근 방법 (설계자 판정 반영 · 2026-07-31)

설계서 §4 조사 범위를 따른다. 정적 소스 read 중심 (실행 안 함).

> **설계자 필수 수정 반영**: 이전 §3-1 이 "`fastapi_app/routes/` 전 라우터" 를 메뉴 모집단으로 잡은 것은 **오류**. **백엔드 API 라우터 ≠ 사용자 메뉴.** 조사 모집단은 **사용자에게 보이는 메뉴/내비게이션** 이다.

**메뉴 조사 순서 (설계자 확정)**:
```
사용자 노출 메뉴·내비게이션 정의 전수 확인
  → 메뉴별 경로(URL) 와 연결 화면/템플릿 확인
  → 그 화면이 직접 사용하는 API·서비스 확인
  → 백엔드 라우터 목록과 교차검증
```

**정리 기준 (설계자 확정)**:
- **사용자 노출 메뉴가 조사 모집단.** API 전용 라우터는 메뉴로 등록하지 않는다(교차검증에만 사용).
- **숨김·조건부 메뉴는 메뉴 목록에 포함.**
- **메뉴 없이 존재하는 화면/기능 = "비메뉴 발견 기능" 으로 별도 기록**(설계서 §6-7).
- 모든 메뉴는 **얕게** 확인. **심층 추적은 대문·메뉴 트리·위험/알람 축으로 제한**.
- 채택 여부·적용 화면·개발 우선순위는 문서에 넣지 않음(AC-11).

**축별 접근**:
1. **전체 메뉴 지도(§4.1, AC-2/3/4)**: 사용자 노출 메뉴 정의(내비게이션 템플릿/메뉴 설정) 전수 → 메뉴→경로→화면/템플릿→직접 호출 API·서비스 연결 → 라우터와 교차검증. 확인 불가/미구현 구분(추측 금지). 캡처 메뉴 vs 실제 소스 차이(AC-4).
2. **대문·대시보드 축(§4.2, AC-5)**: **홈 화면 전체가 우선 심층 조사 대상**(상단만 아님, 설계자 확정) → 정보 구성·배치·차트/시각화·자동/수동 갱신·캐싱·데이터 흐름. 패키지 설치만으로 기술 단정 안 함(실사용 구조만).
3. **메뉴 트리·라우팅 축(§4.3, AC-6)**: 메뉴 그룹↔화면 연결·독립 메뉴 vs 화면 내부 상세 기준·조건부/숨김/미구현·중복 진입점·캡처와 실제 차이.
4. **위험·알람 축(§4.4, AC-7/8)**: 위험/손절/알람 입력 데이터·판정 로직/임계값 위치·저장 여부·표시/알림 흐름·사용자 개입 지점·자동주문/손절/비중조절 연결 여부.

**기준 버전 고정 (Q2 확정)**: 조사 시작 시점의 **경로 + 파일 수 + 파일 목록 해시(또는 스냅샷 해시)** 를 기록. mtime 만으로는 부족(설계자). **조사 중 해시가 바뀌면 중단**. KILL_SWITCHES 에 같은 프로젝트명이 있다는 사실만으로 동일 소스·버전으로 단정하지 않고, **이 압축 해제본 자체를 별도 스냅샷으로 고정**한다.

**코드 인용 (Q4 확정)**: 파일 경로·함수명·라우트·설정 키·확인된 임계값 등 **사실 증거는 기록**. 원본 로직 코드 블록 복사·긴 발췌 금지. 동작은 **서술 또는 의사 흐름**으로 정리.

**민감정보 경계 (Q1 확정 · 사용자 지시 우선)**: `.env`·인증키·토큰·계좌번호·개인정보·실거래/보유 데이터·DB·로그는 **열람(조회)은 가능**하되 **조사 결과 문서에 값·개인정보를 절대 기록하지 않는다.** (설계자 "열람도 제외" 와 다름 — 사용자 지시 우선.) 그런 파일은 **존재·역할·구조만** 기록, 실제 값은 마스킹/생략. 민감 경로로 이어져도 중단하지 않으나, 값은 문서에 남기지 않는다.

**산출물**: 설계서 §6 의 7개 항목만 담은 조사 결과 문서 1개 → `docs/ai_result/POC3/POC3-REF-01_FRIEND_PROJECT_SOURCE_FACT_SURVEY_RESULT_V1.md` (Q5 확정). 채택 판단·구현 지시 섞지 않음(AC-11).

## 5. 착수 게이트 — ✅ 둘 다 해소 (2026-07-31 사용자 확정)

1. **Q1 열람 범위 — ✅ 확정.** 사용자: **"전체 열람 허용 · 민감정보 조회(열람) 가능, 다만 조사 결과 문서에 기록은 불가."**
   - **설계자 문구와의 차이 명시**: 설계자는 민감정보를 "열람·기록 모두 제외" 로 제시했으나, **사용자 지시가 우선** → 민감정보(`.env`·인증키·토큰·계좌번호·개인정보·실거래/보유·DB·로그)는 **열람은 하되(경로가 이어져도 중단 안 함), 값·개인정보를 조사 결과 문서에 절대 기록하지 않는다.**
   - 문서에는 그런 파일의 **존재·역할·구조**만 기록. 실제 값·키·계정·개인정보는 마스킹/생략(적지 않음).
2. **설계서 레드팀 PASS — ✅ 확정.** 사용자: "개발자에게 주는 것은 레드팀 PASS만" → 이 설계서는 레드팀 통과분. 개발자가 별도 레드팀 게이트 확인 불필요.
