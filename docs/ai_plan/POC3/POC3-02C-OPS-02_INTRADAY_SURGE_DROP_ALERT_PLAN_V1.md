### 1-1. 기존 `holdings_risk_alert` 실제 임계값과 상태 단계

`app/runtime_evidence/holdings_risk.py:40-55`

```python
STATE_D5_7, STATE_D7_10, STATE_D10_PLUS = "D5_7", "D7_10", "D10_PLUS"

_RISK_BANDS = (
    (STATE_D10_PLUS, None,  -10.0),
    (STATE_D7_10,   -10.0,   -7.0),
    (STATE_D5_7,     -7.0,   -5.0),
)
```

| 상태 | 구간 | 라벨 | 심각도 |
|---|---|---|---:|
| `D5_7` | `-7% < pct ≤ -5%` | 전일 대비 하락 5~7% | 1 |
| `D7_10` | `-10% < pct ≤ -7%` | 전일 대비 하락 7~10% | 2 |
| `D10_PLUS` | `pct ≤ -10%` | 전일 대비 하락 10% 이상 | 3 |

- 경계는 **상한 배타 · 하한 포함** (정확히 `-5%` → `D5_7`).
- `_SEVERITY = {D5_7:1, D7_10:2, D10_PLUS:3}` · `GROUP_ORDER` 는 나쁜 구간이 위.

> ⚠ **설계 §4-1 과 어긋나는 점**: 설계서는 "단일 값이면 단일, 2단계면 2단계" 를
> 가정했으나 **실제는 3단계**다. 대칭 적용하면 급등도 3단계가 된다(§4 Q1).

### 1-2. 직전 거래일 종가의 실제 source

호출 사슬을 끝까지 따라갔다.

**결론: 분모는 `etf_daily_price` (FDR 기반 · 조정 계열)** 이고, 분자는 Naver
현재가(무조정 체결가)다. 즉 **현재 운영 경로는 조정/무조정이 섞여 있다.**

OCI 실측 커버리지 — 이게 더 중요하다.

```text
etf_daily_price                 1,345,202행 · ~2026-09-17 · 최근 하루 41종목만
krx_etf_daily_price_unadjusted     27,968행 · 2026-08-13~09-16 · 하루 1,168~1,175종목
```

| 대상 | `etf_daily_price`(조정) | `krx_..._unadjusted`(무조정) |
|---|---:|---:|
| 사업군 대표 27종목 | **4 / 27** | **27 / 27** |
| 보유 29종목 | 29 / 29 | **26 / 29** |

- 조정 테이블은 하루 41종목만 갱신돼 **사업군 경로에 쓸 수 없다.**
- 무조정 테이블은 **ETF 전용**이라 보유 중 개별주 3종목
  (`005930` 삼성전자 · `000660` SK하이닉스 · `006400` 삼성SDI)이 **없다.**
  → 보유 경로를 무조정 테이블로 옮기면 **기존 보유 급락 계약이 깨진다(중단 조건).**

겹치는 912행 비교: 불일치 6행 · 최대 괴리 `0.5000%`.

### 1-3. Naver 원응답의 직전 종가 포함 여부 — **포함된다**

`app/market_naver.py:97` 은 `closePrice` 만 뽑고 나머지를 버리는데, 원응답
(`https://m.stock.naver.com/api/stock/{ticker}/basic`)에는 이미 들어 있다.

```text
closePrice                    현재(최종) 체결가
compareToPreviousClosePrice   전일 대비 금액 (부호 없음)
compareToPreviousPrice        방향 코드 (2=상승 / 5=하락)
fluctuationsRatio             전일 대비 등락률 (부호 포함) ← 이것 하나면 된다
localTradedAt                 기준 시각
```

**검증 — `closePrice / (1 + fluctuationsRatio/100)` 이 KRX 무조정 D-1 종가와
일치하는가?** (KRX `20260917` 원본 1,171건과 대조)

| ticker | Naver 현재 | ratio | 역산 전일 | KRX 무조정 D-1 | 일치 |
|---|---:|---:|---:|---:|:--:|
| 069500 | 109,285 | +2.83% | 106,277 | 106,280 | O |
| 305720 | 14,670 | +0.31% | 14,625 | 14,625 | O |
| 091160 | 130,545 | +2.26% | 127,660 | 127,655 | O |
| 466920 | 27,710 | −1.14% | 28,030 | 28,030 | O |
| 396500 | 37,000 | +4.03% | 35,567 | 35,565 | O |
| 364980 | 10,265 | −0.10% | 10,275 | 10,275 | O |
| 102110 | 109,560 | +2.85% | 106,524 | 106,520 | O |

**7 / 7 일치** (반올림 오차 ≤ 5원). 즉 **`fluctuationsRatio` 가 곧 설계 §3 의
`DAY_RETURN` 이다.** 같은 응답·같은 출처라 혼합이 없다.

개별주에서도 같은 필드가 온다 — 무조정 ETF 테이블에 없던 3종목 포함.

```text
005930 삼성전자    260,000  +2.97%    000660 SK하이닉스  1,849,000  +5.96%
006400 삼성SDI     542,000  +0.56%
```

> ⚠ `compareToPreviousClosePrice` 는 **부호가 없다.** 방향 코드로 부호를 복원하면
> `466920` 에서 실제로 틀렸다(역산 +1.17% vs 실제 −1.14%). **`fluctuationsRatio`
> 를 직접 쓴다.**

### 1-4. 09:30 시점 KRX `D-1` 가용 여부 — **07:20 배치로는 불가(D-2)**

07:20 KST 배치 3회 연속 실측(`logs/oci_market_data_batch.log`).

| 배치 실행(KST) | 적재 `basis_date` | 그날의 `D-1` | 판정 |
|---|---|---|---|
| 2026-09-16 07:20 | 2026-09-14 | 09-15 | **D-2** |
| 2026-09-17 07:20 | 2026-09-15 | 09-16 | **D-2** |
| 2026-09-18 07:20 | 2026-09-16 | 09-17 | **D-2** |

거래일 축(`state/market_meta/krx_trading_days_2026.csv`)으로 대조했다 —
09-15·16·17·18 전부 거래일이므로 휴장 때문이 아니다. **07:20 에는 KRX 가 D-1 을
아직 공표하지 않는다.**

같은 API 를 2026-09-19 11:27 KST 에 조회하면 `20260918` 이 1,171건 전부 채워져
있다. 즉 **07:20 이후 어느 시점엔가** 채워지는데, 정확한 공표 시각은 이번 조사로
확정하지 못했다(1회 관측으로는 알 수 없다).

> **그러나 §1-3 때문에 이 질문은 더 이상 게이트가 아니다.** Naver 응답이
> 무조정 D-1 대비 등락률을 이미 주므로 **09:10 KRX 갱신 배치가 불필요**하다.
> 설계 §3 우선순위 **1번으로 해결**된다.

## 4. 설계자 판단이 필요한 3건

### Q1. 급등 대칭이 **3단계**가 된다 (§1-1)

설계 §4-1 은 "단일 또는 2단계" 를 가정했으나 실제 급락은 **3단계**다.

```text
(a) 3단계 대칭   +5~7% / +7~10% / +10% 이상   ← 설계 문장 그대로 따르면 이것
(b) 2단계 축약   +5~10% / +10% 이상
(c) 단일         +5% 이상
```

**(a)** 가 "기존 급락 단계의 절댓값을 양수 방향으로 대칭 적용" 에 맞다고 보지만,
급등은 급락만큼 세분할 실익이 없을 수 있어 확인받는다.

### Q2. 보유 경로의 가격 출처를 바꿀 것인가 (§1-2 · §1-3)

현재 보유 경로는 **무조정 현재가 ÷ 조정 종가** 로 섞여 있다.

```text
(a) 보유도 Naver fluctuationsRatio 로 통일
    → 조정/무조정 혼합 해소 · 개별주 3종목 포함 · 두 구역 출처 동일
    → 다만 "기존 급락 계약 그대로 유지" 를 넓게 읽으면 계산식 변경이다
(b) 보유는 현행 유지 · 사업군만 Naver ratio
    → 기존 계약 문자 그대로 보존
    → 한 메시지 안에서 두 구역의 분모 출처가 달라진다(§3 "출처 혼합" 우려)
(c) 보유도 무조정 테이블로
    → 개별주 3종목 탈락 = 중단 조건. **불가**
```

**(a)** 를 제안한다 — 임계·상태·`worst_state` 계약은 그대로 두고 **분모 정확도만**
올리는 것이라 계약 훼손이 아니라고 본다. 다만 계산식이 바뀌므로 판단을 구한다.

### Q3. KS-5(알림 과다)와 상한의 경계

`docs/KILL_SWITCHES.md` KS-5 기준은 **"시간당 1건 초과"** 다. 설계 §6 은 회차당
최대 1건이고 틱 간격이 1시간이므로 **정확히 경계선**이다.

일일 상한 4건이면 실제로는 시간당 1건 미만이라 위반은 아니라고 읽었다.
이 해석이 맞는지 확인받는다. (고정 4건 + 조건형 4건 = 하루 8건)
